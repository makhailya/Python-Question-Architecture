# 🎯 Абстракция

## 🎯 Ответ на собеседовании

**Абстракция** — принцип ООП, который позволяет **выделить существенные свойства и поведение объекта, скрыв ненужные детали реализации**.

Главная идея:

> Пользователь работает с **интерфейсом объекта**, не зная всех деталей его внутренней реализации.

Например, нам достаточно знать:

```python id="4xk7r1"
car.start()
```

Нам не обязательно знать, как именно внутри запускается двигатель.

---

# 📌 Пример

Представим систему оплаты:

```python id="1i0z5n"
class Payment:
    def pay(self, amount):
        ...
```

Пользователю важно:

```python id="q7b8a3"
payment.pay(1000)
```

А что происходит внутри:

```text id="j2j9y0"
payment.pay(1000)
        ↓
проверка карты
        ↓
запрос в банк
        ↓
проверка баланса
        ↓
подтверждение платежа
```

— скрытая деталь реализации.

---

# 🧱 Абстрактный класс

В Python для явного описания абстрактного интерфейса можно использовать модуль `abc`.

```python id="6qj9aj"
from abc import ABC, abstractmethod


class Payment(ABC):

    @abstractmethod
    def pay(self, amount):
        pass
```

Теперь `Payment` задаёт контракт:

> Каждый конкретный способ оплаты должен реализовать `pay()`.

---

## 🧩 Реализация

```python id="a3h3cc"
class CardPayment(Payment):
    def pay(self, amount):
        print(f"Card payment: {amount}")


class CashPayment(Payment):
    def pay(self, amount):
        print(f"Cash payment: {amount}")
```

Теперь:

```python id="7h8d9z"
card = CardPayment()
cash = CashPayment()

card.pay(1000)
cash.pay(1000)
```

У обоих есть общий интерфейс:

```python id="q0f5s8"
pay()
```

Но реализация разная.

---

# ⚠️ Нельзя создать объект абстрактного класса

```python id="x2d4v1"
payment = Payment()
```

Получим ошибку:

```text
TypeError
```

Потому что `Payment` содержит абстрактный метод `pay()`.

---

# 🦆 Абстракция и duck typing

В Python абстракцию не обязательно реализовывать через `ABC`.

Можно использовать **duck typing**:

```python id="9c5r6h"
def process_payment(payment):
    payment.pay(1000)
```

Функции всё равно, какой конкретно класс передан.

Главное:

```text id="p6z2s4"
объект умеет → pay()
```

Поэтому Python часто использует более гибкий подход:

```text id="6l6f0s"
ABC / Protocol
      ↓
явно описанный интерфейс

Duck typing
      ↓
неявный интерфейс
```

# 📐 Абстракция vs инкапсуляция

Это очень частый вопрос.

|        | Абстракция                    | Инкапсуляция                             |
| ------ | ----------------------------- | ---------------------------------------- |
| Суть   | Выделяет главное              | Скрывает/контролирует детали             |
| Вопрос | **Что объект умеет?**         | **Как устроено внутри?**                 |
| Цель   | Упростить использование       | Защитить внутреннее состояние/реализацию |
| Python | `ABC`, `Protocol`, интерфейсы | `_`, `__`, `property`, методы            |

Например:

```python id="q1p6d0"
class BankAccount:
    def __init__(self, balance):
        self._balance = balance

    def withdraw(self, amount):
        ...
```

**Абстракция:**

```text
withdraw(amount)
```

Пользователю не важно, как именно происходит снятие денег.

**Инкапсуляция:**

```text
_balance
```

Внутреннее состояние не предполагается изменять напрямую.

# 🔄 Абстракция и полиморфизм

Эти принципы хорошо работают вместе:

```python id="7p8n3c"
class Payment(ABC):

    @abstractmethod
    def pay(self, amount):
        pass
```

Разные реализации:

```text id="w3z0q6"
           Payment
              ↓
      ┌───────┼────────┐
      ↓       ↓        ↓
    Card     Cash     SBP
      ↓       ↓        ↓
    pay()   pay()    pay()
```

Код работает с общим интерфейсом:

```python id="6m3g8f"
def process(payment):
    payment.pay(1000)
```

Это сочетает:

* **абстракцию** — общий интерфейс `pay()`;
* **полиморфизм** — разные реализации `pay()`.

# 🏗️ Абстракция в Backend

Очень распространённый пример — работа с хранилищем:

```python id="z8l1u7"
from abc import ABC, abstractmethod


class UserRepository(ABC):

    @abstractmethod
    def get_user(self, user_id):
        pass
```

Конкретная реализация:

```python id="m4d2p8"
class PostgresUserRepository(UserRepository):

    def get_user(self, user_id):
        # запрос в PostgreSQL
        ...
```

Сервис зависит от абстракции:

```python id="e5q9n2"
class UserService:

    def __init__(self, repository):
        self.repository = repository
```

Теперь реализацию можно заменить:

```text id="4a5q7e"
UserService
     ↓
UserRepository
     ↓
 ┌───┴──────────────┐
 ↓                  ↓
PostgreSQL       MockRepository
```

Это помогает уменьшить связанность компонентов и упрощает тестирование.

# 🧠 Главное

```text id="n0m3z7"
Абстракция
    ↓
выделяем главное
    ↓
создаём понятный интерфейс
    ↓
скрываем ненужные детали реализации
```

В Python для этого используются:

* `ABC`;
* `@abstractmethod`;
* `Protocol`;
* duck typing;
* хорошо спроектированные интерфейсы классов.

### 🎤 Суперкоротко

> **Абстракция — принцип ООП, который выделяет существенное поведение объекта и скрывает ненужные детали реализации. В Python абстракцию можно реализовать через абстрактные классы и `@abstractmethod`, `Protocol` или duck typing.**
