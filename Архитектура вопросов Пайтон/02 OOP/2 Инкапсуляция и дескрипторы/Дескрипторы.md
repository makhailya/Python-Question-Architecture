# Дескрипторы

## 🎯 Ответ на собеседовании

**Дескриптор** — это объект, который определяет поведение доступа к атрибуту через специальные методы:

```python
__get__()
__set__()
__delete__()
```

Дескрипторы позволяют управлять тем, **как атрибут читается, изменяется или удаляется**.

Они являются фундаментальным механизмом Python и используются, например, в:

* [[property]];
* методах классов;
* [[classmethod]];
* [[staticmethod]];
* ORM, например [[Django ORM]].

---

## 📌 Простейший дескриптор

```python
class Descriptor:
    def __get__(self, instance, owner):
        return "value"
```

Используем его:

```python
class User:
    name = Descriptor()
```

Теперь:

```python
user = User()

print(user.name)
```

Python вызывает:

```python
Descriptor.__get__(...)
```

и получаем:

```text
value
```

То есть `name` — не обычное значение, а **объект-дескриптор**, который управляет доступом к атрибуту.

---

# 🔧 Методы дескриптора

## `__get__`

Вызывается при получении значения:

```python
user.name
```

```python
def __get__(self, instance, owner):
    ...
```

---

## `__set__`

Вызывается при присваивании:

```python
user.name = "Ilya"
```

```python
def __set__(self, instance, value):
    ...
```

---

## `__delete__`

Вызывается при удалении:

```python
del user.name
```

```python
def __delete__(self, instance):
    ...
```

---

# 🧩 Полный пример

```python
class PositiveNumber:
    def __get__(self, instance, owner):
        return instance._value

    def __set__(self, instance, value):
        if value < 0:
            raise ValueError("Число должно быть положительным")

        instance._value = value

    def __delete__(self, instance):
        del instance._value
```

Используем:

```python
class Product:
    price = PositiveNumber()
```

Теперь:

```python
product = Product()

product.price = 100
print(product.price)  # 100

product.price = -10  # ValueError
```

Дескриптор перехватывает операции с `price` и выполняет дополнительную логику.

---

# 🔥 [[Data-дескрипторы]] и [[Non-data дескрипторы]]

Дескрипторы делятся на два основных типа.

## Data Descriptor

Имеет:

```python
__set__()
```

или:

```python
__delete__()
```

Например:

```python
class Descriptor:
    def __get__(self, instance, owner):
        ...

    def __set__(self, instance, value):
        ...
```

Такой дескриптор имеет **приоритет над `instance.__dict__`**.

---

## Non-Data Descriptor

Имеет только:

```python
__get__()
```

Например:

```python
class Descriptor:
    def __get__(self, instance, owner):
        ...
```

Такой дескриптор может быть перекрыт атрибутом экземпляра.

---

# ⚠️ Почему это важно?

Рассмотрим:

```python
class Descriptor:
    def __get__(self, instance, owner):
        return "descriptor"


class User:
    name = Descriptor()
```

Можно добавить атрибут непосредственно в экземпляр:

```python
user = User()

user.__dict__["name"] = "instance"
```

Поскольку `Descriptor` — **non-data descriptor**, атрибут экземпляра имеет приоритет:

```python
print(user.name)
```

получим:

```text
instance
```

Но если добавить `__set__`:

```python
class Descriptor:
    def __get__(self, instance, owner):
        return "descriptor"

    def __set__(self, instance, value):
        pass
```

дескриптор становится **[[Data-дескрипторы]]** и получает более высокий приоритет.

---

# 🔍 Порядок поиска атрибута

Упрощённо при:

```python
user.name
```

Python ищет атрибут примерно в таком порядке:

```text
1. Data descriptor в классе
        ↓
2. instance.__dict__
        ↓
3. Non-data descriptor / обычный атрибут класса
```

Именно поэтому data descriptor может контролировать доступ к атрибуту экземпляра.

# 🏗️ `property` — дескриптор

Один из самых важных примеров встроенного дескриптора — `property`.

```python
class User:
    def __init__(self, age):
        self._age = age

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError

        self._age = value
```

Когда выполняется:

```python
user.age
```

работает механизм дескрипторов `property`.

То есть:

```text
@property
    ↓
property object
    ↓
__get__()
```

А:

```python
user.age = 30
```

использует setter через механизм дескриптора.

---

# 🧠 Дескрипторы и методы

Обычные функции, определённые внутри класса, тоже связаны с механизмом дескрипторов.

```python
class User:
    def hello(self):
        print("Hello")
```

Когда пишем:

```python
user.hello
```

Python получает функцию через её `__get__()` и формирует **bound method**, привязанный к экземпляру.

Поэтому:

```python
user.hello()
```

фактически позволяет автоматически передать `self`.

---

# 💼 Где используются дескрипторы?

### `property`

```python
@property
def name(self):
    ...
```

### `classmethod`

```python
@classmethod
def create(cls):
    ...
```

### `staticmethod`

```python
@staticmethod
def validate():
    ...
```

### ORM

Например, в Django:

```python
class User(models.Model):
    name = models.CharField(max_length=100)
```

Доступ:

```python
user.name
```

может проходить через дескриптор поля ORM, который управляет чтением и записью значения.

---

# 🆚 Дескриптор vs [[property]]

`property` — это **конкретная реализация дескриптора**.

То есть:

```text
Дескриптор
    ↓
общий механизм Python

property
    ↓
конкретный встроенный дескриптор
```

Можно создать собственный дескриптор вручную, а можно использовать `property` для типичного случая управления атрибутом.

---

# 🧠 Главное

* Дескриптор — объект, реализующий `__get__`, `__set__` и/или `__delete__`.
* Он управляет доступом к атрибутам.
* **Data descriptor** → имеет `__set__` или `__delete__`.
* **Non-data descriptor** → имеет только `__get__`.
* Data descriptor имеет приоритет над `instance.__dict__`.
* `property` — встроенный пример дескриптора.
* Методы классов тоже используют механизм дескрипторов.
* Дескрипторы широко используются во фреймворках и ORM.

## 🎤 Суперкоротко

> **Дескриптор** — это объект, который через `__get__`, `__set__` и `__delete__` управляет доступом к атрибуту. Они лежат в основе `property`, методов классов и многих механизмов ORM. Data descriptor имеет приоритет над атрибутами экземпляра.
