# 🔒 Инкапсуляция

## 🎯 Ответ на собеседовании

**Инкапсуляция** — принцип ООП, при котором **состояние и поведение объекта объединяются в одном классе**, а внутренние детали реализации скрываются или ограничиваются от прямого внешнего доступа.

Главная идея:

> Внешний код должен взаимодействовать с объектом через **предоставленный интерфейс**, а не напрямую управлять его внутренним состоянием.

---

## 📌 Пример

```python
class BankAccount:
    def __init__(self, balance):
        self._balance = balance

    def deposit(self, amount):
        if amount > 0:
            self._balance += amount

    def get_balance(self):
        return self._balance
```

Вместо:

```python
account._balance += 100
```

предполагается использовать:

```python
account.deposit(100)
```

Так класс сам контролирует изменение своего состояния.

---

# 🐍 Как реализуется в Python

В Python нет строгих модификаторов доступа `private` / `protected` как, например, в Java.

Используются соглашения и **name mangling**.

### `_attribute`

Один `_` означает:

> Атрибут внутренний, не предназначен для использования напрямую извне.

```python
class User:
    def __init__(self):
        self._password = "secret"
```

Это **не запрет доступа**:

```python
user._password  # технически возможно
```

---

### `__attribute`

Два `_` в начале запускают **name mangling**:

```python
class User:
    def __init__(self):
        self.__password = "secret"
```

Python преобразует имя примерно в:

```text
_User__password
```

Поэтому:

```python
user.__password
```

не сработает обычным образом.

Но это всё равно **не настоящая приватность** — при необходимости к атрибуту можно обратиться через имя после name mangling.

---

# 🎛️ Инкапсуляция через `property`

Один из удобных способов контролировать доступ к состоянию:

```python
class User:
    def __init__(self, age):
        self._age = age

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("Age cannot be negative")

        self._age = value
```

Теперь:

```python
user = User(30)

user.age = 31      # ✅
user.age = -10     # ❌ ValueError
```

Класс контролирует изменение своего состояния.

# 🎯 Зачем нужна инкапсуляция?

### 1. Контроль состояния

Можно не позволять записывать некорректные значения.

```python
if amount > 0:
    self._balance += amount
```

### 2. Скрытие деталей реализации

Пользователю класса не обязательно знать, **как именно** работает метод.

```python
account.deposit(100)
```

Внутри может быть сложная логика, но внешний интерфейс остаётся простым.

### 3. Уменьшение связанности

Внешний код зависит от публичного интерфейса, а не от внутренней реализации.

Можно изменить:

```python
self._balance
```

на другой способ хранения, не меняя:

```python
account.deposit(100)
```

# 🆚 Инкапсуляция vs абстракция

Их часто путают.

|               | Инкапсуляция                                            | Абстракция                    |
| ------------- | ------------------------------------------------------- | ----------------------------- |
| Основная идея | Скрыть/контролировать внутреннее состояние и реализацию | Выделить важный интерфейс     |
| Вопрос        | **Как ограничить доступ?**                              | **Что объект предоставляет?** |
| Python        | `_`, `__`, `property`, методы                           | ABC, Protocol, интерфейсы     |
| Пример        | `account._balance`                                      | `account.deposit()`           |

Упрощённо:

```text
Инкапсуляция → скрываем детали
Абстракция   → показываем главное
```

---

## ⚠️ Важный нюанс Python

Не стоит говорить:

> ❌ «`_variable` — приватная переменная».

Точнее:

> ✅ «Одинарный `_` — соглашение о внутреннем атрибуте, а `__` вызывает name mangling. В Python нет абсолютной приватности атрибутов».

---

## 🧠 Главное

```text
Инкапсуляция
     ↓
объект управляет своим состоянием
     ↓
внешний код работает через публичный интерфейс
     ↓
внутреннюю реализацию можно менять независимо
```

### 🎤 Суперкоротко

> **Инкапсуляция — принцип ООП, который объединяет состояние и поведение объекта и ограничивает прямой доступ к его внутренней реализации. В Python для этого используют соглашение `_`, name mangling через `__`, методы и [[property]].**
