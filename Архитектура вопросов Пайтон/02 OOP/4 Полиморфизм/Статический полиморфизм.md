# Статический полиморфизм

## 🎯 Ответ на собеседовании

**Статический полиморфизм** — это возможность использовать один интерфейс для разных вариантов поведения, когда выбор конкретной реализации определяется **на этапе компиляции или статического анализа**, а не во время выполнения.

Классический пример — **перегрузка методов (method overloading)**: один метод имеет несколько реализаций с разными сигнатурами.

В Python классической перегрузки методов **нет**.

---

## 📌 Как это выглядит в языках со статической типизацией

Например, условно в Java:

```java
void print(int value) {
    ...
}

void print(String value) {
    ...
}
```

Вызов:

```text
print(10)       → версия для int
print("hello")  → версия для String
```

Компилятор определяет, какую перегрузку использовать.

Это классический пример **статического полиморфизма**.

---

## 🐍 А что в Python?

Python не позволяет определить несколько методов с одним именем:

```python
class Calculator:
    def add(self, a, b):
        return a + b

    def add(self, a, b, c):
        return a + b + c
```

Вторая `add()` просто **перезапишет первую**.

Поэтому:

```python
Calculator().add(1, 2)
```

вызовет последнюю версию и приведёт к ошибке из-за отсутствия `c`.

---

## 🔧 Чем Python заменяет перегрузку?

Обычно используют аргументы по умолчанию:

```python
class Calculator:
    def add(self, a, b, c=0):
        return a + b + c
```

Теперь:

```python
calc = Calculator()

calc.add(1, 2)       # 3
calc.add(1, 2, 3)    # 6
```

Или `*args`:

```python
def add(*args):
    return sum(args)
```

---

## 🏷️ `@overload` из typing

В Python есть `typing.overload`, но это **не runtime-перегрузка**.

```python
from typing import overload


@overload
def process(value: int) -> int: ...


@overload
def process(value: str) -> str: ...


def process(value):
    return value
```

`@overload` используется для **статических анализаторов типов**:

* mypy;
* Pyright;
* IDE.

Во время выполнения существует только реальная реализация:

```python
def process(value):
    return value
```

То есть `@overload` помогает описать разные допустимые сигнатуры, но не создаёт несколько методов.

---

## 🆚 Статический vs динамический полиморфизм

|                                 | Статический                | Динамический            |
| ------------------------------- | -------------------------- | ----------------------- |
| Когда выбирается реализация     | До выполнения              | Во время выполнения     |
| Классический механизм           | Перегрузка методов         | Переопределение         |
| Python                          | `@overload`, type checking | Duck typing, overriding |
| Зависит от фактического объекта | Обычно нет                 | Да                      |

---

## ⚠️ Важный нюанс для собеседования

Не стоит говорить:

> «В Python есть статический полиморфизм через `@overload`».

Точнее:

> **Python не поддерживает классическую runtime-перегрузку методов. `typing.overload` позволяет описать несколько сигнатур для статического анализатора типов, но фактически реализация метода остаётся одна.**

Также термин «статический полиморфизм» в контексте Python используется менее строго, чем в языках вроде C++/Java.

---

## 🧠 Главное

* Статический полиморфизм → выбор варианта поведения **до выполнения**.
* Классический механизм → **перегрузка методов**.
* Python не поддерживает классическую перегрузку методов по сигнатуре.
* `@overload` существует, но работает для **статической проверки типов**, а не создаёт несколько runtime-реализаций.
* В Python гораздо характернее **динамический полиморфизм + duck typing**.

## 🎤 Суперкоротко

> Статический полиморфизм — это выбор реализации на этапе компиляции, классический пример — перегрузка методов. В Python классической перегрузки нет; `@typing.overload` используется только для статической типизации. Основной полиморфизм Python — динамический.
