# 🔄 Полиморфизм

## 🎯 Ответ на собеседовании

**Полиморфизм** — принцип ООП, при котором **один интерфейс может использоваться с объектами разных типов**, а конкретное поведение определяется самим объектом.

Проще:

> **Один интерфейс → разные реализации.**

Например, у разных объектов есть метод `speak()`:

```python id="i1q5x3"
class Dog:
    def speak(self):
        return "Woof"


class Cat:
    def speak(self):
        return "Meow"
```

Одна функция может работать с обоими:

```python id="gk6d2j"
def make_sound(animal):
    print(animal.speak())
```

```python id="n4b0w9"
make_sound(Dog())  # Woof
make_sound(Cat())  # Meow
```

Функции не важно, какой именно класс передан. Ей важно, что объект предоставляет метод `speak()`.

---

# 🦆 Duck Typing

В Python полиморфизм часто реализуется через **duck typing**.

Идея:

> **«Если объект ведёт себя как нужный объект — его можно использовать».**

Например:

```python id="i5xq0b"
class Dog:
    def speak(self):
        return "Woof"


class Robot:
    def speak(self):
        return "Beep"
```

Несмотря на то что `Robot` вообще не является `Animal`:

```python id="4wj7wy"
make_sound(Dog())
make_sound(Robot())
```

оба объекта подходят функции.

Почему?

Потому что у обоих есть:

```python id="k6m9n3"
speak()
```

# 🧬 Полиморфизм через наследование

Можно реализовать полиморфизм через общий базовый класс:

```python id="4vxxad"
class Animal:
    def speak(self):
        raise NotImplementedError


class Dog(Animal):
    def speak(self):
        return "Woof"


class Cat(Animal):
    def speak(self):
        return "Meow"
```

Теперь:

```python id="t5c5sv"
animals = [Dog(), Cat()]

for animal in animals:
    print(animal.speak())
```

Результат:

```text id="qj5h1a"
Woof
Meow
```

Один вызов:

```python id="9g6p5x"
animal.speak()
```

даёт разный результат в зависимости от конкретного объекта.

# 🎯 Полиморфизм через общий интерфейс

В современном Python общий интерфейс можно описывать через `Protocol`:

```python id="0omc4s"
from typing import Protocol


class Speakable(Protocol):
    def speak(self) -> str:
        ...
```

Любой объект, у которого есть подходящий `speak()`, может соответствовать этому протоколу структурно.

```text id="yd8m8q"
        Speakable
        /      \
       /        \
     Dog       Robot
      ↓           ↓
   speak()     speak()
```

Это хорошо соответствует философии duck typing.

# 🧩 Полиморфизм и переопределение

Частый механизм полиморфизма — **переопределение метода** в дочернем классе:

```python id="qz7w4n"
class Animal:
    def speak(self):
        return "Sound"


class Dog(Animal):
    def speak(self):
        return "Woof"
```

При:

```python id="9o6x9c"
animal = Dog()
animal.speak()
```

Python использует реализацию `Dog.speak()`.

---

# 🆚 Полиморфизм vs наследование

Их нельзя приравнивать.

**Наследование**:

> позволяет одному классу получить/расширить поведение другого.

**Полиморфизм**:

> позволяет работать с разными объектами через общий интерфейс.

Например:

```text id="o0h7d1"
Наследование
Animal
   ↓
  Dog


Полиморфизм
Dog ───┐
       ├──→ speak()
Cat ───┤
       │
Robot ─┘
```

Для полиморфизма наследование **не обязательно** в Python.

# 🧠 Полиморфизм в реальном Backend

Представим систему оплаты:

```python id="f9wz6s"
class CardPayment:
    def pay(self, amount):
        ...


class SBPPayment:
    def pay(self, amount):
        ...


class CryptoPayment:
    def pay(self, amount):
        ...
```

Сервису не нужно знать конкретный тип:

```python id="k7c8o8"
def process_payment(payment, amount):
    payment.pay(amount)
```

Теперь можно добавить:

```python id="0e8mwy"
class PayPalPayment:
    def pay(self, amount):
        ...
```

и `process_payment()` менять не обязательно.

Это делает систему более расширяемой.

---

# ⚠️ Важно: полиморфизм ≠ перегрузка

В Python нет классической перегрузки методов по типам аргументов, как в Java/C++.

Например, нельзя просто определить:

```python id="kqv4jh"
def add(a, b):
    ...


def add(a, b, c):
    ...
```

и получить две разные версии метода — второе определение заменит первое.

В Python полиморфизм чаще реализуется через:

* duck typing;
* переопределение методов;
* общий интерфейс;
* `Protocol`;
* абстрактные классы.

### 🎤 Суперкоротко

> **Полиморфизм — это возможность работать с объектами разных типов через единый интерфейс, при этом каждый объект реализует поведение по-своему. В Python полиморфизм часто реализуется через duck typing и переопределение методов; наследование для него не обязательно.**
