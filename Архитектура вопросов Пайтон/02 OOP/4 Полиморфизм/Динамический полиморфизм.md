# Динамический полиморфизм

## 🎯 Ответ на собеседовании

**Динамический полиморфизм** — это способность программы выбирать конкретную реализацию метода **во время выполнения**, в зависимости от фактического типа объекта.

В Python это тесно связано с **duck typing**: функции не обязательно знать конкретный класс объекта — достаточно, чтобы объект поддерживал нужный интерфейс.

---

## 📌 Пример

```python id="j1m7kn"
class Dog:
    def speak(self):
        print("Гав")


class Cat:
    def speak(self):
        print("Мяу")


def make_sound(animal):
    animal.speak()
```

Теперь:

```python id="xq2v5c"
make_sound(Dog())
make_sound(Cat())
```

Результат:

```text id="h4p9sd"
Гав
Мяу
```

Функция `make_sound()` одна, но конкретная реализация `speak()` определяется **во время выполнения**.

---

## 🦆 Duck Typing

Python не требует:

```python id="8g2zqa"
isinstance(animal, Animal)
```

Ему достаточно, чтобы объект имел нужный метод:

```python id="g0t7hc"
def make_sound(animal):
    animal.speak()
```

Например, совершенно независимый класс тоже будет работать:

```python id="8b7m1s"
class Robot:
    def speak(self):
        print("Beep")


make_sound(Robot())
```

Потому что у `Robot` есть необходимый интерфейс `speak()`.

Это и есть характерный для Python подход **duck typing**:

> Если объект ведёт себя как нужный тип — его можно использовать как этот тип.

---

## 🔄 Почему «динамический»?

Потому что Python определяет, какой метод вызвать, **во время выполнения программы**, а не заранее на этапе компиляции.

```python id="5g7w3q"
animal = Dog()

animal.speak()  # Dog.speak()

animal = Cat()

animal.speak()  # Cat.speak()
```

Один и тот же код:

```python id="q0x5fk"
animal.speak()
```

вызывает разные реализации в зависимости от объекта.

---

## 🧬 Через наследование

Динамический полиморфизм может работать и через переопределение методов:

```python id="h9w2pa"
class Animal:
    def speak(self):
        print("Животное издаёт звук")


class Dog(Animal):
    def speak(self):
        print("Гав")


class Cat(Animal):
    def speak(self):
        print("Мяу")
```

```python id="v4y6ks"
animals = [Dog(), Cat()]

for animal in animals:
    animal.speak()
```

Получим:

```text id="q6j8zy"
Гав
Мяу
```

Хотя переменная `animal` одна и та же.

---

## ⚠️ В Python наследование не обязательно

Это важный момент.

Полиморфизм можно реализовать:

* через наследование;
* через duck typing;
* через `ABC`;
* через `Protocol`.

Например, `Dog` и `Robot` вообще не обязаны иметь общего родителя:

```python id="4g1c5z"
class Dog:
    def speak(self):
        print("Гав")


class Robot:
    def speak(self):
        print("Beep")
```

Оба объекта можно передать в:

```python id="j9q4pk"
def make_sound(obj):
    obj.speak()
```

---

## 🆚 Статический vs динамический полиморфизм

|                               | Статический   | Динамический        |
| ----------------------------- | ------------- | ------------------- |
| Когда определяется реализация | До выполнения | Во время выполнения |
| Типичная реализация           | Перегрузка    | Переопределение     |
| Python                        | ограниченно   | основной подход     |
| Duck typing                   | ❌             | ✅                   |

⚠️ В Python нет классической перегрузки методов по сигнатуре, как в Java/C++.

## 💼 Пример из Backend

Допустим, есть разные способы оплаты:

```python id="0l3y6v"
class CardPayment:
    def pay(self, amount):
        print(f"Карта: {amount}")


class SBPPayment:
    def pay(self, amount):
        print(f"СБП: {amount}")


def process_payment(payment, amount):
    payment.pay(amount)
```

Можно передать любой объект, поддерживающий `pay()`:

```python id="p8h4x2"
process_payment(CardPayment(), 1000)
process_payment(SBPPayment(), 1000)
```

`process_payment()` не знает конкретный класс. Он работает с **интерфейсом** `pay()`.

---

## 🧠 Главное

* Динамический полиморфизм → конкретная реализация выбирается **во время выполнения**.
* В Python он часто реализуется через **duck typing**.
* Наследование для него **не обязательно**.
* Один интерфейс → разные реализации.
* Типичный пример: `obj.method()` вызывает реализацию, соответствующую фактическому объекту.

## 🎤 Суперкоротко

> Динамический полиморфизм — это когда один интерфейс может иметь разные реализации, а конкретный метод выбирается во время выполнения в зависимости от фактического объекта. В Python это часто реализуется через duck typing.
