# 🔀 Ad hoc полиморфизм

🎯 **Ответ на собеседовании:**

**Ad hoc полиморфизм** — форма полиморфизма, при которой **одинаковая операция или имя функции может иметь разные реализации для разных типов или наборов аргументов**.

Классический пример — **перегрузка функций (function overloading)**:

```text
add(int, int)       → одна реализация
add(str, str)       → другая реализация
```

Выбор реализации зависит от переданных аргументов.

---

# Перегрузка функций

В языках вроде Java или C++ можно определить несколько функций с одним именем, но разными сигнатурами:

```text
add(int, int)
add(int, int, int)
add(str, str)
```

Компилятор выбирает подходящую реализацию.

Это классический пример **ad hoc полиморфизма**.

---

# А что в Python?

В Python **нет классической перегрузки функций по сигнатуре**.

Если определить функцию несколько раз:

```python
def add(a, b):
    return a + b


def add(a, b, c):
    return a + b + c
```

вторая функция просто **перезапишет первую**.

```python
add(1, 2)
```

даст ошибку:

```text
TypeError
```

потому что осталась только:

```python
add(a, b, c)
```

---

# Как имитировать перегрузку в Python

### 1. Значения по умолчанию

```python
def add(a, b, c=0):
    return a + b + c
```

Теперь:

```python
add(1, 2)       # 3
add(1, 2, 3)    # 6
```

---

### 2. `*args`

```python
def add(*args):
    return sum(args)
```

```python
add(1, 2)       # 3
add(1, 2, 3)    # 6
```

---

### 3. Проверка типов

Можно выбирать поведение в runtime:

```python
def process(value):
    if isinstance(value, int):
        return value * 2

    if isinstance(value, str):
        return value.upper()
```

Здесь одна функция имеет разное поведение для разных типов.

---

# `functools.singledispatch`

В Python есть более формальный механизм **ad hoc-полиморфизма по типу первого аргумента**:

```python
from functools import singledispatch


@singledispatch
def process(value):
    raise TypeError("Unsupported type")


@process.register
def _(value: int):
    return value * 2


@process.register
def _(value: str):
    return value.upper()
```

Теперь:

```python
process(10)       # 20
process("hello")  # HELLO
```

`singledispatch` выбирает реализацию **во время выполнения** в зависимости от типа первого аргумента.

---

# `typing.overload`

В Python также существует:

```python
from typing import overload
```

Например:

```python
@overload
def get(value: int) -> int: ...

@overload
def get(value: str) -> str: ...
```

Но важно:

> `@overload` **не создаёт несколько runtime-реализаций функции**.

Эти объявления используются в основном **статическими анализаторами типов** (`mypy`, Pyright и т. п.).

Реализация всё равно одна:

```python
def get(value):
    return value
```

---

# Почему это называется Ad hoc?

Потому что для конкретных типов или ситуаций можно определить **специальное поведение**.

Например:

```text
одна операция
      ↓
┌─────┴─────┐
int         str
 ↓           ↓
× 2         upper()
```

В отличие от **параметрического полиморфизма**, где один общий алгоритм работает с произвольным типом.

---

# Сравнение видов полиморфизма

| Вид                 | Идея                                           | Python                                            |
| ------------------- | ---------------------------------------------- | ------------------------------------------------- |
| **Ad hoc**          | Разное поведение для конкретных типов/сигнатур | `singledispatch`, `*args`, ручная диспетчеризация |
| **Параметрический** | Один алгоритм для разных типов                 | `TypeVar`, Generics                               |
| **Подтиповый**      | Работа через общий интерфейс/родительский тип  | Наследование, Protocol, duck typing               |

---

## 🧠 Коротко для собеседования

> **Ad hoc полиморфизм — это полиморфизм, при котором одна операция имеет разные реализации для конкретных типов или наборов аргументов. Классический пример — перегрузка функций. В Python классической перегрузки по сигнатуре нет: повторное объявление функции перезаписывает предыдущую реализацию. Вместо этого используют значения по умолчанию, `*args`, runtime-проверки типов, `functools.singledispatch`, а `typing.overload` используется для статической типизации.**

### Главное не перепутать

```text
Ad hoc
→ конкретные типы / сигнатуры
→ разные реализации

Parametric
→ один алгоритм
→ разные типы
→ TypeVar / Generics
```

⚠️ **`@overload` ≠ настоящая runtime-перегрузка.** Это прежде всего информация для статического анализатора.
