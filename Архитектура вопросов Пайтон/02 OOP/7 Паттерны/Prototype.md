# Prototype — конспект для Python Backend

## Формула для собеседования

**Prototype (Прототип)** — порождающий паттерн проектирования, который позволяет создавать новые объекты путём копирования существующего объекта-прототипа, вместо повторного создания объекта с нуля.

**Формула:**

`Готовый объект → Копирование → Новый объект с аналогичным состоянием`

Главная идея: если объект сложно или дорого создавать заново, можно использовать его копию и при необходимости изменить отдельные свойства.

## Короткий ответ

Prototype применяется, когда нужно быстро создавать объекты на основе уже настроенных экземпляров.

Например, Backend-приложение формирует несколько вариантов конфигурации отчёта на основе общего шаблона. Вместо повторного заполнения всех полей приложение копирует шаблон и изменяет необходимые параметры.

В Python для реализации обычно используют `copy.copy()` для поверхностного копирования и `copy.deepcopy()` для глубокого копирования.

## Ответ на собеседовании

Prototype — это порождающий паттерн, который позволяет создавать объекты путём копирования существующих экземпляров. Он полезен, когда создание объекта сложное, дорогостоящее или требует большого количества начальных настроек.

В Python этот подход можно реализовать с помощью модуля `copy`. При поверхностном копировании создаётся новый внешний объект, но вложенные изменяемые объекты могут остаться общими. При глубоком копировании рекурсивно копируется содержимое объекта.

Основные преимущества — уменьшение повторяющегося кода и возможность быстро создавать объекты на основе готовых конфигураций. Главный риск — неправильное копирование вложенных объектов и ресурсов, которыми нельзя безопасно управлять через обычное копирование.

## 1. Какую проблему решает Prototype

Представим, что в Backend-приложении есть сложная конфигурация отчёта:

- период;
- список колонок;
- фильтры;
- сортировка;
- формат экспорта;
- дополнительные параметры.

Каждый пользователь создаёт отчёт на основе общего шаблона, изменяя только некоторые настройки.

Без Prototype приходится повторно задавать все параметры:

```python id="4b3m2z"
report_a = {
    "format": "xlsx",
    "columns": ["name", "amount", "date"],
    "filters": {"status": "paid"},
    "sort": "date",
}

report_b = {
    "format": "xlsx",
    "columns": ["name", "amount", "date"],
    "filters": {"status": "paid"},
    "sort": "amount",
}
```

Здесь большая часть данных дублируется.

С Prototype можно подготовить шаблон, скопировать его и изменить только нужные поля.

## 3. Поверхностное и глубокое копирование

Это ключевая тема для понимания Prototype в Python.

### Поверхностное копирование — `copy.copy()`

Создаётся новый внешний объект, но ссылки на вложенные объекты копируются.

```python id="b1s4nf"
import copy

original = {
    "name": "Отчёт",
    "columns": ["name", "amount"],
}

cloned = copy.copy(original)

cloned["name"] = "Копия отчёта"
cloned["columns"].append("date")

print(original["name"])     # Отчёт
print(original["columns"])  # ['name', 'amount', 'date']
```

Почему исходный список изменился?

Потому что `original` и `cloned` ссылаются на один и тот же вложенный список `columns`.

### Глубокое копирование — `copy.deepcopy()`

Создаётся копия внешнего объекта и рекурсивно копируются вложенные объекты, насколько это поддерживает механизм копирования.

```python id="v2d8kg"
import copy

original = {
    "name": "Отчёт",
    "columns": ["name", "amount"],
}

cloned = copy.deepcopy(original)

cloned["name"] = "Копия отчёта"
cloned["columns"].append("date")

print(original["name"])     # Отчёт
print(original["columns"])  # ['name', 'amount']

print(cloned["columns"])    # ['name', 'amount', 'date']
```

Теперь изменение списка в копии не затрагивает исходный список.

### Сравнение

| Критерий | `copy.copy()` | `copy.deepcopy()` |
|---|---|---|
| Внешний объект | Новый | Новый |
| Вложенные объекты | Обычно остаются общими | Рекурсивно копируются |
| Скорость | Обычно выше | Обычно ниже |
| Использование памяти | Обычно меньше | Обычно больше |
| Основной риск | Изменение общих вложенных объектов | Дорогая или некорректная копия сложного графа объектов |

**Важно:** глубокое копирование не гарантирует, что абсолютно всё станет независимым. Поведение зависит от типа объектов и реализованной ими логики копирования.

## 4. Реализация Prototype на Python

Создадим прототип конфигурации отчёта.

### Шаг 1. Определяем класс

```python id="4d1z8k"
from copy import deepcopy
from dataclasses import dataclass, field


@dataclass
class ReportConfig:
    name: str
    columns: list[str] = field(default_factory=list)
    filters: dict[str, str] = field(default_factory=dict)

    def clone(self) -> "ReportConfig":
        return deepcopy(self)
```

Метод `clone()` инкапсулирует способ копирования. Пользователю класса не нужно каждый раз самостоятельно выбирать функцию из `copy`.

### Шаг 2. Создаём прототип

```python id="v8c2qa"
default_report = ReportConfig(
    name="Стандартный отчёт",
    columns=["name", "amount", "date"],
    filters={"status": "paid"},
)
```

Этот экземпляр служит шаблоном для новых конфигураций.

### Шаг 3. Клонируем и изменяем

```python id="m7p1rf"
sales_report = default_report.clone()
sales_report.name = "Отчёт по продажам"
sales_report.filters["status"] = "completed"

inventory_report = default_report.clone()
inventory_report.name = "Отчёт по остаткам"
inventory_report.columns.append("quantity")
```

Каждая копия может изменяться независимо от исходного прототипа и других копий.

### Шаг 4. Проверяем результат

```python id="x3j9we"
print(default_report.name)
# Стандартный отчёт

print(default_report.filters)
# {'status': 'paid'}

print(default_report.columns)
# ['name', 'amount', 'date']
```

Исходный объект не изменился.

## 5. Когда применять Prototype

Prototype полезен, если:

- создание объекта требует большого количества настроек;
- нужно создавать множество вариантов одного шаблона;
- повторная инициализация объекта дороже копирования;
- тип конкретного объекта определяется во время выполнения;
- необходимо сохранять заранее подготовленные конфигурации.

### Примеры в Python Backend

**Конфигурации отчётов.** Копирование шаблона с изменением фильтров и колонок.

**Шаблоны задач.** Создание задач на основе стандартной конфигурации с индивидуальными параметрами.

**Объекты для тестов.** Подготовка базового набора тестовых данных и создание изолированных вариантов.

**Сложные структуры данных.** Копирование предварительно подготовленных объектов, если это действительно проще и безопаснее повторного построения.

## 6. Когда Prototype не нужен

Не стоит использовать паттерн, если:

- объект легко создать обычным конструктором;
- копирование сложнее, чем повторное создание;
- объект содержит открытые соединения, файловые дескрипторы или другие ресурсы с особым жизненным циклом;
- требуется не независимая копия, а совместное использование неизменяемого объекта;
- поведение копирования трудно предсказать.

Например, для простого объекта:

```python id="a7m3pf"
from dataclasses import dataclass


@dataclass
class User:
    username: str
    email: str


user = User(
    username="ilya",
    email="ilya@example.com",
)
```

Обычный конструктор проще и понятнее, чем отдельная система прототипов.

## 7. Особенности копирования объектов в Python

### `copy.copy()` и `copy.deepcopy()` — не одно и то же

Поверхностная копия создаёт новый внешний объект, но может сохранять общие ссылки на вложенные данные. Глубокая копия пытается рекурсивно копировать вложенные объекты.

### Можно управлять копированием

Классы могут реализовывать специальные методы:

- `__copy__()` — определяет поведение поверхностного копирования;
- `__deepcopy__(memo)` — определяет поведение глубокого копирования.

Параметр `memo` используется для отслеживания уже обработанных объектов, в том числе для корректной работы с циклическими ссылками.

### Не все объекты копируются одинаково

Некоторые объекты нельзя безопасно копировать обычным способом. Например, сетевые соединения, файловые дескрипторы, блокировки и другие системные ресурсы требуют отдельного решения.

Вместо копирования ресурса может понадобиться создать новый ресурс или передавать ссылку на общий управляемый объект.

### Неизменяемые объекты

Для неизменяемых данных, таких как строки и числа, независимое копирование часто не даёт практической пользы. Для сложных структур нужно оценивать не только тип внешнего объекта, но и содержимое.

## 8. Prototype vs Builder vs Factory Method

| Критерий | Prototype | Builder | Factory Method |
|---|---|---|---|
| Основная задача | Копирование готового объекта | Пошаговое построение объекта | Создание конкретного продукта через фабричный метод |
| Отправная точка | Существующий экземпляр | Процесс сборки | Решение о реализации продукта |
| Основная операция | `clone()` | `build()` | `create_product()` |
| Типичный пример | Копия конфигурации | Настройка сложного запроса | Выбор реализации парсера |
| Основной риск | Неправильная глубина копирования | Избыточная сложность сборки | Чрезмерная связанность или сложная иерархия |

**Запомнить:**

- Prototype — копируем существующий объект.
- Builder — собираем объект по шагам.
- Factory Method — делегируем создание объекта определённой реализации.

## 9. Преимущества и недостатки

### Преимущества

- **Меньше дублирования:** новые объекты создаются на основе шаблонов.
- **Гибкость:** можно клонировать объекты конкретных типов без привязки к их конструкторам.
- **Удобство настройки:** после копирования можно изменять отдельные параметры.
- **Сокрытие создания:** сложная логика копирования может быть инкапсулирована в методе `clone()`.

### Недостатки

- **Сложность копирования:** нужно определить, какие данные должны быть общими, а какие независимыми.
- **Расход ресурсов:** глубокое копирование крупных структур может быть дорогим.
- **Проблемы с ресурсами:** не каждый объект безопасно клонировать.
- **Неочевидное состояние:** копия может неожиданно сохранять ссылки на изменяемые вложенные объекты.

## 10. Типичные ошибки

1. **Использовать поверхностное копирование там, где нужна независимость вложенных данных.**
2. **Считать `deepcopy()` универсальным решением для любых объектов.**
3. **Копировать сетевые соединения, файлы и другие ресурсы без анализа их жизненного цикла.**
4. **Клонировать простые объекты вместо использования конструктора.**
5. **Не тестировать независимость копии от исходного объекта.**
6. **Забывать, что собственные классы могут менять стандартное поведение копирования.**

## 11. Вопросы для собеседования

### Что такое Prototype?

Это порождающий паттерн, который создаёт новые объекты путём копирования существующих экземпляров.

### Чем отличается поверхностное копирование от глубокого?

При поверхностном копировании вложенные объекты обычно остаются общими. При глубоком копировании механизм рекурсивно копирует вложенные объекты, насколько это возможно для их типов.

### Как реализовать Prototype в Python?

Использовать `copy.copy()`, `copy.deepcopy()` или собственный метод `clone()`, если нужно контролировать поведение копирования.

### Всегда ли `deepcopy()` создаёт полностью независимый объект?

Нет. Результат зависит от типов вложенных объектов и их реализации копирования. Кроме того, некоторые объекты намеренно сохраняют общие ссылки или не поддерживают копирование.

### Когда Prototype лучше конструктора?

Когда повторное создание объекта сложно или дорого, а существующий экземпляр уже содержит подходящее состояние и настройки.

### Что такое `__deepcopy__()`?

Это специальный метод, который позволяет классу определять собственное поведение при глубоком копировании.
