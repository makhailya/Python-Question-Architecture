ООП: подход к программированию, при котором логика приложения строится вокруг классов (шаблонов) и объектов (экземпляров), которые инкапсулируют данные и поведение и взаимодействуют между собой через методы.

# 1.  Инкапсуляция

Сокрытие внутренней реализации и защита данных от произвольного доступа извне.

```python
class User:
    def __init__(self, name, password):
        self.name = name          # публичный атрибут
        self._password = password # "приватный" по соглашению — не трогай снаружи
        self.__secret = "xyz"     # name mangling

u = User("Ilya", "1234")
print(u._password)     # доступно, но так делать не стоит по договорённости
print(u.__secret)      # AttributeError!
print(u._User__secret) # а вот так — сработает, Python просто переименовал атрибут
```

В Python нет настоящей приватности как в Java/C++ — только договорённость (_) и «затруднение доступа» через переименование (__).

# 2. Наследование и MRO

```python
class A:
    def greet(self):
        return "A"

class B(A):
    pass

class C(A):
    def greet(self):
        return "C"

class D(B, C):
    pass

print(D().greet())  # "C" — благодаря C3-линеаризации (MRO)
print(D.__mro__)
```

MRO (Method Resolution Order) определяет порядок, в котором Python ищет метод по иерархии классов при множественном наследовании. Современный Python использует алгоритм C3-линеаризации — по сути это поиск в ширину (BFS-подобный), а не «слева направо в глубину», как было в очень старых схемах наследования без единого корня (object).

# 3. Полиморфизм

## Одинаковый интерфейс метода — разное поведение в зависимости от объекта.

1. Динамический полиморфизм — привычный для Python: переопределение метода в классах-наследниках, разрешается в рантайме (по факту это тесно связано с наследованием / duck typing).

2. Статический полиморфизм — в Python нет как встроенной языковой концепции (в отличие от C++ со строгой типизацией), но есть похожие инструменты:
	1. Ad hoc полиморфизм (перегрузка функций) — через functools.singledispatch, позволяет диспетчеризовать вызов в зависимости от типа аргумента. Формально это не «настоящая» перегрузка (как в C++), а набор разных функций, между которыми диспетчер выбирает нужную.

	2. Параметрический полиморфизм — обобщённый (generic) код, работающий с любыми типами. В Python — через typing.TypeVar / Generic (современная альтернатива — синтаксис class Stack[T]).

# 4. Абстракция: ABC vs Protocol

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...

    def describe(self):          # обычный метод — можно реализовать полностью
        return f"Площадь: {self.area()}"

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        return 3.14 * self.r ** 2
```

1. ABC (абстрактный базовый класс) — задаёт контракт через @abstractmethod; наследник обязан реализовать эти методы, иначе экземпляр не создастся. При этом ABC может содержать и полностью реализованные обычные методы — это не запрещено.

2. Protocol (typing.Protocol) — более мягкий вариант: не требует явного наследования. Если объект реализует все методы, описанные в протоколе — он считается соответствующим протоколу (структурная типизация / duck typing).
