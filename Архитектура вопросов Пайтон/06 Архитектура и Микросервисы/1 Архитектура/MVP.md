# 🚀 MVP — Minimum Viable Product

## 🎯 Ответ на собеседовании

**MVP (Minimum Viable Product)** — это **минимально жизнеспособный продукт**, который содержит только необходимые функции для решения основной проблемы пользователя и позволяет **проверить бизнес-гипотезу на реальных пользователях**.

Главная идея MVP — не создать сразу полноценный продукт, а **быстро проверить, нужен ли он пользователям**, потратив минимальные ресурсы.

Например, если мы хотим создать сервис доставки еды:

```text
Полный продукт:
├── мобильное приложение
├── рекомендации
├── бонусная система
├── онлайн-оплата
├── карта курьера
├── push-уведомления
└── аналитика

MVP:
└── сайт → выбор еды → заказ → доставка
```

# 🎯 Зачем нужен MVP

Главная задача MVP — **проверить гипотезу**, а не сделать плохую или урезанную версию готового продукта.

Например, есть гипотеза:

> Пользователи готовы платить за сервис автоматического анализа банковских операций.

Вместо создания сложной платформы можно сделать:

```text
CSV-файл
   ↓
Python-скрипт
   ↓
Анализ транзакций
   ↓
Отчёт
```

Если пользователи действительно используют и оплачивают решение, продукт можно развивать дальше.

---

# 🧩 Основные характеристики MVP

### 1. Минимальный набор функций

В MVP реализуют только то, что необходимо для проверки основной гипотезы.

```text
Не:
100 функций

А:
3–5 ключевых функций
```

### 2. Реальная ценность

MVP должен решать **реальную проблему пользователя**.

Просто набор недоделанных функций — не MVP.

### 3. Реальные пользователи

MVP желательно проверять на реальных пользователях, а не только внутри команды.

### 4. Быстрая обратная связь

Получаем:

```text
Пользователь
   ↓
использование продукта
   ↓
Feedback
   ↓
изменение продукта
```

# 🔄 Цикл MVP

```text
Гипотеза
   ↓
MVP
   ↓
Пользователи
   ↓
Метрики + Feedback
   ↓
Анализ
   ↓
Улучшение
   ↓
Новая версия
```

Это позволяет постепенно развивать продукт на основании реальных данных.

---

# 🆚 MVP vs готовый продукт

| MVP                       | Полный продукт           |
| ------------------------- | ------------------------ |
| Минимальный набор функций | Полный набор функций     |
| Быстрый запуск            | Долгая разработка        |
| Проверка гипотезы         | Масштабирование продукта |
| Минимальные затраты       | Более высокие затраты    |
| Может быть простым        | Должен быть полноценным  |

---

# ⚠️ Частая ошибка

Неправильно:

> MVP — это просто недоделанный продукт.

Правильно:

> **MVP — это минимальная версия продукта, специально созданная для проверки ключевой гипотезы на реальных пользователях.**

MVP может быть технически простым, но он должен **решать основную задачу пользователя**.

# 🐍 Пример для Python-разработчика

Допустим, нужно создать сервис поиска вакансий.

Полная система:

```text
FastAPI
PostgreSQL
Redis
Celery
Docker
Frontend
Telegram Bot
ML-рекомендации
Analytics
```

MVP:

```text
HH.ru API
   ↓
Python
   ↓
Фильтрация вакансий
   ↓
Telegram
```

Если пользователям нужен такой сервис, дальше можно добавлять:

```text
PostgreSQL
Redis
Celery
FastAPI
Web-интерфейс
ML-рекомендации
```

### Формулировка для собеседования

> **MVP — Minimum Viable Product, минимально жизнеспособный продукт. Это версия продукта с минимальным набором функций, которая уже приносит ценность пользователю и позволяет проверить основную бизнес-гипотезу на реальных пользователях с минимальными затратами.**
