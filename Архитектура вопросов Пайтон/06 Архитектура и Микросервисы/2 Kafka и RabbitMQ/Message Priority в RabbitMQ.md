# Message Priority в RabbitMQ 🚦

## 🎯 Ответ на собеседовании

**Message Priority позволяет назначать сообщениям разный приоритет внутри RabbitMQ Queue. Сообщения с более высоким приоритетом могут обрабатываться раньше сообщений с низким приоритетом.**

Для этого:

1. Queue создаётся с параметром `x-max-priority`.
2. Producer указывает `priority` у сообщения.
3. RabbitMQ учитывает приоритет при доставке Consumer'у.

Например:

```python
priority = 10
```

означает более высокий приоритет, чем:

```python
priority = 1
```

**Важно:** Priority влияет на порядок доставки из Queue, но не означает абсолютную гарантию порядка обработки, особенно при нескольких Consumer'ах и уже доставленных `unacked` сообщениях.

---

## 🎤 Суперкоротко

```text
Queue
  ↓
messages:
  priority 1
  priority 5
  priority 10
        ↓
Consumer получает сначала более приоритетные
```

Настройка Queue:

```python
x-max-priority = 10
```

Сообщение:

```python
priority = 8
```

---

# Зачем нужен Priority

Представим очередь задач:

```text
task_queue
```

В ней:

```text
Обычная задача       priority=1
Важная задача        priority=5
Критичная задача     priority=10
```

Если Consumer свободен, RabbitMQ может отдать ему:

```text
priority=10
```

раньше:

```text
priority=1
```

Это позволяет выделять важные сообщения.

---

# Как включить Priority

Priority нужно разрешить на уровне Queue.

Например:

```python
queue_arguments = {
    "x-max-priority": 10
}
```

Это означает, что Queue поддерживает приоритеты до `10`.

После этого Producer может указывать:

```python
priority = 5
```

---

# Пример

Допустим:

```python
queue_arguments = {
    "x-max-priority": 10
}
```

В очередь попали:

```text
message A → priority 1
message B → priority 10
message C → priority 5
```

При наличии свободного Consumer порядок доставки может быть примерно:

```text
B → C → A
```

Потому что:

```text
10 > 5 > 1
```

---

# Priority задаёт Producer

Producer при публикации сообщения может указать priority.

Концептуально:

```python
properties = {
    "priority": 10
}
```

Например:

```python
message = "critical task"
priority = 10
```

RabbitMQ сохраняет эту информацию вместе с сообщением.

---

# Priority — это не Routing Key

Не путай:

### Routing Key

Определяет:

```text
в какую Queue направить сообщение
```

### Priority

Определяет:

```text
какое сообщение отдавать Consumer'у раньше
```

Схематично:

```text
Producer
   │
   │ routing_key
   ▼
Exchange
   │
   ▼
Queue
   │
   │ priority
   ▼
Consumer
```

---

# Priority не выбирает Queue

Например:

```text
routing_key = "order.created"
priority = 10
```

Routing Key используется для маршрутизации:

```text
Exchange → orders_queue
```

А Priority используется уже внутри Queue:

```text
orders_queue
      ↓
priority
      ↓
Consumer
```

---

# Что такое `x-max-priority`

Это аргумент Queue:

```python
x-max-priority = 10
```

Он задаёт максимальный уровень приоритета, поддерживаемый Queue.

Например:

```text
x-max-priority = 10
```

можно использовать с:

```text
priority = 0
priority = 1
priority = 5
priority = 10
```

Чем выше число, тем выше приоритет.

---

# Что будет с Priority выше максимального

Если Queue настроена:

```text
x-max-priority = 10
```

а Producer отправляет:

```text
priority = 20
```

RabbitMQ не превращает это в отдельный уровень `20`.

Значение будет ограничено максимальным уровнем Queue.

Поэтому Producer и Queue должны иметь согласованную модель приоритетов.

---

# Priority по умолчанию

Если сообщение не содержит priority, оно фактически рассматривается как сообщение с низким/обычным приоритетом.

Упрощённо можно считать:

```text
priority = 0
```

---

# Несколько Consumer'ов

Здесь появляется важный нюанс.

Допустим:

```text
Queue
  ↓
Consumer 1
Consumer 2
Consumer 3
```

Сообщения распределяются между Consumer'ами.

Priority влияет на то, какие сообщения RabbitMQ предпочитает доставлять из Queue, но он **не может забрать сообщение, которое уже было доставлено другому Consumer'у**.

Например:

```text
Queue
  ↓
Consumer 1 ← message A
Consumer 2 ← message B
```

Если сообщение уже находится у Consumer в состоянии:

```text
unacked
```

его priority уже не заставит RabbitMQ вернуть его обратно и заменить другим сообщением.

---

# Priority и Prefetch

Priority особенно важно рассматривать вместе с `prefetch`.

Например:

```text
prefetch = 10
```

Consumer может получить несколько сообщений заранее.

Получается:

```text
Queue
  ↓
Consumer
  ├── message A
  ├── message B
  ├── message C
  └── ...
```

Если низкоприоритетные сообщения уже были доставлены Consumer'у, появившееся позже высокоприоритетное сообщение не сможет просто «перепрыгнуть» через уже доставленные сообщения.

Поэтому:

> **Priority влияет прежде всего на порядок доставки из Queue, а не на порядок фактического завершения обработки.**

---

# Priority и ACK

Priority не заменяет ACK.

Например:

```text
Queue
  ↓
Consumer
  ↓
priority=10
  ↓
processing
  ↓
ACK
```

ACK по-прежнему подтверждает успешную обработку.

Priority отвечает только за предпочтительный порядок доставки.

---

# Priority и порядок обработки

Допустим:

```text
A priority=1
B priority=10
```

RabbitMQ может доставить:

```text
B
A
```

Но это не означает, что B обязательно завершится раньше A.

Например:

```text
B → сложная обработка → 10 секунд
A → простая обработка → 1 секунда
```

Получится:

```text
A завершилась раньше B
```

Поэтому:

```text
Priority
≠
гарантированный порядок завершения
```

---

# Priority и Starvation

Есть проблема **starvation** — голодание низкоприоритетных сообщений.

Представим:

```text
priority=10 → постоянно приходят новые задачи
priority=1  → ждут
```

Если поток высокоприоритетных сообщений не прекращается:

```text
priority=1
    ↓
ждёт
    ↓
ждёт
    ↓
ждёт
```

Низкоприоритетные задачи могут очень долго не получать обработку.

Поэтому Priority следует использовать аккуратно.

---

# Priority vs несколько Queue

Иногда вместо Priority используют отдельные Queue.

Например:

```text
critical_queue
normal_queue
low_queue
```

И Consumer сам выбирает, какую Queue читать.

### Priority Queue

```text
Queue
 ├── priority 10
 ├── priority 5
 └── priority 1
```

### Несколько Queue

```text
critical_queue
normal_queue
low_queue
```

У обоих подходов есть плюсы и минусы.

---

# Priority vs отдельные Queue

| Priority                            | Отдельные Queue               |
| ----------------------------------- | ----------------------------- |
| Один Queue                          | Несколько Queue               |
| Приоритет у сообщения               | Приоритет определяется Queue  |
| Проще модель маршрутизации          | Больше контроля               |
| Возможен starvation                 | Можно отдельно масштабировать |
| Удобно для умеренного числа уровней | Удобно для сложных политик    |

---

# Когда использовать Priority

Подходит, например, для:

* критичных задач;
* срочных уведомлений;
* VIP-задач;
* фоновых задач разной важности;
* обработки заявок с разными SLA.

Например:

```text
priority=10 → аварийная задача
priority=5  → обычная бизнес-задача
priority=1  → фоновая аналитика
```

---

# Когда Priority может быть плохим выбором

Если приоритетная модель становится очень сложной:

```text
10 уровней
разные SLA
разные Consumer
разные команды
разные лимиты
```

может быть проще использовать отдельные Queue:

```text
critical_queue
normal_queue
background_queue
```

Это также позволяет независимо масштабировать Consumer'ов.

---

# Priority и Kafka

RabbitMQ Priority Queue и Kafka работают по разной модели.

RabbitMQ:

```text
Queue
   ↓
priority
   ↓
Consumer
```

Kafka:

```text
Topic
   ↓
Partition
   ↓
Offset
```

Kafka не является обычной priority queue.

Если нужна приоритизация в Kafka, её обычно проектируют на уровне архитектуры, например через разные Topic/Partition или логику Consumer.

---

# Priority и FIFO

Обычная Queue часто воспринимается как FIFO:

```text
First In
   ↓
First Out
```

Но Priority меняет это поведение.

Например:

```text
Пришли:

A priority=1
B priority=10
C priority=5
```

Вместо:

```text
A → B → C
```

может быть:

```text
B → C → A
```

То есть Priority позволяет отступить от обычного FIFO.

---

# Priority и Retry

Priority можно комбинировать с Retry.

Например:

```text
Main Queue
    ↓
Consumer
    ↓
ошибка
    ↓
Retry Queue
    ↓
TTL
    ↓
DLX
    ↓
Main Queue
```

При возврате сообщения можно сохранить или изменить его приоритет в зависимости от архитектуры.

Но важно не допустить ситуации, когда Retry-задачи постоянно вытесняют обычные задачи.

---

# Priority и DLQ

Если сообщение не удалось обработать после нескольких попыток:

```text
Main Queue
    ↓
Retry
    ↓
Retry
    ↓
Retry
    ↓
DLQ
```

Priority может использоваться и в основной очереди, но DLQ обычно предназначена для анализа и ручной/отдельной обработки проблемных сообщений.

---

# Пример backend

Представим сервис обработки заявок:

```text
critical → priority=10
normal   → priority=5
background → priority=1
```

Producer:

```python
message = "Process application"
priority = 10
```

Queue:

```python
queue_arguments = {
    "x-max-priority": 10
}
```

Consumer получает сначала более важные ожидающие сообщения.

# Частые вопросы на собеседовании

### Что такое Message Priority?

> Механизм RabbitMQ, позволяющий назначать сообщениям разный приоритет и отдавать более приоритетные сообщения раньше низкоприоритетных.

### Где настраивается максимальный приоритет?

На уровне Queue через:

```python
x-max-priority
```

### Где задаётся priority сообщения?

Producer указывает его в свойствах сообщения.

### Priority влияет на маршрутизацию?

Нет.

Маршрутизация выполняется через Exchange, Binding и Routing Key.

### Priority гарантирует порядок обработки?

Нет.

Он влияет на порядок доставки из Queue. Consumer может обрабатывать сообщения параллельно, а уже доставленные сообщения нельзя переставить местами.

### Что такое starvation?

Ситуация, когда низкоприоритетные сообщения долго не получают обработки из-за постоянного потока высокоприоритетных.

### Priority и ACK — одно и то же?

Нет.

Priority определяет предпочтительный порядок доставки, ACK подтверждает успешную обработку.

### Priority и Prefetch связаны?

Да. Большой `prefetch` может привести к тому, что низкоприоритетные сообщения уже будут заранее доставлены Consumer'у, поэтому высокоприоритетное сообщение не сможет полностью изменить фактический порядок обработки.

### Priority Queue или несколько Queue?

Зависит от задачи. Priority удобен для простой модели приоритетов, а отдельные Queue дают больше контроля и позволяют независимо масштабировать разные классы задач.

---

# 🧠 Итоговая схема

```text
Producer
   │
   │ routing_key
   ▼
Exchange
   │
   ▼
Queue
   │
   ├── priority=10
   ├── priority=5
   ├── priority=1
   │
   ▼
Consumer
```

### Главная мысль

```text
Routing Key → КУДА отправить
Priority    → ЧТО отдавать раньше
Prefetch    → СКОЛЬКО можно выдать заранее
ACK         → УСПЕШНО ли обработано
TTL         → СКОЛЬКО сообщение актуально
```

### Формула для собеседования

> **RabbitMQ Priority позволяет назначать сообщениям приоритет внутри Queue. Для этого Queue создаётся с `x-max-priority`, а Producer указывает `priority` сообщения. Более приоритетные сообщения могут доставляться раньше низкоприоритетных, но Priority не гарантирует порядок завершения обработки и может приводить к starvation.**
