# 💾 COMMIT в транзакциях

## 🎯 Ответ на собеседовании

**COMMIT** — SQL-команда, которая завершает транзакцию и фиксирует все выполненные в ней изменения.

После `COMMIT` изменения становятся постоянными и видимыми другим транзакциям согласно правилам изоляции.

```text id="w5f7rm"
BEGIN
  ↓
INSERT
UPDATE
DELETE
  ↓
COMMIT
  ↓
изменения зафиксированы
```

Если во время транзакции произошла ошибка до `COMMIT`, можно выполнить:

```python id="4a1f9b"
ROLLBACK
```

и отменить изменения транзакции.

---

## 🎤 Суперкоротко

> **COMMIT — зафиксировать изменения текущей транзакции. После COMMIT обычный ROLLBACK уже не отменит эти изменения.**

```text id="0h5x3c"
BEGIN
  ↓
операции
  ↓
COMMIT → сохранить
```

или:

```text id="q2m8vd"
BEGIN
  ↓
операции
  ↓
ROLLBACK → отменить
```

---

# 🔹 Пример

```python id="z8m3kv"
BEGIN;

UPDATE accounts
SET balance = balance - 1000
WHERE id = 1;

UPDATE accounts
SET balance = balance + 1000
WHERE id = 2;

COMMIT;
```

До `COMMIT` изменения относятся к текущей транзакции.

После:

```text id="j7r2qp"
COMMIT
  ↓
транзакция завершена
  ↓
изменения зафиксированы
```

---

# 🔄 COMMIT vs ROLLBACK

| Команда    | Результат                             |
| ---------- | ------------------------------------- |
| `COMMIT`   | Зафиксировать изменения               |
| `ROLLBACK` | Отменить изменения текущей транзакции |

```text id="5p8n2x"
             Transaction
                  │
          ┌───────┴───────┐
          ↓               ↓
       COMMIT          ROLLBACK
          ↓               ↓
       сохранить       отменить
```

---

# 🔹 Что происходит после COMMIT

Допустим:

```text id="n4m8qa"
balance = 1000
```

В транзакции:

```python id="k3v7fz"
UPDATE accounts
SET balance = 500
WHERE id = 1;
```

Затем:

```python id="h2p9wc"
COMMIT;
```

Теперь изменение зафиксировано:

```text id="7x4m1b"
balance = 500
```

Если после этого выполнить:

```python id="e6r3zs"
ROLLBACK;
```

это уже **не отменит** предыдущий `COMMIT`.

---

# 🔒 COMMIT и блокировки

Транзакция может удерживать блокировки.

Например:

```python id="u8n2kd"
BEGIN;

SELECT *
FROM accounts
WHERE id = 1
FOR UPDATE;
```

Строка заблокирована для конфликтующих операций.

После:

```python id="p5v7qa"
COMMIT;
```

транзакция завершается, и её блокировки освобождаются.

```text id="c4x9mz"
BEGIN
  ↓
LOCK
  ↓
UPDATE
  ↓
COMMIT
  ↓
UNLOCK
```

Поэтому долго открытая транзакция может мешать другим операциям.

---

# ⚛️ COMMIT и Atomicity

Представим перевод:

```text id="r9k3tw"
A: -1000
B: +1000
```

Обе операции находятся в одной транзакции:

```text id="v2m6qa"
BEGIN
  ↓
A -1000
  ↓
B +1000
  ↓
COMMIT
```

После `COMMIT` обе операции зафиксированы.

Если вторая операция завершилась ошибкой:

```text id="f7n1xp"
BEGIN
  ↓
A -1000
  ↓
B +1000 ❌
  ↓
ROLLBACK
```

Изменения транзакции отменяются.

---

# 🛡️ COMMIT и Durability

`D` в ACID — **Durability**.

После успешного `COMMIT` СУБД должна обеспечить сохранность зафиксированных изменений даже при последующем сбое системы, в рамках гарантий конкретной СУБД и её конфигурации.

Упрощённо:

```text id="d8q4vm"
COMMIT
  ↓
изменения зафиксированы
  ↓
crash
  ↓
данные должны сохраниться
```

---

# 👀 COMMIT и видимость данных

До `COMMIT` изменения одной транзакции обычно не должны быть видны другим транзакциям как обычные зафиксированные изменения.

Например:

```text id="x6m2rk"
Transaction A
balance = 500
      │
      │ не COMMIT
      ↓
Transaction B
видит прежнее состояние
```

Точное поведение зависит от **изоляции транзакций** и конкретной СУБД.

---

# 🧩 COMMIT в Python

Например, с низкоуровневым DB API:

```python id="q4v8ns"
connection.begin()

cursor.execute(
    "UPDATE accounts SET balance = balance - %s WHERE id = %s",
    (1000, 1),
)

connection.commit()
```

При ошибке:

```python id="m7x2cd"
connection.rollback()
```

В ORM это обычно выглядит удобнее.

Например, Django:

```python id="w9k3qa"
from django.db import transaction

with transaction.atomic():
    account.balance -= 1000
    account.save()

    target.balance += 1000
    target.save()
```

При успешном завершении блока транзакция фиксируется.

---

# 🔄 COMMIT и внешний API

Важный архитектурный момент.

Плохо делать длинную транзакцию:

```text id="k8v4mz"
BEGIN
  ↓
UPDATE DB
  ↓
HTTP request → внешний сервис
  ↓
ждать ответа
  ↓
COMMIT
```

Пока внешний сервис отвечает, транзакция остаётся открытой.

Лучше минимизировать время транзакции.

При распределённых операциях вместо попытки удерживать одну транзакцию через несколько сервисов используют паттерны вроде:

```text id="n3p7xr"
Saga
Outbox
```

---

# 🔗 COMMIT + Idempotency

Например:

```text id="u5m8qz"
BEGIN
  ↓
создать Payment
  ↓
сохранить Idempotency Key
  ↓
COMMIT
```

После `COMMIT`:

```text id="c7x2va"
Payment создан
+
Idempotency Key сохранён
```

При retry:

```text id="p9r4mk"
тот же key
   ↓
найден в БД
   ↓
не создавать Payment повторно
```

Здесь важно, чтобы бизнес-изменение и запись состояния идемпотентности были согласованы в одной транзакции, если они находятся в одной БД.

---

# ⚠️ COMMIT ≠ просто «сохранить строку»

`COMMIT` завершает **всю текущую транзакцию**, а не только последнюю SQL-команду.

Например:

```python id="x6v3nb"
BEGIN;

INSERT ...;
UPDATE ...;
DELETE ...;

COMMIT;
```

Все три изменения входят в одну транзакцию.

---

# ⚠️ COMMIT и автокоммит

Во многих приложениях используется **autocommit**.

В этом режиме отдельная SQL-команда автоматически фиксируется после успешного выполнения, если она не выполняется внутри явно открытой транзакции.

Упрощённо:

```text id="j2m8vq"
INSERT
  ↓
COMMIT автоматически
```

Если нужна группа операций как единое целое, используют явную транзакцию.

---

# 🧠 Главное

```text id="s7q4kc"
BEGIN
  ↓
SQL operations
  ↓
COMMIT
  ↓
изменения зафиксированы
```

или:

```text id="f8m2xz"
BEGIN
  ↓
SQL operations
  ↓
ERROR
  ↓
ROLLBACK
  ↓
изменения отменены
```

### Формула для собеседования

> **COMMIT завершает транзакцию и фиксирует выполненные в ней изменения. После успешного COMMIT они становятся постоянными, а удерживаемые транзакцией блокировки освобождаются при завершении транзакции. COMMIT является частью механизма ACID, в частности связан с атомарностью и долговечностью.**
