# Timeout — конспект для Python Backend

## Формула для собеседования

**Timeout = ограничение времени ожидания операции, после которого система прекращает ждать результат и выполняет предусмотренную обработку ошибки.**

## Короткий ответ

Timeout защищает приложение от бесконечного ожидания ответа от базы данных, внешнего API, брокера сообщений или другого сервиса.

Если операция не завершается за установленное время, клиент прекращает ожидание. Однако timeout не всегда означает, что операция на сервере действительно остановилась: запрос мог продолжить выполняться, даже если клиент уже получил ошибку.

## Ответ на собеседовании

Timeout — это механизм ограничения времени выполнения или ожидания операции. Он необходим, чтобы приложение не зависало при медленных ответах внешних сервисов, сетевых сбоях или проблемах с базой данных.

Например, Python Backend отправляет запрос к платёжному сервису. Если ответ не приходит за пять секунд, приложение прекращает ждать, обрабатывает timeout и при необходимости выполняет повторную попытку или возвращает ошибку клиенту.

Таймауты нужно настраивать на всех важных участках взаимодействия: HTTP-клиенте, подключении к базе данных, выполнении запроса и ожидании ответа от другого сервиса. При этом важно учитывать общий бюджет времени запроса и не повторять автоматически операции, которые могли успешно выполниться на удалённой стороне.

## 1. Зачем нужен Timeout

Представим цепочку запросов:

```text
Client
  |
  v
FastAPI
  |
  v
Service A
  |
  v
Service B
  |
  v
Database
```

Если `Service B` зависнет, `Service A` может продолжать ждать. В результате запросы накапливаются, занятые ресурсы не освобождаются, а приложение постепенно перестаёт обрабатывать новые запросы.

Timeout ограничивает время ожидания и помогает контролировать расход ресурсов.

Основные задачи:

- предотвращать бесконечное ожидание;
- ограничивать время ответа API;
- освобождать соединения и другие ресурсы;
- ограничивать влияние медленных зависимостей;
- обеспечивать предсказуемое поведение системы при сбоях.

**Важно:** timeout не гарантирует отмену удалённой операции. Он может ограничить только ожидание на стороне клиента.

## 2. Основные виды Timeout

| Вид | Что ограничивает |
|---|---|
| Connection timeout | Время установления соединения |
| Read timeout | Время ожидания данных или ответа |
| Write timeout | Время отправки данных |
| Request timeout | Общую длительность запроса — если это предусмотрено механизмом |
| Database statement timeout | Время выполнения SQL-команды |
| Pool timeout | Время ожидания свободного соединения из пула |
| Idle timeout | Время простоя соединения или ресурса |

### Connection timeout

Ограничивает время, за которое клиент должен установить соединение с сервером.

Например, если внешний API недоступен, приложение не должно бесконечно пытаться установить TCP-соединение.

### Read timeout

Ограничивает ожидание данных от удалённой стороны. Точная семантика зависит от библиотеки: например, timeout может относиться к ожиданию очередного блока данных, а не ко всей продолжительности скачивания.

### Request timeout

Ограничивает общее время выполнения операции от начала до завершения. Не все HTTP-клиенты предоставляют единый timeout с такой семантикой.

## 3. Timeout в Python: requests

```python
import requests


try:
    response = requests.get(
        "https://api.example.com/users",
        timeout=(2, 5),
    )
    response.raise_for_status()
except requests.exceptions.Timeout:
    print("Время ожидания ответа истекло")
except requests.exceptions.RequestException as exc:
    print(f"Ошибка HTTP-запроса: {exc}")
```

Здесь:

- `2` — timeout соединения;
- `5` — timeout чтения.

Это не обязательно означает, что весь запрос завершится максимум за семь секунд: семантика timeout зависит от этапа соединения и передачи данных.

## 4. Timeout в асинхронном Python

В `asyncio` можно ограничить время ожидания асинхронной операции.

```python
import asyncio


async def fetch_data():
    await asyncio.sleep(10)
    return {"status": "ok"}


async def main():
    try:
        async with asyncio.timeout(3):
            result = await fetch_data()
            print(result)
    except TimeoutError:
        print("Операция превысила лимит времени")


asyncio.run(main())
```

В этом примере операция занимает десять секунд, но контекст ожидания ограничен тремя секундами.

`asyncio.timeout()` доступен в Python 3.11 и новее. Механизм использует отмену задачи, но корректность отмены зависит от того, как операция обрабатывает cancellation. Если внутри выполняется блокирующий код или работа с внешней системой, её фактическое прекращение не гарантируется.

## 5. Timeout в FastAPI

FastAPI сам по себе не устанавливает универсальный timeout на выполнение каждого обработчика. Ограничения могут задаваться на уровне reverse proxy, ASGI-сервера, middleware, клиента или отдельной операции.

Например, для внешнего API с HTTPX:

```python
import httpx
from fastapi import FastAPI, HTTPException

app = FastAPI()


@app.get("/external-data")
async def get_external_data():
    timeout = httpx.Timeout(
        connect=2.0,
        read=5.0,
        write=5.0,
        pool=1.0,
    )

    try:
        async with httpx.AsyncClient(timeout=timeout) as client:
            response = await client.get(
                "https://api.example.com/data"
            )
            response.raise_for_status()
            return response.json()

    except httpx.TimeoutException:
        raise HTTPException(
            status_code=504,
            detail="Внешний сервис не ответил вовремя",
        )
    except httpx.HTTPError:
        raise HTTPException(
            status_code=502,
            detail="Ошибка внешнего сервиса",
        )
```

Для реального сервиса `AsyncClient` обычно создают один раз на время жизни приложения и переиспользуют, а не создают заново при каждом запросе.

Здесь `504 Gateway Timeout` означает, что приложение выступает посредником и не получило своевременный ответ от зависимости. Выбор HTTP-кода зависит от роли сервиса и конкретной ошибки.

## 6. Timeout в PostgreSQL

В PostgreSQL можно ограничить время выполнения SQL-команды через `statement_timeout`.

```sql
SET statement_timeout = '3s';

SELECT *
FROM orders
WHERE user_id = 42;
```

Если выполнение команды превышает установленный предел, PostgreSQL отменяет её выполнение и возвращает ошибку.

Для приложения настройку можно задавать на уровне сессии, транзакции или конфигурации сервера — в зависимости от задачи. Не следует бездумно устанавливать глобально слишком маленький лимит: он может прерывать допустимые аналитические запросы и миграции.

Также существуют другие ограничения, например `lock_timeout`, который ограничивает ожидание блокировки.

## 7. Как выбирать значение Timeout

Timeout должен зависеть от назначения операции и общего бюджета времени ответа.

| Операция | Принцип настройки |
|---|---|
| Внутренний быстрый API | Небольшой лимит, исходя из измеренной задержки |
| Внешний HTTP API | Отдельные лимиты соединения и чтения |
| SQL-запрос | С учётом ожидаемой длительности и критичности |
| Получение соединения из пула | Ограничить ожидание свободного соединения |
| Фоновая задача | Отдельный бюджет с учётом SLA задачи |

Не существует универсального значения, подходящего для всех сервисов. Настройки определяют на основе измеренных задержек, SLO и требований бизнеса.

### Бюджет времени

Допустим, общий бюджет HTTP-запроса — две секунды:

```text
Общий бюджет: 2 секунды
├── Проверка прав: 100 мс
├── Запрос к БД: 400 мс
├── Внешний API: 1000 мс
└── Прочие операции и запас: 500 мс
```

Это пример распределения, а не рекомендуемые значения для любого приложения.

Если каждый вложенный вызов имеет собственный timeout в пять секунд, общий запрос может выполняться значительно дольше ожидаемого. Поэтому важно передавать оставшийся deadline по цепочке вызовов.

## 8. Timeout, Retry и Circuit Breaker

Эти механизмы дополняют друг друга, но не заменяют друг друга.

| Механизм | Задача |
|---|---|
| Timeout | Ограничить время ожидания |
| Retry | Повторить временно неудачную операцию |
| Exponential Backoff | Увеличивать паузу между повторами |
| Circuit Breaker | Временно прекращать вызовы проблемной зависимости |
| Bulkhead | Ограничивать ресурсы, выделенные конкретной зависимости |
| Deadline Propagation | Передавать общий временной бюджет между сервисами |

Типичная комбинация:

```text
Запрос
  |
  v
Timeout
  |
  v
Временная ошибка?
  |
  +-- Да --> Retry с Backoff
  |               |
  |               v
  |        Лимит попыток исчерпан?
  |               |
  |               v
  |        Circuit Breaker / ошибка
  |
  +-- Нет --> Результат
```

Повторять запросы нужно только в пределах общего бюджета времени. Иначе retries могут увеличить нагрузку и усугубить сбой.

Подробнее: [[Retry]], [[Exponential Backoff]], [[Circuit Breaker]].

## 9. Опасность повторных запросов

Предположим, приложение отправило запрос на списание денег. Платёжный сервис выполнил операцию, но ответ потерялся в сети.

Клиент получил timeout и не знает, была ли операция выполнена. Если он просто повторит запрос, деньги могут списаться дважды.

Для операций с побочными эффектами нужны:

- idempotency key;
- проверка статуса операции;
- уникальный идентификатор бизнес-операции;
- безопасная стратегия повторов.

**Timeout означает отсутствие своевременного ответа, а не доказательство того, что операция не произошла.**

## 10. Частые ошибки

- Не задавать timeout вообще.
- Устанавливать одинаковые значения для всех зависимостей.
- Путать read timeout с общим временем выполнения.
- Считать, что timeout автоматически останавливает удалённый сервер.
- Повторять любые запросы без учёта идемпотентности.
- Настраивать вложенные timeout без общего бюджета времени.
- Возвращать пользователю технический traceback вместо контролируемой ошибки.
- Не отслеживать частоту timeout и распределение задержек.

## 11. Частые вопросы на собеседовании

**Что такое Timeout?**

Ограничение времени ожидания операции, после которого система перестаёт ждать и выполняет предусмотренную обработку ошибки.

**Чем Connection Timeout отличается от Read Timeout?**

Connection timeout ограничивает установление соединения, а read timeout — ожидание данных от удалённой стороны.

**Останавливает ли Timeout выполнение операции на сервере?**

Не обязательно. Клиент может прекратить ожидание, а удалённая операция продолжит выполняться. Для реальной отмены нужны поддержка со стороны сервера и корректная обработка cancellation.

**Можно ли всегда делать Retry после Timeout?**

Нет. Сначала нужно понять, безопасно ли повторять операцию. Для изменяющих состояние запросов важны идемпотентность и проверка результата предыдущей попытки.

**Как Timeout связан с Circuit Breaker?**

Timeout ограничивает отдельный вызов. Circuit Breaker отслеживает сбои и может временно блокировать последующие вызовы проблемной зависимости.

**Как настроить Timeout в асинхронном Python?**

Можно использовать `asyncio.timeout()` для ограничения времени ожидания асинхронного участка, а также timeout конкретной библиотеки, например HTTPX или драйвера БД.

**Почему нельзя поставить всем сервисам Timeout в пять секунд?**

У сервисов разные требования к задержке, профили нагрузки и бюджеты времени. Универсальное значение может оказаться слишком большим для критичного API и слишком маленьким для длительной операции.

## 12. Шпаргалка

- Timeout ограничивает ожидание операции.
- Connection timeout — установление соединения.
- Read timeout — ожидание данных.
- Statement timeout — выполнение SQL-команды.
- Timeout не гарантирует остановку удалённой операции.
- Retry нужно ограничивать и применять безопасно.
- Для изменяющих операций важна идемпотентность.
- В распределённых системах нужно учитывать общий deadline.
- Настройки должны соответствовать SLA и измеренным задержкам.
