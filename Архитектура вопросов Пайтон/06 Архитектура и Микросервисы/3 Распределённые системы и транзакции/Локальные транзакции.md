# 🔹 Локальные транзакции

## 🎯 Ответ на собеседовании

**Локальная транзакция** — это транзакция, которая выполняется **в пределах одного сервиса и одного управляемого им ресурса**, обычно одной базы данных.

Например:

```text id="p7k3m1"
Order Service
      ↓
   Order DB
      ↓
BEGIN
  ↓
Создать заказ
  ↓
COMMIT
```

Такая транзакция не охватывает базы данных других микросервисов.

---

## 🎤 Суперкоротко

**Локальная транзакция — это транзакция внутри одного сервиса, которая выполняется атомарно в его собственной БД.**

---

## 🧩 Почему называется локальной

Представим три микросервиса:

```text id="m9x4q2"
Order Service
     ↓
Order DB

Payment Service
     ↓
Payment DB

Product Service
     ↓
Product DB
```

Каждый сервис выполняет свою **локальную транзакцию**:

```text id="v2c8n5"
Order Service
     ↓
Order DB
BEGIN
 ↓
Create Order
 ↓
COMMIT
```

И отдельно:

```text id="q6r1t8"
Payment Service
     ↓
Payment DB
BEGIN
 ↓
Create Payment
 ↓
COMMIT
```

Это две разные транзакции.

---

# 🔄 Локальная транзакция в Saga

Saga строится именно из таких локальных транзакций.

Например:

```text id="a8k5z3"
Create Order
     ↓
локальная транзакция
     ↓
COMMIT
     ↓
Reserve Product
     ↓
локальная транзакция
     ↓
COMMIT
     ↓
Charge Payment
     ↓
локальная транзакция
     ↓
COMMIT
```

Каждый шаг фиксируется отдельно.

---

## ❌ Если следующий шаг не удался

Допустим:

```text id="n4w7p2"
Create Order       → COMMIT ✅
Reserve Product    → COMMIT ✅
Charge Payment     → ERROR ❌
```

Нельзя сделать:

```text id="r3m9x1"
ROLLBACK
```

и автоматически отменить предыдущие транзакции.

Они уже были локально зафиксированы.

Поэтому Saga использует **компенсирующие операции**:

```text id="c8v2k6"
Charge Payment ❌
       ↓
Release Product
       ↓
Cancel Order
```

---

# 🆚 Локальная vs распределённая транзакция

| Локальная                       | Распределённая                     |
| ------------------------------- | ---------------------------------- |
| Один сервис                     | Несколько сервисов                 |
| Обычно одна БД                  | Несколько БД/ресурсов              |
| Обычный `COMMIT/ROLLBACK`       | Нужен специальный механизм         |
| Проще обеспечить ACID           | Сложнее обеспечить согласованность |
| Например PostgreSQL transaction | Например 2PC / Saga                |

---

# 🐍 Пример PostgreSQL

Обычная локальная транзакция:

```python id="k5t2p9"
BEGIN;

INSERT INTO orders (user_id, amount)
VALUES (123, 1000);

UPDATE products
SET stock = stock - 1
WHERE id = 50;

COMMIT;
```

Если произошла ошибка:

```python id="z7m4q1"
ROLLBACK;
```

Обе операции относятся к одной транзакции этой БД.

---

# 🧱 В микросервисах

Допустим:

```text id="w6p3r8"
Order Service
     ↓
Order DB

Payment Service
     ↓
Payment DB
```

Нельзя сделать обычным способом:

```text id="f2q8s4"
BEGIN
 ↓
Order DB
 ↓
Payment DB
 ↓
COMMIT
```

Потому что это уже не обычная локальная транзакция.

Для координации нескольких ресурсов нужны специальные подходы, например:

```text id="e5n9k2"
2PC
Saga
```

---

# 🔄 Saga на простом примере

Бизнес-операция:

```text id="u4x7m1"
Оформить заказ
```

Разбивается:

```text id="j8p2v6"
1. Order Service
   ↓
   BEGIN
   Create Order
   COMMIT

2. Product Service
   ↓
   BEGIN
   Reserve Product
   COMMIT

3. Payment Service
   ↓
   BEGIN
   Charge Payment
   COMMIT
```

Это **три локальные транзакции**, а не одна глобальная.

---

## 🧠 Главное различие

Локальная транзакция гарантирует:

```text id="r5q9w3"
Внутри одной БД:

Operation 1
Operation 2
Operation 3

       ↓

COMMIT
   или
ROLLBACK
```

Saga гарантирует корректность **бизнес-процесса между сервисами** другим способом:

```text id="y2m8k4"
Local Transaction
       ↓
Event
       ↓
Local Transaction
       ↓
Event
       ↓
Local Transaction
       ↓
Compensation при ошибке
```

---

## 🎯 Главное

```text id="s6n3x8"
Локальная транзакция
        ↓
Один сервис
        ↓
Обычно одна БД
        ↓
BEGIN
        ↓
Операции
        ↓
COMMIT / ROLLBACK
```

### Формула для собеседования

**Локальная транзакция = атомарная операция внутри одного сервиса/БД.**

**Saga = последовательность локальных транзакций между сервисами + компенсирующие операции при ошибке.**

Главная мысль:

> **Локальный `ROLLBACK` может отменить только изменения своей транзакции. Он не откатывает автоматически изменения другой микрослужбы.**
