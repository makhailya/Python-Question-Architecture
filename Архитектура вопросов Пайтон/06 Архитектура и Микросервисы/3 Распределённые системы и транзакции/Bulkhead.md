### Bulkhead

## Формула для собеседования

**Bulkhead = изоляция ресурсов между компонентами, чтобы сбой или перегрузка одного компонента не нарушили работу всей системы.**

## Короткий ответ

Bulkhead — паттерн отказоустойчивости, при котором ресурсы приложения разделяются на независимые пулы или лимиты. Например, для разных внешних сервисов выделяются отдельные пулы соединений, очереди или ограничения параллельных запросов.

Если один сервис начинает отвечать медленно и исчерпывает выделенные ему ресурсы, остальные компоненты продолжают работать в пределах собственных лимитов.

## Ответ на собеседовании

Bulkhead — это паттерн изоляции ресурсов, название которого происходит от водонепроницаемых переборок корабля. Они не позволяют затоплению одного отсека привести к затоплению всего судна.

В Backend-разработке ресурсы разделяют между компонентами: например, выделяют отдельные пулы потоков, соединений, очереди задач или лимиты параллельных запросов. Если один внешний сервис начинает работать медленно, он не сможет занять все ресурсы приложения и остановить обработку остальных запросов.

Bulkhead особенно полезен в распределённых системах, где приложение зависит от нескольких внешних сервисов. Он дополняет Timeout и Circuit Breaker: Timeout ограничивает ожидание, Circuit Breaker временно блокирует вызовы проблемной зависимости, а Bulkhead ограничивает ресурсы, которые эта зависимость может потребить.

## 1. Как работает Bulkhead

Представим Backend, который обращается к трём внешним сервисам:

- сервису оплаты;
- сервису рекомендаций;
- сервису доставки.

Без изоляции все запросы могут конкурировать за одни и те же соединения и рабочие потоки.

```text
Без Bulkhead

Все запросы
     |
     v
Общий пул ресурсов
     |
     +── Оплата
     +── Рекомендации (зависли)
     └── Доставка

Медленный сервис может исчерпать общий пул.
```

С Bulkhead каждому направлению выделяется собственный пул или лимит:

```text
С Bulkhead

Оплата ─────────> Пул A
Рекомендации ───> Пул B (лимит исчерпан)
Доставка ───────> Пул C

Перегрузка B не исчерпывает ресурсы A и C.
```

Это логическая схема: конкретная реализация может использовать отдельные пулы, семафоры, очереди или ограничения конкурентности.

## 2. Какие ресурсы можно изолировать

| Ресурс | Пример |
|---|---|
| Потоки | Отдельный thread pool для внешней зависимости |
| Асинхронные задачи | Семафор, ограничивающий число одновременных вызовов |
| Соединения к БД | Отдельные connection pools |
| Очереди | Независимые очереди для разных типов задач |
| Воркеры | Отдельные группы обработчиков фоновых задач |
| Параллельные запросы | Лимит одновременных обращений к сервису |
| Память и вычисления | Ограничения ресурсов для отдельных компонентов или процессов |

Не обязательно физически создавать отдельный пул для каждого компонента. Иногда достаточно ограничить максимальное число одновременно выполняемых операций.

## 3. Пример на Python с asyncio

Допустим, приложение обращается к медленному сервису рекомендаций. Семафор ограничивает количество одновременных вызовов к нему.

```python
import asyncio

recommendations_limit = asyncio.Semaphore(10)


async def get_recommendations(user_id: int):
    async with recommendations_limit:
        return await call_recommendations_service(user_id)


async def call_recommendations_service(user_id: int):
    await asyncio.sleep(1)
    return {"user_id": user_id, "items": []}
```

В этом примере одновременно выполняться внутри ограниченной секции могут не более десяти вызовов.

**Важное уточнение:** это локальный лимит для данного экземпляра приложения, а не полноценная изоляция всех ресурсов. Он не создаёт отдельный пул потоков и не гарантирует защиту от любых видов перегрузки. Для настоящего Bulkhead также учитывают таймауты, ожидание семафора и поведение при исчерпании лимита.

## 4. Bulkhead, Timeout и Circuit Breaker

Эти паттерны решают разные задачи.

| Паттерн | На какой вопрос отвечает |
|---|---|
| Timeout | Как долго ждать операцию? |
| Circuit Breaker | Когда прекратить вызывать проблемный сервис? |
| Bulkhead | Сколько ресурсов разрешить ему потреблять? |
| Retry | Когда и сколько раз повторять неудачный вызов? |
| Rate Limiting | С какой частотой разрешать запросы? |
| Load Shedding | Какие запросы отклонить при перегрузке? |

На практике их часто комбинируют. Например, ограничивают количество одновременных запросов к внешнему сервису, устанавливают timeout и временно отключают вызовы через Circuit Breaker при устойчивых сбоях.

## 5. Преимущества и недостатки

**Преимущества:**
- предотвращает исчерпание всех общих ресурсов одной зависимостью;
- локализует последствия перегрузки;
- помогает сохранять работоспособность критичных функций;
- делает потребление ресурсов более предсказуемым.

**Недостатки:**
- усложняет конфигурацию и мониторинг;
- требует правильно выбирать размеры пулов и лимиты;
- слишком маленькие лимиты могут снижать пропускную способность;
- не устраняет причину медленной работы;
- не гарантирует полную изоляцию, если компоненты всё ещё делят CPU, память или другие общие ресурсы.

## 6. Частые вопросы на собеседовании

**Что такое Bulkhead?**

Паттерн изоляции ресурсов, который не позволяет перегрузке одного компонента исчерпать ресурсы всей системы.

**Почему он так называется?**

По аналогии с переборками корабля, которые ограничивают распространение затопления между отсеками.

**Чем Bulkhead отличается от Circuit Breaker?**

Bulkhead ограничивает ресурсы, доступные компоненту. Circuit Breaker прекращает вызовы к зависимости при обнаружении устойчивых сбоев.

**Достаточно ли поставить Timeout?**

Нет. Таймаут ограничивает время ожидания, но большое количество одновременно ожидающих операций всё ещё может исчерпать ресурсы. Bulkhead ограничивает конкурентность или выделенный пул.

**Как реализовать Bulkhead в асинхронном Python?**

Например, с помощью `asyncio.Semaphore`, ограниченных очередей или отдельных групп обработчиков. Выбор зависит от того, какие именно ресурсы нужно изолировать.

**Какие риски есть у Bulkhead?**

Неверно выбранные лимиты могут снижать производительность или создавать очереди ожидания. Кроме того, локальные лимиты не защищают от всех проблем с общими ресурсами процесса или машины.

## 7. Шпаргалка

- Bulkhead = изоляция ресурсов.
- Цель — не допустить каскадной деградации.
- Реализации: отдельные пулы, семафоры, очереди и лимиты конкурентности.
- Timeout ограничивает ожидание.
- Circuit Breaker блокирует вызовы проблемной зависимости.
- Bulkhead ограничивает потребление ресурсов.
- Для полноценной защиты важно учитывать общие CPU, память и другие разделяемые ресурсы.
