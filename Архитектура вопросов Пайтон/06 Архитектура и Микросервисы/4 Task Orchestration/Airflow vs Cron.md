# ⏰ Airflow vs Cron

## 🎯 Ответ на собеседовании

**Cron** — простой планировщик, который запускает команды или скрипты по расписанию.

**[[Airflow]]** — оркестратор workflow: позволяет описывать сложные зависимости между задачами, выполнять их последовательно или параллельно, делать retries, контролировать состояние и мониторить выполнение.

Если нужно просто запустить Python-скрипт каждый день — достаточно **Cron**.
Если есть сложный пайплайн из множества зависимых задач — лучше **Airflow**.

---

## 🎤 Суперкоротко

> **Cron — запустить задачу по времени. Airflow — управлять workflow из множества зависимых задач.**

---

## 🔹 Cron

**Cron** — стандартный Unix/Linux-механизм для запуска команд по расписанию.

Пример:

```python
0 3 * * * python /app/backup.py
```

Запускает `backup.py` каждый день в 03:00.

Cron хорошо подходит для:

* простых скриптов;
* backup;
* очистки файлов;
* периодических задач;
* простых maintenance-операций.

### Проблема Cron

Если workflow становится сложным:

```text
Extract
   ↓
Transform
   ↓
Load
   ↓
Send report
```

Cron сам по себе не предоставляет полноценного управления зависимостями между этими этапами.

---

# 🔹 Airflow

Airflow позволяет описывать workflow в виде **DAG**:

```text
Extract
   ↓
Transform
   ↓
Load
   ↓
Send report
```

При этом можно задавать:

* зависимости между задачами;
* retries;
* расписание;
* параллельное выполнение;
* timeout;
* условия запуска;
* историю запусков;
* мониторинг;
* состояние задач.

Пример:

```python
from airflow import DAG
from airflow.operators.python import PythonOperator

with DAG("etl_pipeline") as dag:
    extract = PythonOperator(
        task_id="extract",
        python_callable=extract_data,
    )

    transform = PythonOperator(
        task_id="transform",
        python_callable=transform_data,
    )

    load = PythonOperator(
        task_id="load",
        python_callable=load_data,
    )

    extract >> transform >> load
```

Здесь Airflow понимает:

```text
extract → transform → load
```

и не запустит `transform`, пока `extract` не завершится согласно правилам workflow.

# ⚖️ Главное отличие

|                            | Cron           | Airflow |
| -------------------------- | -------------- | ------- |
| Запуск по расписанию       | ✅              | ✅       |
| Простые скрипты            | ✅              | ✅       |
| DAG                        | ❌              | ✅       |
| Зависимости задач          | Ограниченно    | ✅       |
| Retries                    | Внешняя логика | ✅       |
| Мониторинг                 | ❌              | ✅       |
| История запусков           | Ограниченно    | ✅       |
| Параллельные workflow      | Сложно         | ✅       |
| Web UI                     | ❌              | ✅       |
| Сложные ETL/ELT            | Неудобно       | ✅       |
| Простота настройки         | ⭐⭐⭐⭐⭐          | ⭐⭐      |
| Инфраструктурная сложность | Низкая         | Выше    |

---

# 🧩 Когда использовать Cron

Используем **Cron**, если задача простая:

```text
Каждую ночь
     ↓
backup.py
```

или:

```text
Каждый день
     ↓
cleanup.py
```

Нет смысла поднимать Airflow ради одного небольшого скрипта.

---

# 🏗️ Когда использовать Airflow

Airflow оправдан, когда появляется полноценный workflow:

```text
Получить данные
      ↓
Проверить данные
      ↓
Обработать
      ↓
Загрузить в PostgreSQL
      ↓
Обновить отчёт
      ↓
Отправить уведомление
```

Особенно если нужны:

* сложные зависимости;
* несколько DAG;
* retries;
* SLA/таймауты;
* мониторинг;
* история запусков;
* ручной перезапуск отдельных задач;
* параллельное выполнение;
* управление ETL/ELT-пайплайнами.

---

# 🔥 Важный нюанс

**Airflow не просто "Cron с Web UI".**

Cron отвечает преимущественно на вопрос:

> **Когда запустить команду?**

Airflow отвечает на вопросы:

> **Что запустить? В каком порядке? От чего зависит задача? Что делать при ошибке? Как повторить? Как отследить выполнение всего workflow?**

---

# 🔄 Пример

### Cron

```text
03:00
  ↓
script.py
```

Если внутри `script.py`:

```text
extract
transform
load
notify
```

то вся логика управления находится внутри самого скрипта.

### Airflow

```text
         ┌── Transform A ──┐
Extract ─┤                 ├── Load ── Notify
         └── Transform B ──┘
```

Airflow управляет зависимостями между отдельными задачами.

---

## 💡 Как сформулировать на собеседовании

> **Cron подходит для простых периодических задач. Airflow — для оркестрации сложных workflow и ETL/ELT-пайплайнов. Основное преимущество Airflow — DAG, зависимости между задачами, retries, мониторинг и управление состоянием выполнения.**

---

## 🧠 Главное

```text
Cron
 ↓
расписание
 ↓
команда / скрипт
```

```text
Airflow
 ↓
DAG
 ↓
Tasks
 ↓
зависимости
 ↓
Scheduler
 ↓
Executor
 ↓
Workers
```

**Cron = scheduling.**

**Airflow = workflow orchestration.**
