# 🐇 Celery

## 🎯 Ответ на собеседовании

**Celery** — распределённая система для выполнения **фоновых и отложенных задач** в Python-приложениях.

Celery позволяет вынести длительную работу из основного HTTP-запроса и выполнять её отдельными **worker-процессами**.

Типичная архитектура:

```text
                    ┌──────────────┐
HTTP Request ──────→│   FastAPI    │
                    └──────┬───────┘
                           │
                           ↓
                    ┌──────────────┐
                    │ Message      │
                    │ Broker       │
                    │ Redis/Rabbit │
                    └──────┬───────┘
                           │
                           ↓
                    ┌──────────────┐
                    │    Celery    │
                    │   Workers    │
                    └──────────────┘
                           │
                           ↓
                       Task
```

---

## 📌 Зачем нужен Celery?

Представим API:

```python
@app.post("/send-report")
def send_report():
    generate_large_report()
    send_email()

    return {"status": "ok"}
```

Если отчёт генерируется 30 секунд, пользователь будет ждать 30 секунд.

С Celery:

```text
HTTP Request
     ↓
создали задачу
     ↓
положили в очередь
     ↓
сразу ответили клиенту
     ↓
Celery Worker
     ↓
генерирует отчёт
     ↓
отправляет email
```

Пользователь не ждёт завершения фоновой операции.

# 🧩 Основные компоненты

### 1. Producer

Приложение, которое создаёт задачу.

Например:

```python
send_report.delay(user_id)
```

---

### 2. Broker

**Broker** — посредник, через которого приложение передаёт задачи workers.

Популярные варианты:

```text
Redis
RabbitMQ
```

Упрощённо:

```text
Producer
    ↓
Broker
    ↓
Worker
```

---

### 3. Worker

**Celery Worker** получает задачи из очереди и выполняет их.

Можно запустить несколько workers:

```text
Queue
 ├── Task 1 → Worker 1
 ├── Task 2 → Worker 2
 ├── Task 3 → Worker 3
 └── Task 4 → Worker 1
```

---

### 4. Result Backend

Место, где Celery может хранить состояние и результат выполнения задачи.

Например:

```text
PENDING
   ↓
STARTED
   ↓
SUCCESS
```

В качестве result backend также может использоваться Redis или другое поддерживаемое хранилище.

# 📝 Создание задачи

Задача объявляется через `@app.task`:

```python
from celery import Celery

app = Celery(
    "my_app",
    broker="redis://localhost:6379/0",
)


@app.task
def add(x, y):
    return x + y
```

Запуск:

```python
add.delay(2, 3)
```

Здесь:

```text
add()
   ↓
.delay()
   ↓
задача отправляется в Broker
   ↓
Celery Worker получает её
   ↓
add(2, 3)
```

---

# 🔄 `.delay()` vs `.apply()`

```python
add.delay(2, 3)
```

→ отправляет задачу на выполнение **асинхронно через broker**.

А:

```python
add.apply(args=(2, 3))
```

→ выполняет задачу **локально и синхронно**, без отправки worker'у.

# ⏰ Отложенные и периодические задачи

Celery может выполнять задачи:

* в фоне;
* с задержкой;
* периодически;
* повторно после ошибки.

Например:

```text
сейчас
  ↓
создать задачу
  ↓
через 10 минут
  ↓
выполнить
```

Для периодических задач в экосистеме Celery используется **Celery Beat**:

```text
Celery Beat
     ↓
создаёт задачи по расписанию
     ↓
Broker
     ↓
Celery Worker
```

Например:

```text
каждый день в 08:00
→ сформировать отчёт
→ отправить email
```

---

# ⚠️ Celery ≠ asyncio

Это важное различие.

|                       | Celery                        | `asyncio`                 |
| --------------------- | ----------------------------- | ------------------------- |
| Основная задача       | Фоновые/распределённые задачи | Асинхронный I/O           |
| Выполнение            | Workers                       | Event Loop                |
| Очередь               | Broker                        | Обычно не требуется       |
| Процессы              | Часто используются            | Обычно один процесс/поток |
| Распределённость      | ✅                             | ❌ сама по себе            |
| HTTP/БД I/O           | Может                         | ✅ отлично                 |
| Долгие фоновые задачи | ✅                             | ⚠️ не основное назначение |

Например:

```text
FastAPI + asyncio
    ↓
быстрые HTTP-запросы


FastAPI
    ↓
Celery
    ↓
долгая фоновая задача
```

Они **могут использоваться вместе**.

# 📌 Когда использовать Celery?

Хорошие кандидаты:

* отправка email;
* генерация отчётов;
* обработка изображений;
* конвертация файлов;
* массовая обработка данных;
* периодические задачи;
* retry после временной ошибки;
* задачи, которые не должны выполняться внутри HTTP-запроса.

## 🧠 Главное

```text
Celery
  ↓
очередь задач
  ↓
Broker
  ↓
Worker
  ↓
выполнение фоновой задачи
```

**Celery нужен, когда работу необходимо вынести за пределы основного потока обработки запроса и выполнять её независимо, часто с несколькими workers.**

### 🎤 Суперкоротко

> **Celery — распределённая система фоновых задач для Python. Приложение отправляет задачу в broker, например Redis или RabbitMQ, а Celery Worker забирает её из очереди и выполняет. Celery используют для долгих, фоновых, периодических и повторяемых задач.**
