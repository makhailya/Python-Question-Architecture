# 🔷 TypeScript — типизированный JavaScript

## 🎤 Короткий ответ для собеседования

**TypeScript (TS)** — это язык программирования, разработанный Microsoft, который расширяет JavaScript системой статической типизации.

TypeScript позволяет обнаруживать многие ошибки ещё на этапе разработки, до запуска приложения.

Основные возможности:

- Статическая проверка типов.
- Интерфейсы (`interface`).
- Дженерики (`generics`).
- Типизация функций и объектов.
- Улучшенные автодополнение и рефакторинг.

**TypeScript компилируется (транспилируется) в JavaScript**, который затем выполняется в браузере или Node.js.

## 🗣️ Ответ на собеседовании

TypeScript — это надмножество JavaScript, которое добавляет статическую типизацию.

Он позволяет явно описывать типы переменных, параметров функций и возвращаемых значений, а также структуру объектов через интерфейсы.

Это особенно полезно в больших проектах, поскольку многие ошибки можно обнаружить до выполнения кода.

Например, при взаимодействии Frontend с Backend API можно описать типы ожидаемых JSON-данных. Тогда TypeScript проверяет, правильно ли Frontend использует эти данные.

При этом в браузере выполняется обычный JavaScript, поскольку типы TypeScript удаляются при компиляции.

## 🔑 JavaScript vs TypeScript

### JavaScript

```javascript
function sum(a, b) {
    return a + b;
}

sum(10, "20"); // "1020"
```

JavaScript допускает сложение числа со строкой и выполняет преобразование типов.

### TypeScript

```typescript
function sum(a: number, b: number): number {
    return a + b;
}

sum(10, 20);   // OK
sum(10, "20"); // Ошибка проверки типов
```

### Разбор

- `a: number` — параметр должен быть числом.
- `b: number` — второй параметр тоже число.
- `: number` после скобок — тип возвращаемого значения.

**Важно:** TypeScript проверяет типы во время разработки, но не гарантирует проверку типов во время выполнения программы.

## 🧩 Основные типы

| TypeScript | Python |
|---|---|
| `string` | `str` |
| `number` | `int`, `float` |
| `boolean` | `bool` |
| `string[]` | `list[str]` |
| `null` | `None` |
| `undefined` | Нет прямого аналога |
| `unknown` | Нет точного аналога |
| `any` | `Any` из typing |

Пример:

```typescript
let age: number = 25;
let name: string = "Alex";
let active: boolean = true;

let numbers: number[] = [1, 2, 3];
```

TypeScript также умеет самостоятельно выводить типы:

```typescript
let age = 25; // TypeScript определит number
```

## 🏗️ Interface — описание структуры объекта

**Interface** определяет, какие поля и методы должен иметь объект.

```typescript
interface User {
    id: number;
    name: string;
    email?: string;
}

const user: User = {
    id: 1,
    name: "Alex"
};
```

### Разбор

- `interface User` — объявляет интерфейс.
- `id: number` — обязательное числовое поле.
- `name: string` — обязательное строковое поле.
- `email?: string` — необязательное поле.

По смыслу это напоминает `TypedDict` в Python, хотя возможности и правила проверки отличаются.

## 🌐 TypeScript и Backend API

Допустим, FastAPI возвращает:

```json
{
  "id": 123,
  "status": "created"
}
```

На Frontend описываем тип:

```typescript
interface Supply {
    id: number;
    status: string;
}
```

И выполняем запрос:

```typescript
async function getSupply(): Promise<Supply> {
    const response = await fetch("/api/supplies/123");

    if (!response.ok) {
        throw new Error("HTTP error");
    }

    const data: Supply = await response.json();

    return data;
}
```

### Что важно понимать

`Promise<Supply>` означает, что асинхронная функция возвращает Promise, который при успешном выполнении содержит объект типа `Supply`.

Однако `response.json()` не проверяет фактическую структуру JSON по интерфейсу `Supply`.

Для проверки внешних данных во время выполнения используют дополнительные механизмы, например Zod.

## ⚖️ TypeScript vs JavaScript

| Критерий | JavaScript | TypeScript |
|---|---|---|
| Типизация | Динамическая | Статическая проверка типов |
| Проверка типов до запуска | Нет встроенной обязательной | Да |
| Интерфейсы типов | Нет | Да |
| Запуск в браузере | Напрямую | После преобразования в JS |
| Подходит для больших проектов | Да | Да, с дополнительными преимуществами типизации |

## ❓ Частые вопросы на собеседовании

**1. Что такое TypeScript?**

Надмножество JavaScript, добавляющее статическую типизацию и инструменты проверки кода.

**2. Чем TypeScript отличается от JavaScript?**

TypeScript позволяет описывать и проверять типы до выполнения программы.

**3. Может ли браузер выполнять TypeScript напрямую?**

Обычно нет. TypeScript преобразуют в JavaScript.

**4. Что такое interface?**

Описание структуры объекта и ожидаемых типов его свойств.

**5. Что такое generics?**

Механизм создания функций, классов и типов, которые работают с разными типами данных, сохраняя информацию о них.

Пример:

```typescript
function identity<T>(value: T): T {
    return value;
}
```

**6. Чем `any` отличается от `unknown`?**

`any` фактически отключает проверку типов для значения, а `unknown` требует уточнить тип перед использованием.

**7. Проверяет ли TypeScript JSON от Backend?**

Нет, не автоматически во время выполнения. Для этого нужна runtime-валидация.

**8. Что такое `.tsx`?**

Файл TypeScript, который может содержать JSX-разметку, часто используемую в React.

**9. Нужен ли TypeScript Python Backend-разработчику?**

Необязательно знать глубоко, но полезно понимать типизацию, интерфейсы и взаимодействие с REST API.
