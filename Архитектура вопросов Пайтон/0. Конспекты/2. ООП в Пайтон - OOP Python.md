## ⚡ Быстрый ответ (шпаргалка перед собесом)

- **[[ООП]]** — парадигма программирования, где приложение описывается через классы и объекты, которые взаимодействуют между собой. 4 принципа: **[[Инкапсуляция]], [[Наследование]], [[Полиморфизм]], [[Абстракция]]**.

- **[[Инкапсуляция]]** — сокрытие деталей реализации. В Python нет строгих модификаторов доступа: `_name` — «соглашение», предупреждение для разработчика; `__name` — **[[Name Mangling]]** (Python переименовывает атрибут в `_ClassName__name`), доступ извне усложнён, но не запрещён полностью.

- **[[Наследование]]** — класс-наследник получает атрибуты и методы родителя, может их переопределять/расширять. Поиск метода по иерархии классов идёт по алгоритму [[MRO (Method Resolution Order)]], реализованному через **[[C3-линеаризация]]** (поиск в ширину, а не в глубину, как было в старых версиях Python 2).

- **[[Полиморфизм]]** — разные объекты отвечают на вызов одного и того же метода по-разному. Виды:
- **[[Динамический полиморфизм]]** (переопределение метода в разных классах-наследниках, определяется в рантайме) и 
- **[[Статический полиморфизм]]** (в Python явно не поддерживается компилятором, но есть аналоги: [[Ad hoc]] — перегрузка функций через `functools.singledispatch`, и
- **[[Параметрический полиморфизм]]** — обобщённый код через [[Generics и TypeVar]], дженерики).

- **[[Абстракция]]** — контракт: что объект должен уметь, без реализации. Реализуется через [[ABC — Abstract Base Class]] (абстрактный базовый класс, можно частично реализовать методы) или через [[Protocol]] (более мягкий вариант — [[Duck Typing]], не требует явного наследования).

- [[Дескрипторы]] — механизм управления доступом к атрибутам через методы [[__get__]], [[__set__]], [[__delete__]], [[__set_name__]]. **[[Data-дескрипторы]]** реализуют [[__get__]] + [[__set__]]/[[__delete__]] (пример: [[property]]) — имеют приоритет над [[__dict__]] экземпляра. **[[Non-data дескрипторы]]** реализуют только [[__get__]] (пример: [[classmethod]], [[staticmethod]], обычные функции-методы).

- **[[property]]** — способ красиво задать getter/setter/deleter для атрибута с валидацией, логированием и т.п. Под капотом — это тоже [[Декоратор]].

- **[[classmethod]] vs [[staticmethod]]**: `classmethod` получает ссылку на класс (`cls`), может работать с атрибутами класса, вызывается без создания экземпляра. `staticmethod` не получает ни `self`, ни `cls` — по сути обычная функция, логически связанная с классом.
- **[[__new__]] vs [[__init__]]**: сначала вызывается [[__new__]] — создаёт и возвращает новый объект (аналог конструктора). Затем вызывается [[__init__]] — принимает уже созданный объект и инициализирует его атрибуты, ничего не возвращает.

- **[[Итератор]]** — объект с методами [[__iter__]] (возвращает сам итератор) и [[__next__]] (возвращает следующее значение, в конце кидает [[StopIteration]]). Конечен — пройти дважды нельзя без пересоздания.

- **[[Iterable]] vs [[Итератор]]**: [[Iterable]] — объект с методом [[__iter__]] (например, [[list]]), сам список итератором не является — цикл `for` сначала получает из него [[Итератор]]

- **[[Генератор]]** — частный случай [[Итератор]]а с «ленивой» отгрузкой значений (не хранит всю последовательность в памяти). Задаётся через функцию с [[yield]] либо через генераторное выражение `(x for x in ...)`. [[Методы генератора]]: [[send()]], [[throw()]], [[close()]].

- **[[Декоратор]]** — функция, оборачивающая другую функцию и добавляющая функционал до/после её вызова. [[Параметризованный декоратор]]  — обёртка ещё в одну функцию для приёма параметров.

- **[[Контекстный менеджер]]** — объект с методами [[__enter__]] (возвращает объект, доступный через `as`) и [[__exit__]] (принимает тип/значение/traceback исключения; возвращает `True`, если исключение нужно подавить).

# 📖 Подробно

## 1. [[ООП]] и 4 принципа

Определение: подход к программированию, при котором логика приложения строится вокруг **классов** (шаблонов) и **объектов** (экземпляров), которые инкапсулируют данные и поведение и взаимодействуют между собой через методы.

## 2. [[Инкапсуляция]]

Сокрытие внутренней реализации и защита данных от произвольного доступа извне.

```python
class User:
    def __init__(self, name, password):
        self.name = name          # публичный атрибут
        self._password = password # "приватный" по соглашению — не трогай снаружи
        self.__secret = "xyz"     # name mangling

u = User("Ilya", "1234")
print(u._password)     # доступно, но так делать не стоит по договорённости
print(u.__secret)      # AttributeError!
print(u._User__secret) # а вот так — сработает, Python просто переименовал атрибут
```

В Python нет настоящей приватности как в Java/C++ — только договорённость (`_`) и «затруднение доступа» через переименование (`__`).

## 3. [[Наследование]] и [[MRO (Method Resolution Order)]]

```python
class A:
    def greet(self):
        return "A"

class B(A):
    pass

class C(A):
    def greet(self):
        return "C"

class D(B, C):
    pass

print(D().greet())  # "C" — благодаря C3-линеаризации (MRO)
print(D.__mro__)
```

[[MRO (Method Resolution Order)]] определяет порядок, в котором Python ищет метод по иерархии классов при множественном наследовании. Современный Python использует **алгоритм [[C3-линеаризация]]** — по сути это поиск **в ширину** ([[BFS-подобный]]), а не «слева направо в глубину», как было в очень старых схемах наследования без единого корня (`object`).

## 4. [[Полиморфизм]]

Одинаковый интерфейс метода — разное поведение в зависимости от объекта.

- **[[Динамический полиморфизм]]** — привычный для Python: переопределение метода в классах-наследниках, разрешается в рантайме (по факту это тесно связано с наследованием / [[Duck Typing]]).

- **[[Статический полиморфизм]]** — в Python нет как встроенной языковой концепции (в отличие от C++ со строгой типизацией), но есть похожие инструменты:

  - **[[Ad hoc полиморфизм]] (перегрузка функций)** — через [[functools.singledispatch]], позволяет диспетчеризовать вызов в зависимости от типа аргумента. Формально это не «настоящая» перегрузка (как в C++), а набор разных функций, между которыми диспетчер выбирает нужную.
  
  - **[[Параметрический полиморфизм]]** — обобщённый (generic) код, работающий с любыми типами. В Python — через `typing.TypeVar` / `Generic` [[Generics и TypeVar]](современная альтернатива — синтаксис `class Stack[T]`).

## 5. [[Абстракция]]: [[ABC — Abstract Base Class]] vs [[Protocol]]

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...

    def describe(self):          # обычный метод — можно реализовать полностью
        return f"Площадь: {self.area()}"

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        return 3.14 * self.r ** 2
```

- **[[ABC — Abstract Base Class]] (абстрактный базовый класс)** — задаёт контракт через [[@abstractmethod]]; наследник **обязан** реализовать эти методы, иначе экземпляр не создастся. При этом [[ABC — Abstract Base Class]] **может** содержать и полностью реализованные обычные методы — это не запрещено.
- 
- [[Protocol]] (`typing.Protocol`) — более мягкий вариант: не требует явного [[Наследование]]. Если объект реализует все методы, описанные в протоколе — он считается соответствующим протоколу (структурная типизация / [[Duck Typing]]).

## 6. [[Дескрипторы]]

[[Дескрипторы]] — объект, определяющий, как происходит доступ к атрибуту другого объекта, через специальные методы:

| Метод | Что делает |
|---|---|
| `__get__(self, obj, owner)` | Вызывается при чтении атрибута |
| `__set__(self, obj, value)` | Вызывается при записи |
| `__delete__(self, obj)` | Вызывается при удалении (`del`) |
| `__set_name__(self, owner, name)` | Вызывается один раз при создании класса — передаёт дескриптору имя атрибута |

**Виды:**

- **[[Data-дескрипторы]]** — реализует [[__get__]] **и** ([[__set__]] или [[__delete__]]). Пример: [[property]]. Имеет приоритет над [[__dict__]] экземпляра при поиске атрибута.
- 
- **[[Non-data дескрипторы]]** — реализует только [[__get__]]. Примеры: [[classmethod]], `staticmethod`, обычные функции (методы экземпляра — тоже дескрипторы под капотом!).

```python
class Positive:
    def __set_name__(self, owner, name):
        self.name = f"_{name}"

    def __get__(self, obj, owner):
        return getattr(obj, self.name)

    def __set__(self, obj, value):
        if value < 0:
            raise ValueError("Значение должно быть положительным")
        setattr(obj, self.name, value)

class Account:
    balance = Positive()   # data-дескриптор с валидацией

    def __init__(self, balance):
        self.balance = balance
```

**[[property]]** — это функция-хелпер, построенная поверх той же концепции дескрипторов: позволяет удобно задать getter/setter/deleter, добавить валидацию, логирование, либо использовать как альтернативный конструктор.

## 7. [[classmethod]] и [[staticmethod]]

```python
class Pizza:
    def __init__(self, ingredients):
        self.ingredients = ingredients

    @classmethod
    def margherita(cls):        # работает с классом, может вернуть cls(...)
        return cls(["сыр", "томаты"])

    @staticmethod
    def validate(ingredient):   # просто функция, логически внутри класса
        return isinstance(ingredient, str)
```

- Оба **не требуют** экземпляра класса для вызова.
- [[@abstractmethod]] получает `cls` — может обращаться к атрибутам класса, создавать экземпляры (часто используется как альтернативный конструктор).
- [[staticmethod]] не получает ни `self`, ни `cls` — по сути обычная функция, которую просто удобно хранить внутри класса.
- Забавный факт с собеса: и [[classmethod]], и [[staticmethod]] — тоже дескрипторы ([[Non-data дескрипторы]]).

## 8. [[__new__]] vs [[__init__]]

```python
class Point:
    def __new__(cls, *args, **kwargs):
        print("__new__: создаём объект")
        instance = super().__new__(cls)
        return instance

    def __init__(self, x, y):
        print("__init__: инициализируем атрибуты")
        self.x = x
        self.y = y
```

- [[__new__]] вызывается **первым** — это аналог конструктора, он **создаёт** и **возвращает** новый объект.
- [[__init__]] вызывается **вторым**, принимает уже созданный объект и заполняет его атрибутами; **ничего не возвращает** (`None`).
- Ни [[__new__]], ни [[__init__]] дескрипторами **не являются** — это отдельный механизм создания объектов.

## 9. [[Итератор]] и [[Генератор]]

**[[Итератор]]** — объект, реализующий:
- [[__iter__]]()` — возвращает сам итератор (`self`);
- [[__next__]]()` — возвращает следующее значение последовательности, в конце — кидает исключение `StopIteration`.

**[[Iterable]] vs [[Итератор]]** — важный нюанс с собеса: список [[list]] сам по себе **не является [[Итератор]]ом**, это **[[Iterable]]** (объект с методом [[__iter__]], но без [[__next__]]). Когда `for` берёт [[list]], он сначала вызывает `iter(list)` — и получает **новый** объект-итератор. У кастомного же итератора [[__iter__]] обычно возвращает `self`.

```python
class Counter:
    def __init__(self, limit):
        self.limit = limit
        self.current = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.current >= self.limit:
            raise StopIteration
        self.current += 1
        return self.current

for num in Counter(3):
    print(num)  # 1, 2, 3
```

**[[Генератор]]** — частный случай итератора, использующий **ленивую отгрузку** (lazy evaluation): значения не хранятся все сразу в памяти, а вычисляются по требованию (через `next()`).

Два способа задать генератор:
```python
def gen_func():          # генераторная функция
    yield 1
    yield 2
    yield 3

gen_expr = (x**2 for x in range(3))  # генераторное выражение
```

По [[Генератор]]у/[[Итератор]]у можно пройти **только один раз** (если не обернуть логику в `while True`, чтобы создавать бесконечный цикл выдачи значений внутри). Чтобы «пройти заново» — нужно создать новый объект.

**Дополнительные методы [[Генератор]]а** (помимо `next()`):
- [[send()]](value)` — отправить значение внутрь генератора (продолжает выполнение с точки `yield`, значение становится результатом выражения `yield`);
- [[throw()]](exc)` — возбудить исключение внутри генератора, в точке, где он остановлен;
- [[close()]]` — закрыть генератор (внутри кидается `GeneratorExit`), позволяет освободить ресурсы (например, закрыть файл), если это предусмотрено внутри генератора через `try/finally`.

## 10. [[Декоратор]]

```python
import functools

def log_calls(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Вызов {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Результат: {result}")
        return result
    return wrapper

@log_calls
def add(a, b):
    return a + b
```

[[Декоратор]] — функция, которая оборачивает другую функцию, добавляя поведение **до** и/или **после** её вызова. Синтаксис `@decorator` — синтаксический сахар для `func = decorator(func)`.

** [[Параметризованный декоратор]]** — оборачивается ещё в одну внешнюю функцию, принимающую параметры:

```python
def repeat(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(times):
                func(*args, **kwargs)
        return wrapper
    return decorator

@repeat(times=3)
def hello():
    print("Привет!")
```

**[[Декоратор]], работающий и с sync, и с async функцией:**

```python
import asyncio

def universal_decorator(func):
    if asyncio.iscoroutinefunction(func):
        @functools.wraps(func)
        async def async_wrapper(*args, **kwargs):
            return await func(*args, **kwargs)
        return async_wrapper
    else:
        @functools.wraps(func)
        def sync_wrapper(*args, **kwargs):
            return func(*args, **kwargs)
        return sync_wrapper
```

Внутри [[Декоратор]] создаются два враппера (sync/async), и в зависимости от того, является ли переданная функция корутинной (`asyncio.iscoroutinefunction`), выбирается нужный.

## 11. [[Контекстный менеджер]] 

```python
class FileManager:
    def __init__(self, filename):
        self.filename = filename

    def __enter__(self):
        self.file = open(self.filename)
        return self.file            # это то, что попадёт в переменную после `as`

    def __exit__(self, exc_type, exc_value, traceback):
        self.file.close()
        return False                 # False — не подавляем исключение, True — подавляем

with FileManager("data.txt") as f:
    content = f.read()
```

- [[__enter__]](self)` — вызывается на входе в блок `with`, обычно возвращает `self` (или другой полезный объект — именно он и «ловится» через `as obj`).
- 
- [[__exit__]](self, exc_type, exc_value, traceback)` — вызывается на выходе из блока (в том числе при исключении). Возвращает `True`, если исключение нужно подавить (программа продолжится дальше), или `False`/`None`, если исключение должно пробрасываться дальше.
- 
- Асинхронная версия — методы `__aenter__` / `__aexit__`, используется как `async with`.
