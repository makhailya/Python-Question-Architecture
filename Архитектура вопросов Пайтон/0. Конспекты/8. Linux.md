# [[Linux]]: [[Файловая система]], [[Процессы]], [[Права доступа]], [[Bash]], [[SSH]], [[Сеть]], [[systemd]], [[Логи]]

## ⚡ Быстрый ответ (шпаргалка перед собесом)

* **[[Linux]]** — Unix-подобная операционная система с ядром Linux. Серверная разработка часто выполняется именно в Linux-окружении.

* **[[Shell]]** — программа, которая принимает команды пользователя и передаёт их операционной системе. Например, `bash`.

* **[[Bash]]** — командная оболочка и язык сценариев.

* Основные каталоги Linux:

```text
/
├── /bin
├── /etc
├── /home
├── /var
├── /tmp
├── /usr
├── /opt
├── /dev
├── /proc
└── /root
```

* **`/`** — корень файловой системы.

* **`/home`** — домашние директории пользователей.

* **`/etc`** — конфигурационные файлы системы и сервисов.

* **`/var`** — изменяемые данные: логи, очереди, кэш и т.д.

* **`/tmp`** — временные файлы.

* **`/proc`** — виртуальная файловая система с информацией о процессах и состоянии ядра.

* **`/root`** — домашняя директория пользователя `root`.

* **`pwd`** — показывает текущую директорию.

* **`ls`** — показывает содержимое директории.

* **`cd`** — переходит в другую директорию.

* **`cp`** — копирует файлы.

* **`mv`** — перемещает или переименовывает.

* **`rm`** — удаляет.

* **`mkdir`** — создаёт директорию.

* **`cat`** — выводит содержимое файла.

* **`less`** — удобно просматривать большой файл.

* **`grep`** — ищет строки по шаблону.

* **`find`** — ищет файлы и директории.

* **[[Pipe]] `|`** передаёт вывод одной команды на вход другой.

* **`>`** перенаправляет вывод и перезаписывает файл.

* **`>>`** добавляет вывод в конец файла.

* **[[Процесс]]** — выполняющаяся программа.

* **PID** — уникальный идентификатор процесса.

* **`ps`** — показывает процессы.

* **`top` / `htop`** — мониторинг процессов и ресурсов.

* **`kill`** отправляет сигнал процессу. `kill -9` — принудительное завершение через `SIGKILL`.

* **[[Права доступа]]** состоят из прав для:

  * владельца (`user`);
  * группы (`group`);
  * остальных (`other`).

* Основные права:

```text
r = read
w = write
x = execute
```

* `chmod` изменяет права доступа.

* `chown` изменяет владельца файла.

* **`sudo`** позволяет выполнить команду с повышенными привилегиями.

* **[[SSH]]** — протокол безопасного удалённого доступа к серверу.

* **[[systemd]]** — система инициализации и управления сервисами во многих современных Linux-дистрибутивах.

* `systemctl status nginx` — состояние сервиса.

* `systemctl start nginx` — запустить.

* `systemctl stop nginx` — остановить.

* `systemctl restart nginx` — перезапустить.

* **`journalctl`** — просмотр логов systemd/journald.

* **`df -h`** — использование дискового пространства файловыми системами.

* **`du -sh`** — размер директории/файла.

* **`free -h`** — использование RAM.

* **`ip addr`** — сетевые интерфейсы и IP-адреса.

* **`ss`** — просмотр сетевых соединений и listening-портов.

## 1. Что такое [[Linux]]

Linux — ядро операционной системы.

На практике под Linux часто подразумевают целую операционную систему на основе Linux kernel:


Для backend-разработчика Linux особенно важен, потому что серверы, Docker-контейнеры и многие CI/CD-системы работают в Linux-окружении.

# 4. [[Pipe]]

Pipe:

```bash
|
```

передаёт стандартный вывод одной команды на стандартный ввод другой.

Например:

```bash
ps aux | grep python
```

Логика:

```text
ps aux
   ↓
список процессов
   ↓
grep python
   ↓
только строки с python
```

Это одна из фундаментальных концепций shell.

# 8. [[Права доступа Linux]]

В Linux у каждого файла есть:

```text
владелец
группа
права
```

Например:

```text
-rwxr-xr--
```

Разбираем:

```text
-     rwx     r-x     r--
│       │       │       │
│       │       │       └── other
│       │       └────────── group
│       └────────────────── owner
└────────────────────────── file
```

| Право | Файл      | Директория            |
| ----- | --------- | --------------------- |
| `r`   | Читать    | Читать список файлов  |
| `w`   | Изменять  | Создавать/удалять     |
| `x`   | Выполнять | Заходить в директорию |

# 10. [[chmod]]

Изменение прав:

```bash
chmod 755 script.sh
```

Числа:

```text
r = 4
w = 2
x = 1
```

Поэтому:

```text
7 = 4 + 2 + 1 = rwx
5 = 4 + 1     = r-x
5 = 4 + 1     = r-x
```

Получаем:

```text
755 → rwxr-xr-x
```

Например:

```bash
chmod 644 config.py
```

означает:

```text
owner  → rw-
group  → r--
other  → r--
```

---

# 11. `chown`

Изменить владельца:

```bash
sudo chown user file.txt
```

Владелец + группа:

```bash
sudo chown user:group file.txt
```

Для директории рекурсивно:

```bash
sudo chown -R user:group project/
```

---

# 12. `sudo`

`sudo` позволяет выполнить команду с повышенными правами.

Например:

```bash
sudo systemctl restart nginx
```

Почему это необходимо?

Обычный пользователь не должен иметь возможность произвольно:

* менять системные файлы;
* управлять сервисами;
* изменять настройки сети;
* устанавливать системные пакеты.

# 15. `top` и `htop`

```bash

```

показывает процессы в реальном времени.

* RAM;
* PID;

# 16. `kill` и [[Signals]]

Команда:

```bash
kill PID
```

обычно отправляет процессу:

```text
SIGTERM
```

То есть:

> «Пожалуйста, корректно завершись».

Принудительное завершение:

```bash
kill -9 PID
```

Это:

```text
SIGKILL
```

Процесс не может обработать этот сигнал и корректно освободить ресурсы.

Поэтому сначала обычно используют:

```bash
kill PID
```

а `kill -9` оставляют для ситуаций, когда процесс не завершается обычным способом.

# 17. [[SSH]]

SSH — протокол безопасного удалённого управления системой.

Подключение:

```bash
ssh user@192.168.1.100
```

С использованием ключа:

```bash
ssh -i ~/.ssh/id_ed25519 user@server
```

Типичная схема:

```text
MacBook
   │
   │ SSH
   ↓
Linux Server
   │
   ├── Docker
   ├── PostgreSQL
   ├── Redis
   └── Backend
```

---

# 18. [[SSH-ключи]]

Вместо пароля можно использовать пару ключей:

```text
Private Key
     +
Public Key
```

Приватный ключ хранится у пользователя.

Публичный ключ размещается на сервере.

Обычно:

```text
~/.ssh/id_ed25519
~/.ssh/id_ed25519.pub
```

⚠️ Приватный ключ нельзя передавать другим людям.

# 19. [[systemd]]

`systemd` используется для управления системными сервисами.

Например:

```bash
systemctl status nginx
```

Запустить:

```bash
sudo systemctl start nginx
```

Остановить:

```bash
sudo systemctl stop nginx
```

Перезапустить:

```bash
sudo systemctl restart nginx
```

Добавить запуск после загрузки:

```bash
sudo systemctl enable nginx
```

Запустить сейчас и включить автозапуск:

```bash
sudo systemctl enable --now nginx
```

---

# 20. [[journalctl]]

Если сервис управляется через systemd:

```bash
journalctl -u nginx
```

Последние строки:

```bash
journalctl -u nginx -n 100
```

Следить за логами:

```bash
journalctl -u nginx -f
```

Это особенно полезно при расследовании проблем после деплоя.

# 30. Практический сценарий: backend не работает

Представим:

> После деплоя FastAPI перестал отвечать.

Порядок проверки:

### 1. Проверяем сервис

```bash
systemctl status backend
```

### 2. Смотрим логи

```bash
journalctl -u backend -n 100
```

### 3. Проверяем процесс

```bash
ps aux | grep python
```

### 4. Проверяем порт

```bash
ss -tulpn | grep 8000
```

### 5. Проверяем локальный HTTP

```bash
curl http://localhost:8000
```

### 6. Проверяем Nginx

```bash
systemctl status nginx
```

### 7. Проверяем логи Nginx

```bash
journalctl -u nginx -n 100
```

Таким образом:

```text
Сервис
  ↓
Процесс
  ↓
Порт
  ↓
HTTP
  ↓
Nginx
  ↓
Логи
```

Это уже мышление backend-разработчика, а не просто знание отдельных команд.
