# 🧹 VACUUM FULL в PostgreSQL

## 🎯 Ответ на собеседовании

**`VACUUM FULL`** — это операция обслуживания PostgreSQL, которая **физически переписывает таблицу**, удаляя неиспользуемое пространство и позволяя существенно уменьшить её размер на диске.

В отличие от обычного `VACUUM`, который освобождает пространство **для повторного использования внутри таблицы**, `VACUUM FULL` создаёт компактную копию таблицы и заменяет старую.

Главный недостаток — операция требует **сильной блокировки таблицы** и может быть дорогой по времени, диску и I/O.

```python
VACUUM FULL users;
```

---

## 🎤 Суперкоротко

> **`VACUUM FULL`** физически переписывает таблицу, удаляет свободное пространство и может вернуть его операционной системе, уменьшая размер таблицы на диске. Но операция тяжёлая и блокирует таблицу, поэтому для обычного регулярного обслуживания используют обычный `VACUUM` и `autovacuum`.

---

# 📌 Зачем нужен VACUUM FULL

Рассмотрим таблицу:

```text
До:

[DATA][FREE][DATA][FREE][FREE][DATA][FREE]
```

Обычный `VACUUM` может освободить эти области:

```text
VACUUM:

[DATA][FREE][DATA][FREE][FREE][DATA][FREE]
```

Свободное место остаётся внутри физического файла таблицы.

Оно может быть использовано PostgreSQL для новых записей.

А `VACUUM FULL` физически перестраивает таблицу:

```text
VACUUM FULL:

[DATA][DATA][DATA]
```

После этого физический размер таблицы может значительно уменьшиться.

---

# 🔄 Как работает VACUUM FULL

Упрощённо:

```text
Старая таблица
      ↓
много dead tuples / свободного места
      ↓
VACUUM FULL
      ↓
создание новой компактной версии таблицы
      ↓
перенос актуальных строк
      ↓
замена старой таблицы
      ↓
освобождение старого пространства
```

То есть это не просто «более сильный VACUUM».

**`VACUUM FULL` фактически переписывает таблицу.**

---

# 🆚 VACUUM vs VACUUM FULL

|                                       | `VACUUM`   | `VACUUM FULL` |
| ------------------------------------- | ---------- | ------------- |
| Очищает dead tuples                   | ✅          | ✅             |
| Освобождает место внутри таблицы      | ✅          | ✅             |
| Может уменьшить физический размер     | Обычно ❌   | ✅             |
| Переписывает таблицу                  | ❌          | ✅             |
| Требует сильной блокировки            | Обычно нет | ✅             |
| Высокая нагрузка на I/O               | Ниже       | Выше          |
| Подходит для регулярного обслуживания | ✅          | ❌             |
| Может вернуть место ОС                | Обычно нет | ✅             |

---

# 🔐 Блокировка таблицы

Один из главных недостатков:

```python
VACUUM FULL users;
```

требует **`ACCESS EXCLUSIVE` lock** на таблицу.

Это означает, что на время операции нормальный доступ к таблице блокируется.

Упрощённо:

```text
VACUUM FULL
      ↓
ACCESS EXCLUSIVE
      ↓
другие операции с таблицей ждут
```

Поэтому запускать `VACUUM FULL` на большой production-таблице без планирования — плохая идея.

---

# 💾 Требования к диску

Поскольку таблица физически переписывается, PostgreSQL может временно использовать значительный объём дополнительного дискового пространства.

Например:

```text
Старая таблица → 500 GB
```

Во время перестроения может потребоваться дополнительное пространство для новой версии таблицы и связанных структур.

Поэтому перед выполнением `VACUUM FULL` на большой таблице важно учитывать:

* свободное место на диске;
* размер таблицы;
* размер индексов;
* продолжительность блокировки;
* нагрузку на I/O;
* время простоя или допустимое окно обслуживания.

---

# 📈 Когда VACUUM FULL может понадобиться

`VACUUM FULL` может быть оправдан, когда таблица сильно раздулась:

```text
Bloat
  ↓
очень много свободного пространства
  ↓
физический размер таблицы значительно больше
реального объёма данных
```

Например:

```text
Было:
1 TB таблица

Удалили большую часть данных.

После обычного VACUUM:
физический файл всё ещё очень большой.

VACUUM FULL:
таблица переписана
↓
размер существенно уменьшился.
```

---

# ⚠️ VACUUM FULL — не средство регулярной очистки

Неправильно:

```text
Каждую ночь:
VACUUM FULL
```

Правильная модель:

```text
Обычная эксплуатация
        ↓
Autovacuum
        ↓
регулярное обслуживание
```

А `VACUUM FULL` — специальная тяжёлая операция, когда действительно требуется **физическая реорганизация таблицы**.

---

# 🧹 Почему обычного VACUUM обычно достаточно

После:

```python
DELETE FROM users
WHERE created_at < '2020-01-01';
```

старые версии становятся кандидатами на очистку.

Обычный:

```python
VACUUM users;
```

освободит пространство для повторного использования:

```text
[DATA][FREE][DATA][FREE][DATA]
```

Если потом выполнить:

```python
INSERT INTO users (...);
```

PostgreSQL сможет использовать свободные страницы.

Поэтому физический размер таблицы не обязательно должен уменьшаться.

---

# 🧠 VACUUM FULL и Bloat

Связь:

```text
UPDATE / DELETE
       ↓
Dead Tuples
       ↓
Bloat
       ↓
таблица занимает больше места,
чем необходимо для актуальных данных
       ↓
VACUUM
       ↓
место становится reusable
```

Если необходимо именно **сжать физический размер таблицы**:

```text
VACUUM FULL
       ↓
физическая перестройка
       ↓
компактная таблица
```

---

# 🔎 Как проверить размер таблицы

Можно посмотреть размер:

```python
SELECT
    pg_size_pretty(pg_total_relation_size('users'));
```

Например:

```text
250 GB
```

Но один размер сам по себе ещё не означает, что таблица обязательно требует `VACUUM FULL`.

Нужно оценивать:

* количество dead tuples;
* bloat;
* характер изменений;
* свободное место;
* реальную необходимость уменьшения физического файла.

# 🆚 VACUUM FULL и REINDEX

Их тоже важно не путать.

### VACUUM FULL

Перестраивает:

```text
TABLE
```

и позволяет избавиться от значительного количества свободного пространства в таблице.

### REINDEX

Перестраивает:

```text
INDEX
```

Например:

```python
REINDEX INDEX idx_users_email;
```

Упрощённо:

```text
VACUUM FULL
→ проблема с таблицей / её физическим размером

REINDEX
→ проблема с индексом / его физической структурой
```

При `VACUUM FULL` индексы таблицы также перестраиваются как часть процесса.

---

# 🆚 VACUUM FULL и обычный VACUUM

Представь таблицу:

```text
100 GB физически
30 GB актуальных данных
70 GB свободного пространства
```

### Обычный VACUUM

```text
Физически:
100 GB

Актуальные данные:
30 GB

Свободное место:
70 GB
```

Размер файла может остаться около:

```text
100 GB
```

Но PostgreSQL сможет использовать свободное место.

### VACUUM FULL

```text
Физически:
≈30 GB

Актуальные данные:
≈30 GB
```

То есть таблица физически сжимается.

---

# ⚠️ Почему нельзя постоянно использовать VACUUM FULL

Потому что операция:

* переписывает всю таблицу;
* создаёт большую нагрузку на дисковую подсистему;
* требует дополнительного дискового пространства;
* блокирует таблицу;
* может долго выполняться на больших таблицах.

Поэтому в production его обычно выполняют **редко и осознанно**.

---

# 🧩 Что использовать вместо VACUUM FULL

В зависимости от ситуации могут применяться:

```text
Autovacuum
VACUUM
VACUUM (ANALYZE)
REINDEX
pg_repack
партиционирование
```

Например, `pg_repack` может использоваться для онлайн-перестройки таблиц с меньшей блокировкой, но это уже отдельный инструмент и требует дополнительной настройки.

# 🎤 Частые вопросы на собеседовании

### Чем VACUUM FULL отличается от VACUUM?

> Обычный `VACUUM` очищает dead tuples и освобождает пространство для повторного использования внутри таблицы. `VACUUM FULL` физически переписывает таблицу и может уменьшить её размер на диске.

### Почему VACUUM FULL опасен для production?

> Он требует `ACCESS EXCLUSIVE` блокировки таблицы, переписывает данные и создаёт существенную нагрузку на I/O и дисковое пространство.

### Уменьшает ли обычный VACUUM размер файла таблицы?

> Обычно нет. Он освобождает пространство внутри таблицы для повторного использования.

### Когда использовать VACUUM FULL?

> Когда необходимо физически уменьшить таблицу из-за значительного количества свободного пространства или bloat и допустима сильная блокировка на время перестройки.

### Что делает autovacuum?

> Автоматически запускает `VACUUM` и `ANALYZE` для обслуживания таблиц. `VACUUM FULL` не является его обычным механизмом регулярного обслуживания.

### VACUUM FULL удаляет dead tuples?

> Да. При физической перестройке таблицы старые ненужные версии не переносятся в новую компактную таблицу.

### VACUUM FULL перестраивает индексы?

> Да. При перестройке таблицы PostgreSQL также перестраивает связанные с ней индексы.

# 🧭 Ментальная модель

```text
              MVCC
                ↓
         UPDATE / DELETE
                ↓
          Dead Tuples
                ↓
              Bloat
                ↓
        ┌───────┴────────┐
        ↓                ↓
     VACUUM          VACUUM FULL
        ↓                ↓

версии               ↓
        ↓            компактная таблица
место reusable       ↓
        ↓            вернуть место ОС
размер обычно        ↓
не уменьшается       ACCESS EXCLUSIVE
                     LOCK
```

## 🔑 Главное

```text
VACUUM FULL
= физическая перестройка таблицы.

Основная цель:
→ избавиться от значительного свободного пространства;
→ уменьшить физический размер таблицы.

В отличие от обычного VACUUM:
→ переписывает таблицу;
→ может вернуть место операционной системе;
→ требует ACCESS EXCLUSIVE lock;
→ требует дополнительного дискового пространства;
→ создаёт большую нагрузку на I/O.

Обычный VACUUM:
→ регулярное обслуживание;
→ очищает dead tuples;
→ освобождает место для повторного использования;
→ обычно не уменьшает размер файла.

VACUUM FULL:
→ тяжёлая операция;
→ не предназначен для регулярного обслуживания;
→ применяется осознанно при необходимости физического сжатия.

Главная фраза:

"VACUUM освобождает место внутри таблицы,
а VACUUM FULL физически переписывает таблицу
и может вернуть это место операционной системе."
```
