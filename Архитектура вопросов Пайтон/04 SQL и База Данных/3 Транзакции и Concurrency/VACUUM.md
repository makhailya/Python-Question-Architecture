# 🧹 VACUUM в PostgreSQL

## 🎯 Ответ на собеседовании

**VACUUM** — это механизм PostgreSQL, который очищает таблицы от **старых версий строк (dead tuples)**, появившихся из-за MVCC, и выполняет другую работу по обслуживанию таблиц.

При `UPDATE` и `DELETE` старые версии строк не удаляются физически сразу. Они становятся невидимыми для новых транзакций, но некоторое время могут быть нужны старым snapshot.

Когда эти версии больше не нужны, `VACUUM` может освободить их место для **повторного использования**.

Важно:

> `VACUUM` обычно **не уменьшает физический размер файла таблицы**, а освобождает место внутри таблицы для последующих записей.

---

## 🎤 Суперкоротко

> **VACUUM** очищает PostgreSQL от старых версий строк, которые больше не нужны из-за MVCC, и помогает предотвращать накопление dead tuples и bloat. Обычный `VACUUM` освобождает место для повторного использования, но обычно не возвращает его операционной системе.

---

# 📌 Откуда берутся dead tuples

Это напрямую связано с **MVCC**.

Допустим, есть:

```text
id = 1
balance = 100
```

Выполняем:

```python
UPDATE accounts
SET balance = 200
WHERE id = 1;
```

PostgreSQL создаёт новую версию:

```text
Старая версия:
balance = 100

Новая версия:
balance = 200
```

Старая версия становится **dead tuple**, когда она больше не нужна ни одному snapshot.

То же самое происходит при `DELETE`.

```text
DELETE
  ↓
строка становится невидимой
  ↓
после завершения необходимых snapshot
  ↓
dead tuple
  ↓
VACUUM
```

---

# 🧩 Почему PostgreSQL не удаляет строку сразу

Из-за MVCC старая версия может быть нужна другой транзакции.

Например:

```text
Transaction A
    ↓
создала snapshot
    ↓
читает старую версию

Transaction B
    ↓
UPDATE
    ↓
создала новую версию
```

Получается:

```text
          строка
            │
      ┌─────┴─────┐
      ↓           ↓
   старая       новая
   версия       версия
      ↓           ↓
 Transaction A  Transaction B
```

PostgreSQL не может просто физически удалить старую версию, пока она потенциально нужна.

После того как она становится ненужной:

```text
dead tuple
    ↓
VACUUM
    ↓
очистка
```

---

# 🧹 Что делает VACUUM

Основные задачи:

### 1. Очищает dead tuples

Удаляет информацию о старых версиях строк, которые больше не нужны.

### 2. Освобождает место внутри таблицы

Освободившееся пространство может использоваться для новых строк.

### 3. Обновляет Visibility Map

Это важно, в частности, для эффективного выполнения:

```text
Index Only Scan
```

### 4. Помогает обновлять информацию для планировщика

В зависимости от операции обслуживания могут обновляться статистические данные, но для полноценного сбора статистики используется:

```python
ANALYZE
```

### 5. Поддерживает работу Freeze

VACUUM участвует в предотвращении проблем с переполнением transaction ID и замораживании старых tuple.

---

# 🆚 VACUUM и DELETE

Очень важное различие.

Команда:

```python
DELETE FROM users
WHERE id = 100;
```

не означает:

```text
физически удалить данные прямо сейчас
```

Упрощённо:

```text
DELETE
  ↓
строка становится невидимой
  ↓
остаётся физическая версия
  ↓
VACUUM
  ↓
место становится reusable
```

---

# 🆚 VACUUM и VACUUM FULL

Это один из популярных вопросов на собеседовании.

## VACUUM

```python
VACUUM users;
```

Обычный `VACUUM`:

* очищает dead tuples;
* освобождает место для повторного использования;
* обычно не уменьшает размер файла таблицы;
* может выполняться вместе с обычной работой системы.

Упрощённо:

```text
До:

[DATA][DEAD][DATA][DEAD][DATA]

VACUUM

После:

[DATA][FREE][DATA][FREE][DATA]
```

Размер файла примерно тот же, но свободное место можно использовать повторно.

---

## VACUUM FULL

```python
VACUUM FULL users;
```

`VACUUM FULL` физически переписывает таблицу и может существенно уменьшить её размер на диске.

Упрощённо:

```text
До:

[DATA][FREE][DATA][FREE][DATA][FREE]

VACUUM FULL

После:

[DATA][DATA][DATA]
```

Но есть важный недостаток:

> `VACUUM FULL` требует сильной блокировки таблицы и может быть существенно более дорогой операцией.

Поэтому это **не обычная ежедневная замена обычному VACUUM**.

---

# 📊 VACUUM vs VACUUM FULL

|                                                | VACUUM     | VACUUM FULL |
| ---------------------------------------------- | ---------- | ----------- |
| Очищает dead tuples                            | ✅          | ✅           |
| Освобождает место для повторного использования | ✅          | ✅           |
| Обычно уменьшает размер файла таблицы          | ❌          | ✅           |
| Переписывает таблицу                           | ❌          | ✅           |
| Сильная блокировка                             | Обычно нет | ✅           |
| Дешевле                                        | ✅          | ❌           |
| Подходит для регулярного обслуживания          | ✅          | Обычно нет  |

---

# 📈 Что такое bloat

**Bloat** — избыточное пространство, которое возникает из-за большого количества старых версий строк и других особенностей физического хранения.

Например:

```text
UPDATE
UPDATE
UPDATE
UPDATE
DELETE
UPDATE
    ↓
много старых версий
    ↓
dead tuples
    ↓
bloat
```

Если таблица постоянно изменяется:

```text
INSERT
UPDATE
DELETE
UPDATE
DELETE
...
```

то MVCC постоянно создаёт новые версии.

Поэтому PostgreSQL должен регулярно выполнять обслуживание.

---

# 🤖 Autovacuum

В PostgreSQL обычно не нужно вручную запускать `VACUUM` после каждого `UPDATE`.

Для этого существует:

```text
autovacuum
```

**Autovacuum** — фоновый процесс PostgreSQL, который автоматически запускает `VACUUM` и `ANALYZE`, когда это необходимо по настроенным порогам.

Упрощённо:

```text
Много UPDATE / DELETE
        ↓
растёт количество dead tuples
        ↓
Autovacuum
        ↓
VACUUM
        ↓
очистка
```

---

# ⚙️ Почему autovacuum важен

Без нормальной работы autovacuum постепенно могут возникнуть:

* большое количество dead tuples;
* bloat;
* рост таблиц и индексов;
* ухудшение производительности;
* необходимость более тяжёлого ручного обслуживания.

Поэтому в production PostgreSQL:

> **Autovacuum — критически важная часть нормальной эксплуатации базы.**

# 🧊 VACUUM и Transaction ID Wraparound

У PostgreSQL есть ещё одна важная задача VACUUM — **замораживание старых tuple** (`FREEZE`).

PostgreSQL использует transaction ID для определения видимости изменений.

Transaction ID имеет ограниченный диапазон, поэтому его нельзя бесконечно использовать без специального обслуживания.

Старые версии можно «заморозить»:

```text
старый tuple
    ↓
VACUUM / FREEZE
    ↓
frozen tuple
```

Это предотвращает проблему **transaction ID wraparound**.

Поэтому VACUUM нужен не только для борьбы с bloat.

---

# 🔗 VACUUM и Visibility Map

PostgreSQL поддерживает специальную структуру:

```text
Visibility Map
```

Она хранит информацию о страницах таблицы, в частности о том, являются ли они:

```text
all-visible
```

То есть видимы ли все tuple на странице всем текущим и будущим транзакциям с точки зрения соответствующего механизма видимости.

Это важно для:

```text
Index Only Scan
```

Например:

```text
Index Only Scan
       ↓
данные есть в индексе
       ↓
Visibility Map говорит:
страница all-visible
       ↓
можно не читать heap
```

Поэтому нормальная работа VACUUM помогает PostgreSQL поддерживать условия для эффективных `Index Only Scan`.

---

# 🧠 VACUUM и Index Only Scan

Связь:

```text
UPDATE / DELETE
       ↓
старые версии
       ↓
VACUUM
       ↓
Visibility Map
       ↓
страницы становятся all-visible
       ↓
Index Only Scan
может избежать Heap Fetches
```

Поэтому VACUUM связан не только с размером таблицы, но и с производительностью некоторых индексных запросов.

---

# ⚠️ Долгие транзакции мешают VACUUM

Это важный практический момент.

Представим:

```text
Transaction A
BEGIN
   ↓
долго работает
```

А параллельно:

```text
Transaction B
UPDATE
UPDATE
UPDATE
DELETE
UPDATE
```

Старые версии могут оставаться необходимыми для snapshot транзакции A.

В результате:

```text
Долгая транзакция
       ↓
старые версии нельзя очистить
       ↓
VACUUM не может удалить всё
       ↓
dead tuples накапливаются
       ↓
bloat
```

Поэтому долгие транзакции могут быть серьёзной проблемой для PostgreSQL.

# 🔬 Как посмотреть dead tuples

Можно посмотреть статистику таблиц через системное представление:

```python
SELECT
    relname,
    n_live_tup,
    n_dead_tup
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC;
```

Здесь:

```text
n_live_tup
```

— приблизительное количество живых строк.

```text
n_dead_tup
```

— приблизительное количество dead tuples.

Это полезно для диагностики необходимости обслуживания.

# 📌 VACUUM ANALYZE

Можно выполнить:

```python
VACUUM ANALYZE users;
```

Это сочетает:

```text
VACUUM
+
ANALYZE
```

То есть:

```text
VACUUM
→ очистка dead tuples

ANALYZE
→ сбор статистики для планировщика
```

Это разные задачи.

---

# 🆚 VACUUM vs ANALYZE

|                                                | VACUUM             | ANALYZE  |
| ---------------------------------------------- | ------------------ | -------- |
| Очищает dead tuples                            | ✅                  | ❌        |
| Освобождает место для повторного использования | ✅                  | ❌        |
| Обновляет статистику планировщика              | Не основная задача | ✅        |
| Связан с MVCC                                  | ✅                  | Косвенно |
| Нужен для оптимальных планов                   | Косвенно           | ✅        |

# 🧠 Важное различие: свободное место vs уменьшение файла

Это часто спрашивают.

После:

```python
DELETE FROM users;
```

и:

```python
VACUUM users;
```

может быть:

```text
размер файла таблицы:
100 GB → 100 GB
```

Но внутри может появиться свободное пространство:

```text
100 GB физически
│
├── DATA
├── FREE
├── DATA
├── FREE
└── DATA
```

Это место PostgreSQL может использовать для новых данных.

А чтобы реально уменьшить физический размер таблицы:

```python
VACUUM FULL users;
```

или используют другие методы реорганизации, в зависимости от задачи.

# 🎤 Частые вопросы на собеседовании

### Что такое VACUUM?

> VACUUM — механизм обслуживания PostgreSQL, который очищает старые версии строк, ставшие ненужными из-за MVCC, и освобождает пространство для повторного использования.

### Почему нужен VACUUM?

> Потому что при MVCC `UPDATE` и `DELETE` оставляют старые версии строк. Их необходимо очищать после того, как они больше не нужны транзакциям.

### Уменьшает ли VACUUM размер таблицы на диске?

> Обычный VACUUM обычно нет. Он освобождает место внутри таблицы для повторного использования. Для физического уменьшения таблицы используется `VACUUM FULL`, который переписывает таблицу и требует более сильной блокировки.

### Что такое VACUUM FULL?

> Это более тяжёлая операция, которая переписывает таблицу и может вернуть свободное пространство операционной системе, но требует сильной блокировки и обычно не используется как регулярное обслуживание.

### Что такое autovacuum?

> Это фоновые процессы PostgreSQL, которые автоматически запускают VACUUM и ANALYZE в зависимости от состояния таблиц.

### Как MVCC связан с VACUUM?

> MVCC создаёт несколько версий строк. Когда старая версия больше не нужна ни одному snapshot, VACUUM может очистить её и освободить место.

### Почему длинные транзакции мешают VACUUM?

> Потому что их старые snapshot могут всё ещё требовать старые версии строк. Поэтому PostgreSQL не всегда может их очистить.

### Как VACUUM связан с Index Only Scan?

> VACUUM поддерживает Visibility Map. Если страницы таблицы помечены как all-visible, PostgreSQL при Index Only Scan может избежать обращения к heap.

# 🧭 Ментальная модель

```text
                  MVCC
                    ↓
        UPDATE / DELETE создают
          старые версии строк
                    ↓
              Dead Tuples
                    ↓
               AUTOVACUUM
                    ↓
                VACUUM
                    ↓
        ┌───────────┴───────────┐
        ↓                       ↓
очистка dead tuples       Visibility Map
        ↓                       ↓
место reusable            Index Only Scan
```

```text

= обслуживание PostgreSQL после работы MVCC.

        ↓
старые версии строк
        ↓
dead tuples
        ↓
VACUUM
        ↓
очистка и освобождение места
для повторного использования.

Обычный VACUUM:
→ не переписывает всю таблицу;

→ освобождает место внутри таблицы.

VACUUM FULL:
→ переписывает таблицу;

Autovacuum:
→ автоматически выполняет VACUUM и ANALYZE.
```
