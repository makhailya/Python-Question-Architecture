# Amazon DynamoDB — конспект для Python Backend

## Формула для собеседования

**Amazon DynamoDB — это полностью управляемая AWS NoSQL-база данных**, поддерживающая модели key-value и документов. Она рассчитана на низкие задержки и масштабирование без самостоятельного управления серверами БД. Доступ к данным строится вокруг первичного ключа, состоящего из partition key и, опционально, sort key.

**Ключевые слова:** NoSQL, Partition Key, Sort Key, Primary Key, GSI, LSI, Query, Scan, Capacity Units, Eventual Consistency, DynamoDB Streams, TTL.

## Короткий ответ

- **Table** — таблица.
- **Item** — запись в таблице.
- **Attribute** — атрибут записи.
- **Partition Key (PK)** — ключ, определяющий распределение данных.
- **Sort Key (SK)** — дополнительный ключ для упорядочивания элементов внутри одной группы partition key.
- **GSI** — глобальный вторичный индекс с собственной схемой ключей.
- **LSI** — локальный вторичный индекс с тем же partition key, что у таблицы.
- **Query** — чтение по ключу.
- **Scan** — последовательное сканирование таблицы или индекса.
- **TTL** — автоматическое удаление элементов после заданного времени.
- **DynamoDB Streams** — поток изменений элементов таблицы.

## Ответ на собеседовании

DynamoDB — это облачная NoSQL-база данных AWS для приложений, которым нужны предсказуемые задержки, высокая доступность и автоматическое масштабирование. Она поддерживает документы и key-value, но не предоставляет привычную реляционную модель с произвольными JOIN.

В отличие от PostgreSQL, модель данных DynamoDB проектируют прежде всего под конкретные шаблоны доступа: какие запросы должны выполняться и по каким ключам. Поэтому до создания таблиц важно определить основные запросы приложения, подобрать partition key и при необходимости добавить sort key и вторичные индексы.

DynamoDB подходит для пользовательских профилей, корзин, игровых состояний, метаданных и событийных сценариев, особенно когда приложение работает в AWS.

## 1. Основные понятия

```text
DynamoDB
└── Table: Orders
    ├── Item
    │   ├── PK: USER#123
    │   ├── SK: ORDER#2026-001
    │   └── status: "paid"
    └── Item
        ├── PK: USER#123
        ├── SK: ORDER#2026-002
        └── status: "pending"
```

Пример элемента:

```json
{
  "PK": "USER#123",
  "SK": "ORDER#2026-001",
  "status": "paid",
  "amount": 2500,
  "created_at": "2026-10-20T12:00:00Z"
}
```

В DynamoDB таблица не требует, чтобы каждый элемент содержал одинаковый набор атрибутов. Однако первичный ключ должен соответствовать схеме таблицы.

## 2. Partition Key и Sort Key

Первичный ключ может быть двух видов.

### Простой первичный ключ

Состоит только из partition key.

```text
PK = USER#123
```

Он должен быть уникальным для каждого элемента таблицы.

### Составной первичный ключ

Состоит из partition key и sort key.

```text
PK = USER#123
SK = ORDER#001
```

Комбинация PK + SK должна быть уникальной.

Sort key позволяет хранить несколько связанных элементов под одним partition key и эффективно запрашивать диапазоны значений.

Например:

```text
PK = USER#123
SK = ORDER#001
SK = ORDER#002
SK = ORDER#003
```

Можно получить заказы пользователя, не сканируя всю таблицу.

**Важно:** плохо выбранный partition key может приводить к неравномерному распределению нагрузки и горячим партициям (*hot partitions*).

## 3. CRUD-операции

В Python для работы с DynamoDB часто используют библиотеку `boto3`.

Установка:

```bash
pip install boto3
```

Пример с низкоуровневым клиентом:

```python
import boto3

client = boto3.client("dynamodb", region_name="eu-central-1")

client.put_item(
    TableName="Users",
    Item={
        "PK": {"S": "USER#123"},
        "name": {"S": "Иван"},
        "age": {"N": "30"},
    },
)
```

Здесь `S` означает строку, а `N` — числовой атрибут. В низкоуровневом API DynamoDB типы указываются явно.

### Чтение элемента

```python
response = client.get_item(
    TableName="Users",
    Key={
        "PK": {"S": "USER#123"},
    },
)

item = response.get("Item")
```

Если элемент отсутствует, поле `Item` может не присутствовать в ответе.

### Обновление

```python
client.update_item(
    TableName="Users",
    Key={
        "PK": {"S": "USER#123"},
    },
    UpdateExpression="SET #n = :name",
    ExpressionAttributeNames={
        "#n": "name",
    },
    ExpressionAttributeValues={
        ":name": {"S": "Анна"},
    },
)
```

`UpdateExpression` описывает изменение атрибутов. Псевдонимы в `ExpressionAttributeNames` помогают безопасно обращаться к именам, которые конфликтуют с зарезервированными словами.

### Удаление

```python
client.delete_item(
    TableName="Users",
    Key={
        "PK": {"S": "USER#123"},
    },
)
```

Для простых CRUD-операций можно также использовать более удобный ресурсный интерфейс `boto3.resource("dynamodb")`.

## 4. Query vs Scan

Это одна из важнейших тем на собеседовании.

| Query | Scan |
|---|---|
| Запрашивает данные по ключу | Перебирает элементы таблицы или индекса |
| Использует partition key и условия по sort key | Может читать большое количество элементов |
| Обычно предпочтительнее для рабочих запросов | Может быть дорогим и медленным на больших объёмах |

Пример Query:

```python
response = client.query(
    TableName="Orders",
    KeyConditionExpression="PK = :pk",
    ExpressionAttributeValues={
        ":pk": {"S": "USER#123"},
    },
)
```

Этот запрос возвращает элементы с указанным partition key. Если у таблицы есть sort key, к запросу можно добавить условие по нему.

**Правило:** если приложению регулярно нужен конкретный шаблон чтения, лучше проектировать ключи и индексы под него, а не использовать Scan.

## 5. Вторичные индексы

В DynamoDB есть два основных вида вторичных индексов.

### Global Secondary Index (GSI)

- Может иметь собственные partition key и sort key.
- Позволяет запрашивать данные по альтернативным ключам.
- Может использоваться для запросов, которые невозможно эффективно выполнить по первичному ключу таблицы.

Например, таблица заказов имеет ключи `PK` и `SK`, но приложению нужно искать заказы по статусу.

GSI может использовать:

```text
GSI1PK = STATUS#PAID
GSI1SK = 2026-10-20T12:00:00Z
```

### Local Secondary Index (LSI)

- Использует тот же partition key, что и таблица.
- Имеет другой sort key.
- Должен быть определён при создании таблицы.

**На собеседовании:** GSI меняет схему ключей для альтернативного доступа, а LSI сохраняет partition key основной таблицы и меняет способ сортировки.

## 6. Моделирование данных

В реляционной БД часто начинают с сущностей и связей. В DynamoDB сначала определяют **access patterns** — реальные запросы приложения.

Например, для заказов:

1. Получить заказ по ID.
2. Получить все заказы пользователя.
3. Получить заказы пользователя за определённый период.
4. Найти оплаченные заказы.

После этого подбирают ключи и индексы.

Пример схемы с шаблоном *single-table design*:

```text
PK             SK                   Тип
USER#123       PROFILE               Профиль
USER#123       ORDER#001             Заказ
USER#123       ORDER#002             Заказ
```

Несколько типов сущностей могут храниться в одной таблице, если ключи и шаблоны доступа спроектированы соответствующим образом.

**Важно:** single-table design — распространённый подход, но не обязательное требование. Количество таблиц определяется задачами и удобством сопровождения.

## 7. Capacity и стоимость

DynamoDB предлагает два основных режима пропускной способности:

- **On-demand** — сервис автоматически обрабатывает меняющуюся нагрузку в рамках своих ограничений и правил масштабирования; оплата зависит от использования.
- **Provisioned capacity** — задаются единицы чтения и записи, можно использовать auto scaling.

Единицы пропускной способности учитывают объём данных и тип операции. На стоимость также влияют индексы, хранение, потоки изменений, резервное копирование и другие функции.

Для собеседования важно понимать: большие элементы, неэффективные запросы и лишние индексы могут повышать стоимость.

## 8. Согласованность и транзакции

DynamoDB поддерживает разные варианты согласованности чтения.

- **Eventually consistent read** — чтение может некоторое время возвращать не самые свежие данные.
- **Strongly consistent read** — доступно для поддерживаемых операций чтения таблицы и LSI, но не для GSI.
- **Transactions** — позволяют выполнять группы операций с атомарной семантикой в поддерживаемых пределах сервиса.

Не каждый запрос должен использовать строго согласованное чтение: оно может иметь другую стоимость и доступно не для всех видов чтения.

## 9. TTL и DynamoDB Streams

### TTL

TTL позволяет автоматически удалять элементы, срок жизни которых истёк. Для этого задаётся атрибут с временем в формате Unix epoch seconds.

Применение:
- Временные токены.
- Временные сессии.
- Данные с ограниченным сроком хранения.

Удаление по TTL не следует считать мгновенным: удаление просроченного элемента происходит асинхронно.

### DynamoDB Streams

Streams фиксирует изменения элементов таблицы и позволяет обрабатывать их downstream-сервисами, например AWS Lambda.

Применение:
- Реакция на создание и обновление заказов.
- Синхронизация с другими системами.
- Запуск событийной обработки.

Если нужна строгая гарантия бизнес-процесса, обработчик должен учитывать повторы событий и быть идемпотентным.

## 10. DynamoDB vs PostgreSQL vs MongoDB

| Критерий | DynamoDB | PostgreSQL | MongoDB |
|---|---|---|---|
| Тип | Управляемая AWS NoSQL | Реляционная SQL | Документоориентированная NoSQL |
| Инфраструктура | Управляет AWS | Обычно управляет команда или провайдер | Самостоятельно или managed-сервис |
| Основной доступ | По ключам и индексам | SQL и связи | Документы и запросы |
| JOIN | Нет обычных реляционных JOIN | Да | Есть `$lookup`, но это не эквивалент всей реляционной модели |
| Масштабирование | Управляемое, в том числе распределённое | Зависит от архитектуры | Поддерживает репликацию и шардинг |
| Лучший сценарий | Предсказуемые access patterns в AWS | Связанные данные и сложные запросы | Гибкие документы |

## 11. Частые вопросы на собеседовании

**1. Что такое DynamoDB?**

Полностью управляемая NoSQL-база данных AWS, поддерживающая key-value и документную модель.

**2. Чем partition key отличается от sort key?**

Partition key определяет группу и распределение данных, а sort key позволяет упорядочивать элементы внутри группы и запрашивать диапазоны.

**3. Чем Query отличается от Scan?**

Query использует ключи для выборки, а Scan просматривает элементы таблицы или индекса. Для предсказуемых рабочих запросов обычно предпочтительнее Query.

**4. Что такое GSI?**

Глобальный вторичный индекс, позволяющий запрашивать данные по альтернативной схеме ключей.

**5. Что такое hot partition?**

Ситуация, когда слишком большая доля нагрузки приходится на одну партицию из-за неравномерного распределения ключей.

**6. Что такое eventual consistency?**

Модель, в которой обновление не обязательно сразу видно во всех последующих чтениях.

**7. Можно ли использовать DynamoDB как обычную реляционную БД?**

Нет. Она оптимизирована для заранее определённых шаблонов доступа и не предоставляет привычные JOIN и произвольные реляционные запросы.

**8. Для чего нужны DynamoDB Streams?**

Для получения последовательности изменений элементов и запуска последующей обработки.

**9. Удаляет ли TTL элемент точно в момент истечения срока?**

Нет. Истечение TTL делает элемент кандидатом на удаление, которое выполняется асинхронно.

**10. Как проектировать таблицу DynamoDB?**

Начать с шаблонов доступа, определить первичные ключи, оценить распределение нагрузки и добавить необходимые вторичные индексы.

