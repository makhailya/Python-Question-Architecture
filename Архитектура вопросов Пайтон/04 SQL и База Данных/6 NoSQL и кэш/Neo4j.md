# Neo4j — конспект для Python Backend

## Формула для собеседования

**Neo4j** — графовая NoSQL-база данных, которая хранит данные в виде узлов (*Nodes*), связей (*Relationships*) и свойств (*Properties*). Она предназначена для эффективной работы с данными, где важны связи между сущностями.

**Ключевая формула:**

`Neo4j = Nodes + Relationships + Properties + Cypher`

## Краткий ответ

- **Тип:** графовая NoSQL DB.
- **Модель:** Property Graph.
- **Основные сущности:** узлы, связи, свойства, метки.
- **Язык запросов:** Cypher.
- **Связи:** имеют направление и тип, могут содержать свойства.
- **Python:** официальный драйвер `neo4j`.
- **Транзакции:** поддерживаются.
- **Масштабирование:** зависит от редакции, архитектуры и конфигурации развёртывания.
- **Основные сценарии:** социальные сети, рекомендации, графы знаний, поиск путей, fraud detection, управление зависимостями.

## Ответ на собеседовании

Neo4j — графовая база данных, в которой информация хранится не только как отдельные записи, но и как связи между ними. Например, пользователь может подписываться на другого пользователя, покупать товары или состоять в определённой группе.

Вместо SQL Neo4j использует язык запросов Cypher, который позволяет описывать графовые структуры и искать пути между узлами. Это особенно удобно для запросов с несколькими уровнями связей, которые в реляционной базе потребовали бы большого количества JOIN.

Neo4j подходит для систем рекомендаций, графов знаний, обнаружения мошенничества и анализа сетей зависимостей. Однако для обычных CRUD-сервисов с табличными данными PostgreSQL часто проще и универсальнее.

## 1. Модель данных Property Graph

Neo4j использует модель Property Graph — граф, состоящий из узлов и связей, которые могут иметь свойства.

### Основные элементы

| Элемент | Описание | Пример |
|---|---|---|
| **Node** | Узел, представляющий сущность | Пользователь |
| **Relationship** | Направленная связь между узлами | `FOLLOWS` |
| **Label** | Метка, определяющая тип узла | `User`, `Product` |
| **Relationship Type** | Тип связи | `PURCHASED` |
| **Property** | Именованное значение | `name: "Илья"` |

Пример графа:

```text
(:User {name: "Илья"})
    -[:FOLLOWS]->
(:User {name: "Анна"})
    -[:PURCHASED]->
(:Product {name: "Клавиатура"})
```

Здесь:
- `User` и `Product` — метки узлов;
- `FOLLOWS` и `PURCHASED` — типы связей;
- `name` — свойство узла;
- стрелки обозначают направление связей.

### Важные особенности

- Узел может иметь несколько меток.
- Узлы и связи могут содержать свойства.
- Связь имеет направление и тип.
- Связи могут иметь собственные свойства, например дату создания или вес.
- Граф естественным образом представляет сложные взаимосвязи.

В отличие от обычной реляционной модели, связи в Neo4j являются самостоятельными элементами графа.

## 2. Что такое Cypher

**Cypher** — декларативный язык запросов Neo4j. Он позволяет описывать шаблоны графа, которые необходимо найти или изменить.

Визуально запросы напоминают структуру графа.

### Основные конструкции

| Оператор | Назначение |
|---|---|
| `MATCH` | Найти существующий шаблон графа |
| `CREATE` | Создать узлы и связи |
| `MERGE` | Найти существующий шаблон или создать его |
| `WHERE` | Фильтрация |
| `RETURN` | Вернуть результат |
| `SET` | Изменить свойства или метки |
| `DELETE` | Удалить узлы или связи |
| `WITH` | Передать промежуточный результат следующей части запроса |
| `OPTIONAL MATCH` | Найти необязательный шаблон, сохранив строки без совпадения |

### Пример чтения

Найти пользователя по имени:

```cypher
MATCH (u:User {name: "Илья"})
RETURN u;
```

Найти пользователей, на которых подписан Илья:

```cypher
MATCH (:User {name: "Илья"})-[:FOLLOWS]->(friend:User)
RETURN friend.name;
```

### Пример создания

Создать пользователя:

```cypher
CREATE (:User {
    id: "u-101",
    name: "Илья"
});
```

Создать связь между пользователями:

```cypher
MATCH (a:User {id: "u-101"})
MATCH (b:User {id: "u-102"})
CREATE (a)-[:FOLLOWS]->(b);
```

### Пример изменения

```cypher
MATCH (u:User {id: "u-101"})
SET u.city = "Екатеринбург"
RETURN u;
```

### Пример удаления связи

```cypher
MATCH (a:User {id: "u-101"})
      -[r:FOLLOWS]->
      (b:User {id: "u-102"})
DELETE r;
```

Удаление связи не удаляет сами узлы.

## 3. MATCH, CREATE и MERGE

Это три конструкции, которые особенно важно различать на собеседовании.

### MATCH

Ищет существующие узлы и связи.

```cypher
MATCH (u:User {id: "u-101"})
RETURN u;
```

Если совпадений нет, запрос возвращает пустой результат.

### CREATE

Создаёт новые узлы или связи без проверки на существование аналогичного шаблона.

```cypher
CREATE (:User {id: "u-101", name: "Илья"});
```

Повторный запуск может создать дубликат.

### MERGE

Ищет совпадающий шаблон и создаёт его, если он отсутствует.

```cypher
MERGE (u:User {id: "u-101"})
SET u.name = "Илья"
RETURN u;
```

Однако `MERGE` сам по себе не гарантирует уникальность свойства при конкурентных запросах. Для этого следует использовать ограничения уникальности и подходящие транзакции.

**Запомнить:**

- `MATCH` — найти.
- `CREATE` — создать.
- `MERGE` — найти или создать.

## 4. Связи и обход графа

Главное преимущество Neo4j проявляется при запросах, где требуется пройти через несколько связей.

### Поиск друзей друзей

```cypher
MATCH (u:User {id: "u-101"})
      -[:FOLLOWS]->
      (:User)
      -[:FOLLOWS]->
      (friend:User)
RETURN DISTINCT friend.name;
```

`DISTINCT` убирает повторяющиеся результаты.

### Поиск путей между узлами

```cypher
MATCH path = shortestPath(
    (a:User {id: "u-101"})-[:FOLLOWS*]-(b:User {id: "u-205"})
)
RETURN path;
```

Запрос иллюстрирует поиск кратчайшего пути в графе. В production-запросах следует задавать разумные ограничения длины пути и учитывать доступность алгоритма для используемой версии Neo4j.

### Почему это удобно

В реляционной модели цепочка связей обычно требует JOIN между таблицами. В графовой модели Neo4j можно непосредственно обходить связи между узлами.

Это не означает, что Neo4j всегда быстрее SQL: производительность зависит от структуры данных, индексов, формы запроса и количества посещаемых узлов.

## 5. Индексы и ограничения

Графовая модель не отменяет необходимости индексирования.

### Индекс

Индекс помогает быстро найти начальные узлы, с которых начинается обход графа.

Например:

```cypher
CREATE INDEX user_email_index IF NOT EXISTS
FOR (u:User)
ON (u.email);
```

Поиск:

```cypher
MATCH (u:User {email: "user@example.com"})
RETURN u;
```

Индекс особенно полезен, когда запрос начинается с поиска узла по уникальному или часто используемому свойству.

### Ограничение уникальности

```cypher
CREATE CONSTRAINT user_id_unique IF NOT EXISTS
FOR (u:User)
REQUIRE u.id IS UNIQUE;
```

Оно предотвращает появление нескольких узлов с меткой `User` и одинаковым значением `id`.

### Зачем нужны ограничения

- предотвращают дублирование сущностей;
- повышают целостность данных;
- позволяют безопаснее применять `MERGE`;
- упрощают идентификацию узлов.

Поддерживаемые типы ограничений зависят от версии Neo4j и используемой редакции.

## 6. Транзакции и целостность данных

Neo4j поддерживает транзакции и ACID-гарантии в рамках поддерживаемых конфигураций.

Транзакция позволяет объединить несколько операций в одну логическую единицу: либо изменения фиксируются, либо откатываются.

Пример концепции:

```text
BEGIN TRANSACTION
    создать заказ
    связать заказ с пользователем
    связать заказ с товарами
COMMIT
```

Если одна из обязательных операций завершается ошибкой, транзакцию можно откатить.

### Что важно учитывать

- Транзакции не заменяют ограничения уникальности.
- Конкурентные операции требуют продуманной стратегии работы с конфликтами.
- Долгие транзакции могут удерживать ресурсы и ухудшать производительность.
- В распределённых конфигурациях доступные гарантии зависят от архитектуры и настроек.

## 7. Использование Neo4j из Python

Официальный Python-драйвер — пакет `neo4j`.

Документация: https://neo4j.com/docs/python-manual/current/

### Установка

```bash
pip install neo4j
```

### Подключение и чтение

```python
import os

from neo4j import GraphDatabase


URI = os.environ["NEO4J_URI"]
USERNAME = os.environ["NEO4J_USERNAME"]
PASSWORD = os.environ["NEO4J_PASSWORD"]


driver = GraphDatabase.driver(
    URI,
    auth=(USERNAME, PASSWORD),
)


def find_user(user_id: str) -> list[dict]:
    query = """
    MATCH (u:User {id: $user_id})
    RETURN u.id AS id, u.name AS name
    """

    with driver.session() as session:
        result = session.run(query, user_id=user_id)
        return [record.data() for record in result]


try:
    print(find_user("u-101"))
finally:
    driver.close()
```

### Что здесь важно

- `GraphDatabase.driver()` создаёт объект драйвера.
- Драйвер следует переиспользовать, а не создавать для каждого запроса.
- `session()` создаёт сессию для выполнения операций.
- `session.run()` выполняет Cypher-запрос.
- Параметр `$user_id` передаётся отдельно от текста запроса.
- `driver.close()` закрывает ресурсы драйвера.

### Почему нужны параметры

Правильно:

```python
session.run(
    "MATCH (u:User {id: $id}) RETURN u",
    id=user_id,
)
```

Неправильно:

```python
query = f"MATCH (u:User {{id: '{user_id}'}}) RETURN u"
```

Параметризация снижает риск Cypher injection и позволяет безопасно передавать значения. Имена меток, типов связей и других элементов синтаксиса нельзя произвольно подставлять как обычные параметры; для динамического синтаксиса требуется отдельная валидация.

### Транзакции в Python

Для нескольких связанных операций можно использовать управляемую транзакцию:

```python
def create_user(tx, user_id: str, name: str):
    result = tx.run(
        """
        MERGE (u:User {id: $id})
        SET u.name = $name
        RETURN u.id AS id, u.name AS name
        """,
        id=user_id,
        name=name,
    )
    return result.single().data()


with driver.session() as session:
    user = session.execute_write(
        create_user,
        "u-101",
        "Илья",
    )
```

`execute_write()` управляет транзакцией записи. Функции транзакций могут выполняться повторно при определённых временных ошибках, поэтому внутри них не следует выполнять неидемпотентные внешние действия — например, повторно отправлять платёж или письмо.

## 8. Neo4j в архитектуре Python Backend

### Когда использовать

**1. Рекомендательная система**

Моделирование пользователей, товаров, просмотров, покупок и сходства между пользователями.

**2. Граф знаний**

Связи между понятиями, документами, компаниями, людьми и событиями.

**3. Fraud Detection**

Поиск подозрительных цепочек переводов, общих устройств, адресов и связей между аккаунтами.

**4. Анализ зависимостей**

Связи между сервисами, пакетами, компонентами инфраструктуры и ресурсами.

**5. Социальные графы**

Подписки, дружба, общие интересы и поиск связей между пользователями.

### Когда Neo4j не нужна

Не стоит выбирать графовую базу только потому, что в приложении существуют связи между сущностями.

PostgreSQL обычно предпочтительнее, если:
- преобладают обычные CRUD-операции;
- важны SQL, JOIN и реляционные ограничения;
- структура данных хорошо укладывается в таблицы;
- графовые обходы не являются ключевой частью нагрузки.

Neo4j можно использовать вместе с PostgreSQL: первая хранит граф взаимосвязей, а вторая — транзакционные данные приложения. При этом необходимо продумать синхронизацию и согласованность между двумя хранилищами.

## 9. Neo4j vs PostgreSQL vs MongoDB

| Критерий | Neo4j | PostgreSQL | MongoDB |
|---|---|---|---|
| Модель | Графовая | Реляционная | Документная |
| Основные сущности | Узлы и связи | Строки и таблицы | Документы |
| Язык запросов | Cypher | SQL | MongoDB Query API |
| Сложные связи | Основной сценарий | JOIN | Часто вложенные документы или `$lookup` |
| Графовые обходы | Естественный сценарий | Рекурсивные запросы и дополнительные решения | Не основное назначение |
| Схема | Гибкая, с метками и ограничениями | Обычно явно определённая | Гибкая |
| Транзакции | Поддерживаются | ACID | Поддерживаются, в том числе многодокументные |
| Лучший сценарий | Связанные данные и пути | Бизнес-транзакции и реляционные данные | Документные данные |

Выбор определяется характером запросов, а не только размером базы или тем, является ли база NoSQL.

## 10. Частые вопросы на собеседовании

### Что такое Neo4j?

Графовая NoSQL-база данных, которая хранит сущности в виде узлов, связи между ними и свойства этих элементов.

### Что такое Property Graph?

Модель графа, где узлы и связи могут содержать свойства, а узлы дополнительно могут иметь метки.

### Что такое Cypher?

Декларативный язык запросов Neo4j, предназначенный для поиска и изменения графовых структур.

### Чем `MATCH` отличается от `MERGE`?

`MATCH` ищет существующий шаблон. `MERGE` ищет совпадающий шаблон и создаёт его, если он не найден. Для гарантии уникальности нужно правильно настроить ограничения и учитывать конкурентные операции.

### Зачем нужны метки узлов?

Метки классифицируют узлы и используются при поиске, индексировании и настройке ограничений.

### Почему связи имеют направление?

Направление помогает моделировать отношения вроде `FOLLOWS`, `SENT` или `DEPENDS_ON`. В запросе при необходимости можно искать связи в обоих направлениях.

### Почему Neo4j удобна для рекомендательных систем?

Она позволяет проходить по нескольким уровням связей и искать связанные сущности, например товары, которые покупали пользователи с похожими интересами.

### Всегда ли Neo4j быстрее PostgreSQL?

Нет. Neo4j особенно удобна для сложных обходов графа. Для фильтрации табличных данных, агрегаций и обычных транзакционных операций PostgreSQL может оказаться эффективнее и проще.

### Можно ли использовать Neo4j вместе с PostgreSQL?

Да. Например, PostgreSQL хранит заказы и платежи, а Neo4j — граф пользователей, товаров и рекомендаций. При этом нужно решить задачу синхронизации данных.

### Как защититься от Cypher injection?

Передавать значения через параметры `$parameter`, не собирать запросы через конкатенацию пользовательского ввода и валидировать динамические имена меток или типов связей.
