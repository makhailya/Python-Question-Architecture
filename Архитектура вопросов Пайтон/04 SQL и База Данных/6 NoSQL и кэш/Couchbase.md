# Couchbase — конспект для Python Backend

## Формула для собеседования

**Couchbase — это распределённая NoSQL-платформа**, сочетающая документоориентированную базу данных, key-value-доступ, SQL-подобный язык запросов SQL++ (ранее N1QL), индексы, кэширование и репликацию. Она предназначена для приложений, которым нужны быстрый доступ к JSON-документам, горизонтальное масштабирование и высокая доступность.

**Ключевые слова:** Bucket, Scope, Collection, Document, Key-Value, SQL++, Index, SDK, Replication, XDCR, TTL.

## Короткий ответ

- **Bucket** — контейнер верхнего уровня для данных.
- **Scope** — логическая группа коллекций.
- **Collection** — группа документов.
- **Document** — JSON-документ с уникальным ключом в коллекции.
- **Key-Value API** — быстрый доступ к документу по ключу.
- **SQL++** — язык запросов для поиска и обработки документов.
- **Index** — структура для ускорения запросов.
- **XDCR** — репликация данных между кластерами.
- **TTL** — срок жизни документа.
- **SDK** — библиотека для подключения приложения к Couchbase.

## Ответ на собеседовании

Couchbase — распределённая документоориентированная NoSQL-база данных с поддержкой JSON, доступа по ключу и SQL-подобных запросов. Её особенность — сочетание быстрого key-value-доступа с возможностью выполнять запросы по полям документов.

В Python Backend Couchbase можно использовать для хранения пользовательских профилей, сессий, каталогов, настроек и других документов, для которых важны низкие задержки и масштабирование. В отличие от MongoDB, Couchbase предоставляет собственную архитектуру сервисов кластера и язык SQL++, а также интегрированные механизмы кэширования и репликации.

При проектировании важно учитывать структуру документов, индексы, распределение данных и доступность нужных сервисов в кластере.

## 1. Как устроен Couchbase

```text
Couchbase Cluster
└── Bucket: shop
    └── Scope: app
        ├── Collection: users
        │   ├── user::123 → JSON document
        │   └── user::456 → JSON document
        └── Collection: orders
            └── order::789 → JSON document
```

Пример документа:

```json
{
  "type": "user",
  "name": "Иван",
  "age": 30,
  "skills": ["Python", "FastAPI"],
  "address": {
    "city": "Екатеринбург"
  }
}
```

Документ хранится под уникальным ключом, например `user::123`.

Ключ позволяет получить документ напрямую, без поиска по его полям. Для поиска по содержимому используются SQL++ и соответствующие индексы.

## 2. Key-Value и SQL++

В Couchbase есть два принципиальных способа работы с данными.

### Key-Value

Получение документа по известному ключу.

```text
GET user::123
```

Такой доступ обычно быстрее и проще, чем поиск по произвольным полям, поскольку приложению не нужно выполнять запрос по содержимому документа.

### SQL++

SQL++ позволяет выбирать документы по условиям, сортировать и группировать результаты.

Пример:

```sql
SELECT name, age
FROM `shop`.`app`.`users`
WHERE age >= 18
ORDER BY age DESC;
```

Здесь `shop`, `app` и `users` — bucket, scope и collection.

**Важно:** запросы SQL++ для эффективной работы обычно требуют подходящих индексов. Сам факт использования SQL-подобного языка не означает, что запросы выполняются так же, как в реляционной БД.

## 3. CRUD-операции

### Создание документа

```python
collection.insert(
    "user::123",
    {
        "name": "Иван",
        "age": 30,
    },
)
```

`insert()` создаёт документ и возвращает ошибку, если такой ключ уже существует.

### Чтение по ключу

```python
result = collection.get("user::123")
user = result.content_as[dict]
print(user)
```

### Обновление

```python
collection.upsert(
    "user::123",
    {
        "name": "Иван",
        "age": 31,
    },
)
```

`upsert()` создаёт документ, если его нет, или заменяет существующий документ с таким ключом.

### Удаление

```python
collection.remove("user::123")
```

Для реального приложения необходимо обрабатывать ошибки подключения, тайм-ауты, конфликты и ситуации, когда документ не найден.

## 4. Подключение из Python

Установка SDK:

```bash
pip install couchbase
```

Пример подключения:

```python
import os

from couchbase.auth import PasswordAuthenticator
from couchbase.cluster import Cluster
from couchbase.options import ClusterOptions

auth = PasswordAuthenticator(
    os.environ["CB_USERNAME"],
    os.environ["CB_PASSWORD"],
)

cluster = Cluster(
    os.environ["CB_CONNECTION_STRING"],
    ClusterOptions(auth),
)

bucket = cluster.bucket("shop")
collection = (
    bucket.scope("app")
    .collection("users")
)

collection.upsert(
    "user::123",
    {"name": "Иван", "age": 30},
)

result = collection.get("user::123")
print(result.content_as[dict])

cluster.close()
```

Пример предполагает, что кластер, bucket, scope и collection уже созданы, а переменные окружения настроены.

На практике объект `Cluster` создают один раз на время жизни приложения и переиспользуют. При интеграции с FastAPI подключение и закрытие ресурсов удобно организовать через lifespan приложения.

## 5. Индексы

Индексы ускоряют SQL++-запросы по полям документов.

Например, индекс по возрасту:

```sql
CREATE INDEX idx_users_age
ON `shop`.`app`.`users`(age);
```

После этого запрос с фильтрацией по `age` может использовать созданный индекс.

Основные виды индексов и механизмы:
- **Primary Index** — позволяет выполнять запросы без подходящего вторичного индекса, но часто неэффективен для больших наборов данных.
- **Secondary Index** — индекс по конкретным полям документов.
- **Composite Index** — индекс по нескольким полям.
- **Covering Index** — индекс, содержащий необходимые запросу данные и позволяющий в некоторых случаях не читать полные документы.

Индексы ускоряют чтение, но занимают место и требуют ресурсов при изменении данных.

**На собеседовании:** индексы следует проектировать под реальные запросы и проверять план выполнения, а не создавать без анализа.

## 6. Транзакции и согласованность

Couchbase поддерживает транзакции с несколькими документами через SDK, в том числе для сценариев, где необходимо согласованно изменить несколько связанных записей.

Однако транзакции имеют дополнительные накладные расходы. Если операция затрагивает один документ, стоит рассмотреть возможность решить задачу атомарным обновлением этого документа.

При проектировании распределённого приложения необходимо учитывать:
- Границы транзакций.
- Конфликты параллельных изменений.
- Повторные попытки.
- Тайм-ауты.
- Идемпотентность бизнес-операций.

Доступность и согласованность также зависят от выбранных механизмов репликации и настроек чтения.

## 7. Масштабирование и репликация

Couchbase использует кластерную архитектуру. В зависимости от конфигурации разные сервисы могут выполнять хранение документов, индексирование и обработку запросов.

Основные понятия:

- **Data Service** — хранение документов и key-value-операции.
- **Query Service** — выполнение SQL++.
- **Index Service** — обслуживание индексов.
- **Replication** — репликация данных внутри кластера.
- **XDCR** — репликация между кластерами, в том числе для географически распределённых систем.

Горизонтальное масштабирование позволяет распределять нагрузку между узлами. При этом производительность зависит от схемы данных, ключей, индексов, сети и конфигурации сервисов.

## 8. TTL и кэширование

Couchbase поддерживает срок жизни документов — TTL (*Time To Live*).

Применение:
- Временные сессии.
- Кэшированные результаты.
- Временные пользовательские данные.
- Данные с ограниченным сроком хранения.

TTL не следует путать с обычным удалением по бизнес-условию: просроченный документ может физически удаляться не строго в момент истечения срока.

Couchbase также поддерживает быстрый доступ к данным в памяти. Однако не стоит считать, что любой документ всегда находится только в RAM: фактическое хранение и поведение зависят от конфигурации и архитектуры кластера.

## 9. Couchbase vs MongoDB vs DynamoDB

| Критерий | Couchbase | MongoDB | DynamoDB |
|---|---|---|---|
| Тип | Распределённая документная NoSQL-платформа | Документная NoSQL-БД | Управляемая AWS NoSQL-БД |
| Модель данных | JSON-документы и key-value | BSON-документы | Key-value и документы |
| Язык запросов | SQL++ | MQL и Aggregation Pipeline | API операций и выражения запросов |
| Доступ по ключу | Да | Да, по `_id` | Да, по первичному ключу |
| Индексы | Первичные и вторичные | Первичные и вторичные | GSI и LSI |
| Инфраструктура | Самостоятельный или управляемый кластер | Самостоятельный или управляемый сервис | Управляет AWS |
| Отличительная черта | Key-value + SQL++ + сервисная архитектура | Гибкая документная модель | Управляемое масштабирование в AWS |

Выбор зависит от требований к запросам, инфраструктуре, стоимости, масштабированию и согласованности.

## 10. Частые вопросы на собеседовании

**1. Что такое Couchbase?**

Распределённая NoSQL-платформа для хранения JSON-документов с быстрым key-value-доступом и языком запросов SQL++.

**2. Чем key-value отличается от SQL++?**

Key-value получает документ по известному ключу. SQL++ позволяет искать и обрабатывать документы по полям и условиям.

**3. Что такое SQL++?**

Язык запросов Couchbase, совместимый с JSON-ориентированной моделью данных и поддерживающий SQL-подобные операции.

**4. Зачем нужны индексы?**

Чтобы ускорять запросы по полям документов. Без подходящих индексов некоторые запросы могут потребовать чтения большого числа документов.

**5. Что такое bucket, scope и collection?**

Bucket — верхнеуровневый контейнер, scope группирует коллекции, а collection содержит документы.

**6. Чем `insert()` отличается от `upsert()`?**

`insert()` создаёт документ и завершается ошибкой, если ключ уже существует. `upsert()` создаёт документ или заменяет существующий.

**7. Что такое XDCR?**

Механизм репликации данных между кластерами Couchbase.

**8. Можно ли использовать Couchbase как кэш?**

Да, в том числе для временных данных с TTL. Но архитектуру хранения и настройки кластера нужно выбирать исходя из нагрузки и требований к сохранности.

**9. Поддерживает ли Couchbase транзакции?**

Да, SDK поддерживает транзакции с несколькими документами. Их стоит использовать, когда атомарность действительно необходима.

**10. Чем Couchbase отличается от MongoDB?**

Обе системы работают с документами, но Couchbase сочетает key-value-доступ, SQL++ и собственную сервисную архитектуру. MongoDB использует собственный язык запросов и другую архитектуру хранения и масштабирования.

