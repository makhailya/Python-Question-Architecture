# ✖️ CROSS JOIN в SQL

## 🎯 Ответ на собеседовании

**`CROSS JOIN` создаёт декартово произведение двух таблиц: каждая строка первой таблицы соединяется с каждой строкой второй таблицы.**

Если в первой таблице `N` строк, а во второй `M`, результат содержит:

```text
N × M
```

строк.

В отличие от `INNER`, `LEFT`, `RIGHT` и `FULL OUTER JOIN`, **`CROSS JOIN` не использует условие `ON` для соединения строк.**

```python
SELECT *
FROM colors
CROSS JOIN sizes;
```

---

## 🎤 Суперкоротко

```text
CROSS JOIN
→ каждая строка A × каждая строка B
→ декартово произведение
→ N × M строк
```

Например:

```text
3 цвета × 4 размера = 12 комбинаций
```

---

# 📌 Простой пример

### colors

```text
id | color
---+------
1  | red
2  | blue
3  | green
```

### sizes

```text
id | size
---+-----
1  | S
2  | M
3  | L
4  | XL
```

Выполняем:

```python
SELECT
    colors.color,
    sizes.size
FROM colors
CROSS JOIN sizes;
```

Получим:

```text
color | size
------+-----
red   | S
red   | M
red   | L
red   | XL
blue  | S
blue  | M
blue  | L
blue  | XL
green | S
green | M
green | L
green | XL
```

Итого:

```text
3 × 4 = 12 строк
```

---

# 🔹 Как это представить

```text
colors              sizes

       ───────────→ M
       ───────────→ L
       ───────────→ XL

blue   ───────────→ S
       ───────────→ M
       ───────────→ L
       ───────────→ XL

green  ───────────→ S
       ───────────→ M
       ───────────→ L
       ───────────→ XL
```

Каждая строка первой таблицы получает **каждую** строку второй.

---

# 🔢 Формула количества строк

Если:

```text
A = N строк
B = M строк
```

то:

```text
CROSS JOIN = N × M
```

Например:

```text
users = 100
products = 1000
```

Тогда:

```text
100 × 1000 = 100 000 строк
```

⚠️ Поэтому `CROSS JOIN` на больших таблицах может очень быстро создать огромный результат.

---

# 🔹 CROSS JOIN не использует ON

Обычный `INNER JOIN`:

```python
SELECT *
FROM users
INNER JOIN orders
    ON users.id = orders.user_id;
```

Здесь есть условие:

```python
ON users.id = orders.user_id
```

А `CROSS JOIN`:

```python
SELECT *
FROM users
CROSS JOIN orders;
```

Здесь `ON` не нужен.

SQL создаёт все возможные комбинации.

---

# 🔹 CROSS JOIN с WHERE

Иногда `CROSS JOIN` используют вместе с `WHERE`.

Например:

```python
SELECT *
FROM colors
CROSS JOIN sizes
WHERE colors.color = 'red';
```

Сначала концептуально создаются комбинации:

```text
red   × S
red   × M
red   × L
red   × XL
blue  × S
...
```

затем `WHERE` оставляет только:

```text
red | S
red | M
red | L
red | XL
```

Но если задача именно в соединении по условию, обычно правильнее выразить это через соответствующий `JOIN`.

---

# 🔹 CROSS JOIN и запятая в FROM

Старый синтаксис:

```python
SELECT *
FROM colors, sizes;
```

по смыслу соответствует декартову произведению.

Современная и более явная запись:

```python
SELECT *
FROM colors
CROSS JOIN sizes;
```

Предпочтительнее использовать `CROSS JOIN`, потому что сразу понятно намерение.

# 🔹 Когда CROSS JOIN действительно нужен

`CROSS JOIN` полезен, когда нужны **все возможные комбинации**.

Например:

### 🛒 Варианты товара

```text
товар × цвет × размер
```

### 📅 Расписание

```text
дни × временные интервалы
```

### 🧪 Тестовые данные

```text
пользователи × сценарии
```

### 📊 Аналитика

Например, создать полный набор:

```text
дата × категория
```

а затем присоединить фактические данные, чтобы увидеть даже комбинации, где данных нет.

# ⚠️ Главная опасность

Допустим:

```text
table_a = 10 000 строк
table_b = 10 000 строк
```

`CROSS JOIN` создаст:

```text
10 000 × 10 000
= 100 000 000 строк
```

То есть **100 миллионов строк**.

Поэтому перед `CROSS JOIN` всегда стоит понимать ожидаемый размер результата.

---

# 🔹 CROSS JOIN vs INNER JOIN

|                   | `CROSS JOIN`        | `INNER JOIN`               |
| ----------------- | ------------------- | -------------------------- |
| Условие `ON`      | ❌                   | Обычно ✅                   |
| Только совпадения | ❌                   | ✅                          |
| Все комбинации    | ✅                   | ❌                          |
| Количество строк  | `N × M`             | Зависит от совпадений      |
| Основная задача   | Получить комбинации | Соединить связанные данные |

Пример:

```text
A = 3 строки
B = 4 строки
```

### CROSS JOIN

```text
3 × 4 = 12
```

### INNER JOIN

Может вернуть:

```text
0
1
5
8
12
...
```

Количество зависит от условия соединения и данных.

---

# 🔹 CROSS JOIN vs FULL OUTER JOIN

Их легко перепутать из-за слова `FULL`.

### CROSS JOIN

```text
каждая строка A
      ×
каждая строка B
```

```text
N × M
```

### FULL OUTER JOIN

```text
совпадения
+
только A
+
только B
```

То есть:

```text
CROSS JOIN
→ комбинации

FULL OUTER JOIN
→ сопоставление + сохранение несовпавших строк
```

Представь две таблицы:

```text
A:             B:

```

`CROSS JOIN`:

```text

A3 → B2
A3 → B3
```

Получаем:

```text

```

# 🎤 Как ответить на собеседовании

**Вопрос: Что такое CROSS JOIN?**

> `CROSS JOIN` создаёт декартово произведение двух таблиц. Каждая строка первой таблицы комбинируется с каждой строкой второй. Если таблицы содержат `N` и `M` строк, результат потенциально содержит `N × M` строк. У `CROSS JOIN` нет условия `ON`.

**Вопрос: Когда он нужен?**

> Когда действительно нужны все возможные комбинации, например товар × размер, дата × категория или день × временной интервал.

**Вопрос: В чём опасность?**

> Количество строк растёт как произведение размеров таблиц, поэтому на больших таблицах результат может стать очень большим.

---

# 🎯 Главное

```text
CROSS JOIN
     ↓
A × B
     ↓
каждая строка A
соединяется
с каждой строкой B
```

Основной синтаксис:

```python
SELECT ...
FROM table_a
CROSS JOIN table_b;
```

Формула:

```text
N строк × M строк
=
N × M комбинаций
```

Запомнить:

```text
INNER JOIN
→ только совпадения

LEFT JOIN
→ всё слева

RIGHT JOIN
→ всё справа

FULL OUTER JOIN
→ всё с обеих сторон

CROSS JOIN
→ ВСЕ комбинации
```
