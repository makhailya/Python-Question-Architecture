# 🎯 Селективность условия (предиката)

## 🎯 Ответ на собеседовании

**Селективность предиката** — это характеристика условия, которая показывает, насколько сильно оно уменьшает количество строк, участвующих в дальнейшей обработке.

Проще говоря: **какая доля строк удовлетворяет условию**.

Чем **меньше строк проходит условие**, тем **выше его селективность**.

Например:

```python
SELECT *
FROM users
WHERE id = 123;
```

Если в таблице 1 000 000 строк, а условию соответствует одна строка, предикат имеет очень высокую селективность.

Селективность важна для оптимизатора PostgreSQL при выборе плана выполнения: например, использовать `Index Scan`, `Bitmap Scan` или `Seq Scan`.

---

## 🎤 Суперкоротко

> **Селективность предиката** показывает, какая доля строк удовлетворяет условию. Чем меньше подходящих строк, тем выше селективность. Высокая селективность часто делает использование индекса более выгодным, но окончательное решение принимает оптимизатор PostgreSQL.

---

## 📌 Что такое предикат

**Предикат** — это условие, которое проверяется для строк.

Например:

```python
WHERE age > 30
```

Здесь предикатом является:

```python
age > 30
```

Другие примеры:

```python
WHERE id = 100
```

```python
WHERE email = 'user@example.com'
```

```python
WHERE status = 'active'
```

```python
WHERE created_at >= '2026-01-01'
```

---

## 📊 Что такое селективность

Упрощённо селективность можно представить как:

```text
селективность ≈ количество строк, удовлетворяющих условию
                -----------------------------------------
                       общее количество строк
```

Например, есть:

```text
1 000 000 строк
```

Условию соответствует:

```text
1 000 строк
```

Тогда:

```text
1 000 / 1 000 000 = 0.001 = 0.1%
```

То есть условие пропускает только `0.1%` строк.

Это **высокоселективный предикат**.

---

## 🔥 Высокая и низкая селективность

| Селективность | Подходящих строк | Пример                  |
| ------------- | ---------------: | ----------------------- |
| Высокая       |       Очень мало | `id = 123`              |
| Средняя       |  Некоторая часть | `age BETWEEN 30 AND 40` |
| Низкая        |    Большая часть | `is_active = true`      |

⚠️ Здесь легко запутаться:

**Высокая селективность — это не много подходящих строк.**

Наоборот:

```text
Мало совпадений → высокая селективность
Много совпадений → низкая селективность
```

## 🗄️ Селективность и индекс

Рассмотрим запрос:

```python
SELECT *
FROM users
WHERE id = 123;
```

Если `id` индексирован и условие возвращает одну строку, PostgreSQL может выбрать:

```text
Index Scan
```

Почему?

Потому что искать одну строку через индекс обычно выгоднее, чем читать всю таблицу.

Теперь другой запрос:

```python
SELECT *
FROM users
WHERE is_active = true;
```

Допустим:

```text
1 000 000 пользователей
900 000 активных
```

Условие удовлетворяет `90%` строк.

В такой ситуации PostgreSQL может решить, что выгоднее:

```text
Seq Scan
```

чем искать огромное количество строк через индекс.

---

## ⚠️ Индекс не гарантирует использование

Наличие индекса само по себе не означает, что PostgreSQL его использует.

Например:

```python
CREATE INDEX idx_users_is_active
ON users(is_active);
```

ещё не означает, что запрос:

```python
SELECT *
FROM users
WHERE is_active = true;
```

обязательно будет выполнять через `Index Scan`.

Оптимизатор учитывает:

* селективность;
* статистику таблицы;
* размер таблицы;
* ожидаемое количество строк;
* стоимость чтения индекса;
* стоимость чтения таблицы;
* расположение данных;
* другие условия запроса.

Поэтому правильнее говорить:

> **Высокая селективность повышает вероятность эффективного использования индекса, но не гарантирует его использование.**

## 🔎 Селективность и EXPLAIN

Проверить план выполнения можно через:

```python
EXPLAIN
SELECT *
FROM users
WHERE age > 30;
```

В плане PostgreSQL будет оценивать количество подходящих строк:

```text
Seq Scan on users
  (cost=0.00..18000.00 rows=100000 width=...)
```

Здесь:

```text
rows=100000
```

означает, что оптимизатор ожидает примерно `100 000` строк.

Можно сравнить оценку с фактическим результатом:

```python
EXPLAIN ANALYZE
SELECT *
FROM users
WHERE age > 30;
```

Например:

```text
rows=100000
actual rows=95000
```

Если оценки сильно отличаются:

```text
rows=1000
actual rows=500000
```

это может привести к выбору неудачного плана выполнения.

## 🧩 Составной предикат

Предикат может состоять из нескольких условий:

```python
WHERE age > 30
  AND city = 'Moscow'
```

Здесь PostgreSQL должен оценить, сколько строк удовлетворяет **обоим условиям**.

Например:

```text
1 000 000 строк

age > 30
→ 500 000 строк

city = 'Moscow'
→ 100 000 строк

оба условия
→ 50 000 строк
```

Итоговое условие:

```python
WHERE age > 30
  AND city = 'Moscow'
```

пропускает:

```text
50 000 / 1 000 000 = 5%
```

Такой предикат значительно сильнее фильтрует таблицу.

---

## 🧠 Селективность ≠ кардинальность

Эти понятия связаны, но означают разное.

### Кардинальность

**Кардинальность** — количество различных значений.

Например:

```text
is_active:

true
false
```

Кардинальность:

```text
2
```

### Селективность

Селективность показывает, сколько строк удовлетворяет **конкретному условию**.

Например:

```python
WHERE is_active = true
```

Если:

```text
true  → 950 000 строк
false → 50 000 строк
```

то:

```python
WHERE is_active = true
```

имеет низкую селективность.

А:

```python
WHERE is_active = false
```

будет более селективным.

Поэтому **одна и та же колонка может иметь разную селективность для разных условий**.

## 🔗 Селективность и план выполнения

Упрощённая логика:

```text
Предикат
    ↓
Сколько строк ему соответствует?
    ↓
─────────────────────────────
        ↓
    мало строк
        ↓
высокая селективность
        ↓
Index Scan может быть выгоден
```

И наоборот:

```text
Предикат
    ↓
много подходящих строк
    ↓
низкая селективность
    ↓
Seq Scan или Bitmap Scan
может быть выгоднее
```

Но это **не абсолютное правило**.

Решение принимает оптимизатор PostgreSQL на основе стоимости выполнения плана.

## 📌 Селективность предиката и селективность индекса

Не стоит полностью отождествлять эти понятия.

### Селективность предиката

Характеристика условия:

```python
WHERE email = 'user@example.com'
```

Она показывает, насколько сильно условие сокращает количество строк.

### Селективность индекса

Характеристика того, насколько индекс способен эффективно разделять значения и находить небольшое количество подходящих строк.

Например, если `email` уникален:

```text
1 000 000 пользователей
↓
email = конкретный email
↓
1 строка
```

Такое условие очень селективно, и индекс по `email` обычно особенно полезен.

---

## ⚙️ Почему PostgreSQL вообще интересуется селективностью

Оптимизатор должен выбрать наиболее дешёвый способ выполнения запроса.

Например:

```text
Вариант 1:
Seq Scan
→ прочитать всю таблицу

Вариант 2:
Index Scan
→ прочитать индекс
→ найти нужные строки
→ обратиться к таблице
```

Если нужно найти:

```text
10 строк из 10 000 000
```

индекс может быть очень выгоден.

Если нужно найти:

```text
9 000 000 строк из 10 000 000
```

чтение всей таблицы последовательно может оказаться дешевле.

---

## 🎤 Хороший ответ на собеседовании

> **Селективность предиката — это характеристика условия, показывающая долю строк, которые ему соответствуют. Чем меньше строк проходит условие, тем выше его селективность. Например, поиск по уникальному `id` обычно очень селективен, а условие по булевому полю, которому соответствует большинство строк, имеет низкую селективность. PostgreSQL использует селективность вместе со статистикой и оценкой стоимости при выборе плана выполнения, например между Seq Scan, Index Scan и Bitmap Scan.**
