# 📇 Индекс в базе данных

## 🎯 Ответ на собеседовании

**Индекс** — это отдельная структура данных в базе данных, которая позволяет **быстрее находить строки**, не просматривая всю таблицу целиком.

Индекс ускоряет чтение, но занимает дополнительное место и **замедляет INSERT, UPDATE и DELETE**, потому что индекс тоже нужно поддерживать.

---

## 🎤 Суперкоротко

```text
Без индекса:

SELECT * FROM users
WHERE email = 'ivan@mail.ru';

→ Seq Scan
→ проверяем строки таблицы

С индексом:

→ ищем email в индексе
→ получаем нужные строки
→ читаем данные из таблицы
```

**Главная идея:**

> Индекс — это вспомогательная структура, которая ускоряет поиск данных по определённым столбцам.

---

# 1. 🔎 Зачем нужен индекс

Допустим, в таблице:

```text
users
```

находится:

```text
10 000 000 строк
```

Нужно найти:

```python
SELECT *
FROM users
WHERE email = 'ivan@mail.ru';
```

Без подходящего индекса PostgreSQL может выполнить **Seq Scan** — последовательно проверить большое количество строк.

С индексом база может быстро найти нужное значение и получить соответствующие строки.

---

# 2. 📚 Как выглядит индекс концептуально

Таблица:

```text
users

id | email
---+----------------
1  | alex@mail.ru
2  | ivan@mail.ru
3  | petr@mail.ru
```

Индекс можно представить примерно так:

```text
email              → адрес строки
-------------------------------
alex@mail.ru       → row 1
ivan@mail.ru       → row 2
petr@mail.ru       → row 3
```

То есть индекс содержит информацию, позволяющую быстро перейти к нужным данным.

Фактическая структура зависит от типа индекса.

---

# 3. 🌳 B-tree

В PostgreSQL **B-tree — индекс по умолчанию**.

Он хорошо подходит для:

```text
=
<
>
<=
>=
BETWEEN
ORDER BY
```

Например:

```python
CREATE INDEX idx_users_email
ON users(email);
```

Теперь запрос:

```python
SELECT *
FROM users
WHERE email = 'ivan@mail.ru';
```

может использовать этот индекс.

---

# 4. 🚀 Индекс не гарантирует ускорение

Важно:

> **Наличие индекса не означает, что PostgreSQL обязательно его использует.**

Planner оценивает стоимость разных вариантов.

Например, таблица содержит всего:

```text
100 строк
```

и запрос возвращает:

```text
90 строк
```

В таком случае PostgreSQL может решить, что проще сделать:

```text
Seq Scan
```

чем обращаться к индексу и затем получать большое количество строк.

Проверить решение planner можно через:

```python
EXPLAIN
SELECT *
FROM users
WHERE email = 'ivan@mail.ru';
```

---

# 5. ⚖️ Цена индекса

Индекс — не бесплатный.

Он требует:

### 💾 Дополнительное место

Индекс хранится отдельно от таблицы.

### ✍️ Дополнительную работу при записи

При:

```text
INSERT
UPDATE
DELETE
```

PostgreSQL должен поддерживать соответствующие индексы.

Поэтому:

```text
Больше индексов
      ↓
быстрее некоторые SELECT
      ↓
но дороже INSERT / UPDATE / DELETE
```

---

# 6. 🔗 Индекс и JOIN

Индекс может помогать при `JOIN`.

Например:

```python
SELECT *
FROM orders
JOIN users
    ON users.id = orders.user_id;
```

Индекс на:

```text
orders.user_id
```

может быть полезен в зависимости от выбранного плана выполнения.

Например:

```python
CREATE INDEX idx_orders_user_id
ON orders(user_id);
```

Особенно важно помнить:

> **Foreign Key сам по себе не означает, что на дочернем столбце автоматически создан индекс.**

---

# 7. 🔢 Индекс на несколько столбцов

Можно создать **композитный индекс**:

```python
CREATE INDEX idx_users_city_age
ON users(city, age);
```

Порядок столбцов важен.

Такой индекс особенно предсказуемо полезен для условий, начинающихся с ведущего столбца:

```python
WHERE city = 'Moscow';

WHERE city = 'Moscow'
  AND age = 30;
```

Но не следует запоминать это как абсолютное правило «индекс никогда не используется без первого столбца»: PostgreSQL может применять разные стратегии, включая Bitmap Scan.

---

# 8. 🎯 Индекс и селективность

**Селективность** показывает, какая доля строк подходит под условие.

Например:

```text
10 000 000 строк
```

Запрос возвращает:

```text
10 строк
```

Условие очень селективное.

Индекс здесь потенциально очень полезен.

Если условие возвращает:

```text
9 000 000 строк
```

то использование индекса может быть невыгодным.

Поэтому planner учитывает:

```text
статистику
+
селективность
+
стоимость операций
+
размер таблицы
+
другие факторы
```

---

# 9. 🧩 Основные типы индексов PostgreSQL

| Тип         | Основное применение                                   |
| ----------- | ----------------------------------------------------- |
| **B-tree**  | `=`, диапазоны, сортировка                            |
| **Hash**    | Равенство                                             |
| **GIN**     | JSONB, массивы, Full Text Search                      |
| **GiST**    | Диапазоны, геометрия и специализированный поиск       |
| **SP-GiST** | Пространственно-разделённые структуры                 |
| **BRIN**    | Очень большие таблицы с физической корреляцией данных |

Самый распространённый — **B-tree**.

---

# 10. 🔐 Уникальный индекс

Индекс может обеспечивать уникальность:

```python
CREATE UNIQUE INDEX idx_users_email
ON users(email);
```

Теперь два пользователя не смогут иметь одинаковый `email`.

На практике для бизнес-ограничения чаще используют:

```python
ALTER TABLE users
ADD CONSTRAINT users_email_unique
UNIQUE (email);
```

PostgreSQL создаёт индекс, необходимый для поддержки такого ограничения.

---

# 11. 📌 Частичный индекс

Можно индексировать только часть таблицы.

Например, только активных пользователей:

```python
CREATE INDEX idx_active_users_email
ON users(email)
WHERE is_active = true;
```

Это может быть выгоднее полного индекса, если активных пользователей относительно мало.

---

# 12. 📦 Покрывающий индекс

Индекс может содержать не только ключ поиска, но и дополнительные значения:

```python
CREATE INDEX idx_users_email
ON users(email)
INCLUDE (name);
```

Для определённых запросов это позволяет выполнить **Index Only Scan** и не обращаться к heap за самими значениями.

Но:

> **Покрывающий индекс ≠ гарантированный Index Only Scan.**

PostgreSQL также учитывает visibility map и другие условия.

---

# 13. 🔬 Как проверить индекс

Используют:

```python
EXPLAIN
SELECT *
FROM users
WHERE email = 'ivan@mail.ru';
```

Если нужно увидеть фактическое выполнение:

```python
EXPLAIN ANALYZE
SELECT *
FROM users
WHERE email = 'ivan@mail.ru';
```

Можно увидеть, например:

```text
Seq Scan
Index Scan
Index Only Scan
Bitmap Index Scan
Bitmap Heap Scan
```

---

# 14. ⚠️ Когда индекс может быть бесполезен

Индекс не всегда нужен.

Например:

* маленькая таблица;
* запрос возвращает большую часть таблицы;
* индекс имеет низкую практическую полезность для конкретного запроса;
* слишком много индексов создаёт большую нагрузку на записи;
* индекс не соответствует условиям запроса.

Поэтому принцип:

> **Не создавать индексы «на всякий случай», а смотреть на реальные запросы и планы выполнения.**

---

# 15. 🧠 Индекс ≠ отдельная копия таблицы

Индекс не является полноценной копией таблицы.

Он содержит структуру, оптимизированную для определённого типа поиска.

Упрощённо:

```text
Таблица
   │
   ├── реальные строки
   │
   └── Индекс
         │
         ├── ключ
         └── ссылка / информация
             для поиска строки
```

Конкретное внутреннее устройство зависит от типа индекса.

---

# 🎯 Главное

```text
Индекс
│
├── ускоряет поиск данных
│
├── является отдельной структурой
│
├── занимает место на диске
│
├── увеличивает стоимость записи
│
├── не гарантирует использование
│
├── planner выбирает план
│
└── EXPLAIN показывает выбранный план
```

### Формула для собеседования

> **Индекс — это вспомогательная структура данных в БД, предназначенная для ускорения поиска и доступа к строкам. Он ускоряет подходящие SELECT и некоторые JOIN/ORDER BY, но требует дополнительного места и увеличивает стоимость INSERT, UPDATE и DELETE. PostgreSQL не обязан использовать индекс — решение принимает planner на основе статистики и стоимости выполнения.**

```text
Индекс
→ быстрее чтение
→ дороже запись
→ больше места
→ planner решает, использовать его или нет
```
