# 📊 ANALYZE в PostgreSQL

## 🎯 Ответ на собеседовании

**`ANALYZE`** — команда PostgreSQL, которая собирает **статистику о содержимом таблиц и колонок** и сохраняет её для планировщика запросов.

Планировщик использует эту статистику, чтобы оценивать:

* сколько строк удовлетворит условию;
* насколько селективен предикат;
* какой индекс лучше использовать;
* какой тип `JOIN` выбрать;
* какой порядок выполнения операций будет выгоднее.

Например:

```python
ANALYZE users;
```

После этого PostgreSQL получает более актуальную информацию о данных и может строить более точные планы выполнения.

---

## 🎤 Суперкоротко

> **`ANALYZE` собирает статистику о данных и передаёт её планировщику PostgreSQL. На основе этой статистики PostgreSQL оценивает количество строк и стоимость разных вариантов выполнения запроса и выбирает план.**

---

# 📌 Зачем нужен ANALYZE

Представим таблицу:

```text
id="0a1b2c"
users
10 000 000 строк
```

И запрос:

```python
SELECT *
FROM users
WHERE age > 60;
```

Планировщику нужно понять:

```text
Сколько строк соответствует age > 60?
```

Например:

```text
Вариант A:
подходит 10 000 строк
→ Index Scan может быть выгоден

Вариант B:
подходит 9 000 000 строк
→ Seq Scan может быть выгоднее
```

Чтобы сделать такую оценку, PostgreSQL использует **статистику**.

Эту статистику собирает `ANALYZE`.

---

# 🧠 Как ANALYZE связан с планировщиком

Упрощённо:

```text
ANALYZE
   ↓
собирает статистику
   ↓
статистика хранится в PostgreSQL
   ↓
Planner получает информацию о данных
   ↓
оценивает количество строк
   ↓
оценивает стоимость планов
   ↓
выбирает план
```

Например:

```python
EXPLAIN
SELECT *
FROM users
WHERE age > 60;
```

Планировщик может показать:

```text
Seq Scan on users
(cost=0.00..180000.00 rows=2500000)
```

Здесь:

```text
rows=2500000
```

— **оценка планировщика**, основанная в том числе на статистике.

---

# 📊 Что именно собирает ANALYZE

`ANALYZE` собирает статистику по колонкам, которая помогает оценивать распределение данных.

В частности, PostgreSQL использует:

* количество строк;
* количество различных значений;
* долю `NULL`;
* наиболее частые значения;
* распределение значений;
* гистограммы;
* корреляцию физического порядка строк и значений.

Эти данные позволяют планировщику оценивать селективность условий.

---

# 🔎 ANALYZE и селективность

Мы уже рассматривали **селективность предиката**.

Например:

```python
WHERE status = 'active'
```

Планировщику важно знать:

```text
Сколько строк имеют status = 'active'?
```

Если:

```text
active → 99%
```

то условие имеет низкую селективность.

Если:

```text
active → 1%
```

то условие гораздо более селективно.

`ANALYZE` помогает PostgreSQL получить информацию, необходимую для такой оценки.

---

# 🧩 Статистика и наиболее частые значения

Представим:

```text
users.status

active    → 950 000
inactive  → 50 000
```

После `ANALYZE` PostgreSQL может знать, что некоторые значения встречаются значительно чаще других.

Это важно для запроса:

```python
SELECT *
FROM users
WHERE status = 'inactive';
```

и:

```python
SELECT *
FROM users
WHERE status = 'active';
```

Хотя используется одна и та же колонка, количество подходящих строк сильно различается.

---

# 📈 Статистика не хранит каждую строку

Важно понимать:

> `ANALYZE` не создаёт копию таблицы и не хранит полный список всех значений.

PostgreSQL собирает **статистическое представление данных**.

Упрощённо:

```text
1 000 000 строк
       ↓
    ANALYZE
       ↓
статистическая выборка
       ↓
гистограммы / частые значения /
другая статистика
       ↓
Planner
```

Поэтому статистика является **оценкой**, а не точным перечислением всех строк.

---

# 🎯 Почему оценка может быть неточной

Например:

```text
Планировщик ожидает:

rows=1000

Фактически:

actual rows=500000
```

Это серьёзное расхождение.

Причины могут быть разные:

* статистика устарела;
* данные сильно изменились;
* распределение данных сложное;
* зависимости между колонками;
* недостаточный объём статистической выборки;
* особенности конкретного предиката.

Большое расхождение между `rows` и `actual rows` может привести к неправильному выбору плана.

---

# 🔬 ANALYZE и EXPLAIN ANALYZE

Необходимо различать:

### ANALYZE

```python
ANALYZE users;
```

**Собирает статистику.**

### EXPLAIN ANALYZE

```python
EXPLAIN ANALYZE
SELECT *
FROM users
WHERE age > 60;
```

**Выполняет запрос и показывает фактическую статистику выполнения.**

То есть это совершенно разные вещи.

```text
ANALYZE
→ собирает статистику для Planner

EXPLAIN ANALYZE
→ выполняет запрос и показывает фактический план/результаты
```

---

# 🆚 ANALYZE vs VACUUM

Это очень частый вопрос.

|                            | `ANALYZE` | `VACUUM`           |
| -------------------------- | --------- | ------------------ |
| Собирает статистику        | ✅         | Не основная задача |
| Помогает Planner           | ✅         | Косвенно           |
| Очищает dead tuples        | ❌         | ✅                  |
| Связан с MVCC              | Косвенно  | Прямо              |
| Обслуживает Visibility Map | ❌         | ✅                  |
| Нужен для борьбы с bloat   | ❌         | ✅                  |

Главное:

```text
ANALYZE
→ информация для планировщика

VACUUM
→ очистка старых версий строк
```

---

# 🧩 VACUUM ANALYZE

Можно выполнить:

```python
VACUUM ANALYZE users;
```

Это сочетает две операции:

```text
VACUUM
+
ANALYZE
```

То есть:

```text
VACUUM
→ очистка dead tuples

ANALYZE
→ сбор статистики
```

Операции решают **разные задачи**, просто их можно выполнить вместе.

---

# 🤖 Autovacuum и ANALYZE

PostgreSQL обычно не требует постоянно запускать `ANALYZE` вручную.

Фоновая система **autovacuum** автоматически выполняет не только `VACUUM`, но и `ANALYZE`, когда считает это необходимым.

Упрощённо:

```text
INSERT / UPDATE / DELETE
          ↓
изменение данных
          ↓
Autovacuum
     ┌────┴────┐
     ↓         ↓
  VACUUM    ANALYZE
     ↓         ↓
очистка     статистика
MVCC        Planner
```

---

# ⚙️ Когда ANALYZE особенно важен

Например, после большой загрузки данных:

```python
INSERT INTO users (...)
SELECT ...
FROM another_table;
```

Если таблица сильно изменилась, статистика может стать неактуальной.

Можно выполнить:

```python
ANALYZE users;
```

После этого планировщик получит более свежую информацию.

Особенно важно после:

* массового `INSERT`;
* массового `UPDATE`;
* массового `DELETE`;
* изменения распределения данных.

---

# 🎚️ Статистика колонок

PostgreSQL позволяет изменять объём статистики для конкретной колонки.

Например:

```python
ALTER TABLE users
ALTER COLUMN city
SET STATISTICS 500;
```

После этого:

```python
ANALYZE users;
```

соберёт более подробную статистику для этой колонки.

Но увеличение statistics target увеличивает объём работы и размер статистики, поэтому его используют осознанно.

---

# 🔗 Статистика нескольких колонок

Иногда значения разных колонок **зависят друг от друга**.

Например:

```text
country
city
```

Если:

```text
country = Russia
```

то множество городов автоматически исключается.

Простая независимая оценка может ошибаться.

PostgreSQL поддерживает **extended statistics**, которые позволяют собирать дополнительную статистику о нескольких колонках.

Например:

```python
CREATE STATISTICS stats_users_city_country
ON city, country
FROM users;
```

После этого:

```python
ANALYZE users;
```

может собрать дополнительную информацию.

Это помогает планировщику точнее оценивать сложные условия.

---

# 📊 ANALYZE и EXPLAIN

Типичный сценарий диагностики:

```text
Запрос работает медленно
        ↓
EXPLAIN ANALYZE
        ↓
сравниваем:
estimated rows
vs
actual rows
        ↓
большое расхождение?
        ↓
проверяем статистику
        ↓
ANALYZE
        ↓
повторяем EXPLAIN ANALYZE
```

Например:

```python
EXPLAIN (ANALYZE, BUFFERS)
SELECT *
FROM orders
WHERE status = 'paid';
```

Если:

```text
rows=100
actual rows=500000
```

то оценка планировщика сильно ошиблась.

---

# ⚠️ ANALYZE не ускоряет запрос напрямую

Это важный момент.

`ANALYZE` не делает:

```text
SQL → автоматически быстрее
```

Он делает:

```text
SQL
 ↓
Planner получает более актуальную статистику
 ↓
может выбрать лучший план
 ↓
запрос может выполняться быстрее
```

То есть `ANALYZE` **помогает планировщику**, а не ускоряет выполнение запроса напрямую.

---

# 🧠 Ментальная модель

```text
             Данные
                ↓
        INSERT / UPDATE / DELETE
                ↓
       распределение изменилось
                ↓
             ANALYZE
                ↓
       статистика о данных
                ↓
           PostgreSQL
           Planner
                ↓
       оценка количества строк
                ↓
       оценка стоимости планов
                ↓
       Seq Scan / Index Scan /
       Bitmap / Join strategy
```

# 🎤 Частые вопросы на собеседовании

### Что такое ANALYZE?

> `ANALYZE` собирает статистику о содержимом таблиц и колонок, которую PostgreSQL использует для оценки количества строк и выбора оптимального плана выполнения запроса.

### Зачем нужна статистика?

> Чтобы планировщик мог оценить селективность условий, количество результирующих строк и стоимость разных вариантов выполнения запроса.

### Чем ANALYZE отличается от VACUUM?

> `ANALYZE` собирает статистику для планировщика, а `VACUUM` очищает старые версии строк, появившиеся из-за MVCC, и освобождает пространство для повторного использования.

### Чем ANALYZE отличается от EXPLAIN ANALYZE?

> `ANALYZE` собирает статистику в базе. `EXPLAIN ANALYZE` выполняет конкретный запрос и показывает фактический план и статистику его выполнения.

### Нужно ли запускать ANALYZE вручную?

> Обычно нет: autovacuum автоматически запускает `ANALYZE` для изменяющихся таблиц. Но после крупных изменений данных ручной `ANALYZE` может быть полезен.

### Что будет, если статистика устарела?

> Планировщик может неправильно оценить количество строк и выбрать неэффективный план, например Seq Scan вместо Index Scan или неподходящую стратегию JOIN.

### Что означает `rows` в EXPLAIN?

> Это оценка количества строк, которую планировщик ожидает получить на данном узле плана. В `EXPLAIN ANALYZE` её можно сравнить с `actual rows`.

---

## 🔑 Главное

```text
ANALYZE
= сбор статистики о данных.

Статистика нужна Planner PostgreSQL.

ANALYZE помогает оценить:
- количество строк;
- селективность предикатов;
- распределение значений;
- стоимость вариантов плана.

После этого Planner может выбрать:
- Seq Scan;
- Index Scan;
- Bitmap Scan;
- Nested Loop;
- Hash Join;
- Merge Join;
- и другие операции.

ANALYZE:
→ не очищает dead tuples;
→ не уменьшает таблицу;
→ не выполняет сам пользовательский SELECT.

VACUUM:
→ очищает dead tuples.

EXPLAIN ANALYZE:
→ выполняет запрос и показывает фактические показатели.

VACUUM ANALYZE:
→ VACUUM + ANALYZE.

Autovacuum:
→ автоматически выполняет VACUUM и ANALYZE.

Главная фраза:

"ANALYZE собирает статистику о данных,
а PostgreSQL использует её для оценки селективности,
количества строк и выбора оптимального плана запроса."
```
