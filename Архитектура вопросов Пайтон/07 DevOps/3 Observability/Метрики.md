# 📊 Метрики (Observability)

## 🎤 Короткий ответ

**Метрики** — это числовые показатели, которые описывают состояние и поведение системы во времени.

Например:

* загрузка CPU;
* использование памяти;
* количество HTTP-запросов;
* количество ошибок;
* latency;
* количество активных соединений;
* Kafka Consumer Lag.

Метрики позволяют быстро понять **что происходит с системой**, обнаружить аномалии и настроить алерты.

## 🎯 Формула для собеседования

> **Метрика = числовое значение + время + набор меток (labels).**

Например:

```text id="mtr82k"
http_requests_total
method="GET"
status="200"
service="api"

value = 15234
```

---

# 🔹 Что такое метрика

Метрика — это измеряемый числовой показатель системы.

Например, приложение обрабатывает HTTP-запросы:

```text id="q8m2vx"
10:00 → 100 запросов
10:01 → 150 запросов
10:02 → 230 запросов
10:03 → 900 запросов
```

По динамике можно заметить резкий рост нагрузки.

Метрики обычно собираются **регулярно** и хранятся как временные ряды (**time series**).

---

# 🔹 Time Series

**Time series** — последовательность значений метрики во времени.

Например:

```text id="t7k4mc"
timestamp    value
10:00        100
10:01        150
10:02        230
10:03        900
```

Но в системах мониторинга метрика обычно определяется не только именем.

Например:

```text id="p3m8qx"
http_requests_total{
    service="api",
    method="GET",
    status="200"
}
```

Это отдельный временной ряд.

---

# 🔹 Labels

**Labels** — дополнительные измерения метрики.

Например:

```text id="l6q9vx"
http_requests_total{
    method="POST",
    status="500",
    service="payment"
}
```

Здесь:

```text id="f2m7kc"
method  = POST
status  = 500
service = payment
```

Labels позволяют анализировать одну метрику в разных разрезах.

Например:

```text id="x4n8vp"
status="200"
status="400"
status="500"
```

---

# 🔹 Cardinality

Количество уникальных комбинаций labels называется **cardinality**.

Например:

```text id="c8m3qx"
http_requests_total{
    method="GET",
    status="200"
}
```

имеет небольшую cardinality.

А вот:

```text id="v5q7mc"
http_requests_total{
    user_id="123456"
}
```

может создать огромное количество временных рядов.

Поэтому в metrics опасно использовать высококардинальные значения:

```text id="r9m2vx"
user_id
request_id
email
UUID
```

Для таких данных чаще подходят **logs или traces**.

---

# 🔹 Основные типы метрик

В Prometheus наиболее важны четыре типа:

1. **Counter**
2. **Gauge**
3. **Histogram**
4. **Summary**

---

# 🔹 Counter

**Counter** — счётчик, который монотонно увеличивается.

Например:

```text id="u3m8qx"
Количество HTTP-запросов
Количество ошибок
Количество обработанных сообщений
Количество заказов
```

Пример:

```text id="c7q4mp"
100
101
102
103
...
```

Counter может сброситься, например после перезапуска процесса.

Поэтому обычно интересует не само абсолютное значение, а **скорость изменения**.

Например:

```text id="z6m2vk"
requests_total
```

Можно получить количество запросов в секунду.

---

# 🔹 Gauge

**Gauge** — значение, которое может как увеличиваться, так и уменьшаться.

Например:

```text id="g4q8mx"
CPU usage
Memory usage
Количество активных соединений
Размер очереди
Количество работающих задач
```

Пример:

```text id="a7m3vc"
50
60
45
80
30
```

Gauge показывает **текущее состояние**.

---

# 🔹 Counter vs Gauge

|                 | Counter               | Gauge                         |
| --------------- | --------------------- | ----------------------------- |
| Значение        | Растёт                | Может расти и уменьшаться     |
| Типичный пример | Количество запросов   | CPU                           |
| Пример          | `requests_total`      | `memory_usage`                |
| Сброс           | Возможен при рестарте | Просто новое текущее значение |

Запомнить:

> **Counter — сколько произошло. Gauge — сколько сейчас.**

---

# 🔹 Histogram

**Histogram** используется для измерения распределения значений.

Особенно полезен для:

* latency;
* размера запросов;
* времени обработки;
* размера ответов.

Например, хотим узнать время HTTP-запросов:

```text id="h8m4qx"
0–100 ms
100–200 ms
200–500 ms
500–1000 ms
>1000 ms
```

Histogram распределяет наблюдения по **bucket'ам**.

Например:

```text id="b5q7mc"
HTTP latency

≤ 100 ms   → 800 запросов
≤ 500 ms   → 950 запросов
≤ 1000 ms  → 990 запросов
≤ 5000 ms  → 1000 запросов
```

---

# 🔹 Зачем Histogram

Представим:

```text id="j4m8vx"
Средняя latency = 100 ms
```

На первый взгляд всё хорошо.

Но возможно:

```text id="p6q2mc"
99% запросов → 20 ms
1% запросов  → 8 секунд
```

Среднее значение скрывает проблему.

Histogram позволяет анализировать **перцентили**:

```text id="n7m3qx"
P50
P95
P99
```

Например:

```text id="d8q4mv"
P50 = 30 ms
P95 = 150 ms
P99 = 900 ms
```

То есть 99% наблюдений находятся примерно до 900 ms.

---

# 🔹 Summary

**Summary** также используется для измерения распределения значений и может предоставлять квантили.

Например:

```text id="s5m8qx"
P50
P95
P99
```

Но у Summary и Histogram разные свойства и возможности агрегации.

Для Prometheus в типичных backend-задачах часто предпочитают **Histogram**, особенно когда нужно агрегировать latency между несколькими экземплярами сервиса.

---

# 🔹 RED для API

Для мониторинга HTTP-сервисов часто используют методику **RED**:

```text id="r3m7vx"
R — Rate
E — Errors
D — Duration
```

### Rate

Сколько запросов приходит:

```text id="k8q2mc"
1000 requests/sec
```

### Errors

Сколько запросов завершается ошибкой:

```text id="v4m9qx"
5xx = 2%
```

### Duration

Сколько времени занимает обработка:

```text id="p7m3kc"
P50 = 40 ms
P95 = 180 ms
P99 = 700 ms
```

Для backend-разработчика RED — очень полезная модель.

---

# 🔹 USE для инфраструктуры

Для ресурсов инфраструктуры часто используют **USE**:

```text id="u6q4mx"
U — Utilization
S — Saturation
E — Errors
```

### Utilization

Насколько ресурс используется.

```text id="e8m3vp"
CPU = 80%
```

### Saturation

Насколько ресурс перегружен / есть ли очередь.

```text id="w5q7mc"
Disk I/O queue ↑
```

### Errors

Ошибки ресурса.

```text id="x3m8vq"
Disk errors
Network errors
```


# 🔹 Метрики Kubernetes

В Kubernetes можно наблюдать:

```text id="k7m3vc"
Node CPU
Node Memory
Pod CPU
Pod Memory
Pod restarts
Container status
Network traffic
Container filesystem
```

Например:

```text id="z5q8mx"
Pod memory = 850 MiB
Pod CPU    = 700m
Restarts   = 5
```

Если Pod постоянно перезапускается, метрика restart count может помочь обнаружить проблему.

---

# 🔹 Метрики Kafka

Для Kafka особенно важны:

```text id="k4m8qx"
Consumer Lag
Messages/sec
Bytes/sec
Producer rate
Consumer rate
Request latency
```

Например:

```text id="c6q2mv"
Consumer Lag
100
150
200
500
1200
```

Если lag постоянно растёт, consumer не успевает обрабатывать сообщения.

# 🔹 Prometheus

**Prometheus** — популярная система мониторинга и хранения metrics.

Упрощённая архитектура:

```text id="pr7m3x"
Application
     ↓
/metrics
     ↓
Prometheus
     ↓
Time Series
     ↓
Grafana
```

Приложение предоставляет endpoint:

```text id="m2q8vx"
GET /metrics
```

Prometheus периодически получает оттуда metrics.

---

# 🔹 Grafana

**Grafana** используется для визуализации metrics.

Например Dashboard:

```text id="g6m4qx"
┌─────────────────────────────┐
│ Requests/sec      1250      │
├─────────────────────────────┤
│ Error Rate          0.4%    │
├─────────────────────────────┤
│ P95 Latency        180 ms   │
├─────────────────────────────┤
│ CPU                 65%     │
└─────────────────────────────┘
```

Prometheus отвечает преимущественно за **сбор/хранение и запросы к metrics**, Grafana — за **визуализацию и dashboards**.

# 🔹 Метрика и Alert

Метрики позволяют создавать автоматические алерты.

Например:

```text id="al8m3q"
Error Rate > 5%
       ↓
    Alert
       ↓
Engineer
```

Или:

```text id="q5m7vx"
P95 latency > 1 sec
       ↓
      Alert
```

Важно:

> Метрика сама по себе не является alert. Alert — это правило, которое использует метрику.

# 🔹 Метрики и логи

Например, произошёл скачок ошибок.

### Metrics

Показывают:

```text id="m9q4vx"
Error rate = 8%
```

### Logs

Показывают:

```text id="l3m7qc"
Database connection timeout
```

Поэтому их используют вместе:

```text id="x6q8mv"
Metrics
   ↓
Обнаружили проблему
   ↓

   ↓

```

# 🔹 Частые вопросы на собеседовании

### Что такое метрика?

> Числовой показатель состояния или поведения системы, измеряемый во времени.

### Что такое Time Series?

> Последовательность значений метрики во времени, обычно определяемая именем метрики и набором labels.

### Что такое Counter?

> Метрика-счётчик, которая монотонно увеличивается и обычно используется для подсчёта событий.

### Что такое Gauge?

> Метрика текущего значения, которое может как увеличиваться, так и уменьшаться.

### Counter и Gauge — разница?

> Counter отвечает на вопрос «сколько событий произошло», Gauge — «какое значение сейчас».

### Зачем Histogram?

> Для анализа распределения значений, например latency, и расчёта перцентилей.

### Что такое P95?

> Значение, ниже которого находится примерно 95% наблюдений.

### Что такое Cardinality?

> Количество уникальных комбинаций labels в metrics.

### Почему высокая cardinality опасна?

> Она создаёт большое количество time series и увеличивает нагрузку на систему мониторинга.

### Что такое RED?

> Rate, Errors, Duration — количество запросов, ошибки и время обработки.

### Что такое USE?

> Utilization, Saturation, Errors — использование ресурса, его перегрузка и ошибки.

### Зачем Prometheus?

> Для сбора и хранения metrics и выполнения запросов по ним.

### Зачем Grafana?

> Для визуализации metrics и создания dashboards.

# 🔑 Главное

```text id="z8m4qx"
                    Metrics
                       │
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
     Counter         Gauge        Histogram
        │              │              │
    события         состояние       распределение
        │              │              │
        └──────────────┼──────────────┘
                       ↓
                  Time Series
                       ↓
                   Prometheus
                       ↓
                    Grafana
                       ↓
                    Dashboard
                       ↓
                     Alert
```

> **Counter** → сколько произошло
> **Gauge** → сколько сейчас
> **Histogram** → как распределены значения
> **Labels** → в каком разрезе смотрим
> **Prometheus** → собирает и хранит
> **Grafana** → визуализирует
> **Alert** → реагирует на условие
