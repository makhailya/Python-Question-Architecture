# 📁 Файловая система Linux

## 🎤 Короткий ответ

**Файловая система** — это способ организации и хранения данных на диске. В Linux она представлена единым иерархическим деревом, корнем которого является `/`.

В этой структуре находятся файлы, каталоги и специальные файловые объекты:

```text
/
├── home
├── etc
├── var
├── usr
├── tmp
└── dev
```

Linux использует файловую систему не только для обычных файлов: через специальные файловые интерфейсы система предоставляет доступ к устройствам, процессам и информации о ядре.

Для Backend-разработчика важно понимать структуру каталогов, пути, права доступа, владельцев, ссылки и основные команды работы с файлами.

---

## 🗣️ Ответ на собеседовании

Файловая система — это структура и набор правил, по которым операционная система хранит и организует данные.

В Linux используется единое дерево каталогов с корнем `/`. В отличие от Windows, где обычно используются отдельные диски вроде `C:` и `D:`, в Linux различные устройства и разделы подключаются в это дерево через точки монтирования.

Например, `/home` содержит домашние каталоги пользователей, `/etc` — конфигурацию, `/var` — изменяемые данные и логи, `/tmp` — временные файлы, а `/dev` предоставляет интерфейс к устройствам.

Кроме обычных файлов, Linux использует специальные типы файлов и виртуальные файловые системы, например `/proc` и `/sys`.

Также файловая система связана с правами доступа и владельцами, поэтому Linux позволяет контролировать, кто может читать, изменять или выполнять конкретный файл.

# 📚 Разбор поглубже

## 1. Что такое файловая система

Термин **файловая система** можно рассматривать в двух смыслах:

1. способ организации файлов и каталогов;
2. конкретная технология хранения данных на носителе.

Например:

* ext4;
* XFS;
* Btrfs;
* tmpfs.

Файловая система отвечает за то, как операционная система организует хранение и доступ к данным.

Упрощённо:

```text
Приложение
    ↓
System calls
    ↓
VFS
    ↓
Конкретная файловая система
    ↓
Диск / устройство
```

# 2. Единое дерево Linux

Главная особенность Linux — единая иерархия.

Корень:

```text
/
```

От него идут все остальные каталоги:

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── opt
├── proc
├── root
├── run
├── sys
├── tmp
├── usr
└── var
```

Поэтому абсолютный путь начинается от `/`.

Например:

```text
/home/ilya/project/app.py
```

---

# 3. Корневой каталог `/`

`/` — **корень файловой системы**.

Это не домашний каталог пользователя.

Например:

```text
/
├── home
│   └── ilya
└── root
```

Здесь:

```text
/          → корень файловой системы
/home/ilya → домашний каталог пользователя
/root      → домашний каталог root
```

---

# 4. Основные каталоги

## `/home`

Домашние каталоги обычных пользователей.

```text
/home
└── ilya
    ├── projects
    ├── downloads
    └── documents
```

---

## `/root`

Домашний каталог суперпользователя `root`.

Важно:

```text
/
```

и:

```text
/root
```

— совершенно разные вещи.

---

## `/etc`

Конфигурационные файлы системы и приложений.

Например:

```text
/etc/ssh/
/etc/systemd/
/etc/nginx/
```

Для Backend-разработчика `/etc` часто встречается при настройке серверов.

---

## `/var`

Данные, которые изменяются во время работы системы.

Например:

```text
/var/log/
/var/lib/
/var/cache/
```

Особенно важен:

```text
/var/log
```

где часто находятся системные и сервисные логи.

---

## `/tmp`

Каталог для временных файлов.

```text
/tmp
```

Программы могут использовать его для временных данных.

---

## `/usr`

Большая часть пользовательских программ, библиотек и других ресурсов системы.

Например:

```text
/usr/bin
/usr/lib
/usr/local
```

---

## `/opt`

Часто используется для дополнительного программного обеспечения, устанавливаемого отдельно от стандартной системы.

---

## `/dev`

Содержит специальные файловые интерфейсы к устройствам.

Например:

```text
/dev/null
/dev/zero
/dev/sda
```

При этом `/dev` не следует воспринимать как обычный каталог с физическими файлами.

---

## `/proc`

Виртуальная файловая система, предоставляющая информацию о процессах и состоянии ядра.

Например:

```text
/proc/cpuinfo
/proc/meminfo
/proc/1234/
```

где `1234` может быть PID процесса.

---

## `/sys`

Ещё одна виртуальная файловая система, связанная с информацией об устройствах, драйверах и подсистемах ядра.

---

## `/run`

Содержит runtime-данные работающей системы, например PID-файлы и Unix sockets некоторых служб.

# 5. Абсолютный и относительный путь

### Абсолютный путь

Начинается с `/`.

```text
/home/ilya/project/app.py
```

Он однозначно описывает расположение относительно корня.

### Относительный путь

Отсчитывается от текущего каталога.

Например, если мы находимся в:

```text
/home/ilya/project
```

то:

```text
src/app.py
```

означает:

```text
/home/ilya/project/src/app.py
```

# 6. `.` и `..`

Текущий каталог:

```text
.
```

Родительский каталог:

```text
..
```

Например:

```bash
cd ..
```

перейдёт на уровень выше.

А:

```bash
ls .
```

покажет содержимое текущего каталога.

# 7. Домашний каталог `~`

В shell:

```text
~
```

обычно обозначает домашний каталог текущего пользователя.

Например:

```bash
cd ~
```

может привести в:

```text
/home/ilya
```

А:

```bash
ls ~/projects
```

означает:

```text
/home/ilya/projects
```

# 8. Типы файлов

В Linux существуют разные типы файловых объектов.

Основные:

```text
-  обычный файл
d  каталог
l  символическая ссылка
c  character device
b  block device
s  socket
p  named pipe
```

Посмотреть тип можно через:

```bash
ls -l
```

Например:

```text
-rw-r--r--  app.py
drwxr-xr-x  project
lrwxrwxrwx  config -> /etc/myapp/config
```

Первый символ показывает тип объекта.

---

# 9. Обычный файл

Обозначается:

```text
-
```

Например:

```text
-rw-r--r-- app.py
```

Это обычный файл.

Содержимым может быть:

* Python-код;
* текст;
* изображение;
* бинарные данные;
* JSON;
* база данных и т. д.

---

# 10. Каталог

Обозначается:

```text
d
```

Например:

```text
drwxr-xr-x project
```

Каталог содержит ссылки на файловые объекты.

Важно понимать:

> Каталог — это не просто «папка» в абстрактном смысле. На уровне файловой системы он является специальным типом объекта, организующим имена файлов и каталогов.

---

# 11. Символическая ссылка

Обозначается:

```text
l
```

Например:

```text
config -> /etc/myapp/config
```

Создать:

```bash
ln -s /etc/myapp/config config
```

Символическая ссылка содержит путь к другому объекту.

Если исходный объект удалить или переместить, ссылка может стать нерабочей.

# 12. Hard Link и Symbolic Link

Это важное различие.

### Hard link

Несколько имён указывают на один и тот же inode.

```text
name1 ──┐
        ├──→ inode → data
name2 ──┘
```

### Symbolic link

Отдельный объект содержит путь к другому объекту:

```text
symlink → "/path/to/file"
```

Упрощённо:

```text
Hard link
→ тот же inode

Symbolic link
→ путь к другому объекту
```

---

# 13. Inode

**Inode** — структура файловой системы, содержащая метаданные файла.

Например:

* тип;
* права доступа;
* владелец;
* группа;
* размер;
* timestamps;
* ссылки на блоки с данными.

Имя файла не является основной частью inode.

Упрощённо:

```text
directory
   │
   ├── app.py ──→ inode
   │               ├── permissions
   │               ├── owner
   │               ├── size
   │               └── data blocks
```

Посмотреть inode:

```bash
ls -i app.py
```

---

# 14. Имя файла и inode

Важная модель:

```text
Имя
 ↓
directory entry
 ↓
inode
 ↓
данные
```

Поэтому несколько hard links могут ссылаться на один inode:

```text
file1 ──┐
        ├──→ inode ──→ data
file2 ──┘
```

Удаление одного имени не обязательно удаляет данные.

Данные становятся недоступными через обычные имена, когда количество hard links становится нулём и файловый дескриптор также не удерживает файл открытым.

---

# 15. Права доступа

Например:

```text
-rwxr-xr--
```

Разбираем:

```text
-   rwx   r-x   r--
    │     │     │
    │     │     └── others
    │     └──────── group
    └────────────── owner
```

Где:

```text
r = read
w = write
x = execute
```

---

# 16. Права каталога

Для каталогов значения `r`, `w`, `x` имеют немного другой смысл.

### `r`

Можно читать содержимое каталога — получать список имён.

### `w`

Можно изменять записи каталога при наличии необходимых других прав.

### `x`

Можно проходить через каталог и обращаться к объектам внутри него при наличии соответствующих разрешений.

Например:

```text
drwxr-x---
```

---

# 17. Владелец и группа

У объекта есть:

```text
owner
group
```

Например:

```bash
ls -l
```

может показать:

```text
-rw-r--r-- ilya developers app.py
```

Здесь:

```text
owner → ilya
group → developers
```

Права определяются для:

```text
owner
group
others
```

---

# 18. `chmod`

Изменяет права доступа.

Например:

```bash
chmod +x script.sh
```

Числовая запись:

```bash
chmod 755 script.sh
```

Расшифровка:

```text
7 = rwx
5 = r-x
5 = r-x
```

То есть:

```text
owner  → rwx
group  → r-x
others → r-x
```

---

# 19. `chown`

Изменяет владельца и группу.

Например:

```bash
sudo chown ilya:developers app.py
```

Теперь:

```text
owner → ilya
group → developers
```

# 20. Монтирование

В Linux отдельный раздел или устройство подключается к дереву файловой системы через **mount point**.

Например:

```text
/
├── home
├── var
└── mnt
    └── disk
```

Можно подключить устройство:

```bash
mount /dev/sdb1 /mnt/disk
```

После этого содержимое файловой системы устройства доступно через:

```text
/mnt/disk
```

То есть пользователь работает с единым деревом:

```text
/
└── mnt
    └── disk
```

хотя физически данные находятся на другом устройстве.

---

# 21. `mount` и `umount`

Посмотреть смонтированные файловые системы:

```bash
mount
```

или:

```bash
findmnt
```

Подключить:

```bash
sudo mount /dev/sdb1 /mnt/disk
```

Отключить:

```bash
sudo umount /mnt/disk
```

# 22. Файловая система и диск — не одно и то же

Важно различать:

```text
Диск
 ↓
Раздел
 ↓
Файловая система
 ↓
Mount point
 ↓
Файлы
```

Например:

```text
/dev/sdb
   ↓
/dev/sdb1
   ↓
ext4
   ↓
/mnt/data
   ↓
/mnt/data/app.db
```

Диск — физическое или виртуальное устройство хранения.

Файловая система — структура, которая организует данные на этом устройстве.

---

# 23. VFS

Linux использует **VFS — Virtual File System**.

VFS предоставляет единый интерфейс для работы с разными файловыми системами.

Упрощённо:

```text
Application
     ↓
   VFS
   ├── ext4
   ├── XFS
   ├── Btrfs
   ├── tmpfs
   └── другие FS
```

Поэтому приложение обычно не должно знать, используется ли под ним ext4 или XFS.

# 24. Виртуальные файловые системы

Некоторые файловые системы не предназначены для обычного хранения данных на диске.

Например:

```text
/proc
/sys
/dev
```

Они предоставляют интерфейс к системной информации, устройствам и подсистемам ядра.

### `/proc`

Например:

```bash
cat /proc/meminfo
```

может показать информацию об оперативной памяти.

```bash
cat /proc/cpuinfo
```

— информацию о CPU.

---

# 25. Файловые дескрипторы

Когда процесс открывает файл, Linux возвращает ему **file descriptor (FD)** — числовой идентификатор открытого объекта.

Стандартные:

```text
0 → stdin
1 → stdout
2 → stderr
```

Например:

```text
Python process
     │
     ├── 0 stdin
     ├── 1 stdout
     └── 2 stderr
```

Это важно для Backend-разработчика, потому что файловые дескрипторы используются не только для файлов, но и для других I/O-объектов, включая sockets.

---

# 26. Логи и файловая система

В Linux серверные приложения часто работают с логами.

Например:

```text
/var/log/
```

Можно посмотреть последние записи:

```bash
tail -f /var/log/nginx/access.log
```

или журнал systemd:

```bash
journalctl -u nginx
```

Для Backend-разработчика понимание `/var/log`, `journalctl` и файловых прав полезно при диагностике production-проблем.

# 27. Файловая система в Docker

Docker также активно взаимодействует с файловой системой Linux.

Например:

```text
Host
│
├── /app
│
└── Container
     └── /app
```

Можно подключить каталог хоста в контейнер:

```bash
docker run -v /host/data:/app/data image
```

Тогда:

```text
Host:
/host/data

Container:
/app/data
```

будут связаны через mount.

Это называется **bind mount**.

# 28. Что важно различать

### Файловая система vs каталог

Каталог — объект внутри файловой системы.

Файловая система — более широкое понятие, определяющее организацию хранения данных.

### Файл vs inode

Имя файла находится в записи каталога и ссылается на inode.

### Диск vs файловая система

Диск — устройство хранения.

Файловая система — структура, организующая данные на устройстве.

### `/` vs `/root`

```text
/      → корень файловой системы
/root  → домашний каталог root
```

### `/proc` vs обычный каталог

`/proc` — виртуальная файловая система, предоставляющая информацию о процессах и ядре.

## 🎤 Вопросы на собеседовании

### Что такое файловая система?

Механизм организации и хранения данных, который определяет структуру файлов, каталогов и метаданных и предоставляет интерфейс для работы с ними.

### Как организована файловая система Linux?

В виде единого дерева с корнем `/`.

### Что такое `/etc`?

Каталог системной и прикладной конфигурации.

### Что такое `/var`?

Каталог для изменяемых данных, например логов, кэшей и данных служб.

### Что такое `/home`?

Каталог с домашними директориями обычных пользователей.

### Что такое `/proc`?

Виртуальная файловая система, предоставляющая информацию о процессах и состоянии ядра.

### Что такое inode?

Структура файловой системы, содержащая метаданные файла и информацию, необходимую для доступа к его данным.

### Чем hard link отличается от symbolic link?

Hard link указывает на тот же inode, что и исходное имя. Symbolic link — отдельный объект, содержащий путь к другому объекту.

### Что такое mount point?

Каталог, через который подключённая файловая система становится доступной в общем дереве Linux.

### Что такое VFS?

Virtual File System — абстракция ядра Linux, предоставляющая единый интерфейс для работы с различными файловыми системами.

### Что такое file descriptor?

Числовой идентификатор открытого файлового или другого I/O-объекта, который процесс использует для взаимодействия с ним.

### Что означает `755`?

```text
owner  → rwx
group  → r-x
others → r-x
```

### Чем абсолютный путь отличается от относительного?

Абсолютный путь начинается от `/` и не зависит от текущего каталога. Относительный интерпретируется относительно текущего рабочего каталога.

### Что такое `/dev`?

Каталог со специальными файловыми интерфейсами к устройствам.

### Зачем Backend-разработчику знать файловую систему Linux?

Для работы с конфигурацией, логами, правами, процессами, Docker volumes, SSH и диагностикой серверных приложений.
