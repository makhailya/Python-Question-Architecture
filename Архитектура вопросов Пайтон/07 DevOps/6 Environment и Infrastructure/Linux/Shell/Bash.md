# 🐚 Bash

## 🎤 Короткий ответ

**Bash (Bourne Again SHell)** — командный интерпретатор и shell для Unix-подобных операционных систем, широко используемый в Linux.

Он принимает команды пользователя, интерпретирует их и запускает программы. Кроме интерактивной работы, Bash позволяет писать **shell-скрипты** для автоматизации.

Например:

```bash
pwd
ls -la
cd /var/log
```

Bash также поддерживает:

* переменные;
* условия;
* циклы;
* функции;
* перенаправление ввода/вывода;
* pipe (`|`);
* background jobs;
* переменные окружения;
* exit codes.

## 🗣️ Ответ на собеседовании

Bash — это Unix shell и командный интерпретатор, который часто используется в Linux.

Он предоставляет интерфейс между пользователем и операционной системой: получает команду, разбирает её, запускает программу и передаёт ей аргументы и окружение.

Например:

```bash
ls -la /var/log
```

Bash разбирает команду `ls`, аргументы и запускает соответствующий процесс.

Кроме интерактивной работы Bash используется для автоматизации через shell-скрипты. В них можно использовать переменные, условия, циклы, функции, перенаправление потоков и конвейеры.

Например:

```bash
pytest | tee test.log
```

Здесь Bash организует pipe между процессами и перенаправление вывода.

Для Backend-разработчика Bash полезен при работе с Linux-серверами, Docker, CI/CD, логами, процессами и автоматизацией рутинных операций.

# 📚 Разбор поглубже

## 1. Что такое Bash

Bash расшифровывается как:

> **Bourne Again SHell**

Это shell, совместимый с идеями и синтаксисом Bourne shell (`sh`), но с дополнительными возможностями.

Bash может работать в двух основных режимах:

```text
Bash
├── Interactive
└── Non-interactive
```

### Interactive

Пользователь непосредственно вводит команды:

```bash
$ pwd
$ ls
$ cd project
```

### Non-interactive

Bash выполняет скрипт:

```bash
bash deploy.sh
```

# 4. Встроенные команды

Не каждая команда обязательно является отдельным исполняемым файлом.

В Bash есть **builtins** — встроенные команды.

Например:

```bash
cd
export
unset
alias
source
read
```

Проверить:

```bash
type cd
```

Можно получить:

```text
cd is a shell builtin
```

А:

```bash
type ls
```

обычно покажет путь к внешней программе, например:

```text
ls is /usr/bin/ls
```

# 5. `PATH`

Когда мы пишем:

```bash
python
```

Bash должен найти исполняемый файл.

Для этого используется переменная:

```text
PATH
```

Посмотреть:

```bash
echo $PATH
```

Например:

```text
/usr/local/bin:/usr/bin:/bin
```

Bash ищет программу в каталогах, перечисленных в `PATH`.

Посмотреть, какой executable будет найден:

```bash
which python
```

или:

```bash
command -v python
```

`command -v` обычно предпочтительнее для shell-скриптов, поскольку является стандартным механизмом shell.

# 6. Переменные

В Bash переменные можно создавать так:

```bash
name="Ilya"
```

Обратите внимание:

```text
name="Ilya"
```

а не:

```text
name = "Ilya"
```

Пробелы вокруг `=` здесь недопустимы.

Получить значение:

```bash
echo "$name"
```

Результат:

```text
Ilya
```

```text
Bash
 └── APP_ENV=production
```

Это часто используется для конфигурации Backend-приложений.

# 9. Кавычки

Bash различает одинарные и двойные кавычки.

### Двойные

```bash
name="Ilya"
echo "Hello, $name"
```

Результат:

```text
Hello, Ilya
```

Переменная раскрывается.

### Одинарные

```bash
echo 'Hello, $name'
```

Результат:

```text
Hello, $name
```

Переменная не раскрывается.

Упрощённо:

```text
"..." → expansion происходит
'...' → literal text
```

# 10. Command Substitution

Результат одной команды можно подставить в другую.

Современный синтаксис:

```bash
current_dir=$(pwd)
```

Например:

```bash
echo "Current directory: $(pwd)"
```

Bash сначала выполняет:

```bash
pwd
```

а затем подставляет результат в строку.

Старый синтаксис:

```bash
current_dir=`pwd`
```

сейчас обычно не используют в новом коде — предпочтительнее `$()`.

# 11. Pipes

Одна из самых важных возможностей shell — **pipe**.

Символ:

```text
|
```

передаёт стандартный вывод одной команды на стандартный ввод другой.

Например:

```bash
ps aux | grep python
```

Упрощённо:

```text
ps
 │
 │ stdout
 ▼
pipe
 │
 │ stdin
 ▼
grep
```

Это позволяет строить цепочки команд.

Например:

```bash
cat app.log | grep ERROR | head
```

# 12. Redirect

Можно перенаправлять стандартные потоки.

### `>`

Перезаписывает файл:

```bash
echo "hello" > file.txt
```

### `>>`

Добавляет в конец:

```bash
echo "hello" >> file.txt
```

### `<`

Передаёт файл на stdin:

```bash

```

# 13. stdout и stderr

У процесса обычно есть стандартные файловые дескрипторы:

```text
0 → stdin
1 → stdout
2 → stderr
```

Например:

```bash
python app.py > output.log
```

stdout записывается в файл.

Ошибки stderr при этом остаются в терминале.

Чтобы перенаправить stderr:

```bash
python app.py 2> error.log
```

Оба потока в один файл:

```bash
python app.py > app.log 2>&1
```

Современный Bash также поддерживает сокращённую форму:

```bash
python app.py &> app.log
```

# 16. Exit Code

Каждая команда завершается с определённым **exit status**.

Обычно:

```text
0 → успех
не 0 → ошибка / особый результат
```

Узнать код предыдущей команды:

```bash
echo $?
```

Например:

```bash
ls /tmp
echo $?
```

может вывести:

```text
0
```

Если команда завершилась ошибкой:

```bash
some-command
echo $?
```

может получить ненулевое значение.

Exit codes активно используются в автоматизации и CI/CD.

Например:

```text
   ↓
0 → pipeline продолжается
1+ → job failed
```

Для Backend-разработчика это особенно важно в:

# 18. Условия

В Bash можно использовать:

```bash
if
```

Например:

```bash
if [ -f "app.py" ]; then
    echo "File exists"
fi
```

Здесь:

```text
-f
```

проверяет, существует ли обычный файл.

Можно использовать `[[ ]]`:

```bash
if [[ -f "app.py" ]]; then
    echo "File exists"
fi
```

В Bash `[[ ... ]]` обычно предпочтительнее для сложных условий, потому что это встроенный синтаксис Bash с более предсказуемыми правилами.

# 23. Shebang

Первая строка:

```bash

```

называется **shebang**.

Она указывает, каким интерпретатором следует запускать скрипт.

# 24. `source`

Команда:

```bash
source file.sh
```

выполняет команды файла **в текущем shell**.

Также:

```bash
. file.sh
```

эквивалентно `source` в Bash.

Это важно отличать от:

```bash
bash file.sh
```

В последнем случае создаётся отдельный Bash-процесс.

Например:

```bash
# env.sh
export APP_ENV=production
```

Если выполнить:

```bash
source env.sh
```

переменная появится в текущем shell.

# 25. `set -euo pipefail`

В Bash-скриптах часто встречается:

```bash
set -euo pipefail
```

Это не одна настройка, а комбинация:

### `-e`

Скрипт обычно прекращает выполнение при ненулевом статусе команды, если команда находится в контексте, где действует `errexit`.

### `-u`

Обращение к неустановленной переменной обычно вызывает ошибку.

### `pipefail`

Pipeline получает ненулевой статус, если соответствующая команда внутри pipeline завершилась с ошибкой, а не только последняя команда.

Например:

```bash
set -euo pipefail
```

часто используют как базовую настройку для более надёжных Bash-скриптов.

Но `set -e` имеет ряд контекстных исключений и не является полной системой обработки ошибок.

# 26. Globbing

Bash умеет сопоставлять имена файлов с шаблонами.

Например:

```bash
ls *.py
```

означает:

```text
все файлы, заканчивающиеся на .py
```

Другие примеры:

```bash
ls file?.txt
```

`?` — один символ.

```bash
ls [abc].txt
```

один символ из набора `a`, `b`, `c`.

Важно:

> Globbing выполняет shell до запуска команды.

То есть программа `ls` получает уже расширенный список аргументов.

# 29. Bash и Docker

Dockerfile может использовать shell-команды:

```dockerfile
RUN pip install -r requirements.txt
```

Также:

```bash
docker exec -it container bash
```

может открыть Bash внутри контейнера, если Bash установлен в image.

Поэтому важно не считать:


# 30. Типичные ошибки

### Забыть кавычки

Плохо:

```bash
rm $FILE
```

Если значение содержит пробелы или специальные символы, могут возникнуть проблемы.

Чаще безопаснее:

```bash
rm -- "$FILE"
```

### Путать `>` и `>>`

```text
>  → перезаписать
>> → добавить
```

### Путать `$?`

```bash
echo $?
```

показывает exit status **предыдущей команды**, поэтому если между командой и `echo $?` выполнить что-то ещё, значение изменится.

### Не проверять права

```bash
./script.sh
```

может дать:

```text
Permission denied
```

если нет `x`.

### Использовать `kill -9` без необходимости

Сначала обычно стоит дать процессу возможность корректно завершиться через `SIGTERM`.

## 🎤 Вопросы на собеседовании

### Что такое Bash?

Bash — Unix shell и командный интерпретатор, широко используемый в Linux.

### Чем Bash отличается от Linux?

Linux — ядро ОС и название семейства систем в практической речи. Bash — shell, работающий поверх ОС и позволяющий выполнять команды и скрипты.

### Чем Bash отличается от Terminal?

Terminal — интерфейс для работы с командной строкой. Bash — shell, который интерпретирует команды внутри этого интерфейса.

### Что такое shell?

Командный интерпретатор, который принимает команды, обрабатывает shell-синтаксис и запускает программы.

### Что такое `PATH`?

Переменная окружения, содержащая список каталогов, в которых shell ищет исполняемые файлы.

### Что такое pipe?

Механизм передачи `stdout` одной команды в `stdin` другой:

```bash
ps aux | grep python
```

### Что такое redirect?

Перенаправление стандартных потоков ввода/вывода, например:

```bash
command > output.log
```

### Что такое `stdout`, `stderr`, `stdin`?

```text
0 → stdin
1 → stdout
2 → stderr
```

### Что такое exit code?

Числовой статус завершения команды или процесса. Обычно `0` означает успешное выполнение, ненулевое значение — ошибку или другой особый результат.

### Что делает `$?`?

Содержит exit status последней выполненной команды в текущем shell-контексте.

### Что такое environment variable?

Переменная окружения, которая передаётся shell и его дочерним процессам.

### Чем `source script.sh` отличается от `bash script.sh`?

`source` выполняет команды в текущем shell, поэтому изменения его окружения могут сохраниться. `bash script.sh` запускает отдельный Bash-процесс.

### Что такое shebang?

Первая строка исполняемого скрипта, указывающая интерпретатор, например:

```bash
#!/usr/bin/env bash
```

### Что делает `chmod +x script.sh`?

Добавляет право выполнения для применимой категории пользователей согласно текущим permissions.

### Зачем Backend-разработчику Bash?

Для работы с Linux-серверами, Docker, GitLab CI/CD, процессами, логами, файлами, переменными окружения и автоматизацией deployment/test workflow.
