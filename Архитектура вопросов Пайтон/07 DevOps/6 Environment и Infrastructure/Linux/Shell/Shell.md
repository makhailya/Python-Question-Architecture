# 🐚 Shell

## 🎤 Короткий ответ

**Shell** — это командная оболочка, которая позволяет пользователю взаимодействовать с операционной системой через команды.

Она принимает команду:

```text
пользователь → Shell → ОС → программа
```

Например:

```bash
ls
```

Shell разбирает команду, находит программу `ls`, запускает её и передаёт ей аргументы, переменные окружения, stdin/stdout/stderr.

В Linux популярные shell:

* **Bash** — самый распространённый;
* Zsh;
* Fish;
* Dash.

Важно различать:

> **Terminal** — программа, предоставляющая интерфейс ввода/вывода.
> **Shell** — программа, которая интерпретирует команды.

---

## 🗣️ Ответ на собеседовании

Shell — это командная оболочка, через которую пользователь или другой процесс взаимодействует с операционной системой.

Shell умеет интерпретировать команды, запускать программы, работать с переменными, перенаправлением ввода-вывода, пайпами, условиями, циклами и функциями.

Например, Bash получает команду `ls -la`, разбирает её, находит исполняемый файл `ls` через `PATH`, запускает процесс и передаёт ему аргументы. Результат программы выводится через stdout.

Shell также позволяет объединять программы:

```bash
cat access.log | grep ERROR | wc -l
```

Здесь stdout одной программы передаётся через pipe на stdin следующей.

Для Backend-разработчика Shell важен при работе с Linux-серверами, Docker, Git, SSH, CI/CD и запуске Python-приложений.

# 📚 Разбор поглубже

## 1. Что такое Shell

Shell — это **командный интерпретатор**.

Он находится между пользователем и программами операционной системы:

```text
┌─────────────┐
│ Пользователь│
└──────┬──────┘
       ↓
┌─────────────┐
│    Shell    │
│    Bash     │
└──────┬──────┘
       ↓
┌─────────────┐
│  OS / Tools │
│ ls, cp, ps  │
└─────────────┘
```

Но Shell не является самой операционной системой.

---

# 2. Shell vs Terminal

Это очень частая путаница.

### Terminal

Терминал — интерфейс, через который пользователь взаимодействует с shell.

Например:

```text
Terminal
   ↓
Bash
   ↓
Linux
```

На macOS терминалом может быть Terminal.app или iTerm2.

На Linux — например, GNOME Terminal, Konsole и другие.

### Shell

Shell — программа, которая понимает команды.

Например:

```text
bash
zsh
fish
sh
```

Поэтому:

> **Terminal ≠ Shell**

Можно запустить Bash внутри терминала, но также можно запускать shell без привычного графического terminal UI — например, через SSH или в CI/CD.

---

# 3. Shell vs Bash

**Shell** — общее понятие.

**Bash** — конкретная реализация shell.

```text
Shell
├── Bash
├── Zsh
├── Fish
├── Dash
└── другие
```

Bash расшифровывается как:

**Bourne Again SHell**.

Проверить текущий shell:

```bash
echo $SHELL
```

Узнать текущий процесс shell:

```bash
ps -p $$ -o comm=
```

---

# 4. Что происходит при выполнении команды

Допустим:

```bash
ls -la /tmp
```

Упрощённо Shell делает следующее:

```text
1. Получает строку команды
        ↓
2. Разбирает её
        ↓
3. Обрабатывает shell syntax
        ↓
4. Находит программу
        ↓
5. Запускает процесс
        ↓
6. Передаёт аргументы и окружение
        ↓
7. Получает результат
        ↓
8. Показывает stdout/stderr
```

Команда состоит из:

```text
ls      -la       /tmp
│        │          │
│        │          └── argument
│        └───────────── option
└────────────────────── command
```

---

# 5. Built-in команды

Не каждая команда является отдельным исполняемым файлом.

Некоторые команды реализованы непосредственно внутри Shell.

Например, в Bash:

```bash
cd
export
alias
source
read
```

Это **shell builtins**.

Почему `cd` обычно является builtin?

Потому что изменение текущей директории должно происходить в самом shell-процессе.

Если бы `cd` запускался как отдельный дочерний процесс:

```text
Bash
 ↓
cd process
```

дочерний процесс изменил бы свою директорию, но после завершения родительский Bash остался бы в старой директории.

---

# 6. Внешние программы

Многие команды — обычные исполняемые файлы.

Например:

```bash
ls
cat
grep
python
git
curl
```

Shell должен найти соответствующий executable.

Для этого используется переменная:

```bash
PATH
```

---

# 7. PATH

`PATH` — список директорий, в которых Shell ищет исполняемые файлы.

Посмотреть:

```bash
echo $PATH
```

Например:

```text
/usr/local/bin:/usr/bin:/bin
```

Двоеточие разделяет директории.

Если выполнить:

```bash
python
```

Shell ищет `python` примерно в таком порядке:

```text
/usr/local/bin/python
/usr/bin/python
/bin/python
...
```

Можно узнать, какой executable будет найден:

```bash
which python
```

Более надёжный инструмент Bash:

```bash
type -a python
```

---

# 8. Абсолютный и относительный запуск

Можно запускать программу через `PATH`:

```bash
python app.py
```

Или указать путь:

```bash
/usr/bin/python3 app.py
```

Также:

```bash
./script.sh
```

означает:

> запустить `script.sh` из текущей директории.

`./` важен, потому что текущая директория не обязательно находится в `PATH`.

---

# 9. Переменные Shell

В Shell есть переменные:

```bash
name="Ilya"
```

Обращение:

```bash
echo "$name"
```

Результат:

```text
Ilya
```

Важно:

```bash
name="Ilya"
```

а не:

```bash
name = "Ilya"
```

В Bash пробелы вокруг `=` недопустимы в таком присваивании.

---

# 10. Environment Variables

Переменная может быть экспортирована в environment дочерних процессов:

```bash
export APP_ENV=production
```

После этого:

```bash
python app.py
```

Python сможет получить значение через:

```python
import os

print(os.environ["APP_ENV"])
```

Схема:

```text
Shell
 │
 │ environment
 ▼
Python process
```

Это активно используется в Backend:

```text
DATABASE_URL
SECRET_KEY
REDIS_URL
APP_ENV
PORT
```

---

# 11. `export`

Без `export` переменная является shell variable:

```bash
NAME=Ilya
```

Дочерний процесс её автоматически не получает.

С `export`:

```bash
export NAME=Ilya
```

она становится частью environment дочерних процессов.

Проверить:

```bash
env
```

или:

```bash
printenv NAME
```

---

# 12. Кавычки

В Shell кавычки имеют важное значение.

### Одинарные

```bash
echo '$HOME'
```

Выведет буквально:

```text
$HOME
```

### Двойные

```bash
echo "$HOME"
```

Переменная будет раскрыта.

Упрощённо:

```text
'...' → минимальная интерпретация
"..." → разрешены расширения переменных и некоторые другие подстановки
```

---

# 13. Command Substitution

Результат одной команды можно использовать внутри другой:

```bash
echo "Today is $(date)"
```

Например:

```bash
files=$(ls)
```

Теперь результат `ls` находится в переменной `files`.

Современный синтаксис:

```bash
$(command)
```

Старый синтаксис:

```bash
`command`
```

Предпочтительно использовать `$(...)`.

---

# 14. stdin, stdout, stderr

У процесса обычно есть три стандартных потока:

```text
stdin   → 0
stdout  → 1
stderr  → 2
```

Схема:

```text
           ┌──────────────┐
stdin ───→ │   Process    │ ───→ stdout
           │              │
           └──────────────┘
                    │
                    └────────→ stderr
```

### stdin

Входные данные.

### stdout

Обычный вывод.

### stderr

Сообщения об ошибках и диагностический вывод.

---

# 15. Перенаправление stdout

Записать stdout в файл:

```bash
ls > files.txt
```

Если файл существует, `>` обычно перезапишет его.

Добавить в конец:

```bash
ls >> files.txt
```

---

# 16. Перенаправление stderr

Перенаправить stderr:

```bash
command 2> errors.txt
```

stdout и stderr отдельно:

```bash
command > output.txt 2> errors.txt
```

Объединить stderr со stdout:

```bash
command > output.txt 2>&1
```

В Bash также часто используется:

```bash
command &> output.txt
```

---

# 17. stdin из файла

Можно передать файл в stdin:

```bash
sort < names.txt
```

Получается:

```text
names.txt
    ↓
  stdin
    ↓
  sort
```

---

# 18. Pipe

**Pipe `|`** соединяет stdout одной команды со stdin другой.

Например:

```bash
ps aux | grep python
```

Схема:

```text
ps aux
  │
  │ stdout
  ▼
 pipe
  │
  │ stdin
  ▼
grep python
```

Можно строить цепочки:

```bash
cat access.log | grep ERROR | wc -l
```

Получаем:

```text
cat
 ↓
grep
 ↓
wc
```

Это одна из главных идей Unix-подхода:

> небольшие программы выполняют отдельные задачи и объединяются через стандартные потоки.

# 19. Exit Code

После завершения команды Shell получает код возврата.

Обычно:

```text
0 → успех
не 0 → ошибка/особый результат
```

Посмотреть код последней команды:

```bash
echo $?
```

Например:

```bash
true
echo $?
```

Результат:

```text
0
```

А:

```bash
false
echo $?
```

даст ненулевой код.

---

# 20. Почему Exit Code важен для Backend

CI/CD может выполнять:

```text
pytest
   ↓
exit code
   ↓
0 → pipeline продолжает работу
1 → pipeline может завершиться ошибкой
```

То же самое используется в Docker, systemd, shell scripts и автоматизации.

# 21. Условия

Shell позволяет проверять exit code и другие условия:

```bash
if command; then
    echo "Success"
else
    echo "Failed"
fi
```

Например:

```bash
if systemctl is-active --quiet nginx; then
    echo "Nginx is running"
else
    echo "Nginx is not running"
fi
```

# 22. Цепочки команд

Можно выполнять команды условно.

### `&&`

Выполнить следующую команду, если предыдущая успешна:

```bash
mkdir app && cd app
```

### `||`

Выполнить следующую, если предыдущая завершилась ошибкой:

```bash
mkdir app || echo "Failed"
```

Например:

```bash
pytest && echo "Tests passed"
```

# 24. Сигналы

Shell взаимодействует с процессами и сигналами.

Например:

```bash
Ctrl+C
```

обычно приводит к отправке:

```text
SIGINT
```

А:

```bash
kill PID
```

по умолчанию отправляет:

```text
SIGTERM
```

Можно явно указать:

```bash
kill -9 PID
```

Это:

```text
SIGKILL
```

`SIGKILL` нельзя обработать самим процессом.

# 25. Shell Script

Shell можно использовать не только интерактивно, но и для написания скриптов.

Например:

```bash
#!/usr/bin/env bash

echo "Starting application"

python app.py
```

Сохраняем:

```text
start.sh
```

Делаем исполняемым:

```bash
chmod +x start.sh
```

Запускаем:

```bash
./start.sh
```

# 26. Shebang

Первая строка:

```bash
#!/usr/bin/env bash
```

называется **shebang**.

Она указывает, каким интерпретатором нужно выполнить скрипт.

Например:

```python
#!/usr/bin/env python3
```

для Python.

Для Bash:

```bash
#!/usr/bin/env bash
```

# 27. Bash и Python

Для Backend-разработчика важно понимать, когда использовать каждый инструмент.

### Bash

Хорош для:

* запуска программ;
* работы с файлами;
* пайпов;
* автоматизации;

Лучше подходит для:

# 30. Bash vs sh

`sh` — историческое имя/интерфейс для Bourne-style shell.

`bash` предоставляет расширения по сравнению с базовым `sh`.

Например:

```text
sh
├── базовый shell-интерфейс
└── может быть реализован разными shell

bash
├── shell
├── arrays
├── functions
├── расширения Bash
└── Bash-specific syntax
```

Поэтому скрипт с Bash-специфичными конструкциями должен явно указывать Bash:

```bash
#!/usr/bin/env bash
```

---

# 31. `set -euo pipefail`

В Bash-скриптах часто используют:

```bash
set -euo pipefail
```

Идея:

```text
-e → завершаться при ошибках команд
-u → считать обращение к unset-переменной ошибкой
-o pipefail → учитывать ошибки команд внутри pipeline
```

Например, без `pipefail` проблема внутри pipeline может быть неочевидна.

Но это не «магическая защита» скрипта: у `set -e` и `pipefail` есть нюансы поведения в условиях, `if`, pipelines, subshell и других конструкциях.

# 32. Shell и процессы

Shell сам является процессом.

Например:

```text
Terminal
   ↓
Bash
   ├── ls
   ├── grep
   └── python
```

Когда Bash запускает внешнюю программу, создаётся процесс этой программы.

Это связывает темы:

```text
Shell
  ↓
Процессы
  ↓
stdin/stdout/stderr
  ↓
Pipes
  ↓
Signals
```

# 33. Shell и systemd

Эти понятия тоже нужно различать.

### Shell

Интерактивно запускает команды:

```bash
python app.py
```

### systemd

Управляет сервисом как системным unit:

```bash
systemctl start myapp
```

Схема:

```text
systemd
   ↓
ExecStart
   ↓
Python / Gunicorn
```

Shell может вообще не участвовать в запуске сервиса, если `ExecStart` запускает бинарник напрямую.

## 🎤 Вопросы на собеседовании

### Что такое Shell?

Командная оболочка, которая интерпретирует команды и позволяет взаимодействовать с операционной системой и запускать программы.

### Чем Shell отличается от Terminal?

Terminal предоставляет интерфейс ввода/вывода, а Shell интерпретирует команды.

### Что такое Bash?

Bash — конкретная реализация Unix shell.

### Чем Bash отличается от Shell?

Shell — общее понятие, Bash — конкретный shell.

### Что такое `PATH`?

Переменная окружения со списком директорий, в которых Shell ищет исполняемые файлы при запуске команды без явного пути.

### Что такое stdin, stdout и stderr?

```text
stdin   → стандартный ввод
stdout  → стандартный вывод
stderr  → стандартный поток ошибок
```

### Что делает `|`?

Передаёт stdout одной команды в stdin другой:

```bash
ps aux | grep python
```

### Чем `>` отличается от `>>`?

```bash
>   → перезаписать файл
>>  → добавить в конец
```

### Что такое exit code?

Числовой код, который процесс возвращает после завершения. Обычно `0` означает успех, ненулевое значение — ошибку или другой результат.

### Что делает `$?`?

Содержит exit code последней выполненной команды.

### Что делает `export`?

Делает shell-переменную частью environment, который наследуют дочерние процессы.

### Зачем нужен `./script.sh`?

Чтобы явно указать путь к скрипту в текущей директории, если она не входит в `PATH`.

### Что такое shebang?

Первая строка исполняемого скрипта, указывающая интерпретатор:

```bash
#!/usr/bin/env bash
```

### Почему `cd` — builtin Bash?

Потому что изменить текущую рабочую директорию должен сам shell-процесс. Изменение директории дочернего процесса не изменило бы директорию родительского Bash.

### Что такое pipe?

Механизм передачи stdout одного процесса в stdin другого процесса.

### Что такое environment?

Набор переменных окружения, доступных процессу и обычно наследуемых от родительского процесса.

### Что происходит при `python app.py`?

Shell разбирает команду, находит `python` через `PATH`, запускает соответствующий процесс и передаёт ему аргумент `app.py`.

### Что происходит при `ps aux | grep python`?

Shell создаёт pipeline: stdout `ps` направляется в pipe, а stdin `grep` подключается к этому pipe. В результате `grep` фильтрует вывод `ps`.

### Почему Shell важен Backend-разработчику?

Потому что Backend часто работает в Linux-среде, а Shell используется для запуска приложений, работы с процессами, Docker, Git, SSH, systemd, логами и CI/CD.
