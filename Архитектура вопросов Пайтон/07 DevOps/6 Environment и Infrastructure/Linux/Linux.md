# 🐧 Linux

## 🎤 Короткий ответ

**Linux** — это семейство операционных систем с ядром Linux. В разработке Linux особенно широко используется на серверах и в DevOps.

Linux предоставляет:

* управление процессами;
* работу с файлами и каталогами;
* пользователей и права доступа;
* сетевые возможности;
* управление службами;
* командную строку и shell.

Для Python Backend-разработчика Linux важен, потому что приложения часто запускаются на Linux-серверах, в Docker-контейнерах и CI/CD.

# 📚 Разбор поглубже

## 1. Linux — это ядро или операционная система?

Строго технически:

> **Linux — это ядро (kernel).**

Ядро отвечает за взаимодействие программ с аппаратным обеспечением и управление системными ресурсами.

```text
Приложения
    ↓
System calls
    ↓
Linux Kernel
    ↓
Hardware
```

Но в повседневной речи под Linux обычно понимают операционную систему или Linux-дистрибутив.

Например:

* Ubuntu;
* Debian;
* Fedora;
* Arch Linux;
* Rocky Linux;
* AlmaLinux.

---

# 2. Что делает ядро Linux

Ядро управляет основными ресурсами системы.

### Процессы

```text
Application
    ↓
Process
    ↓
Linux Kernel
    ↓
CPU
```

Ядро распределяет процессорное время между процессами.

### Память

Ядро управляет:

* RAM;
* виртуальной памятью;
* адресными пространствами процессов;
* swap.

### Файлами

Ядро предоставляет процессам интерфейс для работы с файловой системой.

### Сетью

Ядро реализует сетевой стек:

```text
Application
    ↓
Socket
    ↓
TCP / UDP
    ↓
IP
    ↓
Network Interface
```

### Устройствами

Linux предоставляет механизм взаимодействия с различными устройствами через драйверы.

---

# 3. Дистрибутив Linux

Само ядро не является полноценной пользовательской средой.

**Linux-дистрибутив** объединяет ядро и набор пользовательских компонентов.

Упрощённо:

```text
Linux Distribution
├── Linux Kernel
├── Shell
├── System utilities
├── Package manager
├── Libraries
└── Applications
```

Например:

```text
Ubuntu
Debian
Fedora
Arch
```

могут использовать одно и то же ядро Linux, но иметь разные наборы пакетов, конфигурацию и инструменты управления.

---

# 4. Shell

**Shell** — программа, которая предоставляет интерфейс командной строки.

Например:

* Bash;
* Zsh;
* Fish.

Когда я пишу:

```bash
ls
```

shell получает команду и запускает соответствующую программу.

Упрощённо:

```text
Пользователь
     ↓
   Shell
     ↓
  команда
     ↓
 Linux
```

---

# 5. Терминал и Shell — не одно и то же

Это частая путаница.

**Terminal** — интерфейс, в котором работает shell.

**Shell** — программа, которая интерпретирует команды.

Например:

```text
Terminal
   ↓
Zsh
   ↓
команда
```

На Linux можно использовать Bash, Zsh и другие shell.

На macOS по умолчанию также используется Unix-подобная командная среда, поэтому многие Linux-команды знакомы пользователям macOS.

---

# 6. Файловая система

Linux использует единое дерево файловой системы:

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
├── opt
├── proc
├── root
├── tmp
├── usr
└── var
```

Корень файловой системы:

```text
/
```

В отличие от Windows, где обычно используются:

```text
C:\
D:\
```

в Linux всё начинается от `/`.

---

# 7. Важные каталоги

### `/home`

Домашние каталоги обычных пользователей.

```text
/home/ilya
```

### `/root`

Домашний каталог пользователя `root`.

Не путать:

```text
/
```

и:

```text
/root
```

### `/etc`

Конфигурационные файлы системы и приложений.

Например:

```text
/etc/ssh/
```

### `/var`

Данные, которые изменяются во время работы системы.

Например:

```text
/var/log/
```

### `/tmp`

Временные файлы.

### `/usr`

Большая часть пользовательских программ, библиотек и других ресурсов системы.

### `/opt`

Часто используется для дополнительного программного обеспечения.

### `/proc`

Виртуальная файловая система с информацией о процессах и состоянии ядра.

# 8. Всё является файлом

В Unix/Linux есть известный принцип:

> **"Everything is a file"**

Это не означает буквально, что абсолютно каждый объект является обычным файлом.

Идея заключается в том, что многие ресурсы системы предоставляются через интерфейсы, похожие на файловые.

Например:

```text
/dev
/proc
```

могут предоставлять интерфейс к устройствам или информации ядра.

# 10. Работа с файлами

Создать файл:

```bash
touch app.py
```

Создать каталог:

```bash
mkdir project
```

Скопировать:

```bash
cp app.py backup.py
```

Переместить:

```bash
mv app.py src/app.py
```

Удалить:

```bash
rm app.py
```

Удалить каталог рекурсивно:

```bash
rm -r project
```

⚠️ Команды удаления в Linux нужно использовать внимательно: CLI обычно не предоставляет привычной корзины для `rm`.

# 13. Права доступа

В Linux у файла есть права доступа.

Например:

```text
-rwxr-xr--
```

Они разделены на три группы:

```text
owner   group   others
 rwx     r-x     r--
```

Где:

```text
r = read
w = write
x = execute
```

Например:

```text
rwx
```

означает:

* `r` — чтение;
* `w` — запись;
* `x` — выполнение.

---

# 14. Пользователь и группа

Каждый файл связан с владельцем и группой.

Посмотреть:

```bash
ls -l
```

Например:

```text
-rw-r--r--  ilya  developers  app.py
```

Получается:

```text
owner  → ilya
group  → developers
```

Права определяются отдельно для:

```text
владельца
группы
остальных пользователей
```

---

# 15. `chmod`

`chmod` изменяет права доступа.

Например:

```bash
chmod +x script.sh
```

делает файл исполняемым для соответствующего набора пользователей согласно применённому режиму.

Часто встречается числовая запись:

```bash
chmod 755 script.sh
```

Числа соответствуют комбинациям:

```text
4 = read
2 = write
1 = execute
```

Поэтому:

```text
7 = 4 + 2 + 1 = rwx
5 = 4 + 1     = r-x
```

И:

```text
755
```

означает:

```text
owner   → rwx
group   → r-x
others  → r-x
```

# 16. `sudo` и `root`

**root** — суперпользователь Linux.

Он имеет очень широкие права в системе.

Команда:

```bash
sudo command
```

позволяет выполнить команду с повышенными привилегиями, если пользователь имеет соответствующие права.

Например:

```bash
sudo systemctl restart nginx
```

# 17. Процессы

Каждая запущенная программа работает в контексте процесса или процессов.

Посмотреть процессы:

```bash
ps aux
```

Интерактивный просмотр:

```bash
top
```

или:

```bash
htop
```

Найти процесс:

```bash
ps aux | grep python
```

---

# 18. PID

Каждый процесс имеет **PID — Process ID**.

Например:

```text
python app.py
     ↓
PID 1234
```

Завершить процесс можно:

```bash
kill 1234
```

По умолчанию отправляется сигнал `SIGTERM`.

Принудительное завершение:

```bash
kill -9 1234
```

`SIGKILL` нельзя обработать или проигнорировать процессом.

Поэтому `kill -9` следует использовать, когда обычное завершение не подходит.

---

# 19. Сигналы

Linux использует сигналы для взаимодействия с процессами.

Например:

```text
SIGTERM
SIGKILL
SIGINT
SIGHUP
```

Часто встречается:

```bash
kill -TERM 1234
```

или:

```bash
kill -15 1234
```

`SIGTERM` позволяет приложению корректно завершить работу.

Это особенно важно для серверных приложений, которым может потребоваться:

* закрыть соединения;
* завершить текущие операции;
* освободить ресурсы.

# 20. Службы и systemd

На современных Linux-системах часто используется **systemd**.

Он управляет системными службами.

Например:

```bash
systemctl status nginx
```

Запустить:

```bash
sudo systemctl start nginx
```

Остановить:

```bash
sudo systemctl stop nginx
```

Перезапустить:

```bash
sudo systemctl restart nginx
```

Включить автоматический запуск:

```bash
sudo systemctl enable nginx
```

# 23. Linux и SSH

Для удалённой работы с сервером часто используется SSH.

Например:

```bash

```

После подключения:

```text
MacBook

   ▼
```


# 24. Переменные окружения

# 26. Что важно различать

### Linux vs Unix

Linux — Unix-like система, но исторически Linux не является Unix в смысле сертифицированной Unix-системы.

### Linux vs Ubuntu

Linux — ядро.

Ubuntu — конкретный Linux-дистрибутив.

### Terminal vs Shell

Terminal — интерфейс.

Shell — программа, интерпретирующая команды.

### Process vs Program

Программа — код/исполняемый файл.

Процесс — экземпляр выполняющейся программы с собственным состоянием и ресурсами.

### `root` vs `/`

```text
root
```

может означать суперпользователя.

```text
/
```

— корень файловой системы.

Контекст определяет значение.

## 🎤 Вопросы на собеседовании

### Что такое Linux?

Linux — ядро операционной системы; в разговорной практике также называют Linux-дистрибутивы, построенные вокруг этого ядра.

### Чем Linux отличается от Ubuntu?

Ubuntu — Linux-дистрибутив, использующий ядро Linux.

### Что такое kernel?

Ядро — центральная часть ОС, управляющая ресурсами компьютера и предоставляющая приложениям системные интерфейсы.

### Что такое shell?

Программа, которая интерпретирует команды пользователя и запускает программы. Например, Bash или Zsh.

### Чем terminal отличается от shell?

Terminal предоставляет интерфейс ввода/вывода, а shell интерпретирует команды.

### Что такое процесс?

Запущенный экземпляр программы, выполняющийся под управлением ОС и имеющий собственное состояние и ресурсы.

### Что такое PID?

Уникальный идентификатор процесса.

### Что такое `root`?

Суперпользователь Linux с очень широкими правами.

### Что делает `sudo`?

Позволяет выполнить команду с повышенными привилегиями, если текущему пользователю это разрешено.

### Что такое `systemd`?

Система инициализации и менеджер служб, используемый во многих современных Linux-дистрибутивах.

### Что такое `chmod`?

Команда для изменения прав доступа к файлам и каталогам.

### Что означает `755`?

```text
7 = rwx
5 = r-x
5 = r-x
```

То есть владелец имеет `rwx`, группа и остальные — `r-x`.

### Что делает `kill`?

Отправляет сигнал процессу. Например, `kill PID` обычно отправляет `SIGTERM`.

### Чем `kill` отличается от `kill -9`?

Обычный `kill` обычно отправляет `SIGTERM`, позволяющий процессу корректно завершиться. `kill -9` отправляет `SIGKILL`, который процесс не может обработать.

### Почему Linux важен Backend-разработчику?

Потому что Backend-приложения часто работают на Linux-серверах и в контейнерах, поэтому разработчику необходимо понимать процессы, файловую систему, права, сеть, SSH, логи, службы и переменные окружения.
