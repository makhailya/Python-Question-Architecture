# 🔐 chmod

## 🎤 Короткий ответ

`chmod` — команда Linux для **изменения прав доступа** к файлам и директориям.

Права задаются для трёх категорий:

```text
user   → владелец
group  → группа
other  → остальные
```

И трёх основных разрешений:

```text
r → read    → чтение
w → write   → запись
x → execute → выполнение
```

Например:

```bash
chmod 755 script.sh
```

означает:

```text
owner  → rwx
group  → r-x
others → r-x
```

`chmod` меняет **mode bits** объекта, но не владельца. Для изменения владельца используется `chown`.

## 🗣️ Ответ на собеседовании

`chmod` — команда Linux для изменения прав доступа к файлам и директориям.

Права определяются отдельно для владельца, группы и остальных пользователей. Основные права — `r`, `w` и `x`: чтение, запись и выполнение.

Их можно задавать символически:

```bash
chmod u+x script.sh
```

или числовым способом:

```bash
chmod 755 script.sh
```

В `755` цифры получаются из суммы прав: `r=4`, `w=2`, `x=1`. Поэтому `7` — это `rwx`, а `5` — `r-x`.

Для директории значение `x` имеет особое значение: оно разрешает **проход/поиск внутри директории**, а не просто «запуск директории».

Проверить права можно через:

```bash
ls -l
```

# 📚 Разбор поглубже

## 1. Что делает chmod

Название:

```text
chmod = change mode
```

Команда изменяет права доступа объекта файловой системы.

Например:

```bash
chmod 644 config.yaml
```

После этого можно проверить:

```bash
ls -l config.yaml
```

Получим что-то вроде:

```text
-rw-r--r--  1 user user 1234 Sep 27 12:00 config.yaml
```

Часть:

```text
-rw-r--r--
```

описывает тип объекта и права доступа.

---

# 2. Как читать `-rw-r--r--`

Разберём:

```text
-rw-r--r--
│├─┤├─┤├─┤
│ │   │   │
│ │   │   └── others
│ │   └────── group
│ └────────── owner
└──────────── type
```

Получается:

```text
-    rw-    r--    r--
│     │      │      │
│   owner   group  others
│
file
```

То есть:

```text
owner  → rw-
group  → r--
other  → r--
```

---

# 3. Три категории пользователей

Linux проверяет права для трёх основных категорий:

### `u` — user

Владелец файла.

### `g` — group

Группа, связанная с файлом.

### `o` — others

Все остальные пользователи.

Также используется:

```text
a = all
```

то есть:

```text
user + group + others
```

---

# 4. Три основных права

## `r` — read

Разрешение на чтение.

Для файла:

```text
можно прочитать содержимое
```

Для директории:

```text
можно получить список её записей
```

---

## `w` — write

Для файла:

```text
можно изменять содержимое
```

Для директории:

```text
можно изменять записи директории
```

Например, создавать, удалять и переименовывать элементы при наличии необходимых прав.

---

## `x` — execute

Для обычного файла:

```text
можно выполнить файл как программу
```

Для директории:

```text
можно проходить через директорию
и обращаться к объектам внутри неё
```

Это важный нюанс.

> `x` у директории — это не «запустить директорию».

---

# 5. Числовые права

Для каждого права используется число:

```text
r = 4
w = 2
x = 1
```

Права складываются.

### `7`

```text
4 + 2 + 1 = 7

rwx
```

### `6`

```text
4 + 2 = 6

rw-
```

### `5`

```text
4 + 1 = 5

r-x
```

### `4`

```text
4

r--
```

### `0`

```text
---
```

# 6. Как получается `755`

Команда:

```bash
chmod 755 script.sh
```

Расшифровка:

```text
7 → rwx
5 → r-x
5 → r-x
```

То есть:

```text
owner  → rwx
group  → r-x
other  → r-x
```

И итог:

```text
-rwxr-xr-x
```

---

# 7. Как получается `644`

```bash
chmod 644 config.yaml
```

Расшифровка:

```text
6 → rw-
4 → r--
4 → r--
```

Итог:

```text
-rw-r--r--
```

Типичный смысл:

```text
owner  → читать + изменять
group  → только читать
other  → только читать
```

---

# 8. Часто используемые права

| Права | Значение                          |
| ----- | --------------------------------- |
| `600` | owner: `rw`, остальные ничего     |
| `644` | owner: `rw`, остальные: `r`       |
| `700` | owner: `rwx`, остальные ничего    |
| `755` | owner: `rwx`, остальные: `r-x`    |
| `775` | owner/group: `rwx`, others: `r-x` |
| `777` | все имеют `rwx`                   |

`777` не является «универсально правильным» решением для Permission denied. Обычно такие права следует избегать без конкретной причины.

---

# 9. Символьный синтаксис

Права можно менять без указания полного набора.

Например:

```bash
chmod u+x script.sh
```

Добавить владельцу право выполнения:

```text
u+x
```

Удалить:

```bash
chmod u-x script.sh
```

Для группы:

```bash
chmod g+w file.txt
```

Для остальных:

```bash
chmod o-r file.txt
```

Для всех:

```bash
chmod a+r file.txt
```

---

# 10. `+`, `-`, `=`

Символьный синтаксис использует:

```text
+ → добавить
- → убрать
= → установить точно
```

Например:

```bash
chmod u+x script.sh
```

Добавить `x`.

```bash
chmod o-w file.txt
```

Убрать `w`.

```bash
chmod u=rw file.txt
```

Установить владельцу ровно `rw`.

---

# 11. Несколько изменений одновременно

Можно написать:

```bash
chmod u+x,g+r,o-r file.txt
```

Здесь:

```text
u+x → owner получает x
g+r → group получает r
o-r → others теряют r
```

---

# 12. Рекурсивное изменение

Для директории и её содержимого:

```bash
chmod -R 755 mydir
```

`-R` означает:

```text
recursive
```

То есть изменения применяются ко всему дереву.

Но с `-R` нужно быть осторожным.

Например, бездумно:

```bash
chmod -R 777 /
```

может серьёзно нарушить безопасность и работоспособность системы.

---

# 13. Права директории

Права директории отличаются от прав обычного файла.

Например:

```text
r → видеть содержимое директории
w → изменять записи директории
x → проходить/искать внутри директории
```

Представим:

```text
/home/app/data/file.txt
```

Чтобы обратиться к:

```text
/home/app/data/file.txt
```

процессу нужны права `x` на соответствующие директории пути.

Например:

```text
/home
/app
/data
```

Поэтому `Permission denied` может возникать даже тогда, когда сам файл имеет подходящие права.

---

# 14. Почему `x` для директории особенно важен

Например:

```text
drwx------
```

У владельца есть:

```text
rwx
```

а у остальных:

```text
---
```

Другой пользователь не сможет нормально пройти через эту директорию к объектам внутри неё, даже если сам файл внутри имеет `644`.

Получается:

```text
directory
   │
   └── file.txt
```

Проверять нужно права **всего пути**, а не только файла.

---

# 15. `chmod` не меняет владельца

Например:

```bash
chmod 644 file.txt
```

изменяет права.

Но:

```text
owner
group
```

остаются прежними.

Для изменения владельца используется:

```bash
chown
```

Например:

```bash
sudo chown app:app file.txt
```

---

# 16. `chmod` vs `chown` vs `chgrp`

| Команда | Что меняет         |
| ------- | ------------------ |
| `chmod` | права доступа      |
| `chown` | владельца и группу |
| `chgrp` | группу             |

Например:

```bash
chmod 640 config.yaml
chown app:app config.yaml
```

Получаем:

```text
owner → app
group → app

permissions:
owner → rw-
group → r--
other → ---
```

# 17. Как посмотреть права

Основная команда:

```bash
ls -l
```

Например:

```text
-rwxr-xr-- 1 ilya developers 1200 Sep 27 12:00 script.sh
```

Можно увидеть:

```text
-rwxr-xr--
│
├── type
├── owner permissions
├── group permissions
└── others permissions
```

# 18. `stat`

Для более подробной информации:

```bash
stat script.sh
```

Можно получить:

* права;
* UID;
* GID;
* размер;
* timestamps;
* inode;
* другие метаданные.

Например:

```bash
stat -c '%A %a %U %G %n' script.sh
```

# 19. `chmod` и Python

Представим, что есть:

```text
script.py
```

И нужно сделать его исполняемым:

```bash
chmod +x script.py
```

Но для запуска непосредственно:

```bash
./script.py
```

нужен подходящий shebang:

```python
#!/usr/bin/env python3

print("Hello")
```

Получается:

```text
shebang
   +
execute permission
   ↓
./script.py
```

Без `x` можно всё равно запустить:

```bash
python script.py
```

потому что исполняемым файлом в этом случае является `python`, а `script.py` передаётся ему как аргумент.

# 20. Типичный Backend-пример

Есть deploy-скрипт:

```text
/opt/myapp/deploy.sh
```

Пытаемся:

```bash
./deploy.sh
```

Получаем:

```text
Permission denied
```

Проверяем:

```bash
ls -l deploy.sh
```

Например:

```text
-rw-r--r-- deploy.sh
```

У файла нет `x`.

Исправляем:

```bash
chmod +x deploy.sh
```

Теперь:

```text
-rwxr-xr-x deploy.sh
```

И можно выполнить:

```bash
./deploy.sh
```

# 21. Типичный Permission denied

Если команда не работает:

```bash
./script.sh
```

проверяем:

### 1. Права файла

```bash
ls -l script.sh
```

### 2. Права директорий пути

```bash
namei -l /opt/myapp/script.sh
```

### 3. Владельца

```bash
ls -ln script.sh
```

### 4. При необходимости ACL

```bash
getfacl script.sh
```

Важно:

> `chmod` — только одна часть модели разрешений Linux.

На результат также могут влиять владелец, группа, ACL, mount options и другие механизмы безопасности.

# 22. Символические права vs числовые

### Числовой вариант

```bash
chmod 755 script.sh
```

Плюс:

* коротко;
* удобно;
* легко использовать в deployment.

Минус:

* нужно помнить, что означает каждая цифра.

### Символьный вариант

```bash
chmod u+x script.sh
```

Плюс:

* явно видно, какое изменение выполняется;
* удобно для точечного изменения.

---

# 23. Важный нюанс: `chmod 755`

`755` означает:

```text
owner  rwx
group  r-x
other  r-x
```

Но это **не означает**, что любой пользователь может изменить файл.

Для записи в файл нужна `w` для соответствующей категории, а для удаления файла критичны права на **директорию**, содержащую этот файл.

Это особенно важно при работе с Linux-серверами.

---

# 24. Специальные mode bits

Помимо `rwx`, Linux поддерживает специальные биты:

```text
setuid
setgid
sticky bit
```

Например:

```text
chmod 4755 program
```

или:

```text
chmod 1777 /some/directory
```

Они относятся к более продвинутому управлению правами.

Типичный пример sticky bit:

```text
/tmp
```

В общем случае он позволяет пользователям создавать файлы в общей директории, но ограничивает удаление чужих файлов.

---

# 25. Почему chmod важен Backend-разработчику

На Linux-сервере Backend постоянно сталкивается с правами:

```text
Python application
        ↓
configuration files
        ↓
logs
        ↓
uploads
        ↓
Unix sockets
        ↓
SSH keys
        ↓
Docker volumes
```

Например:

```text
FastAPI
   ↓
/opt/myapp
   ↓
app user
   ↓
config/logs/uploads
```

Если права настроены неправильно:

```text
Permission denied
```

может возникнуть при:

* чтении конфигурации;
* записи логов;
* загрузке файлов;
* запуске скрипта;
* работе с Unix socket;
* доступе к Docker volume.

## 🎤 Вопросы на собеседовании

### Что такое `chmod`?

Команда Linux для изменения mode bits — прав доступа файла или директории.

### Что означают `r`, `w`, `x`?

```text
r → read
w → write
x → execute
```

Для директории `x` означает возможность прохода/поиска внутри неё.

### Что означают `u`, `g`, `o`?

```text
u → user/owner
g → group
o → others
```

### Что означает `chmod 755 file`?

```text
owner  → rwx
group  → r-x
others → r-x
```

### Что означает `chmod 644 file`?

```text
owner  → rw-
group  → r--
others → r--
```

### Что означает `chmod +x script.sh`?

Добавляет право выполнения для текущей целевой категории по умолчанию, обычно для всех (`a+x`) в распространённом варианте `chmod +x`; при точном управлении лучше явно указать категорию, например `u+x`.

### Чем `chmod` отличается от `chown`?

```text
chmod → права
chown → владелец/группа
```

### Можно ли удалить файл, если у него нет `w`?

Да, если у пользователя есть необходимые права на **родительскую директорию**. Удаление записи из директории определяется прежде всего правами директории, а не `w` самого файла.

### Что означает `x` для директории?

Право проходить через директорию и выполнять поиск имён внутри неё.

### Что делает `chmod -R`?

Рекурсивно изменяет права для директории и её содержимого.

### Как посмотреть права?

```bash
ls -l
```

Более подробно:

```bash
stat file
```

### Как сделать Python-скрипт исполняемым?

```bash
chmod +x script.py
```

и добавить подходящий shebang:

```python
#!/usr/bin/env python3
```

После этого:

```bash
./script.py
```

### Что проверить при `Permission denied`?

```text
1. Права объекта
2. Владелец и группа
3. Права директорий в пути
4. ACL
5. Контекст/дополнительные механизмы безопасности
6. Mount options
```

Для диагностики пути:

```bash
namei -l /path/to/file
```
