# 🔐 Права доступа в Linux

## 🎤 Короткий ответ

**Права доступа** в Linux определяют, какие действия пользователи и процессы могут выполнять над файлами и каталогами.

Основные права:

```text
r — read    — чтение
w — write   — запись
x — execute — выполнение
```

Права задаются отдельно для трёх категорий:

```text
owner   — владелец
group   — группа
others  — остальные
```

Например:

```text
-rwxr-xr--
```

означает:

```text
owner  → rwx
group  → r-x
others → r--
```

Для управления правами используются `chmod`, `chown`, `chgrp`, а для просмотра — `ls -l`.

---

## 🗣️ Ответ на собеседовании

Права доступа в Linux определяют, что конкретный пользователь или процесс может делать с файловым объектом.

Для обычных файлов есть три основных права: `read`, `write` и `execute`. Они задаются отдельно для владельца файла, группы владельца и остальных пользователей.

Например:

```text
-rwxr-xr--
```

означает, что владелец может читать, изменять и выполнять файл, группа может читать и выполнять, а остальные могут только читать.

Права можно задавать символьной или числовой записью с помощью `chmod`. Владельца и группу можно менять через `chown` и `chgrp`.

Для каталогов значения `r`, `w` и `x` имеют немного другое значение: `r` позволяет читать список содержимого, `w` — изменять записи каталога, а `x` — проходить через каталог и обращаться к объектам внутри него.

# 📚 Разбор поглубже

## 1. Зачем нужны права доступа

Linux — многопользовательская система.

На сервере одновременно могут работать:

```text
ilya
deploy
postgres
nginx
root
```

Каждый пользователь и процесс не должен автоматически иметь доступ ко всем файлам.

Например:

```text
/app/.env
```

может содержать:

```text
DATABASE_PASSWORD=...
SECRET_KEY=...
```

Поэтому важно ограничить доступ к файлу.

Модель:

```text
Пользователь / процесс
        ↓
Проверка прав
        ↓
┌───────┴────────┐
│                │
разрешено      запрещено
```

---

# 2. Три основных права

## `r` — read

Разрешает чтение.

Для обычного файла:

```text
r → можно прочитать содержимое
```

Например:

```bash
cat config.txt
```

---

## `w` — write

Разрешает изменение содержимого.

Например:

```bash
echo "hello" > file.txt
```

---

## `x` — execute

Разрешает выполнение файла как программы или скрипта.

Например:

```bash
./script.sh
```

Чтобы это работало, файл должен иметь право `x`.

Например:

```text
-rwxr-xr-x
```

---

# 3. Owner, Group, Others

Для каждого объекта Linux хранит владельца и группу.

Права определяются для трёх категорий:

```text
owner
group
others
```

Например:

```text
-rwxr-x---
```

Разбираем:

```text
owner  → rwx
group  → r-x
others → ---
```

То есть:

| Категория | Права |
| --------- | ----- |
| Owner     | `rwx` |
| Group     | `r-x` |
| Others    | `---` |

---

# 4. Как читать `ls -l`

Команда:

```bash
ls -l
```

может показать:

```text
-rwxr-xr-- 1 ilya developers 1234 Sep 27 18:00 script.sh
```

Разбираем:

```text
-rwxr-xr--
│├──┬──┤
│   │  └── others
│   └───── group
└───────── owner
```

Полностью:

```text
-          → тип объекта
rwx        → owner
r-x        → group
r--        → others
```

---

# 5. Первый символ

Первый символ показывает тип объекта.

```text
- → обычный файл
d → каталог
l → symbolic link
```

Например:

```text
-rw-r--r--
```

обычный файл.

```text
drwxr-xr-x
```

каталог.

```text
lrwxrwxrwx
```

символическая ссылка.

---

# 6. Символьная запись

Права можно задавать через символы.

Например:

```bash
chmod u+x script.sh
```

Где:

```text
u → user/owner
g → group
o → others
a → all
```

Добавить право:

```bash
chmod u+x script.sh
```

Убрать:

```bash
chmod u-x script.sh
```

Добавить группе:

```bash
chmod g+w file.txt
```

Убрать запись для others:

```bash
chmod o-w file.txt
```

---

# 7. Числовая запись

Каждому праву соответствует число:

```text
r = 4
w = 2
x = 1
```

Поэтому:

```text
rwx = 4 + 2 + 1 = 7
rw- = 4 + 2     = 6
r-x = 4 + 1     = 5
-wx = 2 + 1     = 3
r-- = 4         = 4
-w- = 2         = 2
--x = 1         = 1
--- = 0
```

---

# 8. Что означает `755`

Например:

```bash
chmod 755 script.sh
```

Расшифровка:

```text
755
│││
││└── others → 5 → r-x
│└─── group  → 5 → r-x
└──── owner  → 7 → rwx
```

Получаем:

```text
-rwxr-xr-x
```

То есть:

```text
owner  → rwx
group  → r-x
others → r-x
```

---

# 9. Что означает `644`

Очень распространённый вариант для обычных файлов:

```bash
chmod 644 file.txt
```

Получаем:

```text
-rw-r--r--
```

То есть:

```text
owner  → rw-
group  → r--
others → r--
```

Владелец может изменять файл, остальные — только читать.

---

# 10. Что означает `600`

Для файлов с чувствительной информацией часто используют:

```bash
chmod 600 .env
```

Получаем:

```text
-rw-------
```

То есть:

```text
owner  → rw-
group  → ---
others → ---
```

Только владелец может читать и изменять файл.

---

# 11. `chmod`

`chmod` — изменение **permissions**.

Например:

```bash
chmod 755 script.sh
```

или:

```bash
chmod u+x script.sh
```

Проверить:

```bash
ls -l script.sh
```

---

# 12. `chown`

`chown` меняет владельца.

Например:

```bash
sudo chown ilya file.txt
```

Можно одновременно изменить владельца и группу:

```bash
sudo chown ilya:developers file.txt
```

Получится:

```text
owner → ilya
group → developers
```

---

# 13. `chgrp`

`chgrp` меняет только группу:

```bash
sudo chgrp developers file.txt
```

После этого:

```text
owner → прежний владелец
group → developers
```

---

# 14. Права доступа для каталогов

Здесь особенно важно не переносить буквально смысл прав обычного файла.

Для каталога:

### `r` — read

Можно получить список имён объектов внутри каталога.

### `w` — write

Можно изменять записи каталога:

* создавать файлы;
* удалять файлы;
* переименовывать объекты;

при наличии необходимых других разрешений.

### `x` — execute

Для каталога означает возможность **проходить через него** и обращаться к объектам внутри по имени, если остальные проверки доступа позволяют это.

Например:

```text
/home/ilya/project/app.py
```

Чтобы процесс мог обратиться к `app.py`, ему требуется право `x` на каталогах пути.

---

# 15. Почему `x` для каталога особенно важен

Допустим:

```text
project/
└── app.py
```

У пользователя есть:

```text
project → r--
```

Он может видеть имена объектов, но без `x` доступ к самим объектам внутри каталога ограничен.

Поэтому для каталогов часто встречается:

```text
r-x
```

Это означает:

```text
r → посмотреть содержимое
x → пройти внутрь
```

---

# 16. `root` и права

`root` имеет очень широкие привилегии и обычно может обходить многие обычные ограничения доступа.

Например:

```bash
sudo cat /etc/shadow
```

обычный пользователь, как правило, выполнить не сможет.

`root` может получить доступ к системным файлам, недоступным обычным пользователям.

---

# 17. Проверка доступа

Можно посмотреть владельца и права:

```bash
ls -l file.txt
```

Для анализа пути полезна:

```bash
namei -l /home/ilya/project/app.py
```

Она показывает компоненты пути и их права.

Это удобно, когда кажется:

> «У файла вроде правильные права, но приложение всё равно получает Permission denied».

Проблема может находиться в правах одного из родительских каталогов.

---

# 18. `Permission denied`

Одна из самых распространённых ошибок Linux:

```text
Permission denied
```

Например:

```bash
./script.sh
```

может вернуть:

```text
Permission denied
```

Если отсутствует `x`.

Исправление:

```bash
chmod +x script.sh
```

Другой вариант:

```bash
Permission denied: /app/config.json
```

может быть связан с владельцем, группой или правами каталогов.

Поэтому нужно проверить:

```bash
ls -l /app/config.json
namei -l /app/config.json
```

---

# 19. `umask`

При создании новых файлов и каталогов Linux использует **umask**.

Посмотреть:

```bash
umask
```

Например:

```text
0022
```

Umask определяет, какие права будут **убраны** из максимально допустимого набора по умолчанию.

Упрощённо:

```text
Новые объекты
      ↓
Базовые permissions
      ↓
     umask
      ↓
Итоговые permissions
```

Например, часто новые обычные файлы получают права вроде:

```text
644
```

а каталоги:

```text
755
```

при стандартной `umask 022`.

Важно:

> `umask` не просто «задаёт права файла», а ограничивает права, которые могут быть назначены при создании нового объекта.

---

# 20. Специальные права

Помимо `rwx`, в Linux существуют специальные permission bits:

```text
setuid
setgid
sticky bit
```

Они встречаются реже, но важны для понимания Linux.

---

# 21. Setuid

**setuid** для исполняемого файла позволяет при его запуске выполнять программу с effective user ID владельца файла.

Например:

```text
-rwsr-xr-x
```

`x` у owner заменён на:

```text
s
```

Классический пример — некоторые системные программы, которым требуется выполнить ограниченную привилегированную операцию.

Это чувствительный механизм с точки зрения безопасности.

---

# 22. Setgid

Setgid имеет несколько вариантов поведения.

Для исполняемого файла он влияет на effective group ID процесса.

Для каталога:

> новые файлы и подкаталоги обычно наследуют группу каталога.

Например:

```text
drwxrwsr-x project/
```

Здесь `s` в позиции group означает установленный setgid.

Это удобно для shared directories:

```text
project/
├── app.py
├── tests/
└── README.md
```

где несколько пользователей должны работать с одной группой.

---

# 23. Sticky Bit

Sticky bit часто используется на каталогах, в которые разные пользователи могут записывать файлы.

Классический пример:

```text
/tmp
```

Типичный вид:

```text
drwxrwxrwt
```

`t` в конце означает sticky bit.

Его смысл:

> пользователь не может просто удалить или переименовать файл другого пользователя в таком каталоге только потому, что каталог разрешает запись.

Это важно для общих каталогов вроде `/tmp`.

---

# 24. ACL

Стандартная модель:

```text
owner
group
others
```

иногда недостаточна.

**ACL — Access Control List** позволяет задавать дополнительные правила доступа для конкретных пользователей и групп.

Например:

```text
owner  → rwx
group  → r-x
others → ---
```

Но дополнительно:

```text
user:ivan → rw-
```

Посмотреть ACL:

```bash
getfacl file.txt
```

Изменить:

```bash
setfacl -m u:ivan:rw file.txt
```

ACL полезны, когда стандартной модели owner/group/others недостаточно.

---

# 25. Как Linux определяет доступ

Упрощённо:

```text
Процесс
   ↓
UID / GID
   ↓
Объект
   ↓
owner / group / others
   ↓
permissions
   ↓
allow / deny
```

Важно, что процесс имеет credentials, связанные с UID/GID, а проверка доступа выполняется ядром.

---

# 26. Права и процессы

Права относятся не только к пользователю, который «запустил программу».

Доступ проверяется для **процесса**, выполняющего операцию.

Например:

```text
nginx process
UID → www-data
      ↓
/home/ilya/private.txt
      ↓
Permission denied
```

Даже если разработчик сам может прочитать файл, процесс `nginx` может не иметь такого доступа.

Это особенно важно в Backend и Docker.

---

# 27. Права в Docker

Например:

```text
Host
└── /data
```

монтируется в контейнер:

```text
Container
└── /app/data
```

Если процесс внутри контейнера работает от UID, который не имеет нужных прав на файлы, можно получить:

```text
Permission denied
```

Поэтому при проблемах с Docker важно учитывать:

```text
UID
GID
owner
group
permissions
mounts
```

# 28. Типичные значения permissions

| Права       | Число | Типичный сценарий                 |
| ----------- | ----: | --------------------------------- |
| `rwxr-xr-x` | `755` | исполняемый файл / каталог        |
| `rw-r--r--` | `644` | обычный файл                      |
| `rw-------` | `600` | приватный файл                    |
| `rwx------` | `700` | приватный каталог/скрипт          |
| `rwxrwxr-x` | `775` | общий рабочий каталог             |
| `rw-rw-r--` | `664` | файл для совместной работы группы |

Конкретные права должны зависеть от назначения объекта и требований безопасности.

# 29. Практический пример

Допустим, есть приложение:

```text
/app
├── main.py
├── .env
└── logs/
```

Можно сделать:

```text
main.py → 644
.env    → 600
logs/   → 755
```

Например:

```bash
chmod 644 /app/main.py
chmod 600 /app/.env
chmod 755 /app/logs
```

Но если приложение запускается от пользователя `app`, нужно также убедиться, что именно этот пользователь имеет необходимый доступ.

Например:

```bash
chown -R app:app /app
```

# 30. Типичная диагностика `Permission denied`

Если Backend-приложение не может прочитать файл:

### 1. Проверить процесс

```bash
ps aux | grep python
```

### 2. Узнать пользователя процесса

```bash
ps -o pid,user,group,cmd -p PID
```

### 3. Проверить файл

```bash
ls -l /path/to/file
```

### 4. Проверить весь путь

```bash
namei -l /path/to/file
```

### 5. Проверить ACL

```bash
getfacl /path/to/file
```

### 6. Исправить владельца/группу/права

Например:

```bash
sudo chown app:app /path/to/file
chmod 640 /path/to/file
```

# 31. Что важно различать

### `chmod` vs `chown`

```text
chmod → права
chown → владелец и группа
```

### `rwx` для файла vs каталога

Для файла:

```text
r → читать содержимое
w → изменять содержимое
x → выполнять
```

Для каталога:

```text
r → читать список
w → изменять записи
x → проходить внутрь
```

### UID vs имя пользователя

Linux в конечном счёте использует числовые идентификаторы:

```text
UID
GID
```

Имена вроде `ilya` и `developers` — удобное представление этих идентификаторов.

### Permission vs ACL

Обычная модель:

```text
owner / group / others
```

ACL позволяет задавать дополнительные правила.

## 🎤 Вопросы на собеседовании

### Что такое права доступа в Linux?

Механизм, который определяет, какие операции процесс может выполнять над файловым объектом.

### Какие основные права существуют?

```text
r → read
w → write
x → execute
```

### Для кого задаются права?

Для:

```text
owner
group
others
```

### Что означает `755`?

```text
owner  → rwx
group  → r-x
others → r-x
```

### Что означает `644`?

```text
owner  → rw-
group  → r--
others → r--
```

### Чем `chmod` отличается от `chown`?

`chmod` изменяет права доступа, `chown` — владельца и/или группу.

### Что означает `x` для каталога?

Право проходить через каталог и обращаться к объектам внутри него при наличии необходимых разрешений.

### Что такое `umask`?

Маска, которая ограничивает права, назначаемые новым файлам и каталогам при их создании.

### Что такое setuid?

Специальный permission bit для исполняемого файла, позволяющий при его запуске использовать effective UID владельца файла.

### Что такое setgid?

Специальный permission bit. Для исполняемого файла влияет на effective GID, а для каталога обычно обеспечивает наследование группы новыми объектами.

### Что такое sticky bit?

Специальный permission bit каталога, ограничивающий удаление/переименование чужих файлов пользователями, имеющими запись в этот каталог.

### Что такое ACL?

Расширенный механизм управления доступом, позволяющий задавать дополнительные права для конкретных пользователей и групп.

### Почему приложение получает `Permission denied`, хотя файл имеет `644`?

Нужно учитывать **пользователя процесса**, группу и права всех родительских каталогов. Например, файл может быть `644`, но процесс может не иметь `x` на одном из каталогов пути.

### Почему Backend-разработчику важно понимать права доступа?

Потому что серверные приложения работают от конкретных пользователей и групп и должны иметь доступ к конфигурации, логам, сокетам, файлам и Docker volumes, но при этом не получать лишних привилегий.
