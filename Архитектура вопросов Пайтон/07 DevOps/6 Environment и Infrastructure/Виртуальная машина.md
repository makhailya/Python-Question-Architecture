# 🖥️ Виртуальная машина

## 🎤 Короткий ответ

**Виртуальная машина (VM)** — это программно эмулируемый компьютер, который работает внутри физического компьютера и имеет собственные виртуальные CPU, RAM, диск, сетевую карту и **гостевую операционную систему**.

В отличие от Docker-контейнера, VM запускает **полноценную отдельную ОС**.

## 🎯 Формула для собеседования

> **Физический сервер → Hypervisor → Virtual Machine → Guest OS → Application.**

А для контейнеров:

> **Физический сервер → Host OS → Container Runtime → Container → Application.**

---

# 🔹 Что такое виртуальная машина

Представим физический компьютер:

```text
┌──────────────────────────────────────┐
│          Физический сервер           │
│                                      │
│ CPU     RAM     SSD     Network      │
└──────────────────┬───────────────────┘
                   ↓
              Hypervisor
                   ↓
       ┌───────────┴───────────┐
       ↓                       ↓
      VM 1                    VM 2
       │                       │
   Guest OS                Guest OS
       │                       │
   Application             Application
```

Каждая VM получает виртуальные ресурсы:

* vCPU;
* RAM;
* виртуальный диск;
* виртуальную сетевую карту;
* другие виртуальные устройства.

Для гостевой ОС это выглядит как отдельный компьютер.

---

# 🔹 Hypervisor

**Hypervisor** — программный слой, который создаёт и управляет виртуальными машинами.

Он распределяет ресурсы физического сервера между VM:

```text
Physical Server
       │
       ↓
   Hypervisor
   ┌────┼────┐
   ↓    ↓    ↓
  VM1  VM2  VM3
```

Hypervisor отвечает за:

* выделение CPU;
* выделение RAM;
* виртуальные диски;
* виртуальную сеть;
* изоляцию VM;
* запуск и остановку виртуальных машин.

---

# 🔹 Типы Hypervisor

## Type 1 — Bare Metal

Hypervisor работает **непосредственно на физическом сервере**.

```text
Hardware
   ↓
Hypervisor
   ↓
VM
```

Примеры:

* VMware ESXi;
* Microsoft Hyper-V;
* KVM;
* Proxmox VE использует KVM для виртуальных машин.

Такой вариант часто используется на серверах и в дата-центрах.

---

## Type 2 — Hosted

Hypervisor работает **как приложение внутри основной ОС**.

```text
Hardware
   ↓
Host OS
   ↓
Hypervisor
   ↓
VM
```

Примеры:

* VirtualBox;
* VMware Workstation;
* Parallels Desktop.

Часто используется на компьютерах разработчиков.

---

# 🔹 Guest OS

**Guest OS** — операционная система внутри виртуальной машины.

Например:

```text
Physical Mac
     ↓
Virtual Machine
     ↓
Ubuntu Linux
     ↓
Python
     ↓
FastAPI
```

Можно иметь:

```text
VM 1 → Ubuntu
VM 2 → Debian
VM 3 → Windows
```

при этом все VM работают на одном физическом сервере.

---

# 🔹 Виртуальные ресурсы

Допустим, физический сервер имеет:

```text
CPU: 16 cores
RAM: 64 GB
SSD: 1 TB
```

Можно создать:

```text
VM 1
4 vCPU
16 GB RAM
200 GB disk

VM 2
4 vCPU
16 GB RAM
200 GB disk

VM 3
2 vCPU
8 GB RAM
100 GB disk
```

Hypervisor распределяет физические ресурсы между виртуальными машинами.

---

# 🔹 vCPU

**vCPU (virtual CPU)** — виртуальный процессор, предоставленный VM.

Например:

```text
Physical CPU
     │
     ├── vCPU → VM1
     ├── vCPU → VM1
     ├── vCPU → VM2
     └── vCPU → VM3
```

vCPU не обязательно означает отдельное физическое ядро.

Hypervisor планирует выполнение виртуальных CPU на физических CPU.

---

# 🔹 Виртуальная память

VM получает определённый объём RAM:

```text
VM
└── 8 GB RAM
```

Guest OS считает, что у неё есть собственные 8 GB.

Hypervisor управляет соответствием виртуальной памяти физической.

---

# 🔹 Виртуальный диск

VM может иметь виртуальный диск:

```text
VM
   ↓
Virtual Disk
   ↓
disk.qcow2
```

Например, KVM/QEMU может использовать:

```text
qcow2
```

Физически это может быть файл на SSD хоста.

Guest OS при этом видит его как обычный диск:

```text
/dev/sda
```

---

# 🔹 Сеть виртуальной машины

VM также получает виртуальную сетевую карту:

```text
VM
 ↓
Virtual NIC
 ↓
Virtual Switch
 ↓
Physical NIC
 ↓
Network
```

В зависимости от конфигурации VM может иметь:

* NAT;
* bridge;
* отдельный виртуальный интерфейс;
* VLAN.

---

# 🔹 VM vs физический сервер

| Физический сервер            | Виртуальная машина                 |
| ---------------------------- | ---------------------------------- |
| Реальное оборудование        | Виртуализированное оборудование    |
| Физические CPU/RAM           | vCPU/vRAM                          |
| Физический диск              | Виртуальный диск                   |
| Физическая NIC               | Виртуальная NIC                    |
| ОС устанавливается на железо | Guest OS устанавливается внутри VM |

---

# 🔹 VM vs Docker

Это один из самых важных вопросов для Backend/DevOps.

### Virtual Machine

```text
┌─────────────────────────┐
│ Physical Server         │
├─────────────────────────┤
│ Hypervisor              │
├────────────┬────────────┤
│ VM         │ VM         │
│ Guest OS   │ Guest OS   │
│ App        │ App        │
└────────────┴────────────┘
```

### Docker

```text
┌─────────────────────────┐
│ Physical Server         │
├─────────────────────────┤
│ Host OS                 │
├─────────────────────────┤
│ Docker                  │
├────────────┬────────────┤
│ Container  │ Container  │
│ App        │ App        │
└────────────┴────────────┘
```

Главное различие:

> **VM виртуализирует компьютер и запускает полноценную Guest OS. Docker контейнеризирует процессы и использует ядро Host OS.**

---

# 🔹 Сравнение VM и Container

| Характеристика       | VM                  | Container                |
| -------------------- | ------------------- | ------------------------ |
| Guest OS             | ✅ Есть              | ❌ Нет отдельной          |
| Собственное ядро ОС  | ✅                   | ❌ Использует kernel host |
| Изоляция             | Сильная             | Легче                    |
| Размер               | Обычно больше       | Обычно меньше            |
| Запуск               | Обычно медленнее    | Обычно быстрее           |
| Потребление ресурсов | Выше                | Ниже                     |
| Плотность размещения | Ниже                | Выше                     |
| Полная ОС внутри     | ✅                   | ❌                        |
| Типичное применение  | Виртуальные серверы | Микросервисы, приложения |

---

# 🔹 Почему VM тяжелее контейнера

VM должна запустить полноценную ОС:

```text
VM
 ├── Kernel
 ├── System libraries
 ├── Services
 ├── Filesystem
 └── Application
```

Контейнеру отдельная ОС не нужна:

```text
Container
 ├── Application
 ├── Dependencies
 └── Filesystem
```

Kernel берётся от Host OS.

Поэтому контейнеры обычно:

* быстрее стартуют;
* занимают меньше места;
* позволяют разместить больше экземпляров на одном сервере.

---

# 🔹 Snapshot

**Snapshot** — снимок состояния виртуальной машины или её дисков в определённый момент времени.

Например:

```text
VM
 ↓
Snapshot
 ↓
состояние на момент T
```

Можно сделать snapshot перед опасным изменением:

```text
До обновления
     ↓
 Snapshot
     ↓
Обновление
     ↓
Проблема
     ↓
Rollback
```

Но snapshot **не стоит автоматически считать полноценным backup**.

Для надёжного восстановления нужны отдельные резервные копии.

---

# 🔹 Migration

VM можно переносить между физическими серверами.

Например:

```text
Server A
   │
   │ VM
   ↓
Server B
```

Это называется **migration**.

При определённых технологиях возможна **live migration** — перенос работающей VM с минимальным простоем.

Это используется для:

* обслуживания серверов;
* балансировки нагрузки;
* переноса VM;
* обслуживания оборудования.

---

# 🔹 Зачем используют виртуальные машины

Основные сценарии:

### 1. Консолидация серверов

Вместо:

```text
Server 1 → Application A
Server 2 → Application B
Server 3 → Application C
```

можно:

```text
        Physical Server
              ↓
          Hypervisor
        ┌─────┼─────┐
        ↓     ↓     ↓
       VM1   VM2   VM3
```

---

### 2. Изоляция

Разные приложения могут работать в разных VM.

```text
VM 1 → Production
VM 2 → Testing
VM 3 → Development
```

---

### 3. Разные операционные системы

На одном физическом сервере можно запускать:

```text
VM 1 → Linux
VM 2 → Windows
VM 3 → другой Linux
```

---

### 4. Лаборатории и тестирование

Например, можно создать несколько VM:

```text
Ubuntu Server
     +
PostgreSQL
     +
Redis
     +
Docker
```

и использовать их для экспериментов, не затрагивая основную ОС.

---

# 🔹 Виртуализация и Docker вместе

На практике VM и контейнеры **не являются взаимоисключающими технологиями**.

Можно построить:

```text
Physical Server
      ↓
Hypervisor
      ↓
Linux VM
      ↓
Docker
      ↓
┌────────┬────────┬────────┐
│FastAPI │ Redis  │ Nginx  │
└────────┴────────┴────────┘
```

Например, Kubernetes-кластер тоже может работать поверх VM.

---

# 🔹 Пример с Proxmox

Типичная архитектура:

```text
Physical Server
      ↓
Proxmox VE
      ↓
┌──────────────┬──────────────┐
│ VM           │ VM           │
│ Ubuntu       │ Debian       │
│              │              │
│ Docker       │ PostgreSQL   │
│ Containers   │              │
└──────────────┴──────────────┘
```

**Proxmox VE** является платформой виртуализации, которая может управлять VM через KVM/QEMU и контейнерами LXC.

# 🔹 VM и LXC

Важно не путать.

### VM

```text
Hardware
 ↓
Hypervisor
 ↓
VM
 ↓
Guest Kernel
 ↓
Application
```

### LXC

```text
Hardware
 ↓
Host OS
 ↓
LXC
 ↓
Container
 ↓
Application
```

LXC — системная контейнеризация, а не полноценная виртуальная машина.

# 🔹 Частые вопросы на собеседовании

### Что такое виртуальная машина?

> Программно виртуализированный компьютер с виртуальными ресурсами, на котором работает полноценная гостевая ОС.

### Что такое Hypervisor?

> Программный слой, который создаёт и управляет виртуальными машинами и распределяет между ними физические ресурсы.

### Какие бывают Hypervisor?

> Type 1 работает непосредственно на железе, Type 2 работает поверх Host OS.

### Чем VM отличается от Docker?

> VM содержит полноценную Guest OS и собственное виртуализированное оборудование, а контейнер использует ядро Host OS и изолирует процессы.

### Что такое Guest OS?

> Операционная система, работающая внутри виртуальной машины.

### Что такое vCPU?

> Виртуальный процессор, предоставленный виртуальной машине hypervisor'ом.

### Что такое Snapshot?

> Снимок состояния VM/её дисков в определённый момент времени, который можно использовать для возврата к этому состоянию.

### Можно ли запускать Docker внутри VM?

> Да. Это распространённая архитектура: VM предоставляет изолированную ОС, а Docker запускает контейнеры внутри неё.

```text
                 Physical Server
                       │
                       ↓
                  Hypervisor
                       │
          ┌────────────┴────────────┐
          ↓                         ↓
         VM 1                      VM 2
          │                         │
      Guest OS                  Guest OS
          │                         │
      Application               Application
```

### 🎤 Финальная формула

> **Виртуальная машина — это виртуализированный компьютер с собственными vCPU, RAM, диском и сетью, на котором работает полноценная Guest OS. Hypervisor создаёт VM и распределяет физические ресурсы между ними. Главное отличие от Docker: VM виртуализирует целую машину и запускает отдельную ОС, а контейнер использует ядро Host OS.**
