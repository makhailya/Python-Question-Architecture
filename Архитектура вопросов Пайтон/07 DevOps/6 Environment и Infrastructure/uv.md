# uv — конспект для Python Backend

## Формула для собеседования

**uv** — быстрый менеджер Python-пакетов и проектов, написанный на Rust и разработанный Astral. Он объединяет установку зависимостей, управление виртуальными окружениями, разрешение зависимостей, запуск инструментов и управление версиями Python.

**Формула:**

`uv init → uv add → uv run → uv lock → uv sync`

- `uv init` — создать проект.
- `uv add` — добавить зависимость.
- `uv run` — запустить команду в окружении проекта.
- `uv lock` — обновить lock-файл.
- `uv sync` — синхронизировать окружение с зависимостями проекта.

## Короткий ответ

`uv` — современная альтернатива связке `pip + venv` и инструментам управления проектами, таким как Poetry. Он умеет быстро устанавливать пакеты, создавать виртуальные окружения, фиксировать зависимости в `uv.lock` и запускать команды в управляемом окружении.

В Python Backend-разработке `uv` используют для настройки проектов, установки библиотек, воспроизводимой разработки и запуска тестов.

## Ответ на собеседовании

`uv` — это быстрый инструмент управления Python-окружениями и зависимостями. Он позволяет создавать проекты, управлять версиями Python, устанавливать библиотеки, разрешать зависимости и фиксировать их в `uv.lock`.

В отличие от простого `pip`, который в первую очередь устанавливает пакеты, `uv` предоставляет единый интерфейс для управления проектом. Он поддерживает `pyproject.toml`, виртуальные окружения и воспроизводимую синхронизацию зависимостей.

В Backend-проектах я могу использовать `uv add` для добавления библиотек, `uv run pytest` для запуска тестов и `uv sync` для установки зафиксированного набора зависимостей. Это упрощает настройку проекта на разных компьютерах и в CI/CD.

## 1. Какие задачи решает uv

В традиционном Python-проекте можно использовать несколько отдельных инструментов:

| Инструмент | Назначение |
|---|---|
| `python -m venv` | Создание виртуального окружения |
| `pip` | Установка пакетов |
| `pip-tools` | Фиксация разрешённых зависимостей |
| `pyenv` | Управление версиями Python |
| `pipx` | Установка изолированных CLI-инструментов |

`uv` объединяет многие из этих сценариев в одном инструменте.

Он умеет:

- создавать и обслуживать виртуальные окружения;
- устанавливать и управлять версиями Python;
- добавлять и удалять зависимости проекта;
- разрешать совместимые версии пакетов;
- создавать и использовать lock-файл;
- запускать команды в окружении проекта;
- запускать CLI-инструменты в изолированных окружениях.

Это не означает, что `uv` полностью заменяет каждый из перечисленных инструментов во всех сценариях.

## 2. Установка и проверка

На macOS через Homebrew:

```bash
brew install uv
```

Проверка версии:

```bash
uv --version
```

Обновление через Homebrew:

```bash
brew upgrade uv
```

Если `uv` уже установлен другим способом, обновляй его тем же способом, которым устанавливал.

## 3. Создание нового проекта

Перейди в каталог, где хранятся проекты:

```bash
mkdir my-backend
cd my-backend
uv init
```

Команда `uv init` создаёт структуру проекта. В зависимости от типа проекта и версии инструмента могут появиться:

```text
my-backend/
├── .python-version
├── pyproject.toml
├── main.py
└── README.md
```

После добавления зависимостей также обычно появляется `uv.lock`, а при создании локального окружения — `.venv/`.

Посмотреть содержимое проекта:

```bash
ls -la
```

## 4. Управление Python

Посмотреть доступные версии Python, известные `uv`:

```bash
uv python list
```

Установить конкретную версию:

```bash
uv python install 3.13
```

Указать версию Python для проекта:

```bash
uv python pin 3.13
```

Команда `uv python pin` записывает выбранную версию в файл `.python-version`.

Создать виртуальное окружение с определённой версией:

```bash
uv venv --python 3.13
```

Активировать окружение вручную на macOS или Linux:

```bash
source .venv/bin/activate
```

**Важно:** для большинства команд проекта вручную активировать `.venv` необязательно. `uv run` самостоятельно использует окружение проекта.

## 5. Управление зависимостями

### Добавление пакета

```bash
uv add fastapi
uv add "uvicorn[standard]"
uv add sqlalchemy
uv add psycopg
```

Команда `uv add` обычно:

1. Добавляет зависимость в `pyproject.toml`.
2. Разрешает зависимости с учётом ограничений.
3. Обновляет `uv.lock`.
4. Синхронизирует виртуальное окружение.

Для проекта с PostgreSQL может понадобиться подходящий драйвер, например `psycopg`. Конкретный выбор зависит от используемого стека и способа подключения.

### Установка зависимостей для разработки

```bash
uv add --dev pytest ruff
```

В `pyproject.toml` зависимости будут разделены на основные и группы для разработки.

В актуальных проектах `uv` для этого используется секция групп зависимостей, например `dependency-groups`.

### Удаление пакета

```bash
uv remove fastapi
```

`uv` обновит конфигурацию зависимостей и lock-файл, а затем синхронизирует окружение.

### Посмотреть дерево зависимостей

```bash
uv tree
```

Команда помогает понять, какие пакеты установлены напрямую, а какие приходят транзитивно через другие зависимости.

## 6. Что такое pyproject.toml

`pyproject.toml` — стандартный файл конфигурации Python-проекта. В нём можно хранить метаданные проекта, зависимости и настройки инструментов.

Упрощённый пример:

```toml
[project]
name = "my-backend"
version = "0.1.0"
requires-python = ">=3.13"
dependencies = [
    "fastapi",
    "uvicorn[standard]",
    "sqlalchemy",
]

[dependency-groups]
dev = [
    "pytest",
    "ruff",
]
```

В реальном проекте структура может отличаться: например, использовать дополнительные группы зависимостей, настройки сборки или другие инструменты.

**Запомнить:** `pyproject.toml` описывает проект и его зависимости, а `uv.lock` фиксирует конкретные разрешённые версии для воспроизводимой установки.

## 7. Что такое uv.lock

`uv.lock` — lock-файл, в котором зафиксированы разрешённые версии зависимостей и связанные данные, необходимые `uv` для воспроизводимой синхронизации окружения.

Зачем он нужен:

- разработчики получают согласованный набор версий;
- CI/CD устанавливает те же разрешённые зависимости;
- уменьшается риск неожиданного обновления транзитивных пакетов;
- обновление зависимостей можно контролировать отдельно от разработки.

### Основные команды

Обновить lock-файл:

```bash
uv lock
```

Синхронизировать окружение с проектом:

```bash
uv sync
```

Запустить синхронизацию без установки dev-зависимостей:

```bash
uv sync --no-dev
```

Запустить тесты:

```bash
uv run pytest
```

Для обычной работы с проектом lock-файл следует хранить в Git. В CI полезно использовать:

```bash
uv sync --locked
```

Этот режим проверяет, что lock-файл актуален относительно конфигурации проекта, и не позволяет незаметно изменить его при синхронизации.

## 8. uv run — запуск команд

`uv run` запускает команду в окружении проекта, при необходимости синхронизируя зависимости.

Примеры:

```bash
uv run python main.py
uv run pytest
uv run ruff check .
uv run python -c "import sys; print(sys.executable)"
```

Последняя команда показывает путь к интерпретатору, который используется при запуске.

### Почему это удобно

Без `uv run` можно случайно запустить системный Python или использовать пакеты из другого виртуального окружения.

`uv run` уменьшает вероятность такой ошибки, поскольку привязывает выполнение команды к окружению проекта.

## 9. Запуск CLI-инструментов через uvx

`uvx` — удобный интерфейс для запуска CLI-инструментов в изолированных окружениях. Он является сокращённой формой `uv tool run`.

Например:

```bash
uvx ruff check .
uvx httpie --help
```

Это удобно, если нужно использовать инструмент, не добавляя его в основные зависимости проекта.

Разница:

- `uv add --dev ruff` — Ruff становится зависимостью разработки проекта;
- `uvx ruff check .` — запускается изолированный инструмент, не обязательно добавляемый в зависимости проекта.

Если инструмент нужен команде постоянно и должен запускаться одинаково в CI, его часто разумнее зафиксировать в dev-зависимостях проекта.

## 10. uv vs pip + venv vs Poetry

| Возможность | `pip + venv` | Poetry | uv |
|---|---|---|---|
| Установка пакетов | Да | Да | Да |
| Виртуальные окружения | `venv` | Да | Да |
| Управление зависимостями проекта | Частично, через дополнительные средства | Да | Да |
| Lock-файл | Отдельные инструменты или процессы | `poetry.lock` | `uv.lock` |
| Управление версиями Python | Внешние инструменты | Ограниченное взаимодействие | Да |
| Запуск команд в окружении | Вручную или через скрипты | `poetry run` | `uv run` |
| Изолированный запуск CLI | Отдельные инструменты | Не основная функция | `uvx` |
| Скорость разрешения и установки | Зависит от сценария | Зависит от сценария | Часто очень высокая |

`uv` не является единственно правильным выбором. Poetry по-прежнему подходит для управления Python-проектами, а `pip + venv` остаётся распространённым стандартным вариантом.

Выбор зависит от требований команды, существующей инфраструктуры и принятого процесса сборки.

## 11. Типичный workflow Python Backend

Пример настройки небольшого API-проекта:

```bash
uv init
uv python pin 3.13
uv add fastapi "uvicorn[standard]" sqlalchemy
uv add --dev pytest ruff
uv run pytest
uv run ruff check .
```

При клонировании готового проекта:

```bash
git clone <repository-url>
cd <project-directory>
uv sync --locked
uv run pytest
```

В реальном репозитории команда клонирования использует фактический URL, а `uv sync --locked` — уже существующие `pyproject.toml` и `uv.lock`.

### Что хранить в Git

Обычно коммитят:

- `pyproject.toml`;
- `uv.lock`;
- `.python-version`, если проект фиксирует версию Python;
- исходный код и конфигурацию проекта.

Обычно не коммитят:

- `.venv/`;
- секреты в `.env`;
- временные файлы и локальные кэши.

## 12. Типичные ошибки

1. **Путать `uv add` и `uv pip install`.** Первая команда управляет зависимостями проекта и его конфигурацией. Вторая предоставляет интерфейс, совместимый с `pip`, для установки пакетов.
2. **Не коммитить `uv.lock`.** В командной разработке это ухудшает воспроизводимость окружения.
3. **Запускать `python` напрямую и не проверять окружение.** Можно случайно использовать другой интерпретатор.
4. **Редактировать зависимости вручную и забывать обновлять lock-файл.** Используй `uv lock` или соответствующие команды управления проектом.
5. **Считать `.venv` переносимым между компьютерами.** Виртуальное окружение привязано к платформе и интерпретатору; на другом компьютере его обычно пересоздают.
6. **Добавлять все инструменты в production-зависимости.** `pytest` и `ruff` обычно относятся к dev-зависимостям.
7. **Считать `uv sync --locked` командой обновления зависимостей.** Её задача — синхронизировать окружение с уже актуальным lock-файлом, а не свободно обновлять версии.

## 13. Вопросы для собеседования

### Что такое uv?

Быстрый инструмент для управления Python-проектами, пакетами, виртуальными окружениями и версиями Python.

### Чем uv отличается от pip?

`pip` прежде всего устанавливает пакеты. `uv` также предоставляет управление проектом, разрешение и фиксацию зависимостей, работу с виртуальными окружениями и запуск команд.

### Для чего нужен uv.lock?

Для фиксации разрешённых версий зависимостей и воспроизводимой синхронизации окружения.

### В чём разница между uv add и uv sync?

`uv add` изменяет набор зависимостей проекта. `uv sync` приводит окружение к состоянию, описанному конфигурацией и lock-файлом.

### Что делает uv run?

Запускает команду в окружении проекта, при необходимости синхронизируя зависимости.

### Что такое uvx?

Инструмент для запуска CLI-программ в изолированных окружениях без обязательного добавления их в зависимости проекта.

### Нужно ли активировать виртуальное окружение вручную?

Не обязательно. При использовании `uv run` инструмент сам выбирает окружение проекта.
