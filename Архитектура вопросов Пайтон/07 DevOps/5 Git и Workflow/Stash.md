# 📦 Stash в Git

## 🎤 Короткий ответ

**Git Stash** — это механизм временного сохранения незакоммиченных изменений, чтобы можно было очистить рабочую директорию и переключиться на другую ветку или выполнить другую Git-операцию.

Например, я работаю в `feature`, но мне срочно нужно перейти в `main`:

```bash
git stash
git switch main
```

Мои изменения не теряются — Git временно сохраняет их в stash.

Вернуться к ним можно через:

```bash
git stash pop
```

Важно: **stash — это не commit и не замена нормальной истории Git**. Это временное хранилище незакоммичанных изменений.

---

## 🗣️ Ответ на собеседовании

> `git stash` используется для временного сохранения незакоммиченных изменений в рабочей директории и staging area. Это удобно, когда я ещё не закончил работу, но мне нужно временно переключиться на другую ветку.
>
> Например, я изменяю несколько файлов в `feature`, но приходит срочная задача в `main`. Я могу выполнить `git stash`, переключиться на `main`, выполнить необходимые действия, а затем вернуться в `feature` и восстановить изменения через `git stash pop`.
>
> Stash не является обычным commit и обычно используется как временное хранилище. Если изменения уже логически готовы и должны сохраняться надолго, лучше сделать нормальный commit.
>
> Git может хранить несколько stash-записей. Их можно посмотреть через `git stash list`, применить конкретную запись через `git stash apply stash@{1}` или удалить через `git stash drop`.

# 📚 Разбор поглубже

## 1. Зачем нужен Stash

Представим:

```text
feature/login
```

Я начал писать авторизацию:

```text
app/auth.py       изменён
tests/test_auth.py изменён
```

Но работу ещё нельзя нормально коммитить.

В этот момент появляется задача:

> «Срочно переключись на `main` и исправь production bug».

Если просто сделать:

```bash
git switch main
```

Git может не позволить переключиться, если незакоммиченные изменения конфликтуют с файлами другой ветки.

Можно было бы сделать временный commit, но это не всегда удобно:

```text
WIP: unfinished login
```

Для такой ситуации и подходит stash.

```bash
git stash
```

Получаем:

```text
feature/login
    │
    ├── незакоммиченные изменения
    │
    ▼
  git stash
    │
    ▼
рабочая директория очищена
```

Теперь можно переключиться:

```bash
git switch main
```

---

# 2. Что именно сохраняет Stash

Обычный:

```bash
git stash
```

сохраняет изменения, которые находятся в:

* рабочей директории;
* staging area.

После этого рабочая директория возвращается к состоянию последнего commit.

Упрощённо:

```text
До:

Commit
  │
  ├── tracked file A ← изменён
  ├── tracked file B ← изменён + staged
  └── file C ← unchanged

git stash

После:

Commit
  │
  ├── file A ← чистый
  ├── file B ← чистый
  └── file C ← unchanged

Stash
  ├── изменения A
  └── изменения B
```

---

# 3. Создание Stash

Простейшая команда:

```bash
git stash
```

Часто удобнее сразу дать описание:

```bash
git stash push -m "WIP: authentication"
```

Например:

```text
stash@{0}: On feature/login: WIP: authentication
```

Описание помогает понять, что именно находится внутри stash.

---

# 4. Посмотреть список Stash

Все сохранённые stash:

```bash
git stash list
```

Например:

```text
stash@{0}: On feature/login: WIP: authentication
stash@{1}: On feature/payment: WIP: payment validation
stash@{2}: On main: temporary changes
```

Stash имеют индексы:

```text
stash@{0}
stash@{1}
stash@{2}
```

`stash@{0}` — самый свежий.

---

# 5. Восстановление через `pop`

Самый распространённый вариант:

```bash
git stash pop
```

Git:

1. применяет изменения из последнего stash;
2. удаляет этот stash из списка.

Например:

```text
Было:

feature
  │
  └── stash@{0}

git stash pop

Стало:

feature
  │
  └── изменения восстановлены
```

---

# 6. `pop` vs `apply`

Это важное различие.

### `git stash pop`

Применяет stash и **удаляет его**, если применение прошло успешно:

```bash
git stash pop
```

### `git stash apply`

Применяет stash, но **оставляет его**:

```bash
git stash apply
```

Схема:

```text
pop:

stash
  │
  ├── apply
  └── delete stash


apply:

stash
  │
  └── apply
       │
       └── stash остаётся
```

Поэтому `apply` удобнее, если ты хочешь сохранить stash как резервную копию.

---

# 7. Применить конкретный Stash

Например:

```bash
git stash list
```

Получили:

```text
stash@{0}: WIP authentication
stash@{1}: WIP payment
stash@{2}: WIP logging
```

Можно применить второй:

```bash
git stash apply stash@{1}
```

При этом:

```text
stash@{1}
```

останется в списке.

Можно удалить его отдельно:

```bash
git stash drop stash@{1}
```

---

# 8. Удаление Stash

Удалить конкретный:

```bash
git stash drop stash@{1}
```

Удалить все:

```bash
git stash clear
```

⚠️ `git stash clear` удаляет весь stash-list, поэтому использовать его нужно осторожно.

---

# 9. Типичный рабочий сценарий

Допустим:

```text
feature/login
```

Ты работаешь:

```bash
# изменяешь код

git status
```

Получаешь:

```text
modified: app/auth.py
modified: tests/test_auth.py
```

Но приходит срочная задача.

Сохраняешь:

```bash
git stash push -m "WIP: login"
```

Переключаешься:

```bash
git switch main
```

Исправляешь проблему:

```bash
# исправление

git add .
git commit -m "Fix production bug"
git push
```

Возвращаешься:

```bash
git switch feature/login
```

Смотришь stash:

```bash
git stash list
```

Восстанавливаешь:

```bash
git stash pop
```

И продолжаешь работу.

---

# 10. Stash и новые файлы

Обычный:

```bash
git stash
```

не всегда включает **untracked files**.

Например:

```text
git status

modified: app.py
?? new_service.py
```

Если нужно сохранить и неотслеживаемые файлы:

```bash
git stash -u
```

или:

```bash
git stash --include-untracked
```

Тогда в stash попадут и untracked-файлы.

---

# 11. Ignored files

Есть ещё:

```bash
git stash -a
```

или:

```bash
git stash --all
```

Он позволяет включить в stash также **ignored files**.

Например:

```text
.gitignore
```

может исключать:

```text
.env
__pycache__/
*.log
```

`git stash -a` может сохранить и такие файлы.

⚠️ Поэтому использовать `--all` стоит осознанно.

---

# 12. Stash только отдельных изменений

Можно сохранить не всё:

```bash
git stash push -p
```

`-p` — interactive patch.

Git будет спрашивать, какие изменения включить в stash.

Например:

```text
Stash this hunk [y,n,q,a,d,s,e,?]?
```

Можно выбрать только часть изменений.

Это полезно, когда один файл содержит несколько независимых изменений.

---

# 13. Stash и staged changes

Допустим:

```text
Working Directory
    │
    ├── изменение A
    │
Staging Area
    │
    └── изменение B
```

Обычный stash сохраняет изменения обоих состояний.

При восстановлении Git старается восстановить соответствующее состояние.

Для специальных случаев существуют дополнительные опции, например:

```bash
git stash --keep-index
```

Она позволяет сохранить изменения, но оставить staged-состояние нетронутым.

---

# 14. `git stash branch`

Интересная команда:

```bash
git stash branch new-feature
```

Она создаёт новую ветку на основе commit, на котором был создан stash, и пытается применить туда stash.

Упрощённо:

```text
stash
  │
  ▼
new-feature
  │
  └── восстановленные изменения
```

Это может быть полезно, если изменения были сделаны не в той ветке.

---

# 15. Что происходит под капотом

Stash — это не просто «папка с изменениями».

Git создаёт специальные объекты, связанные со snapshot состояния рабочего дерева и, при необходимости, staging area.

Для понимания собеседования достаточно следующей модели:

```text
Working Directory
        │
        ▼
     git stash
        │
        ▼
Git objects / stash reference
        │
        ▼
stash@{0}
```

Stash хранится внутри Git-репозитория, а не в каком-то отдельном внешнем файле.

Поэтому:

```bash
git stash list
```

может показать сохранённые состояния даже после переключения веток.

---

# 16. Stash не является Commit в обычном смысле workflow

Технически stash использует Git commit objects, но для разработчика важно другое:

```text
Commit
    ↓
часть нормальной истории проекта

Stash
    ↓
временное сохранение незавершённой работы
```

Поэтому не стоит использовать stash как постоянную замену commit.

Если работа закончена:

```bash
git add .
git commit -m "Add authentication"
```

Если работа временная:

```bash
git stash
```

# 17. Stash и Commit — сравнение

|                                          | Stash                     | Commit                               |
| ---------------------------------------- | ------------------------- | ------------------------------------ |
| Назначение                               | Временно убрать изменения | Сохранить завершённую единицу работы |
| Попадает в обычную историю ветки         | ❌                         | ✅                                    |
| Можно дать сообщение                     | ✅                         | ✅                                    |
| Можно восстановить                       | ✅                         | Через историю                        |
| Подходит для завершённой feature         | ❌                         | ✅                                    |
| Подходит для временной работы            | ✅                         | Обычно нет                           |
| Можно отправить через обычный `git push` | ❌                         | ✅                                    |

# 18. Stash и конфликт

При восстановлении stash тоже может возникнуть конфликт.

Например:

```bash
git stash pop
```

Git пытается применить старые изменения к уже изменившемуся коду.

Если Git не может их объединить:

```text
CONFLICT (content): Merge conflict in app.py
```

Дальше процесс похож на обычный конфликт:

```bash
git status
```

Исправляем файлы:

```bash
git add .
```

После этого **не нужно автоматически делать `git merge --continue`** — stash pop не запускает обычный merge workflow.

После разрешения конфликта изменения просто находятся в рабочем дереве и могут быть сохранены обычным commit.

---

# 19. Что происходит со Stash при конфликте `pop`

Важный нюанс:

если `git stash pop` не смог полностью применить изменения из-за конфликта, Git обычно **не удаляет stash автоматически**.

Поэтому можно посмотреть:

```bash
git stash list
```

и при необходимости повторно работать с этой записью.

Это одна из причин, почему `apply` иногда удобнее `pop`: stash гарантированно остаётся до явного удаления.

# 20. Практический workflow

Хороший базовый сценарий:

```text
Работаю
   │
   ▼
незакоммиченные изменения
   │
   ├── работа готова ──────► commit
   │
   └── нужно временно уйти
              │
              ▼
            stash
              │
              ▼
        другая задача
              │
              ▼
        возвращаемся
              │
              ▼
        stash pop/apply
              │
              ▼
          продолжаем
```

# 21. Основные команды

| Команда                       | Назначение                        |
| ----------------------------- | --------------------------------- |
| `git stash`                   | Сохранить текущие изменения       |
| `git stash push -m "message"` | Сохранить с описанием             |
| `git stash -u`                | Сохранить также untracked files   |
| `git stash -a`                | Включить также ignored files      |
| `git stash list`              | Показать stash                    |
| `git stash pop`               | Применить последний и удалить его |
| `git stash apply`             | Применить, но оставить stash      |
| `git stash apply stash@{1}`   | Применить конкретный stash        |
| `git stash drop stash@{1}`    | Удалить конкретный stash          |
| `git stash clear`             | Удалить все stash                 |
| `git stash -p`                | Выбрать отдельные изменения       |
| `git stash branch <name>`     | Создать ветку и применить stash   |

## 🎤 Вопросы на собеседовании

### Что такое `git stash`?

> Механизм временного сохранения незакоммиченных изменений, чтобы очистить рабочую директорию и продолжить работу в другом контексте.

### Зачем нужен stash?

> Например, когда я работаю над feature, но мне нужно срочно переключиться на другую ветку, а текущие изменения ещё нельзя коммитить.

### Чем `stash pop` отличается от `stash apply`?

> `pop` применяет stash и удаляет его при успешном применении. `apply` применяет stash, но оставляет его.

### Как посмотреть stash?

```bash
git stash list
```

### Как применить конкретный stash?

```bash
git stash apply stash@{1}
```

### Как сохранить untracked files?

```bash
git stash -u
```

### Как удалить stash?

```bash
git stash drop stash@{0}
```

### Как удалить все stash?

```bash
git stash clear
```

### Stash — это commit?

> В пользовательском workflow stash не является обычным commit истории ветки. Это временное хранилище незакоммиченных изменений, хотя технически Git использует commit objects для представления stash.

### Что делать, если при `git stash pop` возник конфликт?

> Посмотреть `git status`, вручную разрешить конфликт, добавить исправленные файлы через `git add`, а затем при необходимости сохранить результат обычным commit. Если stash не был удалён из-за конфликта, он остаётся доступным в `git stash list`.
