# 🎯 HEAD в Git

## 🎤 Короткий ответ

**HEAD** — это специальная ссылка в Git, которая указывает на **текущее положение пользователя в истории репозитория**, обычно на текущую ветку.

В обычном состоянии:

```text
HEAD → main → commit C
```

Когда я переключаюсь на другую ветку:

```bash
git switch feature/auth
```

HEAD начинает указывать на неё:

```text
HEAD → feature/auth → commit D
```

То есть **HEAD показывает, где я сейчас нахожусь в Git**.

---

## 🗣️ Ответ на собеседовании

HEAD — это специальная ссылка, которая указывает на текущее состояние Git. Обычно HEAD указывает на текущую локальную ветку, а ветка уже указывает на конкретный commit.

Например:

```text
HEAD → main → C
```

Это означает, что я нахожусь на ветке `main`, которая указывает на коммит `C`.

Если я переключусь на `feature`:

```bash
git switch feature
```

получится:

```text
HEAD → feature → D
```

При создании нового коммита Git перемещает указатель текущей ветки на новый commit, а HEAD продолжает указывать на эту ветку.

Также существует состояние **detached HEAD**, когда HEAD указывает непосредственно на commit, а не на ветку.

# 📚 Разбор поглубже

## 1. Что такое HEAD

В Git `HEAD` — это специальная **symbolic reference (символическая ссылка)**.

В обычной ситуации она указывает на текущую локальную ветку:

```text
HEAD
 ↓
main
 ↓
C
```

Где:

* `HEAD` — текущее положение;
* `main` — текущая ветка;
* `C` — последний commit этой ветки.

Поэтому можно запомнить:

> **HEAD → текущая ветка → текущий commit**

---

# 2. Как посмотреть HEAD

Команда:

```bash
git status
```

может показать:

```text
On branch main
```

Можно посмотреть содержимое HEAD:

```bash
cat .git/HEAD
```

В обычном состоянии получится примерно:

```text
ref: refs/heads/main
```

Это означает:

```text
HEAD
 ↓
refs/heads/main
 ↓
commit
```

---

# 3. HEAD и новый commit

Допустим, история выглядит так:

```text
A → B → C
```

И мы находимся на `main`:

```text
HEAD
 ↓
main
 ↓
C
```

Создаём новый commit:

```bash
git commit -m "Add feature"
```

Получаем:

```text
A → B → C → D
             ↑
            main
             ↑
            HEAD
```

То есть перемещается **указатель ветки**, а HEAD продолжает указывать на текущую ветку.

Это важный момент:

> HEAD сам по себе обычно не перемещается по каждому commit независимо — он указывает на текущую ветку, а ветка перемещается на новый commit.

---

# 4. HEAD при переключении веток

Есть две ветки:

```text
A → B → C
         ↑
        main

     D → E
         ↑
      feature
```

Если сейчас:

```text
HEAD → main
```

выполняем:

```bash
git switch feature
```

Теперь:

```text
HEAD → feature
          ↓
          E
```

HEAD переключился на другую ветку.

---

# 5. HEAD и `HEAD~1`

Git позволяет использовать относительные ссылки.

Например:

```bash
git show HEAD
```

означает:

> показать текущий commit.

А:

```bash
git show HEAD~1
```

означает:

> показать родительский commit текущего commit.

Если история:

```text
A → B → C → D
            ↑
           HEAD
```

то:

```text
HEAD     → D
HEAD~1   → C
HEAD~2   → B
HEAD~3   → A
```

---

# 6. `HEAD^`

Также можно использовать `^`.

Для обычной линейной истории:

```text
A → B → C
        ↑
       HEAD
```

получим:

```text
HEAD^  → B
HEAD^^ → A
```

То есть:

```bash
git show HEAD^
```

показывает родительский commit.

---

# 7. `HEAD~` и `HEAD^`

В простой линейной истории они часто дают одинаковый результат:

```text
HEAD~1 ≈ HEAD^
```

Например:

```text
A → B → C
        ↑
       HEAD
```

Оба указывают на `B`.

Но различие становится важным при **merge commit**, потому что у merge commit несколько родителей.

Например:

```text
       B ── C
      /      \
A ─────────── M
              ↑
             HEAD
```

`M` имеет двух родителей.

Поэтому:

```text
HEAD^1 → первый родитель
HEAD^2 → второй родитель
```

А `~` идёт по цепочке первого родителя:

```text
HEAD~1
HEAD~2
HEAD~3
```

---

# 8. Detached HEAD

Обычное состояние:

```text
HEAD → main → C
```

Но можно переключиться непосредственно на commit:

```bash
git switch --detach C
```

Получится:

```text
HEAD
 ↓
 C
```

HEAD больше **не указывает на ветку**.

Это называется:

> **detached HEAD**

Git сообщает примерно:

```text
You are in 'detached HEAD' state
```

---

# 9. Зачем нужен Detached HEAD

Это удобно, например, чтобы:

* посмотреть старую версию проекта;
* протестировать старый commit;
* временно запустить код в прошлом состоянии;
* исследовать историю.

Например:

```bash
git switch --detach HEAD~2
```

Теперь рабочая директория соответствует состоянию проекта два commit назад.

---

# 10. Опасность Detached HEAD

Представим:

```text
A → B → C
         ↑
        main

HEAD → C
```

Переключаемся на `B`:

```text
A → B → C
    ↑
   HEAD
         ↑
        main
```

Создаём новый commit:

```text
A → B → C
    \
     D
     ↑
    HEAD
```

При этом `main` продолжает указывать на `C`.

Commit `D` не принадлежит `main`.

Если затем переключиться на другую ветку, commit `D` может стать труднодоступным, если не сохранить на него ссылку.

Если изменения нужно сохранить, обычно создают ветку:

```bash
git switch -c my-branch
```

---

# 11. HEAD и Branch — разные понятия

Это один из важных моментов.

**Branch** — указатель на commit.

**HEAD** — указатель на текущую ветку или непосредственно на commit в detached-состоянии.

Обычная схема:

```text
HEAD
 ↓
main
 ↓
C
```

То есть:

```text
HEAD → branch → commit
```

А не:

```text
HEAD = branch
```

Это разные ссылки.

---

# 12. HEAD и Remote Branch

Например:

```text
HEAD → main → C

origin/main → D
```

Здесь:

* `HEAD` — где находится текущая работа;
* `main` — локальная ветка;
* `origin/main` — remote-tracking reference.

Они могут указывать на разные commits.

Например:

```text
A → B → C → D
         ↑   ↑
        main origin/main
```

или:

```text
A → B → C → D
         ↑
        main

origin/main
     ↑
     B
```

Это нормально: локальная ветка и `origin/main` могут временно находиться на разных состояниях.

---

# 13. HEAD при Merge

Допустим:

```text
       B ── C
      /      \
A ── D ────── M
               ↑
              main
               ↑
              HEAD
```

После merge:

```text
HEAD → main → M
```

`M` — merge commit.

У него обычно два родителя.

Поэтому:

```bash
git show HEAD^1
```

и:

```bash
git show HEAD^2
```

могут показать разные commits.

---

# 14. HEAD при Rebase

При rebase HEAD также перемещается по истории в процессе выполнения операции.

Упрощённо:

```text
До:

main:    A → B → C
              \
feature:       D → E
```

После rebase:

```text
main:    A → B → C
                   \
feature:            D' → E'
                         ↑
                        HEAD
```

Коммиты `D'` и `E'` — новые commits с новыми SHA.

В обычном завершённом состоянии:

```text
HEAD → feature → E'
```

---

# 15. HEAD и команды Git

HEAD используется во множестве команд:

```bash
git show HEAD
```

Текущий commit.

```bash
git diff HEAD
```

Сравнить рабочую директорию с текущим commit.

```bash
git reset --soft HEAD~1
```

Переместить текущую ветку на один commit назад, сохранив изменения в staging area.

```bash
git restore --source=HEAD file.py
```

Восстановить файл из состояния текущего commit.

```bash
git switch --detach HEAD~2
```

Перейти к состоянию двух commits назад.

---

# 16. Важная модель Git

Полезно держать в голове такую структуру:

```text
                         Remote Repository
                               │
                               │ fetch/push
                               ▼
Local Repository
│
├── Branch
│    └── main ───────→ Commit C
│
└── HEAD
     └──→ main
```

В обычном состоянии:

```text
HEAD → main → Commit
```

Это одна из самых полезных моделей для понимания Git.

## 🎤 Вопросы на собеседовании

### Что такое HEAD в Git?

HEAD — специальная ссылка, указывающая на текущее положение в Git. Обычно она указывает на текущую локальную ветку.

### Куда указывает HEAD?

В обычном состоянии:

```text
HEAD → current branch → commit
```

В detached HEAD:

```text
HEAD → commit
```

### Что такое Detached HEAD?

Состояние, при котором HEAD указывает непосредственно на commit, а не на локальную ветку.

### Что означает `HEAD~1`?

Родительский commit текущего commit по первой родительской цепочке.

### Что означает `HEAD^`?

Первый родитель текущего commit. Для обычной линейной истории `HEAD^` и `HEAD~1` эквивалентны.

### Чем HEAD отличается от branch?

Branch — ссылка на commit.

HEAD — ссылка на текущую ветку либо непосредственно на commit в detached-состоянии.

### Что происходит с HEAD после `git switch feature`?

HEAD начинает указывать на ветку `feature`.

```text
HEAD → feature
```

### Что происходит с HEAD после нового commit?

В обычном состоянии HEAD продолжает указывать на текущую ветку, а сама ветка перемещается на новый commit:

```text
HEAD → main → new_commit
```

### Что такое `HEAD^1` и `HEAD^2`?

Для merge commit это ссылки на первого и второго родителей соответственно.
