# Flake8 🔍

## 🎤 Короткий ответ

**Flake8** — инструмент статического анализа Python-кода, который проверяет код на **стиль и потенциальные ошибки** без запуска программы.

Он объединяет несколько проверок, в частности **PyFlakes** и **pycodestyle**, и использует систему плагинов для расширения возможностей.

> **Flake8 = linting Python-кода → ошибки + стиль + нарушения правил.**

---

## 🎯 Формула для собеседования

**Python-код → Flake8 → статический анализ → диагностики → исправление**

```text
Python Code
     ↓
   Flake8
     ↓
 ┌───────────────┐
 │ Style         │
 │ Errors        │
 │ Imports       │
 │ Plugins       │
 └───────────────┘
```

# 1. Что такое Flake8

Flake8 — это **linter для Python**.

Он анализирует исходный код, не выполняя приложение, и сообщает о проблемах.

Например:

```python
import os

def hello():
    print("Hello")
```

`os` нигде не используется.

Flake8 может сообщить:

```text
F401 'os' imported but unused
```

---

# 2. Что проверяет Flake8

Основные направления:

* стиль кода;
* синтаксические проблемы;
* неиспользуемые импорты;
* неиспользуемые переменные;
* некоторые потенциальные ошибки;
* нарушения выбранных правил.

Например:

```python
x=10
```

может вызвать предупреждение о форматировании.

А:

```python
import os
```

если `os` не используется — предупреждение о неиспользуемом импорте.

---

# 3. Из чего состоит Flake8

Название Flake8 связано с несколькими инструментами:

```text
Flake8
 ├── PyFlakes
 ├── pycodestyle
 └── plugins
```

### PyFlakes

Ищет определённые программные ошибки и проблемы вроде:

* неиспользуемых импортов;
* неиспользуемых локальных переменных;
* неопределённых имён.

### pycodestyle

Проверяет соответствие кода правилам стиля Python, связанным с PEP 8.

### Plugins

Flake8 можно расширять дополнительными плагинами.

# 7. Коды ошибок

Примеры:

| Код | Смысл                          |
| --- | ------------------------------ |
| `E` | ошибки стиля pycodestyle       |
| `W` | предупреждения стиля           |
| `F` | проверки PyFlakes              |
| `C` | правила некоторых плагинов     |
| `B` | например, bugbear через plugin |

Например:

```text
F401
```

означает проблему с неиспользуемым импортом.

---

# 8. Flake8 и PEP 8

Важно не путать:

**PEP 8** — рекомендации по стилю Python.

**Flake8** — инструмент, который автоматически проверяет часть таких правил.

```text
PEP 8
  ↓
правила / рекомендации
  ↓
Flake8
  ↓
автоматическая проверка
```

---

# 9. Flake8 — это не formatter

Это важное отличие.

Flake8:

```text
найти проблему
       ↓
сообщить
```

Он не предназначен для того, чтобы автоматически отформатировать весь код.

Например:

```python
x=10
```

Flake8 может сказать:

```text
E225 missing whitespace around operator
```

Но форматирование обычно выполняет отдельный инструмент:

```text
Black
```

или:

```text
Ruff format
```

# 10. Flake8 vs Black

|                               | Flake8 | Black          |
| ----------------------------- | ------ | -------------- |
| Linting                       | ✅      | ❌              |
| Поиск потенциальных ошибок    | ✅      | ❌              |
| Проверка стиля                | ✅      | ❌              |
| Автоматическое форматирование | ❌      | ✅              |
| Основная задача               | анализ | форматирование |

Типичная связка:

```text
Flake8 → проверяет
Black  → форматирует
```

# 11. Flake8 vs Ruff

Это особенно важно для современного Python Backend.

### Flake8

```text
Flake8
 ├── PyFlakes
 ├── pycodestyle
 └── plugins
```

### Ruff

```text
Ruff
 ├── множество lint-правил
 ├── auto-fix
 ├── import sorting
 └── formatter
```

Ruff был создан как очень быстрый инструмент и может заменить многие сценарии, для которых раньше использовали несколько отдельных инструментов.

Поэтому в новом проекте можно встретить:

```text
Ruff
```

вместо:

```text
Flake8 + isort + Black
```

Но **Flake8 всё ещё встречается в существующих проектах** и его полезно знать для собеседования.

# 12. Flake8 vs MyPy

### Flake8

Проверяет:

```text
style
imports
potential errors
lint rules
```

### MyPy

Проверяет:

```text
type annotations
type compatibility
type inference
```

Например:

```python
def add(a: int, b: int) -> int:
    return a + b
```

MyPy может обнаружить ошибку типов:

```python
result: int = "hello"
```

Flake8 и MyPy решают разные задачи.

---

# 13. Flake8 vs pytest

`pytest` запускает код и проверяет его поведение.

Flake8 — анализирует исходный код без запуска приложения.

```text
Flake8
   ↓
статический анализ

pytest
   ↓
выполнение тестов
```

Поэтому в CI они могут работать вместе:

```text
Flake8
  ↓
MyPy
  ↓
Pytest
```

# 14. Конфигурация

Flake8 можно конфигурировать, например, через:

```text
.flake8
```

или другие поддерживаемые конфигурационные механизмы проекта.

Пример:

```python
[flake8]
max-line-length = 88
exclude = .git,__pycache__,.venv
```

Здесь:

* `max-line-length` — максимальная длина строки;
* `exclude` — исключения.

---

# 15. Игнорирование конкретного правила

Иногда отдельное правило сознательно отключают.

Например:

```python
flake8 --ignore E501 .
```

Это означает:

> Не считать `E501` ошибкой.

Но в командном проекте лучше фиксировать такие настройки в конфигурации, а не передавать вручную при каждом запуске.

# 16. Flake8 и плагины

Одна из сильных сторон Flake8 — система расширений.

Например, можно добавить плагины для:

* bugbear;
* pytest;
* comprehensions;
* naming;
* других специфичных правил.

Получается:

```text
Flake8
   │
   ├── базовые проверки
```

# 17. Flake8 в CI

Типичный pipeline старого/классического Python-проекта:

```text
Git Push
    ↓
CI
    ↓
Flake8
    ↓
Black --check
    ↓
MyPy
    ↓
Pytest
    ↓
Build
```

Если Flake8 обнаружил нарушение:

```text
Flake8 → FAILED
        ↓
CI → FAILED
```

Merge может быть запрещён до исправления.

# 18. Flake8 + pre-commit

Flake8 можно запускать автоматически перед commit:

```text
git commit
    ↓
pre-commit
    ↓
Flake8
    ↓
проверка
    ↓
commit
```

Так разработчик обнаруживает проблемы ещё до отправки кода в remote.

# 19. Flake8 и Code Review

Без линтера reviewer может вручную замечать:

```text
«Неиспользуемый import»
«Нарушен стиль»
«Слишком длинная строка»
```

Flake8 автоматизирует часть таких замечаний:

```text
Code
 ↓
Flake8
 ↓
diagnostics
 ↓
исправление
 ↓
Code Review
```

Это позволяет reviewer'у больше сосредоточиться на:

* бизнес-логике;
* архитектуре;
* безопасности;
* производительности;
* корректности решения.

# 🎤 Вопросы на собеседовании

### Что такое Flake8?

> Flake8 — инструмент статического анализа Python-кода, который проверяет стиль и выявляет определённые потенциальные ошибки без запуска программы.

### Что входит в Flake8?

> Flake8 объединяет проверки PyFlakes и pycodestyle и поддерживает систему плагинов для дополнительных правил.

### Flake8 — formatter?

> Нет. Flake8 — linter. Для форматирования используют Black, Ruff Formatter и другие инструменты.

### Что означает `F401`?

> Обычно это неиспользуемый импорт.

### Чем Flake8 отличается от Black?

> Flake8 анализирует код и сообщает о нарушениях, а Black автоматически форматирует код.

### Чем Flake8 отличается от Ruff?

> Оба могут выполнять linting Python-кода, но Ruff значительно быстрее и объединяет большое количество возможностей, включая auto-fix, сортировку импортов и форматирование.

### Может ли Flake8 найти логическую ошибку?

> Не любую. Он выполняет статический анализ по своим правилам и не заменяет тестирование бизнес-логики.

### Зачем Flake8 в CI?

> Чтобы автоматически проверять качество и стиль кода до merge.
