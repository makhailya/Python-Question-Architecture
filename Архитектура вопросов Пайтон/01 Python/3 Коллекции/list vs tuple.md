# list vs tuple в Python

## 🎯 Ответ на собеседовании

> **`list` и `tuple` — упорядоченные последовательности, поддерживающие индексацию и срезы. Главное отличие в изменяемости: `list` — изменяемый, а `tuple` — неизменяемый.**
>
> `list` используют, когда коллекцию нужно изменять: добавлять, удалять или заменять элементы.
>
> `tuple` используют для данных, которые после создания не должны изменяться. Кроме того, `tuple` может быть ключом словаря или элементом `set`, если все его элементы хешируемые.
>
> `tuple` обычно занимает меньше памяти и может быть немного быстрее `list`, но это не главная причина выбора — в первую очередь выбор зависит от семантики данных.

---

# 📌 Что такое `list`

`list` — это **изменяемая упорядоченная коллекция** объектов.

```python
numbers = [1, 2, 3]
```

Можно:

```python
numbers.append(4)
numbers[0] = 100
numbers.pop()
```

Результат:

```python
[100, 2, 3]
```

### Основные свойства

* ✅ изменяемый (`mutable`)
* ✅ упорядоченный
* ✅ поддерживает индексацию
* ✅ поддерживает срезы
* ✅ может содержать элементы разных типов
* ❌ не является хешируемым
* ❌ нельзя использовать как ключ `dict`

---

# 📌 Что такое `tuple`

`tuple` — это **неизменяемая упорядоченная последовательность**.

```python
numbers = (1, 2, 3)
```

После создания нельзя изменить элементы:

```python
numbers[0] = 100
```

Получим:

```text
TypeError
```

### Основные свойства

* ❌ неизменяемый (`immutable`)
* ✅ упорядоченный
* ✅ поддерживает индексацию
* ✅ поддерживает срезы
* ✅ может содержать элементы разных типов
* ✅ может быть хешируемым, если все его элементы хешируемые
* ✅ может использоваться как ключ `dict`
* ✅ может быть элементом `set`

---

# 🆚 Главное отличие

| Характеристика  | `list` | `tuple` |
| --------------- | ------ | ------- |
| Изменяемость    | ✅ Да   | ❌ Нет   |
| Упорядоченность | ✅ Да   | ✅ Да    |
| Индексация      | ✅ Да   | ✅ Да    |
| Срезы           | ✅ Да   | ✅ Да    |
| Дубли           | ✅ Да   | ✅ Да    |
| Разные типы     | ✅ Да   | ✅ Да    |
| `append()`      | ✅      | ❌       |
| `remove()`      | ✅      | ❌       |
| `pop()`         | ✅      | ❌       |
| Хешируемость    | ❌      | ✅*      |
| Ключ `dict`     | ❌      | ✅*      |
| Элемент `set`   | ❌      | ✅*      |

`*` — только если все элементы `tuple` сами являются хешируемыми.

---

# 🔧 Методы

У `list` методов значительно больше:

```python
items.append(10)
items.extend([20, 30])
items.insert(0, 5)
items.remove(10)
items.pop()
items.clear()
items.sort()
items.reverse()
```

У `tuple` основных методов всего два:

```python
items.count(10)
items.index(10)
```

Потому что изменять `tuple` нельзя.

---

# 🔢 Индексация

Оба типа поддерживают индексацию:

```python
items = [10, 20, 30]
items[0]  # 10
```

```python
items = (10, 20, 30)
items[0]  # 10
```

Также работают отрицательные индексы:

```python
items[-1]
```

И срезы:

```python
items[1:]
items[:2]
items[::-1]
```

---

# ⚠️ Важный нюанс: `tuple` может содержать изменяемые объекты

Неизменяемость `tuple` означает, что **нельзя изменить его ссылки на элементы**.

Но внутри него может находиться изменяемый объект:

```python
data = ([1, 2], 3)

data[0].append(4)

print(data)
# ([1, 2, 4], 3)
```

Сам `tuple` не изменился — ссылка на список осталась той же.

Мы изменили **вложенный `list`**.

Но так нельзя:

```python
data[0] = [10, 20]
```

Получим:

```text
TypeError
```

---

# 🔑 Почему `tuple` может быть ключом словаря?

`dict` требует, чтобы ключ был **хешируемым**.

`list` изменяемый → его хеш может условно меняться → поэтому он не хешируемый:

```python
data = {
    [1, 2]: "value"
}
```

❌ `TypeError: unhashable type: 'list'`

`tuple` неизменяемый и состоящий из хешируемых элементов → может быть ключом:

```python
data = {
    (1, 2): "value"
}
```

✅ Работает.

Но:

```python
data = {
    ([1, 2], 3): "value"
}
```

❌ Не работает, потому что внутри `tuple` есть `list`.

---

# 📦 Когда использовать `list`

Используй `list`, когда коллекция **предполагает изменения**.

Например:

```python
users = []

users.append("Ilya")
users.append("Alex")
```

Другие примеры:

* список пользователей;
* список товаров;
* результаты запросов;
* очередь задач;
* данные, которые нужно сортировать/изменять.

---

# 📦 Когда использовать `tuple`

Используй `tuple`, когда данные представляют собой **фиксированную структуру**.

Например:

```python
point = (10, 20)
```

Координаты точки.

Или:

```python
user = ("Ilya", 31, "Python Developer")
```

Также `tuple` часто используют для:

* фиксированных наборов значений;
* возврата нескольких значений из функции;
* ключей словаря;
* элементов `set`;
* данных, которые не должны случайно измениться.

---

# 🔄 Возврат нескольких значений

Функция:

```python
def get_user():
    return "Ilya", 31
```

Фактически возвращает `tuple`:

```python
result = get_user()

print(result)
# ("Ilya", 31)

print(type(result))
# <class 'tuple'>
```

Можно сразу распаковать:

```python
name, age = get_user()
```

---

# 💾 Память и производительность

`tuple` обычно:

* занимает меньше памяти;
* создаётся немного быстрее;
* быстрее обходится в некоторых сценариях.

Но **не стоит выбирать `tuple` только ради скорости**.

Главный критерий:

> **Если данные должны изменяться → `list`.
> Если данные должны оставаться неизменными → `tuple`.**

Разница в производительности обычно вторична.

---

# ⚠️ Синтаксический нюанс

Пустой `tuple`:

```python
()
```

Но tuple из одного элемента требует **запятую**:

```python
(10,)
```

А это обычное число в скобках:

```python
(10)
```

Проверка:

```python
type((10))
# int

type((10,))
# tuple
```

То есть `tuple` определяется не столько скобками, сколько **запятыми**.

```text
list

 ↓

```

```text
tuple
 ↓

 ↓

 ↓

```

### Главное:

> **`list` — изменяемая последовательность.**
>
> **`tuple` — неизменяемая последовательность.**

И при выборе между ними сначала думай не о производительности, а о **смысле данных**:
**«Эта коллекция должна изменяться или нет?»**
