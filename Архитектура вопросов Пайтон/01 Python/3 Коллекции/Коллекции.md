# 🧩 Коллекции Python

## 🎤 Короткий ответ

Коллекции в Python — это структуры данных, предназначенные для хранения **нескольких объектов**.

Основные встроенные коллекции:

* [[list]] — упорядоченная изменяемая последовательность;
* [[tuple]] — упорядоченная неизменяемая последовательность;
* [[set]] — изменяемая коллекция уникальных хешируемых элементов;
* [[dict]] — изменяемое отображение `ключ → значение`.

Выбор коллекции зависит от задачи: нужен ли порядок, возможность изменения, уникальность элементов и быстрый доступ по ключу.

---

## 🗣️ Ответ на собеседовании

В Python основными встроенными коллекциями являются [[list]], [[tuple]], [[set]] и [[dict]].

[[list]] используется, когда нужна упорядоченная изменяемая последовательность и доступ по индексу.

[[tuple]] похож на [[list]], но является неизменяемым. Его можно использовать, например, для представления фиксированного набора значений.

[[set]] хранит уникальные элементы и основан на хеш-таблице, поэтому проверка принадлежности в среднем выполняется за `O(1)`.

[[dict]] хранит пары `ключ → значение`. Ключ должен быть хешируемым, а доступ к значению по ключу в среднем также выполняется за `O(1)`.

При выборе коллекции я смотрю прежде всего на характер операции: нужен ли индексированный доступ, изменение данных, уникальность элементов или поиск по ключу.

# 📚 Разбор поглубже

## 1. Что такое коллекция

Коллекция — объект, который позволяет хранить и организовывать **несколько элементов**.

Например:

```python
numbers = [10, 20, 30]

user = {
    "name": "Ilya",
    "age": 31,
}
```

В первом случае мы храним последовательность чисел.

Во втором — связанные между собой значения по ключам.

Важно различать:

```text
элемент коллекции ≠ сама коллекция
```

Например:

```python
numbers = [10, 20, 30]
```

Здесь `numbers` — объект `list`, а `10`, `20`, `30` — отдельные объекты внутри него.

# 2. Основные коллекции

| Тип     | Порядок | Изменяемый | Уникальность    | Доступ      |
| ------- | ------- | ---------- | --------------- | ----------- |
| `list`  | Да      | Да         | Нет             | По индексу  |
| `tuple` | Да      | Нет        | Нет             | По индексу  |
| `set`   | Нет     | Да         | Да              | По элементу |
| `dict`  | Да*     | Да         | Ключи уникальны | По ключу    |

* В современных версиях Python `dict` сохраняет порядок добавления элементов.

---

# 3. `list`

`list` — упорядоченная изменяемая последовательность.

```python
numbers = [10, 20, 30]
```

Можно обращаться по индексу:

```python
numbers[0]
# 10

numbers[1]
# 20
```

Можно изменять элементы:

```python
numbers[0] = 100
```

Можно добавлять:

```python
numbers.append(40)
```

И удалять:

```python
numbers.pop()
```

### Главная идея

```text
list
│
├── порядок сохраняется
├── элементы могут повторяться
├── можно изменять
└── доступ по индексу
```

---

# 4. `tuple`

`tuple` — упорядоченная **неизменяемая** последовательность.

```python
point = (10, 20)
```

Доступ по индексу работает так же:

```python
point[0]
# 10
```

Но изменить элемент нельзя:

```python
point[0] = 100
```

Это приведёт к `TypeError`.

### Зачем нужен `tuple`

Он полезен, когда набор значений должен оставаться неизменным:

```python
point = (10, 20)
```

Также `tuple` может использоваться как ключ словаря, если все его элементы хешируемы:

```python
locations = {
    (56.84, 60.61): "Екатеринбург",
}
```

---

# 5. `set`

`set` — коллекция уникальных элементов.

```python
numbers = {1, 2, 3, 3, 3}

print(numbers)
```

Результат:

```python
{1, 2, 3}
```

Дубликаты не сохраняются.

Главная особенность `set` — использование **хеширования**.

Например:

```python
numbers = {10, 20, 30}

20 in numbers
```

В среднем:

```text
O(1)
```

Это делает `set` удобным для быстрых проверок принадлежности.

### Операции множеств

Объединение:

```python
a | b
```

Пересечение:

```python
a & b
```

Разность:

```python
a - b
```

Симметрическая разность:

```python
a ^ b
```

---

# 6. `dict`

`dict` хранит данные в формате:

```text
ключ → значение
```

Например:

```python
user = {
    "name": "Ilya",
    "age": 31,
}
```

Получение значения:

```python
user["name"]
```

Результат:

```text
Ilya
```

Ключи должны быть **хешируемыми**:

```python
user = {
    "name": "Ilya",
    1: "one",
    (10, 20): "point",
}
```

А `list` ключом быть не может:

```python
data = {
    [1, 2, 3]: "value"
}
```

Потому что `list` — изменяемый и нехешируемый объект.

---

# 7. Почему `dict` и `set` быстрые

И `dict`, и `set` используют **хеш-таблицы**.

Упрощённо:

```text
ключ
  │
  ▼
hash(key)
  │
  ▼
индекс в таблице
  │
  ▼
поиск элемента
```

Поэтому в среднем:

```text
dict[key]     → O(1)
key in dict   → O(1)

value in set  → O(1)
```

Но `O(1)` здесь является **средней сложностью**.

В худшем случае операции могут деградировать до `O(n)`.

Внутреннее устройство хеш-таблиц — отдельная тема.

---

# 8. Изменяемость коллекций

Коллекции делятся на mutable и immutable.

### Mutable

Можно изменить существующий объект:

```text
list
set
dict
```

Например:

```python
numbers = [1, 2, 3]

numbers.append(4)
```

Объект списка остался тем же, но его содержимое изменилось.

### Immutable

После создания изменить объект нельзя:

```text
tuple
```

```python
point = (10, 20)
```

Чтобы получить другое значение, создаётся новый объект:

```python
point = (100, 200)
```

# 9. Коллекции и вложенность

Коллекции можно вкладывать друг в друга.

Например:

```python
users = [
    {
        "name": "Ilya",
        "age": 31,
    },
    {
        "name": "Ivan",
        "age": 25,
    },
]
```

Здесь:

```text
list
└── dict
    ├── str
    └── int
```

Это очень распространённая структура в backend-разработке.

Например, JSON-данные после обработки API часто представлены комбинацией:

```text
dict
├── str
├── int
├── list
│   └── dict
└── None
```

# 10. Сложность основных операций

Важно не просто заучить таблицу, а понимать **почему** операция имеет такую сложность.

| Коллекция | Операция            |      Средняя сложность |
| --------- | ------------------- | ---------------------: |
| `list`    | `a[i]`              |                 `O(1)` |
| `list`    | `append()`          | `O(1)` амортизированно |
| `list`    | поиск `x in a`      |                 `O(n)` |
| `list`    | `insert()` в начало |                 `O(n)` |
| `list`    | `pop()` с конца     |                 `O(1)` |
| `dict`    | `d[key]`            |                 `O(1)` |
| `dict`    | `key in d`          |                 `O(1)` |
| `set`     | `x in s`            |                 `O(1)` |
| `tuple`   | `a[i]`              |                 `O(1)` |
| `tuple`   | поиск `x in a`      |                 `O(n)` |

Например, поиск в `list` выполняется последовательно:

```text
[10, 20, 30, 40, 50]
  ↑
  проверка
       ↑
       проверка
            ↑
            проверка
```

Поэтому в худшем случае приходится проверить все `n` элементов.

А `dict` и `set` используют хеширование, поэтому обычно позволяют сразу вычислить область поиска.

# 11. Как выбирать коллекцию

Можно мыслить через основную операцию.

### Нужен порядок + индексы

Используем:

```python
list
```

### Нужен фиксированный неизменяемый набор

Используем:

```python
tuple
```

### Нужны уникальные элементы

Используем:

```python
set
```

### Нужен доступ по ключу

Используем:

```python
dict
```

Например:

```python
users = {
    101: "Ilya",
    102: "Ivan",
}
```

Если основная операция:

```python
users[101]
```

то `dict` естественно соответствует задаче.

# 12. Важный момент: `dict` сохраняет порядок

В современных Python порядок добавления элементов в `dict` является частью поведения языка.

```python
user = {
    "name": "Ilya",
    "age": 31,
    "city": "Ekaterinburg",
}
```

При итерации:

```python
for key in user:
    print(key)
```

ключи будут идти в порядке добавления:

```text
name
age
city
```

Но это **не означает**, что `dict` — это список.

Основная модель `dict` всё равно:

```text
ключ → значение
```

а не:

```text
индекс → значение
```

## 🎤 Вопросы на собеседовании

### Какие основные коллекции есть в Python?

`list`, `tuple`, `set` и `dict`.

### Чем `list` отличается от `tuple`?

Оба являются упорядоченными последовательностями и поддерживают доступ по индексу.

Главное различие:

```text
list   → mutable
tuple  → immutable
```

### Чем `set` отличается от `list`?

`set` хранит уникальные элементы и использует хеширование.

`list` допускает дубликаты и обеспечивает индексированный доступ.

### Почему поиск в `set` обычно `O(1)`?

Потому что `set` использует хеш-таблицу и по хешу элемента может определить позицию поиска.

### Почему поиск элемента в `list` — `O(n)`?

Потому что в общем случае Python должен последовательно проверить элементы списка.

### Почему ключом `dict` нельзя сделать `list`?

Потому что ключ должен быть хешируемым, а `list` является изменяемым и нехешируемым.

### Может ли `tuple` быть ключом `dict`?

Да, если все элементы `tuple` сами являются хешируемыми.

### Какие коллекции mutable?

```text
list
set
dict
```

### Какие immutable?

Из основных коллекций:

```text
tuple
```
