# 🎀 Декоратор

🎯 **Ответ на собеседовании:**

**Декоратор** — это функция или другой вызываемый объект, который **принимает функцию и возвращает новую функцию**, добавляя или изменяя её поведение **без изменения исходного кода**.

Пример:

```python
def logger(func):
    def wrapper():
        print("До вызова")
        func()
        print("После вызова")

    return wrapper
```

Использование:

```python
@logger
def hello():
    print("Hello")


hello()
```

Это эквивалентно:

```python
hello = logger(hello)
```

Результат:

```text
До вызова
Hello
После вызова
```

---

# Как работает `@decorator`

Запись:

```python
@logger
def hello():
    print("Hello")
```

Python преобразует примерно в:

```python
def hello():
    print("Hello")

hello = logger(hello)
```

То есть декоратор **заменяет имя исходной функции результатом работы декоратора**.

---

# Зачем нужны декораторы?

Чтобы вынести общую дополнительную логику:

* логирование;
* измерение времени выполнения;
* авторизация;
* проверка прав;
* кеширование;
* валидация;
* retry;
* регистрация функций;
* обработка исключений.

Например:

```python
@auth_required
def get_profile():
    ...
```

Логика авторизации находится в декораторе, а бизнес-логика — в `get_profile()`.

# `wrapper`

Обычно декоратор содержит внутреннюю функцию-обёртку:

```python
def decorator(func):
    def wrapper(*args, **kwargs):
        print("До")
        result = func(*args, **kwargs)
        print("После")
        return result

    return wrapper
```

Использование:

```python
@decorator
def add(a, b):
    return a + b
```

Теперь:

```python
add(2, 3)
```

проходит через:

```text
add()
 ↓
wrapper()
 ↓
логика декоратора
 ↓
original add()
 ↓
результат
```

---

# `*args` и `**kwargs`

Для универсального декоратора обычно используют:

```python
def decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)

    return wrapper
```

Такой `wrapper` может принимать произвольные позиционные и именованные аргументы исходной функции.

---

# `functools.wraps`

Важная деталь на собеседовании.

Если просто обернуть функцию:

```python
def decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)

    return wrapper
```

метаданные исходной функции могут потеряться:

```python
add.__name__
```

будет:

```text
wrapper
```

Поэтому используют:

```python
from functools import wraps


def decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)

    return wrapper
```

Теперь сохраняются важные метаданные исходной функции:

```python
add.__name__
add.__doc__
```

и т. д.

🎯 **На собеседовании `functools.wraps` стоит упомянуть.**

# Декоратор с аргументами

Например:

```python
@retry(3)
def request():
    ...
```

Здесь `retry(3)` — уже не сам декоратор, а **фабрика декораторов**.

Пример:

```python
def retry(times):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for _ in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    pass

        return wrapper

    return decorator
```

Структура:

```text
retry(3)
   ↓
decorator
   ↓
wrapper
   ↓
original function
```

# Декоратор класса

Декорировать можно не только функции:

```python
def add_attribute(cls):
    cls.version = 1
    return cls


@add_attribute
class User:
    pass
```

Теперь:

```python
User.version
# 1
```

Декоратор получил класс и вернул изменённый класс.

---

# Несколько декораторов

Можно использовать несколько декораторов:

```python
@decorator_a
@decorator_b
def func():
    pass
```

Применяются **снизу вверх**:

```python
func = decorator_a(decorator_b(func))
```

То есть сначала:

```text
func
 ↓
decorator_b
 ↓
decorator_a
```

А вызываются они соответственно через внешнюю обёртку `decorator_a`.

---

# Декораторы и замыкания

Декораторы часто используют **closures (замыкания)**.

```python
def decorator(func):
    def wrapper():
        return func()

    return wrapper
```

`wrapper` сохраняет ссылку на `func`, даже после завершения `decorator`.

Поэтому декораторы тесно связаны с:

* функциями как объектами первого класса;
* вложенными функциями;
* замыканиями;
* `*args` / `**kwargs`.

# Декоратор для async-функции

В Backend это особенно важно.

Обычный декоратор:

```python
def decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)

    return wrapper
```

Для `async def` обычно нужен `async wrapper`:

```python
from functools import wraps


def decorator(func):
    @wraps(func)
    async def wrapper(*args, **kwargs):
        print("До")
        result = await func(*args, **kwargs)
        print("После")
        return result

    return wrapper
```

Иначе легко получить некорректное поведение при работе с coroutine.

---

# Где встречаются в Backend

Декораторы постоянно используются во фреймворках.

Например, в FastAPI:

```python
@app.get("/users")
async def get_users():
    ...
```

`@app.get(...)` — декоратор, который регистрирует функцию как обработчик HTTP-маршрута.

В Python-декораторах также основаны многие механизмы:

```python
@property
@classmethod
@staticmethod
```

и пользовательские декораторы:

```python
@cache
@retry
@requires_auth
```

## 🧠 Коротко для собеседования

> **Декоратор — это callable, который принимает другую функцию или класс и возвращает модифицированный callable, позволяя добавить поведение без изменения исходного кода. Синтаксис `@decorator` является сокращением для присваивания результата декоратора исходному имени. Для сохранения метаданных функции используют `functools.wraps`.**

### Главная схема

```text
@decorator
def func():
    ...
```

↓

```text
func = decorator(func)
```

↓

```text
decorator
    ↓
wrapper
    ↓
original func
```

### 🧠 Что обязательно знать

1. `@decorator` ≈ `func = decorator(func)`
2. `wrapper(*args, **kwargs)`
3. `functools.wraps`
4. декоратор с аргументами → **фабрика декораторов**
5. несколько декораторов применяются **снизу вверх**
6. для `async def` нужен корректный `async wrapper` с `await`
