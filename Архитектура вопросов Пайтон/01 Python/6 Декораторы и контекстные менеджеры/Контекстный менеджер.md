# 🔐 Контекстный менеджер

🎯 **Ответ на собеседовании:**

**Контекстный менеджер** — это объект, который управляет **ресурсом или контекстом выполнения** и гарантирует выполнение определённых действий при входе и выходе из блока [[with]].

Используется через:

```python id="y8tq4p"
with expression as variable:
    ...
```

Классический пример:

```python id="a3m7k1"
with open("data.txt") as file:
    data = file.read()
```

После выхода из `with` файл будет закрыт, в том числе если внутри блока произошло исключение.

---

# Как работает `with`

Контекстный менеджер реализует два основных метода:

```python id="q4x8n2"
__enter__()
__exit__()
```

Упрощённо:

```python id="4f7s9k"
manager = expression

value = manager.__enter__()

try:
    ...
finally:
    manager.__exit__(...)
```

То есть:

```text id="n8x2c5"
with
 ↓
__enter__()
 ↓
код внутри блока
 ↓
__exit__()
 ↓
очистка ресурса
```

---

# `__enter__`

Вызывается **при входе в `with`**.

```python id="p3w7k9"
class Manager:
    def __enter__(self):
        print("Вход")
        return self
```

Значение, возвращённое `__enter__`, можно получить через `as`:

```python id="d5r2m8"
with Manager() as manager:
    ...
```

Здесь:

```python id="1h6v9q"
manager = Manager().__enter__()
```

---

# `__exit__`

Вызывается **при выходе из `with`** — как при обычном завершении, так и при исключении.

```python id="z7c4n1"
class Manager:
    def __enter__(self):
        print("Вход")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("Выход")
```

Параметры `__exit__`:

| Параметр    | Содержимое        |
| ----------- | ----------------- |
| `exc_type`  | Тип исключения    |
| `exc_value` | Объект исключения |
| `traceback` | Traceback         |

Если исключения не было:

```python id="e3k8w2"
exc_type is None
```

---

# `__exit__` может подавить исключение

Если `__exit__` возвращает:

```python id="v5m1x8"
True
```

исключение считается обработанным и **не выходит наружу**.

```python id="r6n2q4"
class Manager:
    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        return True


with Manager():
    raise ValueError("Ошибка")

print("Продолжаем")
```

Результат:

```text id="u8c3p1"
Продолжаем
```

Если вернуть:

```python id="x2k7m5"
False
```

или `None`, исключение продолжит распространяться.

⚠️ Поэтому обычно `__exit__` не подавляет исключения без явной необходимости.

# Собственный контекстный менеджер

Пример с ресурсом:

```python id="h9q4w6"
class Connection:
    def __enter__(self):
        print("Открываем соединение")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("Закрываем соединение")
```

Использование:

```python id="c1m8z3"
with Connection() as connection:
    print("Работаем")
```

Получим:

```text id="n4v6s9"
Открываем соединение
Работаем
Закрываем соединение
```

---

# Контекстные менеджеры нужны для ресурсов

Типичные случаи:

* файлы;
* соединения с БД;
* транзакции;
* блокировки (`Lock`);
* сетевые соединения;
* временные ресурсы;
* изменение состояния, которое нужно гарантированно вернуть обратно.

Например:

```python id="f8k2r5"
with lock:
    shared_data.append(value)
```

После блока `lock` будет освобождён.

# `contextlib`

Python предоставляет готовые инструменты для создания контекстных менеджеров.

Самый удобный вариант — `@contextmanager`:

```python id="m7p3x9"
from contextlib import contextmanager


@contextmanager
def manager():
    print("Вход")

    try:
        yield
    finally:
        print("Выход")
```

Использование:

```python id="q2w8n4"
with manager():
    print("Работа")
```

Результат:

```text id="j5r1c7"
Вход
Работа
Выход
```

Здесь `yield` разделяет:

```text id="b6v9s2"
до yield
   ↓
вход в with

yield
   ↓
код внутри with

после yield
   ↓
выход из with
```

---

# Контекстный менеджер vs `try/finally`

Контекстный менеджер позволяет удобно инкапсулировать шаблон:

```python id="k8n3m5"
resource = acquire()

try:
    use(resource)
finally:
    release(resource)
```

в:

```python id="s4v7p2"
with resource_manager() as resource:
    use(resource)
```

Главное преимущество — **управление ресурсом становится безопасным и переиспользуемым**.

---

# Важный нюанс

`__enter__` и `__exit__` — это **протокол контекстного менеджера**.

Как:

```text id="y5m2r8"
Iterable
  → __iter__

Iterator
  → __next__

Context Manager
  → __enter__
  → __exit__
```

То есть `with` работает благодаря специальному протоколу.

---

## 🧠 Коротко для собеседования

> **Контекстный менеджер — объект, реализующий протокол `__enter__` и `__exit__`, который позволяет безопасно управлять ресурсами или состоянием через `with`. `__enter__` выполняется при входе в блок, а `__exit__` — при выходе, в том числе при возникновении исключения. `__exit__` может подавить исключение, если вернёт `True`.**

### Главное:

```text id="q7f4m1"
with
 ↓
__enter__()
 ↓
код
 ↓
__exit__()
```

### Что обязательно знать на собеседовании

1. `__enter__` — вход в контекст.
2. `__exit__` — выход и cleanup.
3. `__exit__` получает `exc_type`, `exc_value`, `traceback`.
4. `__exit__ → True` подавляет исключение.
5. `contextlib.contextmanager` позволяет создать менеджер через `yield`.
6. Основное назначение — **гарантированное управление ресурсами**.
