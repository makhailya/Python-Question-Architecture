# 🔄 `yield` в Python

## 🎤 Короткий ответ

`yield` используется внутри функции-генератора. Он **возвращает очередное значение и приостанавливает выполнение функции**, сохраняя её состояние.

При следующем вызове `next()` генератор продолжает выполнение с места после `yield`.

```python
def numbers():
    yield 1
    yield 2
    yield 3


gen = numbers()

print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # 3
```

В отличие от `return`, `yield` **не завершает функцию окончательно** — он приостанавливает её.

---

## 🗣️ Ответ на собеседовании

`yield` превращает обычную функцию в **генератор**.

Когда выполнение доходит до `yield`, функция отдаёт значение наружу и приостанавливается. При следующем вызове `next()` она продолжает работу с того места, где остановилась, сохраняя локальные переменные и состояние стека.

Когда выполнение заканчивается, генератор выбрасывает `StopIteration`.

Главное отличие от `return` в том, что `return` завершает текущий вызов функции, а `yield` позволяет выполнять функцию **по частям**, выдавая значения по одному.

Это особенно полезно для ленивых вычислений и обработки больших объёмов данных, потому что генератор не обязан хранить весь результат в памяти.

## 📚 Разбор поглубже

### 1. Что делает `yield`

Рассмотрим:

```python
def numbers():
    yield 1
    yield 2
    yield 3
```

Вызов:

```python
gen = numbers()
```

**не выполняет тело функции сразу.**

Создаётся объект-генератор:

```python
print(gen)
```

Примерно:

```text
<generator object numbers at ...>
```

Выполнение начинается только при запросе следующего значения:

```python
next(gen)
```

---

### 2. Как работает `next()`

Последовательность:

```python
def numbers():
    yield 1
    yield 2
    yield 3
```

```python
gen = numbers()

next(gen)  # 1
next(gen)  # 2
next(gen)  # 3
```

Модель выполнения:

```text
next()
  ↓
запуск генератора
  ↓
yield 1
  ↓
пауза

next()
  ↓
продолжение
  ↓
yield 2
  ↓
пауза

next()
  ↓
продолжение
  ↓
yield 3
  ↓
пауза

next()
  ↓
функция закончилась
  ↓
StopIteration
```

---

### 3. `yield` сохраняет состояние функции

Это одна из ключевых особенностей.

```python
def counter():
    value = 0

    while value < 3:
        value += 1
        yield value
```

```python
gen = counter()

print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # 3
```

После первого `yield` переменная `value` не исчезает.

Генератор сохраняет состояние, чтобы продолжить выполнение позже.

---

### 4. `yield` vs `return`

Главное различие:

| `return`                                      | `yield`                          |
| --------------------------------------------- | -------------------------------- |
| Завершает функцию                             | Приостанавливает функцию         |
| Возвращает результат                          | Выдаёт очередное значение        |
| Состояние текущего вызова завершается         | Состояние генератора сохраняется |
| Повторный `return` невозможен в том же вызове | Можно иметь много `yield`        |
| Обычная функция                               | Генератор                        |

Пример:

```python
def regular():
    return 1
```

После `return` функция закончена.

```python
def generator():
    yield 1
    yield 2
```

Генератор можно продолжить после первого `yield`.

---

### 5. Что происходит после окончания генератора

Когда генератор дошёл до конца:

```python
def numbers():
    yield 1
```

```python
gen = numbers()

print(next(gen))  # 1
print(next(gen))  # StopIteration
```

`StopIteration` — это сигнал протоколу итератора:

> элементов больше нет.

Поэтому `for` не показывает эту ошибку пользователю:

```python
for number in numbers():
    print(number)
```

Внутри `for` фактически используется механизм `next()` и обрабатывается `StopIteration`.

---

### 6. Генератор можно использовать в `for`

Это основной способ использования.

```python
def numbers():
    yield 1
    yield 2
    yield 3


for number in numbers():
    print(number)
```

Получим:

```text
1
2
3
```

При этом значения выдаются **по одному**, а не создаются сразу целым списком.

---

### 7. Ленивые вычисления

Генератор работает **лениво**.

Например:

```python
def squares(n):
    for i in range(n):
        yield i * i
```

```python
for value in squares(1_000_000):
    print(value)
```

Генератор не обязан заранее создать миллион чисел в памяти.

Он вычисляет очередное значение только тогда, когда оно требуется.

```text
список:
создать все значения → хранить в памяти → использовать

generator:
получить значение → использовать → получить следующее
```

---

### 8. Память: `list` vs generator

```python
numbers = [x * x for x in range(1_000_000)]
```

Здесь создаётся список со всеми результатами.

Генераторное выражение:

```python
numbers = (x * x for x in range(1_000_000))
```

создаёт генератор.

Он вычисляет элементы по мере итерации.

Это особенно полезно при:

* больших файлах;
* потоковой обработке;
* ETL;
* обработке логов;
* больших наборах данных;
* пайплайнах обработки.

### 9. `yield` превращает функцию в генератор

Сравним:

```python
def get_numbers():
    return [1, 2, 3]
```

Результат:

```python
[1, 2, 3]
```

А:

```python
def get_numbers():
    yield 1
    yield 2
    yield 3
```

результат вызова:

```python
<generator object ...>
```

То есть наличие `yield` меняет семантику функции.

---

### 10. `yield` и состояние локальных переменных

Рассмотрим:

```python
def counter():
    count = 0

    while True:
        count += 1
        yield count
```

```python
gen = counter()

print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # 3
```

`count` продолжает существовать между вызовами `next()`.

Это принципиально отличается от обычной функции:

```python
def counter():
    count = 0
    count += 1
    return count
```

Каждый новый вызов обычной функции создаёт новое локальное состояние.

---

### 11. `yield` принимает значение через `send()`

У генератора есть более глубокая возможность — отправить значение внутрь генератора через `send()`.

```python
def generator():
    value = yield "Ожидаю значение"
    yield value * 2
```

```python
gen = generator()

print(next(gen))
```

Получим:

```text
Ожидаю значение
```

Теперь:

```python
print(gen.send(10))
```

Получим:

```text
20
```

То есть `yield` может работать не только как источник значения наружу, но и как точка взаимодействия с генератором.

---

### 12. `yield` и `send()`

Концептуально:

```text
                генератор
                   │
          ┌────────┴────────┐
          │                 │
       yield              send()
          │                 │
          ↓                 ↑
   значение наружу     значение внутрь
```

Это связано с расширенным протоколом генераторов:

* `next()`;
* `send()`;
* `throw()`;
* `close()`.

Для обычного использования генераторов достаточно хорошо понимать `next()` и `StopIteration`, но на собеседовании могут спросить про `send()`.

---

### 13. `yield from`

`yield from` позволяет делегировать выдачу значений другому итерируемому объекту или генератору.

Вместо:

```python
def numbers():
    for value in [1, 2, 3]:
        yield value
```

можно написать:

```python
def numbers():
    yield from [1, 2, 3]
```

Результат тот же:

```python
list(numbers())
```

```text
[1, 2, 3]
```

Но `yield from` — это не просто сокращение цикла. Он также делегирует взаимодействие с подгенератором, включая `send()`, `throw()` и обработку его завершения.

---

### 14. `yield from` и возвращаемое значение генератора

Подгенератор может завершиться через `return`:

```python
def child():
    yield 1
    yield 2
    return "done"
```

Его результат можно получить через `yield from`:

```python
def parent():
    result = yield from child()
    print(result)
```

После завершения `child()`:

```text
result == "done"
```

То есть:

```text
yield from
├── делегирует значения
├── делегирует send()
├── делегирует throw()
└── получает return-значение подгенератора
```

Это одна из важных тем при углублённом изучении генераторов.

### 15. Генератор — это итератор

Генераторный объект поддерживает протокол итератора:

```python
gen = (x for x in range(3))

print(iter(gen) is gen)
```

Результат:

```text
True
```

У него есть:

```python
next(gen)
```

Поэтому:

```text
Generator
   ↓
Iterator
   ↓
Iterable
```

Генератор можно передать в `for`.

---

### 16. Генераторное выражение

Есть специальный синтаксис:

```python
squares = (x * x for x in range(10))
```

В отличие от list comprehension:

```python
squares = [x * x for x in range(10)]
```

первый вариант создаёт генератор, второй — список.

```text
[...] → list
(...) → generator expression
```

### 17. Практический пример: чтение большого файла

Необязательно загружать весь файл в память:

```python
def read_lines(filename):
    with open(filename, encoding="utf-8") as file:
        for line in file:
            yield line.strip()
```

Использование:

```python
for line in read_lines("logs.txt"):
    process(line)
```

Данные обрабатываются последовательно.

Для больших файлов это позволяет строить **потоковую обработку**.

---

### 18. Генератор как pipeline

Генераторы хорошо комбинируются:

```python
def numbers():
    for i in range(10):
        yield i


def even(numbers):
    for number in numbers:
        if number % 2 == 0:
            yield number


def squares(numbers):
    for number in numbers:
        yield number * number
```

Pipeline:

```python
result = squares(even(numbers()))

for value in result:
    print(value)
```

Получается ленивый конвейер:

```text
numbers()
    ↓
even()
    ↓
squares()
    ↓
результат
```

Каждый элемент проходит через pipeline по мере необходимости.

---

### 19. Важный нюанс: генератор одноразовый

Генератор нельзя нормально «перемотать» назад.

```python
gen = (x for x in range(3))

print(list(gen))
```

```text
[0, 1, 2]
```

Повторно:

```python
print(list(gen))
```

получим:

```text
[]
```

Генератор уже исчерпан.

Если нужно пройти данные несколько раз, часто нужен контейнер, например `list`.

---

### 20. `yield` и `async`

В асинхронном Python встречается:

```python
async def numbers():
    yield 1
    yield 2
```

Это уже **async generator**.

Используется:

```python
async for number in numbers():
    print(number)
```

Важно не путать:

```text
yield
    → обычный генератор

async def + yield
    → асинхронный генератор

await
    → ожидание awaitable
```

`yield` и `await` решают разные задачи.

## 🎤 Вопросы на собеседовании

**Что такое `yield`?**

`yield` приостанавливает выполнение функции-генератора и возвращает очередное значение. При следующем `next()` выполнение продолжается с места остановки.

**Чем `yield` отличается от `return`?**

`return` завершает функцию, а `yield` приостанавливает генератор и позволяет продолжить его позже.

**Что возвращает функция с `yield` при обычном вызове?**

Объект-генератор. Тело функции начинает выполняться при итерации или вызове `next()`.

**Что происходит при `next()` после окончания генератора?**

Возникает `StopIteration`.

**Зачем нужны генераторы?**

Для ленивых вычислений, экономии памяти и потоковой обработки данных.

**Генератор является итератором?**

Да. Генератор поддерживает протокол итератора и предоставляет `__iter__()` и `__next__()`.

**Что такое `yield from`?**

Механизм делегирования работы другому итерируемому объекту или генератору, включая более глубокое взаимодействие через `send()`, `throw()` и получение значения `return`.

**Можно ли передать значение внутрь генератора?**

Да, через `send()`.

**Можно ли использовать `return` в генераторе?**

Да. Он завершает генератор, а выражение после `return` становится значением `StopIteration.value`.

**Почему генератор экономит память?**

Потому что он не обязан хранить весь результат целиком. Значения вычисляются и выдаются по одному, по мере запроса.

**Можно ли повторно пройти один и тот же генератор?**

Нет, исчерпанный генератор нельзя перемотать. Для повторной итерации нужно создать новый генератор или сохранить данные в контейнере.
