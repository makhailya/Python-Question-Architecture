# λ Lambda-функции в Python

## 🎤 Короткий ответ

**Lambda — это анонимная функция**, которую можно создать непосредственно в выражении.

Синтаксис:

```python
lambda аргументы: выражение
```

Например:

```python
square = lambda x: x ** 2

print(square(5))  # 25
```

Главное ограничение: `lambda` содержит **одно выражение** и автоматически возвращает его результат.

Чаще всего lambda используется там, где функцию нужно передать как аргумент:

```python
numbers = [3, 1, 5, 2]

numbers.sort(key=lambda x: x)
```

---

## 🗣️ Ответ на собеседовании

> Lambda в Python — это способ создать небольшую анонимную функцию с помощью выражения `lambda`.
>
> Синтаксис — `lambda параметры: выражение`. Результат выражения автоматически возвращается, поэтому отдельный `return` внутри lambda использовать нельзя.
>
> Lambda особенно часто применяется как callback или функция, передаваемая в другую функцию, например в `sorted`, `sort`, `map`, `filter`.
>
> При этом lambda — полноценный объект-функция: её можно присвоить переменной, передать как аргумент или вернуть из другой функции. Но для сложной логики лучше использовать обычный `def`, потому что lambda ограничена одним выражением и обычно хуже читается.

# 📚 Разбор поглубже

## 1. Синтаксис

Общий синтаксис:

```python
lambda параметры: выражение
```

Например:

```python
lambda x: x * 2
```

Это примерно эквивалентно:

```python
def double(x):
    return x * 2
```

То есть:

```text
lambda x: x * 2
       ↓
принимает x
       ↓
вычисляет x * 2
       ↓
возвращает результат
```

---

# 2. Lambda автоматически возвращает результат

```python
double = lambda x: x * 2

print(double(5))
```

Результат:

```text
10
```

`return` писать нельзя:

```python
lambda x:
    return x * 2
```

Это синтаксически неверно.

В lambda результатом является само выражение:

```python
lambda x: x * 2
```

---

# 3. Lambda может принимать несколько аргументов

```python
add = lambda a, b: a + b

print(add(2, 3))
```

Результат:

```text
5
```

Можно использовать значения по умолчанию:

```python
power = lambda x, n=2: x ** n

print(power(5))
print(power(5, 3))
```

Результат:

```text
25
125
```

# 4. Lambda — это объект-функция

Lambda можно присвоить переменной:

```python
square = lambda x: x ** 2
```

После этого:

```python
print(square(4))
```

Но важно понимать:

```text
square
  ↓
function object
```

То есть lambda не является каким-то отдельным «типом функции».

```python
type(lambda x: x)
```

даст:

```text
<class 'function'>
```

# 5. Зачем вообще нужна lambda

Основное применение — передать небольшую функцию туда, где она нужна **один раз**.

Например:

```python
numbers = [3, 1, 5, 2]

numbers.sort(key=lambda x: x)
```

Но здесь lambda бессмысленна, потому что сортировка и так работает по элементам.

Гораздо полезнее:

```python
users = [
    {"name": "Илья", "age": 31},
    {"name": "Анна", "age": 25},
    {"name": "Олег", "age": 40},
]

users.sort(key=lambda user: user["age"])
```

Теперь `key` получает каждого пользователя и возвращает значение, по которому нужно сортировать.

# 6. Lambda и `sorted`

Один из самых частых вариантов на Python-собеседованиях:

```python
users = [
    ("Илья", 31),
    ("Анна", 25),
    ("Олег", 40),
]

result = sorted(users, key=lambda user: user[1])
```

Получим:

```text
[
    ("Анна", 25),
    ("Илья", 31),
    ("Олег", 40),
]
```

Механика:

```text
sorted()
   ↓
берёт каждый элемент
   ↓
передаёт его в lambda
   ↓
lambda возвращает ключ
   ↓
sorted использует ключ для сортировки
```

# 7. Lambda и `map`

`map()` применяет функцию к каждому элементу.

```python
numbers = [1, 2, 3, 4]

result = map(lambda x: x * 2, numbers)

print(list(result))
```

Результат:

```text
[2, 4, 6, 8]
```

Смысл:

```text
1 → lambda → 2
2 → lambda → 4
3 → lambda → 6
4 → lambda → 8
```

---

# 8. Lambda и `filter`

`filter()` оставляет элементы, для которых функция возвращает истинное значение.

```python
numbers = [1, 2, 3, 4, 5, 6]

result = filter(lambda x: x % 2 == 0, numbers)

print(list(result))
```

Получим:

```text
[2, 4, 6]
```

Здесь lambda отвечает на вопрос:

> Подходит ли этот элемент?

```text
1 → False
2 → True
3 → False
4 → True
5 → False
6 → True
```

---

# 9. Lambda и `reduce`

`reduce()` последовательно объединяет элементы.

```python
from functools import reduce

numbers = [1, 2, 3, 4]

result = reduce(lambda a, b: a + b, numbers)

print(result)
```

Получим:

```text
10
```

Упрощённо:

```text
1 + 2 = 3
3 + 3 = 6
6 + 4 = 10
```

В современном Python для простого суммирования обычно предпочтительнее:

```python
sum(numbers)
```

# 10. Lambda vs `def`

| Lambda                       | `def`                        |
| ---------------------------- | ---------------------------- |
| Анонимная функция            | Именованная функция          |
| Одно выражение               | Произвольный блок кода       |
| Не использует `return`       | Может использовать `return`  |
| Хороша для коротких callback | Подходит для сложной логики  |
| Часто используется inline    | Обычно определяется отдельно |
| Ограничена одним выражением  | Более выразительная          |

Например, хорошо:

```python
users.sort(key=lambda user: user["age"])
```

А вот так делать уже сомнительно:

```python
process = lambda x: complicated_logic(x)
```

Если логика достаточно сложная, лучше:

```python
def process(x):
    ...
```

# 11. Lambda может использовать условное выражение

В lambda нельзя написать обычный `if`-блок:

```python
lambda x:
    if x > 0:
        return x
```

Но можно использовать **тернарное выражение**:

```python
absolute = lambda x: x if x >= 0 else -x
```

Например:

```python
print(absolute(-5))
```

Результат:

```text
5
```

# 12. Lambda и замыкания

Lambda тоже может создавать замыкание.

```python
def make_multiplier(n):
    return lambda x: x * n
```

Создаём:

```python
double = make_multiplier(2)
triple = make_multiplier(3)
```

Теперь:

```python
print(double(5))
print(triple(5))
```

Результат:

```text
10
15
```

Lambda замкнула переменную `n`.

# 13. Lambda и late binding

Здесь возникает классическая проблема:

```python
funcs = []

for i in range(3):
    funcs.append(lambda: i)

print([func() for func in funcs])
```

Результат:

```text
[2, 2, 2]
```

Почему?

Все lambda используют одну свободную переменную `i`.

```text
lambda 1 ──┐
lambda 2 ──┼──→ i
lambda 3 ──┘
```

При вызове:

```text
i == 2
```

Поэтому все получают `2`.

---

# 14. Как исправить late binding

Используем аргумент по умолчанию:

```python
funcs = []

for i in range(3):
    funcs.append(lambda i=i: i)

print([func() for func in funcs])
```

Получим:

```text
[0, 1, 2]
```

Здесь:

```text
lambda i=0
lambda i=1
lambda i=2
```

Каждая функция получает своё значение через default argument.

# 15. Lambda не всегда означает «лучше»

Иногда разработчик пытается сделать код максимально коротким:

```python
result = list(map(lambda x: x * 2, filter(lambda x: x > 0, numbers)))
```

Это работает, но может быть менее читаемо.

Часто обычное выражение-генератор проще:

```python
result = [x * 2 for x in numbers if x > 0]
```

Поэтому lambda — не инструмент для того, чтобы просто уменьшить количество строк.

Её основная ценность — **короткая функция как значение**, особенно когда она передаётся в другую функцию.

# 16. Lambda как callback

Например:

```python
def execute(callback):
    return callback(10)


result = execute(lambda x: x * 2)

print(result)
```

Получим:

```text
20
```

Схема:

```text
lambda
  ↓
передаём как объект
  ↓
execute()
  ↓
callback(10)
  ↓
20
```

Это напрямую связано с концепцией:

> **Функции в Python являются объектами первого класса.**

# 17. Lambda и `key`

Очень важно понимать, что `key` обычно **не сравнивает элементы**, а возвращает значение, по которому Python выполняет сортировку.

```python
users = [
    {"name": "Илья", "age": 31},
    {"name": "Анна", "age": 25},
]

users.sort(key=lambda user: user["age"])
```

Lambda:

```text
user → user["age"]
```

То есть:

```text
Илья → 31
Анна → 25
```

И сортировка использует эти ключи.

---

# 18. Lambda с несколькими условиями

Например, сортировка сначала по возрасту, затем по имени:

```python
users = [
    ("Илья", 31),
    ("Анна", 25),
    ("Олег", 25),
]

result = sorted(
    users,
    key=lambda user: (user[1], user[0])
)
```

Ключом становится tuple:

```text
(age, name)
```

То есть:

```text
(31, "Илья")
(25, "Анна")
(25, "Олег")
```

---

# 19. Lambda — обычная функция с ограниченным синтаксисом

Важно не считать lambda каким-то отдельным механизмом выполнения.

Например:

```python
square = lambda x: x ** 2
```

по смыслу близко к:

```python
def square(x):
    return x ** 2
```

Обе создают объекты типа `function`.

Основное отличие — синтаксис и ограничения lambda.

# 🎤 Вопросы на собеседовании

### Что такое lambda?

Анонимная функция, определяемая выражением:

```python
lambda args: expression
```

### Может ли lambda содержать несколько выражений?

Нет. Lambda содержит одно выражение.

### Может ли lambda использовать `return`?

Нет. Результат выражения возвращается автоматически.

### Lambda — это отдельный тип?

Нет. Результат создания lambda имеет тип `function`.

### Где чаще всего используют lambda?

В качестве короткого callback, например:

```python
sorted(users, key=lambda user: user["age"])
```

а также с `map`, `filter`, `reduce`.

### Чем lambda отличается от `def`?

`lambda` ограничена одним выражением и удобна для коротких функций inline. `def` позволяет писать полноценный блок кода и обычно используется для более сложной логики.

### Что выведет код?

```python
funcs = []

for i in range(3):
    funcs.append(lambda: i)

print([f() for f in funcs])
```

Ответ:

```text
[2, 2, 2]
```

Причина — **late binding**.

### Как получить `[0, 1, 2]`?

```python
funcs = []

for i in range(3):
    funcs.append(lambda i=i: i)
```

### Может ли lambda быть замыканием?

Да:

```python
def make_multiplier(n):
    return lambda x: x * n
```

Lambda может захватить переменную из enclosing scope.

### Когда лучше не использовать lambda?

Когда выражение становится сложным и ухудшает читаемость. В таком случае лучше обычная именованная функция через `def`.

### Ключевая формула

```text
lambda
├── анонимная функция
├── одно выражение
├── результат → автоматически возвращается
├── объект типа function
├── часто → callback / key / map / filter
└── может участвовать в closure
```
