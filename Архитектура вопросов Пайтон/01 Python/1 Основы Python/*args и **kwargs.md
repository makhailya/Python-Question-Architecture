# 🧩 `*args` и `**kwargs`

## 🎤 Короткий ответ

`*args` и `**kwargs` позволяют функции принимать **произвольное количество аргументов**.

- `*args` собирает позиционные аргументы в `tuple`.
- `**kwargs` собирает именованные аргументы в `dict`.

```python
def func(*args, **kwargs):
    print(args)
    print(kwargs)

func(1, 2, 3, name="Илья", age=31)
```

Получим:

```text
(1, 2, 3)
{"name": "Илья", "age": 31}
```

При вызове функции эти же конструкции делают обратное: `*` распаковывает iterable, а `**` распаковывает mapping в именованные аргументы.

---

## 🗣️ Ответ на собеседовании

`*args` и `**kwargs` используются, когда функция должна принимать переменное количество аргументов.

`*args` собирает все дополнительные позиционные аргументы в кортеж `tuple`, а `**kwargs` — дополнительные именованные аргументы в словарь `dict`.

Например:

```python
def func(*args, **kwargs):
    ...
```

При вызове `func(1, 2, name="Илья")` внутри функции `args` будет `(1, 2)`, а `kwargs` — `{"name": "Илья"}`.

При вызове функции `*` и `**` работают наоборот — распаковывают значения:

```python
numbers = [1, 2, 3]
user = {"name": "Илья", "age": 31}

func(*numbers, **user)
```

Важно понимать, что `args` и `kwargs` — это только общепринятые имена. Синтаксически важны именно `*` и `**`.

## 📚 Разбор поглубже

### 1. `*args` — произвольные позиционные аргументы

```python
def add(*args):
    print(args)

add(1, 2, 3)
```

Внутри:

```python
args == (1, 2, 3)
```

Тип:

```python
type(args)
# tuple
```

Можно работать с ним как с обычным кортежем:

```python
def add(*args):
    return sum(args)

print(add(1, 2, 3, 4))
# 10
```

---

### 2. `**kwargs` — произвольные именованные аргументы

```python
def show_user(**kwargs):
    print(kwargs)

show_user(
    name="Илья",
    age=31,
    city="Екатеринбург"
)
```

Внутри:

```python
kwargs == {
    "name": "Илья",
    "age": 31,
    "city": "Екатеринбург"
}
```

Тип:

```python
type(kwargs)
# dict
```

Можно обращаться как к обычному словарю:

```python
def show_user(**kwargs):
    print(kwargs.get("name"))
```

---

### 3. Можно использовать вместе

```python
def func(*args, **kwargs):
    print(args)
    print(kwargs)

func(
    10,
    20,
    30,
    name="Илья",
    age=31
)
```

Результат:

```text
(10, 20, 30)

{
    "name": "Илья",
    "age": 31
}
```

Схема:

```text
func(10, 20, 30, name="Илья", age=31)
       │
       ├── *args
       │      ↓
       │   (10, 20, 30)
       │
       └── **kwargs
              ↓
          {"name": "Илья", "age": 31}
```

## 4. `*` при вызове — распаковка

Важно различать:

```python
def func(*args):
    ...
```

и:

```python
func(*values)
```

В первом случае `*` **собирает** аргументы.

Во втором — **распаковывает**.

```python
numbers = [1, 2, 3]

def add(a, b, c):
    return a + b + c

add(*numbers)
```

Фактически:

```python
add(1, 2, 3)
```

---

## 5. `**` при вызове — распаковка словаря

```python
user = {
    "name": "Илья",
    "age": 31
}

def introduce(name, age):
    print(name, age)

introduce(**user)
```

Это эквивалентно:

```python
introduce(
    name="Илья",
    age=31
)
```

То есть:

```text
**dict
   ↓
ключи → имена параметров
значения → значения аргументов
```

---

## 6. Порядок параметров

У функции могут быть обычные параметры, `*args` и `**kwargs`.

```python
def func(a, b, *args, **kwargs):
    ...
```

Например:

```python
func(
    1,
    2,
    3,
    4,
    name="Илья"
)
```

Получим:

```text
a = 1
b = 2
args = (3, 4)
kwargs = {"name": "Илья"}
```

---

## 7. `*` может сделать параметры только именованными

Это важный нюанс.

```python
def create_user(name, *, age, city):
    ...
```

После `*` параметры можно передавать **только по имени**:

```python
create_user(
    "Илья",
    age=31,
    city="Екатеринбург"
)
```

А так нельзя:

```python
create_user("Илья", 31, "Екатеринбург")
```

Это называется **keyword-only parameters**.

При этом `*` здесь не означает `*args`.

---

## 8. `**` должен быть последним

Например:

```python
def func(a, *args, **kwargs):
    ...
```

`**kwargs` собирает оставшиеся именованные аргументы.

После `**kwargs` обычные параметры добавить нельзя.

---

## 9. `args` и `kwargs` — не специальные имена

Можно написать:

```python
def func(*numbers, **options):
    print(numbers)
    print(options)
```

Это абсолютно корректно.

Названия:

```text
args
kwargs
```

— просто **соглашение**.

Смысл задают:

```text
* → собрать позиционные аргументы
** → собрать именованные аргументы
```

---

## 10. Практический пример — декоратор

`*args` и `**kwargs` особенно часто встречаются в декораторах:

```python
def log_calls(func):
    def wrapper(*args, **kwargs):
        print("Вызов функции")
        return func(*args, **kwargs)

    return wrapper
```

Почему это удобно?

Декоратор не знает заранее сигнатуру исходной функции.

Она может быть:

```python
def foo(a, b):
    ...
```

или:

```python
def bar(name, age, city):
    ...
```

А `wrapper` сможет принять аргументы обеих функций.

---

## 11. `*args` и `**kwargs` в наследовании

Частый пример:

```python
class Child(Parent):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
```

Здесь аргументы собираются в дочернем классе и затем распаковываются при вызове родительского конструктора.

Это особенно полезно в коде с наследованием, миксинами и фреймворками.

---

## 12. Распаковка нескольких значений

Можно распаковывать несколько iterable:

```python
a = [1, 2]
b = [3, 4]

result = [*a, *b]

print(result)
# [1, 2, 3, 4]
```

Для словарей:

```python
first = {"a": 1}
second = {"b": 2}

result = {**first, **second}
```

Получим:

```python
{"a": 1, "b": 2}
```

Если ключ повторяется, значение из последнего распакованного словаря перекрывает предыдущее.

---

## 13. Типизация

Если функция принимает произвольные аргументы, их можно типизировать:

```python
def process(*args: int, **kwargs: str):
    ...
```

Это означает, что:

- элементы `args` ожидаются как `int`;
- значения `kwargs` ожидаются как `str`.

Но это именно **аннотация типов**, а не автоматическая проверка во время выполнения.

---

## 14. Частая ошибка

Не стоит считать:

```python
*args
```

синонимом:

> «передать список».

Например:

```python
def func(*args):
    print(type(args))
```

При:

```python
func([1, 2, 3])
```

получим:

```text
<class 'tuple'>
```

Потому что список `[1, 2, 3]` — это **один позиционный аргумент**.

А при:

```python
func(*[1, 2, 3])
```

получим:

```text
(1, 2, 3)
```

Потому что список был распакован на три аргумента.

## 🎤 Вопросы на собеседовании

### Что такое `*args`?

Синтаксис для сбора произвольного количества позиционных аргументов в `tuple`.

### Что такое `**kwargs`?

Синтаксис для сбора произвольного количества именованных аргументов в `dict`.

### `args` и `kwargs` — специальные слова Python?

Нет. Это соглашение об именовании. Важны `*` и `**`.

### Что произойдёт здесь?

```python
def func(*args):
    print(args)

func(1, 2, 3)
```

Получим:

```text
(1, 2, 3)
```

### А здесь?

```python
def func(*args):
    print(args)

func([1, 2, 3])
```

Получим:

```text
([1, 2, 3],)
```

Потому что список передан как один позиционный аргумент.

### Что делает `*` при вызове?

Распаковывает iterable в отдельные позиционные аргументы.

### Что делает `**` при вызове?

Распаковывает mapping, обычно `dict`, в именованные аргументы.

### Для чего `*args` и `**kwargs` особенно часто используют в backend-коде?

Для универсальных функций, обёрток и декораторов, когда заранее неизвестна точная сигнатура вызываемой функции.

### Чем отличается `*` от `*args`?

`*args` собирает произвольное количество позиционных аргументов.

Одинокий `*` в сигнатуре обозначает границу, после которой параметры становятся **только именованными**:

```python
def func(a, *, b):
    ...
```
