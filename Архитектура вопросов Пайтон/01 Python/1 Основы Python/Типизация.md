# 🏷️ Типизация в Python

## 🎤 Короткий ответ

Типизация — это система работы с типами данных в языке.

Python — **динамически типизированный язык**: тип связан с объектом, а не с переменной, и проверка многих типов происходит во время выполнения.

При этом Python поддерживает **статическую типизацию через type hints** — аннотации типов, которые анализируют `mypy`, Pyright и IDE.

```python
def add(a: int, b: int) -> int:
    return a + b
```

Аннотации не делают Python статически типизированным и сами по себе обычно не запрещают передать значение другого типа.

---

## 🗣️ Ответ на собеседовании

Python является динамически типизированным языком. Это означает, что тип определяется во время выполнения, а одна и та же переменная может в разные моменты ссылаться на объекты разных типов.

```python
x = 10
x = "hello"
```

При этом в Python есть **аннотации типов**, которые позволяют явно описывать ожидаемые типы параметров, возвращаемых значений, атрибутов и переменных.

```python
def get_user(user_id: int) -> str:
    return "Ilya"
```

Эти аннотации используются IDE и статическими анализаторами, например `mypy` или Pyright, чтобы находить потенциальные ошибки до запуска программы.

Важно различать **динамическую типизацию Python** и **статический анализ типов**. Type hints сами по себе не превращают Python в статически типизированный язык и не являются runtime-проверкой типов.

## 📚 Разбор поглубже

### 1. Что такое типизация

Типизация определяет, **какие типы значений существуют и какие операции над ними допустимы**.

Например:

```python
x = 10
```

`x` ссылается на объект типа `int`.

```python
print(type(x))
```

Результат:

```text
<class 'int'>
```

При этом переменная сама по себе не является контейнером фиксированного типа:

```python
x = 10
x = "hello"
x = [1, 2, 3]
```

В Python имя `x` просто последовательно связывается с разными объектами.

---

### 2. Динамическая типизация

В Python тип объекта определяется во время выполнения.

```python
value = 10

print(type(value))  # int

value = "hello"

print(type(value))  # str
```

Это нормально для Python.

Важно:

> **Динамическая типизация не означает отсутствие типов.**

В Python типы есть. Просто многие проверки происходят во время выполнения.

```python
def add(a, b):
    return a + b
```

Вызов:

```python
add(2, 3)
```

работает.

А:

```python
add(2, "3")
```

приведёт к ошибке во время выполнения:

```text
TypeError
```

---

### 3. Сильная типизация

Python обычно называют **сильно типизированным** языком.

Например:

```python
2 + "3"
```

не приводит автоматически `2` к строке.

Получим:

```text
TypeError
```

Нужно явно преобразовать тип:

```python
str(2) + "3"
```

Результат:

```text
"23"
```

Поэтому важно различать два свойства:

```text
Python
├── динамическая типизация
└── сильная типизация
```

Это разные характеристики.

---

### 4. Type hints

Аннотации типов позволяют описать ожидаемые типы.

```python
def multiply(a: int, b: int) -> int:
    return a * b
```

Здесь:

```text
a: int       → параметр a должен быть int
b: int       → параметр b должен быть int
-> int       → функция ожидаемо возвращает int
```

Аннотации также можно использовать для переменных:

```python
age: int = 31
name: str = "Ilya"
is_active: bool = True
```

---

### 5. Type hints не являются runtime-проверкой

Это один из самых важных моментов для собеседования.

```python
def add(a: int, b: int) -> int:
    return a + b
```

Python сам по себе не обязан остановить такой вызов:

```python
add("hello", "world")
```

Фактическое поведение будет определяться обычной семантикой Python:

```text
"hello" + "world"
→ "helloworld"
```

Аннотация говорит разработчику и инструментам:

> здесь ожидаются `int`.

Но она не является автоматическим runtime-контролем.

Для статической проверки можно использовать, например, `mypy`:

```text
код
 ↓
mypy / Pyright
 ↓
проверка типов
 ↓
ошибки находятся до запуска
```

### 6. `None` и `Optional`

Если функция может вернуть значение или `None`, это нужно явно описать.

Современный Python:

```python
def find_user(user_id: int) -> str | None:
    ...
```

Это означает:

```text
str
или
None
```

В старом стиле часто использовали:

```python
from typing import Optional

def find_user(user_id: int) -> Optional[str]:
    ...
```

`Optional[str]` означает то же самое:

```text
str | None
```

### 7. Union

`Union` означает, что значение может иметь один из нескольких типов.

Современный синтаксис:

```python
def process(value: int | str) -> str:
    return str(value)
```

Значение может быть:

```text
int
или
str
```

Старый синтаксис:

```python
from typing import Union

def process(value: Union[int, str]) -> str:
    ...
```

### 8. Коллекции

Можно описывать тип элементов коллекции.

```python
numbers: list[int] = [1, 2, 3]

names: list[str] = ["Ilya", "Anna"]

users: dict[str, int] = {
    "Ilya": 31,
}
```

Для функции:

```python
def get_names() -> list[str]:
    return ["Ilya", "Anna"]
```

Для словаря:

```python
def get_ages() -> dict[str, int]:
    return {
        "Ilya": 31,
        "Anna": 29,
    }
```

### 9. `Any`

`Any` означает, что значение может иметь практически любой тип с точки зрения статического анализатора.

```python
from typing import Any

value: Any = 10

value = "hello"
value = [1, 2, 3]
```

`Any` полезен при работе с динамическими данными, но чрезмерное его использование фактически отключает преимущества статической типизации на этом участке кода.

Например:

```python
def process(data: Any):
    ...
```

анализатору становится сложнее обнаруживать ошибки.

---

### 10. `TypeVar` и Generics

Generics позволяют описывать обобщённые функции и классы.

Например, функция возвращает тот же тип, который получила:

```python
from typing import TypeVar

T = TypeVar("T")


def identity(value: T) -> T:
    return value
```

Теперь статический анализатор может понимать:

```python
result = identity(10)
```

как:

```text
result: int
```

А:

```python
result = identity("hello")
```

как:

```text
result: str
```

Это особенно важно при создании библиотек, контейнеров и переиспользуемого кода.

### 11. `Callable`

Можно типизировать функцию как значение.

```python
from collections.abc import Callable


def execute(func: Callable[[int], int], value: int) -> int:
    return func(value)
```

Здесь:

```text
Callable[[int], int]
```

означает:

```text
функция
принимает int
возвращает int
```

Например:

```python
def square(x: int) -> int:
    return x * x


execute(square, 5)
```

### 12. `Literal`

`Literal` позволяет указать конкретные допустимые значения.

```python
from typing import Literal


def set_mode(mode: Literal["read", "write"]):
    ...
```

Теперь ожидаются именно:

```text
"read"
или
"write"
```

а не произвольная строка.

### 13. `TypedDict`

Используется, когда нужен словарь с заранее описанной структурой.

```python
from typing import TypedDict


class User(TypedDict):
    name: str
    age: int
```

Теперь:

```python
user: User = {
    "name": "Ilya",
    "age": 31,
}
```

`TypedDict` особенно полезен при работе с JSON-подобными структурами, API и конфигурациями.

### 14. `Protocol`

`Protocol` используется для **структурной типизации**.

Главная идея:

> объект подходит по типу, если у него есть нужный интерфейс, даже если он явно не наследуется от определённого класса.

```python
from typing import Protocol


class Speaker(Protocol):
    def speak(self) -> str:
        ...
```

Любой класс с подходящим методом может соответствовать этому протоколу:

```python
class Dog:
    def speak(self) -> str:
        return "Woof"
```

Отдельно наследоваться от `Speaker` не обязательно.

Это важная тема для Python Backend и особенно для архитектуры и Dependency Injection.

### 15. Статическая и динамическая типизация

| Характеристика              | Динамическая              | Статическая                   |
| --------------------------- | ------------------------- | ----------------------------- |
| Когда определяется тип      | Runtime                   | До запуска / на этапе анализа |
| Пример                      | Python                    | Java, C++, TypeScript*        |
| Можно менять тип переменной | Да                        | Зависит от языка              |
| Ошибки типов                | Часто во время выполнения | Многие находятся заранее      |
| Type hints в Python         | Поддерживаются            | Через статический анализ      |

* TypeScript компилируется/транспилируется в JavaScript, но используется со статической системой типов.

Важно: **наличие type hints не превращает Python в статически типизированный язык.**

---

### 16. Duck typing

Python активно использует принцип **duck typing**:

> Если объект предоставляет нужный интерфейс, его конкретный класс может быть неважен.

Например:

```python
def save(writer):
    writer.write("hello")
```

Функции не обязательно знать конкретный класс `writer`.

Ей достаточно, чтобы объект поддерживал метод:

```python
write()
```

Это тесно связано с:

* полиморфизмом;
* `Protocol`;
* абстракциями;
* Dependency Injection.

### 17. `type()` и `isinstance()`

Для runtime-проверки типа чаще используется `isinstance()`.

```python
value = 10

isinstance(value, int)
```

Результат:

```text
True
```

`type()` позволяет получить конкретный класс:

```python
type(value)
```

Но есть важная разница при наследовании:

```python
class Animal:
    pass


class Dog(Animal):
    pass


dog = Dog()
```

```python
isinstance(dog, Animal)
```

→ `True`

А:

```python
type(dog) is Animal
```

→ `False`

Поэтому `isinstance()` учитывает наследование, а `type(...) is ...` проверяет конкретный тип.

---

### 18. Аннотации можно посмотреть во время выполнения

Аннотации являются частью информации функции.

```python
def add(a: int, b: int) -> int:
    return a + b
```

Можно посмотреть:

```python
print(add.__annotations__)
```

Получим примерно:

```python
{
    "a": int,
    "b": int,
    "return": int,
}
```

То есть type hints доступны runtime, но Python автоматически не обязан использовать их для проверки аргументов.

### 19. Практическая типизация Backend-кода

Для Python Backend type hints особенно полезны на границах системы:

```text
HTTP API
   ↓
Pydantic / DTO
   ↓
Service
   ↓
Repository
   ↓
Database
```

Например:

```python
class UserService:
    def get_user(self, user_id: int) -> User:
        ...
```

Это делает контракт метода явным:

```text
вход  → int
выход → User
```

В FastAPI type hints используются ещё активнее: они участвуют в построении схем API, валидации и документации совместно с Pydantic.

## 🎤 Вопросы на собеседовании

**Python — статически или динамически типизированный язык?**

Динамически типизированный. Тип определяется во время выполнения. При этом Python поддерживает type hints и статический анализ.

**Что такое type hints?**

Аннотации типов, которые описывают ожидаемые типы переменных, параметров, атрибутов и возвращаемых значений.

**Проверяет ли Python type hints автоматически?**

Нет. Обычные аннотации сами по себе не являются runtime-проверкой типов. Их используют IDE и инструменты статического анализа.

**Что такое `Any`?**

Тип, который фактически разрешает произвольное значение с точки зрения статического анализатора.

**Что такое `Union`?**

Тип, допускающий несколько вариантов:

```python
int | str
```

**Что такое `Optional[str]`?**

Старый синтаксис для:

```python
str | None
```

**Что такое Generic?**

Механизм параметризации типов, позволяющий писать обобщённый код с сохранением информации о типах.

**Что такое `Protocol`?**

Механизм структурной типизации: объект подходит, если предоставляет требуемый интерфейс, независимо от явного наследования.

**Что такое duck typing?**

Подход, при котором важны поддерживаемые объектом операции и интерфейс, а не его конкретный класс.

**В чём разница между `type()` и `isinstance()`?**

`type(obj) is Class` проверяет конкретный тип, а `isinstance(obj, Class)` учитывает наследование.

**Зачем типизация нужна в Backend?**

Она делает контракты функций и компонентов явными, улучшает автодополнение и рефакторинг и позволяет статическим анализаторам находить многие ошибки до запуска программы.
