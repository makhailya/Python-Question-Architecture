# 🚪 `if __name__ == "__main__"` в Python

## 🎤 Короткий ответ

`if __name__ == "__main__":` позволяет определить, **запущен ли Python-файл напрямую или импортирован как модуль**.

При прямом запуске файла Python устанавливает специальную переменную `__name__` в значение `"__main__"`:

```python
if __name__ == "__main__":
    main()
```

Если файл импортируется:

```python
import my_module
```

то `__name__` будет равно имени модуля, а код внутри `if` не выполнится.

Это позволяет отделить **код модуля** от **точки входа программы**.

---

## 🗣️ Ответ на собеседовании

`__name__` — специальная переменная модуля в Python. При прямом запуске файла её значение равно `"__main__"`, а при импорте файла — имени модуля.

Поэтому конструкция:

```python
if __name__ == "__main__":
```

используется как условие для кода, который должен выполняться только при непосредственном запуске файла.

Например:

```python
def main():
    print("Application started")


if __name__ == "__main__":
    main()
```

Если запустить файл через `python app.py`, `main()` выполнится.

Если сделать `import app`, функция `main` будет доступна, но код внутри условия автоматически не запустится.

## 📚 Разбор поглубже

### 1. Что такое `__name__`

`__name__` — специальная переменная, которая существует в каждом Python-модуле.

Например:

```python
print(__name__)
```

Если файл запущен напрямую:

```bash
python app.py
```

получим:

```text
__main__
```

Если файл импортирован:

```python
import app
```

то внутри `app.py`:

```text
__name__ == "app"
```

То есть значение зависит от **способа использования модуля**.

---

### 2. Что такое `__main__`

`__main__` — специальное имя, которое Python использует для **главного выполняемого модуля**.

При:

```bash
python app.py
```

Python фактически говорит:

```python
__name__ = "__main__"
```

для этого модуля.

Поэтому:

```python
if __name__ == "__main__":
```

становится:

```python
if True:
```

и код выполняется.

---

### 3. Что происходит при импорте

Есть файл:

```text
project/
├── main.py
└── utils.py
```

`utils.py`:

```python
print(f"Module name: {__name__}")
```

`main.py`:

```python
import utils
```

Запускаем:

```bash
python main.py
```

В `main.py`:

```text
__name__ == "__main__"
```

А в `utils.py`:

```text
__name__ == "utils"
```

Поэтому Python понимает, какой модуль является точкой входа.

---

### 4. Зачем нужен `if __name__ == "__main__"`

Без этой конструкции:

```python
# calculator.py

def add(a, b):
    return a + b


print(add(2, 3))
```

при импорте:

```python
import calculator
```

Python выполнит:

```python
print(add(2, 3))
```

Хотя мы хотели только получить функцию `add`.

Лучше:

```python
# calculator.py

def add(a, b):
    return a + b


if __name__ == "__main__":
    print(add(2, 3))
```

Теперь:

```python
import calculator
```

не запускает демонстрационный код.

---

### 5. Типичный паттерн `main()`

В небольших приложениях часто делают отдельную функцию:

```python
def main():
    print("Application started")
    # основная логика


if __name__ == "__main__":
    main()
```

Получается:

```text
файл
├── функции
├── классы
├── константы
└── точка входа
    └── main()
```

Это делает структуру программы более явной.

---

### 6. Почему не написать код сразу

Можно написать:

```python
print("Hello")


if __name__ == "__main__":
    ...
```

Но часто лучше помещать основную логику в `main()`:

```python
def main():
    print("Hello")


if __name__ == "__main__":
    main()
```

Преимущества:

* проще тестировать;
* проще переиспользовать код;
* меньше побочных эффектов при импорте;
* явно выделена точка входа.

---

### 7. Функции и классы всё равно импортируются

Важно понимать: `if __name__ == "__main__"` **не запрещает импортировать сам файл**.

Например:

```python
# app.py

def add(a, b):
    return a + b


def main():
    print(add(2, 3))


if __name__ == "__main__":
    main()
```

Другой файл:

```python
from app import add
```

может использовать:

```python
print(add(10, 20))
```

Но:

```python
main()
```

автоматически не запускается.

---

### 8. Что происходит с кодом верхнего уровня

При импорте Python всё равно выполняет **код модуля верхнего уровня**.

Например:

```python
print("Importing module")


def add(a, b):
    return a + b


if __name__ == "__main__":
    print("Running application")
```

При:

```python
import module
```

будет:

```text
Importing module
```

но:

```text
Running application
```

не появится.

Поэтому `if __name__ == "__main__"` используют для отделения исполняемой части от импортируемой.

---

### 9. `__name__` и импортируемые модули

Можно проверить:

```python
print(__name__)
```

В разных ситуациях:

| Как используется файл      | `__name__`   |
| -------------------------- | ------------ |
| `python app.py`            | `"__main__"` |
| `import app`               | `"app"`      |
| `python -m package.module` | `"__main__"` |

Последний случай особенно важен.

При запуске:

```bash
python -m package.module
```

модуль выполняется как главный модуль, поэтому внутри него:

```python
__name__ == "__main__"
```

---

### 10. `__main__.py`

Python также поддерживает специальный файл:

```text
package/
├── __init__.py
└── __main__.py
```

Тогда можно выполнить пакет:

```bash
python -m package
```

Python запустит:

```text
package/__main__.py
```

Это другой, но связанный механизм.

Можно представить:

```text
__name__ == "__main__"
        │
        ├── python app.py
        ├── python -m package.module
        └── python -m package
                         ↓
                    __main__.py
```

---

### 11. Почему это особенно полезно для CLI

Для консольных приложений типичная структура:

```python
def main():
    # парсинг аргументов
    # выполнение программы
    ...


if __name__ == "__main__":
    main()
```

Например:

```python
import argparse


def main():
    parser = argparse.ArgumentParser()
    parser.parse_args()

    print("Application started")


if __name__ == "__main__":
    main()
```

При этом `main()` можно отдельно тестировать.

---

### 12. Связь с тестированием

Представим:

```python
def calculate(a, b):
    return a + b


def main():
    print(calculate(2, 3))


if __name__ == "__main__":
    main()
```

Тест может импортировать:

```python
from app import calculate
```

и проверить:

```python
assert calculate(2, 3) == 5
```

При импорте `main()` автоматически не запускается.

Это одна из причин, почему такой паттерн удобен для тестируемого кода.

---

### 13. Частая ошибка

❌ Неправильно понимать конструкцию как:

> «Это специальный синтаксис для запуска программы».

Точнее:

> Это обычная проверка значения специальной переменной `__name__`.

То есть:

```python
if __name__ == "__main__":
```

буквально означает:

> Если текущий модуль является главным выполняемым модулем — выполни следующий код.

---

### 14. Частая ошибка №2

Нужно использовать именно:

```python
if __name__ == "__main__":
```

а не:

```python
if name == "main":
```

Именно двойные подчёркивания являются частью специальных имён Python:

```text
__name__
__main__
```

---

### 15. Под капотом: модуль как объект

Когда Python загружает модуль, он создаёт для него объект модуля и помещает его в `sys.modules`.

У модуля есть пространство имён, где находятся специальные атрибуты, в том числе:

```python
__name__
```

Можно проверить:

```python
import sys

print(sys.modules[__name__])
```

При прямом запуске главный модуль связан с именем:

```text
__main__
```

Именно поэтому конструкция работает на уровне обычной переменной модуля, а не является отдельной конструкцией языка.

## 🎤 Вопросы на собеседовании

**Что такое `__name__`?**

Специальная переменная модуля, содержащая его имя. При непосредственном запуске файла её значение равно `"__main__"`.

**Зачем нужен `if __name__ == "__main__"`?**

Чтобы отделить код, который должен выполняться при непосредственном запуске файла, от кода, который должен быть доступен при импорте.

**Что будет при `import module`?**

Внутри `module.py`:

```python
__name__ == "module"
```

поэтому код внутри `if __name__ == "__main__"` не выполнится.

**Зачем выделять `main()`?**

Чтобы явно обозначить точку входа и отделить исполняемую логику от определений функций и классов. Это также упрощает тестирование и повторное использование.

**Что будет при `python -m module`?**

Модуль запускается как главный, поэтому внутри него:

```python
__name__ == "__main__"
```

**Что такое `__main__.py`?**

Специальный файл пакета, который выполняется при:

```bash
python -m package
```

**Формула для собеседования:**

> **`__name__` — имя текущего модуля. При прямом запуске оно равно `"__main__"`, при импорте — имени модуля. Поэтому `if __name__ == "__main__":` используют для определения точки входа и защиты исполняемого кода от запуска при импорте.**
