# Управление GC вручную

## 🎯 Ответ на собеседовании

> **В Python есть модуль `gc`, с помощью которого можно управлять циклическим сборщиком мусора: запускать сборку вручную, включать и отключать автоматический GC и получать информацию о его состоянии. Обычно вручную управлять GC не требуется.**

---

## 📦 Модуль `gc`

```python
import gc
```

---

## ▶️ Запустить сборку вручную

```python
gc.collect()
```

Запускает сборку циклического мусора.

Метод возвращает количество найденных и освобождённых объектов.

```python
collected = gc.collect()

print(collected)
```

---

## ⛔ Отключить автоматический GC

```python
gc.disable()
```

После этого автоматический циклический GC отключён.

---

## ✅ Включить обратно

```python
gc.enable()
```

---

## 🔍 Проверить состояние

```python
gc.isenabled()
```

Вернёт:

```text
True
```

или:

```text
False
```

---

## 📊 Получить статистику

Можно использовать:

```python
gc.get_count()
```

Например:

```python
print(gc.get_count())
```

Также существуют функции для получения настроек и статистики GC.

---

## ⚠️ Когда отключение может использоваться?

В обычном приложении:

> **GC лучше не отключать без причины.**

Ручное управление может быть оправдано в специализированных сценариях, например при профилировании или когда разработчик точно понимает характер создаваемых объектов.

При этом отключение GC **не отключает Reference Counting**.

То есть в CPython:

```text
gc.disable()
      ↓
циклический GC отключён
      ↓
Reference Counting продолжает работать
```

---

## 🧠 Главное

```python
import gc

gc.collect()   # запустить сборку
gc.disable()   # отключить автоматический GC
gc.enable()    # включить обратно
gc.isenabled() # проверить состояние
```

> **`gc` управляет именно циклическим сборщиком мусора, а не всей системой управления памятью Python.**
