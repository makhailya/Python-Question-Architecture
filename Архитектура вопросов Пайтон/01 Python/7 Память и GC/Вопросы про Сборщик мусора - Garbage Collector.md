Сборщик мусора (Garbage Collector)

Работает по двум механизмам:

1. Подсчёт ссылок (reference counting) — у каждого объекта есть счётчик ссылок; когда он достигает 0, объект сразу удаляется из памяти.
2. Поколенческий сборщик циклических ссылок (generational GC) — нужен, потому что подсчёт ссылок не справляется с циклами (объект A ссылается на B, B ссылается на A, но извне на них никто не ссылается — счётчики никогда не станут 0). Работает по принципу поколений: новые объекты попадают в «первое поколение»; если объект «пережил» цикл сборки — переходит в следующее поколение (всего 3 поколения). Более старые поколения проверяются реже — это оптимизация, основанная на наблюдении, что большинство объектов «умирают молодыми».

Сборщик мусора не атомарен и не потокобезопасен сам по себе — именно поэтому ему (и вообще операциям с счётчиком ссылок) нужен GIL для корректной работы в многопоточном окружении.

Методы борьбы с циклическими ссылками:

Слабые ссылки (weakref) — не увеличивают счётчик ссылок объекта. Если на объект остались только слабые ссылки — сборщик мусора удалит его.
Явный вызов gc.collect().
Архитектурно — избегать ненужных вложенных циклических структур.

# Что такое Garbage Collector в Python?

Ответ для собеседования

Garbage Collector (GC) — это механизм автоматического управления памятью в Python. В CPython основным механизмом освобождения объектов является подсчёт ссылок (reference counting), а GC дополнительно нужен для обнаружения циклических ссылок. Когда объект больше недоступен и его можно удалить, занимаемая им память освобождается. GC также использует поколенческий подход для эффективного поиска циклического мусора.

#  Как работает подсчёт ссылок?

Ответ для собеседования

В CPython у объекта есть счётчик ссылок — количество активных ссылок на этот объект. Когда создаётся новая ссылка, счётчик увеличивается, а когда ссылка удаляется — уменьшается. Когда счётчик становится равен нулю, объект больше недоступен через обычные ссылки и его можно освободить.

# Что происходит, когда счётчик ссылок объекта достигает нуля?

Ответ для собеседования

Когда в CPython счётчик ссылок становится равен нулю, объект больше не имеет активных ссылок и обычно немедленно уничтожается. При уничтожении вызывается механизм освобождения объекта, а его память возвращается Python-аллокатору. Это одна из причин, почему CPython может освобождать многие объекты сразу, без ожидания работы циклического GC.

# Как Python работает с циклическими ссылками?

Ответ для собеседования

Проблема циклических ссылок в том, что reference counting не может удалить объекты, которые ссылаются друг на друга. Например, A ссылается на B, а B на A, хотя снаружи на них уже никто не ссылается. Для таких случаев в CPython существует циклический Garbage Collector, который обнаруживает недоступные циклы и освобождает их.

# Как работает поколенческий сборщик мусора?

Ответ для собеседования

Поколенческий GC основан на идее, что большинство объектов либо быстро становятся мусором, либо живут долго. Поэтому объекты условно разделяются по поколениям, и молодые объекты проверяются чаще, чем старые. Если объект переживает сборку, он продвигается в более старшее поколение. Это позволяет не проверять постоянно все объекты программы.

# Почему существуют поколения объектов?

Ответ для собеседования

Поколения нужны для оптимизации работы Garbage Collector. Статистически большинство новых объектов живут недолго, поэтому выгоднее чаще проверять молодые объекты и реже — долгоживущие. Благодаря этому GC тратит меньше времени на объекты, которые с большой вероятностью всё равно останутся живыми.

# Что такое слабые ссылки?

Ответ для собеседования

Слабая ссылка (weak reference) — это ссылка на объект, которая не увеличивает его счётчик ссылок и не препятствует его уничтожению. Она позволяет обратиться к объекту, пока он существует, но не удерживает его в памяти. Слабые ссылки часто используют для кэшей и хранения дополнительных связей между объектами.

# Учитываются ли слабые ссылки сборщиком мусора?

Ответ для собеседования

Слабая ссылка не считается сильной ссылкой, поэтому она не препятствует уничтожению объекта. Если других сильных ссылок не осталось, объект может быть уничтожен, а weak reference станет недействительной. При обращении к ней после уничтожения объекта получим None.

# Какие ещё существуют способы борьбы с циклическими ссылками?

Ответ для собеседования

Лучший способ — по возможности проектировать код так, чтобы ненужных циклов владения вообще не возникало. Для специальных случаев можно использовать слабые ссылки (weakref), чтобы одна сторона связи не удерживала объект в памяти. Также циклы можно разрывать вручную, удаляя ссылки, когда они больше не нужны. В CPython для автоматического обнаружения таких циклов используется cyclic GC.

# Как можно вручную запустить сборку мусора?

Ответ для собеседования

Для этого используется встроенный модуль gc. Можно вызвать gc.collect(), который запускает сборку циклического мусора. Например, gc.collect() возвращает количество объектов, которые были обнаружены и освобождены. Обычно вручную вызывать GC не требуется — Python делает это автоматически.
