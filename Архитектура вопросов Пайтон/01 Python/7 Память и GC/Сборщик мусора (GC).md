# Garbage Collector (GC) в Python

## 🎯 Ответ на собеседовании

> **Garbage Collector (GC) — механизм Python, который освобождает память от объектов, которые больше не нужны.**
>
> В CPython основным механизмом является **[[Счётчик Ссылок]]**: когда количество ссылок на объект становится равным нулю, объект обычно сразу уничтожается.
>
> Но подсчёт ссылок не может самостоятельно обнаруживать **[[Циклические ссылки]]**. Поэтому в CPython есть дополнительный **циклический сборщик мусора**, который периодически ищет такие циклы и удаляет их.

---

# 📌 Что такое GC?

**Garbage Collector** — сборщик мусора.

Его задача:

> найти объекты, которые больше не используются, и освободить занятую ими память.

Например:

```python
x = [1, 2, 3]

del x
```

После `del` имя `x` больше не ссылается на список.

Если других ссылок на список нет, объект становится недостижимым.

В CPython его счётчик ссылок становится `0`, и объект обычно уничтожается сразу.

---

# 🔢 Подсчёт ссылок

CPython использует **reference counting** — подсчёт ссылок.

У объекта есть счётчик, показывающий, сколько ссылок на него существует.

Например:

```python
a = [1, 2, 3]
```

Условно:

```text
a ─────→ [1, 2, 3]

reference count = 1
```

Если:

```python
b = a
```

получаем:

```text
a ──┐
    ├──→ [1, 2, 3]
b ──┘

reference count = 2
```

Если:

```python
del a
```

остаётся:

```text
b ─────→ [1, 2, 3]

reference count = 1
```

После:

```python
del b
```

ссылок больше нет:

```text
reference count = 0
```

Объект может быть уничтожен.

---

# ♻️ Почему одного подсчёта ссылок недостаточно?

Проблема — **циклические ссылки**.

Например:

```python
a = []
b = []

a.append(b)
b.append(a)
```

Получается:

```text
a ──→ b
↑     ↓
└─────┘
```

Даже если удалить:

```python
del a
del b
```

объекты всё ещё ссылаются друг на друга.

Их внутренние счётчики ссылок не становятся `0`.

Получается **цикл**, который обычный reference counting самостоятельно не удалит.

---

# 🔄 Циклический GC

Для решения этой проблемы CPython имеет отдельный механизм — **cyclic garbage collector**.

Он ищет группы объектов, которые:

* ссылаются друг на друга;
* но больше недостижимы из программы.

Если такие объекты найдены, GC может удалить цикл.

```text
Программа больше не может достичь объектов

        ↓

GC обнаруживает цикл

        ↓

объекты удаляются

        ↓

память освобождается
```

---

# 🧬 Поколенческий GC

Циклический GC в CPython использует **поколенческий подход**.

Идея:

> **молодые объекты чаще проверяются, старые — реже.**

Почему?

Большая часть объектов становится ненужной относительно быстро.

Упрощённо:

```text
Generation 0
    ↓
новые объекты

Generation 1
    ↓
объекты, пережившие проверки

Generation 2
    ↓
долгоживущие объекты
```

Это позволяет не проверять всё множество объектов при каждом запуске GC.

---

# ⚙️ Модуль `gc`

В Python есть модуль:

```python
import gc
```

Например:

```python
gc.collect()
```

можно вручную запустить сборку циклического мусора.

Можно проверить состояние GC:

```python
gc.isenabled()
```

Отключить:

```python
gc.disable()
```

Включить:

```python
gc.enable()
```

---

# ⚠️ Важный нюанс

Не стоит говорить:

> «GC в Python освобождает всю неиспользуемую память».

Точнее:

> **В CPython память объектов в основном освобождается через подсчёт ссылок, а циклический GC занимается обнаружением циклических ссылок.**

Кроме того, освобождение памяти Python-аллокатором не обязательно означает немедленное возвращение этой памяти операционной системе.

---

# 🆚 Reference Counting vs GC

| Механизм               | Что делает                              |
| ---------------------- | --------------------------------------- |
| **Reference counting** | Отслеживает количество ссылок на объект |
| **Cyclic GC**          | Ищет недостижимые циклические структуры |
| `gc`                   | Модуль для управления cyclic GC         |

---

# 🧠 Главное для собеседования

```text
Python / CPython
       ↓
Reference Counting
       ↓
ссылок стало 0
       ↓
объект обычно уничтожается сразу
```

Но:

```text
Циклические ссылки
       ↓
reference count ≠ 0
       ↓
циклический GC
       ↓
обнаруживает недостижимый цикл
       ↓
удаляет объекты
```

### 🎤 Суперкороткая версия

> **В CPython память в основном управляется подсчётом ссылок. Когда у объекта нет ссылок, он обычно сразу уничтожается. Для циклических ссылок используется дополнительный поколенческий Garbage Collector, который периодически находит недостижимые циклы и освобождает их.**
