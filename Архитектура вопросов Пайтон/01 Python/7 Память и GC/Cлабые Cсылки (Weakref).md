# `weakref` — слабые ссылки

## 🎯 Ответ на собеседовании

> **Слабая ссылка (`weak reference`) позволяет ссылаться на объект, не увеличивая его reference count. Поэтому наличие weak reference не препятствует уничтожению объекта, когда других сильных ссылок на него больше нет.**

---

## 📌 Обычная ссылка

```python
obj = SomeClass()
a = obj
```

Здесь:

```text
obj ──┐
      ├──→ объект
a ────┘
```

`a` — сильная ссылка.

Она увеличивает количество ссылок на объект.

---

## 👻 Слабая ссылка

```python
import weakref

obj = SomeClass()
ref = weakref.ref(obj)
```

Теперь:

```text
obj ─────→ объект
             ↑
             │
          weakref
```

`weakref` **не удерживает объект от удаления**.

Если:

```python
del obj
```

объект может быть уничтожен.

---

## 🔍 Получение объекта

```python
object = ref()
```

Если объект ещё существует:

```text
object → исходный объект
```

Если объект уже уничтожен:

```python
ref()
# None
```

Поэтому:

```python
if ref() is not None:
    ...
```

---

## 📦 Где используются?

Слабые ссылки полезны, когда нужно **наблюдать или хранить связь с объектом, но не продлевать его жизнь**.

Например:

* кеши;
* observer-паттерны;
* графы объектов;
* реестры объектов;
* структуры, где не нужно владеть объектом.

В Python есть, например:

```python
weakref.WeakValueDictionary
weakref.WeakKeyDictionary
```

---

## ⚠️ Не все объекты поддерживают weak references

Например, обычный:

```python
weakref.ref(10)
```

не сработает.

Поддержка weak references зависит от типа объекта.

---

## 🧠 Главное

```text
strong reference
      ↓
удерживает объект

weak reference
      ↓
НЕ удерживает объект
```

> **Weak reference позволяет ссылаться на объект, не влияя на его время жизни.**
