# Generational GC — поколенческий сборщик мусора

## 🎯 Ответ на собеседовании

> **Generational GC — подход, при котором объекты разделяются по поколениям в зависимости от их возраста. Идея основана на предположении, что большинство молодых объектов быстро становится ненужным, поэтому молодые объекты проверяются чаще, а долгоживущие — реже.**

---

## 📌 Поколения

Традиционно GC описывают через:

```text
Generation 0
     ↓
новые объекты

Generation 1
     ↓
пережили сборку

Generation 2
     ↓
долгоживущие объекты
```

Если объект переживает сборку мусора, он может перейти в более старшее поколение.

---

## 💡 Зачем это нужно?

Представим:

```text
1 000 000 объектов
```

Большинство из них — временные:

```text
создали → использовали → больше не нужны
```

Нет смысла каждый раз подробно проверять старые объекты.

Поэтому:

```text
молодые → проверять часто
старые  → проверять реже
```

Это уменьшает стоимость работы GC.

---

## ⚠️ Важный нюанс для современного Python

В современных версиях CPython, начиная с **Python 3.14**, модель поколений была изменена: поколение 1 убрали, и остались два поколения — young и old.

Если ты готовишься именно к собеседованию на Python 3.13, актуально говорить о классической модели:

```text
0 → 1 → 2
```

---

## 🧠 Главное

> **Generational GC основан на идее: «молодые объекты умирают чаще, старые живут дольше». Поэтому молодое поколение проверяется чаще.**
