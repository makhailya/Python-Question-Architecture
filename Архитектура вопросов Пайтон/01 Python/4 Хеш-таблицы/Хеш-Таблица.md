# 🗂️ Хэш-таблица

## 🎯 Ответ на собеседовании

**Хэш-таблица** — структура данных, которая хранит пары **ключ → значение** и использует **хэш ключа** для быстрого поиска нужной позиции.

В среднем основные операции имеют сложность **O(1)**:

```text
поиск      → O(1) average
вставка    → O(1) average
удаление   → O(1) average
```

В Python хэш-таблица лежит в основе `dict` и используется также в `set`.

---

## 📌 Как работает

Допустим:

```python
users = {
    "Ilya": 31,
    "Alex": 25,
}
```

При добавлении ключа:

```python
"Ilya" → hash("Ilya") → определённый hash
```

Хэш используется для определения позиции, где искать ключ.

Упрощённо:

```text
ключ
 ↓
hash(key)
 ↓
хэш
 ↓
позиция в таблице
 ↓
поиск ключа
 ↓
значение
```

Поэтому не требуется последовательно проверять все элементы, как в списке.

---

## 🔑 `hash()`

В Python хэш можно получить:

```python
hash("Ilya")
hash(42)
hash((1, 2))
```

Объект должен быть **hashable**, чтобы использоваться как ключ `dict` или элемент `set`.

Например:

```python
hash("hello")    # ✅
hash(42)         # ✅
hash((1, 2))     # ✅

hash([1, 2, 3])  # ❌ TypeError
```

---

## 📌 Почему поиск быстрый?

Список:

```python
users = ["Alex", "Ilya", "John"]
```

При поиске `"John"` Python в худшем случае проверяет элементы последовательно:

```text
Alex → Ilya → John
```

Сложность:

```text
O(n)
```

В `dict`:

```python
users = {
    "Alex": 25,
    "Ilya": 31,
    "John": 40,
}
```

Хэш `"John"` позволяет сразу определить область поиска.

Средняя сложность:

```text
O(1)
```

---

## 💥 Коллизии

**Коллизия** возникает, когда разные ключи приводят к одной позиции в хэш-таблице.

Упрощённо:

```text
key1 → hash → позиция 5
key2 → hash → позиция 5
                  ↑
              коллизия
```

Хэш-таблица должна уметь разрешать такие ситуации.

---

## 🔄 Open Addressing

Один из способов разрешения коллизий — **открытая адресация (open addressing)**.

Если нужная позиция занята, таблица ищет другую подходящую позицию по определённому алгоритму.

Упрощённо:

```text
позиция 5 → занята
     ↓
позиция 6 → занята
     ↓
позиция 7 → свободна
```

**CPython `dict` использует open addressing**, а не классические linked-list buckets, как в некоторых реализациях хэш-таблиц.

---

## 📈 Resize

По мере заполнения таблицы эффективность поиска может снижаться.

Когда внутренняя таблица достигает определённого порога заполнения, Python выполняет **resize**:

```text
маленькая таблица
       ↓
выделяется большая таблица
       ↓
элементы перераспределяются
       ↓
продолжаем работу
```

Сам resize может занимать:

```text
O(n)
```

Но отдельные вставки в среднем остаются:

```text
O(1) amortized
```

---

## 📊 Сложность

| Операция               | Средняя | Худшая |
| ---------------------- | ------: | -----: |
| Поиск                  |    O(1) |   O(n) |
| Вставка                |    O(1) |   O(n) |
| Удаление               |    O(1) |   O(n) |
| Проверка `key in dict` |    O(1) |   O(n) |

Худший случай связан прежде всего с большим количеством коллизий.

---

## 🧩 Хэш-таблица и `dict`

Важно различать:

```text
Хэш-таблица
    ↓
структура данных / концепция

dict
    ↓
конкретная структура Python,
реализованная на основе хэш-таблицы
```

В `dict` ключ используется для вычисления хэша, а по нему находится соответствующее значение.

---

## 🧠 Важное свойство ключей

Если два объекта сравниваются как равные:

```python
a == b
```

то для корректных hashable-объектов должно выполняться:

```python
hash(a) == hash(b)
```

Но обратное **не обязательно**:

```text
hash(a) == hash(b)
        ⇏
    a == b
```

То есть одинаковый хэш ещё не означает, что объекты равны — это может быть коллизия.

---

## 🎤 Суперкоротко

> **Хэш-таблица — структура данных, которая использует хэш ключа для быстрого доступа к данным. В среднем поиск, вставка и удаление выполняются за O(1). В Python `dict` и `set` основаны на хэш-таблицах. Коллизии разрешаются специальным алгоритмом, а при заполнении таблица расширяется.**
