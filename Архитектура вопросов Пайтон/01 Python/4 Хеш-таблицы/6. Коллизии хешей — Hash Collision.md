# Коллизия хешей — Hash Collision

## Коротко

**Коллизия хешей** возникает, когда два разных ключа получают одинаковое хеш-значение.

```text
key A → hash X
key B → hash X
```

Хеш-таблица должна уметь разрешать такие ситуации, чтобы оба ключа могли существовать одновременно.

## На собеседовании достаточно сказать

Коллизия хешей возникает, когда разные ключи имеют одинаковый хеш. Хеш-таблица должна разрешить такую коллизию специальным механизмом, чтобы корректно хранить и находить оба ключа.

## Что важно помнить

Хеш не обязан быть уникальным.

Возможна ситуация:

```
A ≠ B

hash(A) == hash(B)
```

Поэтому нельзя считать, что одинаковый хеш означает равенство объектов.

При работе с dict Python учитывает не только хеш, но и само сравнение ключей.

Упрощённо поиск выглядит так:

```
ключ
 ↓
hash(key)
 ↓
поиск позиции
 ↓
проверка найденного ключа
 ↓
ключ совпал?
 ↓
получаем значение
```

## Простой пример

Представим хеш-таблицу:

```
hash("key1") → 42
hash("key2") → 42
```

Возникла коллизия:

```
"key1" ──→ 42
"key2" ──→ 42
```

Оба ключа могут существовать в словаре:

```python
data = {
    "key1": "value1",
    "key2": "value2"
}
```

Сам факт одинакового хеша не означает, что "key1" и "key2" являются одним ключом.

## Главное

### Запомни:

```
Разные объекты
      ↓
Одинаковый hash
      ↓
Коллизия
      ↓
Механизм разрешения коллизии
```

Коллизии являются нормальной ситуацией для хеш-таблиц и должны корректно обрабатываться.
