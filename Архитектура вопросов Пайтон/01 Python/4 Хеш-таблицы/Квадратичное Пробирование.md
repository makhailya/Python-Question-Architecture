# 🔢 Квадратичное пробирование

## 🎤 Короткий ответ

**Квадратичное пробирование (quadratic probing)** — это способ разрешения коллизий в хеш-таблице с открытой адресацией, при котором после коллизии новые позиции проверяются с **квадратически увеличивающимся шагом**.

Вместо последовательного:

```python
i → i+1 → i+2 → i+3
```

используется, например:

```python
i → i+1² → i+2² → i+3² → ...
```

Главное преимущество — **уменьшает первичную кластеризацию** по сравнению с линейным пробированием.

---

## 🎯 Формула для собеседования

```python
index = (hash(key) + c1 * step + c2 * step**2) % table_size
```

Частый упрощённый вариант:

```python
index = (hash(key) + step**2) % table_size
```

где:

```python
step = 0, 1, 2, 3, ...
```

Логика:

```python
Коллизия
   ↓
+1²
   ↓
+2²
   ↓
+3²
   ↓
+4²
   ↓
...
```

---

# 1. Как работает

Предположим, размер таблицы:

```python
10
```

Хеш дал исходный индекс:

```python
5
```

Ячейка `5` занята.

При квадратичном пробировании проверяем:

```python
step = 0 → 5
step = 1 → (5 + 1²) % 10 = 6
step = 2 → (5 + 2²) % 10 = 9
step = 3 → (5 + 3²) % 10 = 4
step = 4 → (5 + 4²) % 10 = 1
```

Получается последовательность:

```python
5 → 6 → 9 → 4 → 1 → ...
```

В отличие от линейного:

```python
5 → 6 → 7 → 8 → 9 → ...
```

---

# 2. Зачем оно нужно

Главная задача — **уменьшить первичную кластеризацию**.

При линейном пробировании:

```python
[ ] [X] [X] [X] [X] [X] [ ] [ ] [ ]
```

образуются длинные последовательные блоки.

Квадратичное пробирование распределяет следующие попытки менее линейно:

```python
i
 ↓
i + 1²
 ↓
i + 2²
 ↓
i + 3²
```

Поэтому вероятность формирования именно **непрерывного кластера** ниже.

---

# 3. Сравнение с линейным пробированием

### Линейное

```python
i → i+1 → i+2 → i+3 → i+4
```

### Квадратичное

```python
i → i+1² → i+2² → i+3² → i+4²
```

Например, если `i = 5` и размер таблицы `10`:

```python
Линейное:
5 → 6 → 7 → 8 → 9 → 0

Квадратичное:
5 → 6 → 9 → 4 → 1 → ...
```

---

# 4. Первичная кластеризация

При линейном пробировании разные ключи могут быстро объединяться в один длинный кластер.

Например:

```python
Ключ A: 5 → 6 → 7 → 8
Ключ B: 6 → 7 → 8 → 9
Ключ C: 7 → 8 → 9 → 0
```

Они используют соседние ячейки:

```python
[ ] [ ] [ ] [ ] [ ] [A] [B] [C] [D] [ ] 
                         └──────────┘
                            кластер
```

Квадратичное пробирование раздвигает последовательность:

```python
5 → 6 → 9 → 4 → 1 → ...
```

Поэтому **первичная кластеризация уменьшается**.

---

# 5. Но появляется вторичная кластеризация

Это главный недостаток квадратичного пробирования.

Если два ключа имеют одинаковый исходный хеш:

```python
hash(A) % M = 5
hash(B) % M = 5
```

то они будут использовать **одинаковую последовательность пробирования**:

```python
A: 5 → 6 → 9 → 4 → 1
B: 5 → 6 → 9 → 4 → 1
```

То есть они всё равно могут сталкиваться снова и снова.

Это называется:

**вторичная кластеризация (secondary clustering).**

---

# 6. Откуда берётся вторичная кластеризация

Ключевая идея:

> Квадратичное пробирование зависит от исходного индекса, но не делает последовательность уникальной для каждого ключа.

Например:

```python
hash(A) % M = 5
hash(B) % M = 5
```

Получаем:

```python
A → 5 → 6 → 9 → 4 → ...
B → 5 → 6 → 9 → 4 → ...
```

Оба ключа идут по одному маршруту.

---

# 7. Как это решает двойное хеширование

При **двойном хешировании** используется второй хеш:

```python
index = (
    hash1(key) + step * hash2(key)
) % table_size
```

Поэтому:

```python
A → 5 → 8 → 1 → 4 → ...

B → 5 → 7 → 9 → 1 → ...
```

Последовательности могут отличаться.

Таким образом:

```python
Линейное
    ↓
первичная кластеризация

Квадратичное
    ↓
первичная ↓
вторичная возможна

Двойное хеширование
    ↓
кластеризация ещё сильнее уменьшается
```

---

# 8. Проблема размера таблицы

У квадратичного пробирования есть ещё один важный нюанс.

Не любая комбинация:

```python
формула + размер таблицы
```

гарантирует, что мы посетим **все ячейки таблицы**.

Можно получить последовательность, которая начнёт повторяться, хотя свободные ячейки ещё существуют.

Например:

```python
5 → 6 → 9 → 4 → 1 → 0 → ...
```

и при этом некоторые позиции таблицы могут вообще не проверяться.

Поэтому для корректной реализации важны:

* размер таблицы;
* коэффициенты `c1` и `c2`;
* конкретная формула пробирования;
* правила расширения таблицы.

На собеседовании лучше не говорить, что квадратичное пробирование **всегда** гарантирует поиск свободной ячейки.

---

# 9. Load Factor

Квадратичное пробирование, как и другие варианты открытой адресации, чувствительно к заполнению таблицы.

Формула:

```python
α = N / M
```

где:

* `N` — количество элементов;
* `M` — количество слотов.

Чем выше:

```python
α ↑
```

тем меньше свободных ячеек и тем больше пробирований.

Поэтому при достижении определённого порога выполняют:

```python
Resize
   ↓
увеличение таблицы
   ↓
Rehash
   ↓
перераспределение элементов
```

Конкретный порог зависит от реализации.

---

# 10. Сложность

При хорошем распределении хешей и разумном Load Factor:

```python
Поиск      → O(1) в среднем
Вставка    → O(1) в среднем
Удаление   → O(1) в среднем
```

В худшем случае:

```python
O(n)
```

Например, если возникает большое количество коллизий и пробирование вынуждено проверять множество позиций.

---

# 11. Удаление

Как и при линейном пробировании, нельзя просто сделать:

```python
table[index] = None
```

потому что это может прервать цепочку поиска.

Обычно используется специальный маркер:

```python
DELETED
```

Например:

```python
[ ] [A] [B] [C] [ ] 
```

после удаления `A`:

```python
[ ] [DELETED] [B] [C] [ ]
```

При поиске `B` или `C` пробирование продолжается через `DELETED`.

---

# 12. Сравнение способов пробирования

| Метод               | Последовательность    | Кластеризация                             |
| ------------------- | --------------------- | ----------------------------------------- |
| Линейное            | `i+1, i+2, i+3...`    | Первичная                                 |
| Квадратичное        | `i+1², i+2², i+3²...` | Первичная уменьшается, вторичная возможна |
| Двойное хеширование | шаг задаёт второй хеш | Обычно меньше кластеризации               |

---

```python
Линейное:

i → i+1 → i+2 → i+3
       ↓
первичная кластеризация
```

```python
Квадратичное:

i → i+1² → i+2² → i+3²
       ↓
первичная кластеризация уменьшается
       ↓
но вторичная возможна
```

### 🎤 Идеальная формулировка на собеседовании

> **Квадратичное пробирование — это способ разрешения коллизий при открытой адресации, при котором следующие позиции вычисляются с использованием квадратичной функции от номера попытки. Оно уменьшает первичную кластеризацию по сравнению с линейным пробированием, но может приводить к вторичной кластеризации, когда ключи с одинаковым исходным индексом используют одинаковую последовательность пробирования.**
