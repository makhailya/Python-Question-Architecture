# 🔐 Двойное хеширование

## 🎤 Короткий ответ

**Двойное хеширование (double hashing)** — это способ разрешения коллизий в хеш-таблице с открытой адресацией, при котором для определения следующей позиции используются **два хеширования**.

Первый хеш определяет начальную позицию, а второй — **шаг пробирования**.

Главное преимущество — разные ключи могут получать разные последовательности пробирования, поэтому двойное хеширование значительно уменьшает кластеризацию по сравнению с линейным и квадратичным пробированием.

---

## 🎯 Формула для собеседования

```python id="k7p3mz"
index = (hash1(key) + step * hash2(key)) % table_size
```

где:

* `hash1(key)` — начальная позиция;
* `hash2(key)` — размер шага;
* `step` — номер попытки;
* `table_size` — размер таблицы.

Главная идея:

```python id="v4n8qx"
Первый хеш
    ↓
начальная позиция
    ↓
коллизия
    ↓
Второй хеш
    ↓
определяет шаг
    ↓
следующая позиция
```

---

# 1. Зачем нужно двойное хеширование

Предположим, два ключа попали в одну ячейку:

```python id="2f8kqm"
hash1(A) % 10 = 5
hash1(B) % 10 = 5
```

При квадратичном пробировании оба могут использовать одну и ту же последовательность:

```python id="w3m6pc"
A: 5 → 6 → 9 → 4 → 1 → ...

B: 5 → 6 → 9 → 4 → 1 → ...
```

Это называется **вторичной кластеризацией**.

Двойное хеширование решает эту проблему тем, что использует второй хеш, определяющий шаг.

---

# 2. Как работает

Допустим:

```python id="r6q1vz"
table_size = 10
```

Для ключа `A`:

```python id="0n8x4m"
hash1(A) = 5
hash2(A) = 3
```

Получаем:

```python id="5h2kq7"
step = 0:
(5 + 0 * 3) % 10 = 5

step = 1:
(5 + 1 * 3) % 10 = 8

step = 2:
(5 + 2 * 3) % 10 = 1

step = 3:
(5 + 3 * 3) % 10 = 4
```

Последовательность:

```python id="x9c3lb"
5 → 8 → 1 → 4 → 7 → 0 → ...
```

---

# 3. Почему два хеша лучше одного

Теперь другой ключ `B`:

```python id="y6t1pw"
hash1(B) = 5
hash2(B) = 2
```

Начальная позиция та же:

```python id="3a9mjk"
5
```

но шаг другой:

```python id="q8v4nc"
B: 5 → 7 → 9 → 1 → 3 → ...
```

Получаем:

```python id="m2f7sd"
A: 5 → 8 → 1 → 4 → 7 → ...

B: 5 → 7 → 9 → 1 → 3 → ...
```

Ключи больше не обязаны идти по одному маршруту.

Именно это является главным преимуществом двойного хеширования.

---

# 4. Сравнение трёх способов

### Линейное

```python id="e6w2qa"
i → i+1 → i+2 → i+3 → ...
```

Проблема:

**первичная кластеризация.**

---

### Квадратичное

```python id="j4p8mz"
i → i+1² → i+2² → i+3² → ...
```

Проблема:

**вторичная кластеризация всё ещё возможна.**

---

### Двойное хеширование

```python id="c9x5vt"
i → i+h2(k) → i+2*h2(k) → i+3*h2(k) → ...
```

Преимущество:

**последовательность пробирования зависит от ключа.**

---

# 5. Почему возникает меньше кластеризации

В линейном пробировании все ключи используют одинаковый шаг:

```python id="s3m8kp"
+1
```

В квадратичном:

```python id="h7q2wd"
+1²
+2²
+3²
...
```

Но при одинаковом исходном индексе последовательность всё равно одинаковая.

В двойном:

```python id="f1n6xz"
шаг = hash2(key)
```

Поэтому разные ключи могут использовать разные маршруты.

```python id="b8v4rq"
A → шаг 3
B → шаг 5
C → шаг 7
```

Это уменьшает вероятность кластеризации.

---

# 6. Важное требование к второму хешу

Второй хеш должен быть выбран так, чтобы пробирование могло охватить **достаточное количество ячеек**, желательно всю таблицу.

Например, если размер таблицы `10`, а шаг всегда `2`:

```python id="w5c9yn"
0 → 2 → 4 → 6 → 8 → 0 → ...
```

Мы никогда не попадём в:

```python id="r3m7kx"
1, 3, 5, 7, 9
```

То есть часть таблицы вообще не проверяется.

Поэтому для корректного двойного хеширования важны свойства `hash2()` и размер таблицы.

Частый подход — выбирать размер таблицы и вторую хеш-функцию так, чтобы шаг был **взаимно прост с размером таблицы**:

```python id="a6q2pz"
gcd(hash2(key), table_size) = 1
```

Тогда последовательность способна пройти через все позиции таблицы.

---

# 7. Вставка

Допустим:

```python id="n9x4cb"
index = hash1(key) % table_size
```

Если ячейка занята:

```python id="k5m8vd"
index = (
    hash1(key) + step * hash2(key)
) % table_size
```

Проверяем:

```python id="y2q7hs"
step = 0
step = 1
step = 2
step = 3
...
```

пока не найдём свободный слот.

---

# 8. Поиск

При поиске используется **та же последовательность пробирования**, что и при вставке.

Например:

```python id="v7c3mx"
A:

5 → 8 → 1 → 4 → 7
```

Если ищем `A`, начинаем с:

```python id="d1p6kz"
5
```

и повторяем ту же последовательность:

```python id="t8n2qr"
5 → 8 → 1 → 4 → 7
```

Поэтому важно, чтобы `hash1()` и `hash2()` всегда детерминированно возвращали одинаковые значения для одного ключа.

---

# 9. Удаление

Как и при других вариантах открытой адресации, нельзя просто заменить удалённую ячейку на `None`.

Например:

```python id="q6m3vb"
[ ] [A] [B] [C] [ ] [ ]
```

Если удалить `A`:

```python id="x9k2fd"
[ ] [ ] [B] [C] [ ] [ ]
```

поиск `B` может остановиться на пустой ячейке.

Поэтому используется специальный маркер:

```python id="m4z8cp"
DELETED
```

```python id="h1v7qn"
[ ] [DELETED] [B] [C] [ ] [ ]
```

Поиск продолжает пробирование через `DELETED`.

---

# 10. Load Factor

Как и другие методы открытой адресации, двойное хеширование зависит от коэффициента заполнения:

```python id="p5x9md"
α = N / M
```

где:

* `N` — количество элементов;
* `M` — размер таблицы.

При росте:

```python id="e3q7vw"
α ↑
   ↓
свободных ячеек ↓
   ↓
пробирований ↑
   ↓
производительность ↓
```

Поэтому при достижении определённого порога выполняют:

```python id="u8k1zr"
Resize
   ↓
Rehash
   ↓
перераспределение элементов
```

---

# 11. Сложность

При хорошем хешировании и разумном Load Factor:

```python id="c4n7xy"
Поиск      → O(1) в среднем
Вставка    → O(1) в среднем
Удаление   → O(1) в среднем
```

В худшем случае:

```python id="s2m6qp"
O(n)
```

Если возникает большое количество коллизий или таблица сильно заполнена.

---

# 12. Двойное хеширование vs квадратичное

|                           | Квадратичное                  | Двойное                                            |
| ------------------------- | ----------------------------- | -------------------------------------------------- |
| Шаг                       | зависит от `step²`            | зависит от второго хеша                            |
| Одинаковый старт          | одинаковая последовательность | разные ключи могут иметь разные последовательности |
| Первичная кластеризация   | уменьшается                   | уменьшается                                        |
| Вторичная кластеризация   | возможна                      | значительно уменьшается                            |
| Реализация                | проще                         | сложнее                                            |
| Требования к хеш-функциям | умеренные                     | важны свойства `hash2()`                           |

---

# 13. Связь с Python

`dict` и `set` в CPython используют **открытую адресацию**, однако конкретная внутренняя схема пробирования является деталью реализации CPython.

Поэтому на собеседовании не стоит говорить:

> Python `dict` использует именно двойное хеширование.

Корректнее:

> В Python `dict` и `set` основаны на хеш-таблицах с открытой адресацией. Конкретный алгоритм разрешения коллизий определяется реализацией CPython и не должен автоматически отождествляться с классическим двойным хешированием.

# 🧠 Главное

Три подхода:

```python id="q4m8vz"
Линейное:
i → i+1 → i+2 → i+3
          ↓
первичная кластеризация
```

```python id="x7c2pn"
Квадратичное:
i → i+1² → i+2² → i+3²
          ↓
первичная ↓
вторичная возможна
```

```python id="k9w3rs"
Двойное:
i → i+h2(k) → i+2*h2(k) → i+3*h2(k)
          ↓
разные ключи могут иметь разные маршруты
```

### 🎤 Идеальная формулировка на собеседовании

> **Двойное хеширование — это метод разрешения коллизий при открытой адресации, где первый хеш определяет начальную позицию, а второй хеш определяет шаг пробирования. Благодаря этому разные ключи могут использовать разные последовательности поиска, что существенно уменьшает кластеризацию по сравнению с линейным и квадратичным пробированием.**
