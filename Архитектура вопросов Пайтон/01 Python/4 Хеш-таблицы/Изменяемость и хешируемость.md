# Изменяемость и хешируемость — Mutability and Hashability

## Коротко

**Изменяемость (mutability)** — способность объекта изменять своё содержимое после создания.

**Хешируемость (hashability)** — способность объекта иметь стабильное хеш-значение, которое можно получить через `hash()` и использовать объект, например, ключом `dict` или элементом `set`.

Важная связь:

> Изменяемый объект обычно не может быть хешируемым, потому что его содержимое может измениться, а значит, изменился бы и его хеш.

Примеры:

```text
list      → изменяемый      → нехешируемый
dict      → изменяемый      → нехешируемый
set       → изменяемый      → нехешируемый

tuple     → неизменяемый    → может быть хешируемым
str       → неизменяемый    → хешируемый
int       → неизменяемый    → хешируемый
frozenset → неизменяемый    → хешируемый
```

## На собеседовании достаточно сказать

> Изменяемость означает, что объект можно изменить после создания. Хешируемость означает, что объект имеет стабильный хеш и может использоваться, например, ключом словаря или элементом множества. Изменяемые объекты, такие как `list` и `dict`, обычно не хешируются, потому что изменение их содержимого нарушило бы стабильность хеша.

## Что важно помнить

### Изменяемые объекты

Изменяемый объект можно изменить без создания нового объекта.

Например:

```python
items = [1, 2, 3]

items.append(4)

print(items)
```

Результат:

```text
[1, 2, 3, 4]
```

Сам список остался тем же объектом — изменилось его содержимое.

К типичным изменяемым объектам относятся:

```text
list
dict
set
```

---

### Неизменяемые объекты

Неизменяемый объект нельзя изменить после создания.

Например:

```python
x = 10
x = x + 1
```

Здесь объект `10` не изменяется.

Создаётся объект со значением `11`, а имя `x` перепривязывается к нему:

```text
x ───> 10

после x = x + 1:

x ───> 11
```

К типичным неизменяемым объектам относятся:

```text
int
float
bool
str
tuple
frozenset
NoneType
```

## Что такое хеш

Хеш — это числовое значение, которое Python получает для объекта с помощью функции `hash()`:

```python
x = "hello"

print(hash(x))
```

Например, результат может выглядеть так:

```text
-123456789012345678
```

Конкретное значение хеша не нужно запоминать.

Важно понимать сам принцип:

```text
объект
   ↓
hash()
   ↓
числовое значение
```

---

## Какие объекты хешируемые

Можно проверить объект самостоятельно:

```python
print(hash(10))
print(hash("hello"))
print(hash((1, 2, 3)))
```

Эти объекты хешируемые.

А вот:

```python
hash([1, 2, 3])
```

приведёт к:

```text
TypeError: unhashable type: 'list'
```

Потому что `list` — изменяемый объект.

---

## Почему list нельзя использовать ключом dict

Словарь использует хеш ключа для быстрого поиска.

Например:

```python
users = {
    "Ilya": 31
}
```

Для строки `"Ilya"` можно получить стабильный хеш:

```python
hash("Ilya")
```

Но если бы ключом был изменяемый список:

```python
[1, 2, 3]
```

его содержимое можно было бы изменить:

```python
[1, 2, 3]
    ↓
[1, 2, 3, 4]
```

Тогда его хеш потенциально изменился бы.

Это нарушило бы работу хеш-таблицы.

Поэтому:

```python
data = {
    [1, 2, 3]: "value"
}
```

нельзя.

Python выдаст:

```text
TypeError: unhashable type: 'list'
```

## Хешируемость и dict

Ключ словаря должен быть хешируемым:

```python
data = {
    "name": "Ilya",
    42: "answer",
    (1, 2): "tuple"
}
```

Здесь ключи:

```text
str
int
tuple
```

могут быть хешируемыми.

А такие ключи нельзя использовать:

```python
data = {
    [1, 2]: "value"
}
```

или:

```python
data = {
    {"a": 1}: "value"
}
```

Потому что `list` и `dict` нехешируемые.

---

## Хешируемость и set

То же правило действует для `set`.

Элементы множества должны быть хешируемыми:

```python
numbers = {1, 2, 3}
```

Можно добавить строку:

```python
numbers.add("hello")
```

Но нельзя добавить список:

```python
numbers.add([1, 2, 3])
```

Получим:

```text
TypeError: unhashable type: 'list'
```

Поэтому вместо `list` можно использовать `tuple`, если его содержимое тоже хешируемо:

```python
numbers = {
    (1, 2, 3)
}
```

## Не каждый неизменяемый объект обязательно хешируемый

Это важный нюанс.

Часто говорят:

> Неизменяемый объект → хешируемый.

Но это не всегда так.

Например:

```python
data = ([1, 2], [3, 4])
```

Сам `tuple` неизменяемый, но внутри него находятся изменяемые списки.

Попробуем:

```python
hash(data)
```

Получим ошибку:

```text
TypeError: unhashable type: 'list'
```

Почему?

Потому что хешируемость зависит не только от внешнего объекта, но и от его содержимого.

Например:

```python
hash((1, 2, 3))
```

работает.

А:

```python
hash(([1, 2], 3))
```

не работает.

Формула:

> `tuple` может быть хешируемым только тогда, когда все его элементы тоже хешируемы.

## Связь между mutability и hashability

Можно представить так:

```text
Изменяемый объект
       ↓
может измениться
       ↓
его содержимое может измениться
       ↓
хеш не будет стабильным
       ↓
нельзя безопасно использовать как ключ dict / элемент set
```

Поэтому:

```text
list      → mutable   → unhashable
dict      → mutable   → unhashable
set       → mutable   → unhashable
```

А:

```text
str       → immutable → hashable
int       → immutable → hashable
tuple     → immutable → hashable*
frozenset → immutable → hashable*
```

`*` — при условии, что содержимое также хешируемо.

---

## Простой пример

```python
numbers = [1, 2, 3]

print(hash(numbers))
```

Получим ошибку:

```text
TypeError: unhashable type: 'list'
```

Теперь используем кортеж:

```python
numbers = (1, 2, 3)

print(hash(numbers))
```

Работает, потому что все элементы кортежа — числа, а числа хешируемы.

Можно использовать его как ключ:

```python
data = {
    (1, 2, 3): "numbers"
}
```

## Главное

Нужно разделять два понятия.

### Mutability

Можно ли изменить объект?

```text
list  → да
dict  → да
set   → да

str   → нет
int   → нет
tuple → нет
```

### Hashability

Можно ли получить стабильный хеш и использовать объект в хеш-таблице?

```python
hash(obj)
```

Хешируемые объекты могут использоваться:

```python
# как ключ dict
data = {
    obj: value
}

# как элемент set
items = {
    obj
}
```

Главная формула:

```text
mutable
→ содержимое можно изменить
→ хеш не может быть стабильным
→ объект обычно unhashable

immutable
→ содержимое нельзя изменить
→ объект может быть hashable
```

Но:

> **Неизменяемость сама по себе не гарантирует хешируемость.**

Для составных объектов важно, чтобы их внутренние элементы тоже были хешируемыми.
