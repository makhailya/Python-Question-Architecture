# Почему list нельзя использовать ключом dict — Why List Is Unhashable

## Коротко

`list` нельзя использовать как ключ `dict`, потому что список является **изменяемым (mutable)** и поэтому **нехешируемым (unhashable)**.

Ключ словаря должен быть хешируемым, чтобы его хеш не менялся после добавления в словарь.

## На собеседовании достаточно сказать

> `list` нельзя использовать как ключ `dict`, потому что список изменяемый и не является хешируемым. Ключ словаря должен быть хешируемым, чтобы его хеш оставался стабильным.
>
> Поэтому `str`, `int` и подходящий `tuple` могут быть ключами, а `list`, `dict` и `set` — нет.

## Что важно помнить

Представим, что список можно было бы использовать как ключ:

```python
numbers = [1, 2, 3]

data = {
    numbers: "values"
}
```

А потом список изменился:

```python
numbers.append(4)
```

Получилось бы:

```
до изменения:

[1, 2, 3] → hash X

после изменения:

[1, 2, 3, 4] → другой hash
```

Словарь больше не смог бы надёжно найти ключ в той позиции, которая была определена первоначальным хешем.

Поэтому изменяемые объекты вроде list не являются хешируемыми.

## Простой пример

Список нельзя использовать как ключ:

```python
data = {
    [1, 2, 3]: "numbers"
}

# TypeError: unhashable type: 'list'
```

А кортеж можно, если его элементы тоже хешируемые:

```python
data = {
    (1, 2, 3): "numbers"
}

print(data[(1, 2, 3)])
# numbers
```

## Главное

Связь можно запомнить так:

```
list
 ↓
mutable
 ↓
unhashable
 ↓
нельзя использовать как ключ dict
```

А для tuple:

```
tuple
 ↓
immutable
 ↓
может быть hashable
 ↓
может быть ключом dict
```

Но важно: не всякий immutable-объект автоматически является подходящим ключом. Например, tuple с нехешируемым элементом тоже будет нехешируемым:

```
value = ([1, 2], 3)

hash(value)
# TypeError
```
