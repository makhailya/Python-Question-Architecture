# 🔒 Deadlock — взаимная блокировка

## 🎯 Ответ на собеседовании

**Deadlock (взаимная блокировка)** — ситуация, когда две или более задачи **навсегда ждут освобождения ресурсов друг другом**, поэтому ни одна из них не может продолжить выполнение.

Классический пример:

```text
Поток A захватил Lock 1 → ждёт Lock 2
Поток B захватил Lock 2 → ждёт Lock 1

        ↓

A ждёт B
B ждёт A

        ↓

     DEADLOCK
```

---

## 📌 Пример в Python

```python
import threading

lock1 = threading.Lock()
lock2 = threading.Lock()


def task1():
    with lock1:
        with lock2:
            print("Task 1")


def task2():
    with lock2:
        with lock1:
            print("Task 2")
```

Если `task1` и `task2` выполняются одновременно:

```text
Task 1 → захватил lock1
Task 2 → захватил lock2

Task 1 → ждёт lock2
Task 2 → ждёт lock1
```

Ни один поток не может продолжить.

---

## 🔄 Четыре условия возникновения Deadlock

Классически выделяют **4 необходимых условия** (условия Коффмана):

### 1. Mutual Exclusion — взаимное исключение

Ресурс может принадлежать только одному исполнителю одновременно.

```text
Lock → занят потоком A
       ↓
       B должен ждать
```

### 2. Hold and Wait — удержание и ожидание

Поток удерживает один ресурс и одновременно ждёт другой.

```text
A → держит Lock 1
    ждёт Lock 2
```

### 3. No Preemption — отсутствие принудительного освобождения

Ресурс нельзя просто отобрать у потока.

Он должен сам освободить Lock.

### 4. Circular Wait — циклическое ожидание

Возникает цикл:

```text
A → ждёт B
B → ждёт A
```

Или более длинная цепочка:

```text
A → ждёт B
B → ждёт C
C → ждёт A
```

Если **хотя бы одно из этих условий нарушить**, deadlock невозможен.

---

## 🛡️ Как предотвратить Deadlock

### 1. Всегда захватывать Lock в одинаковом порядке

❌ Плохо:

```python
# Thread A
with lock1:
    with lock2:
        ...
```

```python
# Thread B
with lock2:
    with lock1:
        ...
```

✅ Лучше:

```python
# Thread A
with lock1:
    with lock2:
        ...
```

```python
# Thread B
with lock1:
    with lock2:
        ...
```

Теперь циклического ожидания не возникает.

---

### 2. Использовать timeout

```python
if lock.acquire(timeout=1):
    try:
        ...
    finally:
        lock.release()
```

Если Lock долго не удаётся получить, поток не будет ждать бесконечно.

---

### 3. Минимизировать критические секции

Не следует удерживать Lock дольше необходимого:

```python
with lock:
    # только работа с общими данными
    update_shared_data()
```

А долгие операции, например сетевые запросы или вычисления, лучше не выполнять внутри Lock без необходимости.

## 🆚 Deadlock vs Race Condition

|                               | Race Condition                                    | Deadlock                                 |
| ----------------------------- | ------------------------------------------------- | ---------------------------------------- |
| Проблема                      | Некорректный результат                            | Выполнение останавливается               |
| Зависит от порядка выполнения | Да                                                | Да                                       |
| Типичный признак              | Неправильные данные                               | Потоки/задачи «зависли»                  |
| Причина                       | Конкурентный доступ без достаточной синхронизации | Неправильная организация блокировок      |
| Решение                       | Синхронизация                                     | Правильный порядок Lock, timeout и т. д. |

### Пример:

```text
Race Condition
A ──┐
    ├──→ counter ←──┤
B ──┘
       ↓
   потеря данных


Deadlock
A → Lock 1 → ждёт Lock 2
B → Lock 2 → ждёт Lock 1
             ↓
          зависли
```

---

## 🧠 Главное

* **Deadlock** = задачи ждут друг друга и не могут продолжить.
* Обычно возникает из-за нескольких Lock.
* Классический пример: `A → Lock1 → ждёт Lock2`, `B → Lock2 → ждёт Lock1`.
* Существует **4 условия Коффмана**.
* Основной способ профилактики — **единый порядок захвата Lock**.
* `timeout` позволяет не ждать ресурс бесконечно.
* Deadlock ≠ race condition.

### 🎤 Суперкоротко

> **Deadlock — это взаимная блокировка, когда несколько потоков удерживают ресурсы и ждут ресурсы друг друга, из-за чего выполнение останавливается. Предотвращают его единым порядком захвата блокировок, минимизацией критических секций и использованием timeout.**
