# 🧩 Виды многозадачности

## 🎤 Короткий ответ

**Многозадачность** — это способность системы выполнять несколько задач так, чтобы создавалось впечатление их одновременного выполнения или они действительно выполнялись параллельно.

Основные виды:

* **[[Конкурентность (Concurrency)]]** — несколько задач находятся в процессе выполнения и получают возможность продвигаться вперёд, но не обязательно одновременно.
* **[[Параллелизм (Parallelism)]]** — несколько задач действительно выполняются одновременно на разных ядрах CPU.
* **[[Многопоточность (Multithreading)]]** — несколько потоков выполнения внутри одного процесса.
* **[[Многопроцессность (Multiprocessing)]]** — несколько процессов, каждый со своим адресным пространством.
* **[[Асинхронность (Asyncio)]]** — задачи добровольно передают управление [[Event Loop — цикл событий]], обычно во время ожидания [[IO-bound]].

Главное: **[[Конкурентность (Concurrency)]] и [[Параллелизм (Parallelism)]] — это не одно и то же**. Конкурентность описывает организацию выполнения нескольких задач, а параллелизм — их одновременное выполнение.

---

## 🗣️ Ответ на собеседовании

Многозадачность можно рассматривать с двух основных сторон: конкурентность и параллелизм.

При **конкурентном выполнении** несколько задач могут продвигаться вперёд в одном временном промежутке, но процессор может переключаться между ними. Например, один поток выполняет задачу, затем ожидает I/O, и процессор занимается другой.

При **параллельном выполнении** две или более задачи реально выполняются одновременно, например на разных ядрах процессора.

В Python эти модели можно реализовывать разными механизмами. Для потоков используется `threading`, для отдельных процессов — `multiprocessing`, а для асинхронного I/O — `asyncio`.

При этом выбор зависит от характера нагрузки. Для I/O-bound задач часто подходят потоки или `asyncio`, потому что значительная часть времени уходит на ожидание. Для CPU-bound задач нужен настоящий параллелизм, поэтому в Python обычно рассматривают multiprocessing или другие способы вынести вычисления за пределы одного потока выполнения.

# 📚 Разбор поглубже

## 1. Что такое многозадачность

Представим две задачи:

```text
Задача A → работа → ожидание → работа
Задача B → работа → работа → ожидание
```

Система может организовать их выполнение так, чтобы пока одна задача не может продолжать работу, ресурсы использовались другой.

Например:

```text
Время →
──────────────────────────────>

Задача A: ████░░░░████
Задача B: ░░██████░░██
```

`░` — задача не выполняется в данный момент.

Это может быть **конкурентное выполнение**.

---

# 2. Конкурентность

**Concurrency** — несколько задач могут выполняться независимо и продвигаться вперёд в пересекающемся временном интервале.

При этом физически они могут не выполняться одновременно.

Например, одно CPU-ядро:

```text
Время →
────────────────────────────>

A A A B B A A B B B A
```

Процессор переключается между задачами.

Такое переключение называется **context switch**.

### Важная мысль

```text
Concurrency
    ≠
Parallelism
```

Конкурентность отвечает на вопрос:

> «Может ли система продвигать несколько задач одновременно в смысле организации работы?»

А параллелизм:

> «Выполняются ли они физически одновременно?»

---

# 3. Параллелизм

**Parallelism** — одновременное выполнение нескольких задач.

Например, есть CPU с четырьмя ядрами:

```text
Ядро 1 → Task A
Ядро 2 → Task B
Ядро 3 → Task C
Ядро 4 → Task D
```

Здесь задачи действительно могут выполняться одновременно.

Параллелизм особенно важен для **CPU-bound** задач:

```text
CPU-bound
    │
    └── вычисления
        ├── математические операции
        ├── обработка изображений
        ├── ML
        └── кодирование видео
```

---

# 4. Конкурентность без параллелизма

Это важнейший пример.

Допустим, есть одно ядро CPU и две задачи:

```text
Task A → запрос к БД
Task B → обработка другого запроса
```

A отправила запрос и ждёт ответа.

Вместо того чтобы простаивать, система выполняет B:

```text
A: ████──────████
B: ────████████──
```

Здесь задачи **конкурентны**, но одновременно на CPU выполняется только одна.

---

# 5. Параллелизм без понимания конкурентности

На многоядерном CPU:

```text
Core 1 → A █████████
Core 2 → B █████████
```

A и B реально выполняются одновременно.

Это параллелизм.

При этом с точки зрения программы всё равно приходится решать вопросы конкурентного доступа к общим ресурсам:

```text
A ──┐
    ├──► shared resource
B ──┘
```

Отсюда появляются:

* Race Condition;
* Data Race;
* Lock;
* Semaphore;
* другие механизмы синхронизации.

---

# 6. Многопоточность

**Multithreading** — несколько потоков выполнения внутри одного процесса.

```text
Process
│
├── Thread 1
├── Thread 2
├── Thread 3
└── Thread 4
```

Потоки одного процесса используют общее адресное пространство:

```text
Process
│
├── Thread A ──┐
├── Thread B ──┼──► Shared Memory
└── Thread C ──┘
```

Это удобно для совместного доступа к данным, но создаёт необходимость синхронизации.

В Python:

```python
from threading import Thread

def worker():
    print("Работа")

thread = Thread(target=worker)
thread.start()
thread.join()
```

---

# 7. Многопроцессность

**Multiprocessing** — несколько независимых процессов.

```text
Process 1
    │
    └── собственная память

Process 2
    │
    └── собственная память

Process 3
    │
    └── собственная память
```

Процессы не используют одну общую память так, как потоки одного процесса.

Для взаимодействия используются механизмы IPC:

```text
IPC
├── Queue
├── Pipe
├── SharedMemory
├── Value
├── Array
└── Manager
```

Главное преимущество для Python:

**отдельные процессы позволяют получить настоящий CPU-параллелизм независимо от GIL конкретного интерпретатора/процесса.**

---

# 8. Асинхронность

Асинхронность — модель конкурентного выполнения, при которой задача может приостановиться на операции ожидания и передать управление другим задачам.

Например:

```python
import asyncio

async def fetch_data():
    await asyncio.sleep(1)
    return "data"
```

Здесь `await` позволяет Event Loop заниматься другими готовыми задачами, пока текущая задача ожидает.

Упрощённо:

```text
Event Loop
│
├── Task A → await I/O ────────┐
│                              │
├── Task B → выполняется       │
│                              │
├── Task C → выполняется       │
│                              │
└──────────────────────────────┘
                 ↓
          I/O завершился
                 ↓
              Task A
              продолжается
```

Асинхронность особенно эффективна для большого количества **I/O-bound** операций.

# 9. I/O-bound и CPU-bound

Это одно из ключевых разделений.

## I/O-bound

Большая часть времени уходит на ожидание внешнего ресурса:

```text
I/O-bound
├── HTTP-запросы
├── База данных
├── Файлы
├── Сокеты
└── Сетевые операции
```

Например:

```text
отправить HTTP-запрос
       ↓
     WAIT
       ↓
получить ответ
```

В это время CPU может заниматься другими задачами.

Для таких задач часто используют:

```text
asyncio
threading
```

---

## CPU-bound

Большая часть времени уходит непосредственно на вычисления:

```text
CPU-bound
├── сложные вычисления
├── обработка изображений
├── ML
├── сжатие
└── кодирование
```

Здесь ожидания почти нет:

```text
Task
████████████████████████
      CPU работает
```

Для получения параллелизма обычно рассматривают:

```text
multiprocessing
```

или специализированные библиотеки/механизмы, которые выполняют вычисления вне ограничений одного Python-потока.

# 11. Почему это важно для Python Backend

Типичная backend-система одновременно обрабатывает множество запросов:

```text
Client A ──►
Client B ──►     Backend
Client C ──►
Client D ──►
```

Каждый запрос может:

```text
получить запрос
      ↓
проверить данные
      ↓
запросить БД
      ↓
дождаться ответа
      ↓
обработать результат
      ↓
вернуть ответ
```

Если каждый запрос блокирует процесс на ожидании БД или сети, ресурсы используются неэффективно.

Поэтому backend-разработчику важно понимать:

```text
Concurrency
     ↓
Threads / Asyncio / Processes
     ↓
I/O-bound / CPU-bound
     ↓
GIL
     ↓
Synchronization
```

## 🎤 Вопросы на собеседовании

### Что такое многозадачность?

Способность системы организовывать выполнение нескольких задач, позволяя им продвигаться вперёд в одном временном интервале или выполнять их параллельно.

### Чем concurrency отличается от parallelism?

**Concurrency** — про организацию одновременного прогресса нескольких задач.

**Parallelism** — про физическое одновременное выполнение нескольких задач.

### Может ли быть concurrency без parallelism?

Да.

Например, на одном CPU-ядре процессор переключается между несколькими задачами.

### Что такое multithreading?

Выполнение нескольких потоков внутри одного процесса.

### Что такое multiprocessing?

Выполнение нескольких независимых процессов, обычно с отдельными адресными пространствами.

### Что такое asyncio?

Модель асинхронной конкурентности, в которой Event Loop переключается между задачами, когда текущая задача ожидает неблокирующую операцию.

### Что лучше для I/O-bound?

Часто подходят `asyncio` или `threading`, в зависимости от архитектуры и используемых библиотек.

### Что лучше для CPU-bound?

Для настоящего параллелизма обычно рассматривают multiprocessing или вычисления в специализированных нативных библиотеках.

### Что такое context switch?

Переключение процессора с выполнения одного потока/процесса на другой.

При переключении сохраняется состояние текущего выполнения и загружается состояние следующего.

### Можно ли сказать, что многопоточность = параллелизм?

Нет.

Многопоточность — это **механизм организации нескольких потоков**, а параллелизм — **свойство выполнения нескольких задач одновременно**.

## 🎯 Ответ на собеседовании

**Многозадачность (concurrency)** — способность системы организовывать выполнение нескольких задач так, чтобы они могли **прогрессировать независимо друг от друга**.

В Python основные подходы:

1. [[Многопроцессность (Multiprocessing)]]
2. [[Многопоточность (Multithreading)]]
3. [[Асинхронность (Asyncio)]]

Важно:

> **Многозадачность ≠ обязательно параллельное выполнение.**

Задачи могут выполняться одновременно на разных ядрах (**parallelism**) или быстро переключаться между собой на одном ядре (**concurrency**).

---

## 1. ⚙️ Многопроцессность

Несколько **процессов**, каждый со своей памятью и своим Python-интерпретатором.

```text
Process 1 → CPU Core 1
Process 2 → CPU Core 2
Process 3 → CPU Core 3
```

### Подходит для

**CPU-bound** задач:

* тяжёлые вычисления;
* обработка изображений;
* ML;
* кодирование;
* большие вычисления.

### Пример

```python
from multiprocessing import Process

p1 = Process(target=task1)
p2 = Process(target=task2)

p1.start()
p2.start()
```

### Особенности

* отдельная память;
* можно использовать несколько CPU-ядер;
* обход ограничения GIL для Python-кода;
* больше накладных расходов, чем у потоков.

---

## 2. 🧵 Многопоточность

Несколько **потоков внутри одного процесса**.

```text
Process
├── Thread 1
├── Thread 2
└── Thread 3
```

Потоки используют общую память процесса.

### Подходит для

**I/O-bound** задач:

* HTTP-запросы;
* работа с файлами;
* сетевые операции;
* ожидание внешних сервисов.

### Пример

```python
import threading

t1 = threading.Thread(target=task1)
t2 = threading.Thread(target=task2)

t1.start()
t2.start()
```

### Особенности

* общая память;
* дешевле процессов;
* проще обмениваться данными;
* нужны механизмы синхронизации;
* в обычном GIL-enabled CPython несколько потоков не дают полноценного параллелизма для Python-кода, ограниченного CPU.

---

## 3. 🔄 Асинхронность

Несколько задач выполняются **конкурентно внутри одного потока** благодаря Event Loop.

```text
Event Loop
    ↓
Task 1 → await → Task 2 → await → Task 3
                     ↓
                 Task 1 готова
                     ↓
                 Task 1 → продолжение
```

### Подходит для

**I/O-bound** задач:

* HTTP;
* WebSocket;
* базы данных;
* сетевые сервисы;
* большое количество одновременных соединений.

### Пример

```python
import asyncio

async def task():
    await asyncio.sleep(1)

async def main():
    await asyncio.gather(
        task(),
        task(),
        task(),
    )

asyncio.run(main())
```

### Особенности

* обычно один поток;
* Event Loop управляет задачами;
* переключение происходит в точках `await`;
* небольшие накладные расходы;
* блокирующий код может заблокировать весь Event Loop.

# 🧠 Concurrency vs Parallelism

Это **очень важное различие**.

### Concurrency — конкурентность

Несколько задач могут прогрессировать, но не обязательно выполняются одновременно.

```text
CPU:
A → B → A → C → B → A
```

### Parallelism — параллелизм

Несколько задач реально выполняются **одновременно**, например на разных ядрах.

```text
Core 1 → A A A A
Core 2 → B B B B
Core 3 → C C C C
```

Получается:

```text
Concurrency → организация совместного прогресса задач
Parallelism → одновременное выполнение
```

# 🔥 Как выбрать подход?

```text
                 Какая задача?
                       │
            ┌──────────┴──────────┐
            │                     │
         CPU-bound             I/O-bound
            │                     │
            ↓                     ↓
    multiprocessing       ┌──────┴──────┐
                           │             │
                       asyncio       threading
```

### Примеры

**100 HTTP-запросов:**

```text
→ asyncio
```

**Обработка 10 больших изображений:**

```text
→ multiprocessing
```

**Несколько блокирующих библиотек/API:**

```text
→ threading
```
