# 🔄 Конкурентность vs параллелизм

## 🎤 Короткий ответ

**Конкурентность (concurrency)** — это способность системы работать с несколькими задачами так, чтобы их выполнение **перекрывалось во времени**. При этом задачи не обязаны выполняться одновременно.

**Параллелизм (parallelism)** — это фактическое **одновременное выполнение** нескольких задач, обычно на разных CPU-ядрах.

Простой пример:

```text
Конкурентность:
A → работа → ожидание → работа
B       → работа → ожидание → работа

Параллелизм:
CPU 1 → A A A A
CPU 2 → B B B B
```

**Concurrency отвечает на вопрос «как организовать выполнение нескольких задач», а parallelism — «как физически выполнять несколько задач одновременно».**

---

## 🗣️ Ответ на собеседовании

Конкурентность и параллелизм — это не одно и то же.

**Конкурентность** означает, что система может продвигать несколько задач, переключаясь между ними. В каждый конкретный момент задачи могут выполняться по очереди. Например, в `asyncio` одна корутина ждёт I/O через `await`, а Event Loop в это время выполняет другую.

**Параллелизм** означает, что несколько задач действительно выполняются одновременно, например на разных ядрах процессора.

Поэтому один поток Event Loop может обеспечивать конкурентность без параллелизма, а несколько процессов могут обеспечивать настоящий CPU-параллелизм.

Например, для I/O-bound нагрузки часто используют `asyncio`, потому что большую часть времени задачи ждут сеть или базу данных. Для CPU-bound нагрузки часто используют multiprocessing, чтобы распределить вычисления между ядрами.

# 📚 Разбор поглубже

## 1. Конкурентность

**Concurrency** — это организация выполнения нескольких задач, при которой они могут **продвигаться вперемешку**.

Не обязательно одновременно.

Например:

```text id="w4k8s1"
Task A: ███░░░░███░░
Task B: ░░░███░░░███
```

В определённый момент выполняется только одна задача, но система быстро переключается между ними.

### Пример

```python
def task_a():
    ...

def task_b():
    ...
```

Если система организует выполнение:

```text id="q3d9a2"
A → A → B → B → A → B
```

это конкурентное выполнение.

---

# 2. Параллелизм

**Parallelism** — это одновременное выполнение нескольких задач.

Например, если есть два CPU-ядра:

```text id="m9x2c7"
Core 1 → Task A → Task A → Task A

Core 2 → Task B → Task B → Task B
```

В один и тот же момент времени выполняются:

```text
A + B
```

Это настоящий параллелизм.

---

# 3. Главное различие

Самая полезная формулировка:

> **Concurrency — про структуру и управление несколькими задачами. Parallelism — про одновременное физическое выполнение нескольких задач.**

Можно представить так:

```text id="s8f4e2"
CONCURRENCY
──────────────────────────────→ время

A ███     ███
B    ███     ███
C       ███     ███


PARALLELISM
──────────────────────────────→ время

CPU 1   AAAAAAAA
CPU 2   BBBBBBBB
CPU 3   CCCCCCCC
```

---

# 4. Конкурентность без параллелизма

Это очень важный момент.

Можно иметь:

```text
1 CPU core
1 thread
несколько задач
```

и всё равно получить конкурентность.

Например:

```text id="k7q3p1"
A → работает
A → ждёт I/O

B → работает
B → ждёт I/O

C → работает
C → ждёт I/O

A → получил данные
A → продолжает работу
```

Физически CPU выполняет одну задачу за раз.

Но задачи **перекрываются во времени по своему прогрессу**.

Это типичная модель `asyncio`.

---

# 5. Параллелизм без asyncio

Параллелизм можно получить вообще без асинхронного программирования.

Например:

```python
from multiprocessing import Process
```

Можно создать несколько процессов:

```text id="r2n7x4"
Process 1 → CPU core 1
Process 2 → CPU core 2
Process 3 → CPU core 3
Process 4 → CPU core 4
```

Они могут реально выполнять Python-код одновременно.

---

# 6. Asyncio — конкурентность

Рассмотрим:

```python
import asyncio


async def worker(name):
    for _ in range(3):
        print(name)
        await asyncio.sleep(1)


async def main():
    await asyncio.gather(
        worker("A"),
        worker("B"),
    )


asyncio.run(main())
```

Упрощённо:

```text id="c4n8s2"
A
↓
await

B
↓
await

A
↓
await

B
↓
await
```

Это **конкурентность**.

Не нужно говорить:

> «A и B выполняются одновременно».

Точнее:

> **A и B выполняются конкурентно в одном Event Loop.**

---

# 7. Multiprocessing — параллелизм

Например:

```python
from multiprocessing import Process
```

Если система имеет несколько CPU-ядер:

```text id="d6m1p8"
Process A ──→ Core 1
Process B ──→ Core 2
```

A и B действительно могут выполняться одновременно.

Это **параллелизм**.

---

# 8. Threading — особый случай

Многопоточность может использоваться для конкурентности:

```text id="n8s2f4"
Thread A ──┐
Thread B ──┼── конкурентное выполнение
Thread C ──┘
```

Но потоки также могут выполняться параллельно на разных ядрах — если это допускает конкретная среда выполнения и код.

Для обычного CPython с включённым GIL чистый Python bytecode нескольких потоков не выполняется одновременно на разных ядрах.

При этом I/O и некоторые C-расширения могут освобождать GIL.

Поэтому:

```text id="v5k9r2"
threading
    ↓
может дать конкурентность
    ↓
параллелизм зависит от характера работы,
реализации Python и того, освобождается ли GIL
```

---

# 9. Связь с I/O-bound

I/O-bound задачи большую часть времени:

```text
работают → ждут → работают → ждут
```

Поэтому конкурентность особенно полезна.

Например:

```text id="q8f3m1"
Task A → HTTP ────────┐
Task B → DB ───────┐  │
Task C → HTTP ──┐  │  │
                ↓  ↓  ↓
             ответы
```

Пока одна задача ждёт, можно выполнять другую.

Поэтому:

```text id="p2s7k4"
I/O-bound
    ↓
concurrency
    ↓
asyncio / threading
```

---

# 10. Связь с CPU-bound

CPU-bound задачи:

```text
вычисляют → вычисляют → вычисляют
```

Им нечего ждать.

Поэтому простая конкурентность в одном потоке не решает проблему.

Например:

```text id="a7d3f9"
Task A █████████████████
Task B ░░░░░░░░░░░░░░░░░
```

Если A занимает CPU, B просто ждёт.

Чтобы получить ускорение за счёт нескольких ядер:

```text id="x4m8q2"
Core 1 → AAAAAAAAA
Core 2 → BBBBBBBBB
```

нужен параллелизм.

Для обычного CPython CPU-bound Python-кода часто используют:

```text id="k3p7s1"
multiprocessing
ProcessPoolExecutor
```

---

# 11. Контекстное переключение

При конкурентном выполнении система должна переключаться между задачами.

Например:

```text id="m8q2v5"
A
↓
переключение
↓
B
↓
переключение
↓
C
↓
переключение
↓
A
```

Переключение имеет стоимость.

Поэтому конкурентность не означает автоматическое ускорение.

---

# 12. Кооперативная конкурентность

В `asyncio` переключение происходит **кооперативно**.

Корутина сама достигает точки:

```python
await something()
```

и позволяет Event Loop продолжить другую работу.

```text id="r5k1c8"
Task A
   ↓
await
   ↓
уступила управление
   ↓
Task B
```

Это называется:

**cooperative scheduling**.

Если корутина выполняет длинный CPU-bound код без `await`:

```python
async def bad():
    for _ in range(100_000_000):
        calculate()
```

она не уступает управление Event Loop.

---

# 13. Preemptive vs Cooperative

Полезно различать две модели.

### Cooperative

Задача сама уступает управление:

```text id="n3v7x2"
Task A
   ↓
await
   ↓
Task B
```

Характерно для:

```text
asyncio
```

### Preemptive

Планировщик может принудительно переключить выполнение.

```text id="f8q2m5"
Thread A
   ↓
планировщик
   ↓
Thread B
```

Это характерно для потоков/процессов на уровне ОС.

---

# 14. Важная формула

```text id="s4m9k1"
Concurrency
=
несколько задач могут продвигаться
за один и тот же период времени
```

```text id="j7p3d8"
Parallelism
=
несколько задач физически выполняются
в один и тот же момент
```

# 15. Сравнение

| Характеристика           | Конкурентность                  | Параллелизм                                      |
| ------------------------ | ------------------------------- | ------------------------------------------------ |
| Несколько задач          | ✅                               | ✅                                                |
| Перекрытие во времени    | ✅                               | ✅                                                |
| Одновременное выполнение | Не обязательно                  | ✅                                                |
| Нужны несколько ядер     | ❌                               | Обычно да                                        |
| `asyncio`                | ✅                               | ❌                                                |
| Multiprocessing          | Может быть                      | ✅                                                |
| Основная польза          | Эффективное управление задачами | Использование нескольких вычислительных ресурсов |
| Хороший сценарий         | I/O-bound                       | CPU-bound                                        |

# 16. Очень важный нюанс

**Concurrency и parallelism не являются взаимоисключающими понятиями.**

Система может быть одновременно:

```text id="w6r2k9"
конкурентной
      +
параллельной
```

Например:

```text
4 процесса
  ↓
каждый имеет свой Event Loop
  ↓
внутри каждого несколько async-задач
```

Тогда:

```text id="b9x4m2"
между процессами → параллелизм

внутри процесса → конкурентность
```

Это уже комбинация двух подходов.

---

# 17. Визуальная модель

### Только конкурентность

```text
1 CPU
──────────────────────────────→

A ███       ███
B    ███       ███
C       ███       ███
```

В один момент времени выполняется одна задача.

---

### Только параллельное выполнение

```text
CPU 1 ────────────────────────→
      AAAAAAAAAAAAAAAAA

CPU 2 ────────────────────────→
      BBBBBBBBBBBBBBBBBBB
```

A и B выполняются одновременно.

---

### Конкурентность + параллелизм

```text
CPU 1
  ├── A ──await── C ──await── A
  │
CPU 2
  ├── B ──await── D ──await── B
```

Здесь есть:

* параллелизм между CPU;
* конкурентность внутри каждого Event Loop.

> **Конкурентность — это способность системы продвигать несколько задач в одном временном интервале, при этом они не обязаны выполняться одновременно.
