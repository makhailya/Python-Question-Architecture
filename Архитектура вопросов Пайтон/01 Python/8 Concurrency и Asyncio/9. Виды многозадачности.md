
| Вид                                 | Что это                                                                       | Хорошо для                                                                | Плохо для                                                           |
| ----------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Многопроцессность (multiprocessing) | Несколько отдельных процессов, у каждого свой интерпретатор и своя память     | CPU-bound (математика, рендеринг)                                         | IO-bound — только тратим ресурсы на создание процессов без выигрыша |
| Многопоточность (threading)         | Несколько потоков в рамках одного процесса, управляются ОС                    | IO-bound (ожидание сети/диска)                                            | CPU-bound — GIL блокирует параллельное исполнение вычислений        |
| Асинхронность (asyncio)             | Конкурентное выполнение в одном потоке через event loop, корутины, генераторы | IO-bound, особенно много одновременных ожиданий (много запросов к API/БД) |                                                                     |
|                                     |                                                                               |                                                                           |                                                                     |

Если внутри асинхронного кода нужно выполнить синхронную (блокирующую) функцию — она заблокирует event loop, и все остальные корутины будут ждать. Решение: вынести эту функцию в отдельный поток (run_in_executor / asyncio.to_thread) либо в отдельный процесс/воркер (например, Celery).
