# 🔄 Event Loop — цикл событий

## 🎯 Ответ на собеседовании

**Event Loop (цикл событий)** — это механизм `asyncio`, который управляет выполнением асинхронных задач: запускает корутины, отслеживает операции ожидания и переключается между задачами, пока одна из них ждёт завершения I/O.

Главная идея:

> **Event Loop не выполняет несколько Python-корутин одновременно. Он быстро переключается между ними в моменты `await`, пока одна задача ждёт результат.**

---

## 📌 Как это работает

Допустим, есть две корутины:

```python
async def task1():
    print("task 1 start")
    await asyncio.sleep(2)
    print("task 1 end")


async def task2():
    print("task 2 start")
    await asyncio.sleep(1)
    print("task 2 end")
```

Запускаем:

```python
await asyncio.gather(task1(), task2())
```

Event Loop примерно делает следующее:

```text
Event Loop
    │
    ├── task1 → выполняется → await → ждёт
    │
    ├── task2 → выполняется → await → ждёт
    │
    ├── task2 → готова → продолжает выполнение
    │
    └── task1 → готова → продолжает выполнение
```

Поэтому программа не ждёт `task1` целиком перед запуском `task2`.

---

## 🔑 `await` — ключевой момент

Когда корутина встречает:

```python
await some_operation()
```

она **приостанавливает своё выполнение** и отдаёт управление Event Loop.

Event Loop в это время может запустить другую готовую задачу.

Когда ожидаемая операция завершится, Event Loop сможет продолжить выполнение первой корутины.

---

## 📌 Event Loop и Task

Обычно корутина превращается в **Task**:

```python
task = asyncio.create_task(my_coroutine())
```

Task — это объект, которым Event Loop управляет как отдельной асинхронной задачей.

Например:

```python
async def main():
    task1 = asyncio.create_task(download_1())
    task2 = asyncio.create_task(download_2())

    await task1
    await task2
```

Event Loop координирует выполнение обеих задач.

---

## 📌 Кто за что отвечает

| Компонент      | Роль                                                              |
| -------------- | ----------------------------------------------------------------- |
| `async def`    | определяет корутину                                               |
| `await`        | приостанавливает корутину и отдаёт управление                     |
| `Task`         | оборачивает корутину и позволяет планировать её выполнение        |
| **Event Loop** | управляет задачами и переключает их                               |
| I/O            | операция, во время ожидания которой можно выполнять другие задачи |

---

## ⚠️ Event Loop не делает CPU-bound код параллельным

Плохо:

```python
async def main():
    result = very_heavy_calculation()
```

Если `very_heavy_calculation()` долго выполняется синхронно, Event Loop будет заблокирован.

Другие async-задачи не смогут нормально выполняться.

Для CPU-bound задач обычно используют:

```text
multiprocessing
ProcessPoolExecutor
```

---

## ⚠️ Блокирующий код внутри async

Плохо:

```python
async def main():
    time.sleep(5)
```

`time.sleep()` блокирует поток, а значит блокируется и Event Loop.

Лучше:

```python
async def main():
    await asyncio.sleep(5)
```

Здесь Event Loop может заниматься другими задачами во время ожидания.

---

## 📌 Как запускается Event Loop

В современном Python обычно:

```python
asyncio.run(main())
```

`asyncio.run()` создаёт Event Loop, запускает `main()` и после завершения закрывает цикл.

Упрощённо:

```text
asyncio.run(main())
        ↓
создание Event Loop
        ↓
запуск main()
        ↓
планирование Task
        ↓
await → задача ждёт
        ↓
Event Loop выполняет другие задачи
        ↓
I/O завершилось
        ↓
задача продолжает выполнение
        ↓
main() завершилась
        ↓
Event Loop закрывается
```

---

## 🧠 Главное

**Event Loop — это диспетчер асинхронного выполнения.**

Он:

* запускает корутины и Task;
* следит за ожидающими операциями;
* переключается между задачами;
* не блокирует выполнение на I/O;
* работает в основном в одном потоке;
* не даёт настоящего CPU-параллелизма сам по себе.

### 🎤 Суперкоротко

> **Event Loop — это цикл событий `asyncio`, который управляет асинхронными задачами и переключается между ними, когда текущая задача ждёт I/O или другую awaitable-операцию.**
