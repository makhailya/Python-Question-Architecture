# Поток (Thread) в Python

## 🎯 Ответ на собеседовании

> **Поток (`thread`) — это единица выполнения внутри процесса. Один процесс может содержать несколько потоков, которые выполняют задачи конкурентно и используют общее адресное пространство процесса.**
>
> В CPython потоки имеют общую память процесса, поэтому они могут напрямую работать с одними и теми же объектами. Для синхронизации доступа используются `Lock`, `RLock`, `Semaphore` и другие примитивы.
>
> В обычном CPython с GIL несколько потоков не могут одновременно выполнять Python-байткод в одном процессе, поэтому `threading` чаще используют для **I/O-bound задач**.

---

# 📌 Процесс и поток

**Процесс (`process`)** — запущенный экземпляр программы со своим адресным пространством.

**Поток (`thread`)** — отдельная линия выполнения внутри процесса.

```text
Процесс
│
├── Thread 1
├── Thread 2
└── Thread 3
```

У одного процесса может быть несколько потоков.

---

# 🧠 Что общего у потоков?

Потоки одного процесса используют общие:

* объекты Python;
* память процесса;
* глобальные переменные;
* открытые файловые дескрипторы;
* другие ресурсы процесса.

Например:

```python id="2n0f8c"
counter = 0
```

Несколько потоков могут обращаться к `counter`.

Именно поэтому между потоками легко обмениваться данными.

Но возникает проблема:

> **Несколько потоков могут одновременно изменить общие данные.**

Для защиты используются механизмы синхронизации.

---

# 🧵 Создание потока

Для работы с потоками используется модуль `threading`:

```python id="3q4w8e"
import threading

def worker():
    print("Работаю")

thread = threading.Thread(target=worker)

thread.start()
thread.join()
```

### `start()`

Запускает поток.

```python id="p7j3hs"
thread.start()
```

### `join()`

Ждёт завершения потока.

```python id="c9x1az"
thread.join()
```

---

# 🔄 Конкурентность

Несколько потоков могут выполнять задачи конкурентно:

```text id="5d8r2k"
Thread 1 → работа → ожидание → работа
Thread 2 → ожидание → работа → ожидание
Thread 3 → работа → ожидание → работа
```

Это особенно полезно, когда потоки большую часть времени **ждут**:

* сеть;
* базу данных;
* файл;
* API;
* другой внешний ресурс.

---

# 🌐 I/O-bound задачи

Например, есть несколько HTTP-запросов.

```text id="7m4k2p"
Thread 1 → отправил запрос → ждёт
Thread 2 → отправил запрос → ждёт
Thread 3 → отправил запрос → ждёт
```

Пока один поток ждёт I/O, другой может выполнять работу.

Поэтому `threading` хорошо подходит для **I/O-bound** задач.

---

# 🧮 CPU-bound задачи

CPU-bound — задачи, где основное время уходит на вычисления:

```python id="j6s3hx"
for i in range(10_000_000):
    result += i ** 2
```

В обычном CPython здесь появляется ограничение **GIL**:

```text id="p9k1zm"
Thread 1 ──→ Python bytecode ←── GIL
Thread 2 ──→ ждёт
Thread 3 ──→ ждёт
```

Поэтому несколько потоков не дают настоящего параллельного выполнения CPU-bound Python-кода в одном обычном CPython-процессе.

Для CPU-bound задач обычно рассматривают **multiprocessing**.

---

# 🔒 Синхронизация потоков

Поскольку потоки имеют общую память, возможны **race condition** — ситуации, когда результат зависит от порядка выполнения потоков.

Для защиты общих данных можно использовать:

```python id="v1m8cr"
import threading

lock = threading.Lock()

with lock:
    # работа с общими данными
    ...
```

Основные примитивы:

* `Lock`
* `RLock`
* `Semaphore`
* `Event`
* `Condition`

---

# 🆚 Thread vs Process

|                             | Thread                | Process                              |
| --------------------------- | --------------------- | ------------------------------------ |
| Единица выполнения          | Поток                 | Процесс                              |
| Память                      | Общая внутри процесса | Отдельная                            |
| Создание                    | Обычно дешевле        | Обычно дороже                        |
| Обмен данными               | Относительно простой  | Требует IPC / специальных механизмов |
| CPU-bound в обычном CPython | Ограничен GIL         | ✅ Хорошо подходит                    |
| I/O-bound                   | ✅ Хорошо подходит     | ✅ Можно использовать                 |

# 🧠 Главное

```text id="g8k2pw"
Process
   ↓
┌───────────────┐
│ Thread 1      │
│ Thread 2      │
│ Thread 3      │
└───────────────┘
       ↓
  общая память
```

> **Поток — это единица выполнения внутри процесса. Потоки одного процесса разделяют память, поэтому они удобны для I/O-bound задач, но требуют синхронизации при работе с общими данными. В обычном CPython CPU-bound выполнение потоков ограничивается GIL.**

### 🎤 Суперкоротко

> **Thread — это поток выполнения внутри процесса. Несколько потоков разделяют память процесса и могут работать конкурентно. В CPython из-за GIL они не выполняют Python-байткод параллельно на нескольких ядрах, поэтому потоки особенно полезны для I/O-bound задач.**
