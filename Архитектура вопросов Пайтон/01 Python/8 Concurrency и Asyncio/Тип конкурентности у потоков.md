# 🧵 Тип конкурентности у потоков

## 🎤 Короткий ответ

**Потоки работают конкурентно** — несколько потоков могут выполнять задачи, переключаясь между собой. В CPython из-за **[[GIL — Global Interpreter Lock]]** одновременно Python-байткод обычно выполняется только одним потоком, поэтому потоки особенно полезны для **I/O-bound задач**: сеть, файлы, ожидание БД.

При этом конкурентность не обязательно означает параллельное выполнение.

---

## 🗣️ Ответ на собеседовании

В многопоточности потоки работают **конкурентно**: операционная система или среда выполнения переключает выполнение между потоками, создавая ощущение одновременной работы.

В CPython есть **GIL**, поэтому два потока не могут одновременно исполнять Python-байткод в одном процессе. Из-за этого многопоточность не даёт настоящего параллельного выполнения CPU-bound Python-кода.

Зато для **I/O-bound задач** потоки хорошо подходят: пока один поток ждёт сеть, диск или базу данных, другой поток может выполнять свою работу.

Поэтому важно различать **конкурентность** и **параллелизм**: конкурентность — это организация нескольких задач в перекрывающийся период времени, а параллелизм — фактическое одновременное выполнение на нескольких ядрах.

## 📚 Разбор поглубже

### 1. Что происходит с потоками

Представим два потока:

```python
Thread 1 → запрос к API → ждёт ответ
Thread 2 → обрабатывает данные
Thread 1 → получил ответ → продолжает работу
```

Они не обязательно выполняются одновременно.

Вместо этого выполнение может выглядеть так:

```text
Время →

Thread 1: ████░░░░████
Thread 2: ░░████████░░

          ↑
       переключение
```

Это и есть **конкурентное выполнение**.

---

### 2. Почему потоки особенно полезны для I/O

Например:

```python
def download(url):
    response = requests.get(url)
    return response
```

Если один поток ждёт ответа от сервера:

```text
Thread 1
   │
   ├── отправил HTTP-запрос
   │
   └── ждёт сеть ───────────────┐
                                │
Thread 2                        │
   │                            │
   ├── выполняет другую работу  │
   │                            │
   └────────────────────────────┘
```

Потому потоки могут хорошо ускорять выполнение множества независимых I/O-задач.

---

### 3. А что с CPU-bound

Например:

```python
def calculate():
    total = 0
    for i in range(100_000_000):
        total += i
    return total
```

Если запустить несколько таких задач в потоках CPython, GIL ограничивает одновременное выполнение Python-байткода.

Условно:

```text
CPU
│
├── Thread 1 → Python bytecode
│
└── Thread 2 → ждёт GIL
```

Поэтому для CPU-bound задач обычно рассматривают **multiprocessing**, а также другие варианты, если конкретная библиотека освобождает GIL.

---

### 4. Конкурентность ≠ параллелизм

Это один из важных моментов на собеседовании.

**Конкурентность:**

```text
Task A ────┐    ┌────
           └────┘

Task B ──┐    ┌──────
         └────┘
```

Задачи прогрессируют в перекрывающийся период времени.

**Параллелизм:**

```text
CPU 1: █████████████
CPU 2: █████████████
```

Две задачи реально выполняются одновременно на разных вычислительных ресурсах.

### Важная формулировка

> **Конкурентность — про структуру и организацию выполнения нескольких задач. Параллелизм — про физическое одновременное выполнение.**

---

### 5. Какие варианты конкурентности бывают

В Python можно встретить несколько подходов:

| Подход | Основная идея | Типичные задачи |
|---|---|---|
| `threading` | несколько потоков | I/O-bound |
| `multiprocessing` | несколько процессов | CPU-bound |
| `asyncio` | кооперативное выполнение корутин | большое количество I/O |
| `concurrent.futures` | удобная абстракция потоков/процессов | I/O и CPU |

---

### 6. Потоки и GIL

Упрощённая модель CPython:

```text
Процесс
│
├── Thread 1 ──┐
├── Thread 2 ──┼── GIL → Python bytecode
├── Thread 3 ──┘
│
└── общая память
```

Потоки одного процесса имеют **общее адресное пространство**.

Это удобно:

```python
shared_data = []

# несколько потоков могут обращаться
# к одному объекту
```

Но одновременно это создаёт проблему **состояния, разделяемого между потоками**.

Например:

```python
counter += 1
```

В многопоточном коде нельзя автоматически считать такие операции безопасными. При работе с общими изменяемыми данными могут возникать **Race Condition** и **Data Race**, поэтому используются механизмы синхронизации.

---

### 7. Что сказать, если спрашивают: «Потоки выполняются параллельно?»

Хороший ответ:

> В общем случае потоки могут выполняться параллельно на разных ядрах, но в CPython выполнение Python-байткода ограничивается GIL. Поэтому для обычного CPU-bound Python-кода потоки не дают полноценного параллелизма. Для I/O-bound задач они эффективны, потому что во время ожидания I/O выполнение может продолжаться в других потоках.

## 🎤 Вопросы на собеседовании

**1. Какой тип конкурентности используется потоками?**  
Конкурентное выполнение: несколько потоков могут продвигаться по своим задачам с переключением между ними.

**2. Потоки выполняются параллельно?**  
В CPython обычный Python-байткод ограничен GIL, поэтому полноценного параллелизма для CPU-bound Python-кода обычно нет.

**3. Почему threading подходит для I/O-bound?**  
Потому что во время ожидания I/O один поток может уступить выполнение другому.

**4. Почему threading плохо подходит для CPU-bound в CPython?**  
Из-за GIL, который ограничивает одновременное выполнение Python-байткода потоками одного процесса.

**5. Чем конкурентность отличается от параллелизма?**  
Конкурентность — несколько задач находятся в процессе выполнения в перекрывающийся период времени. Параллелизм — задачи реально выполняются одновременно.

**6. Чем потоки отличаются от процессов?**  
Потоки разделяют память процесса, процессы имеют отдельные адресные пространства. Поэтому процессы лучше подходят для CPU-bound задач в CPython, а потоки часто удобнее для I/O-bound.
