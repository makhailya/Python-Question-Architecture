# 🧵 queue.Queue — потокобезопасная очередь в Python

## 🎤 Короткий ответ

**`queue.Queue`** — потокобезопасная очередь из стандартной библиотеки Python, предназначенная для обмена данными между потоками.

Она работает по принципу **FIFO (First In, First Out)** — первым извлекается элемент, который был добавлен первым.

Основные методы:

- `put()` — добавить элемент в очередь.
- `get()` — извлечь элемент из очереди.
- `task_done()` — сообщить, что обработка элемента завершена.
- `join()` — дождаться завершения обработки всех поставленных задач.

`queue.Queue` самостоятельно обеспечивает синхронизацию между потоками, поэтому обычно не требуется дополнительно использовать `Lock` или `Condition`.

## 🗣️ Ответ на собеседовании

`queue.Queue` — это потокобезопасная очередь, которую используют для передачи задач или данных между потоками.

Чаще всего она применяется в паттерне Producer–Consumer, когда один или несколько потоков создают задачи, а другие их обрабатывают.

Например, один поток получает задания на обработку файлов и добавляет их через `put()`, а несколько рабочих потоков забирают задания через `get()`.

Если очередь пустая, `get()` может заблокировать поток до появления нового элемента. Если очередь ограничена по размеру и заполнена, `put()` может ожидать освобождения места.

Внутри `Queue` используются блокировки и условные переменные, поэтому операции добавления и извлечения безопасны при одновременном обращении нескольких потоков.

После обработки задания рабочий поток вызывает `task_done()`, а `join()` позволяет дождаться завершения всех заданий.

В Backend это полезно для организации фоновой работы внутри процесса, например обработки файлов, логов или других I/O-bound операций.

При этом `queue.Queue` не является распределённым брокером сообщений и не обеспечивает сохранность заданий после завершения процесса.

### 1. Зачем нужна Queue

Представим Backend-приложение, которое получает файлы для обработки.

Один поток принимает задания, а несколько других выполняют обработку.

Без очереди пришлось бы самостоятельно организовывать:

- Общий список заданий.
- Блокировку для безопасного доступа.
- Ожидание появления новых элементов.
- Уведомления между потоками.
- Учёт завершённых заданий.

`queue.Queue` уже реализует эти механизмы.

Схема:

```text
                 Producer
                    |
                    | put()
                    v
           ┌─────────────────┐
           │      Queue      │
           │                 │
           │  Task 1         │
           │  Task 2         │
           │  Task 3         │
           └─────────────────┘
                    |
                   get()
                    |
          ┌─────────┼─────────┐
          v         v         v
       Worker 1  Worker 2  Worker 3
          |         |         |
          v         v         v
       Обработка Обработка Обработка
          |         |         |
          v         v         v
       task_done() task_done() task_done()
```

Producer создаёт задания, Queue хранит их, Worker обрабатывает.

Это называется **Producer–Consumer (производитель–потребитель)**.

### 2. Простой пример Queue

```python
import queue
import threading
import time


tasks = queue.Queue()


def producer():
    for number in range(5):
        tasks.put(number)
        print(f"Добавлено: {number}")


def consumer():
    while True:
        try:
            item = tasks.get(timeout=1)
        except queue.Empty:
            break

        try:
            print(f"Обработка: {item}")
            time.sleep(0.5)
        finally:
            tasks.task_done()


producer_thread = threading.Thread(target=producer)
consumer_thread = threading.Thread(target=consumer)

producer_thread.start()
consumer_thread.start()

producer_thread.join()
consumer_thread.join()

tasks.join()

print("Все задания обработаны")
```

Пример результата:

```text
Добавлено: 0
Добавлено: 1
Добавлено: 2
Добавлено: 3
Добавлено: 4
Обработка: 0
Обработка: 1
Обработка: 2
Обработка: 3
Обработка: 4
Все задания обработаны
```

Разберём ключевые строки.

**`tasks = queue.Queue()`**

Создаём потокобезопасную очередь.

**`tasks.put(number)`**

Добавляем число в очередь.

**`tasks.get(timeout=1)`**

Извлекаем элемент. Если очередь пустая, ожидаем до одной секунды.

**`except queue.Empty`**

Обрабатываем ситуацию, когда за указанное время элемент не появился.

**`tasks.task_done()`**

Сообщаем очереди, что обработка извлечённого задания завершена.

**`tasks.join()`**

Ожидаем, пока счётчик незавершённых заданий не станет равен нулю.

В этом примере выход по таймауту допустим, поскольку производитель сначала завершается через `join()`, а потребитель выходит после опустошения очереди. В общем случае таймаут не следует использовать как единственный сигнал окончания производства: если задания могут появиться позже, потребитель завершится преждевременно.

### 3. FIFO — принцип работы Queue

Обычная `queue.Queue` работает по принципу FIFO.

```text
Добавление:

put(10)
put(20)
put(30)

Очередь:

┌────┬────┬────┐
│ 10 │ 20 │ 30 │
└────┴────┴────┘
  ^
  |
 get()

Извлечение:

get() → 10
get() → 20
get() → 30
```

Пример:

```python
from queue import Queue


q = Queue()

q.put("A")
q.put("B")
q.put("C")

print(q.get())
print(q.get())
print(q.get())
```

Результат:

```text
A
B
C
```

**Важно:** FIFO определяет порядок извлечения элементов, но не гарантирует порядок завершения их обработки разными потоками.

### 4. Основные методы Queue

| Метод | Назначение |
|---|---|
| `put(item)` | Добавить элемент |
| `get()` | Извлечь элемент |
| `put_nowait(item)` | Добавить без ожидания |
| `get_nowait()` | Извлечь без ожидания |
| `task_done()` | Отметить завершение обработки |
| `join()` | Дождаться обработки всех заданий |
| `qsize()` | Приблизительное количество элементов |
| `empty()` | Проверить, пуста ли очередь в момент проверки |
| `full()` | Проверить, заполнена ли очередь в момент проверки |

Методы `qsize()`, `empty()` и `full()` не подходят для принятия решений без учёта конкурентности: сразу после проверки другой поток может изменить состояние очереди.

### 5. put() — добавление элемента

```python
q.put("Задача")
```

По умолчанию `put()` блокирует поток, если очередь ограничена и заполнена.

Можно задать максимальный размер:

```python
q = queue.Queue(maxsize=3)
```

Теперь в очереди одновременно может находиться не более трёх элементов.

```python
q.put("A")
q.put("B")
q.put("C")
```

Следующий вызов:

```python
q.put("D")
```

Будет ожидать, пока другой поток не извлечёт элемент.

Это механизм **backpressure** — ограничения скорости производителя, когда потребитель не успевает обрабатывать данные.

Можно задать таймаут:

```python
try:
    q.put("D", timeout=2)
except queue.Full:
    print("Очередь заполнена")
```

Если за две секунды место не освободится, возникнет `queue.Full`.

### 6. get() — получение элемента

```python
item = q.get()
```

Если очередь пустая, поток блокируется до появления элемента.

Можно использовать таймаут:

```python
try:
    item = q.get(timeout=2)
except queue.Empty:
    print("Данных нет")
```

Или получить элемент без ожидания:

```python
try:
    item = q.get_nowait()
except queue.Empty:
    print("Очередь пуста")
```

`get_nowait()` эквивалентен `get(block=False)`.

### 7. task_done() и join()

Это важная тема для собеседования.

Когда вызывается `put()`, очередь увеличивает внутренний счётчик незавершённых заданий.

Когда вызывается `task_done()`, счётчик уменьшается.

`join()` блокирует вызывающий поток, пока счётчик не станет равен нулю.

Пример:

```python
import queue
import threading
import time


q = queue.Queue()


def worker():
    while True:
        item = q.get()

        try:
            if item is None:
                return

            print(f"Обрабатываю {item}")
            time.sleep(1)
        finally:
            q.task_done()


thread = threading.Thread(target=worker)
thread.start()

for number in range(3):
    q.put(number)

q.join()

q.put(None)
thread.join()

print("Работа завершена")
```

Здесь `None` — специальный маркер завершения работы, который называют **sentinel**.

Что происходит:

1. В очередь добавляются три задания.
2. Рабочий поток последовательно извлекает их.
3. После каждого задания вызывает `task_done()`.
4. `q.join()` дожидается обработки всех трёх заданий.
5. В очередь добавляется `None`.
6. Рабочий поток получает маркер и завершает работу.
7. `thread.join()` дожидается завершения потока.

Обрати внимание: `q.join()` и `thread.join()` — разные методы.

**`q.join()`** ожидает завершения учтённых заданий.

**`thread.join()`** ожидает завершения конкретного потока.

Если забыть `task_done()`, `q.join()` может зависнуть навсегда.

### 8. Producer–Consumer с несколькими Worker

Это классический пример многопоточной обработки.

```python
import queue
import threading
import time


tasks = queue.Queue()


def worker(worker_id):
    while True:
        item = tasks.get()

        try:
            if item is None:
                return

            print(f"Worker {worker_id}: задача {item}")
            time.sleep(1)

        finally:
            tasks.task_done()


workers = []

for worker_id in range(3):
    thread = threading.Thread(
        target=worker,
        args=(worker_id,),
    )

    thread.start()
    workers.append(thread)


for number in range(9):
    tasks.put(number)


tasks.join()


for _ in workers:
    tasks.put(None)


for thread in workers:
    thread.join()


print("Все задачи выполнены")
```

Здесь три рабочих потока обрабатывают девять заданий.

При условии, что обработка каждого задания занимает одну секунду и ожидание действительно допускает конкурентное выполнение, общее время будет примерно три секунды.

В отличие от последовательной обработки, где потребовалось бы примерно девять секунд.

**Важно:** ускорение происходит благодаря перекрытию операций ожидания. Для CPU-bound вычислений обычные потоки CPython с GIL обычно не дают аналогичного ускорения на нескольких ядрах.

### 9. Как Queue устроена внутри

Упрощённо `queue.Queue` использует:

- `mutex` — блокировку для защиты общего состояния.
- `not_empty` — условную переменную для ожидания появления элементов.
- `not_full` — условную переменную для ожидания свободного места.
- `all_tasks_done` — условную переменную для ожидания завершения заданий.

Схема:

```text
                  queue.Queue
                       |
          ┌────────────┼────────────┐
          |            |            |
          v            v            v
        mutex      not_empty     not_full
          |            |            |
          v            v            v
     Защита данных  Ожидание     Ожидание
                    элементов    места
                       |
                       v
                 all_tasks_done
                       |
                       v
                  Queue.join()
```

Именно поэтому при обычном использовании `Queue` не нужно самостоятельно создавать `Lock` и `Condition`.

Очередь уже синхронизирует операции добавления и извлечения.

### 10. Queue vs Condition

Оба механизма связаны с синхронизацией потоков.

Но решают разные задачи.

**Condition:**

```python
with condition:
    while not data:
        condition.wait()

    item = data.pop()
```

Здесь мы вручную управляем общим состоянием.

**Queue:**

```python
item = q.get()
```

Очередь самостоятельно организует ожидание появления элемента.

| Характеристика | Queue | Condition |
|---|---|---|
| Передача данных | Да | Самостоятельно не передаёт |
| Встроенное хранение элементов | Да | Нет |
| Потокобезопасность | Да | При корректном использовании блокировки |
| Ожидание элементов | Встроено | Реализуется через условие |
| Учёт завершения заданий | Да | Нет |
| Произвольные условия ожидания | Ограниченно | Да |

**Вывод:** если нужно передавать задания между потоками, обычно выбирают `Queue`. Если требуется ждать произвольного изменения состояния, используют `Condition`.

### 11. Виды очередей в Python

В модуле `queue` есть несколько типов очередей.

| Тип | Принцип |
|---|---|
| `Queue` | FIFO |
| `LifoQueue` | LIFO |
| `PriorityQueue` | Приоритет элементов |
| `SimpleQueue` | Упрощённая FIFO-очередь |

**Queue — FIFO**

```python
from queue import Queue

q = Queue()
```

Первым извлекается самый ранний добавленный элемент.

**LifoQueue — LIFO**

```python
from queue import LifoQueue

q = LifoQueue()
```

Последним добавленный элемент извлекается первым, как в стеке.

**PriorityQueue — очередь с приоритетами**

```python
from queue import PriorityQueue

q = PriorityQueue()

q.put((3, "Низкий приоритет"))
q.put((1, "Высокий приоритет"))
q.put((2, "Средний приоритет"))

print(q.get())
```

Результат:

```text
(1, 'Высокий приоритет')
```

В данном примере меньшему числу соответствует более высокий приоритет.

**SimpleQueue**

```python
from queue import SimpleQueue

q = SimpleQueue()
```

Подходит для простой потокобезопасной передачи элементов без ограничения размера и без механизмов `task_done()` / `join()`.

### 12. Queue vs asyncio.Queue vs multiprocessing.Queue

Названия похожи, но механизмы разные.

| Характеристика | queue.Queue | asyncio.Queue | multiprocessing.Queue |
|---|---|---|---|
| Для чего | Потоки | Корутины | Процессы |
| Получение элемента | `get()` | `await get()` | `get()` |
| Блокирует поток при ожидании | Да | Нет | Да |
| Передача между процессами | Нет | Нет | Да |
| Типичный сценарий | threading | asyncio | multiprocessing |

**threading:**

```python
from queue import Queue

q = Queue()
item = q.get()
```

**asyncio:**

```python
import asyncio

q = asyncio.Queue()
item = await q.get()
```

**multiprocessing:**

```python
from multiprocessing import Queue

q = Queue()
item = q.get()
```

Не стоит использовать блокирующий `queue.Queue.get()` непосредственно внутри асинхронной корутины: он может заблокировать Event Loop.

### 13. Queue и GIL

GIL не делает очередь ненужной.

В обычной сборке CPython GIL ограничивает одновременное выполнение Python-байткода несколькими потоками, но не гарантирует безопасность произвольной последовательности операций с общим состоянием.

`queue.Queue` использует собственную синхронизацию, поэтому безопасна для конкурентного добавления и извлечения элементов.

Особенно полезна она в I/O-bound сценариях:

- Сетевые запросы.
- Чтение и запись файлов.
- Работа с внешними сервисами.
- Обработка логов.
- Загрузка и выгрузка данных.

Для тяжёлых CPU-bound вычислений стоит рассмотреть `multiprocessing` или `ProcessPoolExecutor`.

### 14. Практический пример в Backend

Представим сервис, который принимает задания на обработку файлов.

Основной поток добавляет имена файлов в очередь, а несколько рабочих потоков их обрабатывают.

```python
import queue
import threading
import time


file_queue = queue.Queue(maxsize=10)


def process_file(filename):
    print(f"Начата обработка: {filename}")

    time.sleep(1)

    print(f"Обработка завершена: {filename}")


def worker():
    while True:
        filename = file_queue.get()

        try:
            if filename is None:
                return

            process_file(filename)

        finally:
            file_queue.task_done()


workers = [
    threading.Thread(target=worker)
    for _ in range(3)
]

for thread in workers:
    thread.start()


files = [
    "report_1.xlsx",
    "report_2.xlsx",
    "report_3.xlsx",
    "report_4.xlsx",
    "report_5.xlsx",
]

for filename in files:
    file_queue.put(filename)


file_queue.join()


for _ in workers:
    file_queue.put(None)

for thread in workers:
    thread.join()


print("Все файлы обработаны")
```

Что здесь важно:

- `Queue(maxsize=10)` ограничивает количество ожидающих элементов.
- Три потока выполняют обработку конкурентно.
- `get()` безопасно распределяет задания между потоками.
- `task_done()` ведёт учёт завершённых заданий.
- `join()` позволяет дождаться завершения обработки.
- `None` используется как сигнал остановки.

Это учебный пример. В реальном приложении нужно дополнительно предусмотреть обработку ошибок и повторные попытки. Вызов `task_done()` означает, что обработка задания закончена с точки зрения счётчика очереди, но не гарантирует её успешность.

### 15. Queue vs Celery, RabbitMQ и Kafka

Это полезно понимать Backend-разработчику.

`queue.Queue` работает **в памяти одного процесса**.

Если приложение аварийно завершится, задания в такой очереди будут потеряны.

Для распределённой обработки используют другие решения.

| Инструмент | Назначение |
|---|---|
| `queue.Queue` | Передача заданий между потоками |
| `multiprocessing.Queue` | Передача данных между процессами |
| Celery | Распределённое выполнение фоновых задач |
| RabbitMQ | Брокер сообщений |
| Kafka | Распределённая платформа событий и потоков данных |

Например, в FastAPI можно использовать локальную очередь для вспомогательной работы внутри процесса.

Но если требуется надёжная обработка платежей, отправка важных уведомлений или выполнение заданий несколькими серверами, одной `queue.Queue` недостаточно.

### 16. Нововведение Python 3.13 — Queue.shutdown()

Начиная с Python 3.13 у `queue.Queue` появился метод `shutdown()`.

Он позволяет явно завершать работу очереди без обязательного использования sentinel-значений.

```python
import queue

q = queue.Queue()

q.put("Задача 1")

q.shutdown()
```

После вызова `shutdown()` новые элементы добавлять нельзя: соответствующие операции поднимают `queue.ShutDown`.

При обычном завершении `shutdown(immediate=False)` уже поставленные элементы можно извлечь и обработать. Когда очередь опустеет, дальнейшие `get()` поднимут `queue.ShutDown`.

Для ожидающих рабочих потоков можно использовать:

```python
try:
    item = q.get()
except queue.ShutDown:
    return
```

Есть и режим `shutdown(immediate=True)`, который немедленно опустошает очередь и может разблокировать `join()` даже без завершения всех заданий. Его нужно использовать осторожно, поскольку он нарушает обычную гарантию `join()`.

В Python 3.11 и 3.12 метода `shutdown()` ещё нет, поэтому там часто применяют sentinel-значения.

### 17. Типичные ошибки

**Ошибка 1. Забывать task_done().**

```python
item = q.get()
process(item)
```

Если затем вызвать `q.join()`, ожидание может не завершиться.

Правильнее:

```python
item = q.get()

try:
    process(item)
finally:
    q.task_done()
```

**Ошибка 2. Путать Queue.join() и Thread.join().**

`Queue.join()` ожидает завершения учтённых заданий.

`Thread.join()` ожидает завершения потока.

**Ошибка 3. Считать empty() надёжной проверкой перед get().**

```python
if not q.empty():
    item = q.get()
```

Другой поток может забрать последний элемент между проверкой и вызовом `get()`.

Лучше использовать `get_nowait()` с обработкой `queue.Empty`.

**Ошибка 4. Не предусматривать завершение Worker.**

Если рабочий поток бесконечно вызывает `get()`, он может остаться заблокированным после завершения производителя.

Используют sentinel-значения или `shutdown()` в Python 3.13+.

**Ошибка 5. Использовать queue.Queue как распределённую очередь.**

Она работает только внутри одного процесса и не обеспечивает долговременного хранения заданий.

**Ошибка 6. Использовать Queue для ускорения CPU-bound задач.**

Обычные потоки CPython с GIL не обеспечивают параллельное выполнение Python-вычислений на нескольких ядрах.

**Ошибка 7. Считать task_done() подтверждением успешной обработки.**

Метод только уменьшает счётчик незавершённых заданий. Учёт ошибок и повторные попытки нужно реализовать отдельно.

## 🎤 Вопросы на собеседовании

**1. Что такое queue.Queue?**

Потокобезопасная FIFO-очередь для обмена данными между потоками.

**2. Почему Queue потокобезопасна?**

Потому что внутри использует блокировки и условные переменные для синхронизации операций.

**3. Что делает put()?**

Добавляет элемент в очередь и при необходимости ожидает свободного места.

**4. Что делает get()?**

Извлекает элемент из очереди и при необходимости ожидает появления данных.

**5. Чем task_done() отличается от join()?**

`task_done()` отмечает завершение одного задания, а `join()` ожидает завершения всех учтённых заданий.

**6. Что произойдёт, если забыть task_done()?**

Счётчик незавершённых заданий не уменьшится, и `join()` может заблокироваться навсегда.

**7. Что такое Producer–Consumer?**

Паттерн, в котором одни потоки создают задания, а другие извлекают их из очереди и обрабатывают.

**8. Чем Queue отличается от Condition?**

`Queue` хранит и передаёт элементы, а `Condition` предоставляет механизм ожидания изменения общего состояния.

**9. Чем queue.Queue отличается от asyncio.Queue?**

Первая предназначена для потоков и использует блокирующие операции, вторая — для асинхронных задач и использует `await`.

**10. Что такое maxsize?**

Максимальное количество элементов, которые могут одновременно находиться в очереди. Позволяет ограничивать накопление заданий.

**11. Что такое sentinel?**

Специальное значение, например `None`, которое сигнализирует рабочему потоку о необходимости завершиться.

**12. Что произойдёт, если процесс завершится с заданиями в Queue?**

Задания будут потеряны, поскольку очередь находится в памяти процесса.

**13. Когда использовать Queue, а когда Celery?**

`Queue` подходит для локальной многопоточной обработки. Celery — для распределённых фоновых задач, которые должны выполняться независимо от конкретного процесса приложения.

**14. Что нового появилось в Python 3.13?**

Метод `Queue.shutdown()`, позволяющий явно завершать работу очереди.
