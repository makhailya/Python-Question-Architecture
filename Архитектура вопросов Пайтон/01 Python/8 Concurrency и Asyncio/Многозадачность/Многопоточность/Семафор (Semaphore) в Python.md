# 🚦 Семафор (Semaphore) в Python

## 🎤 Короткий ответ

**Semaphore** — примитив синхронизации, который ограничивает количество потоков или задач, одновременно выполняющих определённый участок кода или использующих общий ресурс.

Семафор хранит внутренний счётчик разрешений. `acquire()` уменьшает его, а `release()` увеличивает. Если разрешений нет, следующий `acquire()` блокируется до тех пор, пока кто-то не вызовет `release()`.

Например, если семафор создан с `3`, одновременно пройти в критическую секцию смогут максимум **3 задачи**.

```python
import threading

semaphore = threading.Semaphore(3)


def worker():
    with semaphore:
        # одновременно здесь могут находиться максимум 3 потока
        ...
```

---

## 🗣️ Ответ на собеседовании

`Semaphore` — это примитив синхронизации, который позволяет ограничить количество одновременно выполняющихся участников.

Внутри есть счётчик разрешений. При `acquire()` одно разрешение забирается. Если счётчик больше нуля, выполнение продолжается. Если счётчик равен нулю, поток или задача ждёт. После завершения работы вызывается `release()`, который возвращает разрешение и позволяет следующему ожидающему продолжить.

В отличие от `Lock`, который обычно позволяет войти в критическую секцию только одному потоку, семафор может разрешить одновременный доступ нескольким участникам.

Типичный пример — ограничить количество одновременных запросов к API, соединений с ресурсом или операций с ограниченным пулом ресурсов.

## 📚 Разбор поглубже

### 1. Что такое Semaphore

Семафор можно представить как **счётчик доступных разрешений**.

Например:

```python
semaphore = threading.Semaphore(3)
```

Начальное состояние:

```text
Semaphore = 3
```

Три участника могут получить разрешение:

```text
Worker 1 → acquire() → 2
Worker 2 → acquire() → 1
Worker 3 → acquire() → 0
```

Четвёртый:

```text
Worker 4 → acquire()
              ↓
           ждёт
```

Когда один из первых завершит работу:

```text
Worker 1 → release()
              ↓
           Semaphore = 1
              ↓
Worker 4 продолжает
```

---

### 2. `acquire()`

`acquire()` пытается получить одно разрешение.

```python
semaphore.acquire()
```

Если разрешение доступно:

```text
counter > 0
    ↓
counter -= 1
    ↓
продолжаем выполнение
```

Если:

```text
counter == 0
```

то вызывающий поток блокируется до появления разрешения.

---

### 3. `release()`

`release()` возвращает разрешение:

```python
semaphore.release()
```

Логика:

```text
release()
   ↓
counter += 1
   ↓
один ожидающий участник может продолжить
```

Поэтому типичный шаблон:

```python
semaphore.acquire()

try:
    do_work()
finally:
    semaphore.release()
```

Но лучше использовать контекстный менеджер.

---

### 4. Контекстный менеджер

```python
import threading

semaphore = threading.Semaphore(3)


def worker():
    with semaphore:
        do_work()
```

Конструкция:

```python
with semaphore:
```

эквивалентна концептуально:

```python
semaphore.acquire()

try:
    do_work()
finally:
    semaphore.release()
```

Это снижает риск забыть вызвать `release()` при исключении.

---

### 5. Пример с потоками

Допустим, есть ресурс, который способен обслуживать максимум **2 операции одновременно**.

```python
import threading
import time

semaphore = threading.Semaphore(2)


def worker(number):
    with semaphore:
        print(f"Worker {number} начал работу")
        time.sleep(2)
        print(f"Worker {number} закончил работу")
```

Создадим несколько потоков:

```python
threads = []

for i in range(5):
    thread = threading.Thread(
        target=worker,
        args=(i,),
    )
    threads.append(thread)
    thread.start()

for thread in threads:
    thread.join()
```

Хотя потоков 5, внутри защищённого участка одновременно находятся максимум 2.

```text
5 потоков
   │
   ▼
Semaphore(2)
   │
   ├── Worker 1 ─┐
   ├── Worker 2 ─┤ → работают
   ├── Worker 3 ─┘ → ждёт
   ├── Worker 4   → ждёт
   └── Worker 5   → ждёт
```

---

### 6. `Semaphore` не обязательно защищает данные

Это важный момент.

Семафор может использоваться для ограничения **количества одновременных участников**, но сам по себе он не означает:

> «этот код выполняется только одним потоком».

Например:

```python
semaphore = threading.Semaphore(3)
```

означает:

```text
максимум 3 участника одновременно
```

А:

```python
lock = threading.Lock()
```

означает:

```text
максимум 1 участник одновременно
```

Поэтому `Semaphore(1)` по поведению похож на `Lock`, но семантически это разные примитивы.

---

### 7. `Semaphore(1)` vs `Lock`

```python
semaphore = threading.Semaphore(1)
```

Может разрешить только одному участнику войти одновременно.

Но:

```python
threading.Lock()
```

явно выражает намерение:

> защищаем критическую секцию от одновременного доступа.

А `Semaphore` обычно выражает другую идею:

> есть ограниченное количество разрешений/ресурсов.

Например:

```text
Lock
→ один владелец критической секции

Semaphore(5)
→ пять одновременно доступных ресурсов
```

---

### 8. Главный use case — ограничение ресурсов

Представим пул из 3 подключений к внешнему сервису.

```python
connection_limit = threading.Semaphore(3)
```

Теперь независимо от количества потоков:

```text
100 workers
      ↓
Semaphore(3)
      ↓
максимум 3 одновременно
```

Это называется **ограничением concurrency**.

Семафор особенно полезен для:

* ограничений API;
* пулов соединений;
* файловых ресурсов;
* доступа к ограниченным внешним сервисам;
* ограничения числа одновременных операций;
* защиты от чрезмерной нагрузки.

## 9. Semaphore в `asyncio`

В асинхронном Python есть отдельный семафор:

```python
asyncio.Semaphore
```

Пример:

```python
import asyncio

semaphore = asyncio.Semaphore(3)


async def request(number):
    async with semaphore:
        print(f"Запрос {number}")
        await asyncio.sleep(1)
```

Создадим несколько задач:

```python
async def main():
    tasks = [
        asyncio.create_task(request(i))
        for i in range(10)
    ]

    await asyncio.gather(*tasks)
```

Одновременно внутри:

```python
async with semaphore:
```

будет находиться максимум 3 задачи.

---

### 10. `threading.Semaphore` vs `asyncio.Semaphore`

| `threading.Semaphore`         | `asyncio.Semaphore`     |
| ----------------------------- | ----------------------- |
| Для потоков                   | Для async-задач         |
| `acquire()`                   | `await acquire()`       |
| `with semaphore`              | `async with semaphore`  |
| Блокирует поток при ожидании  | Не блокирует event loop |
| Используется в threading-коде | Используется в asyncio  |

Асинхронный вариант:

```python
async with semaphore:
    await do_request()
```

Важно: не следует использовать блокирующий `threading.Semaphore` для обычной синхронизации внутри asyncio-кода, если это может блокировать event loop.

---

### 11. Почему `asyncio.Semaphore` не блокирует event loop

Предположим:

```python
semaphore = asyncio.Semaphore(2)
```

Есть 10 задач.

Первые две получают разрешение:

```text
Task 1 → running
Task 2 → running
Task 3 → waiting
Task 4 → waiting
...
Task 10 → waiting
```

Ожидающие async-задачи не должны блокировать поток event loop.

Когда одна задача освобождает семафор:

```python
async with semaphore:
    ...
```

после выхода разрешение становится доступным следующей ожидающей задаче.

## 12. Semaphore и rate limiting

Семафор часто путают с **rate limiter**.

Это не одно и то же.

### Semaphore

Ограничивает количество **одновременно выполняющихся операций**.

```text
максимум 5 concurrent requests
```

### Rate limiter

Ограничивает **скорость выполнения операций во времени**.

Например:

```text
100 requests / second
```

Можно иметь:

```text
Semaphore(10)
+
Rate Limiter(100 req/s)
```

То есть одновременно максимум 10 запросов и при этом не больше 100 запросов в секунду.

## 13. Semaphore и Lock

|                          |                    `Lock` |               `Semaphore` |
| ------------------------ | ------------------------: | ------------------------: |
| Одновременных участников |                         1 |                         N |
| Основная задача          | Защита критической секции |   Ограничение concurrency |
| Счётчик разрешений       |                Обычно нет |                        Да |
| Типичный пример          |   Защита общего состояния | Ограничение пула ресурсов |
| `Semaphore(1)`           |                         — |             Похож на Lock |

## 14. `BoundedSemaphore`

В `threading` существует:

```python
threading.BoundedSemaphore
```

Он похож на обычный `Semaphore`, но дополнительно контролирует, чтобы количество `release()` не увеличило счётчик выше исходного значения.

Например:

```python
import threading

semaphore = threading.BoundedSemaphore(2)

semaphore.acquire()
semaphore.release()
```

Нормально.

Но:

```python
semaphore.release()
semaphore.release()
semaphore.release()
```

может привести к ошибке, потому что разрешений стало больше первоначального лимита.

Это помогает обнаруживать ошибки вида:

```text
acquire()
release()
release()  ← лишний release
```

---

## 15. Почему `BoundedSemaphore` полезен

Обычный `Semaphore` допускает увеличение внутреннего счётчика через лишний `release()`.

`BoundedSemaphore` проверяет верхнюю границу.

Поэтому:

```text
Semaphore
→ обычный счётчик разрешений

BoundedSemaphore
→ счётчик + контроль верхней границы
```

На практике `BoundedSemaphore` полезен, когда важно обнаружить нарушение баланса:

```text
acquire ↔ release
```

## 16. Типичная ошибка — забыть `release()`

Плохо:

```python
semaphore.acquire()

do_work()

semaphore.release()
```

Если `do_work()` выбросит исключение:

```text
acquire()
   ↓
do_work()
   ↓
Exception
   ↓
release() не выполнен
```

Разрешение останется занятым.

Правильно:

```python
semaphore.acquire()

try:
    do_work()
finally:
    semaphore.release()
```

Или:

```python
with semaphore:
    do_work()
```

## 17. Семафор не решает Race Condition автоматически

Это важный момент для собеседования.

Допустим, есть:

```python
counter = 0
```

И:

```python
semaphore = threading.Semaphore(3)
```

Если три потока одновременно изменяют `counter`, семафор с тремя разрешениями **не гарантирует**, что изменения будут последовательными.

Если нужно обеспечить эксклюзивный доступ:

```python
lock = threading.Lock()
```

И использовать:

```python
with lock:
    counter += 1
```

Семафор отвечает прежде всего за **ограничение числа участников**, а не за эксклюзивность.

## 18. Модель для запоминания

Очень полезно представлять семафор как **парковку с ограниченным количеством мест** 🚗

Например:

```text
Semaphore(3)

┌──────────────────────┐
│ 🚗 │ 🚗 │ 🚗 │
└──────────────────────┘
       3 места
```

Первый поток занимает место:

```text
🚗 → acquire()
```

Место освобождается:

```text
🚗 → release()
```

Если все места заняты:

```text
🚗 🚗 🚗
         ↓
      следующий
         ↓
       ждёт
```

Это хорошая ментальная модель для собеседования.

## 19. Главное отличие от других примитивов

```text
Lock
└── один участник

RLock
└── один участник
    └── тот же поток может захватить повторно

Semaphore(N)
└── максимум N участников

Condition
└── ожидание определённого состояния

Queue
└── безопасный обмен данными между участниками
```

## 🎤 Вопросы на собеседовании

**Что такое Semaphore?**

Примитив синхронизации, который ограничивает количество участников, одновременно выполняющих определённый участок кода или использующих ресурс.

**Как работает Semaphore?**

У него есть счётчик разрешений. `acquire()` уменьшает его, а `release()` увеличивает. При отсутствии разрешений `acquire()` ждёт.

**Чем Semaphore отличается от Lock?**

`Lock` обычно допускает одного участника, а `Semaphore(N)` — до `N` участников одновременно.

**Зачем нужен `Semaphore(10)`?**

Чтобы ограничить concurrency до 10 одновременных операций, например запросов к внешнему API.

**Что произойдёт при `acquire()`, когда разрешений нет?**

Синхронный поток будет ждать освобождения разрешения. В `asyncio` задача будет ждать асинхронно, не блокируя event loop.

**Что такое `BoundedSemaphore`?**

Вариант семафора, который контролирует, чтобы число разрешений не стало больше первоначального значения из-за лишних `release()`.

**Можно ли использовать Semaphore для защиты общей переменной?**

Технически можно ограничить количество одновременных участников, но для эксклюзивной защиты общего состояния обычно нужен `Lock`.

**Чем `asyncio.Semaphore` отличается от `threading.Semaphore`?**

`threading.Semaphore` предназначен для потоков и блокирующего кода, а `asyncio.Semaphore` — для async-задач и используется через `await` / `async with`.

**Semaphore — это rate limiter?**

Нет. Semaphore ограничивает количество одновременно выполняющихся операций, а rate limiter ограничивает скорость операций во времени.

**Формула для собеседования:**

> **`Semaphore(N)` = максимум N участников одновременно. `acquire()` забирает разрешение, `release()` возвращает его. В отличие от `Lock`, семафор позволяет нескольким участникам работать параллельно, но в пределах установленного лимита.**
