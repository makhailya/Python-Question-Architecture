# 🧵 Многопоточность (Multithreading)

## 🎤 Короткий ответ

**Многопоточность** — это выполнение нескольких потоков внутри одного процесса.

Потоки одного процесса:

* имеют общее адресное пространство;
* могут работать с общими данными;
* имеют собственный стек и состояние выполнения;
* могут выполняться конкурентно, а при подходящих условиях — параллельно.

В Python для работы с потоками используется модуль `threading`.

Главная особенность CPython — **GIL**: несколько потоков не могут одновременно выполнять Python bytecode в одном интерпретаторе в классической модели CPython. Поэтому threading особенно полезен для **I/O-bound** задач, а не как основной способ ускорения CPU-bound Python-кода.

## 🗣️ Ответ на собеседовании

Многопоточность — это использование нескольких потоков выполнения внутри одного процесса.

Все потоки одного процесса имеют общее адресное пространство, поэтому могут обращаться к общим объектам и данным. При этом у каждого потока есть собственный стек и состояние выполнения.

В Python многопоточность реализуется, например, через модуль `threading`. Она особенно полезна для I/O-bound задач: пока один поток ждёт сеть, файл или другую внешнюю операцию, другой поток может выполнять работу.

Для CPython важен GIL — Global Interpreter Lock. Он не позволяет нескольким потокам одновременно выполнять Python bytecode в одном интерпретаторе в классической модели CPython. Поэтому threading обычно не используют как способ получения CPU-параллелизма для чистого Python-кода. Для CPU-bound задач чаще рассматривают multiprocessing или специализированные библиотеки.

При этом многопоточность создаёт проблему совместного доступа к данным, поэтому могут потребоваться механизмы синхронизации: `Lock`, `RLock`, `Semaphore`, `Condition`, `Queue` и другие.

# 📚 Разбор поглубже

## 1. Что такое поток

**Thread** — это отдельный поток выполнения внутри процесса.

Например:

```text
Process
│
├── Thread 1
├── Thread 2
└── Thread 3
```

Один процесс может содержать несколько потоков.

Каждый поток имеет собственный:

* instruction pointer / состояние выполнения;
* стек;
* набор регистров CPU.

Но память процесса в целом является общей.

---

# 2. Процесс и поток

Главное различие:

```text
Process
│
├── собственное адресное пространство
├── ресурсы процесса
└── Threads
    ├── Thread A
    ├── Thread B
    └── Thread C
```

То есть:

```text
Процесс
    ↓
контейнер ресурсов
    ↓
несколько потоков выполнения
```

Потоки внутри одного процесса используют общую память:

```text
Process
│
├── Thread A ──┐
├── Thread B ──┼──► Shared Memory
└── Thread C ──┘
```

Именно это делает обмен данными между потоками относительно удобным, но одновременно создаёт проблемы синхронизации.

---

# 3. Создание потока

В Python можно использовать `threading.Thread`.

```python
import threading


def worker():
    print("Работа потока")


thread = threading.Thread(target=worker)

thread.start()
thread.join()
```

Здесь:

```python
thread = threading.Thread(...)
```

создаёт объект потока.

```python
thread.start()
```

запускает поток.

```python
thread.join()
```

заставляет текущий поток дождаться его завершения.

---

# 4. `start()` и `run()`

Важное различие:

```python
thread.start()
```

и:

```python
thread.run()
```

Это не одно и то же.

### `start()`

Запускает поток выполнения.

```text
main thread
    │
    ├── работа
    │
    └── start()
          ↓
       worker thread
```

### `run()`

Просто вызывает метод `run()` в текущем потоке.

То есть:

```python
thread.run()
```

не создаёт новый поток выполнения.

---

# 5. `join()`

`join()` используется для ожидания завершения потока.

```python
thread.start()

thread.join()

print("Поток завершился")
```

Упрощённо:

```text
Main Thread
    │
    ├── start()
    │
    ├── работа
    │
    └── join()
          │
          │ WAIT
          ▼
      Worker Thread
          │
          ▼
       завершение
          │
          ▼
     Main продолжает
```

`join()` не останавливает всю операционную систему или другие процессы. Он блокирует вызывающий поток до завершения указанного потока или до истечения timeout.

---

# 6. Потоки и конкурентность

Несколько потоков позволяют организовать конкурентное выполнение:

```text
Thread A → ████────████
Thread B → ───████████─
```

На одном ядре это может выглядеть как переключение:

```text
A A A B B A A B B
```

На многоядерной системе потоки также могут физически выполняться одновременно.

Но для Python здесь появляется важный нюанс — GIL.

---

# 7. GIL

**GIL (Global Interpreter Lock)** — механизм CPython, который ограничивает одновременное выполнение Python bytecode несколькими потоками внутри одного интерпретатора.

Упрощённо:

```text
Process
│
├── Thread A ──┐
├── Thread B ──┼──► GIL
└── Thread C ──┘
```

В каждый конкретный момент соответствующей классической модели CPython только один поток получает возможность выполнять Python bytecode под GIL.

Поэтому:

```text
2 CPU cores
+
2 Python threads
```

не означает автоматически:

```text
Core 1 → Python bytecode A
Core 2 → Python bytecode B
```

---

# 8. Почему threading полезен для I/O-bound

Представим:

```text
Thread A
   ↓
HTTP request
   ↓
WAIT
```

Пока поток ждёт I/O, другой поток может получить возможность выполнять работу.

```text
Thread A → request → WAIT
Thread B → работа → работа
Thread A → response → продолжение
```

Поэтому многопоточность часто используется для I/O-bound задач.

Например:

```text
I/O-bound
├── HTTP
├── database
├── files
├── sockets
└── external APIs
```

---

# 9. Threading и CPU-bound

Для чистого Python CPU-bound кода ситуация другая.

Например:

```python
def calculate():
    total = 0

    for i in range(10_000_000):
        total += i

    return total
```

Если запустить несколько таких вычислений через обычные Python threads, GIL ограничивает одновременное выполнение Python bytecode в одном интерпретаторе.

Поэтому threading обычно не является способом получить линейное ускорение CPU-bound Python-кода.

Для этого чаще рассматривают:

```text
CPU-bound
    ↓
multiprocessing
    ↓
несколько процессов
    ↓
несколько CPU cores
```

---

# 10. Потоки используют общую память

Например:

```python
counter = 0
```

Несколько потоков могут обращаться к одной переменной/общему объекту.

```text
Thread A ──┐
Thread B ──┼──► shared object
Thread C ──┘
```

Это удобно.

Но возникает вопрос:

> Что произойдёт, если несколько потоков одновременно изменяют один объект?

Здесь появляются:

* Race Condition;
* Data Race;
* синхронизация;
* блокировки.

---

# 11. Race Condition

Предположим:

```python
counter += 1
```

Интуитивно кажется, что это одна операция.

Но концептуально изменение значения можно представить как:

```text
прочитать
   ↓
прибавить 1
   ↓
записать
```

Два потока могут взаимодействовать с общей переменной таким образом, что итог зависит от порядка выполнения.

```text
Thread A ──┐
            ├──► counter
Thread B ──┘
```

Это пример класса проблем, связанных с конкурентным доступом.

Подробно `Race Condition` и `Data Race` лучше рассматривать отдельными заметками.

---

# 12. Синхронизация

Когда несколько потоков работают с общими ресурсами, может потребоваться синхронизация.

Основные механизмы:

```text
Synchronization
│
├── Lock
├── RLock
├── Semaphore
├── Condition
└── Queue
```

Например, `Lock` позволяет ограничить участок кода одним потоком:

```python
import threading


lock = threading.Lock()
counter = 0


def increment():
    global counter

    with lock:
        counter += 1
```

Упрощённо:

```text
Thread A ──► LOCK ──► critical section ──► UNLOCK
Thread B ───────────── WAIT ──────────────►
```

---

# 13. Thread-safe

**Thread-safe** означает, что объект или код корректно работает при использовании несколькими потоками в соответствии с его контрактом и моделью синхронизации.

Важно:

```text
GIL
 ≠
thread safety
```

Наличие GIL не означает, что любой многопоточный код автоматически безопасен.

Например, логика приложения может содержать:

```text
прочитать данные
      ↓
принять решение
      ↓
изменить данные
```

и несколько потоков могут вмешаться друг в друга.

Поэтому синхронизация может быть необходима независимо от существования GIL.

---

# 14. Потоки и очереди

Для обмена данными между потоками часто удобно использовать `queue.Queue`.

```python
from queue import Queue
from threading import Thread


queue = Queue()


def worker():
    item = queue.get()
    print(item)
    queue.task_done()


thread = Thread(target=worker)
thread.start()

queue.put("Задача")
queue.join()
```

Схема:

```text
Producer
   │
   ▼
 Queue
   │
   ▼
Consumer Thread
```

Это удобнее и безопаснее, чем самостоятельно строить сложную систему обмена данными и блокировок.

---

# 15. Потоки и исключения

Исключение, возникшее в worker thread, не становится автоматически исключением в основном потоке в том смысле, что `try/except` вокруг `thread.start()` его не перехватит.

Например, это не работает так, как можно ожидать:

```python
try:
    thread.start()
except ValueError:
    ...
```

Исключение возникает внутри другого потока.

Для более удобного управления результатами и исключениями часто используют `concurrent.futures.ThreadPoolExecutor`.

---

# 16. `ThreadPoolExecutor`

Вместо ручного управления большим количеством Thread можно использовать пул потоков:

```python
from concurrent.futures import ThreadPoolExecutor


def worker(number):
    return number * 2


with ThreadPoolExecutor(max_workers=4) as executor:
    results = executor.map(worker, [1, 2, 3, 4])
```

Упрощённо:

```text
ThreadPoolExecutor
│
├── Worker 1
├── Worker 2
├── Worker 3
└── Worker 4
```

Пул переиспользует потоки вместо постоянного создания новых.

Это особенно удобно для большого количества однотипных I/O-bound задач.

# 18. Потоки vs asyncio

|                  | Threading                     | Asyncio                                        |
| ---------------- | ----------------------------- | ---------------------------------------------- |
| Основная модель  | Потоки                        | Event Loop                                     |
| Переключение     | Управляется ОС/рантаймом      | Кооперативное                                  |
| Память           | Общая между потоками          | Обычно общий поток/процесс                     |
| Синтаксис        | Обычные функции               | `async def` / `await`                          |
| Основная область | I/O-bound                     | I/O-bound                                      |
| Блокировки       | Возможны                      | Блокирующий код может заблокировать Event Loop |
| Количество задач | Ограничено стоимостью потоков | Можно обслуживать много лёгких async-задач     |

Главная разница:

```text
Threading
    ↓
несколько потоков

Asyncio
    ↓
обычно один поток
    ↓
Event Loop
    ↓
много Task
```

# 🎤 Вопросы на собеседовании

### Что такое многопоточность?

Выполнение нескольких потоков внутри одного процесса.

### Что такое Thread?

Поток выполнения внутри процесса.

### Общая ли память у потоков?

Да. Потоки одного процесса используют общее адресное пространство.

При этом у каждого потока есть собственный стек и состояние выполнения.

### Чем Thread отличается от Process?

Потоки находятся внутри одного процесса и используют общую память.

Процессы имеют отдельные адресные пространства.

### Как создать Thread в Python?

```python
thread = threading.Thread(target=worker)
thread.start()
```

### Для чего нужен `join()`?

Чтобы дождаться завершения потока:

```python
thread.join()
```

### Чем `start()` отличается от `run()`?

`start()` запускает отдельный поток.

`run()` выполняет метод в текущем потоке и сам новый поток не создаёт.

### Что такое GIL?

Global Interpreter Lock — механизм CPython, ограничивающий одновременное выполнение Python bytecode несколькими потоками внутри одного интерпретатора.

### Почему threading хорошо подходит для I/O-bound?

Поток может ожидать I/O, пока другие потоки получают возможность выполнять работу.

### Почему threading не является стандартным решением для CPU-bound Python-кода?

Из-за ограничений GIL на одновременное выполнение Python bytecode несколькими потоками в одном интерпретаторе.

### Делает ли GIL код thread-safe?

Нет.

GIL не заменяет синхронизацию и не защищает автоматически бизнес-логику от race conditions.

### Что такое shared memory?

Область памяти процесса, к которой могут обращаться его потоки.
