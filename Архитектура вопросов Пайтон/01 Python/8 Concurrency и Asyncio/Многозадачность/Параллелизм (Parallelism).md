# ⚡ Параллелизм в Python

## 🎤 Короткий ответ

**Параллелизм (parallelism)** — это одновременное выполнение нескольких задач, обычно на **разных вычислительных ядрах**.

Например:

```text
CPU Core 1 → Task A █████████
CPU Core 2 → Task B █████████
```

В отличие от конкурентности, где задачи могут просто чередоваться:

```text
A A A B B A A B
```

при параллелизме задачи **физически выполняются одновременно**.

Параллелизм особенно полезен для **CPU-bound** задач — вычислений, обработки изображений, ML и т. п.

В Python для CPU-bound задач часто используют `multiprocessing`, поскольку отдельные процессы позволяют выполнять Python-код на разных CPU-ядрах независимо друг от друга.

## 🗣️ Ответ на собеседовании

Параллелизм — это одновременное физическое выполнение нескольких задач.

Например, если у процессора несколько ядер, одна задача может выполняться на одном ядре, а другая — на другом. В отличие от конкурентности, где несколько задач могут продвигаться вперёд, переключаясь между собой, при параллелизме выполнение действительно происходит одновременно.

Параллелизм особенно полезен для CPU-bound задач, когда основное время уходит на вычисления. В Python для таких задач часто используют [[Многопроцессность (Multiprocessing)]], создавая несколько процессов, которые могут выполняться на разных ядрах.

Важно не путать параллелизм с многопоточностью или асинхронностью. Threading и asyncio — это механизмы организации выполнения, а parallelism — характеристика того, выполняются ли задачи физически одновременно.

# 📚 Разбор поглубже

## 1. Что такое параллелизм

Представим две независимые задачи:

```text
Task A → вычисления
Task B → вычисления
```

При последовательном выполнении:

```text
Время →

A █████████
          B █████████
```

Сначала полностью выполняется `A`, потом `B`.

При параллельном:

```text
Время →

Core 1 → A █████████
Core 2 → B █████████
```

Обе задачи выполняются одновременно.

Если задачи примерно одинаковой продолжительности и действительно могут выполняться независимо, общее время выполнения может существенно сократиться.

---

# 2. Параллелизм требует вычислительных ресурсов

Чтобы две CPU-задачи действительно выполнялись одновременно, системе нужны соответствующие вычислительные ресурсы.

Например:

```text
2 CPU cores

Core 1 → Task A
Core 2 → Task B
```

Но если есть только одно ядро:

```text
1 CPU core

Core 1 → A / B / A / B
```

то одновременно выполнить две обычные CPU-инструкции на одном ядре нельзя.

В таком случае мы можем получить **конкурентность**, но не физический параллелизм этих задач.

---

# 3. Параллелизм и конкурентность

Это главное различие.

### Конкурентность

```text
1 Core

A ███     ███
B    ████    ███
```

CPU переключается между задачами.

### Параллелизм

```text
2 Cores

Core 1 → A █████████
Core 2 → B █████████
```

Задачи реально выполняются одновременно.

Поэтому:

```text
Concurrency
    ↓
как организовано выполнение нескольких задач

Parallelism
    ↓
выполняются ли задачи физически одновременно
```

---

# 4. CPU-bound задачи

Параллелизм особенно полезен для **CPU-bound** нагрузки.

CPU-bound означает, что основное время задачи тратится на вычисления.

Например:

```text
CPU-bound
│
├── сложные математические вычисления
├── обработка изображений
├── обработка видео
├── машинное обучение
├── криптографические вычисления
└── другие CPU-intensive операции
```

Упрощённо:

```text
Task
████████████████████
      CPU
```

Процессор практически постоянно занят вычислениями.

---

# 5. Почему I/O-bound — другая история

Для I/O-bound задачи большую часть времени программа ждёт:

```text
HTTP request
    ↓
    WAIT
    ↓
response
```

В этот момент CPU может выполнять другие задачи.

Поэтому здесь часто важнее **конкурентность**, чем CPU-параллелизм:

```text
Task A → I/O WAIT
Task B → работа
Task C → I/O WAIT
Task D → работа
```

Именно поэтому для большого количества сетевых запросов часто используют `asyncio`.

---

# 6. Параллелизм в Python

В Python есть несколько механизмов, которые нужно различать:

```text
Python
│
├── threading
│
├── multiprocessing
│
└── asyncio
```

Они решают разные задачи.

### `asyncio`

Основная идея:

```text
конкурентность
+
неблокирующее I/O
```

### `threading`

Несколько потоков:

```text
Process
├── Thread A
├── Thread B
└── Thread C
```

Потоки могут использоваться для конкурентного выполнения I/O-bound задач.

### `multiprocessing`

Несколько процессов:

```text
Process A → Core 1
Process B → Core 2
Process C → Core 3
Process D → Core 4
```

Это один из основных способов получить CPU-параллелизм для Python-кода.

---

# 7. Параллелизм и GIL

Для CPython важно учитывать **GIL (Global Interpreter Lock)**.

Упрощённо, в традиционной модели CPython GIL ограничивает одновременное выполнение Python bytecode несколькими потоками внутри одного процесса.

Поэтому:

```text
CPU-bound Python code
        +
несколько threads
        ↓
не означает обычный CPU-параллелизм
```

Для CPU-bound задач часто используют:

```text
multiprocessing
       ↓
несколько процессов
       ↓
разные адресные пространства
       ↓
разные CPU cores
       ↓
настоящий параллелизм
```

При этом нельзя сводить всю тему производительности Python только к GIL: существуют нативные библиотеки и другие механизмы, которые могут выполнять вычисления вне интерпретатора и иначе взаимодействовать с GIL.

# 8. Multiprocessing

Пример:

```python
from multiprocessing import Process


def worker(name):
    print(f"Работает {name}")


if __name__ == "__main__":
    processes = [
        Process(target=worker, args=("A",)),
        Process(target=worker, args=("B",)),
    ]

    for process in processes:
        process.start()

    for process in processes:
        process.join()
```

Здесь создаются два отдельных процесса.

Упрощённо:

```text
Main Process
    │
    ├── Process A → CPU
    │
    └── Process B → CPU
```

Операционная система может разместить их на разных ядрах.

---

# 9. Почему процессы могут выполняться параллельно

Каждый процесс имеет собственное адресное пространство:

```text
Process A
└── Memory A

Process B
└── Memory B
```

Они не делят обычные Python-объекты напрямую.

Поэтому два процесса могут независимо выполнять Python-код:

```text
Core 1 → Process A → Python code
Core 2 → Process B → Python code
```

Для обмена данными используются IPC-механизмы:

```text
IPC
├── Queue
├── Pipe
├── SharedMemory
├── Value
├── Array
└── Manager
```

---

# 10. Параллелизм не всегда ускоряет программу

Это важный нюанс.

Представим очень маленькую задачу:

```text
Task A → 1 ms
Task B → 1 ms
```

Создание процессов, передача данных и синхронизация тоже стоят ресурсов.

```text
Параллельное выполнение
│
├── создание процесса
├── планирование
├── IPC
├── синхронизация
└── переключения
```

Поэтому для маленьких задач накладные расходы могут оказаться сопоставимыми с самой работой.

Кроме того, если задачи конкурируют за один ресурс:

```text
A ──┐
B ──┼──► один ресурс
C ──┘
```

параллельное выполнение не обязательно даст пропорциональное ускорение.

---

# 11. Закон Амдала

При оценке ускорения параллельной программы полезен **закон Амдала**.

Идея простая:

> Ускорение ограничено той частью программы, которую невозможно распараллелить.

Например:

```text
Программа
│
├── 80% → можно распараллелить
└── 20% → только последовательно
```

Даже если у нас бесконечно много ядер, последовательная часть остаётся ограничением.

В реальных системах дополнительно учитываются:

* накладные расходы;
* синхронизация;
* обмен данными;
* дисбаланс нагрузки;
* ограничение количества CPU-ядер.

---

# 12. Data Race и параллелизм

Параллельное выполнение нескольких задач создаёт дополнительные проблемы при работе с общими ресурсами.

Например:

```text
Thread A ──┐
           ├──► shared data
Thread B ──┘
```

Если оба потока одновременно изменяют данные, может возникнуть **Race Condition** или **Data Race** в зависимости от конкретной ситуации и модели памяти.

Поэтому появляются механизмы синхронизации:

```text
Synchronization
├── Lock
├── RLock
├── Semaphore
├── Condition
└── Queue
```

Эта тема будет отдельной веткой.

---

# 13. Параллелизм и масштабирование

Параллелизм может использоваться не только внутри одного процесса.

Например:

```text
Server
│
├── Worker 1 → Core 1
├── Worker 2 → Core 2
├── Worker 3 → Core 3
└── Worker 4 → Core 4
```

Это распространённая модель серверных приложений.

Несколько worker-процессов позволяют использовать несколько CPU-ядер.

# 14. Три понятия в одной схеме

```text
                    МНОГОЗАДАЧНОСТЬ
                           │
             ┌─────────────┴─────────────┐
             │                           │
       CONCURRENCY                  PARALLELISM
       конкурентность               параллелизм
             │                           │
      несколько задач              несколько задач
      могут продвигаться            выполняются
      вперемешку                     одновременно
             │                           │
       ┌─────┴─────┐                ┌────┴────┐
       │           │                │         │
   asyncio     threads          threads*   processes
                                     
* при наличии подходящих условий
```

Главное — **не путать механизм и свойство**:

```text
Thread / Process / Task
        ↓
механизмы выполнения

Concurrency / Parallelism
        ↓
модели организации выполнения
```

# 15. Ментальная модель

Если нужно объяснить разницу очень быстро:

### Конкурентность

```text
Один повар
A → готовит
A → ждёт духовку
B → готовит
B → ждёт
A → продолжает
```

Работа организована так, чтобы не простаивать.

### Параллелизм

```text
Два повара

Повар 1 → A
Повар 2 → B
```

Две работы выполняются одновременно.

Для компьютера:

```text
Concurrency → переключение / ожидание / кооперация

Parallelism → несколько вычислительных ресурсов
              выполняют работу одновременно
```

## 🎤 Вопросы на собеседовании

### Что такое параллелизм?

Параллелизм — одновременное физическое выполнение нескольких задач, например на разных ядрах CPU.

### Чем параллелизм отличается от конкурентности?

При конкурентности несколько задач могут продвигаться вперёд в одном временном интервале, но не обязательно одновременно.

При параллелизме они действительно выполняются одновременно.

### Нужны ли несколько CPU-ядер для параллельного выполнения CPU-задач?

Для одновременного выполнения нескольких CPU-задач нужны соответствующие вычислительные ресурсы, например несколько ядер.

### Что такое CPU-bound?

Задача, в которой основное время занимает вычислительная работа CPU.

### Что такое I/O-bound?

Задача, в которой значительная часть времени уходит на ожидание внешних операций: сети, БД, файлов и т. п.

### Что обычно используют в Python для CPU-bound параллелизма?

Один из основных вариантов — `multiprocessing`, то есть несколько процессов.

### Почему несколько Python threads не всегда дают CPU-параллелизм?

В CPython GIL ограничивает одновременное выполнение Python bytecode несколькими потоками внутри одного процесса.

### Может ли `asyncio` дать CPU-параллелизм?

Сам по себе `asyncio` предназначен прежде всего для конкурентного выполнения задач, особенно I/O-bound, а не для распределения CPU-вычислений по ядрам.

### Всегда ли параллелизм ускоряет программу?

Нет. Есть накладные расходы на создание и управление задачами, синхронизацию, обмен данными, а также последовательные участки программы.

### Что такое закон Амдала?

Модель, показывающая, что максимальное ускорение параллельной программы ограничено долей работы, которую нельзя распараллелить.

## 🧠 Формула

```text
Параллелизм
    ↓
несколько задач
    ↓
физически одновременно
    ↓
несколько вычислительных ресурсов
    ↓
особенно полезен для CPU-bound
```

И главное различие:

```text
Concurrency
→ задачи могут продвигаться одновременно по времени

Parallelism
→ задачи выполняются физически одновременно
```

> **Конкурентность — про организацию работы нескольких задач. Параллелизм — про их одновременное физическое выполнение.**
