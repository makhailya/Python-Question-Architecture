# ⚡ Asyncio в Python

## 🎤 Короткий ответ

`asyncio` — это стандартная библиотека Python для асинхронного программирования. Она позволяет эффективно выполнять большое количество **[[IO-bound]] задач** без создания отдельного потока или процесса для каждой задачи.

В основе `asyncio` лежит **[[Event Loop — цикл событий]]**: он запускает [[Корутина - (coroutine)]], при [[await]] приостанавливает текущую корутину и переключается на другие готовые задачи. Благодаря этому пока одна задача ждёт сеть, диск или другой I/O, процессор может обслуживать другие задачи.

`asyncio` — это прежде всего **[[Конкурентность (Concurrency)]]**, а не [[Параллелизм (Parallelism)]].

---

## 🗣️ Ответ на собеседовании

`asyncio` — это механизм асинхронного программирования в Python, предназначенный в первую очередь для I/O-bound задач: HTTP-запросов, работы с базами данных, сокетами и другими операциями, где много времени уходит на ожидание.

Главный компонент — **Event Loop**. Он управляет выполнением асинхронных задач. Когда корутина доходит до `await` и ожидает завершения операции, она добровольно приостанавливается. Event Loop в это время может запустить или продолжить другую готовую корутину.

Основные сущности — **coroutine, Task, Future и Event Loop**.

Например, если нужно сделать 100 HTTP-запросов, нет необходимости создавать 100 потоков. Можно создать 100 asyncio-задач, и пока одна ждёт ответа от сервера, Event Loop будет выполнять другие.

При этом `asyncio` не делает обычный синхронный код автоматически асинхронным. Если внутри корутины выполнить блокирующую операцию, Event Loop может остановиться на этой операции. Поэтому блокирующий код нужно выносить, например, в отдельный поток через `asyncio.to_thread()` или использовать подходящий async API.

# 📚 Разбор поглубже

## 1. Что такое asyncio

`asyncio` — это фреймворк стандартной библиотеки Python для написания **асинхронного кода**.

Основная идея:

```text
Есть много задач
      ↓
Большинство времени они ждут I/O
      ↓
Не нужно блокировать выполнение на каждой задаче
      ↓
При ожидании задача уступает управление
      ↓
Event Loop выполняет другую задачу
```

Например:

```python
async def request():
    response = await make_request()
    return response
```

На `await` текущая корутина может быть приостановлена до готовности результата.

---

# 2. Конкурентность, а не параллелизм

Это принципиальное различие.

### Asyncio

```text
        один поток
             │
       Event Loop
             │
    ┌────────┼────────┐
    ↓        ↓        ↓
 Task A    Task B    Task C
    │        │        │
   I/O      I/O      I/O
    │        │        │
    └── управление ───┘
```

Задачи **не обязательно выполняются одновременно**.

Они продвигаются по очереди:

```text
A работает
↓
A ждёт I/O

B работает
↓
B ждёт I/O

C работает
↓
C ждёт I/O

A получил данные
↓
A продолжает работу
```

Это **concurrency**.

---

# 3. Главный компонент — Event Loop

**Event Loop** — цикл событий, который управляет выполнением асинхронных задач.

Упрощённо:

```text
Event Loop
    │
    ├── взять готовую Task
    │
    ├── продолжить её выполнение
    │
    ├── Task дошла до await
    │
    ├── Task приостановлена
    │
    ├── ждать события I/O
    │
    └── продолжить другую готовую Task
```

Упрощённая модель:

```python
while True:
    ready_tasks = get_ready_tasks()

    for task in ready_tasks:
        task.run()

    wait_for_io_events()
```

Реальная реализация сложнее, но для собеседования такая модель хорошо объясняет принцип.

---

# 4. Coroutine

Корутинная функция объявляется через `async def`:

```python
async def hello():
    return "Hello"
```

Важно различать:

### Coroutine function

```python
async def hello():
    ...
```

Это функция.

### Coroutine object

```python
coro = hello()
```

Это уже объект-корутина.

Само создание:

```python
coro = hello()
```

ещё не означает, что код функции полностью выполнился.

Корутину можно передать Event Loop через `Task` или непосредственно ожидать:

```python
result = await hello()
```

---

# 5. `await`

`await` говорит:

> «Мне нужен результат этой асинхронной операции. Пока его нет, я могу уступить управление Event Loop».

Например:

```python
async def get_data():
    result = await request()
    return result
```

Логика:

```text
get_data()
    ↓
await request()
    ↓
приостановка get_data
    ↓
Event Loop занимается другими задачами
    ↓
request завершился
    ↓
get_data продолжает выполнение
```

`await` можно применять только к **awaitable** объектам.

Основные awaitable:

* coroutine
* Task
* Future
* объекты с `__await__()`

---

# 6. Task

`Task` — объект `asyncio`, который позволяет Event Loop планировать выполнение корутины.

```python
import asyncio


async def worker():
    await asyncio.sleep(1)
    return "done"


async def main():
    task = asyncio.create_task(worker())

    result = await task

    print(result)


asyncio.run(main())
```

Здесь:

```python
task = asyncio.create_task(worker())
```

корутина превращается в `Task` и планируется Event Loop.

Важно:

```text
Coroutine
   ↓
create_task()
   ↓
Task
   ↓
Event Loop
   ↓
выполнение
```

---

# 7. Зачем вообще нужны Task

Посмотрим на два варианта.

### Последовательное выполнение

```python
async def main():
    await task_a()
    await task_b()
    await task_c()
```

Условно:

```text
A ──────┐
        ↓
B ──────┐
        ↓
C ──────┐
```

Если каждая операция занимает 1 секунду ожидания:

```text
≈ 3 секунды
```

### Конкурентное выполнение

```python
async def main():
    tasks = [
        asyncio.create_task(task_a()),
        asyncio.create_task(task_b()),
        asyncio.create_task(task_c()),
    ]

    results = await asyncio.gather(*tasks)
```

Теперь:

```text
A ─────────
B ─────────
C ─────────
```

Если они в основном ждут I/O:

```text
≈ 1 секунда
```

То есть `asyncio` позволяет эффективно использовать время ожидания.

---

# 8. `asyncio.gather()`

`gather()` позволяет ожидать несколько awaitable одновременно:

```python
results = await asyncio.gather(
    request_a(),
    request_b(),
    request_c(),
)
```

Упрощённо:

```text
request_a ────────┐
request_b ────────┼──→ результаты
request_c ────────┘
```

Это один из наиболее распространённых способов организовать конкурентное выполнение нескольких async-операций.

---

# 9. Future

`Future` — низкоуровневый объект, представляющий результат операции, который появится позже.

Состояние:

```text
Pending
   ↓
  Done
   ↓
Result / Exception
```

Например:

```python
future.set_result(42)
```

После этого:

```python
result = await future
```

вернёт:

```text
42
```

В прикладном коде обычно чаще работают с `Task` и корутинами, чем создают `Future` вручную.

Связь:

```text
Future
  ↑
  │
Task
  │
  └── представляет выполнение coroutine
```

`Task` концептуально является специализированным `Future`.

---

# 10. Как Event Loop взаимодействует с I/O

Здесь начинается более глубокая часть `asyncio`.

Event Loop не обязан постоянно проверять каждый сокет:

```text
"Ну что, данные пришли?"
"Ну что?"
"Ну что?"
```

Операционная система предоставляет механизмы ожидания событий I/O.

На Unix-системах это может быть:

* `select`
* `poll`
* `epoll`
* `kqueue`

Event Loop регистрирует интересующие его события и ждёт:

```text
Event Loop
    ↓
Selector
    ↓
ОС
    ↓
событие I/O
    ↓
готовый сокет
    ↓
Event Loop
    ↓
нужная Task продолжает работу
```

Это называется **I/O multiplexing**.

---

# 11. Почему asyncio особенно хорош для I/O-bound задач

Представим:

```text
HTTP-запрос
    ↓
отправили запрос
    ↓
ждём сервер 500 ms
```

Процессор в этот момент не обязан выполнять полезную работу именно этой задачи.

С asyncio:

```text
Task A
  ↓
ждёт HTTP

Task B
  ↓
работает

Task C
  ↓
ждёт БД

Task D
  ↓
работает
```

Один поток может эффективно обслуживать большое количество I/O-bound операций.

Типичные задачи:

* HTTP-клиенты;
* WebSocket;
* сетевые серверы;
* асинхронные БД;
* большое количество API-запросов;
* прокси;
* сетевые сервисы.

# 12. Самая важная проблема — блокирующий код

`asyncio` не превращает любой код в асинхронный.

Например:

```python
import time


async def bad():
    time.sleep(5)
```

Проблема:

```text
Event Loop
    ↓
bad()
    ↓
time.sleep(5)
    ↓
ВСЁ ЗАБЛОКИРОВАНО НА 5 СЕКУНД
```

Пока `time.sleep()` выполняется, Event Loop не может нормально переключаться на другие задачи.

Для asyncio нужно использовать:

```python
await asyncio.sleep(5)
```

Тогда:

```text
Task A
  ↓
await asyncio.sleep()
  ↓
уступает управление
  ↓
Task B
  ↓
Task C
```

---

# 13. Что делать с блокирующим кодом

Если есть синхронная блокирующая функция:

```python
def blocking_operation():
    ...
```

её можно вынести в отдельный поток:

```python
result = await asyncio.to_thread(
    blocking_operation
)
```

Получается:

```text
Event Loop
    │
    └── asyncio.to_thread()
             ↓
          Thread
             ↓
       blocking code
```

Для CPU-bound задач одного `asyncio` обычно недостаточно. Там может потребоваться multiprocessing / `ProcessPoolExecutor` или другой способ вынести CPU-нагрузку.

---

# 14. Asyncio ≠ Threading

| Asyncio                                          | Threading                                       |
| ------------------------------------------------ | ----------------------------------------------- |
| Обычно один поток Event Loop                     | Несколько потоков                               |
| Кооперативное переключение                       | Планирование потоков ОС                         |
| `await` уступает управление                      | Переключение потоков выполняет ОС/интерпретатор |
| Отлично для I/O                                  | I/O и другие сценарии                           |
| Нужен async-compatible код                       | Можно использовать обычный синхронный код       |
| Нет необходимости в Lock для каждой async-задачи | Нужна синхронизация shared state                |

Но у asyncio тоже существуют примитивы синхронизации:

```python
asyncio.Lock
asyncio.Semaphore
asyncio.Event
asyncio.Condition
asyncio.Queue
```

Они предназначены для координации **async-задач**, а не обычных потоков.

---

# 15. Asyncio ≠ Multiprocessing

```text
Asyncio
└── конкурентность
    └── эффективное ожидание I/O

Multiprocessing
└── параллелизм
    └── несколько процессов
        └── CPU-bound
```

Например:

### 100 HTTP-запросов

```text
asyncio → хороший сценарий
```

### Обработка огромного количества CPU-вычислений

```text
multiprocessing → подходящий инструмент
```

# 16. Полная модель asyncio

На собеседовании полезно держать в голове такую цепочку:

```text
async def
   ↓
Coroutine
   ↓
Task
   ↓
Event Loop
   ↓
await
   ↓
приостановка coroutine
   ↓
I/O
   ↓
Selector / ОС
   ↓
I/O готов
   ↓
Event Loop
   ↓
Task продолжает выполнение
```

Именно эта цепочка связывает практически все основные понятия `asyncio`.

# 17. Где здесь `yield`

`asyncio` тесно связан с концепцией **кооперативного переключения**.

Когда корутина выполняет:

```python
await operation()
```

она фактически позволяет системе продолжить выполнение другой работы.

Но важно не смешивать:

```text
yield
```

и

```text
await
```

`yield` относится к генераторам.

`await` используется для ожидания **awaitable** в асинхронном коде.

Исторически asyncio действительно строился на механизмах генераторов и `yield from`, но современный код использует:

```python
async def
await
```

# 18. `asyncio.run()`

Обычно точкой входа в asyncio-программу является:

```python
asyncio.run(main())
```

Например:

```python
import asyncio


async def main():
    print("Hello")


asyncio.run(main())
```

`asyncio.run()` запускает основную корутину внутри Event Loop и завершает его после окончания работы.

---

# 19. Пример реального сценария

Допустим, API должен получить информацию о трёх сервисах:

```text
Service A ── 500 ms
Service B ── 300 ms
Service C ── 700 ms
```

Последовательно:

```python
a = await request_a()
b = await request_b()
c = await request_c()
```

Время ожидания примерно:

```text
500 + 300 + 700 = 1500 ms
```

Конкурентно:

```python
results = await asyncio.gather(
    request_a(),
    request_b(),
    request_c(),
)
```

В идеализированном случае:

```text
max(500, 300, 700) = 700 ms
```

Плюс накладные расходы.

Именно поэтому asyncio полезен для сервисов, которые одновременно обслуживают множество I/O-операций.

---

# 20. Главная ловушка на собеседовании

Нельзя говорить:

> «Asyncio позволяет выполнять код параллельно».

Это слишком грубое и обычно неверное утверждение.

Лучше:

> **Asyncio обеспечивает конкурентное выполнение задач в Event Loop. Пока одна задача ожидает I/O через `await`, Event Loop может выполнять другие задачи. Сам по себе asyncio не даёт CPU-параллелизм в одном потоке.**

Это существенно точнее.
