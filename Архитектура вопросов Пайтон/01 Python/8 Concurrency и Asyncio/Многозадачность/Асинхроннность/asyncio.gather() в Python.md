# ⚡ asyncio.gather() в Python

## 🎤 Короткий ответ

**`asyncio.gather()`** — функция из библиотеки `asyncio`, которая позволяет конкурентно выполнять несколько асинхронных операций и получать их результаты.

Она принимает несколько awaitable-объектов (например, корутины или задачи), запускает их конкурентно в рамках Event Loop и возвращает результаты в том же порядке, в котором были переданы операции.

По умолчанию, если одна операция завершается с исключением, `gather()` передаёт его вызывающему коду, но не отменяет автоматически остальные задачи.

## 🗣️ Ответ на собеседовании

`asyncio.gather()` используется, когда нужно выполнить несколько независимых асинхронных операций конкурентно и дождаться их результатов.

Например, Backend-сервису необходимо одновременно получить информацию о пользователе, заказах и платежах из разных внешних API.

Вместо последовательного выполнения трёх запросов можно передать соответствующие корутины в `asyncio.gather()`.

Если передать корутины, `gather()` автоматически запланирует их выполнение как задачи в Event Loop. При этом конкурентность достигается за счёт переключения между задачами во время `await`, а не за счёт создания отдельных потоков.

Результаты возвращаются в порядке переданных операций, независимо от того, какая завершилась раньше.

Также у `gather()` есть параметр `return_exceptions=True`, позволяющий собрать исключения вместе с успешными результатами.

В современных версиях Python для структурированной конкурентности часто используют `asyncio.TaskGroup`, особенно когда требуется отменять остальные задачи при ошибке одной из них.

## 📚 Разбор поглубже

### 1. Зачем нужен asyncio.gather()

Представим, что необходимо выполнить три запроса к внешним сервисам.

Каждый запрос занимает одну секунду.

При последовательном выполнении:

```python
import asyncio


async def fetch_data(name):
    await asyncio.sleep(1)
    return f"{name}: готово"


async def main():
    user = await fetch_data("User")
    orders = await fetch_data("Orders")
    payments = await fetch_data("Payments")

    print(user, orders, payments)


asyncio.run(main())
```

Каждая операция начинается после завершения предыдущей.

Общее время — примерно 3 секунды.

Теперь используем `gather()`:

```python
import asyncio


async def fetch_data(name):
    await asyncio.sleep(1)
    return f"{name}: готово"


async def main():
    results = await asyncio.gather(
        fetch_data("User"),
        fetch_data("Orders"),
        fetch_data("Payments"),
    )

    print(results)


asyncio.run(main())
```

Результат:

```text
['User: готово', 'Orders: готово', 'Payments: готово']
```

Общее время — примерно 1 секунда.

Почему?

Потому что все три операции ожидают завершения таймера конкурентно. Пока одна корутина находится в состоянии ожидания, Event Loop может выполнять другие.

**Важно:** это не означает, что Python одновременно выполняет три участка CPU-bound кода. Здесь конкурентность эффективна благодаря неблокирующим операциям ожидания.

### 2. Как работает asyncio.gather()

Общая схема:

```text
                main()
                   |
                   v
           asyncio.gather()
                   |
          ┌────────┼────────┐
          v        v        v
       Task A   Task B   Task C
          |        |        |
        await    await    await
          |        |        |
          └────────┼────────┘
                   |
                   v
              Event Loop
                   |
                   v
           Сбор результатов
                   |
                   v
             [A, B, C]
```

Последовательность:

1. `gather()` принимает awaitable-объекты.
2. Если переданы корутины, они автоматически планируются как задачи.
3. Event Loop переключается между готовыми к выполнению задачами.
4. Когда операции завершаются, `gather()` собирает их результаты.
5. `await gather(...)` возвращает список результатов.

### 3. Порядок результатов

Одна из особенностей `gather()` — результаты возвращаются в порядке аргументов, а не в порядке завершения.

```python
import asyncio


async def worker(name, delay):
    await asyncio.sleep(delay)
    print(f"{name} завершился")
    return name


async def main():
    results = await asyncio.gather(
        worker("A", 3),
        worker("B", 1),
        worker("C", 2),
    )

    print(results)


asyncio.run(main())
```

Вывод:

```text
B завершился
C завершился
A завершился
['A', 'B', 'C']
```

Хотя задача B завершилась первой, её результат остался на второй позиции.

Это удобно, когда результат каждой операции должен соответствовать определённому аргументу.

### 4. Обработка исключений

По умолчанию `return_exceptions=False`.

```python
import asyncio


async def success():
    await asyncio.sleep(1)
    return "OK"


async def failure():
    await asyncio.sleep(0.5)
    raise ValueError("Ошибка обработки")


async def main():
    try:
        results = await asyncio.gather(
            success(),
            failure(),
        )
        print(results)
    except ValueError as error:
        print(f"Поймали ошибку: {error}")


asyncio.run(main())
```

Если одна операция выбрасывает исключение, `gather()` передаёт его вызывающему коду.

При этом остальные задачи **не отменяются автоматически**.

Но есть нюанс: в примере `asyncio.run()` завершает работу после выхода из `main()` и отменяет оставшиеся задачи при закрытии цикла выполнения. Это не автоматическая отмена со стороны `gather()`.

### 5. return_exceptions=True

Если необходимо получить результаты всех операций, включая ошибки:

```python
import asyncio


async def divide(a, b):
    await asyncio.sleep(0.1)
    return a / b


async def main():
    results = await asyncio.gather(
        divide(10, 2),
        divide(10, 0),
        divide(20, 4),
        return_exceptions=True,
    )

    for result in results:
        if isinstance(result, BaseException):
            print(f"Ошибка: {result}")
        else:
            print(f"Результат: {result}")


asyncio.run(main())
```

Пример вывода:

```text
Результат: 5.0
Ошибка: division by zero
Результат: 5.0
```

При `return_exceptions=True` исключения обычных задач становятся элементами списка результатов.

Это полезно, когда ошибки отдельных операций не должны прерывать сбор остальных результатов.

Но их обязательно нужно обработать, иначе можно случайно принять исключение за успешный результат.

### 6. gather() и create_task()

Эти инструменты связаны, но выполняют разные задачи.

**`asyncio.create_task()`** создаёт и планирует отдельную задачу.

```python
task = asyncio.create_task(fetch_data("User"))
```

**`asyncio.gather()`** позволяет конкурентно выполнять несколько awaitable-объектов и собрать результаты.

```python
results = await asyncio.gather(
    fetch_data("User"),
    fetch_data("Orders"),
)
```

Можно использовать их совместно:

```python
async def main():
    user_task = asyncio.create_task(fetch_data("User"))
    orders_task = asyncio.create_task(fetch_data("Orders"))

    results = await asyncio.gather(
        user_task,
        orders_task,
    )

    print(results)
```

Здесь `create_task()` создаёт задачи, а `gather()` ожидает их завершения и собирает результаты.

Если не требуется отдельно управлять задачами, обычно достаточно передать корутины непосредственно в `gather()`.

### 7. gather() vs TaskGroup

Начиная с Python 3.11 доступен `asyncio.TaskGroup`.

Пример:

```python
import asyncio


async def worker(name):
    await asyncio.sleep(1)
    return f"{name}: OK"


async def main():
    async with asyncio.TaskGroup() as group:
        task1 = group.create_task(worker("A"))
        task2 = group.create_task(worker("B"))

    print(task1.result())
    print(task2.result())


asyncio.run(main())
```

Различия:

| Характеристика | gather() | TaskGroup |
|---|---|---|
| Конкурентный запуск | Да | Да |
| Сбор результатов | Список | Через объекты Task |
| Автоматическая отмена остальных при обычной ошибке одной задачи | Нет | Да |
| Структурированная конкурентность | Нет в строгом смысле | Да |
| Доступность | Давно в asyncio | Python 3.11+ |

При ошибке одной задачи `TaskGroup` обычно отменяет остальные незавершённые задачи и после завершения группы поднимает `ExceptionGroup`.

Это делает управление жизненным циклом связанных задач более предсказуемым.

### 8. gather() vs wait() vs as_completed()

| Инструмент | Когда использовать |
|---|---|
| `asyncio.gather()` | Нужно дождаться нескольких операций и получить результаты в порядке аргументов |
| `asyncio.wait()` | Нужно управлять ожиданием набора задач, например до первого завершения |
| `asyncio.as_completed()` | Нужно обрабатывать результаты по мере завершения операций |
| `asyncio.TaskGroup` | Нужна структурированная конкурентность и согласованная обработка ошибок |

Например, если необходимо получить все результаты в фиксированном порядке, удобно использовать `gather()`.

Если важнее сразу обрабатывать самый быстрый ответ, может подойти `as_completed()`.

### 9. Ограничение конкурентности через Semaphore

Предположим, необходимо выполнить 1000 HTTP-запросов.

Запускать все одновременно может быть нежелательно из-за ограничений внешнего API или нагрузки на сервис.

Можно использовать `asyncio.Semaphore`.

```python
import asyncio


semaphore = asyncio.Semaphore(5)


async def fetch_data(number):
    async with semaphore:
        print(f"Запрос {number}")
        await asyncio.sleep(1)
        return number


async def main():
    results = await asyncio.gather(
        *(fetch_data(i) for i in range(20))
    )

    print(results)


asyncio.run(main())
```

Здесь:

- `gather()` организует конкурентное выполнение 20 операций.
- `Semaphore(5)` разрешает одновременно находиться внутри защищённого участка не более чем пяти задачам.
- Остальные ожидают освобождения разрешения.

Важно: Semaphore ограничивает число одновременно выполняемых операций внутри участка, но сам по себе не ограничивает количество запросов в секунду.

### 10. Таймауты и отмена

Если нужно ограничить время выполнения группы операций, можно использовать `asyncio.wait_for()`:

```python
import asyncio


async def worker():
    await asyncio.sleep(10)
    return "OK"


async def main():
    try:
        results = await asyncio.wait_for(
            asyncio.gather(worker(), worker()),
            timeout=2,
        )
        print(results)

    except TimeoutError:
        print("Превышено время ожидания")


asyncio.run(main())
```

Если таймаут истёк, `wait_for()` отменяет ожидаемую операцию. Отмена `gather()` распространяется на незавершённые дочерние задачи.

При этом код корутин должен корректно обрабатывать отмену и не подавлять `asyncio.CancelledError` без необходимости.

### 11. Когда использовать в Backend

Типичный сценарий — агрегирующий API.

Например, endpoint должен получить:

- данные пользователя;
- список заказов;
- историю платежей.

Эти операции независимы и выполняют сетевой I/O.

```python
async def get_dashboard(user_id):
    user, orders, payments = await asyncio.gather(
        get_user(user_id),
        get_orders(user_id),
        get_payments(user_id),
    )

    return {
        "user": user,
        "orders": orders,
        "payments": payments,
    }
```

Такой подход позволяет сократить общее время ожидания по сравнению с последовательными запросами.

Но важно учитывать ограничения подключений к БД, внешних API и общих ресурсов. Не всякий асинхронный код безопасно выполнять конкурентно — например, несколько операций через одну и ту же сессию SQLAlchemy `AsyncSession` не следует запускать одновременно.

### 12. Типичные ошибки

**Ошибка 1. Считать gather() параллельным выполнением на нескольких ядрах.**

`gather()` обеспечивает конкурентность асинхронных задач, но не создаёт автоматически отдельные процессы или потоки.

**Ошибка 2. Использовать блокирующий код внутри async-функции.**

```python
import time


async def bad_worker():
    time.sleep(2)  # Блокирует Event Loop
```

Правильно для асинхронного ожидания:

```python
import asyncio


async def good_worker():
    await asyncio.sleep(2)
```

**Ошибка 3. Считать, что gather() возвращает результаты по мере завершения.**

Результаты упорядочены по переданным аргументам.

**Ошибка 4. Считать, что gather() отменяет все задачи при ошибке одной из них.**

По умолчанию этого не происходит.

**Ошибка 5. Использовать return_exceptions=True и не проверять результаты.**

В списке могут оказаться объекты исключений.

**Ошибка 6. Запускать слишком много задач без ограничения ресурсов.**

При большом количестве операций нужно учитывать лимиты соединений, памяти и внешних сервисов.

## 🎤 Вопросы на собеседовании

**1. Что такое asyncio.gather()?**

Это функция для конкурентного выполнения нескольких awaitable-объектов и сбора их результатов.

**2. В каком порядке возвращаются результаты?**

В порядке переданных аргументов, независимо от порядка завершения задач.

**3. Создаёт ли gather() задачи автоматически?**

Да. Переданные корутины автоматически планируются как задачи.

**4. Что произойдёт, если одна задача завершится с исключением?**

По умолчанию исключение передаётся вызывающему коду. Остальные задачи не отменяются автоматически.

**5. Для чего нужен return_exceptions=True?**

Чтобы собрать исключения в списке результатов вместе с успешными значениями.

**6. Чем gather() отличается от create_task()?**

`create_task()` создаёт и планирует отдельную задачу. `gather()` координирует несколько awaitable-объектов и собирает результаты.

**7. Чем gather() отличается от TaskGroup?**

`TaskGroup` обеспечивает структурированную конкурентность и при обычной ошибке одной задачи отменяет остальные. `gather()` по умолчанию этого не делает.

**8. Подходит ли gather() для CPU-bound задач?**

Сам по себе нет. Для вычислительных задач может потребоваться multiprocessing, ProcessPoolExecutor или другие способы параллельного выполнения.

**9. Как ограничить количество одновременно выполняемых операций?**

Использовать `asyncio.Semaphore` или другой механизм ограничения конкурентности.

**10. Когда gather() полезен в Backend?**

Когда нужно конкурентно выполнить несколько независимых I/O-bound операций, например HTTP-запросы к внешним сервисам, и дождаться всех результатов.
