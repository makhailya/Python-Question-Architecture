# ⚡ asyncio.as_completed() в Python

## 🎤 Короткий ответ

**`asyncio.as_completed()`** — функция из стандартной библиотеки Python, которая позволяет обрабатывать результаты нескольких асинхронных операций **по мере их завершения**, не дожидаясь остальных.

В отличие от `asyncio.gather()`, который возвращает результаты в порядке переданных аргументов, `as_completed()` позволяет получать результаты в порядке готовности.

Это полезно при работе с несколькими внешними API, загрузке данных и обработке независимых I/O-bound операций.

## 🗣️ Ответ на собеседовании

`asyncio.as_completed()` используется, когда нужно запустить несколько асинхронных операций конкурентно и обрабатывать их результаты сразу после завершения каждой.

Например, Backend-сервис отправляет запросы к пяти внешним API. Один отвечает за секунду, другой — за три, третий — за пять.

Если использовать `gather()`, мы получим итоговый список после завершения всех запросов. А с `as_completed()` можем обработать первый результат уже через секунду, пока остальные запросы продолжают выполняться.

Функция принимает коллекцию awaitable-объектов и обеспечивает их конкурентное выполнение.

В Python 3.13+ она поддерживает асинхронную итерацию через `async for`, а также обычную итерацию, доступную в более ранних версиях.

Важный момент: `as_completed()` не гарантирует успешного выполнения задач. Исключения нужно обрабатывать, а при досрочном завершении обработки — контролировать оставшиеся задачи.

## 📚 Разбор поглубже

### 1. Зачем нужен asyncio.as_completed()

Представим три асинхронных запроса:

| Запрос | Время выполнения |
|---|---|
| A | 3 секунды |
| B | 1 секунда |
| C | 2 секунды |

С `asyncio.gather()` мы получим результаты примерно через три секунды:

```python
import asyncio


async def worker(name, delay):
    await asyncio.sleep(delay)
    return name


async def main():
    results = await asyncio.gather(
        worker("A", 3),
        worker("B", 1),
        worker("C", 2),
    )

    print(results)


asyncio.run(main())
```

Результат:

```text
['A', 'B', 'C']
```

Хотя B завершился первым, результаты сохраняют порядок аргументов.

Теперь используем `as_completed()`:

```python
import asyncio


async def worker(name, delay):
    await asyncio.sleep(delay)
    return name


async def main():
    coroutines = [
        worker("A", 3),
        worker("B", 1),
        worker("C", 2),
    ]

    for completed in asyncio.as_completed(coroutines):
        result = await completed
        print(result)


asyncio.run(main())
```

Результат:

```text
B
C
A
```

Теперь результаты обрабатываются по мере готовности:

- B — примерно через 1 секунду;
- C — примерно через 2 секунды;
- A — примерно через 3 секунды.

Общее время выполнения остаётся примерно три секунды, но первые результаты доступны значительно раньше.

### 2. Как работает asyncio.as_completed()

Упрощённая схема:

```text
            asyncio.as_completed()
                      |
            ┌─────────┼─────────┐
            v         v         v
          Task A    Task B    Task C
            3с        1с        2с
                      |
                      v
                B завершилась
                      |
                      v
               Обработка B
                      |
                      v
                C завершилась
                      |
                      v
               Обработка C
                      |
                      v
                A завершилась
                      |
                      v
               Обработка A
```

Важный принцип:

**Порядок обработки определяется временем завершения операций, а не порядком их запуска.**

### 3. Синтаксис

```python
asyncio.as_completed(
    aws,
    timeout=None,
)
```

Где:

- `aws` — итерируемая коллекция awaitable-объектов;
- `timeout` — необязательное ограничение общего времени ожидания завершения всех операций.

Функция возвращает объект, который можно перебирать.

В Python 3.12 и более ранних версиях используется обычная итерация. В Python 3.13+ дополнительно доступна асинхронная итерация.

### 4. Обычная итерация — for

Этот способ работает в Python 3.11, 3.12, 3.13 и более новых версиях.

```python
import asyncio


async def fetch_data(number):
    await asyncio.sleep(number)
    return number * 10


async def main():
    tasks = [
        fetch_data(3),
        fetch_data(1),
        fetch_data(2),
    ]

    for completed in asyncio.as_completed(tasks):
        result = await completed
        print(result)


asyncio.run(main())
```

Результат:

```text
10
20
30
```

Разберём ключевые строки.

`fetch_data(number)` — асинхронная функция, имитирующая операцию с задержкой.

`tasks` — список объектов корутин. Несмотря на название переменной, на этом этапе это ещё не объекты `Task`.

`asyncio.as_completed(tasks)` — организует конкурентное выполнение переданных операций.

`for completed in ...` — получает очередной awaitable-объект, позволяющий дождаться следующего готового результата.

`await completed` — возвращает результат соответствующей завершившейся операции или поднимает её исключение.

### 5. Асинхронная итерация — async for (Python 3.13+)

Начиная с Python 3.13 `as_completed()` поддерживает `async for`.

```python
import asyncio


async def worker(name, delay):
    await asyncio.sleep(delay)
    return name


async def main():
    tasks = [
        asyncio.create_task(worker("A", 3)),
        asyncio.create_task(worker("B", 1)),
        asyncio.create_task(worker("C", 2)),
    ]

    async for completed_task in asyncio.as_completed(tasks):
        print(completed_task.result())


asyncio.run(main())
```

При передаче заранее созданных объектов `Task` асинхронная итерация возвращает именно эти исходные задачи.

Это позволяет определить, какая задача завершилась.

Например:

```python
import asyncio


async def worker(name, delay):
    await asyncio.sleep(delay)
    return name


async def main():
    task_a = asyncio.create_task(
        worker("A", 2),
        name="task_a",
    )

    task_b = asyncio.create_task(
        worker("B", 1),
        name="task_b",
    )

    async for task in asyncio.as_completed([task_a, task_b]):
        print(task.get_name(), task.result())


asyncio.run(main())
```

Результат:

```text
task_b B
task_a A
```

**Важный нюанс:** при обычном `for` возвращаются новые awaitable-объекты для получения очередного результата, а не исходные `Task`. Поэтому нельзя рассчитывать, что `completed is task_a` будет работать.

### 6. Обработка исключений

Любая асинхронная операция может завершиться ошибкой.

```python
import asyncio


async def worker(number):
    await asyncio.sleep(number * 0.1)

    if number == 2:
        raise ValueError("Ошибка второй задачи")

    return number * 10


async def main():
    coroutines = [
        worker(1),
        worker(2),
        worker(3),
    ]

    for completed in asyncio.as_completed(coroutines):
        try:
            result = await completed
            print("Результат:", result)

        except ValueError as error:
            print("Ошибка:", error)


asyncio.run(main())
```

Пример результата:

```text
Результат: 10
Ошибка: Ошибка второй задачи
Результат: 30
```

Здесь ошибка одной операции не мешает нам обработать остальные результаты, потому что исключение перехватывается внутри цикла.

`as_completed()` сам по себе не подавляет исключения.

### 7. Таймауты

У `asyncio.as_completed()` есть параметр `timeout`.

```python
import asyncio


async def worker(delay):
    await asyncio.sleep(delay)
    return delay


async def main():
    tasks = [
        asyncio.create_task(worker(1)),
        asyncio.create_task(worker(5)),
    ]

    try:
        for completed in asyncio.as_completed(
            tasks,
            timeout=2,
        ):
            result = await completed
            print(result)

    except TimeoutError:
        print("Время ожидания истекло")

    finally:
        for task in tasks:
            if not task.done():
                task.cancel()

        await asyncio.gather(
            *tasks,
            return_exceptions=True,
        )


asyncio.run(main())
```

Пример результата:

```text
1
Время ожидания истекло
```

Таймаут относится ко всему набору операций, а не начинается заново для каждого результата.

При превышении таймаута возникает `TimeoutError`, если не все операции успели завершиться.

**Важно:** `as_completed()` не отменяет оставшиеся задачи автоматически. Поэтому в примере мы отменяем незавершённые задачи и дожидаемся обработки отмены.

### 8. asyncio.as_completed() vs asyncio.gather()

Это главное сравнение для собеседования.

| Характеристика | gather() | as_completed() |
|---|---|---|
| Конкурентный запуск | Да | Да |
| Порядок результатов | Порядок аргументов | Порядок завершения |
| Получение результатов | После завершения всех при успешном выполнении | По мере готовности |
| Автоматическая отмена остальных при обычной ошибке | Нет | Нет |
| Удобно для потоковой обработки результатов | Не напрямую | Да |
| Поддержка таймаута параметром | Нет | Да |

**Когда выбирать gather()?**

Когда необходимо получить все результаты в заранее известном порядке.

**Когда выбирать as_completed()?**

Когда важно начать обработку результатов сразу после их появления.

### 9. asyncio.as_completed() vs asyncio.wait()

Оба инструмента могут использоваться для обработки задач по мере завершения, но предоставляют разные интерфейсы.

**asyncio.wait():**

```python
done, pending = await asyncio.wait(
    tasks,
    return_when=asyncio.FIRST_COMPLETED,
)
```

Возвращает два множества: завершённые и незавершённые задачи.

**asyncio.as_completed():**

```python
for completed in asyncio.as_completed(tasks):
    result = await completed
    print(result)
```

Предоставляет последовательность результатов по мере готовности.

| Инструмент | Когда использовать |
|---|---|
| `gather()` | Собрать все результаты |
| `wait()` | Получить множества `done` и `pending` |
| `as_completed()` | Последовательно обрабатывать готовые результаты |
| `TaskGroup` | Управлять жизненным циклом связанных задач |

### 10. Практический пример в Backend

Представим, что Backend-сервис получает информацию о товарах из нескольких независимых внешних API.

Каждый сервис отвечает с разной скоростью.

```python
import asyncio


async def fetch_product(source, delay):
    await asyncio.sleep(delay)

    return {
        "source": source,
        "price": 1000 + delay * 100,
    }


async def main():
    requests = [
        fetch_product("Store A", 3),
        fetch_product("Store B", 1),
        fetch_product("Store C", 2),
    ]

    async for result_task in asyncio.as_completed(requests):
        result = result_task.result()

        print(
            f"{result['source']}: "
            f"{result['price']} ₽"
        )


asyncio.run(main())
```

Этот вариант требует Python 3.13+.

Пример результата:

```text
Store B: 1100 ₽
Store C: 1200 ₽
Store A: 1300 ₽
```

Вместо ожидания всех трёх сервисов мы можем обрабатывать предложения сразу после получения.

В реальном Backend это может использоваться для:

- агрегации данных из внешних API;
- обработки результатов нескольких независимых запросов;
- постепенной отправки результатов клиенту через WebSocket или Server-Sent Events;
- параллельной проверки доступности сервисов.

### 11. Что происходит под капотом

`as_completed()` не создаёт отдельные потоки.

Он использует Event Loop и механизм асинхронных задач.

Упрощённо:

```text
       Коллекция awaitable
                |
                v
       asyncio.as_completed()
                |
                v
       Планирование корутин
                |
                v
             Event Loop
                |
       ┌────────┼────────┐
       v        v        v
     Task A   Task B   Task C
       |        |        |
     await    await    await
                |
                v
        Завершение Task B
                |
                v
      Доступен результат B
                |
                v
        Завершение Task C
                |
                v
      Доступен результат C
                |
                v
        Завершение Task A
                |
                v
      Доступен результат A
```

Event Loop отслеживает готовность задач и возобновляет их выполнение после завершения ожидаемых операций.

`as_completed()` позволяет потребителю получать результаты в соответствии с фактическим порядком завершения.

### 12. Типичные ошибки

**Ошибка 1. Считать, что as_completed() возвращает результаты в порядке аргументов.**

Нет. Результаты доступны в порядке завершения задач.

**Ошибка 2. Путать for и async for.**

Обычная итерация поддерживается в старых версиях Python.

Асинхронная итерация появилась в Python 3.13.

**Ошибка 3. Считать, что обычный for возвращает исходные Task.**

В обычной итерации возвращаются awaitable-объекты, через которые получают очередной результат.

**Ошибка 4. Игнорировать исключения.**

Ошибка внутри задачи проявляется при получении её результата. Исключения необходимо обрабатывать.

**Ошибка 5. Считать, что timeout отменяет задачи.**

Нет. Незавершённые задачи требуют отдельного управления.

**Ошибка 6. Использовать as_completed() для CPU-bound вычислений в надежде получить параллелизм.**

`asyncio` эффективен прежде всего для неблокирующих I/O-bound операций. Тяжёлый синхронный код блокирует Event Loop.

**Ошибка 7. Не учитывать ограничения внешних сервисов.**

При запуске большого количества запросов нужно контролировать конкурентность, например через `asyncio.Semaphore`.

## 🎤 Вопросы на собеседовании

**1. Что делает asyncio.as_completed()?**

Позволяет конкурентно выполнять несколько awaitable-объектов и обрабатывать их результаты по мере завершения.

**2. Чем as_completed() отличается от gather()?**

`gather()` возвращает результаты в порядке аргументов после завершения всех операций, а `as_completed()` позволяет получать результаты в порядке готовности.

**3. Чем as_completed() отличается от wait()?**

`wait()` возвращает множества завершённых и незавершённых задач, а `as_completed()` предоставляет результаты по мере завершения.

**4. Можно ли передавать корутины напрямую?**

Да. В отличие от `asyncio.wait()`, `as_completed()` принимает корутины и организует их выполнение.

**5. Что произойдёт, если одна задача завершится с исключением?**

Исключение будет поднято при получении результата этой задачи. Его можно перехватить и продолжить обработку остальных.

**6. Поддерживает ли as_completed() таймаут?**

Да, через параметр `timeout`. Он ограничивает общее время ожидания завершения операций.

**7. Отменяются ли задачи при таймауте?**

Нет. Незавершённые задачи необходимо отменять отдельно, если дальнейшее выполнение не требуется.

**8. В чём отличие for от async for?**

Обычный `for` возвращает awaitable-объекты для получения результатов. В Python 3.13+ `async for` позволяет получать исходные Task/Future, если они были переданы, либо созданные задачи для корутин.

**9. Когда использовать as_completed() в Backend?**

Когда нужно обрабатывать результаты независимых сетевых запросов по мере готовности, например при агрегации данных из нескольких API.

**10. Может ли as_completed() ускорить выполнение всех задач?**

Сам по себе он не ускоряет отдельные операции. Его преимущество — возможность раньше начать обработку готовых результатов, пока остальные операции ещё выполняются.
