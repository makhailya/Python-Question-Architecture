# 🧩 Конкурентность

## 🎤 Короткий ответ

**Конкурентность (concurrency)** — это способность системы организовывать выполнение нескольких задач так, чтобы они могли **продвигаться вперёд в пересекающемся временном интервале**.

При этом задачи **не обязаны выполняться физически одновременно**.

Например, если одна задача ждёт ответа от БД, выполнение может переключиться на другую:

```text
Задача A → работа → ожидание БД ─────────→ продолжение
                         ↓
Задача B → работа → работа → работа
```

Конкурентность — это прежде всего **способ организации выполнения задач**, а не количество ядер CPU.

---

## 🗣️ Ответ на собеседовании

Конкурентность — это возможность системы работать с несколькими задачами в одном временном интервале, позволяя им независимо продвигаться вперёд.

При этом конкурентность не означает, что задачи выполняются одновременно. Например, на одном ядре [[CPU-bound]] система может переключаться между несколькими задачами. Если одна задача ожидает [[IO-bound]] — например, ответ от базы данных или сети — процессор может выполнять другую задачу.

Конкурентность можно реализовать разными способами: через [[Многопоточность (Multithreading)]], [[Многопроцессность (Multiprocessing)]] или [[Асинхронность (Asyncio)]]. В `asyncio`, например, задачи выполняются конкурентно через [[Event Loop — цикл событий]]: когда одна [[Корутина - (coroutine)]] доходит до [[await]] и ожидает I/O, [[Event Loop — цикл событий]] может передать управление другой готовой задаче.

От **[[Параллелизм (Parallelism)]]а** конкурентность отличается тем, что параллелизм означает фактическое одновременное выполнение нескольких задач, например на разных ядрах [[CPU-bound]].

# 📚 Разбор поглубже

## 1. Что такое конкурентность

Представим две задачи:

```text
A — загрузить данные из БД
B — обработать другой HTTP-запрос
```

Если выполнять их строго последовательно:

```text
Время →

A █████████████████
B                  █████████████████
```

Вторая задача ждёт полного завершения первой.

При конкурентном подходе:

```text
Время →

A ████──────████
B     ███████████
```

Задача `A` дошла до операции ожидания.

Пока она ждёт, система занимается `B`.

После завершения ожидания `A` снова получает возможность продолжить работу.

---

# 2. Конкурентность ≠ параллелизм

Это главное различие.

### Конкурентность

```text
A ████    ████
B     █████
```

Задачи чередуются или одна выполняется во время ожидания другой.

### Параллелизм

```text
CPU 1 → A █████████
CPU 2 → B █████████
```

Задачи действительно выполняются одновременно.

Можно сформулировать так:

> **Concurrency — несколько задач могут продвигаться вперёд.**

> **Parallelism — несколько задач выполняются одновременно физически.**

---

# 3. Конкурентность на одном ядре

Конкурентность возможна даже при одном CPU-ядре.

Например:

```text
CPU
│
├── Task A
├── Task B
└── Task C
```

Процессор не может физически выполнять все три инструкции одновременно на одном ядре.

Он переключается:

```text
Время →

A A A A B B C C A A B C C
```

Каждая задача получает часть времени CPU.

Это пример конкурентного выполнения **без параллелизма**.

---

# 4. Context Switch

Переключение между выполняющимися задачами связано с понятием **context switch**.

Упрощённо:

```text
Task A
  │
  ├── CPU выполняет A
  │
  └── переключение
          ↓
Task B
  │
  └── CPU выполняет B
```

Система должна сохранить состояние выполнения одной задачи и восстановить состояние другой.

Частые переключения имеют стоимость:

```text
context switch
      ↓
сохранение состояния
      ↓
загрузка состояния другой задачи
      ↓
продолжение выполнения
```

Поэтому многозадачность не означает, что добавление большого количества задач автоматически ускоряет программу.

---

# 5. Кооперативная конкурентность

В асинхронных системах часто используется **кооперативная модель**.

Задача сама отдаёт управление в определённых точках.

В `asyncio` такой точкой часто является `await`:

```python
async def fetch():
    result = await get_data()
    return result
```

Упрощённо:

```text
Task A
  │
  ▼
await I/O
  │
  └──────► управление Event Loop
                  │
                  ▼
               Task B
                  │
                  ▼
               Task C
```

Когда операция `A` завершится, Event Loop сможет снова запланировать её продолжение.

---

# 6. Конкурентность и I/O-bound задачи

Конкурентность особенно полезна, когда задачи много времени проводят в ожидании.

Например:

```text
HTTP request
     ↓
отправили запрос
     ↓
      WAIT
     ↓
получили ответ
```

Вместо:

```text
A → WAIT → WAIT → WAIT
```

можно выполнять:

```text
A → WAIT
B → работа
C → работа
A → продолжение
```

Поэтому конкурентность особенно важна для backend-систем, где одновременно выполняются:

* HTTP-запросы;
* запросы к БД;
* обращения к внешним API;
* операции с сетью;
* чтение и запись данных.

---

# 7. Конкурентность и CPU-bound задачи

Если задача почти всё время занята вычислениями:

```text
Task
████████████████████████
       CPU работа
```

то простое переключение между задачами обычно не даёт такого преимущества, как при I/O-bound нагрузке.

Например:

```text
A → вычисляет
B → вычисляет
C → вычисляет
```

Если CPU одно, переключение между ними не создаёт дополнительной вычислительной мощности.

Для CPU-bound задач становится важен **параллелизм** — использование нескольких CPU-ядер.

---

# 8. Как реализуется конкурентность в Python

Есть несколько основных подходов.

```text
Конкурентность
│
├── Threading
│   └── несколько потоков
│
├── Multiprocessing
│   └── несколько процессов
│
└── Asyncio
    └── Event Loop + Tasks
```

### Threading

Несколько потоков могут работать внутри одного процесса:

```text
Process
├── Thread A
├── Thread B
└── Thread C
```

Память процесса общая.

---

### Multiprocessing

Создаются отдельные процессы:

```text
Process A
Process B
Process C
```

У каждого процесса своё адресное пространство.

---

### Asyncio

Обычно один поток управляет множеством задач:

```text
Event Loop
│
├── Task A
├── Task B
├── Task C
└── Task D
```

Когда одна задача ожидает неблокирующий I/O, Event Loop может заниматься другой.

---

# 9. Конкурентность — это не обязательно быстрее

Это важный нюанс.

Допустим, есть две маленькие CPU-задачи.

Последовательно:

```text
A █████
B      █████
```

Конкурентно:

```text
A ███  ███
B   ███  ██
```

При переключении появляются дополнительные расходы.

Поэтому конкурентность нужна не для того, чтобы **любую программу сделать быстрее**, а чтобы эффективнее организовать выполнение множества независимых задач.

Особенно хорошо это проявляется при I/O-bound нагрузке.

# 10. Конкурентность в backend

Представим сервер:

```text
Client A ──┐
Client B ──┤
Client C ──┼──► Backend
Client D ──┘
```

Каждый запрос может ожидать БД:

```text
Request A → PostgreSQL → WAIT
Request B → PostgreSQL → WAIT
Request C → внешний API → WAIT
```

Конкурентная модель позволяет не держать вычислительный ресурс без дела во время ожидания:

```text
A → DB WAIT
        ↓
B → работа
        ↓
C → API WAIT
        ↓
D → работа
        ↓
A → продолжение
```

Именно поэтому понимание конкурентности важно для Python Backend.

# 11. Связь с GIL

В CPython существует **GIL (Global Interpreter Lock)**, который влияет на выполнение Python-кода потоками.

Важно не делать неправильный вывод:

```text
GIL ≠ отсутствие конкурентности
```

Потоки могут конкурировать за выполнение Python-кода и особенно эффективно использоваться в сценариях с I/O.

Для CPU-bound Python-кода вопрос GIL становится существенно важнее, потому что несколько потоков одного процесса не дают обычного параллельного выполнения Python bytecode так, как несколько независимых процессов.

Поэтому:

```text
I/O-bound
    ↓
Threading / Asyncio

CPU-bound
    ↓
Multiprocessing / настоящий parallelism
```

Это упрощённая практическая схема; конкретный выбор зависит от библиотек, реализации и характера нагрузки.

# 🎤 Вопросы на собеседовании

### Что такое конкурентность?

Конкурентность — это организация выполнения нескольких задач таким образом, чтобы они могли независимо продвигаться вперёд в одном временном интервале.

### Обязательно ли при конкурентности задачи выполняются одновременно?

Нет. Они могут чередоваться на одном CPU-ядре.

### Может ли быть конкурентность на одном ядре?

Да. Процессор переключается между задачами.

### Чем конкурентность отличается от параллелизма?

Конкурентность — несколько задач находятся в процессе выполнения и получают возможность продвигаться.

Параллелизм — несколько задач **физически выполняются одновременно**, например на разных ядрах.

### Почему конкурентность полезна для I/O-bound задач?

Потому что во время ожидания I/O можно выполнять другую задачу вместо простоя CPU.

### Что такое Context Switch?

Переключение выполнения с одной задачи или потока на другую с сохранением и восстановлением их состояния.

### Как `asyncio` реализует конкурентность?

Через Event Loop, который управляет задачами и переключает выполнение между ними, когда текущая coroutine достигает точки ожидания, например `await`.

### Даёт ли конкурентность ускорение CPU-bound задачи?

Не обязательно. На одном ядре переключение между CPU-bound задачами само по себе не создаёт дополнительной вычислительной мощности.

### Как связаны concurrency и parallelism?

Параллелизм можно рассматривать как частный случай выполнения нескольких задач одновременно, тогда как конкурентность шире: задачи могут продвигаться конкурентно даже без физического одновременного исполнения.
