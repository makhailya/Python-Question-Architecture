# Добавление в конец списка — List Append Complexity

## Коротко

Добавление элемента в конец списка через `append()` имеет **амортизированную сложность `O(1)`**.

В большинстве случаев элемент добавляется за постоянное количество операций.

Иногда список должен расширить внутренний массив и перенести элементы. Такая отдельная операция может иметь сложность `O(n)`, но при большом количестве `append()` средняя стоимость одной операции остаётся `O(1)`.

## На собеседовании достаточно сказать

> Добавление элемента в конец списка через `append()` имеет амортизированную сложность `O(1)`.
>
> Иногда при заполнении внутреннего массива Python увеличивает его размер и переносит элементы. Такая операция может занять `O(n)`, но в среднем `append()` работает за `O(1)`.

## Что важно помнить

Python `list` реализован не как связанный список, а как **динамический массив**.

Когда места внутри выделенной памяти достаточно:

```python
numbers.append(4)
```

элемент просто добавляется в конец.

### Это O(1).

Когда свободного места недостаточно, Python выделяет больше памяти и переносит существующие элементы:

```
[1, 2, 3, 4]
        ↓
нужно больше места
        ↓
выделяется новый участок памяти
        ↓
элементы переносятся
        ↓
[1, 2, 3, 4, 5, ...]
```

Такая операция может быть O(n).

Но увеличение ёмкости происходит не после каждого append(), поэтому серия добавлений имеет амортизированную сложность O(1) на операцию.

## Простой пример

```python
numbers = [1, 2, 3]

numbers.append(4)

print(numbers)
# [1, 2, 3, 4]
```

Обычный append() в конец списка:

```
append() → O(1) амортизированно
```

## Главное

Не стоит говорить просто:

append() всегда имеет O(1).

## Точнее:

append() имеет амортизированную сложность O(1), но отдельная операция расширения списка может занять O(n).
