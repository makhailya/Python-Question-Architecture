# Поиск элемента в списке — List Search Complexity

## Коротко

Поиск элемента в обычном `list` имеет сложность **O(n)** в худшем случае.

Python может последовательно проверить каждый элемент списка, пока не найдёт нужный.

## На собеседовании достаточно сказать

> Поиск элемента по значению в списке имеет сложность O(n) в худшем случае, потому что Python последовательно проверяет элементы, пока не найдёт нужный или не дойдёт до конца списка.

## Что важно помнить

Например:

```python
numbers = [10, 20, 30, 40, 50]

30 in numbers
```

Python проверяет элементы последовательно:

```
10 → 20 → 30
         ↑
       нашли
```

В лучшем случае элемент находится сразу:

```
[30, 10, 20, 40, 50]
 ↑
нашли сразу
```

Но в худшем случае элемент находится в конце:

```
[10, 20, 30, 40, 50]
                  ↑
                нашли
```

Или элемента вообще нет:

```python
100 in numbers
```

Тогда Python проверит весь список.

Поэтому:

```
Лучший случай:   O(1)
Худший случай:   O(n)
```

## В контексте собеседований обычно отвечают O(n).

## Простой пример

```python
numbers = [10, 20, 30, 40, 50]

if 40 in numbers:
    print("Нашли")
```

Для поиска 40 Python последовательно проверяет элементы:

```
10 → 20 → 30 → 40
```

Сложность поиска в списке — O(n).

## Главное

Не путай две операции:

```python
numbers[3]
```

### Доступ по индексу → O(1)

```python
40 in numbers
```

### Поиск по значению → O(n) в худшем случае.

Именно поэтому выбор структуры данных важен.

Если требуется часто проверять наличие элемента, set или dict обычно подходят лучше, поскольку поиск по ключу/элементу в среднем имеет сложность O(1).
