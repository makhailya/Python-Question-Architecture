# Алгоритмическая сложность — Algorithmic Complexity

## Коротко

Алгоритмическая сложность показывает, **как изменяется количество ресурсов, необходимых алгоритму, при увеличении размера входных данных**.

Чаще всего рассматривают:

- **временную сложность** — сколько времени требуется алгоритму;
- **пространственную сложность** — сколько дополнительной памяти требуется алгоритму.

Для обозначения сложности обычно используют **Big O**: `O(1)`, `O(n)`, `O(log n)`, `O(n²)` и т. д.

## На собеседовании достаточно сказать

> Алгоритмическая сложность показывает, как изменяются затраты алгоритма по времени или памяти при увеличении размера входных данных.
>
> Обычно для этого используют Big O. Например, `O(1)` — постоянная сложность, а `O(n)` — линейная.

## Что важно помнить

Размер входных данных обычно обозначают буквой `n`.

Например, если у нас есть список из `n` элементов:

```python
numbers = [1, 2, 3, 4, 5]
```

и алгоритм должен проверить каждый элемент списка, количество операций будет зависеть от размера списка.

Если элементов станет в 10 раз больше, алгоритму в общем случае потребуется примерно в 10 раз больше операций.

### Это будет линейная сложность — O(n).

## Основные виды сложности

```
O(1)       постоянная
O(log n)   логарифмическая
O(n)       линейная
O(n log n) линейно-логарифмическая
O(n²)      квадратичная
O(2ⁿ)      экспоненциальная
```

Чем быстрее растёт сложность при увеличении n, тем хуже алгоритм масштабируется.

## Простой пример

Доступ к элементу списка по индексу:

```python
numbers = [10, 20, 30, 40, 50]

value = numbers[2]
```

Нам не нужно просматривать весь список. Мы сразу обращаемся к нужному индексу.

### Сложность такой операции — O(1).

А поиск элемента:

```python
numbers = [10, 20, 30, 40, 50]

if 50 in numbers:
    print("Нашли")
```

В худшем случае Python должен проверить все элементы.

Сложность — O(n).

## Главное

Алгоритмическая сложность нужна для того, чтобы оценивать, как алгоритм будет вести себя при увеличении количества данных.

## Например:

```
100 элементов      → быстро
1 000 элементов    → быстро
1 000 000 элементов → разница между O(1), O(n) и O(n²) становится существенной
```

Поэтому при выборе алгоритма важно учитывать не только то, что он работает, но и насколько хорошо он масштабируется.
