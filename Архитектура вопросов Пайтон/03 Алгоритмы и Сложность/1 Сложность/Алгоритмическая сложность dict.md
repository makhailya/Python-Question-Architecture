# Сложность операций `dict` в Python

## 🎯 Ответ на собеседовании

> `dict` в Python реализован на основе **хеш-таблицы**. Поэтому поиск, добавление и удаление элемента по ключу в среднем имеют сложность **O(1)**.
>
> В худшем случае отдельная операция может иметь **O(n)**, например из-за коллизий хешей.
>
> При этом перебор всех элементов словаря, получение всех ключей или значений занимает **O(n)**.

---

## 📊 Основные операции

| Операция           |   Средняя | Худшая | Пример               |
| ------------------ | --------: | -----: | -------------------- |
| Получение по ключу |  **O(1)** |   O(n) | `d[key]`             |
| `get()`            |  **O(1)** |   O(n) | `d.get(key)`         |
| Добавление         | **O(1)*** |   O(n) | `d[key] = value`     |
| Изменение          | **O(1)*** |   O(n) | `d[key] = new_value` |
| Удаление           |  **O(1)** |   O(n) | `del d[key]`         |
| `pop()`            |  **O(1)** |   O(n) | `d.pop(key)`         |
| Проверка ключа     |  **O(1)** |   O(n) | `key in d`           |
| `len()`            |  **O(1)** |   O(1) | `len(d)`             |
| `keys()`           |  **O(1)** |   O(1) | `d.keys()`           |
| `values()`         |  **O(1)** |   O(1) | `d.values()`         |
| `items()`          |  **O(1)** |   O(1) | `d.items()`          |
| Перебор            |  **O(n)** |   O(n) | `for k in d`         |
| `copy()`           |  **O(n)** |   O(n) | `d.copy()`           |

`*` — обычно O(1), но при изменении внутренней таблицы возможна операция перераспределения.

# 🔑 Почему `dict` работает быстро?

Словарь хранит пары:

```python id="0w4yqr"
user = {
    "name": "Ilya",
    "age": 31
}
```

У каждой пары есть:

```text id="nq3v9j"
ключ → значение
```

Когда мы выполняем:

```python id="f5hhj5"
user["name"]
```

Python примерно делает:

```text id="s5a5l7"
"name"
   ↓
hash("name")
   ↓
определение позиции в хеш-таблице
   ↓
поиск значения
   ↓
"Ilya"
```

Поэтому не нужно перебирать все элементы словаря.

---

# 💥 Коллизии

Иногда разные ключи могут получить одинаковую позицию/конфликт при размещении в хеш-таблице.

Это называется **коллизией**.

Упрощённо:

```text id="l0h5w1"
key1 ──→ hash ──→ позиция 5
key2 ──→ hash ──→ позиция 5
```

Python должен разрешить такую коллизию и найти нужный ключ.

В обычной ситуации это не проблема, поэтому операции остаются очень быстрыми.

Но теоретически в худшем случае:

**O(n)**

---

# 🔍 Получение элемента

```python id="9m6n8p"
value = user["name"]
```

Средняя сложность:

**O(1)**

То же самое:

```python id="0dd7gi"
user.get("name")
```

---

# ➕ Добавление

```python id="7s7n2k"
user["city"] = "Yekaterinburg"
```

Средняя сложность:

**O(1)**

Python вычисляет хеш ключа и определяет, где разместить значение.

---

# ❌ Удаление

```python id="s5sp8q"
del user["age"]
```

Средняя сложность:

**O(1)**

Аналогично:

```python id="0e1qgi"
user.pop("age")
```

---

# 🔎 Проверка наличия ключа

```python id="qg3g8h"
if "name" in user:
    ...
```

Средняя сложность:

**O(1)**

Важно:

```python id="v8klk4"
"name" in user
```

проверяет **ключи**, а не значения.

А вот:

```python id="pj6o7p"
"Ilya" in user.values()
```

требует перебора значений:

**O(n)**

---

# 🔄 Перебор словаря

```python id="0x3t4k"
for key, value in user.items():
    print(key, value)
```

Если в словаре `n` элементов, мы посещаем каждый элемент:

**O(n)**

---

# 📦 `keys()`, `values()`, `items()`

```python id="4r5t8p"
user.keys()
user.values()
user.items()
```

Создание этих представлений (`dict_keys`, `dict_values`, `dict_items`) занимает **O(1)**.

Но если потом пройти по ним:

```python id="k4w8xz"
for key in user.keys():
    ...
```

это уже:

**O(n)**

---

# ⚠️ Важный нюанс: `dict` — не просто «массив»

Не нужно говорить:

> «В словаре Python ищет элемент по индексу».

У словаря нет обычной индексации как у `list`.

```python id="a2m3pz"
d[0]
```

означает поиск **ключа `0`**, а не элемента с индексом `0`.

---

# 🧠 Сравнение `list` и `dict`

| Операция          |       `list` | `dict` |
| ----------------- | -----------: | -----: |
| `x[i]` / `d[key]` |         O(1) |   O(1) |
| Поиск элемента    |         O(n) |  O(1)* |
| Добавление        | O(1) в конец |  O(1)* |
| Удаление          |         O(n) |  O(1)* |
| Проверка наличия  |         O(n) |  O(1)* |

`*` — средняя сложность.

Например:

```python id="w8y7yn"
# list
"name" in ["name", "age", "city"]
# O(n)

# dict
"name" in {"name": "Ilya", "age": 31}
# O(1) в среднем
```

---

# 🎤 Что обязательно запомнить

```text id="f8w2qa"
dict = хеш-таблица

Получение по ключу → O(1) average
Добавление          → O(1) average
Удаление            → O(1) average
Проверка ключа       → O(1) average

Перебор              → O(n)
Копирование          → O(n)

Worst case основных операций → O(n)
```

### 🧠 Ключевая фраза

> **`dict` используют, когда нужен быстрый доступ к данным по ключу. В среднем основные операции с ключами выполняются за O(1), потому что словарь использует хеширование.**
