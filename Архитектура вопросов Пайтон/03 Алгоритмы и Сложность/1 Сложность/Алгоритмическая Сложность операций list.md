# Сложность операций `list` в Python

## 🎯 Ответ на собеседовании

> `list` в Python реализован как **динамический массив**. Поэтому доступ по индексу занимает `O(1)`, а поиск и вставка/удаление в начале или середине списка обычно занимают `O(n)`.
>
> Добавление элемента в конец через `append()` имеет **амортизированную сложность `O(1)`**.

---

## 📊 Основные операции

| Операция           |      Сложность | Почему                            |
| ------------------ | -------------: | --------------------------------- |
| `lst[i]`           |       **O(1)** | прямой доступ по индексу          |
| `lst[i] = x`       |       **O(1)** | прямой доступ                     |
| `lst.append(x)`    |      **O(1)*** | добавление в конец                |
| `lst.pop()`        |       **O(1)** | удаление последнего               |
| `lst.insert(0, x)` |       **O(n)** | нужно сдвинуть элементы           |
| `lst.insert(i, x)` |       **O(n)** | нужно сдвинуть часть элементов    |
| `lst.pop(0)`       |       **O(n)** | нужно сдвинуть остальные элементы |
| `lst.pop(i)`       |       **O(n)** | нужно сдвинуть элементы           |
| `x in lst`         |       **O(n)** | последовательный поиск            |
| `lst.index(x)`     |       **O(n)** | последовательный поиск            |
| `lst.count(x)`     |       **O(n)** | проверка всех элементов           |
| `lst.remove(x)`    |       **O(n)** | поиск + удаление                  |
| `lst.copy()`       |       **O(n)** | копируются все ссылки             |
| `lst[:]`           |       **O(n)** | создаётся новый список            |
| `lst + other`      |   **O(n + m)** | создаётся новый список            |
| `lst.reverse()`    |       **O(n)** | нужно обработать элементы         |
| `lst.sort()`       | **O(n log n)** | используется Timsort              |
| `len(lst)`         |       **O(1)** | длина хранится в объекте          |

`*` — **амортизированно** `O(1)`.

---

# 🔍 Почему `lst[i]` — O(1)?

Список — динамический массив.

Условно:

```text
index:   0      1      2      3
         ↓      ↓      ↓      ↓
       [10]   [20]   [30]   [40]
```

Python может сразу вычислить адрес нужного элемента по индексу.

Поэтому:

```python
lst[3]
```

не требует проходить:

```text
10 → 20 → 30 → 40
```

Можно сразу обратиться к элементу №3.

Поэтому:

**`lst[i]` → O(1)**

---

# ➕ Почему `append()` — O(1)?

```python
lst.append(10)
```

Обычно новый элемент добавляется в конец массива.

Поэтому операция занимает **O(1)**.

Но иногда внутреннего места недостаточно.

Тогда Python должен:

1. выделить больший блок памяти;
2. перенести ссылки на элементы;
3. добавить новый элемент.

Это уже `O(n)`.

Но такие операции происходят не при каждом `append()`.

Поэтому в среднем:

> **`append()` имеет амортизированную сложность O(1).**

---

# ➕ Почему `insert(0, x)` — O(n)?

```python
lst.insert(0, 10)
```

Нужно вставить элемент в начало:

```text
Было:

[20, 30, 40]

Стало:

[10, 20, 30, 40]
```

Существующие элементы приходится сдвинуть:

```text
20 → 30 → 40
```

Чем больше список, тем больше элементов нужно переместить.

Поэтому:

**`insert(0, x)` → O(n)**

---

# ❌ Почему `pop(0)` — O(n)?

```python
lst.pop(0)
```

Удалили первый элемент:

```text
Было:

[10, 20, 30, 40]

Стало:

[20, 30, 40]
```

Остальные элементы приходится сдвинуть влево.

Поэтому:

**`pop(0)` → O(n)**

А:

```python
lst.pop()
```

удаляет последний элемент.

Сдвигать ничего не нужно:

**`pop()` → O(1)**

---

# 🔎 Поиск элемента

```python
x in lst
```

Например:

```python
numbers = [10, 20, 30, 40, 50]
30 in numbers
```

Python последовательно проверяет элементы:

```text
10 → 20 → 30
```

В худшем случае придётся проверить весь список.

Поэтому:

**поиск → O(n)**

То же самое:

```python
lst.index(x)
lst.count(x)
lst.remove(x)
```

---

# 🧹 `remove()`

```python
lst.remove(30)
```

Здесь выполняются две потенциально дорогие операции:

1. найти `30` → `O(n)`;
2. сдвинуть элементы после него → `O(n)`.

Итог:

**`remove()` → O(n)**

---

# 🔄 Сортировка

```python
lst.sort()
```

Python использует алгоритм **Timsort**.

Средняя и худшая сложность:

**O(n log n)**

При этом Timsort может работать быстрее на уже частично отсортированных данных.

---

# 📋 Копирование

```python
new_list = lst.copy()
```

Нужно создать новый список и скопировать в него ссылки на все элементы.

Если `n` элементов:

**O(n)**

То же самое:

```python
new_list = lst[:]
```

# 🧠 Самая важная таблица

```text
O(1)
├── lst[i]
├── lst[i] = x
├── append()
├── pop()
└── len()

O(n)
├── поиск: x in lst
├── index()
├── count()
├── remove()
├── insert()
├── pop(i)
├── копирование
└── срез

O(n log n)

```

## 🎤 Что обязательно запомнить для собеседования

**Главные 6 операций:**

```text
lst[i]       → O(1)
append()     → O(1) амортизированно
pop()        → O(1)
x in lst     → O(n)
insert(0,x)  → O(n)
pop(0)       → O(n)
```

### Ключевая идея

> **`list` — динамический массив.**
>
> Поэтому **доступ по индексу быстрый — O(1)**, но **вставка/удаление в начале или середине дорогие — O(n)** из-за сдвига элементов.

Если часто нужны операции с началом очереди, вместо `list` обычно рассматривают `collections.deque`.
