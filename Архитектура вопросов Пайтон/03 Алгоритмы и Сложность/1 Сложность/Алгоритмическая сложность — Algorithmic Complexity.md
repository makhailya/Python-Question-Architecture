# Алгоритмическая сложность — Algorithmic Complexity

## Коротко

Алгоритмическая сложность показывает, как изменяются затраты ресурсов алгоритма при увеличении размера входных данных.

Основные ресурсы:

- **временная сложность (`Time Complexity`)** — сколько вычислений требуется;
- **пространственная сложность (`Space Complexity`)** — сколько дополнительной памяти требуется.

Например, если алгоритм перебирает все `n` элементов:

```python
for item in items:
    print(item)
```

его временная сложность:

```
O(n)
```

Если алгоритм сразу обращается к элементу по индексу:

```
items[100]
```

сложность доступа:

```
O(1)
```

## На собеседовании достаточно сказать

Алгоритмическая сложность показывает, как растут временные и пространственные затраты алгоритма при увеличении размера входных данных. Обычно временную сложность описывают с помощью Big O, например O(1), O(log n), O(n) и O(n²).

## Что важно помнить

Размер входных данных обычно обозначают:

```
n
```

Например:

```python
numbers = [1, 2, 3, 4, 5]
```

Здесь:

```
n = 5
```

Если список увеличится до миллиона элементов:

```
n = 1_000_000
```

нам важно понимать, как изменится количество операций алгоритма.

## Основные варианты

От более эффективных к менее эффективным при больших n:

```
O(1)
O(log n)
O(n)
O(n log n)
O(n²)
O(2ⁿ)
O(n!)
```

Например:

```
O(1)
→ количество операций практически не зависит от n

O(log n)
→ количество операций растёт медленно

O(n)
→ количество операций растёт примерно пропорционально n

O(n²)
→ количество операций растёт примерно как n²
```

## Временная сложность (Time Complexity)

Рассмотрим:

```python
for item in items:
    print(item)
```

Если элементов n, цикл выполнится примерно n раз:

```
O(n)
```

Два вложенных цикла:

```python
for i in items:
    for j in items:
        print(i, j)
```

Если каждый цикл выполняется n раз:

```
n × n = n²
```

Поэтому:

```
O(n²)
```

## Пространственная сложность

Алгоритм может требовать дополнительную память.

Например:

```python
result = []

for item in items:
    result.append(item * 2)
```

Создаётся новый список размером примерно n.

Дополнительная пространственная сложность:

```
O(n)
```

Если же алгоритм использует только несколько переменных:

```python
total = 0
count = 0
```

дополнительная память не зависит от размера входа:

```
O(1)
```

## Что происходит с константами

При оценке Big O обычно не учитывают постоянные множители.

Например:

```python
for item in items:
    print(item)

for item in items:
    print(item)
```

Здесь примерно:

```
2n
```

операций.

Но сложность записывают:

```
O(n)
```

Потому что при росте n главное — порядок роста, а не постоянный множитель.

Аналогично:

```
O(3n)   → O(n)
O(10n)  → O(n)
O(n² + n) → O(n²)
```

## Важно различать сложность и реальное время

Big O не говорит:

«Этот алгоритм выполнится ровно за 1 секунду».

Она описывает характер роста затрат при увеличении размера входных данных.

Поэтому два алгоритма с одинаковой асимптотической сложностью O(n) могут работать с разной реальной скоростью.

На практике также влияют:

* константы;
* структура данных;
* реализация;
* CPU и память;
* операции ввода-вывода.

## Главное

Алгоритмическая сложность отвечает на вопрос:

```
Что произойдёт с затратами алгоритма,
если входных данных станет больше?
```

Нужно различать:

```
Time Complexity
→ сколько вычислений требуется

Space Complexity
→ сколько дополнительной памяти требуется
```

А для описания роста обычно используется:

```
Big O
```

Например:

```
O(1)       → константная
O(log n)   → логарифмическая
O(n)       → линейная
O(n log n) → линейно-логарифмическая
O(n²)      → квадратичная
```
