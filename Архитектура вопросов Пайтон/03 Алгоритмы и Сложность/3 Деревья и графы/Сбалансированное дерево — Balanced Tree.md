# Сбалансированное дерево — Balanced Tree

## Коротко

Сбалансированное дерево — это дерево, в котором высота поддеревьев поддерживается примерно одинаковой.

Для бинарного дерева поиска баланс важен, потому что от высоты дерева зависит сложность операций.

Сбалансированное дерево:

```text
        10
       /  \
      5    20
     / \   / \
    2   7 15 30
```

Сильно несбалансированное:

```
10
  \
   20
     \
      30
        \
         40
```

Во втором случае дерево фактически превращается в подобие связного списка.

## На собеседовании достаточно сказать

Сбалансированное дерево — это дерево, в котором высота левого и правого поддеревьев не отличается слишком сильно. Балансировка позволяет сохранять небольшую высоту дерева и поэтому поддерживать операции поиска, вставки и удаления близкими к O(log n).

## Что важно помнить

Для сбалансированного дерева высота растёт примерно как:

```
O(log n)
```

Поэтому в BST поиск может выполняться за:

```
O(log n)
```

Если дерево становится сильно перекошенным:

```
10
  \
   20
     \
      30
        \
         40
```

его высота становится:

```
O(n)
```

И операции могут деградировать до:

```
O(n)
```

## Зачем нужна балансировка

Без балансировки последовательная вставка значений:

```
10
20
30
40
50
```

может привести к:

```
10
  \
   20
     \
      30
        \
         40
           \
            50
```

Это уже не даёт преимуществ дерева перед связным списком.

Балансировка старается сохранить структуру ближе к:

```
        30
       /  \
      20   40
     /       \
    10        50
```

## Виды сбалансированных деревьев

На собеседовании можно встретить:

* AVL-дерево (AVL Tree)
* красно-чёрное дерево (Red-Black Tree)

Они автоматически поддерживают баланс при изменении структуры.

Например, AVL-дерево контролирует разницу высот левого и правого поддеревьев.

Красно-чёрное дерево использует дополнительные правила, связанные с цветом узлов.

Подробно запоминать реализацию этих алгоритмов на начальном этапе необязательно. Важно понимать зачем нужна балансировка.

## Простой пример

Представим обычный BST:

```
        10
       /  \
      5    20
     / \
    2   7
```

Высота небольшая, поэтому поиск может быть близок к:

```
O(log n)
```

А если значения добавляются последовательно:

```
10 → 20 → 30 → 40 → 50
```

дерево может стать:

```
10
  \
   20
     \
      30
        \
         40
           \
            50
```

Тогда поиск:

```
O(n)
```

## Главное

Главная идея:

```
Баланс
  ↓
меньшая высота дерева
  ↓
быстрее поиск
  ↓
O(log n)
```

А без балансировки:

```
перекошенное дерево
  ↓
высота O(n)
  ↓
операции могут стать O(n)
```
