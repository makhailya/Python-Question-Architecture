# 🌳 BFS-подобный

🎯 **Ответ на собеседовании:**

**BFS (Breadth-First Search, поиск в ширину)** — алгоритм обхода графа или дерева, при котором сначала обрабатываются элементы, находящиеся **на текущем уровне**, а затем переходят к следующему уровню.

Пример дерева:

```text
        A
       / \
      B   C
     / \   \
    D   E   F
```

BFS обходит его примерно так:

```text
A → B → C → D → E → F
```

То есть:

```text
Уровень 0: A
Уровень 1: B, C
Уровень 2: D, E, F
```

---

## BFS vs DFS

### BFS — поиск в ширину

```text
A
├── B
├── C
├── D
├── E
└── F
```

Сначала соседи, потом их потомки.

Обычно реализуется через **очередь (`queue`)**:

```python id="h3q2vk"
queue = [start]

while queue:
    node = queue.pop(0)
    ...
```

На практике используют `collections.deque`.

---

### DFS — поиск в глубину

DFS сначала идёт максимально глубоко по одной ветке:

```text
A → B → D → E → C → F
```

Обычно используется:

* стек;
* рекурсия.

---

# BFS-подобный

**BFS-подобный** означает, что алгоритм по своему поведению или структуре **напоминает поиск в ширину**, но не обязательно является настоящим BFS.

Например, если алгоритм приоритетно рассматривает элементы нескольких уровней иерархии, можно сказать, что он имеет BFS-подобное поведение.

⚠️ Но **«BFS-подобный» — не формальное название алгоритма**.

---

# Связь с MRO

В контексте Python иногда говорят, что MRO выглядит **BFS-подобно**, потому что результат не похож на простой обход одной ветки в глубину.

Однако **C3-линеаризация не является BFS**.

Она строит MRO через специальный алгоритм `merge`, учитывая:

* порядок родителей;
* MRO каждого родителя;
* ограничения C3;
* отсутствие противоречий.

Поэтому на собеседовании лучше говорить:

> **C3-линеаризация не является BFS; BFS-подобность — лишь интуитивная аналогия.**

## 🧠 Коротко

> **BFS — поиск в ширину: сначала обрабатываются элементы текущего уровня, затем следующего. «BFS-подобный» означает похожий принцип обхода, но не обязательно настоящий BFS. В случае C3 это только аналогия, поскольку C3 использует алгоритм слияния (`merge`), а не обычный BFS.**

```text
BFS:
уровень → уровень → уровень

DFS:
ветка → глубина → возврат → следующая ветка

C3:
MRO родителей → merge → согласованный MRO
```
