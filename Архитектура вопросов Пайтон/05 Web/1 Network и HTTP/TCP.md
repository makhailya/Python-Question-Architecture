# 🔗 TCP

## 🎤 Суперкоротко

> **TCP — транспортный протокол с установлением соединения, который обеспечивает надёжную и упорядоченную доставку данных между двумя узлами. Он использует подтверждения, нумерацию сегментов, повторную передачу потерянных данных и контроль перегрузки.**

---

# 🎯 Ответ на собеседовании

**TCP (Transmission Control Protocol)** — протокол транспортного уровня модели TCP/IP.

Он обеспечивает **надёжную, последовательную и контролируемую передачу потока байтов** между двумя участниками соединения.

Упрощённо:

```text
Приложение
    ↓
TCP
    ↓
IP
    ↓
Сеть
```

Например:

```text
HTTP/1.1
    ↓
TCP
    ↓
IP
```

TCP отвечает за доставку данных, а HTTP — за правила взаимодействия приложения.

---

# 🧩 Основные свойства TCP

TCP предоставляет:

```text
Надёжность
     ↓
данные не должны теряться незаметно

Порядок
     ↓
данные собираются в правильной последовательности

Контроль ошибок
     ↓
повреждённые данные обнаруживаются

Flow Control
     ↓
контроль скорости передачи относительно получателя

Congestion Control
     ↓
контроль нагрузки на сеть

Connection-oriented
     ↓
сначала устанавливается соединение
```

---

# 🔌 TCP — протокол с установлением соединения

Перед передачей данных TCP сначала устанавливает соединение.

Используется **трёхстороннее рукопожатие — Three-Way Handshake**.

```text
Client                         Server
   │                              │
   │────── SYN ─────────────────→│
   │                              │
   │←──── SYN + ACK ─────────────│
   │                              │
   │────── ACK ─────────────────→│
   │                              │
   │       Connection             │
   │       established            │
```

После этого стороны могут передавать данные.

---

# 🤝 Three-Way Handshake

## 1. SYN

Клиент отправляет `SYN`.

```text
Client → Server
SYN
```

Это означает:

> «Я хочу установить TCP-соединение».

---

## 2. SYN + ACK

Сервер отвечает:

```text
Server → Client
SYN + ACK
```

Сервер подтверждает получение `SYN` и одновременно сообщает о своей готовности установить соединение.

---

## 3. ACK

Клиент отправляет:

```text
Client → Server
ACK
```

После этого соединение считается установленным.

```text
SYN
 ↓
SYN + ACK
 ↓
ACK
 ↓
соединение установлено
```

---

# 📦 TCP Segment

TCP передаёт данные небольшими единицами — **сегментами**.

Упрощённо:

```text
Application Data
       ↓
      TCP
       ↓
   TCP Segment
       ↓
      IP
```

TCP-сегмент содержит служебную информацию и данные.

Важные поля:

```text
Source Port
Destination Port
Sequence Number
Acknowledgment Number
Flags
Window Size
Checksum
Data
```

---

# 🔢 Sequence Number

TCP использует **Sequence Number**, чтобы отслеживать порядок данных.

Например:

```text
Segment 1 → Sequence Number 1000
Segment 2 → Sequence Number 1500
Segment 3 → Sequence Number 2000
```

Если сегменты пришли не по порядку:

```text
1 → 3 → 2
```

TCP может собрать данные обратно в правильном порядке:

```text
1 → 2 → 3
```

---

# ✅ Acknowledgment

Получатель подтверждает получение данных с помощью **ACK**.

Упрощённый пример:

```text
Client
   │
   │ Data
   ↓
Server
   │
   │ ACK
   ↓
Client
```

ACK сообщает отправителю, какие данные были успешно получены.

---

# 🔁 Повторная передача

Если данные потерялись, TCP может обнаружить это и выполнить **retransmission**.

Например:

```text
Segment 1 ✓
Segment 2 ✗
Segment 3 ✓
```

TCP обнаруживает проблему и повторно передаёт потерянные данные.

```text
Segment 2
    ↓
Retransmission
    ↓
Server
```

Именно поэтому TCP считается надёжным транспортом.

---

# 🧵 TCP — поток байтов

Очень важный момент:

> **TCP передаёт поток байтов, а не отдельные сообщения.**

Например, приложение отправило:

```python
data = b"Hello World"
```

TCP рассматривает это как последовательность байтов:

```text
H e l l o   W o r l d
```

Границы сообщений приложения TCP сам по себе не сохраняет.

Например, приложение отправило:

```text
Hello
World
```

Получатель теоретически может получить:

```text
Hel
loWo
rld
```

Поэтому протокол более высокого уровня должен самостоятельно определять границы сообщений.

---

# 🌊 Flow Control

**Flow Control** защищает получателя от ситуации, когда отправитель передаёт данные слишком быстро.

TCP использует **Receive Window (rwnd)**.

Упрощённо:

```text
Fast Sender
     ↓
     ↓
     ↓
Slow Receiver
```

Получатель сообщает, сколько данных он ещё способен принять.

```text
Receiver
    ↓
Window = 10 KB
    ↓
Sender не должен превышать доступное окно
```

Таким образом TCP учитывает возможности конкретного получателя.

---

# 🚦 Congestion Control

**Congestion Control** отвечает уже не за получателя, а за **перегрузку сети**.

Например:

```text
Sender
   ↓
Network
   ↓
много трафика
   ↓
перегрузка
```

TCP регулирует скорость передачи, чтобы не перегружать сеть.

Используются механизмы и алгоритмы вроде:

```text
Slow Start
Congestion Avoidance
Fast Retransmit
Fast Recovery
```

Конкретное поведение зависит от алгоритма контроля перегрузки.

---

# 🆚 Flow Control vs Congestion Control

Это часто спрашивают на собеседовании.

**Flow Control**:

> Защищает получателя от слишком быстрого отправителя.

```text
Sender → Receiver
           ↑
      возможности
       получателя
```

**Congestion Control**:

> Защищает сеть от перегрузки.

```text
Sender → Network → Receiver
            ↑
        состояние
          сети
```

Запомнить:

```text
Flow Control
     ↓
Receiver

Congestion Control
     ↓
Network
```

---

# ❌ Что происходит при потере пакета

Предположим:

```text
Packet 1 ✓
Packet 2 ✗
Packet 3 ✓
Packet 4 ✓
```

TCP обнаруживает потерю и инициирует повторную передачу.

Поскольку TCP обеспечивает **упорядоченный поток байтов**, данные после потерянного участка могут ждать его восстановления.

Именно это связано с **Head-of-Line Blocking** на уровне TCP.

```text
Packet 2 потерян
      ↓
TCP ждёт повторную передачу
      ↓
данные после него могут задерживаться
```

В HTTP/2 это особенно важно, потому что несколько HTTP-потоков могут использовать одно TCP-соединение.

---

# 🔐 TCP и HTTPS

TCP сам по себе **не шифрует данные**.

Например:

```text
HTTPS
  ↓
TLS
  ↓
TCP
  ↓
IP
```

TLS отвечает за:

* шифрование;
* целостность;
* аутентификацию сервера.

TCP отвечает за:

* надёжность;
* порядок;
* доставку потока байтов.

---

# 🔌 Порты

TCP использует **порты**, чтобы определить приложение или сетевой сервис.

Например:

```python
http_port = 80
https_port = 443
```

У соединения есть:

```text
IP клиента
+
порт клиента
+
IP сервера
+
порт сервера
```

Например:

```text
192.168.1.10:53000
        ↓
93.184.216.34:443
```

Здесь:

```text
53000 → клиентский порт
443   → серверный порт HTTPS
```

---

# 🔄 Завершение TCP-соединения

TCP-соединение обычно закрывается через обмен `FIN` и `ACK`.

Упрощённо:

```text
Client                         Server
   │                              │
   │──────── FIN ────────────────→│
   │←──────── ACK ────────────────│
   │                              │
   │←──────── FIN ────────────────│
   │──────── ACK ────────────────→│
   │                              │
   │       Connection closed      │
```

В отличие от установки соединения, закрытие обычно требует больше этапов.

# 🆚 TCP vs UDP

Один из обязательных вопросов на собеседовании.

| TCP                        | UDP                               |
| -------------------------- | --------------------------------- |
| С установлением соединения | Без установления соединения       |
| Надёжная доставка          | Нет гарантии доставки             |
| Сохраняет порядок          | Не гарантирует порядок            |
| Есть retransmission        | Нет встроенной повторной передачи |
| Есть flow control          | Нет                               |
| Есть congestion control    | Нет в самом UDP                   |
| Поток байтов               | Датаграммы                        |
| Больше накладных расходов  | Меньше накладных расходов         |

Упрощённо:

```text
TCP
 ↓
надёжность
 ↓
порядок
 ↓
контроль

UDP
 ↓
минимум механизмов
 ↓
быстрая передача
```

HTTP/1.1:

```text
HTTP/1.1
    ↓
TCP
```

HTTP/2:

```text
HTTP/2
    ↓
TCP
```

HTTP/3:

```text
HTTP/3
    ↓
QUIC
    ↓
UDP
```

Поэтому важно запомнить:

```text
HTTP/1.1 → TCP

```

# 🧠 TCP в Backend

Когда Python-приложение делает HTTP-запрос:

```python
import requests

response = requests.get("https://example.com")

print(response.status_code)
```

Приложение не управляет TCP вручную.

Стек выглядит примерно так:

```text
Python
   ↓
HTTP
   ↓
TLS
   ↓
TCP
   ↓
IP
   ↓
Network
```

Операционная система и сетевые библиотеки выполняют низкоуровневую работу с TCP.

# ⚠️ Что важно запомнить

### TCP не гарантирует скорость

TCP обеспечивает надёжность и контроль передачи, но скорость зависит от:

```text
пропускной способности
задержки
потерь пакетов
перегрузки сети
TCP congestion control
```

---

### TCP не знает о HTTP

TCP не понимает:

```text
GET
POST
JSON
HTTP headers
REST
```

Для TCP это просто поток байтов.

```text
HTTP
 ↓
формирует данные
 ↓
TCP
 ↓
передаёт поток байтов
```

---

### TCP не шифрует данные

Шифрование обеспечивает TLS:

```text
HTTPS
 ↓
TLS
 ↓
TCP
```

> **TCP — надёжный транспортный протокол с установлением соединения. Он передаёт поток байтов, гарантирует порядок данных, использует подтверждения и повторную передачу потерянных данных, а также реализует flow control и congestion control.
