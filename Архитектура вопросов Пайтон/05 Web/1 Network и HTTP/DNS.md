# 🌐 DNS

## 🎯 Ответ на собеседовании

**DNS (Domain Name System)** — это распределённая система, которая преобразует **доменные имена в IP-адреса** и обратно.

Например:

```text id="3qv7km"
google.com
    ↓
DNS
    ↓
142.250.x.x
```

DNS нужен потому, что человеку проще запомнить доменное имя, а компьютеру для установления сетевого соединения нужен IP-адрес.

---

## 🎤 Суперкоротко

**DNS = система преобразования доменных имён в IP-адреса.**

```text id="8qj4cs"
example.com → 93.184.216.34
```

---

# 🔄 Как работает DNS-запрос

Когда пользователь вводит:

```text id="g5k8wp"
https://example.com
```

компьютеру сначала нужно узнать IP-адрес `example.com`.

Упрощённо процесс выглядит так:

```text id="k8z5aq"
Browser
   ↓
DNS Resolver
   ↓
Root DNS
   ↓
TLD DNS (.com)
   ↓
Authoritative DNS
   ↓
IP address
```

Например:

```text id="s3q6mn"
example.com
    ↓
93.184.216.34
```

После получения IP браузер может установить соединение с сервером.

---

# 🧩 Основные компоненты DNS

## 1. 💻 DNS Client

Устройство пользователя отправляет DNS-запрос.

Например:

```text id="f4y8kp"
"Какой IP у example.com?"
```

---

## 2. 🔎 Recursive DNS Resolver

**DNS Resolver** принимает запрос от клиента и ищет ответ.

Например:

```text id="z6p3ra"
Client
  ↓
DNS Resolver
```

Resolver может иметь нужный ответ в своём **кэше**.

Если ответа нет, он выполняет дальнейшее разрешение имени.

---

## 3. 🌳 Root DNS Server

Корневые DNS-серверы находятся на вершине иерархии DNS.

Они не обязательно знают IP конкретного сайта.

Они могут указать, где искать информацию о доменной зоне.

Например:

```text id="m7v2cn"
example.com
     ↓
Root
     ↓
.com TLD servers
```

---

## 4. 🌐 TLD DNS Server

**TLD (Top-Level Domain)** — сервер доменной зоны верхнего уровня.

Например:

```text id="7j4wqz"
.com
.org
.net
.ru
```

TLD-сервер сообщает, где находятся **авторитетные DNS-серверы** нужного домена.

---

## 5. 🏛️ Authoritative DNS Server

**Authoritative DNS Server** содержит официальные DNS-записи конкретного домена.

Например:

```text id="g2x9mt"
example.com → 93.184.216.34
```

Именно от него resolver получает окончательный ответ.

---

# 📋 Основные DNS-записи

На собеседовании часто спрашивают именно их.

| Запись  | Назначение                                                    |
| ------- | ------------------------------------------------------------- |
| `A`     | Домен → IPv4                                                  |
| `AAAA`  | Домен → IPv6                                                  |
| `CNAME` | Псевдоним одного домена для другого                           |
| `MX`    | Почтовые серверы домена                                       |
| `NS`    | Авторитетные DNS-серверы домена                               |
| `TXT`   | Произвольная текстовая информация, часто SPF/DKIM/верификация |
| `PTR`   | IP → доменное имя                                             |

---

## 🔢 A-запись

Связывает домен с **IPv4**:

```text id="k6w3pn"
example.com → 93.184.216.34
```

---

## 🌍 AAAA-запись

Связывает домен с **IPv6**:

```text id="c5v8zr"
example.com → 2001:db8::1
```

---

## 🔗 CNAME

Создаёт псевдоним для другого доменного имени.

Например:

```text id="p8x4mv"
www.example.com
       ↓
example.com
```

То есть `www.example.com` указывает на другое доменное имя.

---

## 📧 MX

Определяет почтовые серверы домена.

```text id="r2w6fk"
example.com
    ↓
MX
    ↓
mail.example.com
```

Используется для доставки электронной почты.

---

## 🏷️ NS

Указывает, какие DNS-серверы являются авторитетными для домена.

```text id="n4j7bs"
example.com
    ↓
NS
    ↓
ns1.example.com
ns2.example.com
```

---

## 📝 TXT

Хранит текстовые данные.

Часто используется для:

* SPF;
* DKIM;
* подтверждения владения доменом;
* различных настроек сервисов.

---

## 🔄 PTR

Используется для **обратного DNS-разрешения**:

```text id="y5k2qd"
93.184.216.34
      ↓
PTR
      ↓
example.com
```

То есть:

```text id="f6n3ra"
A    → имя → IP
PTR  → IP → имя
```

---

# 💾 DNS Cache

DNS активно использует **кэширование**.

Например:

```text id="m8q4vz"
Client
  ↓
DNS Resolver
  ↓
Cache
```

Если resolver уже знает IP:

```text id="w3r6pk"
example.com → 93.184.216.34
```

ему не нужно заново обращаться к Root, TLD и Authoritative DNS.

Это ускоряет разрешение имён и снижает нагрузку на DNS-инфраструктуру.

---

# ⏱️ TTL

**TTL (Time To Live)** определяет, как долго DNS-запись может храниться в кэше.

Например:

```text id="q7m2ds"
A example.com
TTL = 3600
```

Запись может кэшироваться примерно **1 час**.

После истечения TTL resolver должен получить актуальную информацию заново.

---

# 🚀 DNS и HTTP

DNS происходит **до установления соединения с сервером**.

Упрощённая последовательность:

```text id="h9x3fk"
1. Пользователь вводит example.com
             ↓
2. DNS → получает IP
             ↓
3. TCP Three-Way Handshake
             ↓
4. TLS Handshake (для HTTPS)
             ↓
5. HTTP Request
             ↓
6. HTTP Response
```

То есть:

**DNS → TCP → TLS → HTTP**

Для HTTPS.

---

# ⚠️ DNS не устанавливает HTTP-соединение

Важно не путать:

```text id="a3p7vn"
DNS
→ узнаёт IP-адрес

TCP
→ устанавливает соединение

TLS
→ устанавливает защищённый канал

HTTP
→ передаёт запрос и ответ
```

Каждый механизм решает свою задачу.

---

# 🧠 Главное

```text id="r8m4qc"
DNS

Домен
  ↓
DNS Resolver
  ↓
Root
  ↓
TLD
  ↓
Authoritative DNS
  ↓
IP
```

Основные записи:

```text id="u6z2wp"
A      → IPv4
AAAA   → IPv6
CNAME  → псевдоним
MX     → почта
NS     → DNS-серверы
TXT    → текстовые данные
PTR    → IP → имя
```

Главная цепочка при открытии HTTPS-сайта:

```text id="k5n8xs"
DNS
 ↓
IP
 ↓
TCP Handshake
 ↓
TLS Handshake
 ↓
HTTP
```

**DNS — распределённая система доменных имён, которая позволяет преобразовать удобное для человека доменное имя в IP-адрес, необходимый для сетевого взаимодействия.**
