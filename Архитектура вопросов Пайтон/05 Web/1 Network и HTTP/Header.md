# 🧩 JWT Header

## 🎯 Ответ на собеседовании

**Header — это первая часть JWT, в которой хранится служебная информация о токене, прежде всего алгоритм подписи (`alg`) и тип токена (`typ`).**

Header кодируется в Base64URL и является первой частью JWT:

```text
Header.Payload.Signature
```

Например:

```python
{
    "alg": "HS256",
    "typ": "JWT"
}
```

---

## 🎤 Суперкоротко

**Header = информация о том, как обрабатывать JWT.**

Главное поле:

```text
alg → алгоритм подписи
```

Часто также:

```text
typ → тип токена
```

---

# 🧩 Структура Header

Обычно Header выглядит примерно так:

```python
header = {
    "alg": "HS256",
    "typ": "JWT"
}
```

### `alg`

**Algorithm** — алгоритм, которым была создана подпись.

Например:

```text
HS256
RS256
ES256
```

---

### `typ`

**Type** — тип токена.

Для JWT обычно:

```python
{
    "typ": "JWT"
}
```

---

# 🔄 Где находится Header

JWT состоит из трёх частей:

```text
eyJhbGciOiJIUzI1NiJ9
.
eyJzdWIiOiIxMjMifQ
.
SIGNATURE
```

Первая часть:

```text
eyJhbGciOiJIUzI1NiJ9
```

— это Base64URL-представление Header.

После декодирования получаем:

```python
{
    "alg": "HS256",
    "typ": "JWT"
}
```

---

# ⚠️ Header не является секретным

Header **не шифруется**.

Он только кодируется в Base64URL.

Поэтому его содержимое можно прочитать.

```text
JWT
 ↓
Base64URL decode
 ↓
Header
```

---

# 🛡️ Почему `alg` важен

Сервер должен сам определять, какие алгоритмы он доверяет.

Нельзя бездумно доверять алгоритму, указанному в пользовательском JWT.

Правильная логика:

```text
JWT
 ↓
Header
 ↓
alg = ?
 ↓
Разрешён ли этот алгоритм?
 ↓
Да → проверяем Signature
Нет → отклоняем JWT
```

---

# 🎯 Главное

```text
Header
 ├── alg → алгоритм подписи
 └── typ → тип токена
```

**Header не содержит данные пользователя.**

Он содержит служебную информацию о JWT.
