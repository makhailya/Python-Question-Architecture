# 🔐 HTTPS — HTTP Secure

# 🧠 Формула для собеседования

**HTTPS — это HTTP, работающий поверх TLS. TLS обеспечивает конфиденциальность, целостность и аутентификацию сервера. При подключении сначала устанавливается защищённое TLS-соединение, после чего HTTP-запросы и ответы передаются внутри этого защищённого канала. Стандартный порт HTTPS — 443.**
## 🎤 Суперкоротко

**HTTPS = HTTP + TLS.**

HTTPS — это передача HTTP-запросов и ответов через защищённое TLS-соединение.

TLS обеспечивает:

* 🔒 конфиденциальность;
* 🛡️ целостность;
* 🪪 аутентификацию сервера.

Стандартный порт HTTPS — **443**.

```text
HTTPS
  ↓
HTTP
  ↓
TLS
  ↓
TCP
  ↓
IP
```

---

## 🎯 Ответ на собеседовании

**HTTPS (HTTP Secure)** — это HTTP, работающий поверх TLS.

TLS устанавливает защищённое соединение между клиентом и сервером, проверяет сертификат сервера и обеспечивает шифрование и целостность передаваемых HTTP-данных.

По умолчанию HTTPS использует порт **443**.

---

# 🌐 HTTP vs HTTPS

Главное отличие — защита передаваемых данных.

### HTTP

```text
Клиент ───── HTTP ─────> Сервер
```

Данные передаются без шифрования на уровне HTTP.

Например:

```python
request = {
    "login": "ilya",
    "password": "123456"
}
```

При перехвате трафика содержимое может быть прочитано.

---

### HTTPS

```text
Клиент
   │
   │ HTTP
   ↓
  TLS 🔐
   │
   ↓
 TCP
   │
   ↓
 Сервер
```

HTTP-данные перед передачей защищаются TLS.

---

# 🔐 Что именно защищает HTTPS

## 1. Конфиденциальность

Посторонний наблюдатель не должен прочитать содержимое HTTP-запроса.

Например:

```text
login=ilya
password=123456
```

передаётся в зашифрованном виде.

---

## 2. Целостность

HTTPS позволяет обнаружить изменение данных во время передачи.

Например:

```text
amount=100
```

нельзя незаметно изменить на:

```text
amount=10000
```

---

## 3. Аутентификация сервера

Сертификат позволяет клиенту проверить, что он подключился к нужному серверу.

Например:

```text
https://example.com
```

Сертификат должен подтверждать принадлежность домена соответствующему серверу.

---

# 🪪 Сертификат в HTTPS

При установлении HTTPS-соединения сервер предоставляет TLS-сертификат.

Упрощённо:

```text
HTTPS
  ↓
TLS Handshake
  ↓
Сервер отправляет Certificate
  ↓
Клиент проверяет сертификат
  ↓
Защищённое соединение
```

Клиент проверяет, в частности:

* доменное имя;
* срок действия;
* подпись сертификата;
* цепочку доверия;
* соответствие сертификата назначению.

---

# 🤝 Как устанавливается HTTPS-соединение

Упрощённо процесс выглядит так:

```text
Клиент                         Сервер
  │                              │
  │──── TCP connection ─────────>│
  │                              │
  │──── TLS ClientHello ────────>│
  │                              │
  │<─── TLS ServerHello ─────────│
  │<─── Certificate ─────────────│
  │                              │
  │──── TLS handshake ──────────>│
  │                              │
  │════ Зашифрованный HTTP ══════│
```

То есть сначала устанавливается транспортное соединение, затем TLS устанавливает защищённый канал, и уже внутри него передаётся HTTP.

---

# 🔄 HTTPS-запрос

Например, приложение отправляет:

```python
import requests

response = requests.get(
    "https://example.com/users"
)

print(response.status_code)
```

Логически происходит:

```text
requests
   ↓
HTTP GET
   ↓
TLS
   ↓
TCP
   ↓
Internet
   ↓
Server
```

Сервер получает обычный HTTP-запрос после расшифровки TLS на своей стороне.

---

# 🔢 Порт HTTPS

Стандартный порт:

```text
HTTPS → 443
```

Для сравнения:

```text
HTTP  → 80
HTTPS → 443
```

При этом порт не является обязательным свойством самого протокола — сервер технически может использовать другой порт.

---

# 🆚 HTTP и HTTPS

| Характеристика         | HTTP | HTTPS                         |
| ---------------------- | ---- | ----------------------------- |
| Шифрование             | ❌    | ✅                             |
| Целостность данных     | ❌    | ✅                             |
| Аутентификация сервера | ❌    | ✅                             |
| TLS                    | ❌    | ✅                             |
| Стандартный порт       | 80   | 443                           |
| Защита от MITM         | ❌    | ✅ при корректной проверке TLS |

---

# 🧠 HTTPS — это отдельный протокол?

На собеседовании лучше сказать:

**HTTPS — не принципиально новый протокол вместо HTTP. Это HTTP, передаваемый через защищённое TLS-соединение.**

```text
HTTP + TLS = HTTPS
```

---

# 🔐 Что происходит с HTTP-запросом

Допустим, клиент отправляет:

```python
request = {
    "method": "POST",
    "url": "/login",
    "body": {
        "login": "ilya",
        "password": "123456"
    }
}
```

Без TLS:

```text
HTTP
 ↓
TCP
 ↓
Сеть
```

С HTTPS:

```text
HTTP
 ↓
TLS 🔐
 ↓
TCP
 ↓
Сеть
```

HTTP-содержимое защищается TLS при передаче.

---

# ⚠️ Что HTTPS НЕ защищает

HTTPS не означает, что система полностью безопасна.

Он защищает **данные в пути**, но не защищает от всех возможных атак.

Например, HTTPS не спасёт от:

* уязвимости самого приложения;
* украденного пароля;
* вредоносного кода на компьютере;
* компрометации сервера;
* SQL-инъекции;
* XSS;
* неправильной авторизации.

```text
HTTPS
  ↓
Защищает передачу данных
```

Но:

```text
HTTPS ≠ безопасное приложение
```

---

# 👀 Что может быть видно при HTTPS

HTTPS скрывает содержимое HTTP-трафика, но не делает соединение полностью невидимым.

В зависимости от ситуации наблюдателю могут быть доступны:

* IP-адрес сервера;
* факт соединения;
* объём трафика;
* время соединения;
* сетевые метаданные.

То есть:

```text
HTTPS ≠ анонимность
```

---

# 🧩 HTTPS и DNS

Важно не путать:

```text
DNS
 ↓
узнать IP-адрес домена
```

и:

```text
HTTPS
 ↓
защитить HTTP-трафик
```

Например:

```text
example.com
     ↓
DNS
     ↓
IP-адрес
     ↓
TCP
     ↓
TLS
     ↓
HTTP
```

При этом существуют отдельные механизмы защиты DNS, например DoH и DoT, но это уже отдельная тема.

# 🚀 HTTPS и HTTP/2

HTTP/2 часто используется поверх TLS:

```text
HTTP/2
   ↓
TLS
   ↓
TCP
```

Поэтому в браузере HTTPS тесно связан с HTTP/2.

---

# ⚡ HTTPS и HTTP/3

HTTP/3 работает через QUIC:

```text
HTTP/3
   ↓
QUIC
   ↓
UDP
```

При этом QUIC использует TLS 1.3 для криптографической защиты соединения.

Упрощённо:

```text
HTTP/3
   ↓
QUIC + TLS 1.3
   ↓
UDP
```
