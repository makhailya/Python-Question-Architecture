# 📡 UDP

## 🎤 Суперкоротко

> **UDP — транспортный протокол без установления соединения, который передаёт датаграммы без гарантии доставки, порядка и повторной передачи. За счёт минимальных накладных расходов он работает быстрее и имеет меньшую задержку, чем TCP, поэтому используется там, где важнее скорость и своевременность данных.**

---

# 🎯 Ответ на собеседовании

**UDP (User Datagram Protocol)** — протокол транспортного уровня модели TCP/IP.

В отличие от TCP, UDP **не устанавливает соединение** перед передачей данных и не обеспечивает надёжную доставку.

```text
Приложение
    ↓
UDP
    ↓
IP
    ↓
Сеть
```

UDP передаёт данные в виде **датаграмм**.

Главная идея:

```text
TCP
 ↓
надёжность + порядок
 ↓
больше накладных расходов


UDP
 ↓
минимум механизмов
 ↓
меньше накладных расходов
```

---

# 📦 UDP Datagram

UDP передаёт данные отдельными **датаграммами**.

Например:

```text
Datagram 1
Datagram 2
Datagram 3
```

Каждая датаграмма является отдельной единицей передачи.

В отличие от TCP, UDP не предоставляет приложению единый поток байтов.

```text
TCP
 ↓
поток байтов

UDP
 ↓
отдельные датаграммы
```

---

# 🔌 UDP не устанавливает соединение

TCP перед передачей данных выполняет handshake:

```text
SYN
 ↓
SYN + ACK
 ↓
ACK
 ↓
соединение
```

UDP этого не делает.

Можно сразу отправить датаграмму:

```text
Client
   │
   │ UDP Datagram
   ↓
Server
```

Поэтому UDP называют **connectionless protocol**.

---

# ⚡ Почему UDP быстрее TCP

У UDP нет многих механизмов TCP:

```text
❌ Three-Way Handshake
❌ подтверждений ACK
❌ встроенной повторной передачи
❌ гарантии порядка
❌ TCP Flow Control
❌ TCP Congestion Control
```

Поэтому служебных данных меньше.

```text
UDP
 ↓
меньше overhead
 ↓
меньше задержка
```

Но важно:

> **UDP не гарантирует, что данные действительно будут доставлены.**

---

# ❌ Нет гарантии доставки

Предположим, отправили:

```text
Datagram 1 ✓
Datagram 2 ✗
Datagram 3 ✓
```

UDP сам по себе не обнаружит потерю на уровне механизма доставки и не отправит `Datagram 2` повторно.

```text
UDP
 ↓
отправил
 ↓
готово
```

Если приложению нужна надёжность, оно должно реализовать необходимые механизмы самостоятельно или использовать протокол поверх UDP.

---

# 🔢 Нет гарантии порядка

UDP не гарантирует, что датаграммы придут в том же порядке.

Отправили:

```text
1 → 2 → 3
```

Получить можно:

```text
1 → 3 → 2
```

UDP не будет автоматически переставлять их обратно.

Если порядок важен, приложение должно самостоятельно обрабатывать эту ситуацию.

---

# 🔄 Нет автоматической повторной передачи

TCP при потере данных может выполнить retransmission:

```text
Packet 1 ✓
Packet 2 ✗
Packet 3 ✓
      ↓
Packet 2 → retransmission
```

UDP этого механизма не имеет.

```text
UDP
 ↓
потеря
 ↓
нет автоматической повторной передачи
```

Если повторная передача необходима, её можно реализовать на уровне приложения.

---

# 🧵 UDP и TCP — главное отличие

```text
TCP
 ↓
поток байтов
 ↓
надёжность
 ↓
порядок
 ↓
повторная передача


UDP
 ↓
датаграммы
 ↓
нет гарантии доставки
 ↓
нет гарантии порядка
 ↓
нет автоматической повторной передачи
```

---

# 📦 Структура UDP Datagram

UDP-заголовок значительно проще TCP.

Основные поля:

```text
Source Port
Destination Port
Length
Checksum
```

То есть UDP имеет всего **8 байт заголовка**.

Для сравнения, TCP имеет гораздо более сложный заголовок и множество управляющих механизмов.

---

# 🔌 Порты

Как и TCP, UDP использует **порты**.

Например:

```python
dns_port = 53
dhcp_server_port = 67
dhcp_client_port = 68
```

Порт позволяет операционной системе определить, какому приложению передать полученную датаграмму.

Например:

```text
192.168.1.10:53000
        ↓
8.8.8.8:53
```

Здесь:

```text
53000 → порт клиента
53    → порт DNS
```

---

# 🌐 Где используется UDP

UDP полезен, когда важнее **скорость и низкая задержка**, чем гарантированная доставка каждого отдельного пакета.

Типичные примеры:

```text
DNS
DHCP
VoIP
онлайн-игры
видеоконференции
стриминг
```

---

# 🎮 UDP в онлайн-играх

Представим онлайн-игру.

Игрок отправляет координаты:

```text
x = 100
y = 250
```

Если один пакет потерялся:

```text
Position 1 ✓
Position 2 ✗
Position 3 ✓
```

часто нет смысла повторно передавать старую позицию.

Через некоторое время игрок уже находится в новом месте.

Поэтому иногда лучше:

```text
потерять старые данные
       ↓
получить новые
       ↓
продолжить игру
```

чем ждать повторную передачу.

---

# 📞 UDP и VoIP

Для голосовой связи важнее своевременность данных.

Например:

```text
Audio 1 ✓
Audio 2 ✗
Audio 3 ✓
Audio 4 ✓
```

Повторно передавать старый аудиофрагмент может быть бессмысленно.

Если голос задержится на несколько секунд, разговор станет хуже.

Поэтому в некоторых real-time системах допустима небольшая потеря данных ради низкой задержки.

---

# 🌍 DNS и UDP

DNS традиционно часто использует UDP.

Например:

```text
Client
   │
   │ UDP
   │ port 53
   ↓
DNS Server
```

Клиент отправляет DNS-запрос:

```python
dns_request = {
    "domain": "example.com",
    "type": "A",
}
```

Сервер возвращает ответ.

Для некоторых DNS-сценариев может использоваться и TCP, например при определённых условиях или больших ответах.

---

# 🚀 QUIC и UDP

Очень важная связь с предыдущей темой:

```text
HTTP/3
   ↓
QUIC
   ↓
UDP
```

Но:

> **QUIC не означает, что HTTP/3 становится ненадёжным.**

QUIC самостоятельно реализует необходимые механизмы:

```text
QUIC
 ├── надёжность
 ├── контроль перегрузки
 ├── streams
 ├── шифрование
 └── connection management
```

Получается:

```text
UDP
 ↓
минимальный транспорт
 ↓
QUIC
 ↓
добавляет необходимые механизмы
 ↓
HTTP/3
```

---

# 🆚 TCP vs UDP

| TCP                     | UDP                            |
| ----------------------- | ------------------------------ |
| Connection-oriented     | Connectionless                 |
| Надёжная доставка       | Нет гарантии доставки          |
| Сохраняет порядок       | Не гарантирует порядок         |
| Есть ACK                | Нет ACK                        |
| Есть retransmission     | Нет встроенного retransmission |
| Поток байтов            | Датаграммы                     |
| Есть Flow Control       | Нет                            |
| Есть Congestion Control | Нет в самом UDP                |
| Больше overhead         | Меньше overhead                |
| Обычно выше задержка    | Обычно ниже задержка           |

---

# 🧠 Важный нюанс: UDP не обязательно быстрее

На собеседовании лучше не говорить:

> «UDP всегда быстрее TCP».

Правильнее:

> **UDP имеет меньшие накладные расходы и не выполняет механизмы установления соединения, подтверждений и повторной передачи, поэтому он может обеспечивать меньшую задержку.**

Реальная производительность зависит от приложения и сети.

---

# 🧩 TCP и UDP на одном уровне

Оба протокола относятся к **транспортному уровню**:

```text
Application
     ↓
┌─────────────┐
│ TCP / UDP   │
└─────────────┘
     ↓
     IP
     ↓
  Network
```

Например:

```text
HTTP/1.1 → TCP → IP
HTTP/2   → TCP → IP
DNS      → UDP → IP
HTTP/3   → QUIC → UDP → IP
```

# 🐍 UDP в Python

В Python для работы с UDP можно использовать `socket`.

Например, UDP-клиент:

```python
import socket


client = socket.socket(
    socket.AF_INET,
    socket.SOCK_DGRAM,
)

message = b"Hello, server!"

client.sendto(
    message,
    ("127.0.0.1", 5000),
)

client.close()
```

Здесь:

```python
socket.AF_INET
```

означает IPv4.

```python
socket.SOCK_DGRAM
```

означает UDP-сокет.

А:

```python
client.sendto(
    message,
    ("127.0.0.1", 5000),
)
```

отправляет UDP-датаграмму на IP-адрес и порт.

---

# 🖥️ UDP-сервер

Простейший UDP-сервер:

```python
import socket


server = socket.socket(
    socket.AF_INET,
    socket.SOCK_DGRAM,
)

server.bind(("127.0.0.1", 5000))

data, address = server.recvfrom(1024)

print(data)
print(address)

server.close()
```

Важное отличие от TCP:

```text
TCP
 ↓
socket()
 ↓
bind()
 ↓
listen()
 ↓
accept()
 ↓
connection


UDP
 ↓
socket()
 ↓
bind()
 ↓
recvfrom()
```

UDP не требует `listen()` и `accept()` для установления соединения.

---

# ⚠️ Что важно не перепутать

### UDP не гарантирует доставку

```text
UDP
 ↓
отправил датаграмму
 ↓
нет гарантии, что она дойдёт
```

---

### UDP не гарантирует порядок

```text
Отправили:
1 → 2 → 3

Может прийти:
1 → 3 → 2
```

---

### UDP не означает отсутствие контроля вообще

Сам UDP простой, но приложение может реализовать поверх него:

```text
ACK
retransmission
ordering
encryption
congestion control
```

Именно так, например, QUIC добавляет поверх UDP множество механизмов.
