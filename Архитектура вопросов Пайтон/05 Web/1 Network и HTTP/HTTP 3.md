# 🚀 HTTP/3

## 🎤 Суперкоротко

> **HTTP/3 — современная версия HTTP, которая работает поверх QUIC, а QUIC — поверх UDP. Главное преимущество HTTP/3 — независимые потоки без TCP Head-of-Line Blocking, а также более быстрое установление соединения благодаря встроенному TLS 1.3.**

---

# 🎯 Ответ на собеседовании

**HTTP/3** — версия протокола HTTP, которая использует **QUIC** вместо TCP.

Архитектура выглядит так:

```text
HTTP/3
   ↓
QUIC
   ↓
UDP
   ↓
IP
```

Главное отличие от предыдущих версий:

```text
HTTP/1.1 → TCP
HTTP/2   → TCP
HTTP/3   → QUIC → UDP
```

---

# 🔗 Почему появился HTTP/3

HTTP/2 решил многие проблемы HTTP/1.1.

Например, HTTP/2 умеет мультиплексирование:

```text
TCP connection
│
├── Stream 1
├── Stream 3
├── Stream 5
└── Stream 7
```

Но HTTP/2 всё ещё работает поверх TCP.

TCP гарантирует порядок доставки данных.

Если один пакет потерялся:

```text
Packet 1 ✓
Packet 2 ✗
Packet 3 ✓
Packet 4 ✓
```

TCP должен дождаться повторной передачи `Packet 2`.

Из-за этого могут ждать и данные других HTTP/2-потоков.

Это **TCP Head-of-Line Blocking**.

---

# 🚀 QUIC

HTTP/3 использует протокол **QUIC**.

QUIC разработан для быстрой и надёжной передачи данных поверх UDP.

Схема:

```text
HTTP/3
   ↓
QUIC
   ↓
UDP
```

Важно:

> **HTTP/3 не является просто «HTTP поверх UDP».**

QUIC сам реализует многие возможности, которые раньше обеспечивал TCP:

```text
QUIC
 ├── надёжная доставка
 ├── контроль перегрузки
 ├── порядок данных внутри потоков
 ├── мультиплексирование
 └── шифрование
```

---

# 🧵 Независимые потоки

Одна из главных особенностей QUIC — независимые потоки.

Например:

```text
QUIC connection
│
├── Stream 1
├── Stream 2
├── Stream 3
└── Stream 4
```

Если потерялись данные в одном потоке:

```text
Stream 1 → потеря пакета ❌
Stream 2 → продолжает работу ✅
Stream 3 → продолжает работу ✅
Stream 4 → продолжает работу ✅
```

Это важное отличие от HTTP/2 поверх TCP.

В HTTP/2:

```text
HTTP/2
   ↓
TCP
   ↓
потеря TCP-пакета
   ↓
может задержать все потоки
```

В HTTP/3:

```text
HTTP/3
   ↓
QUIC
   ↓
потеря данных Stream 1
   ↓
Stream 2, 3, 4 продолжают работу
```

---

# 🚧 Head-of-Line Blocking

Это одно из главных преимуществ HTTP/3.

В HTTP/2:

```text
Stream 1 ──┐
Stream 2 ──┤
Stream 3 ──┤
            ↓
         TCP loss
            ↓
       ожидание данных
```

В HTTP/3:

```text
Stream 1 → потеря данных ❌

Stream 2 → работает ✅
Stream 3 → работает ✅
Stream 4 → работает ✅
```

Поэтому:

> **HTTP/3 устраняет TCP-level Head-of-Line Blocking между независимыми потоками.**

При этом потерянные данные конкретного потока всё равно должны быть доставлены повторно.

---

# ⚡ Быстрое установление соединения

QUIC использует **TLS 1.3** для защиты соединения.

Вместо отдельной комбинации:

```text
TCP handshake
      ↓
TLS handshake
      ↓
HTTP
```

QUIC объединяет установление защищённого соединения значительно эффективнее.

Упрощённо:

```text
QUIC
  +
TLS 1.3
  ↓
быстрое установление защищённого соединения
```

Для повторных подключений QUIC также поддерживает механизмы быстрого восстановления соединения.

---

# 🔐 TLS 1.3

Шифрование является фундаментальной частью QUIC.

QUIC использует **TLS 1.3** для:

* аутентификации;
* согласования ключей;
* шифрования данных.

Важно:

> В HTTP/3 TLS не является отдельным дополнительным уровнем поверх QUIC в том же смысле, как TLS поверх TCP для обычного HTTPS. QUIC интегрирует TLS 1.3 в процесс установления соединения.

---

# 📦 QUIC и UDP

Почему используется UDP?

UDP сам по себе очень простой:

```text
UDP
 ↓
отправить датаграмму
```

Он не предоставляет:

```text
❌ гарантированную доставку
❌ порядок доставки
❌ контроль перегрузки
```

Но QUIC реализует необходимые механизмы самостоятельно:

```text
UDP
 ↓
QUIC
 ├── надёжность
 ├── контроль перегрузки
 ├── streams
 ├── шифрование
 └── connection management
```

Получается:

> **QUIC использует простоту UDP и реализует необходимые возможности транспортного протокола самостоятельно.**

---

# 🔄 Connection Migration

Ещё одна важная особенность QUIC — **Connection Migration**.

TCP-соединение сильно связано с парой:

```text
IP + Port
```

Если устройство меняет сеть:

```text
Wi-Fi
  ↓
мобильная сеть
```

TCP-соединение может быть разорвано.

QUIC использует **Connection ID**, благодаря которому соединение может продолжаться при изменении сетевого пути.

Например:

```text
Ноутбук
   │
   ├── Wi-Fi
   │
   ↓
смена сети
   │
   ↓
мобильный интернет
   │
   ↓
QUIC connection продолжается
```

Это особенно полезно для мобильных устройств.

---

# 🧵 Streams в QUIC

QUIC поддерживает несколько независимых потоков.

Например:

```text
QUIC connection
│
├── Stream 1 → HTML
├── Stream 2 → CSS
├── Stream 3 → JavaScript
└── Stream 4 → Image
```

Каждый поток может передавать данные независимо.

Это позволяет HTTP/3 эффективно использовать одно соединение.

---

# 🗜️ Сжатие заголовков

HTTP/3 использует **QPACK** для сжатия HTTP-заголовков.

В HTTP/2 используется:

```text
HPACK
```

В HTTP/3:

```text
QPACK
```

Запомнить:

```text
HTTP/2 → HPACK
HTTP/3 → QPACK
```

QPACK разработан с учётом особенностей мультиплексированной передачи данных в QUIC.

---

# 📦 HTTP/3 Frames

HTTP/3, как и HTTP/2, использует фреймы.

Например:

```text
HEADERS
DATA
SETTINGS
CANCEL_PUSH
PUSH_PROMISE
GOAWAY
```

Но HTTP/3 работает поверх QUIC, поэтому структура транспортного уровня уже отличается от HTTP/2.

---

# 🚫 Server Push

HTTP/3 первоначально поддерживал механизм **Server Push**, аналогичный HTTP/2.

Но Server Push оказался мало востребованным и сложным в практическом использовании.

В современных браузерах этот механизм не является практически значимой частью веб-разработки.

---

# 🌍 Где полезен HTTP/3

HTTP/3 особенно полезен там, где:

* нестабильное сетевое соединение;
* высокая задержка;
* мобильные сети;
* пользователь часто переключается между сетями;
* есть потеря пакетов.

Например:

```text
Мобильный телефон
       ↓
Wi-Fi
       ↓
потеря пакетов
       ↓
переключение сети
       ↓
мобильный интернет
```

QUIC позволяет эффективнее переживать такие изменения.

---

# 🆚 HTTP/2 vs HTTP/3

Главное отличие:

```text
HTTP/2
   ↓
TCP
   ↓
один TCP connection
   ↓
много streams
```

```text
HTTP/3
   ↓
QUIC
   ↓
UDP
   ↓
много независимых streams
```

| HTTP/2                 | HTTP/3                     |
| ---------------------- | -------------------------- |
| TCP                    | QUIC                       |
| TCP поверх IP          | QUIC поверх UDP            |
| Бинарные фреймы        | Бинарные фреймы            |
| Multiplexing           | Multiplexing               |
| HPACK                  | QPACK                      |
| TCP HOL Blocking       | Нет TCP HOL между потоками |
| TLS обычно через HTTPS | TLS 1.3 встроен в QUIC     |

---

# 🆚 HTTP/1.1 vs HTTP/2 vs HTTP/3

```text
HTTP/1.1
    ↓
TCP
    ↓
текст
    ↓
последовательная обработка


HTTP/2
    ↓
TCP
    ↓
бинарные frames
    ↓
multiplexing
    ↓
streams


HTTP/3
    ↓
QUIC
    ↓
UDP
    ↓
бинарные frames
    ↓
multiplexing
    ↓
независимые streams
```

---

# 🧠 Самая важная цепочка

Запомнить нужно буквально эту последовательность:

```text
HTTP/1.1 → TCP
HTTP/2   → TCP
HTTP/3   → QUIC → UDP
```

А дальше:

```text
HTTP/2
 ↓
Multiplexing
 ↓
но TCP HOL остаётся


HTTP/3
 ↓
QUIC
 ↓
независимые streams
 ↓
TCP HOL устранён
```

# 🐍 HTTP/3 в Python

Как и с HTTP/2, разработчик обычно не работает с QUIC вручную.

Например, клиентская библиотека может использовать HTTP/3:

```python
import httpx


with httpx.Client(http2=True) as client:
    response = client.get("https://example.com")

print(response.status_code)
```

Важно: конкретная библиотека должна поддерживать HTTP/3/QUIC отдельно. Сам Python-код работы с API обычно практически не меняется.

То есть для Backend-разработчика главное понимать архитектуру:

```text
Python application
       ↓
HTTP client
       ↓
HTTP/3
       ↓
QUIC
       ↓
UDP
```

---

# ⚠️ Что важно не перепутать

### HTTP/3 ≠ UDP

HTTP/3 работает через **QUIC**, а QUIC использует UDP:

```text
HTTP/3 → QUIC → UDP
```

---

### QUIC ≠ просто UDP

UDP предоставляет минимальный транспорт.

QUIC поверх него реализует:

```text
reliability
congestion control
streams
encryption
connection migration
```

---

### HTTP/3 не отменяет надёжность

HTTP/3 обеспечивает надёжную передачу данных через QUIC.

Просто эта надёжность реализована не TCP, а самим QUIC.

---

### HTTP/3 не означает «три соединения»

Число `3` — это номер версии HTTP:

```text
HTTP/1.1
HTTP/2
HTTP/3
```

А не количество соединений.

---
