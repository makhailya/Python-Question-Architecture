# 🔗 URI (Uniform Resource Identifier)

## 🎤 Короткий ответ

**URI (Uniform Resource Identifier)** — это строка, которая **идентифицирует ресурс** в сети или информационной системе.

В Web URI используется для обозначения конкретного ресурса: пользователя, товара, заказа, файла и т. д.

Например:

```python
https://api.example.com/users/42
```

Здесь URI идентифицирует пользователя с `id=42`.

**URI — более общее понятие, чем URL:** URL не только идентифицирует ресурс, но и указывает, **где и как его получить**.

---

## 🗣️ Ответ на собеседовании

URI — это Uniform Resource Identifier, то есть унифицированный идентификатор ресурса.

В REST API URI обычно используется для идентификации ресурсов. Например, `/users/42` идентифицирует пользователя с ID 42, а `/users/42/orders` — его заказы.

URI может содержать схему, домен, путь, query-параметры и другие компоненты.

Важно не путать URI и URL: **URL является разновидностью URI** и содержит информацию о способе доступа к ресурсу. Например, `https://example.com/users/42` — URL, который одновременно является URI.

В REST обычно стараются строить URI вокруг **ресурсов**, а не действий: `/users/42`, а не `/getUser?id=42`.

# 📚 Разбор поглубже

## 1. Что такое URI

**URI = Uniform Resource Identifier.**

Главная идея:

> URI отвечает на вопрос: **«Как однозначно идентифицировать этот ресурс?»**

Например:

```python
/users/42
```

Можно воспринимать как идентификатор ресурса:

```text
/users/42
```

где:

* `/users` — коллекция пользователей;
* `42` — конкретный пользователь.

Другой пример:

```python
/users/42/orders/15
```

Здесь идентифицируется заказ `15`, принадлежащий пользователю `42`.

---

## 2. Из чего может состоять URI

Полный URI может выглядеть так:

```python
https://api.example.com:443/users/42?active=true#profile
```

Разберём:

```text
https://              → scheme
api.example.com       → host
:443                  → port
/users/42             → path
?active=true          → query
#profile              → fragment
```

То есть концептуально:

```text
scheme://host:port/path?query#fragment
```

Не каждый URI обязан содержать все эти компоненты.

---

## 3. URI в REST API

В REST URI обычно описывает **ресурс**, а HTTP-метод определяет, что мы хотим с ним сделать.

Например:

```text
GET    /users/42
POST   /users
PUT    /users/42
PATCH  /users/42
DELETE /users/42
```

URI:

```text
/users/42
```

остаётся идентификатором пользователя.

А действие определяется HTTP-методом:

| Метод  | Смысл             |
| ------ | ----------------- |
| GET    | получить          |
| POST   | создать           |
| PUT    | заменить          |
| PATCH  | частично изменить |
| DELETE | удалить           |

Это важный принцип REST.

---

## 4. URI должен описывать ресурс, а не действие

Хороший REST-подход:

```python
GET /users/42
```

Вместо:

```python
GET /getUser/42
```

И:

```python
DELETE /users/42
```

Вместо:

```python
POST /deleteUser/42
```

Почему?

Потому что **действие уже выражено HTTP-методом**.

URI описывает:

```text
ЧТО?
```

HTTP-метод описывает:

```text
ЧТО СДЕЛАТЬ?
```

# 5. URI ≠ URL

Это один из частых вопросов на собеседовании.

### URI

Общее понятие — **идентификатор ресурса**.

### URL

**Uniform Resource Locator** — идентификатор, который также указывает способ/место доступа к ресурсу.

Например:

```python
https://example.com/users/42
```

Это URL и одновременно URI.

Упрощённо:

```text
URI
├── URL
└── URN
```

Поэтому корректно сказать:

> **Каждый URL является URI, но не каждый URI является URL.**

---

# 6. URI и URN

**URN (Uniform Resource Name)** — разновидность URI, которая идентифицирует ресурс по имени.

Например:

```python
urn:isbn:9780132350884
```

Здесь не указывается HTTP-адрес, по которому можно получить книгу.

Идея:

```text
URL → где/как найти
URN → имя/идентичность
URI → общее понятие идентификатора
```

---

# 7. Path и Query Parameters

Это тоже важно для REST.

### Path Parameter

Используется для идентификации конкретного ресурса:

```python
/users/42
```

Здесь:

```text
42
```

— идентификатор пользователя.

### Query Parameter

Используется для параметров запроса, фильтрации, сортировки и т. д.:

```python
/users?role=admin&active=true
```

Здесь:

```text
/users
```

— ресурс,

а:

```text
role=admin
active=true
```

— параметры запроса.

Упрощённо:

```text
/users/42
        ↑
   конкретный ресурс

/users?active=true
       ↑
    фильтрация
```

# 8. URI и идентификация ресурса

Например, есть интернет-магазин.

```text
/products
```

означает коллекцию товаров.

```text
/products/15
```

означает конкретный товар.

```text
/products/15/reviews
```

означает отзывы этого товара.

Можно представить иерархию:

```text
/products
└── /15
    └── /reviews
```

Это хорошо соответствует ресурсной модели REST.

---

# 9. URI не обязательно означает физический файл

Это важный нюанс.

Когда мы пишем:

```python
/users/42
```

это **не означает**, что на сервере существует файл:

```text
/users/42
```

URI — логический идентификатор ресурса.

Сервер может получить данные:

```text
/users/42
        ↓
FastAPI
        ↓
Service
        ↓
PostgreSQL
        ↓
User
```

То есть URI является частью интерфейса API, а не обязательно путём к файлу на диске.

---

# 10. URI и REST

В REST API обычно придерживаются ресурсной модели:

```text
/users
/users/42
/users/42/orders
/orders
/orders/100
```

А операции выполняются через HTTP:

```text
GET    /users/42
POST   /users
PATCH  /users/42
DELETE /users/42
```

Поэтому полезно держать в голове формулу:

```text
URI → какой ресурс
HTTP Method → какая операция
HTTP Status → результат операции
Representation → представление ресурса
```

Например:

```text
GET /users/42
```

означает:

> получить представление ресурса пользователя `42`.

# 11. Частая ошибка на собеседовании

❌ Неправильно:

> URI — это просто адрес сайта.

Более точно:

> URI — это унифицированный идентификатор ресурса. URL — частный случай URI, который предоставляет информацию о расположении и способе доступа к ресурсу.

## 🎤 Вопросы на собеседовании

**Что такое URI?**

> Унифицированный идентификатор ресурса. В REST API URI используется для идентификации ресурсов.

**Чем URI отличается от URL?**

> URI — более общее понятие. URL является разновидностью URI и содержит информацию о местоположении и способе доступа к ресурсу.

**Что такое URN?**

> Разновидность URI, идентифицирующая ресурс по имени, без указания способа его получения.

**Что обычно находится в URI REST API?**

> Идентификатор ресурса и его иерархия. Например `/users/42/orders`.

**Почему `/users/42`, а не `/getUser/42`?**

> Потому что в REST URI идентифицирует ресурс, а действие выражается HTTP-методом: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.

**URI обязательно указывает на файл?**

> Нет. Это логический идентификатор ресурса. Сервер сам определяет, откуда получить или как сформировать это представление.
