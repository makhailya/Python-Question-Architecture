# 🌐 HTTP-методы

## 🎤 Суперкоротко

> **HTTP-методы определяют, какое действие клиент хочет выполнить над ресурсом. Основные методы REST API: GET — получить, POST — создать, PUT — полностью заменить, PATCH — частично изменить, DELETE — удалить.**

---

# 🎯 Ответ на собеседовании

**HTTP-метод** — это часть HTTP-запроса, которая определяет намерение клиента относительно ресурса.

В REST API HTTP-методы используются для выражения операций над ресурсами.

Например:

```python
GET = "получить ресурс"
POST = "создать ресурс"
PUT = "полностью заменить ресурс"
PATCH = "частично изменить ресурс"
DELETE = "удалить ресурс"
```

---

# 🔍 GET

Используется для **получения ресурса или коллекции ресурсов**.

```python
GET /users
```

Получить список пользователей.

```python
GET /users/42
```

Получить пользователя с ID `42`.

`GET` не должен изменять состояние сервера.

Пример на FastAPI:

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {
        "id": user_id,
        "name": "Ilya",
    }
```

---

# ➕ POST

Используется для **создания нового ресурса**.

```python
POST /users
```

Например, клиент отправляет данные:

```python
user = {
    "name": "Ilya",
    "email": "ilya@example.com",
}
```

Сервер создаёт нового пользователя.

Пример:

```python
@app.post("/users")
def create_user(name: str, email: str):
    return {
        "name": name,
        "email": email,
    }
```

После успешного создания обычно возвращается:

```python
status_code = 201  # Created
```

---

# 🔄 PUT

Используется для **полной замены ресурса**.

```python
PUT /users/42
```

Например:

```python
user = {
    "name": "Ilya",
    "email": "new@example.com",
    "age": 31,
}
```

Идея:

```text
Старый ресурс
      ↓
полностью заменяется
      ↓
Новым представлением
```

Пример:

```python
@app.put("/users/{user_id}")
def replace_user(
    user_id: int,
    name: str,
    email: str,
):
    return {
        "id": user_id,
        "name": name,
        "email": email,
    }
```

---

# 🩹 PATCH

Используется для **частичного изменения ресурса**.

```python
PATCH /users/42
```

Например, хотим изменить только имя:

```python
user_update = {
    "name": "Alex",
}
```

Остальные поля передавать необязательно.

Пример:

```python
@app.patch("/users/{user_id}")
def update_user(
    user_id: int,
    name: str | None = None,
):
    return {
        "id": user_id,
        "name": name,
    }
```

Главное отличие:

```text
PUT
 ↓
полная замена

PATCH
 ↓
частичное изменение
```

---

# 🗑️ DELETE

Используется для **удаления ресурса**.

```python
DELETE /users/42
```

Удалить пользователя с ID `42`.

Пример:

```python
@app.delete("/users/{user_id}")
def delete_user(user_id: int):
    return {
        "message": f"User {user_id} deleted",
    }
```

После успешного удаления часто возвращают:

```python
status_code = 204  # No Content
```

---

# 🆚 PUT vs PATCH

Это один из самых популярных вопросов на собеседовании.

Предположим, есть пользователь:

```python
user = {
    "id": 42,
    "name": "Ilya",
    "email": "ilya@example.com",
    "age": 31,
}
```

### PUT

Передаём новое **полное представление**:

```python
put_data = {
    "name": "Alex",
    "email": "alex@example.com",
    "age": 32,
}
```

### PATCH

Передаём только изменяемое поле:

```python
patch_data = {
    "age": 32,
}
```

Запомнить:

```text
PUT
 ↓
заменить ресурс целиком

PATCH
 ↓
изменить часть ресурса
```

# 🧠 CRUD и HTTP-методы

HTTP-методы часто сопоставляют с CRUD:

```text
CRUD
 ↓
Create → POST
Read   → GET
Update → PUT / PATCH
Delete → DELETE
```

Но важно:

> **CRUD и HTTP-методы — не одно и то же.**

CRUD описывает операции над данными, а HTTP-методы являются частью протокола HTTP.

---

# 🔒 Безопасные HTTP-методы

**Safe method** — метод, который по смыслу запроса не должен изменять состояние сервера.

К безопасным относятся:

```python
safe_methods = [
    "GET",
    "HEAD",
    "OPTIONS",
    "TRACE",
]
```

Например:

```python
GET /users/42
```

должен только получать данные.

---

# 🔁 Идемпотентность

**Идемпотентный метод** — метод, повторное выполнение которого должно иметь тот же итоговый эффект на состояние сервера, что и однократное выполнение.

Обычно к идемпотентным относятся:

```python
idempotent_methods = [
    "GET",
    "PUT",
    "DELETE",
    "HEAD",
    "OPTIONS",
    "TRACE",
]
```

Например:

```python
PUT /users/42
```

Если отправить один и тот же запрос несколько раз, ресурс должен прийти к одному и тому же состоянию.

С `POST` ситуация другая:

```python
POST /users
```

Повторная отправка может создать несколько ресурсов:

```text
1 POST → пользователь №1
2 POST → пользователь №2
3 POST → пользователь №3
```

Поэтому `POST` обычно не является идемпотентным.

---

# ⚠️ DELETE и идемпотентность

`DELETE` считается идемпотентным по результату изменения состояния.

Например:

```python
DELETE /users/42
```

Первый запрос удаляет пользователя.

Повторный запрос может вернуть `404`, но итоговое состояние остаётся тем же:

```text
пользователь с ID 42 отсутствует
```

То есть:

```text
1 × DELETE → пользователь отсутствует
2 × DELETE → пользователь отсутствует
3 × DELETE → пользователь отсутствует
```

Для идемпотентности важен **итоговый эффект**, а не обязательно одинаковый HTTP-ответ.

# 🧩 Другие HTTP-методы

Помимо основных методов существуют:

```python
other_methods = [
    "HEAD",
    "OPTIONS",
    "TRACE",
    "CONNECT",
]
```

### HEAD

Похож на `GET`, но сервер возвращает заголовки без тела ответа.

Используется, например, чтобы проверить ресурс без загрузки его содержимого.

---

### OPTIONS

Позволяет узнать, какие методы и возможности поддерживает ресурс.

Часто встречается при работе с **CORS**.

Например:

```python
OPTIONS /users
```

---

### TRACE

Используется преимущественно для диагностических целей.

В современных REST API применяется редко.

---

### CONNECT

Используется для создания сетевого туннеля.

Часто связан с работой прокси и HTTPS.

# 🧠 Главное

```text
GET
 ↓
получить

 ↓
создать

PUT
 ↓
полностью заменить

PATCH
 ↓
частично изменить

DELETE
 ↓
удалить
```

Ещё два важных понятия:

```text
Safe
 ↓
не должен изменять состояние сервера

Idempotent
 ↓
повторение запроса даёт тот же итоговый эффект
```

# 🎯 Формула для запоминания

```text
GET    → Read
POST   → Create
PUT    → Replace
PATCH  → Partial Update
DELETE → Delete
```

> **На собеседовании особенно важно понимать разницу между PUT и PATCH, а также понятия safe и idempotent.**
