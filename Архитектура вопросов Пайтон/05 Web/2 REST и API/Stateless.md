# 🧠 Stateless

## 🎯 Ответ на собеседовании

**Stateless** — это принцип REST, согласно которому **сервер не хранит состояние клиента между запросами**.

Каждый запрос должен содержать **всю необходимую информацию для его обработки**.

Сервер обрабатывает каждый запрос независимо от предыдущих запросов этого клиента.

Например:

```python
GET /api/profile
Authorization: Bearer <token>
```

Сервер получает токен из текущего запроса, определяет пользователя и возвращает его профиль.

Ему не нужно помнить, что этот клиент уже отправлял какой-то предыдущий запрос.

---

## 🎤 Суперкоротко

**Stateless = каждый запрос самодостаточен.**

```text
Запрос 1 → сервер
Запрос 2 → сервер
Запрос 3 → сервер
```

Сервер не должен зависеть от состояния предыдущих запросов.

---

## 🔄 Пример

Клиент делает запрос:

```python
GET /api/profile
Authorization: Bearer <JWT>
```

Сервер:

```text
JWT
 ↓
проверка токена
 ↓
определение пользователя
 ↓
получение данных
 ↓
ответ
```

Следующий запрос снова содержит необходимую информацию:

```python
GET /api/orders
Authorization: Bearer <JWT>
```

Сервер снова самостоятельно обрабатывает запрос.

---

## ❌ Stateful

При **stateful** сервер хранит состояние клиента у себя.

Например:

```text
Client
   ↓
Server 1
   ↓
Session = user_123
```

Следующий запрос может зависеть от предыдущего:

```text
Client → Server 1
```

Если запрос попадёт на другой сервер:

```text
Client → Server 2
```

Server 2 может не знать о существующей сессии.

---

## ✅ Stateless

При stateless серверу не нужно помнить состояние клиента:

```text
             ┌→ Server 1
Client → LB ─┼→ Server 2
             └→ Server 3
```

Любой сервер может обработать запрос, потому что необходимая информация находится в самом запросе или доступна через общее внешнее хранилище.

---

## 🔑 JWT и Stateless

Частый пример stateless-аутентификации — **JWT**.

```python
Authorization: Bearer <JWT>
```

JWT содержит информацию, необходимую для идентификации пользователя.

Сервер проверяет подпись токена и получает данные пользователя.

Поэтому серверу не обязательно хранить отдельную серверную сессию для каждого клиента.

```text
Client
  ↓ JWT
Load Balancer
  ↓
Server 1 / Server 2 / Server 3
```

---

## ⚠️ Stateless ≠ отсутствие состояния вообще

Это важный момент на собеседовании.

**Stateless означает, что сервер не хранит состояние клиента между запросами в рамках самого взаимодействия.**

Это не означает, что сервер вообще ничего не хранит.

Например, сервер может хранить:

```text
PostgreSQL → данные пользователей
Redis      → кэш
```

Но обработка конкретного запроса не должна зависеть от памяти о предыдущем запросе этого клиента.

---

## 🚀 Зачем нужен Stateless

Главное преимущество — **горизонтальное масштабирование**.

Можно добавить новые серверы:

```text
             ┌→ Server 1
             ├→ Server 2
Client → LB ─┼→ Server 3
             └→ Server 4
```

Любой сервер может обработать любой запрос.

Это упрощает:

* балансировку нагрузки;
* масштабирование;
* отказоустойчивость;
* замену и добавление серверов.

---

## 🆚 Stateful vs Stateless

|                                      | Stateful            | Stateless |
| ------------------------------------ | ------------------- | --------- |
| Сервер хранит состояние клиента      | Да                  | Нет       |
| Запросы зависят от предыдущих        | Могут               | Нет       |
| Любой сервер может обработать запрос | Не всегда           | Да        |
| Масштабирование                      | Сложнее             | Проще     |
| Пример                               | Server-side session | JWT       |

---

## 🧩 Связь с Sticky Session

Если приложение **stateful** и хранит сессию локально:

```text
Client → Server 1
```

может потребоваться **Sticky Session**:

```text
Client → Server 1
Client → Server 1
Client → Server 1
```

Если приложение **stateless**:

```text
Client → Server 1
Client → Server 2
Client → Server 3
```

запросы могут свободно распределяться между серверами.

---

## 🧠 Главное

```text
Stateless

Каждый запрос
      ↓
самодостаточный
      ↓
сервер обрабатывает его независимо
      ↓
не зависит от предыдущего запроса
```

**Stateless = сервер не хранит состояние клиента между запросами, а каждый запрос содержит всю необходимую информацию для его обработки.**

Главное преимущество:

**любой сервер может обработать любой запрос → проще масштабировать систему.**
