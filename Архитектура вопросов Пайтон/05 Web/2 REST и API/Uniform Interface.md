# 🔗 Uniform Interface

## 🎯 Ответ на собеседовании

**Uniform Interface** — это принцип REST, согласно которому взаимодействие клиента и сервера должно происходить через **единый, стандартизированный и предсказуемый интерфейс**.

Клиент должен понимать, **как обращаться к ресурсам и как с ними работать**, независимо от внутренней реализации сервера.

Основные элементы Uniform Interface:

1. **Идентификация ресурсов**
2. **Манипуляция ресурсами через представления**
3. **Самодостаточные сообщения**
4. **HATEOAS** — предоставление ссылок на связанные действия

---

## 🎤 Суперкоротко

**Uniform Interface = единый и предсказуемый способ взаимодействия с ресурсами.**

Например:

```python id="c7s3qe"
GET    /users
GET    /users/10
POST   /users
PATCH  /users/10
DELETE /users/10
```

Клиент использует стандартные HTTP-механизмы, а не знает внутреннюю реализацию сервера.

---

# 1. 🆔 Идентификация ресурсов

Каждый ресурс должен иметь **уникальный идентификатор**.

Обычно в REST API для этого используются URI.

Например:

```python id="4q7f5a"
GET /users
GET /users/10

GET /products
GET /products/25

GET /orders
GET /orders/100
```

Здесь:

```text id="8pxf3m"
 /users       → коллекция пользователей
 /users/10    → конкретный пользователь
```

Важно разделять:

```text id="p7s0rj"
Ресурс ≠ его представление
```

Например, пользователь — это ресурс, а JSON:

```python id="j3c4s8"
{
    "id": 10,
    "name": "Ilya"
}
```

— его **представление**.

---

# 2. 🔄 Манипуляция ресурсами через представления

Клиент взаимодействует с ресурсом через его **представление**.

Например:

```python id="f0y6qj"
GET /users/10
```

Сервер возвращает представление ресурса:

```python id="0d8p1r"
{
    "id": 10,
    "name": "Ilya"
}
```

Клиент может отправить новое представление для изменения ресурса:

```python id="x9p5la"
PATCH /users/10
```

```python id="0m8q4w"
{
    "name": "Alex"
}
```

Сервер самостоятельно решает, **как изменить данные внутри системы**.

Клиенту не нужно знать:

```text
как устроена база данных
какие таблицы используются
какая ORM используется
как реализована бизнес-логика
```

---

# 3. 🧾 Self-Descriptive Messages

Сообщения должны быть **самодостаточными** — из запроса или ответа должно быть понятно, как его интерпретировать.

Например:

```python id="a2q7nf"
GET /users/10
Accept: application/json
Authorization: Bearer <token>
```

Здесь указано:

```text id="k9n2vc"
GET
→ что хотим получить

/users/10
→ какой ресурс

Accept: application/json
→ какое представление ожидаем

Authorization
→ данные для аутентификации
```

Ответ также содержит информацию о результате:

```python id="m6z1tw"
HTTP/1.1 200 OK
Content-Type: application/json
```

То есть сообщение содержит необходимые метаданные для его обработки.

---

# 4. 🔗 HATEOAS

**HATEOAS (Hypermedia As The Engine Of Application State)** — принцип, при котором сервер может предоставлять клиенту ссылки на связанные действия и ресурсы.

Например:

```python id="v8g5pk"
{
    "id": 10,
    "name": "Ilya",
    "links": [
        {
            "rel": "self",
            "href": "/users/10"
        },
        {
            "rel": "orders",
            "href": "/users/10/orders"
        }
    ]
}
```

Клиент получает не только данные пользователя, но и информацию о том, **куда он может перейти дальше**.

---

# 🧩 Почему Interface называется Uniform

Представь API без единого подхода:

```text id="9k3tqz"
GET  /getUsers
POST /createNewUser
GET  /userInfo?id=10
POST /deleteUser?id=10
```

А REST-подход стремится сделать интерфейс предсказуемым:

```python id="x1q8ma"
GET    /users
GET    /users/10
POST   /users
PATCH  /users/10
DELETE /users/10
```

Используются:

* URI для идентификации ресурсов;
* HTTP-методы для операций;
* HTTP status codes для результата;
* headers для метаданных;
* стандартные представления ресурсов.

---

# 🆚 Uniform Interface vs обычный API

### Непредсказуемый API

```python id="e7s2kw"
GET  /getUser?id=10
POST /updateUser
POST /deleteUser
```

### Единообразный REST API

```python id="k5p9wr"
GET    /users/10
PATCH  /users/10
DELETE /users/10
```

Клиенту проще понимать и использовать такой API.

---

# ⚠️ Важный нюанс

**Uniform Interface — это не просто "использовать GET, POST, PUT и DELETE".**

Это более широкое ограничение, включающее четыре концепции:

```text id="p2r6fx"
Uniform Interface
│
├── Identification of Resources
├── Manipulation through Representations
├── Self-Descriptive Messages
└── HATEOAS
```

Поэтому если на собеседовании спрашивают:

> Какие элементы входят в Uniform Interface?

Лучше назвать **все четыре**.

---

# 🧠 Главное

```text id="b7m4nx"
Uniform Interface
       ↓
Единый способ взаимодействия
       ↓
┌──────────────────────────────┐
│ Идентификация ресурсов       │
│ Представления ресурсов       │
│ Самодостаточные сообщения    │
│ HATEOAS                      │
└──────────────────────────────┘
```

**Uniform Interface = единый, стандартизированный и предсказуемый интерфейс взаимодействия клиента с ресурсами.**

Для собеседования:

> **Клиент взаимодействует с ресурсами через единый интерфейс: ресурсы идентифицируются URI, изменяются через свои представления, сообщения являются самодостаточными, а сервер при необходимости предоставляет гипермедийные ссылки на дальнейшие действия.**
