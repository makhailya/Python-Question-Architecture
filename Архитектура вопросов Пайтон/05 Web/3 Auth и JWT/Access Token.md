# 🎫 Access Token

## 🎯 Ответ на собеседовании

**Access Token** — это токен, который клиент использует для **доступа к защищённым ресурсам API**.

После успешной аутентификации сервер выдаёт клиенту access-токен. Клиент затем передаёт его в каждом запросе к защищённым ресурсам.

Чаще всего токен передают в HTTP-заголовке:

```python
Authorization: Bearer <access_token>
```

Сервер проверяет токен и, если он действителен, предоставляет доступ к ресурсу.

---

## 🎤 Суперкоротко

**Access Token = временный пропуск к защищённым ресурсам API.**

```text
Аутентификация
      ↓
Access Token
      ↓
Authorization: Bearer <token>
      ↓
Защищённый API
```

---

# 🔄 Как работает

Пользователь сначала проходит аутентификацию:

```text
Client
  ↓
логин + пароль
  ↓
Auth Server
```

Сервер выдаёт:

```text
Access Token
```

Затем клиент использует его:

```python
GET /api/profile
Authorization: Bearer eyJhbGciOi...
```

Сервер:

```text
получает токен
     ↓
проверяет токен
     ↓
определяет пользователя
     ↓
проверяет права
     ↓
возвращает ресурс
```

---

# ⏱️ Время жизни

Access Token обычно имеет **ограниченный срок действия**.

Например:

```text
Access Token
TTL = 15 минут
```

После истечения срока токен становится недействительным.

Это снижает последствия утечки токена: украденный access-токен не должен оставаться действительным бесконечно долго.

---

# 🔄 Access Token и Refresh Token

Часто используются два токена:

```text
Access Token
→ используется для доступа к API

Refresh Token
→ используется для получения нового Access Token
```

Схема:

```text
             ┌→ Access Token → API
Auth Server ─┤
             └→ Refresh Token
                         ↓
                 новый Access Token
```

Например:

```text
Access Token  → 15 минут
Refresh Token → значительно дольше
```

---

# 🔐 JWT Access Token

Access Token может быть представлен в формате **JWT**.

Например:

```python
Authorization: Bearer <JWT>
```

JWT содержит:

```text
Header
Payload
Signature
```

Сервер проверяет подпись и срок действия токена.

---

# 🆚 Access Token vs API Key

**Access Token** обычно связан с конкретной авторизацией пользователя или клиента и часто имеет срок действия.

**API Key** обычно представляет приложение или интеграцию и часто используется как более простой механизм идентификации/доступа.

```text
Access Token → временный доступ
API Key      → ключ приложения/интеграции
```

---

# ⚠️ Важный момент

**Access Token подтверждает право доступа, но не обязательно содержит пароль или другую секретную информацию.**

Например, JWT может содержать:

```python
{
    "sub": "123",
    "exp": 1780000000,
    "role": "user"
}
```

При этом содержимое JWT в обычном случае **не зашифровано**, а закодировано Base64URL. Защиту от подделки обеспечивает подпись.

---

# 🧠 Главное

```text
Login
  ↓
Authentication
  ↓
Access Token
  ↓
Authorization: Bearer <token>
  ↓
Protected API
```

**Access Token — это временный credential, который клиент предъявляет API для получения доступа к защищённым ресурсам.**

Главное на собеседовании:

> **Access Token выдаётся после аутентификации и используется клиентом для доступа к защищённым ресурсам API. Обычно он передаётся в заголовке `Authorization: Bearer <token>` и имеет ограниченный срок действия.**
