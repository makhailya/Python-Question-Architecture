# 🔐 Способы аутентификации

## 🎤 Суперкоротко

**Способы аутентификации** — это способы доказать системе, что пользователь действительно является тем, за кого себя выдаёт.

Основные факторы:

```text
1. Что ты знаешь       → пароль, PIN
2. Что у тебя есть     → телефон, токен, ключ
3. Кто ты              → биометрия
```

Дополнительно в веб-разработке часто встречаются:

* парольная аутентификация;
* OTP / TOTP;
* токены;
* сессии и cookies;
* API keys;
* сертификаты;
* OAuth 2.0 / OpenID Connect;
* MFA.

---

## 🎯 Ответ на собеседовании

**Аутентификация может выполняться с использованием разных факторов и механизмов.**

Классически выделяют три фактора:

1. **Knowledge factor** — то, что пользователь знает.
2. **Possession factor** — то, что пользователь имеет.
3. **Inherence factor** — то, чем пользователь является.

Для повышения безопасности можно использовать несколько факторов одновременно — это называется **MFA (Multi-Factor Authentication)**.

---

# 🧠 1. Что ты знаешь

Пользователь доказывает личность информацией, которую должен знать только он.

Примеры:

```text
Пароль
PIN-код
Секретная фраза
```

Самый распространённый вариант:

```text
Логин + Пароль
```

Например:

```python
username = "ilya"
password = "my_password"
```

Сервер проверяет предоставленные credentials.

---

# 🔑 Как правильно хранить пароль

Пароли **нельзя хранить в базе данных в открытом виде**.

Плохо:

```python
user = {
    "username": "ilya",
    "password": "123456"
}
```

Правильно — хранить **хэш пароля**.

```text
Пароль
   ↓
Password Hash Function
   ↓
Хэш
   ↓
Database
```

При входе:

```text
Введённый пароль
       ↓
Хэширование
       ↓
Сравнение с сохранённым хэшем
```

Для паролей используются специальные password hashing algorithms, например:

* Argon2;
* bcrypt;
* scrypt.

Обычный быстрый SHA-256 для хранения паролей использовать не следует.

---

# 📱 2. Что у тебя есть

Пользователь доказывает личность с помощью объекта или устройства, которым он владеет.

Примеры:

```text
📱 Телефон
🔑 Аппаратный ключ
🎟️ Токен
💳 Карта
```

Например, система отправляет одноразовый код на телефон:

```text
SMS → 483921
```

Пользователь вводит:

```python
otp = "483921"
```

Система проверяет код.

---

# 🔢 OTP

**OTP (One-Time Password)** — одноразовый пароль.

Он действителен:

* один раз;
* или ограниченное время.

Пример:

```text
Введите код:
483921
```

После успешного использования код становится недействительным.

---

# ⏱️ TOTP

**TOTP (Time-Based One-Time Password)** — одноразовый пароль, который вычисляется на основе времени.

Используется, например, приложениями-аутентификаторами.

Упрощённо:

```text
Секретный ключ + текущее время
              ↓
             TOTP
              ↓
            483921
```

Код обычно меняется через определённый интервал времени.

---

# 👤 3. Кто ты

Это **биометрический фактор**.

Примеры:

```text
👆 Отпечаток пальца
🙂 Распознавание лица
👁️ Радужная оболочка
🗣️ Голос
```

Идея:

> Используется уникальный физический или поведенческий признак человека.

---

# 🔐 MFA

**MFA (Multi-Factor Authentication)** — многофакторная аутентификация.

Используются **два или более разных факторов**.

Например:

```text
Пароль
   +
TOTP
   ↓
MFA
```

Здесь:

```text
Пароль → что ты знаешь
TOTP   → что у тебя есть
```

Другой пример:

```text
Пароль
   +
Аппаратный ключ
   ↓
MFA
```

---

# ⚠️ 2FA и MFA

**2FA (Two-Factor Authentication)** — используется ровно два фактора.

**MFA** — два или больше факторов.

```text
2FA ⊂ MFA
```

То есть любая 2FA является MFA, но MFA не обязательно ограничивается двумя факторами.

---

# 🍪 4. Сессии и Cookies

В веб-приложениях после успешной аутентификации сервер может создать сессию.

Схема:

```text
Логин + Пароль
       ↓
Аутентификация
       ↓
Создание Session
       ↓
Session ID
       ↓
Cookie
```

Например:

```text
Set-Cookie: session_id=abc123
```

Браузер затем отправляет:

```text
Cookie: session_id=abc123
```

Сервер по `session_id` определяет пользователя.

---

# 🎟️ 5. Токены

Другой распространённый подход — использование токена.

После успешной аутентификации сервер выдаёт токен:

```text
Логин + Пароль
       ↓
Аутентификация
       ↓
Access Token
```

Клиент использует его в следующих запросах:

```python
headers = {
    "Authorization": "Bearer TOKEN"
}
```

Сервер проверяет токен и определяет пользователя.

---

# 🪪 JWT

**JWT (JSON Web Token)** — один из форматов токенов.

Упрощённо JWT состоит из:

```text
Header.Payload.Signature
```

Например:

```text
eyJhbGciOiJIUzI1NiJ9
.
eyJzdWIiOiIxMjMifQ
.
SIGNATURE
```

JWT может содержать claims, например:

```python
payload = {
    "sub": "123",
    "role": "user"
}
```

Важно:

**JWT — это формат токена, а не отдельный способ шифрования.**

---

# 🔑 6. API Key

**API Key** — секретный идентификатор, который приложение использует для аутентификации или идентификации клиента API.

Например:

```python
headers = {
    "X-API-Key": "secret-key"
}
```

API keys часто используются:

* между сервисами;
* для доступа к внешним API;
* для идентификации приложения.

API key следует считать секретом и не помещать в публичный репозиторий.

---

# 📜 7. Сертификаты

Для аутентификации можно использовать цифровые сертификаты.

Например, при **mTLS**:

```text
Клиент ── Certificate ──> Сервер
Сервер ── Certificate ──> Клиент
```

Обе стороны подтверждают свою личность с помощью сертификатов.

Часто используется:

* в микросервисах;
* во внутренних корпоративных системах;
* при service-to-service взаимодействии.

---

# 🌍 8. OAuth 2.0

**OAuth 2.0** — протокол делегирования авторизации.

Важный нюанс:

**OAuth 2.0 сам по себе предназначен прежде всего для авторизации, а не для аутентификации пользователя.**

Например:

> «Разрешить этому приложению получить доступ к определённым ресурсам».

Для аутентификации пользователя поверх OAuth 2.0 часто используется **OpenID Connect (OIDC)**.

---

# 🪪 OpenID Connect

**OpenID Connect** — слой идентификации поверх OAuth 2.0.

Упрощённо:

```text
OAuth 2.0
    ↓
Делегирование доступа

OpenID Connect
    ↓
Аутентификация пользователя
```

Например:

```text
Войти через Google
        ↓
OpenID Connect
        ↓
Приложение узнаёт,
кто пользователь
```

---

# 🔐 Сравнение способов

| Способ     | Фактор / механизм            | Пример               |
| ---------- | ---------------------------- | -------------------- |
| Пароль     | Что знаешь                   | `password`           |
| PIN        | Что знаешь                   | `1234`               |
| SMS OTP    | Что имеешь                   | код на телефон       |
| TOTP       | Что имеешь                   | Authenticator        |
| Биометрия  | Кто ты                       | Face ID              |
| Session    | Сессионный механизм          | Cookie + Session ID  |
| JWT        | Токен                        | Bearer Token         |
| API Key    | Секретный ключ               | `X-API-Key`          |
| Сертификат | Криптографический credential | mTLS                 |
| OIDC       | Федеративная аутентификация  | «Войти через Google» |

# 🧩 Password vs Token

### Password

Пользователь постоянно предоставляет секрет:

```text
Login + Password
```

Сервер проверяет пароль.

### Token

Пароль используется для получения токена:

```text
Login + Password
       ↓
     Token
       ↓
Последующие запросы
```

Это позволяет не передавать пароль при каждом запросе.

---

# 🧠 Важное различие

Не нужно смешивать **фактор аутентификации** и **механизм аутентификации**.

Например:

```text
Пароль
```

— это фактор:

> «Что ты знаешь».

А:

```text
Session Cookie
JWT
API Key
```

— это механизмы передачи credentials / состояния между запросами.

---

# 🎯 Как это выглядит в реальном API

Например, пользователь входит:

```text
POST /login
       ↓
login + password
       ↓
Authentication
       ↓
Access Token
```

Затем:

```text
GET /profile

Authorization: Bearer TOKEN
```

Сервер:

```text
Token
 ↓
Проверка
 ↓
Пользователь
 ↓
Authorization
 ↓
Проверка прав
```

То есть:

```text
Идентификация
     ↓
Аутентификация
     ↓
Получение credentials
     ↓
Авторизация
```

---

# 🧠 Главное

Три классических фактора:

```text
🧠 Что ты знаешь
   → пароль, PIN

📱 Что у тебя есть
   → телефон, токен, аппаратный ключ

👤 Кто ты
   → биометрия
```

**MFA** — использование нескольких разных факторов.

В веб-разработке часто встречаются:

```text
Password
Session + Cookie
JWT / Bearer Token
API Key
OTP / TOTP
Certificates / mTLS
OAuth 2.0 + OpenID Connect
```

И главное различие:

```text
Идентификация
→ «Кто ты?»

Аутентификация
→ «Докажи, что это ты»

Авторизация
→ «Что тебе разрешено?»
```
