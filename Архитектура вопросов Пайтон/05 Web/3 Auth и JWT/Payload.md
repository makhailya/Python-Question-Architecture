# 📦 JWT Payload

## 🎯 Ответ на собеседовании

**Payload — это вторая часть JWT, содержащая claims — утверждения и данные о токене и его субъекте.**

В Payload могут находиться, например:

* идентификатор пользователя;
* роль;
* срок действия токена;
* время выпуска;
* issuer;
* audience.

Payload **не шифруется**, а обычно кодируется Base64URL, поэтому его содержимое можно прочитать.

---

## 🎤 Суперкоротко

**Payload = данные и claims JWT.**

Например:

```python
{
    "sub": "123",
    "role": "user",
    "exp": 1790000000
}
```

Важно:

**Payload нельзя считать секретным.**

---

# 🧩 Где находится Payload

JWT:

```text
Header.Payload.Signature
```

Например:

```text
eyJhbGciOiJIUzI1NiJ9
.
eyJzdWIiOiIxMjMifQ
.
SIGNATURE
```

Вторая часть:

```text
eyJzdWIiOiIxMjMifQ
```

— Payload.

После Base64URL-декодирования получаем JSON.

---

# 📋 Claims

Данные внутри Payload называются **claims**.

Они описывают субъект или свойства токена.

Например:

```python
payload = {
    "sub": "123",
    "role": "user",
    "exp": 1790000000
}
```

---

# 🔑 Основные claims

## `sub`

**Subject** — субъект токена.

Часто содержит ID пользователя:

```python
{
    "sub": "123"
}
```

---

## `exp`

**Expiration Time** — время окончания действия токена.

```python
{
    "exp": 1790000000
}
```

После этого момента JWT считается истёкшим.

---

## `iat`

**Issued At** — время выпуска токена.

```python
{
    "iat": 1789990000
}
```

---

## `iss`

**Issuer** — кто выпустил токен.

```python
{
    "iss": "auth.example.com"
}
```

---

## `aud`

**Audience** — для кого предназначен токен.

```python
{
    "aud": "my-api"
}
```

---

# ⚠️ Payload не зашифрован

Очень важный момент:

```text
Base64URL ≠ Encryption
```

Например, если Payload содержит:

```python
{
    "user_id": 123,
    "role": "admin"
}
```

эти данные можно декодировать.

Поэтому не следует помещать в Payload:

```text
❌ пароль
❌ секретный ключ
❌ номер банковской карты
❌ другую конфиденциальную информацию
```

---

# 🛡️ Но Payload нельзя незаметно изменить

Payload защищается подписью.

Если злоумышленник изменит:

```python
{
    "role": "user"
}
```

на:

```python
{
    "role": "admin"
}
```

подпись перестанет соответствовать содержимому.

```text
Payload изменён
      ↓
Signature не совпадает
      ↓
❌ JWT недействителен
```

---

# 🎯 Главное

```text
Payload
   ↓
Claims
   ↓
Данные о токене / субъекте
```

Payload:

* можно прочитать;
* нельзя считать секретным;
* защищён от незаметного изменения подписью.

---

# 🧠 Формула для запоминания

**Payload = «Что говорится в этом JWT?»**

Например:

> Пользователь 123, роль user, токен действует до определённого времени.
