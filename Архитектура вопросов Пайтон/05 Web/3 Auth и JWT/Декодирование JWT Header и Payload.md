# 🔓 Декодирование JWT Header и Payload

## 🎯 Ответ на собеседовании

**JWT состоит из трёх частей: Header, Payload и Signature.**

```text
Header.Payload.Signature
```

`Header` и `Payload` представлены в формате **Base64URL**, поэтому их можно декодировать без секретного ключа.

Например:

```text
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
eyJzdWIiOiIxMjMiLCJleHAiOjE3ODAwMDAwMDB9
.
<signature>
```

После декодирования:

```python
Header:
{
    "alg": "HS256",
    "typ": "JWT"
}

Payload:
{
    "sub": "123",
    "exp": 1780000000
}
```

---

## 🎤 Суперкоротко

**Header и Payload JWT можно просто декодировать из Base64URL.**

```text
JWT
 ↓
Header      → Base64URL → JSON
Payload     → Base64URL → JSON
Signature   → нельзя просто декодировать для получения секрета
```

**Для декодирования Header и Payload секретный ключ не нужен.**

---

# 🧩 Header

Header содержит информацию о JWT.

Например:

```python
{
    "alg": "HS256",
    "typ": "JWT"
}
```

Где:

```text
alg → алгоритм подписи
typ → тип токена
```

---

# 📦 Payload

Payload содержит **claims** — утверждения о пользователе или токене.

Например:

```python
{
    "sub": "123",
    "role": "admin",
    "exp": 1780000000
}
```

Часто встречаются:

```text
sub → идентификатор субъекта
exp → время истечения токена
iat → время выдачи
iss → издатель токена
aud → получатель токена
```

---

# 🔓 Почему их можно декодировать без ключа

JWT использует:

```text
Base64URL
```

Это **кодирование**, а не шифрование.

Поэтому любой человек, получивший JWT, может посмотреть содержимое Header и Payload.

```text
JWT
 ↓
Base64URL decode
 ↓
JSON
```

Например:

```python
import base64
import json

payload = "eyJzdWIiOiIxMjMifQ"

padding = "=" * (-len(payload) % 4)

decoded = base64.urlsafe_b64decode(payload + padding)

data = json.loads(decoded)

print(data)
```

Результат:

```python
{
    "sub": "123"
}
```

---

# ⚠️ Самое важное: декодирование ≠ проверка

Это часто спрашивают на собеседовании.

Можно декодировать:

```text
Header
Payload
```

без ключа.

Но это **не означает, что токен настоящий**.

Сервер должен проверить **Signature**.

```text
Header + Payload
       ↓
декодировать можно без ключа

Signature
       ↓
проверить подлинность
       ↓
нужен соответствующий ключ
```

Например, злоумышленник может изменить:

```python
{
    "role": "user"
}
```

на:

```python
{
    "role": "admin"
}
```

После изменения Payload подпись уже не будет соответствовать данным.

Сервер проверит подпись и отклонит такой токен.

---

# 🔐 JWT не шифрует Payload

Поэтому **нельзя помещать в обычный JWT секретные данные**, рассчитывая на то, что Payload скрыт.

Не стоит хранить там:

```text
пароли
секретные ключи
данные банковских карт
другую конфиденциальную информацию
```

JWT обычно обеспечивает **целостность и подлинность токена через подпись**, а не конфиденциальность его содержимого.

Если нужна именно конфиденциальность, используются механизмы шифрования JWT, например **JWE**.

---

# 🧠 Главное

```text
JWT
│
├── Header
│     ↓
│   Base64URL
│     ↓
│   можно декодировать
│
├── Payload
│     ↓
│   Base64URL
│     ↓
│   можно декодировать
│
└── Signature
      ↓
    проверяется
      ↓
    нужен ключ
```

**Главная формулировка для собеседования:**

> **Header и Payload JWT можно декодировать без секретного ключа, потому что они закодированы в Base64URL, а не зашифрованы. Но декодирование не подтверждает подлинность токена — для этого сервер должен проверить Signature.**
