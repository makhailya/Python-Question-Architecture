# ✍️ JWT Signature

## 🎯 Ответ на собеседовании

**Signature — это третья часть JWT, цифровая подпись, которая позволяет проверить целостность токена и подлинность его подписи.**

Подпись создаётся на основе Header и Payload с использованием криптографического ключа и алгоритма, указанного в Header.

Упрощённо:

```text
Header + Payload
       ↓
 алгоритм + ключ
       ↓
 Signature
```

Если Header или Payload изменить, подпись перестанет совпадать.

---

## 🎤 Суперкоротко

**Signature = защита JWT от незаметного изменения.**

JWT:

```text
Header.Payload.Signature
```

Подпись позволяет серверу проверить:

```text
JWT не изменён?
Подпись создана доверенной стороной?
```

---

# 🔐 Как создаётся Signature

Упрощённо:

```text
Encoded Header
      +
Encoded Payload
      ↓
  Algorithm
      +
     Key
      ↓
  Signature
```

Например, для HMAC:

```python
signature = HMAC(
    secret_key,
    encoded_header + "." + encoded_payload
)
```

---

# 🔑 HS256

При использовании **HS256** применяется общий секретный ключ.

```text
              Secret
             ↙      ↘
        Sign          Verify
         ↓              ↓
      Server          Server
```

Один и тот же секрет используется для создания и проверки подписи.

---

# 🔑 RS256

При **RS256** используется пара ключей:

```text
Private Key → создаёт подпись

Public Key → проверяет подпись
```

Схема:

```text
Private Key
     ↓
 Signature
     ↓
    JWT
     ↓
Public Key
     ↓
 Проверка
```

Это удобно, когда токены выпускает один сервис, а проверяют несколько сервисов.

---

# 🛡️ Что произойдёт при изменении Payload

Допустим, настоящий JWT содержит:

```python
{
    "role": "user"
}
```

Злоумышленник изменяет его:

```python
{
    "role": "admin"
}
```

Но Signature остаётся старой.

Сервер пересчитывает подпись:

```text
Новый Header + Новый Payload
             ↓
        Новая Signature
             ↓
        Сравнение
             ↓
❌ Не совпадает
```

JWT отклоняется.

---

# ⚠️ Signature не скрывает данные

Подпись:

```text
❌ не шифрует Payload
✅ защищает его целостность
```

Поэтому:

```text
JWT ≠ зашифрованный текст
```

Если требуется именно шифрование содержимого, используется другой механизм — **JWE**.

---

# 🧩 Три части JWT

Теперь вся конструкция:

```text
┌──────────┬───────────┬─────────────┐
│  Header  │  Payload  │  Signature  │
└──────────┴───────────┴─────────────┘
     ↓          ↓             ↓
   Как?       Что?          Проверка
```

Или для запоминания:

```text
Header
→ Как обработать?

Payload
→ Какие данные?

Signature
→ Можно ли им доверять?
```

---

# 🎯 Главное

**Header** определяет алгоритм и тип токена.

**Payload** содержит claims.

**Signature** защищает JWT от незаметного изменения и позволяет проверить подпись.

Полная схема:

```text
JWT
 │
 ├── Header
 │      ↓
 │    alg, typ
 │
 ├── Payload
 │      ↓
 │    claims
 │
 └── Signature
        ↓
      проверка
```

---

# 🧠 Формула для запоминания

**Header → как?**

**Payload → что?**

**Signature → действительно ли токен подлинный и не изменён?**
