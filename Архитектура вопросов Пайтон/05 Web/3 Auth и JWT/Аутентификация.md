# 🔐 Аутентификация

## 🎤 Суперкоротко

**Аутентификация** — это проверка того, что пользователь действительно является тем, за кого себя выдаёт.

**Аутентификация отвечает на вопрос: «Ты действительно тот, за кого себя выдаёшь?»**

Примеры:

* пароль;
* код из SMS;
* TOTP;
* биометрия;
* аппаратный ключ;
* сертификат.

---

## 🎯 Ответ на собеседовании

**Аутентификация** — это процесс проверки подлинности субъекта, который пытается получить доступ к системе.

Сначала пользователь идентифицирует себя, например вводит логин, а затем предоставляет доказательство своей личности — пароль, одноразовый код, токен, сертификат и т. д.

---

# 🔄 Идентификация → Аутентификация

Типичный процесс:

```text
Пользователь
     ↓
Логин
     ↓
Идентификация
     ↓
Пароль
     ↓
Аутентификация
     ↓
Пользователь подтверждён
```

---

# 🔑 Факторы аутентификации

Факторы обычно разделяют на несколько категорий.

## 1. Что ты знаешь

То, что пользователь знает:

* пароль;
* PIN;
* секретный ответ.

```text
Пароль → 🔑
```

---

## 2. Что у тебя есть

Физический объект или устройство:

* телефон;
* аппаратный ключ;
* токен;
* банковская карта.

```text
Телефон → 📱
```

---

## 3. Кто ты

Биометрические признаки:

* отпечаток пальца;
* лицо;
* голос;
* радужка глаза.

```text
Биометрия → 👤
```

---

# 🔐 MFA

**MFA (Multi-Factor Authentication)** — многофакторная аутентификация.

Используется несколько независимых факторов.

Например:

```text
Пароль
   +
TOTP-код
   ↓
MFA
```

Важно понимать:

**два пароля — это не обязательно два фактора.**

Например:

```text
Пароль + PIN
```

оба относятся к категории:

```text
«Что ты знаешь»
```

---

# 🎟️ Аутентификация с токеном

В веб-приложениях после успешной аутентификации сервер может выдать токен.

Например:

```python
token = "eyJhbGciOi..."
```

Клиент затем отправляет его с последующими запросами:

```text
Authorization: Bearer <token>
```

Смысл:

```text
Логин + пароль
       ↓
Аутентификация
       ↓
Токен
       ↓
Следующие запросы
```

---

# 🆚 Аутентификация и Авторизация

Это разные процессы.

### Аутентификация

```text
КТО ты?
```

### Авторизация

```text
ЧТО тебе разрешено?
```

Например:

```text
Логин + пароль
      ↓
Аутентификация
      ↓
Ты — user123
      ↓
Проверка прав
      ↓
Авторизация
```

---

# 🌐 Пример в API

Клиент отправляет:

```python
headers = {
    "Authorization": "Bearer TOKEN"
}
```

Сервер:

```text
1. Получает токен
       ↓
2. Проверяет его
       ↓
3. Определяет пользователя
       ↓
4. Проверяет права
       ↓
5. Разрешает или запрещает операцию
```

Пункты 1–3 относятся к аутентификации, а проверка разрешений — к авторизации.

---

# ⚠️ Authentication ≠ Authorization

Очень частая тема на собеседованиях.

Запомнить:

```text
Authentication
      ↓
Кто ты?

Authorization
      ↓
Что тебе можно?
```

Пример:

```text
Ты действительно admin?
      ↓
Authentication

Может ли admin удалить пользователя?
      ↓
Authorization
```

---

# 🧠 Главное

Аутентификация:

* проверяет личность;
* использует один или несколько факторов;
* может использовать пароль, токен, сертификат, биометрию;
* часто происходит перед авторизацией.

---

# 🧠 Формула для запоминания

**Аутентификация = доказать, кто ты.**

> «Я Илья, и вот доказательство — мой пароль/токен/ключ».

После успешной аутентификации система переходит к проверке прав — **авторизации**.
