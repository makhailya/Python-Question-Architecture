# 🔗 Least Connections

## 🎯 Ответ на собеседовании

**Least Connections** — это алгоритм балансировки нагрузки, при котором новый запрос направляется на сервер с **наименьшим количеством активных соединений**.

В отличие от Round Robin, алгоритм учитывает **текущую нагрузку на серверы**.

Например:

```text
Server 1 → 10 активных соединений
Server 2 → 4 активных соединения
Server 3 → 7 активных соединений
```

Следующий запрос будет отправлен на **Server 2**, потому что у него меньше всего активных соединений.

---

## 🎤 Суперкоротко

**Least Connections = отправить запрос на сервер с наименьшим количеством активных соединений.**

---

## 🔄 Как работает

Допустим:

```text
Server 1 → 8 соединений
Server 2 → 3 соединения
Server 3 → 5 соединений
```

Приходит новый запрос:

```text
        ↓
   Load Balancer
        ↓
Server 2 — 3 connections
```

После установления нового соединения:

```text
Server 1 → 8
Server 2 → 4
Server 3 → 5
```

Следующий запрос снова будет рассматриваться с учётом текущего количества соединений.

---

## 🆚 Round Robin

**Round Robin** не смотрит на текущую нагрузку:

```text
Server 1 → Server 2 → Server 3 → Server 1 → ...
```

Даже если:

```text
Server 1 → 100 соединений
Server 2 → 2 соединения
Server 3 → 5 соединений
```

очередь продолжится по кругу.

**Least Connections** посмотрит на состояние серверов:

```text
Server 1 → 100
Server 2 → 2  ← следующий запрос
Server 3 → 5
```

---

## 💡 Когда полезен

Особенно полезен, когда запросы имеют **разную длительность**.

Например:

```text
Request A → выполняется 10 секунд
Request B → выполняется 100 мс
```

Если использовать Round Robin, сервер может получить несколько долгих запросов и оказаться перегруженным.

Least Connections старается отправлять новые запросы туда, где сейчас меньше активных соединений.

---

## ⚠️ Важный нюанс

**Количество соединений ≠ реальная загрузка сервера.**

Например:

```text
Server 1 → 5 соединений → CPU 20%
Server 2 → 3 соединения → CPU 95%
```

Least Connections выберет Server 2, хотя он фактически сильнее загружен.

Поэтому алгоритм учитывает только **количество активных соединений**, а не CPU, RAM или время выполнения запросов.

---

## ⚖️ Weighted Least Connections

Существует вариант **Weighted Least Connections**, который учитывает одновременно:

1. количество активных соединений;
2. вес сервера.

Например:

```text
Server 1 → weight 4
Server 2 → weight 1
```

Server 1 способен принимать большую нагрузку, поэтому при выборе учитывается его более высокий вес.

---

## 🆚 Сравнение алгоритмов

| Алгоритм                   | Что учитывает                  |
| -------------------------- | ------------------------------ |
| Round Robin                | Только порядок серверов        |
| Weighted Round Robin       | Порядок + вес                  |
| Least Connections          | Количество активных соединений |
| Weighted Least Connections | Соединения + вес               |

---

## 🧠 Главное

```text
Round Robin
→ по очереди

Weighted Round Robin
→ по очереди с учётом мощности серверов

Least Connections
→ на сервер с наименьшим количеством активных соединений

Weighted Least Connections
→ наименее загруженное соединение с учётом веса сервера
```

**Least Connections = балансировщик смотрит, у какого сервера сейчас меньше активных соединений, и направляет новый запрос туда.**
