# 🎲 Random

## 🎯 Ответ на собеседовании

**Random** — это алгоритм балансировки нагрузки, при котором каждый новый запрос направляется на **случайно выбранный сервер** из доступных.

Балансировщик не учитывает порядок запросов, IP клиента или количество активных соединений — он просто случайным образом выбирает сервер.

Например:

```python
servers = ["Server 1", "Server 2", "Server 3"]

request_1 → Server 2
request_2 → Server 1
request_3 → Server 3
request_4 → Server 2
request_5 → Server 1
```

---

## 🎤 Суперкоротко

**Random = случайный выбор сервера для каждого запроса.**

---

## 🔄 Как работает

Есть три сервера:

```text
Server 1
Server 2
Server 3
```

Приходит запрос:

```text
        ↓
Load Balancer
        ↓
  случайный выбор
        ↓
Server 2
```

Следующий запрос снова выбирается случайно:

```text
Request 1 → Server 2
Request 2 → Server 3
Request 3 → Server 3
Request 4 → Server 1
Request 5 → Server 2
```

В долгосрочной перспективе количество запросов может распределяться примерно равномерно, но **гарантии равномерного распределения нет**.

---

## 🆚 Random vs Round Robin

### Round Robin

Серверы выбираются строго по очереди:

```text
Server 1 → Server 2 → Server 3 → Server 1 → ...
```

Распределение предсказуемое.

### Random

Сервер выбирается случайно:

```text
Server 2 → Server 2 → Server 1 → Server 3 → Server 2 → ...
```

Распределение непредсказуемое.

---

## 🆚 Random vs Least Connections

**Random:**

```text
случайный сервер
```

Не учитывает нагрузку.

**Least Connections:**

```text
сервер с минимальным количеством активных соединений
```

Учитывает текущее количество соединений.

Например:

```text
Server 1 → 100 соединений
Server 2 →   5 соединений
Server 3 →  10 соединений
```

Random может выбрать любой сервер.

Least Connections выберет:

```text
Server 2
```

---

## ⚖️ Weighted Random

Существует вариант **Weighted Random**, где серверы имеют разные вероятности выбора.

Например:

```text
Server 1 → weight = 6
Server 2 → weight = 3
Server 3 → weight = 1
```

Вероятности примерно:

```text
Server 1 → 60%
Server 2 → 30%
Server 3 → 10%
```

Это позволяет отправлять больше запросов на более мощные серверы.

---

## ✅ Плюсы

* очень простой алгоритм;
* легко реализуется;
* не требует отслеживания количества соединений;
* может хорошо работать при большом количестве запросов;
* можно использовать веса через Weighted Random.

---

## ❌ Минусы

* не учитывает текущую нагрузку;
* распределение может быть неравномерным на небольших объёмах запросов;
* не обеспечивает sticky sessions;
* не учитывает производительность серверов без использования весов.

Например, случайно может получиться:

```text
Server 1 → 80 запросов
Server 2 → 15 запросов
Server 3 → 5 запросов
```

Хотя в среднем при большом количестве запросов распределение будет стремиться к равномерному.

---

## 🆚 Сравнение алгоритмов

| Алгоритм                   | Принцип                                |
| -------------------------- | -------------------------------------- |
| Round Robin                | По очереди                             |
| Weighted Round Robin       | По очереди + вес                       |
| Least Connections          | Минимум активных соединений            |
| Weighted Least Connections | Соединения + вес                       |
| IP Hash                    | Выбор по IP клиента                    |
| Random                     | Случайный сервер                       |
| Weighted Random            | Случайный сервер + вероятность по весу |

## 🧠 Главное

```text
Random
   ↓
случайный выбор
   ↓
Server 1 / Server 2 / Server 3
```

**Random = каждый запрос отправляется на случайно выбранный сервер.**

Главное отличие:

```text
Round Robin     → предсказуемо по очереди
Random          → случайно
Least Connections → по текущему числу соединений
IP Hash         → по IP клиента
```
