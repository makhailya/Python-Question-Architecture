# ⚖️ Weighted Least Connections

## 🎯 Ответ на собеседовании

**Weighted Least Connections** — это алгоритм балансировки нагрузки, который выбирает сервер с учётом **количества активных соединений и веса сервера**.

В отличие от обычного **Least Connections**, алгоритм учитывает, что серверы могут иметь разную производительность.

Например:

```python
Server 1 → 10 соединений, weight=5
Server 2 → 3 соединения,  weight=1
```

Несмотря на то, что у Server 1 больше соединений, его высокая производительность учитывается при выборе.

Проще говоря:

**Weighted Least Connections = Least Connections + вес сервера.**

---

## 🎤 Суперкоротко

**Выбирает наименее загруженный сервер с учётом его веса.**

Чем выше вес → тем больше нагрузки сервер способен принять.

---

## 🔄 Как работает

Допустим, есть три сервера:

```text
Server 1 → 10 соединений, weight=5
Server 2 →  4 соединения, weight=2
Server 3 →  3 соединения, weight=1
```

Балансировщик учитывает не только количество соединений, но и производительность серверов.

Условно можно сравнивать:

```text
connections / weight
```

Получаем:

```text
Server 1 → 10 / 5 = 2.0
Server 2 →  4 / 2 = 2.0
Server 3 →  3 / 1 = 3.0
```

Server 1 и Server 2 имеют одинаковый относительный уровень нагрузки, а Server 3 — выше.

---

## 💡 Зачем нужны веса

В реальной инфраструктуре серверы могут отличаться по ресурсам:

```text
Server 1 → 16 CPU, weight=4
Server 2 →  8 CPU, weight=2
Server 3 →  4 CPU, weight=1
```

Если использовать обычный Least Connections, серверы рассматриваются примерно одинаково.

Weighted Least Connections позволяет учитывать их различную производительность.

```text
мощнее сервер
     ↓
выше weight
     ↓
может получить больше соединений
```

---

## 🆚 Least Connections

**Least Connections:**

```text
Server 1 → 10
Server 2 →  4  ← выбран
Server 3 →  7
```

Выбирается сервер с минимальным количеством соединений.

**Weighted Least Connections:**

```text
Server 1 → 10 connections, weight=5
Server 2 →  4 connections, weight=2
Server 3 →  7 connections, weight=1
```

При выборе дополнительно учитывается **вес сервера**.

---

## ⚠️ Важный нюанс

Как и Least Connections, этот алгоритм ориентируется на **количество активных соединений**, а не непосредственно на:

* CPU;
* RAM;
* latency;
* время выполнения запросов;
* фактическую загрузку приложения.

Поэтому высокий вес не означает, что сервер всегда будет быстрее — вес является заданной настройкой балансировщика.

| -------------------------- | ------------------------- |
| Round Robin                | Порядок                   |
| Weighted Round Robin       | Порядок + вес             |
| Least Connections          | Активные соединения       |
| Weighted Least Connections | Активные соединения + вес |

## 🧠 Главное

```text
Round Robin
→ по очереди

Weighted Round Robin
→ по очереди + вес

Least Connections
→ сервер с наименьшим количеством соединений

Weighted Least Connections
→ количество соединений + вес сервера
```

**Формула для понимания:**

```text
относительная нагрузка ≈ connections / weight
```

Чем меньше значение → тем предпочтительнее сервер.

**Weighted Least Connections = выбор сервера с наименьшей относительной нагрузкой с учётом его веса.**
