# 🔄 Round Robin

## 🎯 Ответ на собеседовании

**Round Robin** — алгоритм балансировки нагрузки, при котором запросы распределяются между серверами **по очереди, циклически**.

Например, есть три сервера:

```text
Server 1
Server 2
Server 3
```

Запросы будут распределяться так:

```text
Request 1 → Server 1
Request 2 → Server 2
Request 3 → Server 3
Request 4 → Server 1
Request 5 → Server 2
Request 6 → Server 3
```

То есть после последнего сервера алгоритм возвращается к первому.

Главное:

> **Round Robin распределяет запросы последовательно между доступными серверами, не учитывая их текущую загрузку.**

---

## 🎤 Суперкоротко

```text
Round Robin = "по очереди"

1 → Server 1
2 → Server 2
3 → Server 3
4 → Server 1
5 → Server 2
...
```

---

# ⚙️ Как работает

Допустим, есть:

```text
Load Balancer
      ↓
 ┌────┼────┐
 ↓    ↓    ↓
App1 App2 App3
```

Приходят запросы:

```text
R1 → App1
R2 → App2
R3 → App3
R4 → App1
R5 → App2
R6 → App3
```

Алгоритм просто движется по кругу:

```text
App1 → App2 → App3 → App1 → App2 → App3 → ...
```

```text
                    ↓

                    │
          ┌─────────┼─────────┐
          ↓         ↓         ↓
        App 1     App 2     App 3
          ↑                   │
          └───────────────────┘
```

# ⚖️ Главное свойство

Round Robin **не смотрит на текущую нагрузку сервера**.

Например:

```text
App1 → 100 активных запросов
App2 → 5 активных запросов
App3 → 10 активных запросов
```

При следующем запросе обычный Round Robin всё равно выберет следующий сервер согласно очереди.

Он не анализирует:

```text
CPU
RAM
количество соединений
время выполнения запросов
```

---

# ✅ Преимущества

### Простота

Алгоритм очень простой и предсказуемый.

```text
App1 → App2 → App3 → App1 → ...
```

### Равномерное распределение

Если серверы примерно одинаковые, запросы распределяются достаточно равномерно:

```text
100 запросов

App1 → ~33
App2 → ~33
App3 → ~34
```

### Небольшие накладные расходы

Не нужно постоянно собирать информацию о загрузке каждого сервера.

---

# ❌ Недостатки

Главный недостаток:

> **Round Robin не учитывает реальную нагрузку на серверы.**

Например:

```text
App1 → мощный сервер
App2 → мощный сервер
App3 → слабый сервер
```

Обычный Round Robin будет распределять:

```text
App1 → 1/3
App2 → 1/3
App3 → 1/3
```

Хотя `App3` может не справляться с такой нагрузкой.

Для этого существует **Weighted Round Robin**.

---

# ⚖️ Weighted Round Robin

Weighted Round Robin добавляет **вес** каждому серверу.

Например:

```text
App1 → weight 3
App2 → weight 2
App3 → weight 1
```

Тогда более мощный сервер получает больше запросов.

Условно:

```text
App1 → App1 → App1
App2 → App2
App3
```

И снова:

```text
App1 → App1 → App1 → App2 → App2 → App3 → ...
```

То есть:

```text
Round Robin
        ↓
каждому серверу примерно одинаково

Weighted Round Robin
        ↓
количество запросов зависит от веса
```

# 🌐 Round Robin в Nginx

Например:

```python
upstream backend {
    server app1:8000;
    server app2:8000;
    server app3:8000;
}
```

Nginx будет распределять запросы между серверами upstream по Round Robin.

Схема:

```text
Client
  ↓
Nginx
  ↓
Round Robin
  ├── app1
  ├── app2
  └── app3
```

---

# 🆚 Round Robin vs Least Connections

| Round Robin                   | Least Connections                        |
| ----------------------------- | ---------------------------------------- |
| По очереди                    | На сервер с наименьшим числом соединений |
| Не учитывает текущую нагрузку | Учитывает активные соединения            |
| Очень простой                 | Более динамический                       |
| Хорош для одинаковых серверов | Полезен при разной длительности запросов |

Пример:

```text
App1 → 20 connections
App2 → 5 connections
App3 → 10 connections
```

**Round Robin**:

```text
следующий сервер по очереди
```

**Least Connections**:

```text
App2
```

---

# 🧠 Когда использовать Round Robin

Подходит, когда:

```text
Серверы примерно одинаковые
        ↓
Запросы примерно одинаковые
        ↓
Нужна простая балансировка
        ↓
Round Robin
```

Если серверы сильно отличаются по мощности:

```text
Round Robin
      ↓
Weighted Round Robin
```

Если запросы имеют сильно разную продолжительность:

```text
Least Connections
```
