# ⚖️ Weighted Round Robin

## 🎯 Ответ на собеседовании

**Weighted Round Robin** — это алгоритм балансировки нагрузки, при котором запросы распределяются между серверами по очереди, но с учётом **веса каждого сервера**.

Вес показывает, какую долю запросов сервер должен получать относительно других серверов.

Например:

* Server 1 — вес `3`
* Server 2 — вес `2`
* Server 3 — вес `1`

Тогда примерно каждые 6 запросов распределятся так:

`Server 1 → Server 1 → Server 1 → Server 2 → Server 2 → Server 3`

То есть более мощный сервер получает больше запросов.

---

## 🎤 Суперкоротко

**Weighted Round Robin = Round Robin + веса серверов.**

Чем выше вес сервера → тем больше запросов он получает.

---

## 🔄 Как работает

Допустим, есть три сервера:

```text
Server 1 — weight 3
Server 2 — weight 2
Server 3 — weight 1
```

Суммарный вес:

```text
3 + 2 + 1 = 6
```

Примерное распределение:

```text
Server 1 → 50%
Server 2 → 33%
Server 3 → 17%
```

Потому что:

```text
3 / 6 = 50%
2 / 6 ≈ 33%
1 / 6 ≈ 17%
```

---

## 🆚 Обычный Round Robin

Обычный Round Robin:

```text
Server 1 → Server 2 → Server 3 → Server 1 → ...
```

Все серверы получают примерно одинаковое количество запросов.

Weighted Round Robin:

```text
Server 1 → Server 1 → Server 1
Server 2 → Server 2
Server 3
```

Количество запросов зависит от веса.

---

## 💡 Зачем нужны веса

Когда серверы имеют разную производительность.

Например:

```text
Server 1 — 16 CPU
Server 2 — 8 CPU
Server 3 — 4 CPU
```

Нет смысла отправлять каждому одинаковое количество запросов.

Можно задать:

```text
Server 1 — weight 4
Server 2 — weight 2
Server 3 — weight 1
```

Тогда мощный сервер будет получать больше нагрузки.

---

## ⚙️ Пример в Nginx

```python
upstream backend {
    server 192.168.1.10 weight=3;
    server 192.168.1.11 weight=2;
    server 192.168.1.12 weight=1;
}
```

Nginx будет распределять запросы с учётом указанных весов.

---

## ✅ Плюсы

* учитывает разную производительность серверов;
* простой и предсказуемый алгоритм;
* позволяет контролировать распределение нагрузки;
* хорошо подходит для серверов с разными ресурсами.

---

## ❌ Минусы

Как и обычный Round Robin, **не учитывает текущее состояние серверов**.

Он не знает:

* сколько сейчас активных запросов;
* загружен ли CPU;
* сколько свободно RAM;
* насколько долго выполняются запросы.

Например, сервер с большим весом может быть уже сильно загружен, но алгоритм всё равно продолжит отправлять ему больше запросов.

---

## 🆚 Weighted Round Robin vs Least Connections

| Алгоритм                   | Принцип                                                |
| -------------------------- | ------------------------------------------------------ |
| Round Robin                | По очереди                                             |
| Weighted Round Robin       | По очереди с учётом веса                               |
| Least Connections          | На сервер с наименьшим количеством активных соединений |
| Weighted Least Connections | Наименее загруженный сервер с учётом веса              |

**Round Robin** хорошо работает, когда серверы примерно одинаковые.

**Weighted Round Robin** — когда серверы отличаются по мощности.

**Least Connections** — когда важно учитывать текущую нагрузку.

---

## 🧠 Главное

```text
Round Robin
→ всем примерно поровну

Weighted Round Robin
→ более мощному серверу больше запросов

Least Connections
→ запрос отправляется серверу с наименьшим количеством активных соединений
```

### Формула

```text
Доля сервера = вес сервера / сумма всех весов
```

Например:

```text
weights = 3, 2, 1

Server 1 = 3 / 6 = 50%
Server 2 = 2 / 6 ≈ 33%
Server 3 = 1 / 6 ≈ 17%
```

**Weighted Round Robin = распределение запросов по кругу с учётом веса серверов.**
