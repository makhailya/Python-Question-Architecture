# Как contribute

Спасибо, что хотите дополнить конспекты! Этот репозиторий открыт для правок.

> [!IMPORTANT]
> **Нужен доступ для записи.** Если вы присоединились к репозиторию, а не форкнули его,
> то при первом же push GitHub попросит **contributor access** — напишите владельцу
> (@makhailya), и он выдаст права. Остальное работает как обычно.

---

## 🚀 Быстрый старт

### 1. Форкните репозиторий

Нажмите **Fork** в правом верхнем углу на GitHub. Это создаст вашу копию:
`https://github.com/<ваш-ник>/Python-Question-Architecture`

### 2. Склонируйте свой форк

```bash
git clone git@github.com:<ваш-ник>/Python-Question-Architecture.git
cd Python-Question-Architecture
```

> Рекомендуем клонировать по **SSH**, а не по HTTPS — тогда push будет работать без ввода
> логина и токена каждый раз.

### 3. Настройте адрес origin

По умолчанию `origin` указывает на **ваш форк** — это как раз то, что нужно для push.

```bash
git remote -v
# origin  git@github.com:<ваш-ник>/Python-Question-Architecture.git (fetch)
# origin  git@github.com:<ваш-ник>/Python-Question-Architecture.git (push)
```

### 4. Создайте ветку под свою тему

```bash
git switch -c add-my-topic      # или fix/some-note
```

Работайте в ветке, а не в `main` — так правки не будут конфликтовать с другими участниками.

### 5. Делайте изменения

### 6. Зафиксируйте и отправьте

```bash
git add .
git commit -m "Кратко: что изменил"
git push origin add-my-topic
```

### 7. Откройте Pull Request

После `git push` GitHub покажет ссылку «Create pull request» — перейдите по ней,
заполните шаблон и нажмите **Create pull request**.

После этого владелец увидит изменения и при необходимости попросит что-то поправить.

## 💡 Что можно делать

| Хочу | Как назвать коммит |
|---|---|
| Добавить новую заметку-вопрос | `Add заметка про GIL` |
| Дополнить существующую заметку | `Improve заметка про сортировку` |
| Исправить опечатку / ошибку | `Fix опечатка в заметке про GIL` |

Коммиты на английском или русском — как вам удобнее. Главное, чтобы было понятно,
что изменилось.

## 📝 Как писать заметки

Все заметки в репозитории сделаны по одному шаблону. Чтобы новые выглядели так же:

```markdown
# 🎯 Название темы

## 🎤 Короткий ответ

**Термин** — определение в одном-двух предложениях.

---

## 🗣️ Ответ на собеседовании

Как это объяснить своими словами, живой речью.

---

# 📚 Разбор поглубже

Подробное объяснение с примерами кода.

---

## 🎤 Вопросы на собеседовании

### Что такое X?

> Ответ.
```

Правила:

- **Одна заметка — одна тема.** Не нужно смешивать несколько вопросов в одном файле.
- **Примеры кода** — на Python, в блоках ```python.
- **Используйте ссылки** `[[Название другой заметки]]`, чтобы связать темы между собой.
- **Эмодзи в заголовках** (🎤 📚 🎯) — как в остальных заметках, но не обязательно.

## ⚠️ Технические тонкости

### Кириллица и macOS

Если вы работаете на macOS в **Obsidian**, следите за двумя вещами:

1. **Не используйте `git mv` бездумно.** Имена файлов с кириллицей macOS хранит в
   нормализации Unicode NFD. Обычное перетаскивание в Obsidian безопаснее.
2. **Не меняйте регистр и пробелы в именах существующих файлов** — GitHub начнёт
   отдавать такие файлы по 404.

### Не редактируйте папку `.obsidian`

Это служебные файлы Obsidian (плагины, тема, настройки). Их почти никогда не нужно
трогать. Если файл в `.obsidian` изменился у вас сам — просто не добавляйте его в коммит
(`git add` вручную, только нужные файлы из `.md`).

### Исключённые файлы

В `.gitignore` уже исключены `.DS_Store`, кэш плагинов и состояние окон —
не нужно их коммитить, Git отфильтрует их сам.
