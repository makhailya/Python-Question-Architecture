# 📊 ELK Stack — конспект для собеседования

## 🎤 Короткий ответ

**ELK Stack** — это стек инструментов для централизованного сбора, обработки, хранения и анализа логов.

Состоит из трёх компонентов:

- **Elasticsearch** — хранит, индексирует и позволяет быстро искать логи.
- **Logstash** — принимает, обрабатывает и передаёт логи.
- **Kibana** — веб-интерфейс для поиска, анализа и визуализации логов.

Дополнительно используются **Filebeat** или **Elastic Agent** для сбора логов с серверов и контейнеров.

## 🗣️ Как рассказать на собеседовании

ELK используется для централизованного логирования, особенно в микросервисной архитектуре.

Например, у нас несколько сервисов, каждый пишет свои логи. Чтобы не заходить в каждый контейнер отдельно, мы собираем события через Filebeat, при необходимости обрабатываем через Logstash и сохраняем в Elasticsearch.

В Kibana можем найти ошибки конкретного сервиса, посмотреть события за нужный период или отследить обработку запроса по `trace_id`.

Это помогает быстрее находить причины ошибок и разбирать инциденты.

## ⚙️ Как работает ELK

```text
Python / FastAPI / Docker
          |
          v
 Filebeat / Elastic Agent
          |
          v
       Logstash
     (необязательно)
          |
          v
     Elasticsearch
          |
          v
        Kibana
```

## 🔍 Что важно знать

| Термин | Значение |
|---|---|
| Structured Logging | Логи в JSON с отдельными полями |
| Log Levels | DEBUG, INFO, WARNING, ERROR, CRITICAL |
| `trace_id` | Идентификатор распределённой трассировки |
| `request_id` | Идентификатор конкретного запроса |
| Index | Структура хранения и поиска документов в Elasticsearch |
| ILM | Управление жизненным циклом индексов и сроками хранения |

### Пример структурированного лога

```json
{
  "level": "ERROR",
  "service": "validation-service",
  "message": "Validation failed",
  "supply_id": 123,
  "trace_id": "abc123"
}
```

По `trace_id` можно найти связанные события в разных микросервисах, если они записывают этот идентификатор.

## ⚖️ ELK vs Prometheus vs Grafana

| Инструмент | Для чего |
|---|---|
| ELK | Логи: что произошло? |
| Prometheus | Метрики: сколько ошибок, какая нагрузка? |
| Grafana | Дашборды и визуализация |
| Jaeger | Трассировка: где запрос задержался? |

## ❓ Частые вопросы

**1. Обязателен ли Logstash?**

Нет. Filebeat или Elastic Agent могут отправлять данные напрямую в Elasticsearch.

**2. Что такое централизованное логирование?**

Сбор логов нескольких приложений в одном хранилище для общего поиска и анализа.

**3. Что такое Structured Logging?**

Запись событий в структурированном формате, обычно JSON.

**4. Зачем нужен trace_id?**

Чтобы связывать события одного распределённого запроса между микросервисами.

**5. Что делать, если Elasticsearch недоступен?**

Использовать буферизацию и повторную доставку логов. Сбой логирования по возможности не должен останавливать бизнес-операции.

**6. Чем ELK отличается от мониторинга?**

ELK традиционно используют для анализа логов, а мониторинг — для отслеживания метрик и состояния системы. Современная платформа Elastic также поддерживает метрики и трассировки.

## 🧠 Запомнить

**ELK = Elasticsearch + Logstash + Kibana.**

- Elasticsearch — **хранит и ищет**.
- Logstash — **обрабатывает**.
- Kibana — **показывает**.
- Filebeat — **собирает и доставляет**.

**Главная польза:** быстро находить ошибки и анализировать работу нескольких микросервисов в одном месте.
