# ⚙️ Jenkins — автоматизация CI/CD

## 🎤 Короткий ответ для собеседования

**Jenkins** — это open-source сервер автоматизации, который используется для построения CI/CD-пайплайнов.

Он позволяет автоматически:

- Собирать приложение.
- Запускать тесты.
- Проверять качество кода.
- Создавать Docker-образы.
- Публиковать артефакты.
- Развёртывать приложение на сервере.

**CI (Continuous Integration)** — непрерывная интеграция: автоматическая проверка изменений кода.

**CD (Continuous Delivery / Deployment)** — автоматизация подготовки релиза или развёртывания приложения.

## 🗣️ Ответ на собеседовании

Jenkins — это инструмент автоматизации CI/CD.

Например, разработчик создаёт ветку, пишет код и открывает Pull Request. Jenkins может автоматически запустить пайплайн: установить зависимости, проверить код через Ruff, выполнить тесты Pytest и собрать Docker-образ.

После успешного слияния изменений в основную ветку запускается процесс доставки приложения: образ публикуется в Docker Registry, после чего приложение развёртывается на сервере.

Все этапы описываются в `Jenkinsfile`, который хранится вместе с исходным кодом.

Это позволяет автоматизировать процесс от коммита до деплоя и уменьшить количество ручных ошибок.

## 🔄 Как работает CI/CD с Jenkins

```text
Разработчик
    |
    v
Git Push / Pull Request
    |
    v
GitHub / GitLab
    |
    v
Webhook
    |
    v
Jenkins Pipeline
    |
    ├── Checkout
    ├── Install Dependencies
    ├── Lint (Ruff)
    ├── Tests (Pytest)
    ├── Build Docker Image
    └── Push to Registry
              |
              v
          Deployment
              |
              v
          Production
```

**Важно:** деплой в production обычно выполняется только после успешных проверок и при выполнении условий релизного процесса.

## 🧩 Основные компоненты Jenkins

| Компонент | Назначение |
|---|---|
| Controller | Управляет заданиями и пайплайнами |
| Agent | Выполняет задачи сборки и тестирования |
| Pipeline | Последовательность этапов CI/CD |
| Jenkinsfile | Файл с описанием пайплайна |
| Stage | Отдельный этап выполнения |
| Step | Конкретная команда внутри этапа |
| Plugin | Расширяет функциональность Jenkins |
| Credentials | Безопасное хранение секретов и учётных данных |

### Controller и Agent

```text
        Jenkins Controller
                |
       ┌────────┼────────┐
       |        |        |
       v        v        v
    Agent 1  Agent 2  Agent 3
       |        |        |
     Tests    Build    Deploy
```

**Controller** управляет заданиями, а **Agents** выполняют команды.

Так можно распределять нагрузку между несколькими серверами.

## 📝 Jenkinsfile — пример для Python Backend

`Jenkinsfile` обычно хранится в корне Git-репозитория.

```groovy
pipeline {
    agent any

    stages {
        stage('Checkout') {
            steps {
                checkout scm
            }
        }

        stage('Install') {
            steps {
                sh 'python -m pip install -r requirements.txt'
            }
        }

        stage('Lint') {
            steps {
                sh 'ruff check .'
            }
        }

        stage('Tests') {
            steps {
                sh 'pytest'
            }
        }

        stage('Build') {
            steps {
                sh 'docker build -t myapp:latest .'
            }
        }
    }
}
```

Для этого примера на агенте должны быть установлены Python, Ruff, Pytest и Docker; зависимости проекта должны включать необходимые инструменты.

### Разбор

- `pipeline` — объявляет CI/CD-пайплайн.
- `agent any` — позволяет выполнять его на любом подходящем доступном агенте.
- `stages` — содержит этапы.
- `stage` — отдельный этап.
- `steps` — команды этапа.
- `sh` — выполнение shell-команды.
- `checkout scm` — получение исходного кода из Git.

**Если команда завершается с ненулевым кодом возврата, этап обычно считается неуспешным, а следующие обычные этапы не выполняются.**

## 🚀 Как выглядит полный процесс деплоя

```text
1. Создал feature-ветку
           |
           v
2. Написал код и тесты
           |
           v
3. Открыл Pull Request
           |
           v
4. Jenkins запустил проверки
           |
           v
5. Code Review
           |
           v
6. Merge в main
           |
           v
7. Сборка Docker-образа
           |
           v
8. Push в Docker Registry
           |
           v
9. Deploy на сервер
           |
           v
10. Health Check
```

При неуспешном Health Check система может остановить релиз или запустить rollback, если такая логика предусмотрена пайплайном.

## ⚖️ Jenkins vs GitLab CI vs GitHub Actions

| Инструмент | Особенность |
|---|---|
| Jenkins | Отдельный сервер автоматизации, гибкая настройка через плагины |
| GitLab CI/CD | CI/CD, интегрированный с GitLab |
| GitHub Actions | Автоматизация непосредственно в GitHub |

**Jenkins** требует администрирования контроллера, агентов, плагинов и обновлений.

**GitLab CI/CD** обычно описывается в `.gitlab-ci.yml`.

**GitHub Actions** использует YAML-файлы в `.github/workflows/`.

Все три инструмента могут выполнять сборку, тестирование и деплой.

## ❓ Частые вопросы на собеседовании

**1. Что такое Jenkins?**

Сервер автоматизации для построения CI/CD-процессов.

**2. Что такое Jenkinsfile?**

Файл, в котором описан пайплайн сборки, тестирования и доставки приложения.

**3. Чем CI отличается от CD?**

CI отвечает за регулярную интеграцию и проверку изменений. CD автоматизирует подготовку релиза или его развёртывание.

**4. Что такое Pipeline?**

Последовательность автоматизированных этапов обработки изменений.

**5. Что такое Agent?**

Исполнитель, на котором Jenkins запускает задачи.

**6. Что произойдёт, если тесты упадут?**

Пайплайн обычно завершится ошибкой и не перейдёт к последующим этапам сборки или деплоя.

**7. Как Jenkins узнаёт о новом коммите?**

Например, через Git webhook, периодическую проверку репозитория или ручной запуск.

**8. Как хранить пароли и токены?**

Через Jenkins Credentials и подходящие интеграции с хранилищами секретов, а не в исходном коде.

**9. Как выполнить rollback?**

Например, развернуть предыдущий проверенный Docker-образ. Механизм отката нужно реализовать в процессе деплоя.

**10. Зачем Jenkins, если есть Docker?**

Docker упаковывает и запускает приложение в контейнере, а Jenkins автоматизирует сборку, проверку и доставку.
