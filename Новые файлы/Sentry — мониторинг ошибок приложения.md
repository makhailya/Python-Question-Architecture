# 🐛 Sentry — мониторинг ошибок приложения

## 🎤 Короткий ответ для собеседования

**Sentry** — это платформа для отслеживания ошибок, исключений и проблем производительности приложений.

Она автоматически собирает информацию об ошибках и помогает разработчикам быстро находить причины сбоев.

Sentry позволяет:

- Отслеживать исключения и ошибки.
- Просматривать **Stack Trace** — стек вызовов.
- Группировать одинаковые ошибки.
- Получать уведомления о новых проблемах.
- Анализировать ошибки по релизам и окружениям.
- Отслеживать производительность запросов.

## 🗣️ Ответ на собеседовании

Sentry использовали для мониторинга ошибок Backend-сервисов.

Интегрировали через Python SDK. При возникновении необработанного исключения Sentry автоматически фиксировал ошибку, сохранял Stack Trace и дополнительный контекст: сервис, окружение, версию приложения и данные запроса с учётом настроек безопасности.

Это позволяло видеть частоту ошибок, определять, после какого релиза они появились, и получать уведомления о критических проблемах.

В отличие от ELK, который используется для централизованного анализа логов, Sentry в первую очередь ориентирован на отслеживание исключений и управление ошибками.

## 🔧 Пример интеграции с FastAPI

Установка:

```bash
pip install "sentry-sdk[fastapi]"
```

Подключение:

```python
import sentry_sdk
from fastapi import FastAPI

sentry_sdk.init(
    dsn="https://example@sentry.example/123",
    traces_sample_rate=0.1,
    environment="production",
    send_default_pii=False,
)

app = FastAPI()


@app.get("/test")
def test_error():
    return 1 / 0
```

### Что происходит?

1. `sentry_sdk.init()` — инициализирует Sentry.
2. `dsn` — адрес проекта для отправки событий.
3. `traces_sample_rate=0.1` — включает выборку примерно 10% транзакций для мониторинга производительности.
4. `environment` — указывает окружение.
5. `send_default_pii=False` — отключает автоматическую отправку части персональных данных по умолчанию.
6. `1 / 0` — вызывает `ZeroDivisionError`.

Sentry автоматически перехватит необработанное исключение через интеграцию с FastAPI и отправит событие при корректной настройке подключения.

Для отправки ошибки вручную:

```python
try:
    result = 1 / 0
except ZeroDivisionError as exc:
    sentry_sdk.capture_exception(exc)
```

## 🔍 Основные понятия

| Термин | Значение |
|---|---|
| Event | Отдельное событие об ошибке |
| Issue | Группа похожих ошибок |
| Stack Trace | Цепочка вызовов до возникновения исключения |
| Breadcrumbs | События, предшествовавшие ошибке |
| Release | Версия приложения |
| Environment | Окружение: production, staging и др. |
| Alert | Уведомление об ошибке |
| Performance Monitoring | Анализ времени выполнения операций |

## ⚖️ Sentry vs ELK vs Prometheus

| Инструмент | Основная задача |
|---|---|
| **Sentry** | Отслеживание исключений, группировка ошибок |
| **ELK** | Централизованное хранение и поиск логов |
| **Prometheus** | Сбор и хранение метрик |
| **Grafana** | Визуализация метрик и других данных |

Пример:

**Sentry:** показывает, что в `validation-service` возник `KeyError`, на какой строке и сколько раз ошибка повторилась.

**ELK:** позволяет найти связанные логи и восстановить последовательность событий.

**Prometheus:** показывает, что количество HTTP 500 увеличилось за последние 10 минут.

Эти инструменты дополняют друг друга.

## ❓ Частые вопросы на собеседовании

**1. Чем Sentry отличается от обычного логирования?**

Sentry автоматически собирает исключения, группирует похожие ошибки, показывает Stack Trace и позволяет отслеживать их состояние.

**2. Что такое Stack Trace?**

Последовательность вызовов функций, которая помогает определить место возникновения ошибки.

**3. Что такое Breadcrumbs?**

Записи о событиях, произошедших перед ошибкой, которые помогают восстановить контекст.

**4. Как Sentry группирует ошибки?**

Использует механизм fingerprinting на основе характеристик исключения и стека вызовов. Группировку можно настраивать.

**5. Можно ли отправлять ошибки вручную?**

Да, через `sentry_sdk.capture_exception()` или `sentry_sdk.capture_message()`.

**6. Что делать, если Sentry недоступен?**

SDK обычно отправляет события асинхронно и не должен блокировать бизнес-операции. При длительной недоступности часть событий может потеряться.

**7. Нужно ли отправлять в Sentry все ошибки?**

Нет. Например, ожидаемые бизнес-ошибки валидации не всегда являются исключительными ситуациями. Важно избегать лишнего шума.

## 🧠 Запомнить

**Sentry — это инструмент для мониторинга и расследования ошибок приложения.**

```text
Ошибка → Sentry SDK → Issue → Stack Trace → Уведомление
```

**Главное отличие:**

- **Sentry** — какая ошибка возникла и где.
- **ELK** — какие события происходили в системе.
- **Prometheus** — что происходит с метриками системы.

Для Python Backend Sentry особенно полезен при диагностике необработанных исключений в production.
