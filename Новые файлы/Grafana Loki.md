# 📊 Grafana Loki

## 🎤 Короткий ответ

**Grafana Loki** — это система централизованного сбора и хранения логов, предназначенная для поиска и анализа логов приложений и инфраструктуры. Она похожа на Prometheus, но работает с логами вместо метрик. Loki индексирует преимущественно метаданные и labels, а сами записи логов хранит в виде сжатых chunks. Обычно логи собирает агент, например Grafana Alloy, после чего они отправляются в Loki и анализируются через Grafana с помощью языка запросов LogQL.

## 🗣️ Ответ на собеседовании

Grafana Loki — это система агрегации логов, которую используют для централизованного мониторинга backend-приложений и инфраструктуры.

Например, если Python-приложение работает в Docker или Kubernetes, его логи можно собирать в одном месте, а не подключаться к каждому серверу отдельно. Агент сбора логов читает вывод приложений, добавляет метки, например имя сервиса и окружение, и отправляет записи в Loki.

Loki хранит логи и индексирует их labels, а не строит полнотекстовый индекс по каждому слову в каждой записи. Поэтому при поиске сначала выбирают поток логов по меткам, а затем фильтруют содержимое. Для запросов используется LogQL.

Grafana предоставляет интерфейс, в котором можно искать ошибки, анализировать события и сопоставлять логи с метриками из Prometheus. Например, при росте количества HTTP 500 можно посмотреть логи конкретного сервиса и выяснить причину ошибки.

Loki помогает централизовать логи и ускорить диагностику, но качество поиска зависит от правильного выбора labels, организации хранения и настройки сбора данных.

## 📚 Разбор поглубже

### 1. Какие задачи решает Loki

Без централизованного сбора логи могут находиться на разных серверах, в контейнерах или файлах. При возникновении ошибки разработчику приходится искать их в разных местах.

Loki позволяет:
- собирать логи из разных сервисов в одном месте;
- фильтровать события по сервису, окружению и другим меткам;
- искать исключения и ошибки;
- исследовать инциденты;
- связывать события в логах с метриками и трассировками.

**Пример:** после деплоя FastAPI-приложения выросло количество ответов HTTP 500. В Grafana можно выбрать логи нужного сервиса, найти сообщения об исключениях и определить, на каком этапе возникла ошибка.

### 2. Как устроен сбор логов

Типичный конвейер выглядит так:

```text
Python-приложение
       ↓
stdout / stderr или файлы
       ↓
Grafana Alloy / другой агент
       ↓
Добавление labels и обработка
       ↓
Grafana Loki
       ↓
Grafana + LogQL
       ↓
Поиск и диагностика
```

**Пример компонентов:**

- **Приложение** — пишет структурированные или обычные текстовые логи.
- **Агент** — читает логи, обрабатывает их и отправляет в хранилище.
- **Loki** — принимает, хранит и предоставляет логи для запросов.
- **Grafana** — отображает результаты запросов и позволяет исследовать события.

Grafana и Loki — разные компоненты. Grafana является интерфейсом визуализации и исследования данных, а Loki — backend для хранения и поиска логов.

### 3. Labels — метки логов

Labels — ключевые атрибуты, по которым Loki организует потоки логов и выполняет первичный отбор данных.

Например:

```text
service="payment-api"
environment="production"
level="error"
```

Запись лога может содержать текст:

```text
2026-10-26 12:30:15 ERROR Payment processing failed
```

А поток логов при этом иметь labels:

```text
{service="payment-api", environment="production"}
```

Важно: не каждое поле лога обязательно должно становиться label. Обычно в labels помещают ограниченный набор стабильных атрибутов.

**Почему опасна высокая кардинальность labels?**

Если использовать в качестве labels уникальные `request_id`, `user_id` или произвольные URL, количество потоков может резко вырасти. Это увеличивает нагрузку на систему и ухудшает эффективность хранения и запросов.

Такие динамические значения обычно лучше оставлять в содержимом лога или извлекать на этапе запроса, если это уместно.

### 4. LogQL — язык запросов

LogQL используется для поиска и анализа логов в Loki.

Простой запрос:

```logql
{service="payment-api"}
```

Он выбирает логи из потоков с указанным label.

Фильтрация по тексту:

```logql
{service="payment-api"} |= "failed"
```

Поиск ошибок в JSON-логах:

```logql
{service="payment-api"}
| json
| level = "error"
```

Подсчёт количества ошибок за пять минут:

```logql
sum(
  count_over_time(
    {service="payment-api"} |= "ERROR" [5m]
  )
)
```

Последний запрос считает количество записей, содержащих `ERROR`, за скользящее пятиминутное окно. Он не гарантирует, что все такие записи являются настоящими ошибками, если формат логирования не стандартизирован.

### 5. Как Loki хранит логи

Ключевая особенность Loki — **он не индексирует весь текст каждой записи так же, как полнотекстовые поисковые системы**.

В упрощённом виде:
- labels определяют поток логов;
- записи объединяются в chunks;
- chunks сжимаются и хранятся;
- индекс помогает находить нужные потоки и данные;
- содержимое записей фильтруется при выполнении запроса.

Это позволяет уменьшить затраты на индексирование по сравнению с системами, которые создают полнотекстовый индекс для всех полей. Однако производительность зависит от объёма данных, выбранных labels, временного диапазона и сложности фильтров.

### 6. Loki vs Prometheus vs Elasticsearch

| Система | Основное назначение |
|---|---|
| Grafana Loki | Централизованный сбор, хранение и поиск логов |
| Prometheus | Сбор и запрос метрик временных рядов |
| Elasticsearch | Поиск и аналитика документов, в том числе логов, с развитым индексированием |

Loki и Prometheus часто используют вместе: Prometheus помогает обнаружить аномалию по метрикам, а Loki — изучить соответствующие события в логах.

Elasticsearch может быть удобен для сложного полнотекстового поиска, но выбор системы зависит от требований, архитектуры и стоимости эксплуатации.

### 7. Применение в Python Backend

В FastAPI или Django приложение может писать логи в `stdout` и `stderr`. Агент сбора считывает их и отправляет в Loki.

Пример структурированного логирования:

```python
import json
import logging

logger = logging.getLogger(__name__)

def process_payment(payment_id: str) -> None:
    try:
        # Здесь выполняется обработка платежа.
        logger.info(
            json.dumps({
                "event": "payment_processed",
                "payment_id": payment_id,
                "level": "info",
            })
        )
    except Exception:
        logger.exception("Payment processing failed")
        raise
```

Это иллюстративный пример. В реальном проекте лучше настроить единый форматтер структурированных логов, чтобы поля добавлялись последовательно и не приходилось вручную сериализовать каждый вызов.

Не следует записывать в логи пароли, токены авторизации, секреты или лишние персональные данные.

### 8. Loki и наблюдаемость (Observability)

Observability обычно рассматривают через три основных типа телеметрии:

- **Metrics** — числовые показатели, например количество запросов, задержка и процент ошибок.
- **Logs** — отдельные события с подробностями произошедшего.
- **Traces** — путь одного запроса через несколько сервисов.

Например, метрики показывают рост задержки, трассировка помогает определить медленный сервис, а Loki позволяет найти конкретные сообщения об ошибках.

Для эффективной диагностики полезно связывать логи с trace ID и метриками, но при этом не создавать labels с высокой кардинальностью.

### 9. Типичные ошибки

1. Создавать label для каждого уникального `request_id`.
2. Пытаться использовать Loki как полноценную базу метрик.
3. Считать, что Grafana сама хранит логи Loki.
4. Искать по огромному временному диапазону без предварительного отбора по labels.
5. Не стандартизировать структуру логов и уровни `INFO`, `WARNING`, `ERROR`.
6. Не настроить retention, контроль доступа и защиту чувствительных данных.
7. Считать, что централизованный сбор логов автоматически гарантирует обнаружение всех ошибок.

## 🎤 Вопросы на собеседовании

**1. Что такое Grafana Loki?**

Система централизованного хранения и поиска логов, использующая labels для организации потоков и первичного отбора данных.

**2. Чем Loki отличается от Prometheus?**

Loki работает с логами, а Prometheus — с метриками.

**3. Что такое LogQL?**

Язык запросов Loki для выбора потоков, фильтрации записей и выполнения операций над логами.

**4. Почему важно избегать высокой кардинальности labels?**

Большое количество уникальных комбинаций labels увеличивает число потоков и может ухудшать производительность и стоимость хранения.

**5. Как логи попадают в Loki?**

Обычно агент, например Grafana Alloy, собирает логи приложения или контейнера, при необходимости обрабатывает их и отправляет в Loki.

**6. Как использовать Loki для диагностики HTTP 500?**

Выбрать сервис и временной диапазон, отфильтровать сообщения об ошибках, изучить исключения и сопоставить их с метриками или трассировками.

**7. Зачем Loki используют вместе с Grafana?**

Loki хранит и предоставляет логи, а Grafana позволяет выполнять запросы, визуализировать результаты и сопоставлять логи с другими источниками наблюдаемости.
