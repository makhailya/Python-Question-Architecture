LLM — это большая языковая модель, которая обучается на текстовых данных и может генерировать ответы, писать код, суммировать документы и выполнять другие языковые задачи.

Сначала текст преобразуется в токены с помощью токенизатора. Затем модель обрабатывает их с использованием нейросетевой архитектуры, чаще всего Transformer, и вычисляет вероятности следующих токенов. При генерации модель выбирает очередной токен, добавляет его к последовательности и повторяет процесс, пока не будет достигнут критерий остановки.

Перед использованием модель проходит предварительное обучение, а затем может дополнительно настраиваться на инструкции и предпочтения пользователей. При этом LLM не является обычной базой данных: она не гарантирует точного воспроизведения фактов и может генерировать правдоподобные, но ошибочные ответы.

В backend-разработке LLM подключают через API или запускают локально. Её используют для чат-ботов, классификации, извлечения данных, генерации кода и RAG-систем, где модель получает найденный внешний контекст перед формированием ответа.

## 📚 Разбор поглубже

### 1. Что такое LLM

LLM — это нейросетевая модель, предназначенная для обработки и генерации естественного языка. Современные модели также могут работать с кодом, структурированными данными, изображениями и другими типами входных данных — в зависимости от архитектуры и обучения.

Примеры семейств моделей:
- GPT;
- Claude;
- Gemini;
- Llama;
- Qwen;
- Gemma.

LLM — это сама модель, а не приложение, интерфейс или сервер, через который к ней обращаются.

### 2. Как LLM обрабатывает текст

Основной путь обработки выглядит так:

```text
Текст пользователя
       ↓
Tokenizer
       ↓
Token IDs
       ↓
Embeddings
       ↓
Transformer
       ↓
Вероятности следующих токенов
       ↓
Выбор следующего токена
       ↓
Декодирование в текст
```

**Токенизация.** Текст разбивается на токены. Токеном может быть слово, часть слова, символ или другой фрагмент в зависимости от токенизатора.

**Embeddings.** Идентификаторы токенов преобразуются в векторные представления, которые модель может обрабатывать.

**Transformer.** Модель использует механизмы внимания и другие нейросетевые слои для обработки контекста и вычисления представлений токенов.

**Генерация.** Модель формирует распределение вероятностей следующего токена. Алгоритм декодирования выбирает токен, после чего процесс повторяется.

Важно: LLM не всегда выбирает токен с максимальной вероятностью. Поведение зависит от параметров генерации, например temperature, top-p и выбранного алгоритма декодирования.

### 3. Что такое Transformer и Attention

Transformer — архитектура нейросетей, лежащая в основе большинства современных LLM.

Механизм **Self-Attention** позволяет модели учитывать взаимосвязи между токенами в контексте. Например, при обработке местоимения модель может учитывать слова, которые встречались раньше.

В decoder-only моделях, широко используемых для генерации текста, применяется причинная маска: при предсказании следующего токена модель не должна использовать будущие токены из целевой последовательности.

Для понимания LLM на уровне Python Backend достаточно сначала знать назначение токенизации, контекстного окна, attention и генерации. Математические детали можно изучать отдельно.

### 4. Этапы обучения

#### Pretraining

Предварительное обучение на больших массивах данных. Для многих современных языковых моделей одна из основных задач — предсказать следующий токен по предыдущему контексту.

#### Instruction Tuning

Дополнительное обучение на примерах инструкций и ответов, чтобы модель лучше выполняла запросы пользователя.

#### Alignment

Методы настройки поведения модели с учётом предпочтений и требований к безопасности. В зависимости от модели могут использоваться предпочтительные ответы, обратная связь людей и другие методы обучения.

Эти этапы не являются обязательной универсальной схемой для каждой модели: конкретные подходы различаются.

### 5. Inference и генерация

Inference — использование уже обученной модели для получения результата.

При генерации модель обычно обрабатывает входной контекст, вычисляет следующий токен, а затем продолжает генерацию. В autoregressive-моделях этот процесс повторяется последовательно.

Основные параметры:

| Параметр | Назначение |
|---|---|
| Temperature | Управляет случайностью выбора токенов |
| Top-p | Ограничивает выборку наиболее вероятной частью распределения |
| Max tokens | Ограничивает количество генерируемых токенов |
| Stop sequences | Задают последовательности, при которых генерация останавливается |

Высокая temperature обычно увеличивает разнообразие ответов, но может уменьшать предсказуемость. Низкая temperature делает генерацию более консервативной, однако сама по себе не гарантирует фактическую точность.

### 6. Context Window

Context Window — максимальный объём токенов, который модель может учитывать в рамках одного запроса или последовательности взаимодействия согласно её архитектуре и ограничениям реализации.

В контекст могут входить:
- системные инструкции;
- история диалога;
- текущий запрос;
- найденные RAG-фрагменты;
- описания доступных инструментов;
- часть ответа, который уже генерируется.

Если контекст переполняется, приложение должно сокращать историю, выбирать релевантные сообщения или иначе управлять входными данными.

**Контекстное окно не равно памяти модели.** Содержимое конкретного диалога не обязательно сохраняется между независимыми запросами. Долгосрочная память обычно реализуется на уровне приложения или внешнего хранилища.

### 7. LLM и галлюцинации

Галлюцинация — ситуация, когда модель выдаёт утверждение, которое не соответствует фактам или не подтверждается доступными источниками.

Это связано с тем, что модель генерирует последовательность токенов на основе выученных закономерностей и текущего контекста, а не выполняет автоматическую проверку каждого утверждения по достоверной базе данных.

Снизить риск помогают:
- RAG и проверенные источники;
- ограничения на ответы при недостатке данных;
- вызов внешних API и инструментов;
- валидация структурированных ответов;
- тестирование на реальных примерах.

Ни один из этих методов сам по себе не гарантирует отсутствия ошибок.

### 8. LLM, RAG и Fine-tuning

| Понятие | Роль |
|---|---|
| LLM | Генерирует результат на основе входного контекста и выученных параметров |
| RAG | Находит внешние сведения и добавляет их в контекст LLM |
| Fine-tuning | Дополнительно обучает модель для изменения поведения или специализации |
| Embedding Model | Преобразует данные в векторные представления для поиска и других задач |
| Prompt Engineering | Помогает сформулировать инструкции и контекст для модели |

Эти компоненты решают разные задачи и могут использоваться совместно.

### 9. Как подключить LLM в Python Backend

Типичный backend-сценарий:

```text
Клиент
   ↓ HTTP
FastAPI
   ↓
Бизнес-логика
   ↓
LLM API или локальная модель
   ↓
Обработка и проверка результата
   ↓
HTTP-ответ клиенту
```

Пример с условным клиентом:

```python
def generate_answer(question: str) -> str:
    response = llm_client.generate(
        prompt=question,
        max_tokens=300,
    )
    return response.text
```

Здесь `llm_client` — условный объект, интерфейс которого зависит от конкретной библиотеки или провайдера.

В production-приложении также учитывают:
- таймауты и повторные попытки;
- ограничения частоты запросов;
- стоимость токенов;
- потоковую передачу ответа;
- обработку ошибок провайдера;
- защиту персональных и секретных данных;
- проверку и валидацию результата.

### 10. Локальная модель и облачный API

**Облачный API**
- не требует от разработчика самостоятельно обслуживать веса модели;
- обычно проще масштабируется;
- зависит от внешнего провайдера, его тарифов и доступности;
- требует учитывать передачу данных за пределы собственной инфраструктуры.

**Локальная модель**
- может работать без отправки запросов внешнему провайдеру;
- даёт больше контроля над окружением и конфигурацией;
- требует подходящих вычислительных ресурсов;
- требует самостоятельно учитывать производительность, обновления и эксплуатацию.

Выбор зависит от требований к качеству, задержке, стоимости, конфиденциальности и доступной инфраструктуре.

## 🎤 Вопросы на собеседовании

**1. Что такое LLM?**

Большая языковая модель, обученная обрабатывать и генерировать последовательности токенов. Она может использоваться для ответов на вопросы, генерации кода и других задач обработки языка.

**2. Как LLM генерирует текст?**

Преобразует вход в токены, обрабатывает контекст, вычисляет вероятности следующего токена и последовательно формирует ответ.

**3. Что такое токен?**

Единица текста, определяемая токенизатором. Это может быть слово, часть слова, символ или другой фрагмент.

**4. Что такое Context Window?**

Объём токенов, который модель может учитывать в рамках одного контекста. Он ограничивает размер инструкций, истории, найденных документов и других входных данных.

**5. Почему LLM может ошибаться?**

Модель может генерировать правдоподобный текст, который не соответствует фактам, а её обученные параметры не являются гарантированно точной и актуальной базой знаний.

**6. Чем LLM отличается от RAG?**

LLM — модель генерации, а RAG — архитектурный подход, который дополняет её ответ информацией, найденной во внешних источниках.

**7. Что такое inference?**

Выполнение обученной модели для получения результата на основе входных данных.

**8. Что делает temperature?**

Регулирует случайность при выборе токенов во время генерации. Она влияет на разнообразие ответов, но не является прямым параметром достоверности.

**9. Как использовать LLM в backend-приложении?**

Подключить модель через API или локальный inference-сервер, вызвать её из бизнес-логики и предусмотреть таймауты, обработку ошибок, контроль стоимости и валидацию результатов.
